# 튜토리얼 끊김 조사와 변경 없는 칙령 저장 비용

갱신일: 2026-10-05 · [English](Tutorial_Save_Hitch_20261005.en.md)

튜토리얼에서 불규칙하게 화면 전체가 멈춘다는 제보를 조사했다. 제공된 전사 보스전 영상에서 약 0.75초의 정지 구간들과 이어진 약 1.58초의 정지 구간을 확인했다. 가변 프레임률 영상의 타임스탬프 공백은 화면 정지의 보조 근거이며, 어느 CPU 작업이 해당 프레임을 막았는지 증명하지 않는다.

## 확인된 저장 비용과 수정

`GameController.Update`는 튜토리얼 전투 상태를 포함해 3초마다 동기 저장한다. 사용자 행동의 거래에서도 저장할 수 있다. `GameStore.Write`의 칙령 공개 권한 검사는 변경 없는 영웅까지 실행 정책으로 투영한 뒤 스킬 정책을 반복 복사·정규화·비교했다. 실제 튜토리얼 체크포인트의 비공개 사본에서 전체 `GameStore.Save` 호출에 약 600~625ms가 걸렸다. 이 비용은 화면을 멈출 수 있는 실제 게임 내부 작업이지만, 영상의 모든 정지 구간과 일대일로 대응하는 Profiler 프레임은 아직 분석하지 않았다.

소유 코드 [HuntEdictProgression.cs](../../Assets/HELLSCRIPT/Runtime/Core/HuntEdictProgression.cs)의 변경은 두 곳이다.

- 기존에 보관하는 깊은 복사 저장 경계와 현재 영웅의 `build`, `edict`, 패시브 슬롯을 먼저 비교한다. 값이 같으면 공개 권한의 설정 변경 검사용 투영을 만들지 않는다. 값이 다르면 기존 검사를 수행한다.
- `ValidateChange`에서 편집 문서가 원래 문서와 동일하면 항목별 정책 계산을 종료한다.

추천 모드·프리셋·공유 권한 검사는 별도로 계속 수행한다. 영웅 레벨·소유 스킬 검증, 정규화, 파일 기록·교체, 경계 복사와 저장 성공 알림도 유지한다. 저장 간격·실패 처리·전투 틱·보상 거래를 바꾸지 않았다. 새 비동기 저장이나 캐시 계층은 추가하지 않았다.

## 분리 측정 결과

macOS Unity 6000.6.0f1 Editor의 Play를 끈 상태에서 같은 튜토리얼 체크포인트 사본을 읽고 `Stopwatch`로 전체 `GameStore.Save`를 연속 5회 측정했다. 실제 계정·인증 파일을 복사하거나 변경하지 않았다. UI 저장 subscriber와 실행 중인 전투는 포함하지 않는다.

| 상태 | 5회 저장 시간, ms | 5회 동안 Gen0 수집 횟수 |
| --- | --- | --- |
| 수정 전 `53502b35` | 622.2184, 612.8623, 599.5749, 624.9421, 614.7562 | 65 |
| 첫 문서 동일성 검사 `6dda6d6f` | 185.6419, 188.5237, 241.2693, 247.7571, 304.9346 | 4 |
| 저장 경계 비교 추가 `1cd8e027` | 17.8545, 13.1911, 16.4521, 16.4783, 12.7055 | 2 |

최종 범위는 약 13~18ms다. 중간에 통합한 최신 `main`의 장비 상세 변경은 이 측정 대상인 Runtime/Core 파일을 바꾸지 않았다. 로드 시 오프라인 시간 정산과 저장 정규화가 있으며, 각각의 측정은 한 Editor 프로세스 안의 반복 호출이다. 이 결과는 해당 입력의 분리된 저장 호출 비용으로 한정한다. 전체 게임 프레임시간·CPU 사용률·GC 바이트/프레임, 같은 조건의 실제 이전/이후 플레이어 3회 실행, 모바일·웹 성능이나 영상의 모든 멈춤 해결을 검증한 결과가 아니다.

제보 당시 이 작업의 빌드·전체 검사는 실행 중이 아니었다. OS 표본에는 유휴 CPU가 남고 1초 동안 swap 입출력이 없었지만, 다른 프로세스가 멈춤에 기여했는지는 확정하지 않았다. 재현 원본 영상·체크포인트·측정 원자료는 비공개 검증 경로에 보존한다.

## 검증과 남은 확인

최종 코드가 `main`에 반영된 뒤 `HuntEdictProgressionTests` EditMode 34개가 통과했다. 실패 0, 건너뜀 0이다. 기존 공개 일정·공식 간편 정책 검증·기존 계정 접근·직접 저장 차단과 세 직업의 v3 비교 재시작·물약 적용·한 번만 지급하는 보상을 포함한다.

새 회귀 검사는 세 직업에서 변경 없는 저장이 성공한 다음, 잘못된 영웅 레벨과 미공개 반복 설정 변경을 각각 거절하고 마지막 성공 저장 파일을 유지하는지 확인한다. 거절 후 복원과 다음 정상 저장도 확인한다. 저장 실패를 의도적으로 일으키는 기존 검사에서 파일 접근 오류 로그 3개가 발생했으며 예상한 실패 경로로 통과했다. 컴파일 오류는 없다. 전체 게임 검사와 새 플레이어 빌드는 수행하지 않았다.

실제 튜토리얼을 같은 구간에서 다시 플레이해 멈춤이 남는지 확인하는 단계는 남아 있다. 남는 정지는 해당 프레임의 주 스레드·GC·입출력과 외부 부하를 다시 좁혀야 한다. 이번 수정은 기존 튜토리얼의 미완료 네이티브 수용 검사를 완료 처리하지 않는다. 로컬 진행을 다시 시작할 때는 [Unity 튜토리얼 계정 초기화](Tutorial_Account_Reset.md)를 사용한다.
