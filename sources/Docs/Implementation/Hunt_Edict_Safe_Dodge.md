# 사냥 칙령의 안전 위치 회피

갱신일: 2026-10-04 · [English](Hunt_Edict_Safe_Dodge.en.md)

바닥 경계가 표시된 공격을 회피하면 가장 가까운 도달 가능한 안전 위치로 이동하고, 해당 공격이 끝날 때까지 그 위치를 유지합니다. 경계 밖으로 나왔다는 이유만으로 추적·접근·선회가 다시 시작되어 위험 구역을 오가는 동작을 막습니다.

원형·고리·직선·부채꼴의 실제 판정 경계에서 작은 여유 거리를 둔 후보를 찾습니다. 기존 시야·벽·착지·적 점유·경로·위험·도착 시간 검증을 유지하며, 안전한 후보끼리는 실제 경로가 짧은 순서로 고릅니다. 회피는 무적 효과가 아니므로 도달 불가능한 위치나 이미 피하기 늦은 공격을 무시하지 않습니다.

## 기다리는 동안의 전투와 시간 그래프

- 회피한 공격의 준비 동작과 실제 공격·투사체·잔여 피해 지대가 끝날 때까지 위치를 유지합니다. 취소된 공격은 즉시 잠금을 해제합니다.
- 사거리와 시야 안에 공격 가능한 적이 있다면 현재 위치에서 공격합니다. 현재 대상이 멀리 있어도 가까운 다른 적을 선택할 수 있습니다. 접근·추적·선회와 이동형 스킬로 안전 위치를 벗어나지 않습니다.
- 새 공격이 안전 위치를 위협하면 다시 회피합니다. 전역 긴급 생존 대응은 계속 작동합니다.
- 이동과 가만히 기다리는 시간은 기존 활동 그래프의 **회피**에 누적됩니다. 실제 공격 중인 구간은 **공격**으로 기록하고 같은 구간을 중복 계산하지 않습니다.

## 소유 상태와 호환

`CombatSimulation.EdictMovement`가 안전 위치를 선택하고, `EdictResponseState`가 회피한 실제 행동·피해 지대의 ID를 보관합니다. `CombatSimulation.EdictResponse`가 수명을 확인하며 기존 이동·대상 선택·조준·클래스 스킬 판단 경로가 이를 따릅니다. 고정 대기 타이머나 별도의 미리보기용 공격 판단을 추가하지 않습니다.

보관한 상태는 기존 진행 균열 스냅샷에 함께 저장됩니다. 오래된 저장에는 빈 목록이 기본으로 들어갑니다. 같은 진행 균열을 다시 열면 대기를 이어가며, 사냥 칙령을 변경하거나 끄면 기존 대기를 해제하고 새 설정을 읽습니다. 활동 기록은 기존 `CombatFeedback`과 HUD·결과 그래프를 재사용합니다.

## 검증

집중 검사 56개가 통과했습니다. 네 가지 경계, 경고에서 잔여 지대로 이어지는 대기, 저장 복원·취소, 가까운 다른 적에 대한 정지 공격, 새 경고 재회피와 누적 회피 시간을 확인했습니다.

병합한 전투 코드의 최종 관련 Edit Mode 검사는 1,289개 중 1,279개 통과, 기존 실패 10개, 신규 실패 0개입니다. 실패 이름과 실제 assertion을 이전 통합 결과와 대조했습니다. 전체 프로젝트 검사를 다시 실행한 결과는 아닙니다.

macOS 개발 플레이어에서 실제 균열·클래스 스킬·월드·활동 HUD를 사용해 안전 위치까지 이동, 2초 정지 대기의 회피 누적, 먼 현재 대상 대신 가까운 다른 적에 대한 W14·기본 공격, 이동형 W11 제한과 피해 지대 종료 후 해제를 확인했습니다. 고정 전투 틱과 별도 저장 경로를 사용한 개발 전용 검사이며 실제 포인터 조작·모바일 실기기·밸런스·성능 검증으로 취급하지 않습니다. 검사 배치의 위치와 캡처 갱신을 고친 뒤 실패한 macOS 검사만 재실행했으며, 변경하지 않은 전투 코드의 Edit Mode 결과를 재사용했습니다.

UI 소유 계약 및 관련 도구 검사 11개도 통과했습니다. UI 배치는 변경하지 않았고 글자 크기별 검사는 실행하지 않았습니다. [전체 검증 기록](SafeDodgeEvidence20261003/validation.json), [안전 위치 대기](SafeDodgeEvidence20261003/safe-waiting-1600x900-ko.png), [제자리 공격](SafeDodgeEvidence20261003/safe-attack-1600x900-ko.png)을 보존합니다.
