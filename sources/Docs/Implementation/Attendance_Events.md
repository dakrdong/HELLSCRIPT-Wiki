# 7일·28일 출석 이벤트

갱신일: 2026-09-24
영어판: [Attendance events](Attendance_Events.en.md)

매일 **한국 시간 00:00**을 기준으로 계정의 접속일을 센다. 7일 출석은 월요일 00:00, 28일 출석은 매월 1일 00:00에 초기화한다. 같은 날 두 트랙의 보상을 각각 받을 수 있다. 캐릭터를 바꾸거나 재접속해도 출석일과 수령 횟수는 늘어나지 않는다.

## 출석과 보상

기간 중 실제 접속한 날마다 1일차씩 누적한다. 예를 들어 목요일에 처음 접속하면 주간 1일차부터 시작하며 다음 월요일에 다시 1일차가 된다. 접속하지 않은 날은 세지 않는다. 이미 출석했지만 받지 않은 보상은 같은 기간 안에서 나중에 받을 수 있으며, 기간이 초기화되면 사라진다. 월간 28일을 채우면 남은 날짜에는 추가 보상이 없고 다음 달까지 완료 상태를 유지한다.

보상 정의는 `Attendance.Reward`가 소유한다. 위키의 **출석 보상 / Attendance** DB도 같은 코드를 읽어 35개 항목을 생성한다.

| 주간 일차 | 보상 |
| --- | --- |
| 1 | 심연 주화 10개 |
| 2 | 3단계 무작위 색상 보석 10개 |
| 3 | 심연 주화 30개 |
| 4 | 골드 10,000 |
| 5 | 심연 주화 50개 |
| 6 | 무작위 부위 코어 5개 |
| 7 | 무작위 부위 전설 상자 1개 |

월간 보상은 같은 순서를 네 묶음으로 확장한다. 전설 상자는 7·14·21일차에 1개씩, 28일차에 2개를 준다.

| 보상 | 1~7일차 | 8~14일차 | 15~21일차 | 22~28일차 |
| --- | --- | --- | --- | --- |
| 첫째 날 · 심연 주화 | 1일: 10개 | 8일: 20개 | 15일: 30개 | 22일: 40개 |
| 둘째 날 · 3단계 보석 | 2일: 10개 | 9일: 20개 | 16일: 30개 | 23일: 40개 |
| 셋째 날 · 심연 주화 | 3일: 30개 | 10일: 60개 | 17일: 90개 | 24일: 120개 |
| 넷째 날 · 골드 | 4일: 10,000 | 11일: 20,000 | 18일: 30,000 | 25일: 40,000 |
| 다섯째 날 · 심연 주화 | 5일: 50개 | 12일: 100개 | 19일: 150개 | 26일: 200개 |
| 여섯째 날 · 코어 | 6일: 5개 | 13일: 10개 | 20일: 15개 | 27일: 20개 |
| 일곱째 날 · 전설 상자 | 7일: 1개 | 14일: 1개 | 21일: 1개 | 28일: 2개 |

월간 합계는 심연 주화 900개, 3단계 보석 100개, 골드 100,000, 코어 50개, 전설 상자 5개다. 보석 색상과 코어 부위는 각 개체마다 추첨한다. 보석은 기존 6종, 코어는 기존 8부위를 사용한다.

전설 상자는 별도로 보관하며 기간 초기화로 없어지지 않는다. 수령 시점의 캐릭터 직업과 최고 클리어 단계(최소 1, 기존 아이템 레벨 상한 적용)를 기록한다. 이벤트 화면에서 상자를 열면 해당 조건의 전설 장비를 무작위 부위로 생성해 현재 캐릭터 가방에 보관한다. 자동 장착·판매·분해는 실행하지 않는다. 가방이 가득 차면 상자를 유지한다.

## 화면과 조작

게임에 입장하면 **7일 출석 → 28일 출석** 순서로 각각 팝업을 보여 준다. 첫 팝업에서 월간 페이지까지 넘겨 봤다면 같은 접속에서 월간 팝업을 반복해서 띄우지 않는다. 각 팝업 아래의 **하루 동안 보여주지 않기**는 서로 독립적인 기기 설정이다. 체크하면 다음 한국 시간 00:00까지 자동 표시하지 않으며, 체크를 해제하면 다음 접속부터 다시 표시한다.

마을과 균열 필드 왼쪽 위의 **이벤트** 버튼은 숨김 설정과 관계없이 1번인 7일 출석을 연다. 2번은 28일 출석이다. 좌우 스와이프, 탐색 탭, 양쪽 화살표로 이동한다. 위아래 스크롤은 보상 목록만 움직인다. 오늘 받을 수 있는 보상, 수령 완료, 아직 출석하지 않은 보상을 문구와 색으로 구분한다. 수령 가능한 보상이 남으면 이벤트 버튼에 표시한다.

공통 `ContentWindowView`의 제목·안전 영역·탐색·본문·고정 행동 영역을 사용한다. 출석 타일은 장비 상세가 아니라 일차별 보상 정의다. 기존 `UiTheme`, `UiFonts`, 보석·주화 이미지와 `RiftRewardChest`를 재사용한다. 전투 중 열면 `ContentWindowHost`가 일시정지와 입력을 관리하고 닫을 때 이전 상태로 복원한다.

## 저장과 경계

`AccountSave.attendance`가 출석·수령 기록과 미개봉 상자를 소유한다. `GameStore` 거래가 지급과 수령 표시를 함께 저장하고, `StoreViewBinding`이 저장 성공 후 표시를 갱신한다. 보석 공간 부족이나 저장 실패 시 일부만 지급하지 않는다. 무작위 결과는 계정·기간·일차별로 고정하여 실패 후 다시 눌러도 재추첨하지 않는다. 기기 숨김 설정은 별도 파일에 저장한다.

저장 스키마는 12다. 기존 저장은 빈 출석 기록으로 시작하며 미래 버전이나 잘못된 기록은 원본을 보존하고 읽기를 중단한다. 지난 기간의 화면에서 누른 수령과 시계를 이전 출석일보다 되돌린 요청은 거절한다. 현재 개발용 로컬 저장·기기 시계를 사용한다. 서버 권위 시각과 서버 계정 인증은 아직 별도의 제품 경계다.

## 참고와 검증

[검은사막 모바일의 공식 주간 출석 이벤트](https://www.world.blackdesertm.com/Ocean/News/Detail?boardNo=4064)에서 이벤트 버튼, 일차별 보상, 직접 수령, 00:00 갱신 흐름을 참고했다. HELLSCRIPT에서는 계정 공유, 별도 주간·월간 초기화와 기존 테마를 적용한다.

- Unity 6000.6.0f1의 관련 Edit Mode 검사 **108개가 통과했으며 실패·건너뜀은 0개**다. [검사 결과](AttendanceEvidence/editmode.xml)에는 주간·월간 초기화, 자정, 윤년·월말·연말, 재접속·캐릭터 변경·중복 요청, 보관 공간과 저장 실패를 포함한다.
- macOS 개발 빌드는 오류 0개로 성공했다. 합성 uGUI 포인터는 실제 레이캐스트로 누를 대상을 확인한다. 접속 순서, 숨김 설정, 수령, 상자 개봉, 스와이프와 스크롤, 날짜 전환과 전투 일시정지 복원을 검사했다.
- 440×956, 956×440, 1440×810, 1440×900, 1680×720에서 한국어·영어와 100%·150% 글자를 조합했다. 두 페이지의 **40개 화면 검사**가 안전 영역, 문구 높이, 고정 행동 버튼의 접근성을 확인한다. 좁은 필드에서는 이벤트 버튼과 보스 정보의 겹침도 검사한다.
- 별도 프로세스로 저장을 다시 열어 출석·재화·개봉한 장비·숨김 설정의 유지, 사용한 상자의 제거와 이벤트 버튼을 통한 수동 열기를 확인했다. [실행 결과](AttendanceEvidence/initial.txt), [재시작 결과](AttendanceEvidence/resume.txt), [범위와 소스 해시](AttendanceEvidence/validation.json)를 함께 보관한다.
- **모바일 실기기는 검사하지 않았다.** 기존 URP 후처리 셰이더 경고는 출석 기능 오류와 구분한다.
