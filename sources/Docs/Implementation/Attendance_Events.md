# 7일·28일 출석 이벤트

갱신일: 2026-09-28
영어판: [Attendance events](Attendance_Events.en.md)

매일 **한국 시간 00:00**을 기준으로 계정의 접속일을 센다. 7일 출석은 월요일 00:00, 28일 출석은 매월 1일 00:00에 초기화한다. 같은 날 두 트랙의 보상을 각각 받을 수 있다. 캐릭터를 바꾸거나 재접속해도 출석일과 수령 횟수는 늘어나지 않는다.

## 출석과 보상

기간 중 실제 접속한 날마다 1일차씩 누적한다. 예를 들어 목요일에 처음 접속하면 주간 1일차부터 시작하며 다음 월요일에 다시 1일차가 된다. 접속하지 않은 날은 세지 않는다. 이미 출석했지만 받지 않은 보상은 같은 기간 안에서 나중에 받을 수 있으며, 기간이 초기화되면 사라진다. 월간 28일을 채우면 남은 날짜에는 추가 보상이 없고 다음 달까지 완료 상태를 유지한다.

보상 정의는 `Attendance.Reward`가 소유한다. 위키의 **출석 보상 / Attendance** DB도 같은 코드를 읽어 35개 항목을 생성한다.

| 주간 일차 | 보상 |
| --- | --- |
| 1 | 심연 주화 10개 |
| 2 | 3단계 무작위 색상 보석 10개 |
| 3 | 심연 주화 30개 |
| 4 | 골드 10,000 |
| 5 | 심연 주화 50개 |
| 6 | 무작위 부위 코어 5개 |
| 7 | 무작위 부위 전설 상자 1개 |

월간 보상은 같은 순서를 네 묶음으로 확장한다. 전설 상자는 7·14·21일차에 1개씩, 28일차에 2개를 준다.

| 보상 | 1~7일차 | 8~14일차 | 15~21일차 | 22~28일차 |
| --- | --- | --- | --- | --- |
| 첫째 날 · 심연 주화 | 1일: 10개 | 8일: 20개 | 15일: 30개 | 22일: 40개 |
| 둘째 날 · 3단계 보석 | 2일: 10개 | 9일: 20개 | 16일: 30개 | 23일: 40개 |
| 셋째 날 · 심연 주화 | 3일: 30개 | 10일: 60개 | 17일: 90개 | 24일: 120개 |
| 넷째 날 · 골드 | 4일: 10,000 | 11일: 20,000 | 18일: 30,000 | 25일: 40,000 |
| 다섯째 날 · 심연 주화 | 5일: 50개 | 12일: 100개 | 19일: 150개 | 26일: 200개 |
| 여섯째 날 · 코어 | 6일: 5개 | 13일: 10개 | 20일: 15개 | 27일: 20개 |
| 일곱째 날 · 전설 상자 | 7일: 1개 | 14일: 1개 | 21일: 1개 | 28일: 2개 |

월간 합계는 심연 주화 900개, 3단계 보석 100개, 골드 100,000, 코어 50개, 전설 상자 5개다. 보석 색상과 코어 부위는 각 개체마다 추첨한다. 보석은 기존 6종, 코어는 기존 8부위를 사용한다.

전설 상자는 별도로 보관하며 기간 초기화로 없어지지 않는다. 수령 시점의 캐릭터 직업과 최고 클리어 단계(최소 1, 기존 아이템 레벨 상한 적용)를 기록한다. 이벤트 화면에서 상자를 열면 해당 조건의 전설 장비를 무작위 부위로 생성해 현재 캐릭터 가방에 보관한다. 자동 장착·판매·분해는 실행하지 않는다. 가방이 가득 차면 상자를 유지한다.

## 화면과 조작

게임에 입장하면 **7일 출석 → 28일 출석** 순서로 각각 팝업을 보여 준다. 첫 팝업에서 월간 페이지까지 넘겨 봤다면 같은 접속에서 월간 팝업을 반복해서 띄우지 않는다. 각 팝업 아래의 **하루 동안 보여주지 않기**는 서로 독립적인 기기 설정이다. 체크하면 다음 한국 시간 00:00까지 자동 표시하지 않으며, 체크를 해제하면 다음 접속부터 다시 표시한다.

마을과 균열 필드 왼쪽 위의 **이벤트** 버튼은 숨김 설정과 관계없이 7일 출석을 연다. 위쪽 탭이나 좌우 스와이프로 28일 출석과 오간다. 받을 보상이 남은 탭과 이벤트 버튼에는 빨간 점을 표시한다. 위아래 스크롤은 본문만 움직인다. 튜토리얼의 **모험 안내** 버튼은 이벤트 버튼 아래에 놓인다. 좁은 전투 화면에서 이벤트 버튼이 보스 정보를 피해 내려가면 모험 안내 버튼도 함께 내려간다.

팝업은 가로와 세로 화면에서 다르게 배치한다. 21:9처럼 넓은 화면에서도 팝업 너비는 900단위를 넘지 않는다.

| 화면 | 선택한 보상 | 7일 출석 | 28일 출석 |
| --- | --- | --- | --- |
| 가로(956×440, PC 16:9·16:10·21:9) | 왼쪽 제단 패널 | 오른쪽 3×2칸과 세로로 긴 7일차 카드 | 오른쪽 7×4 달력 |
| 세로(440×956) | 위쪽 제단 패널 | 3×2칸과 가로로 긴 7일차 카드 | 7×4 달력 |

글자 100%에서는 모든 일차가 스크롤 없이 보인다. 글자를 키우면 칸이 커지고 본문이 스크롤된다. 제단 패널은 선택한 일차의 보상을 제단 위에 올려 보여 주고, 이름·수량·상태·출석 진행 칸과 초기화 날짜를 함께 적는다. 칸을 누르면 그 일차를 선택한다. 창을 열면 받을 수 있는 가장 이른 일차를, 없으면 다음 일차를 먼저 선택한다.

| 상태 | 칸 표시 | 제단 패널 문구 | 수령 버튼 |
| --- | --- | --- | --- |
| 받을 수 있음 | 아이템 뒤 초록빛, 고정 초록색 테두리, 초록 점 | 수령 가능 | **출석 보상 받기** |
| 받음 | 어둡게 가리고 붉은 밀랍 도장 | 수령 완료 | 수령 완료(비활성) |
| 이후 일차 | 기본 칸 | 남은 출석 N일 | 아직 받을 수 없습니다(비활성) |
| 이번 기간에 닿을 수 없음 | 기본 칸 | 이번 기간에는 받을 수 없습니다 | 아직 받을 수 없습니다(비활성) |

"닿을 수 없음"은 초기화 전에 남은 날짜를 모두 출석해도 그 일차까지 쌓이지 않는 경우다. 예를 들어 일요일에 3일차까지 쌓였다면 4~7일차가 여기에 해당한다. 전설 상자 일차(7·14·21·28일)는 금색 윗줄과 따뜻한 바탕으로 구분한다. 칸에는 수량을 짧게 적고(10,000 → 10K), 정확한 수량은 제단 패널에 적는다. 보관 중인 전설 상자는 보상 칸 아래에 나타나며 그 자리에서 연다.

하단 고정 영역에는 수령 버튼과 **하루 동안 보여주지 않기**를 둔다. 가로에서는 한 줄, 세로에서는 두 줄로 놓는다. 탭·스와이프와 기능이 겹치는 좌우 화살표 버튼은 없앴다.

공통 `ContentWindowView`의 제목·안전 영역·탐색·본문·고정 행동 영역을 사용한다. 출석 칸은 장비 상세가 아니라 일차별 보상 정의다. 기존 `UiTheme`, `UiFonts`와 보석·심연 주화 이미지를 재사용하고, 골드·코어·전설 상자·제단·도장은 `AttendanceArt`가 불러온다. 약식 수량은 보석상의 `JewelerSession.Compact`, 맥동은 `ForgeWorkingPulse`, 원형 빛은 `TownCircleGraphic`을 사용한다. 전투 중 열면 `ContentWindowHost`가 일시정지와 입력을 관리하고 닫을 때 이전 상태로 복원한다.

## 팝업 리소스

사용자의 지시에 따라 GPT에 두 이미지를 요청했다. Claude Code가 `codex exec`로 Codex의 내장 이미지 생성을 호출했고, 이미지마다 두 가지 안을 받아 하나를 골랐다. 선택한 원본은 바이트 변경 없이 등록했다.

| 리소스 | 표현 | 선택 이유 |
| --- | --- | --- |
| [출석 팝업 제단](../../Assets/HELLSCRIPT/Resources/Art/Attendance/popup-altar.png) | 빛이 떨어지는 빈 석제 제단과 고딕 예배당. 1254×1254 불투명 RGB | 제단 앞면이 단순해 보상 아이콘이 돋보인다. 다른 안은 제단 앞의 별 문양과 석상이 아이콘과 시선을 다퉜다. |
| [수령 완료 도장](../../Assets/HELLSCRIPT/Resources/Art/Attendance/claimed-seal.png) | 황동 테와 체크 표시가 있는 붉은 밀랍 도장. 1254×1254 RGBA | 어두운 적갈색이 화면 색과 맞는다. 다른 안은 더 밝고 가장자리가 넓었다. |

제단은 정사각형 원화 하나를 패널 비율에 맞게 잘라 쓴다. 원화 위에서 46% 지점의 제단 윗면이 보상 아이콘 바로 아래에 오도록 자르는 위치를 계산한다. `AttendanceArtImporter`는 제단만 1024픽셀 상한으로 가져오고, 도장과 기존 아이콘은 512픽셀로 둔다. Android 예산은 제단 1024픽셀 ASTC 6×6, 나머지 출석 이미지 256픽셀이다.

Codex는 내장 생성 도구에 모델 선택 기능이 없다고 답했고, 네 이미지 모두 모델 정보 없이 반환했다. 그래서 기존 아이콘과 같이 **모델 미확인 개발용 리소스**(`candidate_model_unknown`, `productionApproved=false`)로 기록한다. [요청문과 선택 기록](../Art/Attendance/popup-manifest.json), [알파와 원본 해시 검사](../Art/Attendance/popup-validation.json)를 보관한다. 도장은 가장자리 알파가 1 이하이고 완전 투명 픽셀이 743,404개다. 제단에는 투명 픽셀이 없다. 위키 리소스 DB도 두 이미지를 표시한다.

## 보상 아이콘 교체

골드·무작위 부위 코어·전설 상자의 단순 도형을 투명 PNG로 교체했다. 주간과 월간은 같은 리소스를 사용하며, 보상 수량·수령 상태·저장 규칙은 바꾸지 않았다. 심연 주화와 세 보석을 겹친 무작위 보석 표시는 기존 이미지를 유지한다.

| 리소스 | 표현 |
| --- | --- |
| [골드](../../Assets/HELLSCRIPT/Resources/Art/Attendance/reward-gold.png) | 낡은 금화 여러 개를 겹쳐 묶음 보상을 나타낸다. |
| [무작위 부위 코어](../../Assets/HELLSCRIPT/Resources/Art/Attendance/reward-random-core.png) | 어두운 광물과 황동 테두리 안에 호박색 핵을 배치해 보석과 구분한다. |
| [전설 상자](../../Assets/HELLSCRIPT/Resources/Art/Attendance/reward-legendary-chest.png) | 검은 철제 몸체·황동 장식·호박색 봉인을 가진 닫힌 상자다. |

내장 `image_gen`으로 생성한 1254×1254 RGBA 원본을 바이트 변경 없이 등록했다. 별도의 배경 제거·색상 키·확대 처리는 하지 않았다. `AttendanceArtImporter`가 새 폴더만 Sprite·알파 유지·512픽셀 상한·밉맵 없음·무압축으로 가져온다. 화면에서는 종횡비를 유지하고 입력을 가로채지 않는다.

생성 요청에는 `gpt-image-2`를 지정했지만, 호출 인터페이스와 반환 메타데이터에서 실제 모델명을 확인할 수 없었다. 따라서 **모델 미확인 개발용 리소스**(`candidate_model_unknown`, `productionApproved=false`)로 기록하며 정식 출시 승인으로 해석하지 않는다. [전체 프롬프트와 출처](../Art/Attendance/source-manifest.json), [알파와 원본 해시 검사](../Art/Attendance/alpha-validation.json)를 함께 보관한다. 위키의 출석 보상 DB와 리소스 DB도 같은 PNG를 표시한다.

## 저장과 경계

`AccountSave.attendance`가 출석·수령 기록과 미개봉 상자를 소유한다. `GameStore` 거래가 지급과 수령 표시를 함께 저장하고, `StoreViewBinding`이 저장 성공 후 표시를 갱신한다. 보석 공간 부족이나 저장 실패 시 일부만 지급하지 않는다. 무작위 결과는 계정·기간·일차별로 고정하여 실패 후 다시 눌러도 재추첨하지 않는다. 기기 숨김 설정은 별도 파일에 저장한다.

저장 스키마는 12다. 기존 저장은 빈 출석 기록으로 시작하며 미래 버전이나 잘못된 기록은 원본을 보존하고 읽기를 중단한다. 지난 기간의 화면에서 누른 수령과 시계를 이전 출석일보다 되돌린 요청은 거절한다. 현재 개발용 로컬 저장·기기 시계를 사용한다. 서버 권위 시각과 서버 계정 인증은 아직 별도의 제품 경계다.

## 초록색 수령 가능 표시 — 2026-09-28
