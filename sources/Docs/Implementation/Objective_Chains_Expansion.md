# 정수 운반자·제물 운반 개발 기록

작성일: 2026-09-12 · 이전 단계: [관문 통행](Gate_Passage_Expansion.md)

## 구현한 플레이 흐름

[던전 구성 상세 기획](../Design/HELLSCRIPT_Dungeon_Composition_Detail.md)의 목표 표에 따라 봉인 2개, 정수 운반자 3명, 제물 3개를 사용한다. 5단계 이상에서 **새로 생성한 균열**은 세 종류 중 하나를 선택한다. 1~4단계는 기존 처치 게이지 방식이며, 진행 중이던 이전 버전 지도는 저장된 구성을 유지한다.

| 목표 | 생성과 자동 진행 | 완료 조건 |
|---|---|---|
| 정수 운반자 | 서로 다른 통로방·갈림의 기존 정예 3명에 표식을 붙인다. 방문한 목표 방이나 마지막으로 관측한 위치로 접근하고, 전투에서는 현재 사냥 설정을 따른다. | 지정한 적 3명의 사망을 정산하면 관문이 열린다. |
| 제물 운반 | 서로 다른 전투 방 3곳에 경비가 지키는 제물을 둔다. 경비 처치 후 안전하게 접근하면 즉시 회수한다. 3개를 모두 모으면 보스 전실의 제단으로 이동한다. | 제단에서 전투 시간 1초 동안 제물을 바치면 관문이 열린다. |
| 공통 우회 조건 | 목표를 마치지 못해도 처치 게이지 100으로 관문을 열 수 있다. | 게이지로 열리면 미완료 목표의 상호작용을 종료하고, 그 시점의 진행도를 기록한다. |

목표 종류는 입장 시드에 고정된다. 지도 생성 재시도나 고정 비상 지도 선택으로 목표 종류를 다시 뽑지 않는다. 정수·제물 목표에서는 통로방·갈림 3곳을 확보하도록 곁방 수를 제한한다. 새 두 목표의 대상 방과 보스 전실에는 합계 100게이지 이상의 기존 적을 배치하며, 기존 봉인의 기준값 60은 유지했다.

적의 총수는 일반 110명·정예 8명으로 유지한다. 운반자를 지정하기 위해 적을 추가하거나 능력치를 높이지 않는다. 제단 몸체는 이동을 막지만, 출입구·몬스터·상자·성소 접근과 저주 상자 이벤트의 적 생성 지점을 침범하지 않는 위치를 선택한다.

## 중단·저장·결과 기록

- 정수 처치는 사망 보상 정산 뒤 처리한다. 균열과 목표의 고유 번호로 한 번만 저장한다.
- 제물 회수와 제단 전달도 각각 중복되지 않는 저장 요청을 사용한다. 저장 실패 시 같은 균열에서 멈추고, 재확인 후 이어간다.
- 제단에서 공격받거나 위험이 생기면 전달을 중단한다. 이미 진행한 시간은 남으며, 안전해진 뒤 다시 접근하면 나머지만 진행한다. 지도·일시정지 중에는 진행 시간이 늘어나지 않는다.
- 관문이 열리는 순간 목표 종류, 진행 수, 제물 전달 여부, 개방 이유, 전투 시간을 고정한다. 보스전 이후 시간이 늘어도 결과와 과거 기록에는 같은 내용을 표시한다.
- 관문을 열기 전에 실패·귀환하면 종료 시점의 진행도를 기록한다. 이전 지도에는 정확한 개방 시점을 소급해 넣지 않고 ‘시점 기록 없음’으로 표시한다.
- 지도와 필드 표식은 발견한 정보만 사용한다. 정수 운반자의 숨겨진 현재 위치를 표시하거나 추적하지 않는다.

전투 HUD, 확대 지도, 결과 화면, 지난 균열 기록에 한국어·영어 표시를 연결했다. 임시 표현은 Unity 기본 도형으로 구성했다. 정수 표식, 제물 용기, 제단의 세 표시등과 전달 진행 원이 저장된 상태에 맞춰 바뀐다.

## 병행 작업과 검증 범위

클로드의 별도 능력치·밸런스 작업 폴더는 이번 수정에 포함하지 않았다. 작업 도중 다른 Codex 작업 **「균열 단계별 등급 확률 추가」**가 원본 폴더의 보상 코드와 화면을 수정하기 시작한 것도 확인했다.

이후 검증은 코드 207개를 이전 해시 기록과 대조한 별도 복사본에서 진행했다. 복사본에서만 해당 보상 작업의 새 파일 5개와 공용 파일의 변경분을 제외했다. 원본의 보상 코드·화면·기획서·설정은 되돌리지 않았다. 이 문서의 실행본은 **목표 기능 검증용 실행본**이며, 단계별 보상 확률과 재설정 비용 변경을 포함한 통합 실행본을 뜻하지 않는다. 별도 보상 작업은 최종 기록 시점에 완료되었으며, 두 변경을 함께 포함한 상태의 검증은 다음 단계에서 진행한다.

분리 기준과 파일별 해시는 `Artifacts/Validation/ObjectiveChains/isolation.json` 및 `tested-source-manifest.json`에 기록한다. 현재 원본의 전체 상태와 검증한 복사본을 구분한다.

## 검증 결과

| 검사 | 결과 |
|---|---|
| 최종 복사본 전체 Editor 검사 | 1,287개 통과, 실패·건너뜀 0개 |
| 새 목표 관련 검사 | 생성 10개와 진행·저장·결과 16개 포함 |
| 배치 조합 | 두 테마의 6·7·8개 방, 고정 비상 지도 6종 × 목표 3종 |
| 자동 이동 | 직접 위치를 바꾸지 않고 발견한 제물 3개를 회수해 제단에 전달 |
| 저장 예외 | 회수·전달·정수 처치의 저장 실패, 재시도, 재접속, 중복 요청 및 영웅 동시 사망 |
| 실제 지도 1만 개 생성 | 모두 통과 · 봉인 3,361개, 정수 3,401개, 제물 3,238개 · 생성 재시도 3,157개, 비상 지도 사용 0개 |
| 최종 실행 앱·재시작 | 5회 통과 · 화면 캡처 13장 · 한국어·영어, 1920×1080·1280×720·720×1280·640×360 |
| 파일 연결·검증본 대조 | 코드 207개가 전체 검사 이후 동일 · 기존 보호 대상 300개 유지 · GUID 중복과 C# 메타 누락 0개 |

지도 표본은 5~30단계의 실제 생성 결과다. 관문이 닫힌 상태의 목표·전투 경로와 열린 상태의 이동 경로를 모두 검사했다. 순수 추첨만 반복한 결과와 구분한다.

실행본은 [목표 기능 검증용 macOS 앱](../../Builds/macOS-ObjectiveChains/HELLSCRIPT.app)이다. [최종 검증 요약](../../Artifacts/Validation/ObjectiveChains/validation-summary.json), [소스 파일 기록](../../Artifacts/Validation/ObjectiveChains/final-source-manifest.json), [보관한 Unity 프로젝트](../../Artifacts/Validation/ObjectiveChains/validated-project.tar.gz)와 [압축본 해시·대조 결과](../../Artifacts/Validation/ObjectiveChains/validated-project.json)를 함께 보관한다. 압축본에는 검증에 사용한 Assets·Packages·ProjectSettings·기획 문서가 있으며 Library·임시 파일·다른 작업 폴더는 포함하지 않는다.

초기 검사에서 고정 비상 지도의 제단 공간 부족, 작은 화면의 목표 표시, 세로 화면의 긴 영어 지도 안내를 수정했다. 기존 성소 검사에서 ‘모든 적 제거’가 새 정수 목표까지 완료시키던 준비 조건은 봉인 목표로 고정했다. 제단과 이벤트 생성 지점의 간섭 조건도 추가했다.

검증 로그, 실패했던 중간 검사와 이전 실행 결과를 함께 보관한다. 모바일 실기기의 터치·성능·발열과 장기 난이도·경제 조정은 이 검증에 포함하지 않는다.

## 주요 구현 위치

- 목표 데이터·배치·기록: `Assets/HELLSCRIPT/Runtime/Core/RiftObjectives.cs`
- 자동 진행·중복 방지 저장: `Assets/HELLSCRIPT/Runtime/Core/CombatSimulation.ObjectiveChains.cs`
- 화면과 임시 모델: `Assets/HELLSCRIPT/Runtime/Presentation/GameUI.Objectives.cs`, `WorldView.ObjectiveChains.cs`
- 검사: `ObjectiveChainTests.cs`, `ObjectiveProgressTests.cs`, `RuntimeObjectiveChainSmoke.cs`

이번 목표 확장 다음에는 아직 연결되지 않은 전리품 고블린의 실제 행동·처치 보상과 사냥 칙령 연동을 검토한다. 능력치 화면과 밸런스 작업은 담당 작업의 진행 상황을 확인한 뒤 통합한다.

실행 화면 검토에서 기존 귀환 결과에도 ‘사망 원인 분석’ 버튼이 남는 것을 확인했다. 이후 [목표·보상 통합 단계](Rift_Integration_Expansion.md)에서 실제 사망 결과에만 표시하도록 수정하고, 저장된 로그의 영어 표시도 보완했다. 해당 후속 실행본에는 단계별 등급 확률 변경을 함께 포함했다. 위 검증 수치는 이 문서의 목표 기능 실행본에 대한 당시 결과다.
