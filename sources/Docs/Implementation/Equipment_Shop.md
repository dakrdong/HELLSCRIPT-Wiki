# 장비 상인과 실제 상점 연결

작성일: 2026-09-21 · [English](Equipment_Shop.en.md) · [승인한 상점 시안](../Design/HELLSCRIPT_Equipment_Shop_Proposal.md)

마을의 **장비 상인에게 가까이 가면 구매·판매 버튼이 나타난다.** 구매는 구매 탭, 판매는 판매 탭을 연다. 접근만으로 창을 열지 않으며, 닫으면 같은 NPC 앞에서 이동을 계속할 수 있다. 상점이 열린 동안 뒤쪽 캐릭터 이동은 멈춘다. 별도로 배치한 [갬블 상인](Gamble_Shop.md)도 구매·판매 버튼을 사용하고, 다른 주민은 기존 대화 버튼을 유지한다.

## 실제 데이터와 거래

HTML 예시 계정이나 임의 골드를 게임에 가져오지 않는다. `EquipmentShopWindow`는 실제 `GameStore`, `HeroSave.inventory`, `ItemCatalog`를 읽는 Unity uGUI 화면이다. 기존 창고의 `StorageSurface`, `StorageGlyph`, `EquipmentAtlas`를 재사용한다.

- **구매:** 판매 목록과 현재 장착 비교만 표시한다. 구매하면 골드가 차감되고 실제 가방의 빈칸에 장비가 들어간다. 구매한 상품은 다음 입고까지 구매 완료로 남는다.
- **판매:** 실제 소지품을 위치순 8열 슬롯으로 표시한다. 아이템을 누르면 상세·현재 장착 비교와 판매 버튼을 표시한다. 수동 다중 선택과 확인 후 일괄 판매도 지원한다.
- **되사기:** 판매한 장비 하나가 한 줄을 차지한다. 판매 당시의 ID, 접사, 품질·강화·걸작·재설정 기록을 보존하고 판매가로 되산다. 최근 12개를 초과하는 판매에는 오래된 기록이 삭제된다는 확인을 표시한다.

거래는 계정 복사본에서 검증한 뒤 디스크 저장에 성공해야 원본에 반영한다. 중복 요청은 한 번만 처리한다. 일괄 판매는 확인창을 열 때의 장비 정보와 현재 소유·보호 상태를 다시 비교하며, 하나라도 달라지면 전체 판매를 거부한다. 장착·잠금·프리셋 참조·보석 장착 장비는 항상 보호한다. 골드 부족, 가방 부족, 진행 중인 균열도 거래를 막는다.

## 비교와 화면 배치

2026-09-22부터 모든 장비 비교는 [공통 비교 규칙](../Design/Equipment_Comparison_Rules.md)을 사용한다. 착용품은 왼쪽, 후보는 오른쪽에 배치하며 반지·양손 무기도 같은 장착 계획으로 비교한다. 갬블 획득 상세는 `장착 비교` 버튼으로 공통 비교창을 연다. 자동 선택 설정은 인벤토리 분해와 같은 캐릭터 저장값을 공유한다. 설정 저장과 아이템 선택·거래는 별개다.

선택 전 비교 영역은 비어 있다. 선택한 장비와 현재 장착 장비를 나란히 표시하고, 선택 장비의 각 능력치·접사 뒤에 차이를 괄호로 붙인다. 현재 장착품에만 있는 접사·고유 효과·고정 저항·소켓 효과는 아래쪽의 사라지는 속성 목록에 표시한다. 강화 예상치나 보유 최고 장비 비교는 제공하지 않는다. 기존 저장 데이터에 이미 존재하는 업그레이드 기록만 읽는다.

가로 화면은 거래 목록 왼쪽, 비교 오른쪽이다. 세로 구매 화면은 상품 약 6.5줄 아래에 비교 영역을 둔다. 목록과 두 비교 본문은 각각 스크롤하며 거래 버튼은 고정한다. `UiSafeArea.Current`를 사용해 화면 회전, 실제 안전 영역, 글자 크기에 대응한다.

## 자동 선택

1. 판매할 등급을 체크한다. 기본값은 일반·마법이다.
2. 판매할 장비 종류를 체크한다. 등급과 종류가 모두 맞아야 대상이 된다.
3. 남겨 둘 장비 종류에만 세부 설정을 켠다. 해당 부위의 실제 기본 능력치와 접사별 기준값을 지정한다. 기준 이상인 옵션이 N개 이상이면 판매 대상에서 제외한다. N은 0부터 켠 조건 수까지이며, 0은 제외 조건을 끈다. 없는 접사는 기준값이 0이어도 일치하지 않는다.

세부 설정을 끄면 값을 보존하되 판정에는 사용하지 않는다. 설정은 캐릭터별로 저장한다. **자동 선택 버튼은 저장된 조건으로 체크 목록만 만든다. 설정창을 열거나 수동 다중 선택 모드로 바꾸지 않는다.** 결과를 누르면 상세를 표시하며 체크 목록을 바꾸지 않는다. 실제 판매는 별도 확인을 거친다.

### 간결한 세부 옵션 설정 (2026-09-22)

장비 종류별 대표 옵션을 먼저 표시하고, 나머지는 **＋ 제외 옵션 추가** 목록에서 하나씩 선택한다. 일반 무기는 공격력·치명타 확률·치명타 피해·공격 속도·주 능력치를, 신발은 방어도·이동 속도·회피 확률·물리 피해 감소를 먼저 보여 준다. 원거리 무기의 주 능력치는 민첩성, 지팡이 계열은 지능을 사용한다. 목록은 해당 장비에 실제로 붙을 수 있는 접사만 포함하며, 대표 옵션과 이미 추가한 옵션은 제외한다. 목록 높이는 제한하고 내부에서 스크롤한다.

추가한 옵션을 해제하면 설정 행이 사라지고 추가 목록으로 돌아간다. 대표 옵션 행은 해제해도 남는다. 입력한 기준값은 보존하므로 같은 옵션을 다시 추가해도 다시 입력할 필요가 없다. 기존 저장에서 켜 둔 추가 조건도 모두 표시하며, 화면을 줄이기 위해 판매 보호 조건을 지우지 않는다. 세부 설정을 끄면 옵션 추가와 기준값 입력도 비활성화한다.

옵션을 해제하면 제외 조건 일치 개수의 상한을 켜진 조건 수에 맞춰 줄인다. 조건이 없는 상태에서 첫 조건을 켜면 일치 개수를 1로 설정한다. 조건이 이미 있는 상태에서 사용자가 지정한 0은 유지한다. 설정 저장 전 변경은 임시 상태이며, 창을 닫으면 저장하지 않는다.

관련 Edit Mode 검사 64개가 통과했다. macOS 개발 빌드에서는 버튼을 29번 조작해 추가·해제·중복 방지·기준값 보존·조건 개수 보정·설정 저장·재열기·디스크 재로드를 확인했다. 목록을 열면 화면 안으로 스크롤하고, 선택 후에는 새 설정 행을 보여 준다. 한국어·영어와 1600×900, 440×956, 956×440 창 크기를 확인했으며 모바일 실기기 검증은 아니다. ## 판매 장비의 성장 범위

일반·마법·희귀 장비만 기존 생성기로 만든다. 레벨 상한은 `min(60, 캐릭터 레벨 × 2, max(1, 최고 클리어) + 2)`이다. 부위마다 최대 128개 후보를 검사해 현재 장착품을 교체했을 때 기본 공격 기대값 또는 방어 지표가 약 2~5% 좋아지는 후보를 우선한다. 다른 지표가 1%보다 많이 낮아지는 후보는 개선 후보로 취급하지 않는다. 안전한 후보가 없으면 조건을 완화해 강한 장비를 강제로 생성하지 않는다.

이 지표는 실제 `HeroStats`와 룬 기여를 복사본에서 계산한 **기본 공격·생존 능력치 지표**다. 모든 스킬 운용, 세트 발동, 보스 패턴까지 재현한 전투 승률이나 클리어 시간의 보장은 아니다. 고유 효과·소켓·무기 종류 변경은 단순 수치만으로 개선 판정을 하지 않는다. 기획서의 일반·정예·보스 고정 시드 전투 평가와 단계 건너뛰기 시뮬레이션은 별도 밸런스 검증 과제다.

사냥 획득 기록과 상점 구매 기록은 분리해 저장한다. 구매·되사기·약한 장비 장착·입고 시간 경과로 사냥 기준이 높아지지 않는다. 부위별 누적 구매 지표 상한도 보존해, 장비를 팔거나 약한 상품을 다시 사는 것으로 상한을 낮출 수 없다. 새 사냥 장비나 실제 레벨·최고 클리어 진행에 따라 기준을 갱신한다. 기존 저장은 출처를 알 수 없는 보유 장비를 최초 한 번 기준으로 기록한다.

입고는 60분 또는 실제 레벨·최고 클리어 변경 시 갱신한다. 창을 다시 열거나 구매·장착만 해서는 새 상품을 뽑지 않는다. 일반 가격은 기존 마을 상점 가격과 판매가의 2배 중 큰 값, 희귀 기준가는 `640 × 아이템 레벨 × 부위 계수`이며 마법은 그 절반이다. 부위 계수는 무기·갑옷 1.0, 투구·반지 0.8, 장갑·신발 0.7, 허리띠 0.6, 목걸이 0.9다. 갬블 상점도 이 희귀 기준가를 사용한다. 수치와 가격은 초기 튜닝값이다.

### 가방 무기 체계 연결 (2026-09-21)

한손 지팡이·오브·스크롤·방패·화살·단검 필터를 추가했다. 새 필터는 꺼진 상태로 시작하며, 기존 선택값을 유지하고 지팡이 자동 판매 설정을 물려받지 않는다. 방패의 상세·기준값에는 방어도를 표시하고 새 장비는 해당 벡터 아이콘을 사용한다. 상점 능력치 미리보기도 실제 두 슬롯 교체 규칙을 사용한다. 자세한 내용은 [가방 UI와 두 무기 슬롯](Native_Inventory.md)을 참고한다.
