# 2026-09-25 전체 브랜치 main 통합

갱신일: 2026-09-25 · [English](Main_Integration_20260925.en.md)

작업 시작 시 로컬 브랜치 27개와 워크트리 17개, 원격 브랜치의 커밋을 확인했다. `main`을 제외한 개발 브랜치 26개 중 24개는 이미 `main`에 포함돼 있었다. 남은 `codex/balance-1000-analysis`와 이를 포함하는 `codex/idle-offline-rewards`를 최신 `main`에 통합했다. 출석 보상 이미지와 사냥칙령 간편 프리셋을 포함한 기존 변경을 함께 유지했다.

통합 전 `main`은 `16678cce`, 균열 밸런스는 `3b8f2726`, 방치·미접속 보급은 `47809c65`였다. 브랜치를 삭제하거나 이력을 재작성하지 않고 모든 대상 커밋의 포함 관계를 검사한다. [브랜치·검증 기록](MainIntegration20260925Evidence/validation.json)에 대상과 결과를 보존한다.

## 충돌 해결과 원본 보존

- 영어 문구는 간편 프리셋과 미접속 보급 양쪽을 유지했다.
- 위키 생성기는 출석 보상 이미지와 지급 상자 이미지·DB를 함께 포함한다.
- 공통 UI 문서의 한국어·영어 이력은 양쪽 본문 해시를 모두 보존하고 같은 본문의 중복을 정리했다.
- 원래 `main` 폴더의 미커밋 이미지 임포트 메타데이터 408개는 내용 해시와 패치로 보존했다. 통합 변경과 겹치는 경로는 없었다. 이 파일들을 기능 커밋에 섞거나 되돌리지 않는다.
- 검증용 Unity 실행이 만든 임포트·프로젝트 설정 변경과 과거 진단 보고서의 자동 재생성은 통합 소스에서 제외한다. 사용자의 저장 데이터는 사용하지 않는다.

## 통합 검증

컴파일·검사 대상과 macOS 빌드의 코드·데이터·이미지 1,523개가 같은지 해시로 확인했다. 전체 Edit Mode 결과와 macOS 실행 결과는 [검증 기록](MainIntegration20260925Evidence/validation.json), [전체 검사 원문](MainIntegration20260925Evidence/editmode.xml), [수정 회귀 원문](MainIntegration20260925Evidence/repair-regression.xml), [실행 기록](MainIntegration20260925Evidence/native-results.json)을 따른다. 검사 횟수는 서로 겹치는 실행을 합산하지 않는다.

첫 전체 Edit Mode 실행은 3,873개 중 3,851개 통과, 22개 실패였다. 실패 항목을 실제 결함과 바뀐 개방 조건을 반영하지 못한 검사로 구분했다. 전체 실행을 모두 통과한 것으로 기록하지 않으며, 수정 후 회귀 결과는 별도로 보존한다. 첫 수정 회귀 검사는 351개 중 350개가 통과했고, 남은 예비 맵의 상자 공간 오류를 고친 뒤 [맵 회귀 검사 18개](MainIntegration20260925Evidence/map-repair.xml)가 모두 통과했다. 여기에는 예비 맵 6종 × 보상 시드 5개 × 단계 1·5·30의 90개 생성 조합과 12개 직업별 전투 시드의 통행 검사가 포함된다. 최초 22개 실패 항목 모두 후속 통과 검사로 확인했으며, 수정 후 전체 3,873개를 다시 실행한 것은 아니다.

- 미접속 보상과 소수 잔액이 모두 변하지 않는 접속에서는 금융 거래 기록을 추가하지 않고 정규화·복구 결과와 시각을 저장한다. 저장이 실패하면 같은 구간을 다시 시도하며, 실제 보상·소수 잔액 정산은 기존 원자적 거래를 유지한다.
- 초반 맵의 정예 4마리 중 상자 경비를 입구에서 두 방 이상 떨어진 곳에 확보한다. 상자·성소 후보는 큰 적의 통로와 겹치지 않아야 하며, 최종 통행 검증도 유지한다. 축소된 기존 위치를 사용할 수 없으면 같은 안전 검사를 거친 방 안 보조 위치를 사용한다.
- 출석 스와이프의 Unity 객체 참조에서 C# null 병합을 제거했다. 번역 중복·남은 옛 문구를 정리하고 회전 중 이동 선택지를 설계 표와 맞췄다.
- 보석 물약 60단계·룬 15단계 개방을 사용하는 검사의 계정 전제를 갱신했다. 10단계 전에 얻은 보석은 보관되지만 보석 기능을 조기 개방하지 않는지 검사한다.

방치 사냥은 새 전사와 시작 장비로 실제 1배속 실행했다. 균열 1→2를 235.90초에 연속 클리어했고 실패는 0회였다. 레벨 1→6, 골드 4,737, 강화석 26개를 실제 획득했다. 마지막 클리어를 기준으로 미접속 1시간을 주입한 검사에서는 골드 1,763·강화석 19개를 지급했으며, 보급 창 재열기와 저장 재접속에서 중복 지급이 없었다. OS 시각을 변경하거나 실제로 한 시간 동안 미접속한 검사는 아니다.

기존 지급 상자 실행 검사에는 전설 보상을 10단계에서 받던 과거 전제가 남아 있었다. 게임의 현재 보상은 올바르게 지급됐으며 검사 코드를 수정했다. 새 검사는 10단계에서 전설 없이 상자 5개를 받고, 30단계의 전설 무기 상자를 실제로 수령·개봉한다. [이전 검증 기록](RewardBoxEvidence/Reward_Box_Verification.md)은 당시 결과로 보존하고 현재 규칙과 구분했다.

출석 실행 검사도 자동 저장으로 갱신된 화면 대신 이전 스크롤 객체를 참조하던 부분을 수정했다. 실제 화면의 스크롤 위치를 다시 읽고, 마을 자동 저장이 진행된 뒤에도 페이지와 스크롤 위치가 유지되는지 추가로 검사한다. 두 수정은 실행 검증 코드에 한정하며 보상이나 화면 동작을 바꾸지 않는다.

macOS 검사는 방치·보급, 지급 상자, 콘텐츠 개방, 간편 프리셋과 재시작, 출석과 재시작을 포함한다. uGUI 레이캐스트와 포인터 이벤트로 입력 전후 상태를 검사하며, 세로·가로·PC 비율과 한국어·영어·100%·150% 글자 크기를 확인한다. 모바일 실기기 검증은 아니다.
