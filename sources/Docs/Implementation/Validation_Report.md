# 첫 플레이 빌드 검증 기록

2026-09-08 · Unity 6000.6.0f1 · macOS / Apple M3 Pro

## 확인한 결과

- Unity가 `Hellscript.unity`와 스킬 18개 카탈로그를 생성했다. C# 컴파일 오류는 없었다.
- 최종 Edit Mode 자동 검사 13개가 모두 통과했다. 보스 보상 중복 방지와 캐릭터별 초회 지급 검사까지 포함한다.
- 프로젝트 구성 작업을 다시 실행했을 때 씬, 카탈로그, 빌드 씬 목록의 해시가 같았다. `setup-idempotence.json`에 비교 결과를 기록했다.
- macOS 개발 빌드가 성공했고 BuildReport의 오류 수는 0이었다.
- 실제 macOS 플레이어를 540×960으로 실행했다. 생성 배경·아이콘과 한국어 글꼴을 화면에서 확인했다.
- 실제 플레이어에서 성소의 행동 편집 버튼, 설정 적용, 다수 적 훈련, 1.5배·2배, 일시정지, 조건 편집 후 복귀, 장비 화면과 저장을 확인했다. `runtime-smoke.txt`가 생성되었다.
- 3직업 모두 다수 적 훈련의 적 8명을 처치했다. 전사 6.6초, 궁수 8.6초, 마법사 9.1초였다. 이 수치는 고정된 제품 성능이나 승률을 뜻하지 않는다.
- 별도 로컬 계정으로 실제 1단계 균열을 반복 계산했다. 시도 사이에는 획득 장비를 장착했다. 전사는 2회차, 궁수는 4회차, 마법사는 2회차에 클리어했다. 무작위 배치의 한 관찰 결과이며 밸런스가 확정되었다는 뜻은 아니다.

## 자동 검사 범위

`editmode.xml`의 최신 결과를 기준으로 한다. 검사에는 콘텐츠 ID·장착 수량, 지도 연결·먼 방 이동, 최소 처치 점수, 정지·포탈 동결, 훈련 격리, 소탕 중복 방지·공간 검사, 잠금·전설 보호, 접사·전설 후보 풀, 강화 재료 회수, 저장 복원, 3직업 진행, 보스 보상 중복 방지와 캐릭터별 초회 판정을 포함한다.

## 남은 검증과 한계

현재 URP 템플릿이 사용하지 않는 피사계 심도·Panini 후처리 셰이더에 대해 제거 경고를 출력했다. 해당 후처리 효과는 사용하지 않으며 확인한 화면은 정상 렌더링되었다. 런타임 예외는 발견하지 못했다. 경고 없는 전용 렌더링 설정은 후속 정리 대상이다.

Android 모듈과 시험 기기가 없어 Android 빌드·30fps·발열·터치·글꼴을 검증하지 않았다. macOS에서도 이 기록을 30분 성능 측정이나 전체 콘텐츠 회귀 검증으로 간주하지 않는다. 실제 계정 서버·결제·교차 저장은 연결되지 않았으므로 온라인 서비스 검증 결과도 아니다.

현재 구현 범위와 미완료 항목은 `Playable_Build.md`를 따른다.
