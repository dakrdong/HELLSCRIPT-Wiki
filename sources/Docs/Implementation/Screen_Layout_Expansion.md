# 화면 배치 대응 개발 기록

작성일: 2026-09-09 · 프리셋 대화창부터 적용 중

후속 [장비 목록·비교·일괄 정리 개발 기록](Inventory_Management_Expansion.md)에서는 가방과 창고를 한 영역·두 영역·세 영역으로 재배치하고 선택·필터·정렬·읽던 문단·처리 확인 내용을 유지한다. 아래 프리셋 단계의 발견과 검사 수는 당시 기록으로 보존한다.

후속 [전투 HUD·카메라 배치 개발 기록](Battle_Layout_Expansion.md)에서는 실제 전투 표시 영역, 16개 창 크기의 배치와 미탐색 정보 가림, 전체 전투 상태 열기를 연결했다. [배속 접근 제한](Speed_Access_Expansion.md)은 그 위에 최신 잠금 정책을 적용한다. 아래 구조 표는 프리셋 단계 당시의 발견 기록이다.

후속 [화면 설정·공통 안내 개발 기록](Screen_Settings_Expansion.md)에서 상단 **설정·안내** 진입, 분류·본문 재배치, 기기별 방향 설정과 전투·반복·초안 보존을 이어서 구현했다. 아래 프리셋 단계의 검사 수와 구조 발견은 당시 기록이며, 최신 설정 창의 검증 범위는 후속 문서를 따른다.

## 적용 기준

[화면 비율·방향 대응 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)의 전체 내용을 읽고 개발 기준에 반영했다. 모바일 가로·세로와 PC에서 기능을 함께 제공하고, 공간이 부족하면 열을 합친다. 화면 방향을 바꾸는 일과 게임 설정을 저장하는 일을 구분한다. 이 기록의 부분 구현을 SCR-01~08 전체 완료로 해석하지 않는다.

사냥 칙령의 편집 범위는 [스킬별 핵심 옵션 v0.2](../Design/HELLSCRIPT_Hunt_Edict_Skill_Option_Catalog.md)를 따른다. 총 89개 항목, 스킬당 자동 사용 포함 4~5개이며 최대 8개를 넘지 않는다. 기존 규칙 편집기를 가로로 배치하는 작업만으로 새 사냥 칙령 화면을 대체하지 않는다.

후속 [핵심 옵션 v0.2 데이터 구현](Hunt_Edict_V2_Expansion.md)은 UI와 분리한 원본에서 스킬 칸 교환·해제 후에도 설정과 공통 공격 순서를 보존한다. 전체 검사 780개가 통과했지만, 이 검사는 실제 화면 재배치·방향 적용·입력 보존의 완료 증거가 아니다. 해당 화면 연결과 SCR-01~08의 남은 범위는 아래 순서를 유지한다.

## 프리셋 단계에서 확인한 구조와 변경 경계

| 영역 | 현재 소유자와 발견 사항 | 다음 변경의 경계 |
|---|---|---|
| 공통 화면 | `GameUI.Initialize`의 주 Canvas는 720×1280 기준 배율을 사용한다. `Base`와 하위 화면에는 고정 폭·높이가 남아 있다. | 공통 목록·상세·하단 작업 영역을 순차적으로 재배치한다. 게임 데이터나 명령을 플랫폼마다 복제하지 않는다. |
| 프리셋 대화창 | `GameUI.Presets`가 이름 초안·슬롯 확인·저장·닫기를 소유한다. | 별도 루트 Canvas에서 표시 배율을 계산하고, 같은 입력 객체와 내용을 유지한 채 요약·입력 영역을 옮긴다. 기존 세로 Canvas의 글자를 확대해서 생기던 흐림을 줄인다. |
| 읽던 위치 | `DialogReadingAnchor`가 현재 보이는 내용 객체와 문단 안의 위치를 기록한다. `DialogScrollRect`가 사용자가 읽던 영역을 구분한다. | 전체 문서 길이의 비율 대신 읽던 항목을 새 영역에서 복원한다. 입력에 초점이 있으면 입력칸의 접근성을 우선한다. |
| 안전 영역·키보드 | 새 대화창은 화면 크기와 안전 영역 변경을 확인하고, 키보드가 차지한 영역 위에 내용을 배치한다. | 모바일의 실제 키보드·노치·복귀 검증이 필요하다. 기존 모든 화면에 적용됐다는 의미는 아니다. |
| 전투 표현 | `WorldView.Present`는 현재 카메라 비율로 확대 정도를 조절하지만, HUD가 차지한 영역을 제외한 전투 표시 영역은 계산하지 않는다. | HUD 배치가 정해진 뒤 카메라 표시 영역을 연결한다. 감지·탐색·생성·사거리·난수 상태는 표현 변경과 분리한다. |
| 실행과 정지 | `GameController`가 전투 진행·일시정지·자동 반복을 관리한다. | 화면 설정 진입 전의 정지 사유와 반복 대기시간을 보관하고 닫을 때 복원한다. 창 크기 변경을 정지 명령으로 사용하지 않는다. |
| 기기 설정 | 모바일 방향 선택과 기기별 저장은 아직 없다. | 실제 방향 적용과 저장 성공을 따로 처리한다. 계정·영웅·공유 코드에는 방향 값을 넣지 않는다. |

새 대화창의 PC 배율은 1이며 읽기 좋은 최대 크기를 둔다. 모바일의 표시 밀도 계산은 초기 구현일 뿐 실기기 검증을 거친 확정값이 아니다. PC의 640×360 창을 포함한 시험은 해당 대화창의 검토 범위이며, 게임 전체의 최소 지원 크기를 확정하지 않는다.

## 이번 변경

- 넓은 공간에서는 요약과 이름 입력을 나란히, 좁은 공간에서는 한 열로 배치한다. 저장·닫기와 미저장 이탈의 세 가지 선택은 본문 스크롤 밖에 둔다.
- 창 크기가 바뀌어도 입력칸을 다시 만들지 않는다. 입력 문자열과 확인 대상 슬롯, 이름 초안은 그대로 유지한다.
- 두 영역을 합치거나 나눌 때 읽던 문단을 따라 스크롤 위치를 복원한다. 줄바꿈에 따라 문단 높이가 달라지는 점을 고려한다.
- 프리셋 이름에 들어간 `<b>` 등의 문자열을 서식으로 해석하지 않고 그대로 표시한다.
- 장비·전투·보상 처리와 씬·카메라에는 이 배치 변경을 연결하지 않는다.

## 검증 기록

macOS 개발 빌드는 오류 0건으로 완료했다. 별도의 시험 저장 폴더를 사용해 UI 콜백을 실행하고 Metal 화면을 확인했다. 첫 실행과 실제 프로세스 재시작이 모두 종료 코드 0으로 끝났다. 사용자가 실행 중인 기존 앱과 실제 저장 파일은 교체하지 않았다.

| 검사 | 확인 결과와 범위 |
|---|---|
| 화면 크기 | 720×1280, 1280×720, 1920×1200, 900×900, 640×360, 862×600, 864×600, 1400×900과 짧은 가로 900×360을 확인했다. |
| 열 전환 경계 | 안전 영역에 여백을 뺀 카드 폭 840을 기준으로 두 열을 사용한다. 실제 창 폭 862에서는 한 열, 864에서는 두 열이 되며 이름을 유지했다. 이 값은 현재 대화창의 시험 기준이다. |
| 읽던 항목 | 짧은 가로 창에서 마지막 요약 문단을 읽다가 640×360으로 합치고 다시 두 열로 나눴다. 해당 문단의 표시와 이름 초안·계정 불변을 확인했다. |
| 저장·닫기 | 주요 버튼이 안전 영역 안에 있고 본문과 겹치지 않는지 검사했다. 미저장 이름의 저장·폐기·계속 편집하기 선택을 확인했다. |
| 실패·재시작 | 의도한 파일 쓰기 실패에서 실제 슬롯·디스크·입력 초안을 유지했다. 재시도·이름만 변경·불러오기 미리보기·프로세스 재시작 후 5번째 슬롯 복원을 통과했다. |
| 시각 검토 | 작은 창의 글자 흐림이 개선됐다. 이름과 안내 문장의 줄바꿈, 마지막 요약 문단과 고정 버튼을 확인했다. 저장 실패는 재시도 안내로 표시하고 자세한 파일 오류는 로그에 남긴다. 일부 이모지의 빈칸 표시는 남아 있다. |

첫 경계 시험은 macOS가 요청한 863픽셀을 864픽셀로 적용해 창 크기 일치 검사에서 중단됐다. 첫 실패 증거를 보존하고 실제 적용 가능한 짝수 폭 862와 864로 양쪽 경계를 검사했다. 그 뒤 저장 실패 안내 문구를 다듬고 최종 빌드·실행·재시작을 다시 확인했다.

이전 전체 Edit Mode 검사 682개 이후 변경한 것은 화면·실행 검증 코드다. 전투·경제·저장 핵심 소스는 당시 검사본과 같다. 이번 화면 검증을 682개의 새 검사로 집계하지 않는다. 보호 자산 98개 중 97개가 기준과 같고, 프로젝트 설정에는 기존 Unity Inference 패키지가 관리하는 `SENTIS_ANALYTICS_ENABLED` 기호만 추가됐다. 원문 차이를 기록했으며 씬·프리팹·패키지와 방향 설정은 기준과 같다.

자동 검사에서 사용하는 UI 콜백과 화면 크기 변경은 실제 사람이 키보드로 입력하거나 창 테두리를 끄는 검사와 구분한다. 모바일 방향 전환·물리 터치·운영체제 복귀·노치·글자 확대·키보드·진행 중 전투 상태 보존을 완료했다고 표시하지 않는다.

## 이어서 진행할 순서

1. 공통 안내·설정에 적용한 배치 기준을 성소·결과 요약으로 확대하고 가로·세로·PC의 정보를 대조한다.
2. 구현한 모바일 방향의 명시적 적용·기기별 저장·실패 후 재시도를 실제 모바일 기기에서 확인한다. PC의 `가로 구성 · 창 크기에 맞춤` 안내와 설정·안내 창은 후속 구현에 포함했다.
3. 장비 비교의 선택·필터·정렬·읽던 항목·처리 확인 보존은 후속 장비 단계에서 연결했다. v0.2 사냥 칙령의 전체 편집 화면과 초안 보존은 이어서 구현한다. 이름 대화창만의 보존 검사를 전체 편집 페이지의 미저장 이탈 검사로 확대하지 않는다.
4. 전투 HUD·카메라 연결과 동일 훈련 120틱 비교는 후속 배치 단계에서 확인했다. 결과·훈련 비교 페이지와 나머지 관리 화면을 재배치하고 같은 상태 보존 기준을 확대한다.
5. PC의 실제 창 조절·키보드와 모바일의 가로·세로·터치·키보드·백그라운드 복귀를 검증한다. 실패·연속 전환·구형 저장을 포함해 SCR-01~08의 결과를 별도로 남긴다.

현재 모바일 빌드·실기기 검증은 남아 있다. 프리셋 이름의 일부 이모지는 문자열로 보존되지만 기존 글꼴에서 빈칸으로 표시된다. 글꼴 표시와 실제 한글 조합 입력은 이름 기능의 남은 검증 항목이다.
