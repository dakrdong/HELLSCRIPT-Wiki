# 런타임 스모크 실패 원인 조사와 수리

작성일: 2026-09-11 · 실패 6건의 원인과 처리

## 조사 배경과 방법

[터치 영역·안전 영역 작업](Touch_And_Safe_Area_Expansion.md)에서 26종의 런타임 스모크를 처음으로 한 번에 돌리면서 실패 4건을 확인했다. 같은 검사를 그 변경 이전 빌드에서도 실행해 실패가 그대로 재현되는지 먼저 확인했고, 네 건 모두 재현되어 원인이 그 이전에 있음을 확정했다. 이후 조사에서 겉으로는 멈춤처럼 보이던 2건이 더 드러나 모두 6건을 처리했다.

원인은 모두 검사 쪽의 낡은 가정이었다. 게임 코드는 한 줄도 바꾸지 않았다.

## 원인 1: 배속 잠금과 시간 예산

현재 정책은 1배속만 허용한다. `CombatSpeedAccess.CanSelect`는 1배속 외의 요청을 거부하고 `Resolve`는 저장값도 1배속으로 읽는다. 그런데 스모크 17개가 `SetSpeed(1.5)`나 `SetSpeed(2)`를 호출하고 있었고, 이 호출은 조용히 거부되며 잠금 안내만 띄운다.

전투가 짧은 검사들은 여유 시간 덕분에 계속 통과했지만, 60초짜리 훈련이나 균열 한 판을 기다리는 검사는 2배속을 전제로 잡은 시간 예산 안에 끝나지 못했다.

| 스모크 | 기다린 것 | 이전 예산 | 지금 |
|---|---|---|---|
| 고정 훈련장 | 훈련 60초 완료 | 38초 | 90초 |
| 훈련 A/B 비교 | A와 B 각각 60초 완료 | 40초 | 90초 |
| 첫 플레이 | 균열 한 판 완료 | 180초 | 480초 |
| 첫 플레이 | 훈련 60초 완료 | 40초 | 90초 |

거부되는 배속 요청은 모두 1배속 요청으로 바꿨다. 배속 잠금 자체를 확인하는 스모크만 예외로 두었다. 실제로 첫 균열은 전투 시간 214초가 걸렸고 전체 첫 플레이 흐름은 285초에 끝난다.

## 원인 2: 증거 문구가 사실과 달랐다

스모크 9개의 통과 기록이 "at 2x", "resumes at 1.5x"처럼 실제로는 일어나지 않은 배속을 적고 있었다. 배속 잠금이 들어온 뒤로 이 문장들은 사실이 아니다. 해당 문구를 모두 고쳐 지금 실행되는 1배속만 주장하게 했다.

## 원인 3: 행동 연속성과 충전 고정값

돌진·충전 스모크는 회오리 충전을 0.3초로 심고 곧바로 도약이 시작된다고 가정했다. 지금은 설정을 적용해도 이미 시작한 채널링이 다음 0.25초 경계에서 끝난다. 채널 종료와 다음 판단, 도약 준비 0.15초를 더하면 0.3초를 넘기므로 충전이 예약되기 전에 사라졌다.

게임 동작은 의도한 대로다. 검사의 고정값을 1초로 올려 채널 종료와 준비를 견디게 했다. 예약이 충전을 0으로 만든다는 확인 자체는 그대로 남는다.

## 원인 4: 접사 재설정 버튼의 이름 변경

기본 스모크는 재설정 선택 버튼을 "선택"이라는 낱말로 찾고 있었다. 현재 이름은 `접미 · 힘 +12 [T3]` 형식이라 찾지 못했다. 앞머리로 찾도록 바꿨다.

이 스모크에는 예외가 났을 때 프로세스를 끝내는 처리가 없어서, 실패가 무한 대기처럼 보였다. 다른 스모크와 같은 종료 처리를 넣어 실패가 종료 코드 1로 드러나게 했다.

## 원인 5: 읽음 표시를 장비 변경으로 셌다

첫 플레이 스모크는 장비 비교 화면을 연 뒤 소유 장비가 그대로인지 JSON 전체로 비교했다. 상세를 열면 그 장비의 읽음 표시가 켜지므로 비교가 실패했다. 읽음 표시는 새 장비 배지를 지우기 위한 의도된 동작이다.

장비 비교에서 읽음 표시만 제외하고, 표시가 실제로 켜졌는지는 따로 확인하도록 바꿨다. 값 하나를 빼는 대신 확인 항목이 하나 늘었다.

## 남긴 개선

- 실패 메시지에 실제 값을 넣었다. 돌진 스모크는 기술·단계·경과·충전·세트 수를, 첫 플레이는 처음으로 달라진 장비의 이전과 이후 내용을 출력한다. 이번 조사에서 원인을 가른 것이 이 출력이다.
- 기본 스모크가 예외에서 종료 코드 1로 끝난다.

## 검증

macOS 개발 빌드로 26종을 순서대로 실행해 모두 종료 코드 0을 확인했다. 결과는 `Artifacts/Validation/P4Suite/results.txt`에 있다. 이전 빌드와의 대조 기록은 `Artifacts/Validation/P4Regression`과 `Artifacts/Validation/P4Older`에 남아 있다.

Edit Mode 검사는 이번 수리로 바뀌지 않는다. 고친 파일이 모두 런타임 스모크이기 때문이다.
