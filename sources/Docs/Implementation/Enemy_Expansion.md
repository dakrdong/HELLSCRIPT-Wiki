# 일반 몬스터와 정예 특성의 전투 구현

작성일: 2026-09-09 · 단계: D3 진행 중

## 1. 적용한 기획과 구현 범위

[일반 적·정예 전투 상세 시험안](../Design/HELLSCRIPT_Enemy_Combat_Detail.md)을 먼저 작성하고, N01–N12의 행동과 E01–E06의 특성을 연결했다. [플레이 완료 기준](../Design/HELLSCRIPT_Gameplay_Completion_Checklist.md)의 4.2·4.3과 CHK-C05·CHK-P02·CHK-P04에 해당하는 작업이다. 피해·사망 정산은 [정산 개발 기록](Outcome_Expansion.md), 영웅 장판은 [장판 개발 기록](Area_Expansion.md)의 공통 처리를 이어 쓴다.

이번 단계의 피해량·사거리·주기·예고 시간은 시험값이다. 정식 보스 3종의 갈고리·광선·소환·연속 폭발은 다음 단계다. 기존 보스의 공통 동작으로 균열을 클리어한 결과를 정식 보스 패턴 완료로 집계하지 않는다.

## 2. 적의 판단·공격·이동

| 묶음 | 구현한 차이 |
|---|---|
| N01·N06·N07·N12 근접 | 준비 시작 방향을 고정한 전방 120도 타격을 사용한다. N07은 타격 종료 후 0.8초 동안 뒤쪽 120도에서 받는 직접·기본 공격에 가산 피해 +25%를 적용한다. |
| N02·N08 돌진 | 예고한 직선을 실제로 이동하면서 선분 충돌을 검사한다. 벽에서 멈추며 한 돌진에서 한 번만 피해를 준다. N08의 두 번째 돌진은 마지막 관측 위치로 다시 조준하고 0.6초 예고한다. |
| N03·N09 사격 | 독립 투사체를 발사한다. 사거리와 사선 확보를 구분한다. N09의 세 화살은 같은 발동에서 영웅을 한 번만 맞힌다. 발사자가 죽어도 이미 나온 화살은 유지된다. |
| N04·N10 장판 | 준비 시작의 목표 위치 또는 관측 이동으로 예측한 위치를 고정한다. N04는 4초 독 장판, N10은 3초 화염 장판을 만든다. 0.5초 주기와 부분 수명을 처리하며 시전자 사망으로 지우지 않는다. |
| N05 회복 | 회복할 살아 있는 아군이 있을 때만 준비한다. 시전 완료 때 반경·벽·생존을 다시 검사한다. 자신·보스·소환 부하도 회복할 수 있고 사체는 회복하지 않는다. |
| N11 오라 | 벽으로 막히지 않은 4m 안의 다른 아군 공격을 20% 높인다. 같은 오라는 한 번만 적용하고 이탈·사망을 그 틱에 반영한다. 이미 확정한 공격 스냅샷은 바꾸지 않는다. |
| N06·N12 사망 | 본체·사체·사망 공격을 서로 다른 발생 ID로 관리한다. N06은 1초 뒤 폭발하고 N12는 0.9초 뒤 세 방향 파편을 발사한다. 파편도 같은 발동의 중복 적중을 막는다. |

인지 범위는 14m이며 시야를 잃으면 4초 동안 마지막 관측 위치를 추적한다. N10은 최근 0.5초 이내의 관측만 사용해 최대 4m 앞을 조준한다. 숨은 영웅의 미래 이동을 읽지 않는다. 기존 `RiftNavigation`이 위치와 벽 판정을 소유하며, 모델이나 별도 NavMeshAgent가 전투 위치를 덮어쓰지 않는다.

준비 시작에 CD를 소비한다. 기절·빙결은 진행 중 일반 공격을 취소하고 CD를 돌려주지 않는다. 속박은 돌진을 중단한다. 이미 생성한 장판·투사체·사망 예고는 독립적으로 진행한다. 피해와 사망은 기존 0.05초 고정 간격의 통합 정산을 사용한다.

## 3. 정예 조합과 위험 판정

E01 화염과 E02 얼음 고리는 각자 CD로 생성된다. E02는 안쪽 2m·바깥쪽 4m의 실제 고리이며 중심은 안전하다. 적중하면 이동속도를 35% 줄이는 2초 상태를 남긴다. E03은 저장된 연결 상대의 생존·정예 여부·5m 거리를 검사한다. E04는 정면 120도에서 들어온 영웅의 화살·원거리 기본 투사체만 50% 감소시킨다. 근접·연쇄·장판·화염구의 범위 폭발과 혼동하지 않는다. 다른 감소 효과와의 합산은 기존 공통 감소 상한을 따른다.

E05는 가까운 일반 적 사체를 고르고 소비자를 즉시 저장한다. 두 정예가 같은 사체를 다시 선택하지 못하며 N06/N12의 고유 사망 공격과는 공존한다. 보스·소환 부하의 사체는 선택하지 않는다. E06은 생성 이후 생존 시간 10초마다 공격 +10%, 최대 +50%를 쌓는다. 교전 밖에서도 시간이 흐르고 재시작으로 초기화하지 않는다.

원·고리·부채꼴·직선의 공통 자료를 실제 피해, 행동 규칙의 위험 조건, 회피 후보, 상자·보스 진입 안전 확인과 화면 예고가 사용한다. 화살의 직선 예고는 실제 투사체와 같은 벽 끝점을 사용한다. 장판의 원·고리·부채꼴은 영웅 중심점으로, 화살·돌진의 직선은 영웅 충돌 반경을 포함해 검사한다. 준비 중 예고와 이미 발사된 투사체의 이동 표현은 구분한다.

## 4. 저장·화면·소유자

행동 동작 버전을 1에서 2로 올렸다. 적의 준비·돌진 진행·남은 연속 횟수·고정 방향·공격 스냅샷, 관측 이력·정예 CD·분노·후방 취약, 독립 장판·사체 소비를 저장한다. 구형 살아 있는 적은 남아 있던 준비와 조준을 이어 받고 새 상태가 없는 목록만 초기화한다. 과거 생존 시간을 알 수 없는 구형 분노에 임의의 누적 시간을 지급하지 않는다. 이미 사망 정산이 끝난 구형 적에게 사망 공격을 다시 만들지 않는다. 더 새로운 행동 버전은 기존 저장 보호 경계에서 거절한다. 효과 버전 4와 행동 규칙 버전 2는 유지했다.

‘전투 효과와 피해 기록’에서 ‘적의 행동과 위험 확인’을 열면 감지한 적의 상태·준비 시간·연속 횟수·정예 특성·오라·분노·후방 취약과 최근 사건을 확인한다. 닫으면 원래 일시정지 상태를 복원한다. 모델은 골격 없는 임시 몸체로 유지하면서 지원형·사격형·돌진형·폭발형·중장갑의 모양과 준비·돌진 기울기를 구분했다. 위험 윤곽·오라·연결·정면 방벽·후방 취약도 코드로 표현한다.

| 소유 파일 | 역할 |
|---|---|
| `EnemyCombat.cs` | 적의 직렬화 상태, 패턴 정의, 위험 형상과 윤곽을 소유한다. |
| `CombatSimulation.Enemies.cs` | 인지·상태 전환·이동 요청·정예·사망 공격과 사건을 처리한다. |
| `CombatSimulation.Damage.cs`·`Projectiles.cs` | 방향별 투사체 감소, 후방 취약, 연속 충돌과 동일 발동 중복 적중을 처리한다. |
| `CombatSimulation.Outcomes.cs`·`RiftNavigation.cs` | 기존 사망 정산에 독립 사망 공격을 연결하고 벽 끝점을 공유한다. |
| `WorldView.Enemies.cs`·`GameUI.Enemies.cs` | 전투 상태를 읽어 임시 모델·윤곽과 상태 상세 화면을 표현한다. 피해를 판정하지 않는다. |

씬·프리팹·패키지·프로젝트 설정과 이미지 원본을 직접 편집하지 않았다. 기존 프로젝트 구성 도구로 같은 씬·카탈로그를 갱신하고 macOS 개발 빌드를 만들었다. 새 패키지나 생성 이미지는 추가하지 않았다.

## 5. 검사와 실제 재시작

Unity Edit Mode의 최종 결과는 `Artifacts/Validation/enemies-editmode-verified.xml`의 **303/303개 통과**, 58.0094663초다. 기존 256개에 적 콘텐츠 검사 47개를 추가했다. 종류별 준비·CD, 빗나감·중단·연속 돌진, 독립 사망 효과와 같은 상태 복원, 장판 주기·예측·벽, 회복·오라·후방 조건, 정예 조합·고리 경계·방향·사체·분노와 화살 예고의 벽 차단을 포함한다.

초기 돌진 벽 검사 한 건은 정지한 적과 영웅의 거리가 사거리보다 멀어 공격 자체를 시작하지 않던 시험 배치 오류였다. 사거리 안에서 벽을 향하도록 배치를 고쳤다. 이후 화살 예고가 투사체 전용 벽을 통과해 그려지는 공백을 보완하고 같은 벽 끝점을 쓰는 검사를 추가했다. 위 최종 303개 결과는 이 수정 이후의 검사다.

macOS 빌드는 `enemies-build-mac-verified.log`의 `HELLSCRIPT_BUILD Succeeded errors=0`을 확인했다. `enemies-final-source-manifest.json`은 검사 XML, 최종 C# 64개와 실제 실행 DLL의 해시를 기록한다. 검사·빌드 이후 게임 소스를 변경하지 않았다.

네이티브 검증은 사용자 저장과 분리한 `EnemyNativeSave`를 사용해 일반 그래픽 프로세스 3개와 실제 재시작 2회로 진행했다. 세 로그 `enemies-native-checkpoint.log`, `enemies-native-resume.log`, `enemies-native-death-resume.log`의 완료 표지와 종료 코드 0, `EnemyNativeEvidence/runtime-enemies-smoke.txt`의 PASS를 확인했다.

- N08의 첫 돌진이 1.2m 진행된 전투 1.05초에 저장·종료했다. 재실행한 뒤 실행 ID·시간·HP·자원·RNG와 적·장판·사체의 개별 값을 대조했다. 1.5배속으로 이어서 반대 방향의 두 번째 예고를 확인했고, 두 돌진의 피해는 각각 1.40초·2.35초에 한 번씩 발생했다. 실행 ID는 `237bf0514b344f879f095687ed909ba9`다.
- N09 세 화살, N10 고정 장판, N11 오라, N05의 15% 회복, N07의 재준비를 실제 처리기로 진행했다. E01/E02의 독립 예고와 E03/E04 표시도 저장·촬영했다.
- 실제 W03으로 N06/N12를 처치한 뒤 E05가 사체 하나를 선택하도록 진행했다. 전투 1.05초에 폭발 대기 0.55초, 파편 대기 0.45초, 시체 폭발 대기 1.2초를 저장·종료했다. 재실행 후 2배속으로 이어서 각각 1.60·1.65·2.25초에 한 번씩 피해를 적용했다. 사망 정산 2건과 사체 소비 1건은 반복되지 않았다. 실행 ID는 `952b955ff33d437894cb23199bcf0c09`다.

Metal, 540×960 화면 10장을 저장했다. 돌진의 첫 예고·재조준·복원, 화살·장판·오라, 고리·연결, 중첩 사망 예고와 실제 피해 기록을 확인했다. 상태 화면의 한글·버튼에 겹침이나 잘림은 없었으며 긴 기록은 스크롤한다. 위험 윤곽은 임시 표현이며 작은 화면의 최종 대비·2배속 가독성과 물리 터치는 D6에서 검증한다.

검증 영웅은 레벨 30 전사와 합법적인 희귀 장비 8부위다. 개별 패턴 확인용 적은 정지·고HP·공격력 5이고, 보여 줄 공격 외의 기본 CD를 길게 설정했다. 정예 예고를 촬영하기 위해 CD를 한 번 줄였으며 사망 공격 대상 둘은 실제 W03 직전에 HP를 1로 설정했다. UI 메서드를 호출한 검사로서 물리 마우스·터치, 자연 성장, 균형, Android 성능 또는 정식 보스 검증으로 확대 해석하지 않는다.

### 5.1 자동 생성 균열 전체 흐름

별도 `EnemyRiftNativeSave`에서 일반 그래픽 프로세스 2개와 실제 재시작 1회로 전체 흐름을 확인했다. 레벨 30 전사·희귀 장비 8부위·1단계·시드 91367, 상자 탐색 거리 30m와 보스 이후 상자 회수 설정을 사용했다. 중간 저장의 실행 ID·지도 지문·HP·시간·RNG를 다시 실행한 상태와 대조한 뒤 자동 탐색·전투·상자 개봉·보스 처치·결과 정산까지 진행했다.

실행 ID `b434809c752846b18402f0bf216eab14`, 지도 지문 `c8beaf52`에서 **처치 87, 상자 4/6개 개봉, 획득 장비 13개, 전투 시간 286.35초**로 클리어했다. 캐릭터의 최고 클리어가 1단계로 저장됐으며 결과 화면에도 같은 처치·획득 수가 표시됐다. `enemies-native-rift-checkpoint.log`, `enemies-native-rift-resume.log`의 완료 표지와 종료 코드 0, `EnemyRiftNativeEvidence/runtime-rift-smoke.txt`의 PASS를 확인했다. 화면 5장은 Metal 540×960이다.

이 결과는 이번 적 변경이 전체 균열 흐름을 끊지 않는지 확인한 사례다. 6빌드·30개 시드의 균형 검사나 자연 성장 결과가 아니다. 이 판의 보스는 아직 공통 동작을 사용한다. 개별 패턴과 전체 흐름을 합친 증거는 `Artifacts/Validation/enemies-validation-summary.json`에 기록한다.

최종 정적 점검에서 C# 64개의 해시가 검사·빌드 기록과 같았고 메타 파일 누락과 GUID 중복이 없었다. 문서 로컬 링크 127개의 대상·절 연결도 통과했다.

## 6. 이어서 진행할 범위

보스 3종의 후속 구현·검증은 [보스 개발 기록](Boss_Expansion.md)에 이어서 정리했다. 아래 목록은 일반 적·정예 단계 종료 시점의 후속 범위다.

1. 보스 3종의 갈고리·소환·광선·연속 폭발·HP 단계별 추가타와 안전 경로를 정식 패턴으로 구현한다. 공통 제압·중단·저장 처리를 연결한다.
2. 전체 패시브·전설·세트의 합법적인 부위 조합과 6빌드의 행동 차이를 검사한다.
3. D4 성장·마을·훈련 비교·결과 분석, D5 온라인 계정·교차 저장·보석·결제, D6 기기·아트·음향·입력·성능의 남은 기준을 진행한다.
