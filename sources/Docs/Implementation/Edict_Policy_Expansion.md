## 적용 범위

[편집 화면](Edict_Editor_Expansion.md)까지 만든 뒤에도 전투가 실제로 읽는 원본 값은 [전투 연결](Edict_Drive_Expansion.md)의 전역 생존 대응뿐이었다. 이 단계는 전역 설정의 나머지 분류인 대상, 위치, 자동 물약, 전리품, 가방, 탐색·상호작용, 반복을 기존 전투 코드가 읽는 값에 연결한다. 공격 순서·자동 사용과 스킬별 조준은 다음 두 단계에서 연결한다.

## 연결 방식

기존 시뮬레이션은 전역 정책을 `State.build`의 필드에서 직접 읽었다. 여기에 `Policy` 접근자를 두고, 정책 필드를 읽는 서른다섯 지점을 모두 이 접근자로 바꿨다. 사냥 칙령이 꺼져 있으면 `Policy`는 `State.build` 그 자체를 돌려주므로 기존 동작은 바이트 단위로 같다. 켜져 있으면 원본에서 파생한 `BuildConfig` 사본을 돌려준다.

파생은 `EdictPolicyBridge.Apply`가 담당한다. 원본을 정규화한 뒤 `State.build`의 사본을 만들고 정책 필드만 덮어쓴다. 규칙, 장착 스킬, 패시브는 그대로 사본에 실린다. 실제 `State.build`는 절대 다시 쓰지 않으므로 사냥 칙령을 끄면 영웅은 이전과 완전히 같은 방식으로 돌아간다. 사본은 전투 시작과 빌드 변경 때 다시 만들고, 편집기가 저장 뒤 호출하는 `RefreshEdict`로도 갱신된다.

길찾기 실패로 자동 반복을 끄는 세 지점은 `State.build`와 사본을 함께 끄도록 바꿨다. 하나만 끄면 컨트롤러가 다른 쪽을 읽고 다음 판을 시작할 수 있기 때문이다. 컨트롤러의 반복 흐름과 탐색 모듈의 벽 따라가기도 같은 접근자를 읽는다.

## 대응표

| 전역 설정 | 기존 필드 | 대응 |
|---|---|---|
| 기본 대상 | `target` | 가까운 적·낮은 HP·밀집한 곳은 그대로. 높은 HP는 기존 방식이 없어 가까운 적으로 읽는다. |
| 우선할 특수 대상·순서 | `target` | 켠 항목을 순서대로 보아 보스·정예는 정예 우선, 지원형은 지원형 우선으로 읽는다. 원거리형은 기존 방식이 없어 다음 항목으로 넘어간다. |
| 기본 전투 위치 | `movement` | 무리 중심은 접근, 거리 유지·제자리·선회는 그대로. 가장자리는 기존 방식이 없어 선회로 읽는다. |
| 희망 거리·기준 | `distance` | 직접 지정은 값 그대로, 기본 공격 사거리 기준은 전사 2m, 그 외 10m다. |
| 시계 방향 선회 | `clockwise` | 그대로. |
| 자동 물약·기준 | `potionThreshold` | 켜면 기준 HP, 끄면 0이다. 살아 있는 영웅은 항상 0%를 넘으므로 0은 사용하지 않는다는 뜻이다. |
| 등급별 회수 | `minimumRarity`, `pursueRarity` | 획득 안 함이 아닌 첫 등급이 획득 하한, 전투 후·전투 중 우선인 첫 등급이 추적 하한이다. 지나가며 획득만 고르면 추적하지 않는다. 세트는 기존에 별도 채널이 없다. |
| 가방 부족 대응 | `bagPolicy` | 마을 정리·교체·무시가 그대로 대응한다. |
| 탐색 방식 | `exploration` | 네 가지가 그대로 대응한다. |
| 상자·성소 | `openChests` 등 11개 | 이용 여부, 종류별 무시, 우회 거리, 보스 후 개봉, 저주 상자 허용·최소 시간, 성소 종류가 대응한다. |
| 자동 반복·성공 후·연속 실패 | `autoRepeat`, `advanceOnWin`, `stopAfterFailures` | 다음 단계는 성공 시 진행으로 읽는다. 성공 후 중단은 기존 플래그로 표현할 수 없어 자동 반복 없음으로 읽는다. 사용자가 요청하지 않은 판을 시작하지 않는 쪽을 택했다. |

대응이 없는 항목은 의도를 지어내지 않고 가장 가까운 기존 값으로 읽되 위 표에 그 사실을 적었다. 회피 규칙, 몰이, 추적 한도, 회수 이동 거리, 가방 보호·정리, 시간 부족 대응, 실패 후 하향은 기존 전투에 대응하는 값이 없어 이번 단계에서 연결하지 않았다.

## 검증

전체 Edit Mode 검사 **1,094개**가 통과했다. 이 중 정책 연결 검사는 10개다. 서른다섯 지점을 바꾼 뒤에도 이전 1,084개가 그대로 통과한 것이 꺼진 상태의 동작이 같다는 근거다.

| 검사 | 확인한 결과 |
|---|---|
| 꺼진 상태 | `Policy`가 `State.build`와 같은 객체다. |
| 사본 격리 | 원본을 적용해도 `State.build`가 바뀌지 않고 규칙·장착·패시브가 사본에 실린다. |
| 대응표 | 대상, 위치, 거리, 선회, 물약, 탐색, 상자·성소, 반복의 값이 각각 기존 필드에 놓인다. |
| 특수 대상 | 켠 순서대로 정예·지원형을 고르고, 원거리형과 높은 HP는 다음 항목이나 가까운 적으로 넘어간다. |
| 기본 사거리 | 전사 2m, 마법사 10m로 읽는다. |
| 회수 하한 | 무시·지나가며·전투 후·전투 중 우선의 조합이 두 하한으로 정확히 옮겨진다. |
| 성공 후 중단 | 자동 반복 없음으로 읽는다. |
| 실제 읽기 | 같은 낮은 HP에서 기존 설정은 물약을 마시고, 사냥 칙령의 물약을 끈 실행은 마시지 않는다. 그동안 `State.build`의 값은 그대로다. |
| 갱신 | 원본을 바꿔도 알리기 전에는 그대로이고 `RefreshEdict` 뒤 사본이 바뀐다. |
| 결정성 | 같은 정책의 두 실행이 같은 상태에 도달한다. |
