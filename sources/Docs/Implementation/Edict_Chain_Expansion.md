# 연쇄 번개 사냥 칙령 개발 기록

작성일: 2026-09-13 · [English](Edict_Chain_Expansion.en.md)

상태: **M03의 네 핵심 옵션 연결, 전체 검사와 새 macOS 앱 실행·재시작, 선택한 16판의 진단을 완료했다.**

## 해결한 문제

연쇄 번개 카드의 선택값을 실제 조준에 사용해도, 실행 후보는 이전 자동 행동 규칙에서 만들어지고 있었다. 이제 사냥 칙령을 켠 영웅이 M03을 장착하면 저장된 네 옵션으로 독립적인 실행 판단을 만든다. 이전 규칙이 없거나 꺼져 있거나 옛 조건을 만족하지 않아도 새 설정으로 판단한다. 중복 규칙은 실행 후보 하나로 합치며, 원래 규칙 목록은 수정하지 않는다. 사냥 칙령을 끄면 이전 규칙을 사용한다.

M01·M02·M03은 공통 공격 순서를 따르고 판단 기록에 각 스킬 이름을 표시한다. 사거리 밖의 유효한 첫 대상에는 접근할 수 있으며, 자동 사용을 끄면 해당 접근도 중단한다. 해금 레벨·실제 비용·쿨타임·행동 잠금과 전역 생존 대응은 기존 실행 검사를 따른다.

## 전투에 연결한 네 옵션

| 옵션 | 실제 처리 |
|---|---|
| 자동 사용 | OFF는 새 시전을 제외한다. 이미 지불한 준비 동작의 첫 대상과 예약한 세트 보너스는 유지한다. |
| 사용 방식 | SINGLE은 유효한 첫 대상 한 명이면 사용한다. LINKED는 실제 연결 규칙으로 서로 다른 적 두 명 이상을 예상할 때 사용한다. SAVE_CHARGE는 기본적으로 두 명을 요구하되, SMB 4세트의 실제 남은 충전이 있고 만료까지 1초 이하이면 한 명도 허용한다. 세트가 없으면 LINKED로 판단하고 원래 선택을 보존한다. 서리 폭발을 기다리는 별도 대기 상태는 만들지 않는다. |
| 첫 대상 | ALL은 전체 유효 후보를 비교한다. ELITE는 정예·보스, SUPPORT는 지원형 중 유효한 첫 대상을 먼저 비교한다. 해당 종류가 없거나 모두 첫 사거리 밖이면 다른 유효 후보를 쓴다. 우선 대상군에서 연결 수가 부족하면 다른 군집의 인원을 빌려 시전하지 않는다. |
| 연결 선택 기준 | UNIQUE는 예상 고유 대상 수, TOTAL_HITS는 LM04 재방문을 포함한 예상 총 타격 수를 비교한다. 첫 대상의 우선 대상군 안에서 비교하고, 동률이면 정확한 전역 대상과 가까운 적, 식별자가 작은 적 순으로 고른다. LM04가 없으면 고유 대상 수로 판단하며 저장된 TOTAL_HITS는 유지한다. |

첫 대상은 살아 있고 감지되며 전역 추적에서 제외되지 않아야 한다. 첫 사거리 10m와 시야를 검사한다. 이후 연결은 실제 연쇄 판정대로 현재 감지한 적을 사용하며, 첫 대상 제외 정책이 후속 타격까지 면역으로 만들지는 않는다. 예측은 현재 배치를 사용하므로 준비 중 적이 이동하면 실제 결과가 달라질 수 있다.

## 연결·피해·충전의 경계

다음 대상은 이전 적과 4m 이내이고 시야가 통하며 살아 있어야 한다. 방문하지 않은 적을 먼저 고르고, 거리와 식별자로 동률을 정한다. 기본 타격 한도는 4회, MP03은 1회, 시전 시작에 예약한 SMB 충전은 2회를 추가해 최대 7회다. 예측과 실제 실행이 같은 한도 계산과 다음 대상 선택 함수를 사용한다.

LM04는 각 적을 최대 두 번 방문할 수 있지만 같은 적을 연속 타격하지 않는다. A→B→A는 가능하며, 한 번 타격할 때마다 적용하는 0.8배 감쇠에 재방문 피해 0.5배를 추가한다. LM04는 전체 타격 한도를 늘리지 않는다. 단독 보스는 MP03과 충전이 있어도 한 번만 맞는다.

SMB 4세트는 서리 폭발이 실제로 적에게 맞으면 6초 동안 사용할 충전 두 개를 만든다. 연쇄 번개가 준비를 시작할 때 하나씩 소비하고, 예약한 추가 타격 두 회를 진행 중 행동에 보관한다. 예측·조건 보류·자원 부족·쿨타임·해금 제한은 충전을 소비하지 않는다. SMB 2세트 비용 할인과 LC02는 기존 비용 감소 상한 50%를 따른다.

준비를 마칠 때 첫 대상의 생존·감지·사거리·시야를 다시 검사하도록 수정했다. 대상이 죽거나 사거리 밖·벽 뒤로 이동하면 `ACTION_MISS`를 기록하고 피해를 주지 않는다. 다른 적으로 자동 교체하지 않으며 이미 지불한 자원·충전을 반환하지 않는다. 이 수정은 이전 규칙으로 시전하는 연쇄 번개에도 적용한다. 후속 연결 대상도 발사 시점의 배치에서 다시 고른다.

## 화면과 저장

연쇄 번개 카드에 네 설정의 적용 범위와 충전 소비 시점 안내를 한국어·영어로 추가했다. 새 실행 판단은 `edict:M03`으로 표시한다. [화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)의 본문 스크롤·하단 버튼 접근성·큰 글자·작은 가로 화면을 검증 기준으로 삼는다.

저장 스키마·기존 규칙 목록·씬·프리팹·패키지를 유지한다. 준비 중 첫 대상 우선순위를 바꾸거나 OFF로 저장해도 지불한 시전의 대상과 예약 보너스는 바꾸지 않는다. 검사는 분리된 프로젝트와 전용 저장 폴더에서 수행한다.

## 연쇄 제어 진단의 범위

완료된 [접사 대조 실험](Affix_Audit_Expansion.md)에서 연쇄 제어는 두 접사 체계 모두 클리어율이 낮았다. 후속 진단 도구는 전투 수치를 바꾸지 않고 준비·쿨타임·다른 행동·적 미감지·첫 사거리 밖·그 밖의 상태에 머문 시간과 실제 시전·연결·보스 피해를 수집한다. 시간은 0.05초마다 행동을 처리한 뒤의 상태를 분류한 근사값이며, 그 자체를 지연의 원인으로 단정하지 않는다. 그 밖의 상태도 모든 시전 조건을 통과했다는 뜻은 아니다. 관측 도구가 생성 균열의 결과와 기존 전투 집계를 바꾸지 않는지도 검사한다.

20단계에서 이전 결과의 보스 전 사망·보스 전 시간 초과·보스 등장 후 사망·등장 후 시간 초과를 각각 두 사례씩 선택한다. 시드 인덱스는 0·1·2·3·4·5·9·14이며 무작위 표본이 아니다. 레벨 30과 합법적인 8부위 장비를 고정하고 동일한 지도·적·장비에서 기존 규칙과 현재 사냥 칙령을 비교한다. 사냥 칙령 쪽은 전역 방침까지 포함하므로 차이를 M03 하나의 효과로 해석하지 않는다. 과거 실험과는 실행 코드가 달라졌으므로 과거 런타임을 그대로 재현한 결과도 아니다.

### 선택한 16판의 결과

2026-09-12 15:57:47~15:59:41 UTC에 16판 수집을 완료했다. 각 쌍과 과거 표본 사이의 시드·지도·초기 적·목표·장비 전체 값·최대 HP·기본 피해·능력치 시트가 일치했다. 시전 시작·발사·적중 수를 기존 전투 집계와 대조했으며, 모든 판의 관측 시간 합계가 실제 진행 시간과 허용 오차 안에서 맞았다.

옵션 연결과 충전 소비만으로 낮은 성능이 해결되지는 않았다. 선택한 표본에서는 자원 부족보다 탐색·다른 행동·시전 중단을 먼저 조사할 근거가 있다. 다만 ‘적 미감지’에는 정상 탐험도 포함되며, ‘다른 행동’도 오류를 뜻하지 않는다. 기존 규칙에서 보스가 등장한 네 판의 평균 등장 시점은 232.63초로, 300초 제한의 상당 부분을 이미 사용했다. 보스에게 한 번만 연결되는 조건은 명세대로 유지한다.

다음 단계에서는 중단 사유와 당시 위험·생존 대응을 함께 기록하고, M04 등 남은 핵심 판단을 연결하면서 준비 취소가 불필요하게 반복되는지 확인한다. 보스 도달 전 시간과 단일 보스 피해를 따로 비교한다. 이번 표본을 전체 승률로 확장하거나 접사 가중치·피해 배율을 임의로 조정하지 않았다.

원자료는 `Artifacts/Validation/EdictChain/Diagnostic1/runs.jsonl`, 대조 결과는 `diagnostic-summary.json`이다. 도구는 별도 프로젝트에서 `Hellscript.Editor.BuildIntegrationValidation.RunChainDiagnostics`로 실행하며 `-hellscriptAuditStage`, `-hellscriptChainSeeds`, `-hellscriptAuditOutput`을 받는다. 기존 출력이 있는 폴더는 덮어쓰지 않는다.

## 검증과 실행본

최종 집중 검사 **292개**와 전체 Edit Mode 검사 **1,566개**가 통과했다. 전체 검사는 2026-09-12 15:56:55~16:01:59 UTC에 약 304.19초 동안 실행됐으며 실패·건너뜀은 0개다. 새 M03 검사는 51개, 진단 관측의 비간섭 검사는 1개다. 실제 서리 폭발이 만든 충전 두 개를 연쇄 번개 두 번이 소비하고, 각 시전이 7회 타격하는 연결도 포함한다.

첫 집중 검사에서는 290개 중 289개가 통과했다. 실패한 한 건은 시야 차단을 검사하려고 만든 합성 지도에 호환되지 않는 통로 정보를 남겨 발생했다. 검사 구성을 고친 뒤 실제 서리 폭발 연계와 관측 검사까지 추가해 모두 통과했다. 최초 실패 보고서는 보존한다.

| 실제 macOS 앱 검사 | 확인한 결과 |
|---|---|
| 옵션 편집·저장 | 실제 버튼으로 SAVE_CHARGE·SUPPORT·TOTAL_HITS를 선택했다. 편집 중 원본은 유지되고, 저장 후 메모리와 다시 읽은 파일이 일치했다. 사냥 칙령 사용 전환도 실제 버튼을 사용했다. |
| 충전 대기·시전 시작 | 충전 없는 단독 대상에서는 사용을 보류했다. 검사용 짧은 충전과 연결할 적을 제공하자 지원형을 첫 대상으로 고르고 충전 하나를 준비 시작에 소비했다. 충전을 실제로 생성하는 서리 폭발 연결은 별도의 Edit Mode 검사로 확인했다. |
| 독립 프로세스 재시작 | 준비 중 ELITE·OFF로 저장하고 앱을 종료했다. 재시작 후 원래 첫 대상·자원·시간·예약 보너스를 복원해 7회 타격을 한 번만 실행했다. 각 적은 두 번 이하로 맞았고 같은 적을 연속 타격하지 않았다. 중복 지불·추가 충전 소비·OFF 상태의 후속 시전은 없었다. |
| 화면·정지 상태 | 1280×720·720×1280·640×360에서 한국어·영어와 140% 글자를 검사했다. 문구 높이·번역 누락·하단 버튼 안전 영역 검사를 통과했다. 판단 화면의 언어 변경과 닫기 뒤 실행 중·수동 정지 상태가 각각 유지됐다. |

첫 앱 검사에서는 새 실행 옵션 이름이 기존 균열 목표 검사의 옵션과 겹쳐 종료됐다. 새 검사만 `-hellscriptChainEdictSmoke`·`-hellscriptChainEdictResume`으로 분리했다. 최종 빌드와 `Native2`의 두 프로세스는 2026-09-12 15:58:14~15:58:34 UTC에 성공했다. 전체 검사·진단 소스와 최종 앱 소스의 차이는 이 검사용 옵션 두 이름뿐이며, 그 차이를 별도 보관했다. 전투·화면 처리는 전체 검사 이후 변경하지 않았다.

화면 10장을 보관하고 영어 140% 옵션·작은 가로 옵션·한국어 재시작 판단·재시작 후 전투 화면을 직접 확인했다. 자동 입력은 실제 UI 콜백을 사용했고 전투 배치·시간은 고정했다. 모바일 실기기의 터치·회전·성능을 확인한 결과는 아니다.

새 실행본은 `Builds/macOS-EdictChain/HELLSCRIPT.app`, 증거 폴더는 `Artifacts/Validation/EdictChain/`이다. Runtime C# 172개를 포함한 C#·영어 문구 표 242개가 최종 빌드 소스와 일치하며 C# 메타 누락·자산 GUID 중복은 없다. 소스·기획 입력·원래 설정과 검사용 실행 옵션의 이전 형태를 포함한 653개 파일을 `validated-source.tar.gz`에 보관했다. SHA-256은 `55cec1caeb98aa741755e80e16714679c1e000e213b22e13368e21b56090cbd2`다. Unity가 검증 사본의 머티리얼에 추가한 URP Editor 버전 자료는 차이로 기록하고 원본 자산을 유지했다.

## 남은 개발

다음 범위는 M04 등 나머지 스킬의 고정 판단과 시전 중단 사유를 연결하는 작업이다. 연쇄 제어는 보스 도달 시간과 생존 대응·공격 중단을 함께 조사한다. 여러 단계의 성장·파밍 효용, 전설·세트의 나머지 장착 경계, 모바일 실행과 전체 출시 품질은 계속 남은 작업으로 관리한다.
