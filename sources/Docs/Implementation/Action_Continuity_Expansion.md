# 설정 저장 후 전투 동작 보존 개발 기록

작성일: 2026-09-09 · 기존 행동 편집기의 실행 전환 보완

## 변경한 동작

[사냥 칙령 상세안 6.2](../Design/HELLSCRIPT_Hunt_Edict_Detail.md)의 기준에 따라, 설정이 실제로 달라진 저장에서도 이미 시작한 일반 공격·스킬을 즉시 취소하지 않도록 바꿨다. 공격은 시작할 때 확정한 조준점·착지점·동작 시간·눈보라 추적 모드로 마무리한다. 이미 지불한 비용과 스킬별 쿨타임은 그대로 유지한다.

진행 중인 행동에는 시작 당시 설정 버전, 원래 규칙, 목표 선택 방침, 유효 이동 방식·거리·회전 방향과 후퇴 시 덫 장착 여부를 따로 보관한다. 이후 설정을 바꿔도 이 자료는 새 값으로 덮어쓰지 않는다. 행동의 시작·효과 실행·완료 기록은 해당 행동이 시작된 버전을 가리킨다. 공격력·버프의 피해 계산 시점은 기존 효과 발동 규칙을 유지하며, 설정 저장 시 시간을 진행하거나 피해를 미리 계산하지 않는다.

| 상황 | 처리 |
|---|---|
| 준비·이동·마무리 중 저장 | 동일한 행동 객체와 진행 시간을 유지한다. 새 공격을 다시 시작하거나 비용을 환불·재청구하지 않는다. |
| 회오리 유지 중 변경 저장 | 종료 요청을 남기고, 기존 0.25초 처리 경계에 도달하면 정상 종료한다. 그 경계에서 다음 피해·비용을 추가로 발생시키지 않는다. |
| 회오리 종료 대기 중 재저장 | 남은 처리 시간과 누적 비용을 유지한다. 변경 저장을 반복해 종료 시점을 미룰 수 없다. |
| 회오리 종료까지의 이동·목표 재평가 | 새 규칙의 같은 행을 참조하지 않고, 시작 당시 방침을 사용한다. |
| 설정 행의 순서 변경 | 준비 동작에 개입할 수 있는 기존 상위 생존 규칙의 우선순위를 규칙 ID와 행동·스킬의 일치 여부로 찾는다. 원래 행 번호를 다른 스킬의 우선순위로 오인하지 않는다. 원래 규칙이 사라진 경우에는 새 행을 대신 연결하지 않는다. |
| 일반 중단 사유 | 잘못된 착지점, 갈고리에 끌림, 전투 종료 등 기존 중단 사유는 계속 적용한다. 모든 상황에서 공격 완료를 강제하는 기능은 아니다. |
| 저장 실패·설정이 같은 재저장 | 기존 저장 경로의 보존 규칙을 유지한다. 실패한 저장은 실제 행동에 종료 요청조차 남기지 않는다. |

저장은 [현재 설정 저장 경로](Current_Build_Save_Expansion.md)의 사본 사전 검증 → 파일 기록 → 실제 반영 순서를 그대로 사용한다. 전투 상태 버전은 4로 올렸다. 버전 3 이하의 진행 중 행동은 저장된 설정에서 행동 방침을 보완하며, 이미 발동한 구형 효과를 다시 발생시키지 않는다.

[화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)의 상태 보존 경계도 유지한다. 편집 화면을 연 동안 정지하고, 저장 성공 뒤에는 진입 전 실행·정지 상태로 돌아간다. 이번 변경은 전투 전환의 기반이며, 화면 방향 설정이나 전체 관리 화면의 반응형 배치를 새로 완성한 것은 아니다.

## 검증

집중 Edit Mode 검사 **185개가 모두 통과**했다. 새 동작 보존 검사 39개와 기존 전투·장판·충전·패시브·저장 실패 검사를 함께 실행했다. 17개 비채널 스킬과 세 직업의 기본 공격, 준비·이동·마무리 단계의 저장 복원, 회오리 처리 경계 10가지, 반복 저장, 목표·이동 방침, 규칙 순서 변경과 구형 전투 상태 이관을 포함한다.

전체 Edit Mode 검사 **735개가 모두 통과**했다. [집중 검사 결과](../../Artifacts/Validation/action-continuity-focused.xml), [전체 검사 결과](../../Artifacts/Validation/action-continuity-editmode.xml), [전체 검사 당시 소스](../../Artifacts/Validation/action-continuity-core-source-manifest.json)를 보존했다. 구형 장판 검사에서 설정 변경 즉시 취소를 기대하던 항목은 새 기획에 맞춰 원래 위치·모드로 장판을 한 번만 생성하는 검사로 바꿨다. 구형 보스 이관 검사는 기존 패턴의 완료와 중복 방지 검사를 유지하면서 최종 전투 버전을 현재 버전으로 확인한다.

최종 macOS 개발 빌드는 오류 0건으로 완료했다. 별도 저장 폴더와 [검증용 앱](../../Builds/macOS-ActionContinuity/HELLSCRIPT.app)을 사용해 실제 프로세스를 세 번 실행했고, 모두 종료 코드 0과 각 단계의 완료 표식을 확인했다.

1. 성소·임시 훈련·일반 균열의 저장 실패와 재시도를 다시 검사했다. 자동 생성 균열에서 자연스럽게 시작한 Lv.1 마법사의 화염구를 편집한 뒤, 성공한 변경 저장과 설정값이 같은 재저장 모두에서 원래 시전 객체를 유지했다. 진입 전의 일시정지 상태와 디스크에 기록한 전투 상태도 일치했다.
2. 새 프로세스에서 계정·전투 상태를 대조하고 해당 화염구를 이어서 진행했다. 효과가 한 번만 실행되고 원래 설정 버전으로 기록되는지 확인했다. 이어 Lv.1 전사의 일반 균열에서 자연스럽게 시작한 회오리를 일시정지하고 설정을 바꿨다. 종료 요청만 추가되고 원래 처리 시간·비용·일시정지 상태가 유지된 저장을 만들었다.
3. 세 번째 프로세스에서 회오리 종료 대기 상태를 그대로 복원했다. 저장된 처리 경계에 맞춰 끝났고, 추가 피해나 자원 비용 없이 원래 설정 버전의 완료 기록이 한 번만 남았다.

[저장 후 유지된 화염구](../../Artifacts/Validation/ActionContinuityNativeEvidence/05-no-op-keeps-paused-cast.png), [재시작 후 화염구 준비](../../Artifacts/Validation/ActionContinuityNativeEvidence/10-resumed-in-flight-build.png), [원래 화염구의 효과 실행](../../Artifacts/Validation/ActionContinuityNativeEvidence/11-original-fireball-released.png), [저장한 회오리 종료 대기](../../Artifacts/Validation/ActionContinuityNativeEvidence/06-changed-channel-awaits-boundary.png), [재시작 후 회오리 종료](../../Artifacts/Validation/ActionContinuityNativeEvidence/13-channel-exited-at-boundary.png), [실행 기록](../../Artifacts/Validation/ActionContinuityNativeEvidence/runtime-action-continuity-smoke.txt)과 [검증 요약](../../Artifacts/Validation/action-continuity-validation-summary.json)을 남겼다.

첫 실행의 상태 검사는 통과했지만 화면 검토에서 촬영 도구의 표시 갱신 누락을 발견했다. 검증을 위해 전투 진행을 끈 직후 화면을 찍어, 복원된 적과 캐릭터의 위치가 표시 객체에 반영되기 전이었다. 촬영 전 표시만 동기화하고 전투 상태가 바뀌지 않는지 검사하도록 보완한 뒤 빌드와 세 차례 실행을 반복했다. 첫 실행 자료는 `before-view-sync` 이름으로 보존했다. 전체 735개 검사 이후 변경한 소스는 이 촬영 도구뿐이며 [최종 소스 기록](../../Artifacts/Validation/action-continuity-source-manifest.json)에 구분했다.

이번 실행 화면은 Metal의 720×1280에서 확인했다. UI 콜백·실제 프로세스·렌더링 검증이며 사람의 물리 입력이나 모바일 실기기 검증은 아니다. 보호 자산 98개는 최종 상태에서 단계 시작본과 모두 같다. 검사 중 Unity 패키지가 분석용 정의 기호를 자동 갱신한 차이는 별도로 기록했고, 최종 빌드 후에는 원래 값과 같았다. 씬·프리팹·패키지·화면 방향 설정의 최종 변경은 없으며 기존 실행 앱과 실제 플레이 저장도 교체하지 않았다.

## 남은 범위

1. 일반 균열의 액티브 장착 제한을 해제하는 작업은 아직 연결하지 않았다. 이번 동작 보존을 기반으로 스킬 ID별 쿨타임, 미장착 옵션 보관과 새 장착 구성을 통합해야 한다.
2. 핵심 옵션 v0.2의 89개 항목·새 원본·공유 코드·5칸 프리셋 통합은 별도 후속 작업이다. 기존 규칙 표현을 새 사용자 옵션으로 제시하지 않는다.
3. 패시브를 교체할 수 있는 임시 훈련의 능력치 전환과 새 장비 편집은 일반 균열의 장비·패시브 고정 조건과 구분해 검증해야 한다. A/B 비교의 구성 고정은 유지한다.
4. 전체 편집 화면의 되돌리기·미저장 이탈 확인, 기기별 화면 방향 저장, 모바일 실기기의 방향·터치·키보드·앱 복귀와 전체 화면 배치는 계속 개발해야 한다.

이 단계의 통과로 사냥 칙령 전체나 D3~D6를 완료 처리하지 않는다.
