# 전투 HUD·카메라 배치 개발 기록

작성일: 2026-09-09 · 화면 상세 기획의 전투 화면 부분 구현

## 적용 범위

[화면 비율·방향 대응 상세 기획](../Design/HELLSCRIPT_Screen_Layout_Detail.md)의 전투 HUD와 실제 전투 표시 영역을 연결했다. 성소·장비·사냥 칙령·결과 페이지의 전체 재배치를 완료한 단계는 아니다. 기존 [공통 설정·안내](Screen_Settings_Expansion.md) 위에 전투 상태 읽기 화면을 추가하고, 모든 전투 배치에서 같은 기능에 접근하도록 했다.

전투 화면의 고정 좌표를 화면 크기로 계산하는 배치로 바꿨다. 같은 HP·자원·처치 게이지·보스·스킬·행동·배속 데이터와 기존 명령을 사용하며, 방향별 게임 상태나 전투 로직을 복제하지 않았다.

## 배치 규칙

아래 크기는 안전 영역과 표시 밀도를 반영한 논리 단위다. 실제 모바일 해상도를 그대로 대입해 배치를 선택하지 않는다. PC는 기본 배율 1을 사용한다.

| 구성 | 표시 방식 |
|---|---|
| 넓은 화면 | 너비 960 이상·높이 640 이상에서는 오른쪽에 현재 행동·스킬·미니맵을 배치한다. 왼쪽 위에는 생존·시간·진행 정보를 두고, 그 아래를 전투 영역으로 사용한다. |
| 세로·중간 화면 | 위에는 생존·시간·진행, 아래에는 현재 행동과 스킬을 배치한다. 스킬은 사용 가능한 폭에 따라 한 줄 또는 두 줄을 사용한다. 미니맵은 **지도**로 연다. |
| 작은 세로 화면 | 너비 600 미만·높이 820 미만에서는 스킬 목록을 **전투 상태**로 접고 전투 영역을 확보한다. 창이 커지면 같은 스킬의 상태를 다시 펼친다. |
| 짧은 가로 화면 | 높이 600 미만에서는 상단을 간결하게 하고 현재 행동과 주요 버튼을 유지한다. 스킬별 상태와 긴 설명은 **전투 상태**에서 읽는다. |
| 공통 명령 | 하단에 일시정지/재개·행동 수정·지도·전투 상태·귀환을 둔다. 상단의 **설정·안내**도 유지한다. |

공간이 부족한 현재 행동은 생략 표시를 사용한다. **전투 상태**에서 전체 행동 문장, HP·보호막·자원, 장착 스킬의 해금·동작·쿨타임, 상자·성소·잔향 상태를 읽을 수 있다. 상태창을 연 동안은 전투를 멈추고, 닫으면 기존 정지 상태를 유지한다. 기존 현재 행동 버튼의 판단 기록 진입도 유지했다.

전투 알림은 현재 행동 영역에 잠시 표시하고 전체 문구를 전투 상태에서 읽도록 했다. 화면 크기 때문에 알림이 창 밖으로 나가거나 전투 중앙을 가리지 않게 한다. 다른 관리 페이지의 알림 배치는 이번 변경 범위가 아니다.

## 카메라와 탐색 정보

`GameUI`가 실제 전투 영역을 화면 좌표로 계산하고 `WorldView`가 카메라의 표시 사각형에 적용한다. 상단 상태창·옆 패널·하단 버튼을 그 영역에서 제외한다. 전투 영역 밖은 단색 테두리로 덮어 이전 프레임의 지형이 남지 않도록 한다.

작은 표시 영역에서 영웅이 지나치게 작아지지 않도록 카메라 거리를 조절한다. 주변 맥락을 유지하기 위한 세로 반경 5m·가로 반경 6m의 표시 기준을 두었다. 이 값은 화면 표현의 개발 기준이며 실제 감지·사거리·위험 판정·생성 거리를 변경하는 수치가 아니다.

넓어진 카메라가 미탐색 방을 공개하지 않도록 생성 지형을 방별 표현 객체로 나눴다. 방과 그 장식은 기존 `visited` 기록을 따른다. 통로는 작은 구간으로 나누어 양끝 방을 방문했거나 영웅의 고정 12m 관찰 범위와 기존 시야 검사에 들어온 구간을 표시한다. 카메라의 크기나 방향으로 탐색 기록을 추가하지 않는다. 적과 발견한 상자·성소의 기존 표시 기준을 유지했다.

적 투사체·구형 적 장판과 타격·이동 궤적은 전투의 관찰 기준인 14m와 기존 시야 검사를 적용해 미관찰 위치를 드러내지 않도록 보완했다. 형상 반경을 사용하는 장판은 해당 반경을 포함한다. 생명 연결선도 양쪽 적이 관찰될 때만 표시한다. 피해·이동·생성·난수 계산은 바꾸지 않았다.

이 처리는 자동 생성 균열의 지형에 적용한다. 구형 균열과 훈련의 기존 알려진 지형 구성은 유지한다. 탐색 안개 경계의 미술적 개선과 실제 기기의 렌더링 비용 측정은 남아 있다.

## 구현 소유자

| 파일 | 책임 |
|---|---|
| `BattleHudLayout.cs` | 화면 크기·보스 표시로 배치 영역과 카메라 표시 기준을 계산한다. |
| `GameUI.BattleLayout.cs` | 같은 HUD 객체를 재배치하고 표시 영역·버튼·본문·스킬 요약을 연결한다. |
| `GameUI.cs` | 전투 페이지의 표시 배율과 알림·갱신·기존 페이지 복귀를 연결한다. |
| `GameUI.ScreenSettings.cs` | 기존 공통 창에 읽기 전용 전투 상태 분류를 추가한다. |
| `WorldView.cs` | 카메라 표시 영역·확대 정도를 적용한다. |
| `WorldView.Exploration.cs`, `WorldView.Rift.cs` | 생성 지형의 표시를 기존 탐색·시야 상태에 맞춘다. |
| `WorldView.Actions.cs`, `WorldView.Enemies.cs` | 적 투사체·장판·연결선이 관찰하지 않은 적의 정보를 드러내지 않도록 한다. |

## 검증 기록

전투 배치 단계의 전체 Edit Mode 검사 974개가 통과했다. 이후 적 표시 경계의 표현 코드를 보완하고 macOS 빌드·실행을 통과했다. 해당 표현 보완 뒤에는 핵심 전투 계산 소스를 변경하지 않았다. 별도 저장 폴더에서 실행한 최종 배치 검사는 다음 범위를 확인했다.

| 검사 | 결과 |
|---|---|
| 일반 전투 16개 크기 | 720×1280, 1280×720, 1920×1080, 1920×1200, 900×900, 640×360, 360×640, 768×1024, 958×640, 960×640, 1280×600, 900×360, 390×844, 390×818, 390×820, 3440×1440의 실제 macOS 창을 확인했다. |
| 보스 화면 5개 크기 | 1280×720, 640×360, 360×640, 720×1280, 960×640에서 보스 상태와 위험 예고를 확인했다. |
| 배치·가독성 | 카메라 영역과 HUD의 비중첩, 영웅의 화면 내 배치, 한국어 문장의 높이, 주요 버튼 접근, 보조 스킬의 접힘 경계와 전체 상태 열기를 통과했다. 작은 세로 창의 전투 영역·영웅 크기·하단 여백을 시각 검토 후 보완했다. |
| 미관찰 정보 | 미방문 방·원거리 적·벽 뒤 적·투사체·적 장판·연결선·일시적인 타격 및 이동 효과가 숨겨지는지 확인했다. 관찰 중인 위험 표시는 유지됐다. |
| 상태 보존 | 같은 HUD 객체를 재배치했으며, 렌더링 전후 전체 전투·계정 JSON이 같았다. 편집→설정→창 변경→편집→전투 복귀를 확인했다. |
| 전투 동일성 | 3개 표시 크기를 거치는 훈련 120틱을 표시 없는 동일한 시뮬레이션과 비교해 전체 전투·영웅 상태가 일치했다. |

[작은 세로 화면](../../Artifacts/Validation/BattleLayoutVerifiedEvidence/07-battle-360x640.png), [넓은 전투 화면](../../Artifacts/Validation/BattleLayoutVerifiedEvidence/02-battle-1280x720.png), [전투 상태 화면](../../Artifacts/Validation/BattleLayoutVerifiedEvidence/23-compact-combat-overview.png)을 포함한 이미지 25개가 있다.

위 배치 검사 직후 확인한 [배속 잠금 정책](../Design/HELLSCRIPT_Speed_Access_Detail.md)은 후속 [배속 접근 제한 개발 기록](Speed_Access_Expansion.md)으로 연결한다. 위의 화면은 배속 잠금 반영 전의 배치 증거이며, 최신 실행 파일과 잠금 표시 검사는 후속 기록을 따른다.

후속 잠금 적용 코드에서도 동일한 전투 배치·보스·미관찰 정보·120틱 검사를 다시 통과했다. 최신 [넓은 화면](../../Artifacts/Validation/ScreenLayoutLockedEvidence/02-battle-1280x720.png)과 [작은 세로 화면](../../Artifacts/Validation/ScreenLayoutLockedEvidence/07-battle-360x640.png), [실행 기록](../../Artifacts/Validation/ScreenLayoutLockedEvidence/runtime-battle-layout-smoke.txt)을 확인한다. 배속 정책을 포함한 전체 검사는 990개이며, 상세 범위와 한계는 후속 문서에 기록했다.

모바일 실기기의 회전·밀도·터치·노치·키보드·백그라운드 복귀와 장시간 성능 측정은 남아 있다. PC 실행과 UI 콜백 검사를 모바일 완료나 사람이 직접 입력한 증거로 사용하지 않는다. 다른 관리 화면과 확인창 전체에 이번 배치를 적용한 것으로 표시하지 않는다.
