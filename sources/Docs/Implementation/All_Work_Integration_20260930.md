# 전체 워크트리·브랜치 통합과 정리 — 2026-09-30

작성일: 2026-09-30 · [English](All_Work_Integration_20260930.en.md)

사용자가 모든 워크트리와 브랜치를 `main`에 병합하고 커밋·푸시한 뒤, 남은 워크트리와 브랜치를 지우도록 요청했다. [2026-09-28 통합](All_Work_Integration_20260928.md) 때는 워크트리와 브랜치를 남겨 두었다. 이번에는 병합을 마친 뒤 모두 지웠다.

## 통합 범위

- 시작 기준은 `origin/main`의 `20169eaf`다. 워크트리는 메인 체크아웃을 포함해 11개, 브랜치는 11개, 열린 PR은 3개(#34, #36, #39)였다.
- 메인 체크아웃을 뺀 모든 워크트리에는 커밋하지 않은 변경이 없었다. 메인 체크아웃에는 Unity가 다시 쓴 `.meta` 31개와 추적하지 않는 `.DS_Store`가 있었다. 실행 중인 HELLSCRIPT 세션은 없었다.
- `main`보다 앞선 커밋이 있는 브랜치 6개를 병합했다. 나머지 5개(`claude/ecstatic-rhodes-26a7bd`, `claude/training-ground-mockup`, `claude/tutorial-prologue`, `codex/edict-resume-preset-fix`, `codex/storage-chest-art`)는 이미 `main`에 들어 있었다.

## 충돌과 통합 중 수정

- `Wiki/history/tutorial-progression.json`과 영어판이 충돌했다. 스킬 시작 규칙 브랜치와 F06 브랜치가 게시되지 않은 6번 버전을 각각 추가했기 때문이다. `main`의 이력을 유지하고, 위키 생성이 병합된 기록의 새 버전 하나를 남기게 했다. 공개 위키는 `20169eaf`에서 게시된 상태였으므로 이미 공개된 버전은 사라지지 않았다.
- 튜토리얼 기록에는 두 브랜치의 문단이 모두 들어왔다. 스킬 시작 규칙 브랜치의 문단은 10레벨 W04 보정을 설명한다. 이 문단이 현재 규칙처럼 읽히지 않도록, 같은 날 규칙이 바뀌었다는 문장을 덧붙였다.
- 병합 후 공통 UI 계약 검사가 실패했다. UI 개편 브랜치가 추가한 색상 검사에, 그 브랜치가 마지막으로 `main`을 받은 뒤 들어온 프롤로그 코드의 색상 6곳이 걸렸다. `GameUI.TutorialStaging.cs`의 `f3d9a0` 4곳과 `PrologueGate.cs`의 `262116`·`0f0d09`이다. 가장 가까운 토큰인 `GoldBright`(`f2d9a4`), `Raised`(`211e19`), `Background`(`100f0d`)로 바꿨다. 바꾼 색과 원래 색의 차이는 채널마다 5 이하다. 병합 후 튜토리얼 스모크 캡처에서 프롤로그의 빛과 내레이션 판이 정상적으로 그려지는 것을 확인했다. 이전 캡처와 나란히 비교하지는 않았다.
- 메인 체크아웃의 `.meta` 31개는 별도 커밋으로 넣었다. 훈련장 이미지 26개에는 `ResourceTextureBudget`이 정한 데스크톱·WebGL 제한(초상화 256, 훈련장 2048)이 가져오기 때 기록되었다. 캐릭터 모델 5개는 빈 값 뒤의 공백만 다르다. GUID는 모두 그대로다.

## 검증

- 공통 UI 계약 검사와 검사 도구 테스트 9개가 통과했다. 직업 스킬 생성기 검사 4종, 스킬 트리 프로토타입 재생성(차이 없음)과 엔진 테스트 39개도 통과했다.
- 위키 생성·검사, 위키 테스트 11개, 화면 경로 검사가 통과했다. 공개본과 비교하면 새 문서 2개(UI 스타일 한국어·영어)와 바뀐 문서 23개, 바뀐 DB 3개(skills, class-abilities, resources)가 있다. 사라진 문서는 없다. 모두 병합한 브랜치에서 나온 변경이다.
- 통합 결과로 만든 macOS 개발 빌드에서 런타임 스모크 11종이 모두 통과했다. 튜토리얼(두 프로세스), 스킬 트리·초기화·메뉴·프리셋·칙령 구역, 빠른 프리셋, 직업 스킬, 출석, 이전 균열 가방, UI 스타일이다. 튜토리얼에서 F06은 4레벨에 W02로 완료되었고 레벨 보정은 쓰지 않았다. 궁수와 마법사는 스킬 없이 시작했다.
- 전체 Edit Mode는 4,742개 중 4,695개가 통과하고 47개가 실패했다. 실패 47개는 2026-09-27에 기록한 기존 실패 목록과 같고, 새로 생긴 실패나 새로 고쳐진 실패는 없다.
- 모바일 실기기에서는 확인하지 않았다. 웹과 APK는 다시 빌드하지 않았다.

## 정리

- 지우기 전에 모든 참조를 저장소 밖 번들로 보관했다. 경로는 `~/HellscriptBackups/hellscript-all-refs-20260930.bundle`이고 SHA-256은 `bb1973b591a5d89eae11d20b3950dfa06149ea3501cf94f694bb1097aee40c36`이다. `git bundle verify`가 통과했다. 참조 목록과 워크트리 목록도 같은 폴더에 있다.
