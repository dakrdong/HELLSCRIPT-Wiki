# 갬블 상점

작성일: 2026-09-21 · [English](Gamble_Shop.en.md) · [장비 상점](Equipment_Shop.md)

## NPC와 진입

장비 상인과 **별개의 갬블 상인**을 마을 남쪽 길의 보석 상인과 룬 상인 사이에 배치한다. 보라색 천막과 봉인된 꾸러미 진열대로 구분한다. 가까이 가면 구매·판매 선택지가 나타나며, 구매를 누르면 갬블 구매 탭, 판매를 누르면 소지품 판매 탭을 연다. 접근만으로 상점을 열지 않는다. 기존 계정 해금 규칙에 따라 어느 영웅으로든 균열 10단계를 클리어하면 구매가 개방된다. 해금 전에는 상품 안내에서 조건을 표시한다. 기존 제작 화면의 미확인 장비 구매 버튼은 **갬블 상인 찾아가기**로 바꿔 같은 NPC로 안내한다.

장비 상점과 창고의 올리브색 바탕, 황동 테두리, 실제 장비 아이콘을 공유한다. 판매·되사기·자동 선택 설정은 장비 상점과 같은 화면과 실제 소지품을 사용한다. 되사기 보관함과 자동 선택 설정은 캐릭터별로 두 상점이 공유한다.

## 구매 전 정보와 고정 가격

상품은 무기·투구·갑옷·장갑·신발·허리띠·목걸이·반지의 8개 부위다. 구매 전에는 물음표 아이콘, 부위, 아이템 레벨, 가격만 표시한다. 실제 이름·등급·공격력·방어도·접사·고유 효과는 숨긴다. 무기는 구매 캐릭터가 사용할 수 있는 실제 무기군에서 생성한다.

가격은 **동일한 부위·레벨의 장비 상점 희귀 기준가 × 2**로 고정한다. 숨겨진 등급이나 옵션, 현재 입고 목록과 무관하다. 기준가를 희귀로 통일해 같은 상품의 가격이 매번 변하지 않게 한다. 골드만 사용하며 구매 시점에 가격과 가방 여유를 다시 확인한다.

`희귀 기준가 = 640 × 아이템 레벨 × 부위 계수`

| 부위 | 부위 계수 | 레벨 10 희귀 기준가 | 레벨 10 갬블 가격 |
| --- | ---: | ---: | ---: |
| 무기 | 1.0 | 6,400 | 12,800 |
| 투구 | 0.8 | 5,120 | 10,240 |
| 갑옷 | 1.0 | 6,400 | 12,800 |
| 장갑 | 0.7 | 4,480 | 8,960 |
| 신발 | 0.7 | 4,480 | 8,960 |
| 허리띠 | 0.6 | 3,840 | 7,680 |
| 목걸이 | 0.9 | 5,760 | 11,520 |
| 반지 | 0.8 | 5,120 | 10,240 |

위 금액은 초기 밸런스값이다. 레벨은 장비 상점과 같은 상한인 `min(60, 캐릭터 레벨 × 2, max(1, 최고 클리어) + 2)`를 사용한다. 기존 미확인 장비 생성 규칙인 마법 60%, 희귀 38%, 전설·세트 합계 2%를 재사용한다. 갬블은 무작위 결과이므로 현재 장착품보다 항상 좋아지지는 않으며, 장비 상점의 약 2~5% 개선 후보 정책은 적용하지 않는다. 구매 결과로 장비 상점의 사냥 획득 기준을 높이지 않는다.

## 구매와 공개 연출

1. 구매를 누르면 실제 아이템을 생성하고 골드 차감·가방 배치·저장을 한 거래로 완료한다. 저장에 실패하면 차감이나 아이템 지급도 반영하지 않는다.
2. 저장 성공 후 화면을 어둡게 덮고 물음표 아이콘이 두 번 커지는 박동을 재생한다. 약 1.7초 뒤 짧은 빛과 확대 연출로 장비를 공개한다. 연출 중 새로 추첨하지 않는다.
3. 결과창의 왼쪽 중앙에는 실제 아이콘을 표시한다. 오른쪽은 기존 장비 상세 카드를 그대로 사용해 작은 아이콘과 이름, 등급·레벨·기본 능력치·접사와 범위·고유 효과·소켓·기존 업그레이드 기록·판매가를 표시한다. 현재 장착품과의 차이는 각 수치 뒤 괄호에, 교체 시 사라지는 속성은 하단에 표시한다. 상세는 스크롤할 수 있다.
4. 하단 중앙의 **연출 제거** 체크는 기기에 저장한다. 체크하면 이후 구매에서 박동과 공개 연출을 건너뛰고 결과창을 즉시 표시한다. 결과창 자체는 유지한다.
5. 그 아래 **확인**을 누르거나 창 바깥을 누르면 닫힌다. 창 내부를 누르거나 상세를 스크롤하는 것으로 닫히지 않는다. 공개 도중 닫아도 이미 지급된 아이템은 남는다.

PC와 모바일 가로·세로에서 같은 구조를 사용한다. 가로는 목록 왼쪽·구매 안내 오른쪽, 세로는 약 6.5줄 목록 아래 구매 안내다. 결과창은 모든 방향에서 아이콘 왼쪽·상세 오른쪽을 유지하며 안전 영역 안에 배치한다. 구매 후에는 판매 탭이나 일반 인벤토리에서 실제 장비 상세를 확인할 수 있다.

## 결과 화면의 시각 구성

결과창은 큰 배경 판 없이 중앙에 모인 아이콘과 상세 카드로 구성한다. 뒤의 상점은 짙게 어둡게 처리한다. 아이콘 뒤에는 등급색을 약하게 반영한 광륜과 작은 빛 장식을 두고, 사각 슬롯 배경은 제거한다. 제목 아래 장식선, 상세 카드 모서리, 확인 버튼에는 기존 올리브·황동 계열의 가는 장식을 사용한다. 연출 제거를 체크하면 박동·회전·섬광을 재생하지 않으며 장식은 정지된 상태로 남는다.

상세 카드는 화면 폭에 따라 가로로 늘리지 않는다. 기준 좌표의 최대 폭은 304이며 세로 화면에서는 화면 폭의 66% 이내로 제한한다. 카드 높이는 실제 내용 높이에 맞춰 줄이고, 화면 높이가 부족하면 카드 내부만 스크롤한다. 스크롤이 필요한 경우 오른쪽에 가는 스크롤바를 표시한다. 실제 화면 크기는 기존 상점 캔버스 배율을 따른다. 정보 내용과 장착품 비교는 기존 상세 카드 구성요소를 그대로 사용한다.

시각적인 참고로 [Diablo IV 공식 아이템 카드 화면](https://news.blizzard.com/en-gb/article/24292852/the-3-2-0-ptr-what-you-need-to-know)의 좁은 카드 비례와 금속성 모서리 장식을, [Diablo Immortal 공식 화면](https://news.blizzard.com/en-us/article/24244451/deliver-sanctuary-from-madness)의 원형 장식 구성을 확인했다. 이를 HELLSCRIPT의 기존 색상과 실제 장비 아이콘에 맞게 재구성했다. 외부 이미지를 게임 리소스로 복사하지 않았으며 장식은 원본 벡터 UI로 그린다.

## 구현과 검증

`TownWalk`와 `WorldView.Town`이 전용 NPC·건물을 생성한다. `GameUI.Plaza`와 `GameController.InteractEquipmentMerchant`가 가까운 NPC에 맞는 상점을 연다. `GambleShop`은 가격·생성·거래를, `EquipmentShopWindow.Gamble`은 미확인 목록과 결과창을 소유한다. 기존 `GameStore.Transact`가 요청 중복과 저장 실패를 처리한다.

2026-09-21에 관련 Edit Mode 538개를 재검사 포함 최종 통과했고, 갬블 전용 검사 6개는 고정 가격, 중복 요청, 실제 아이템 저장과 재접속, 오래된 견적·골드·가방·균열 제한, 디스크 실패 시 원상 유지, 직업·부위별 생성 범위와 기존 계정 해금 조건을 확인했다. 실행별 수치는 [검사 요약](EquipmentShopEvidence/validation.json)에 기록했다.

macOS 개발 빌드에서는 별도 갬블 NPC까지 이동해 구매·판매 선택, 구매 전 능력치 숨김, 연출 전 아이템 저장, 공개 전·후 상세 표시 상태, 연출 생략 설정, 확인·바깥 클릭 닫기, 구매품의 인벤토리 상세, 한국어·영어를 검증했다. [실행 기록](EquipmentShopEvidence/runtime-equipment-shop-smoke.txt)에 장비 상점과 함께 남겼다. 모바일 예시 크기 검사는 440×956·956×440의 macOS 창에서 수행했으며 실기기 검증은 아니다.

2026-09-21 결과창 수정 후에는 관련 Edit Mode **54개가 모두 통과**했다. macOS 개발 빌드에서 바깥 판·테두리가 투명한지, 기존 상세 카드의 아이콘 행과 장착 비교 수치가 표시되는지, 연출 전 정보 숨김·연출 생략·확인·바깥 클릭 닫기가 유지되는지 확인했다. [수정 검증 기록](GambleRevealEvidence/validation.json)에 검사 범위와 결과를 기록했다.

같은 날 결과창의 비례와 장식을 다시 정리했다. 관련 Edit Mode 54개를 통과했고, 마지막 여백·조명 조정 후 macOS 개발 빌드에서 42회 UI 클릭과 상세 스크롤을 검증했다. 카드 최대 폭·내용에 맞춘 높이·아이콘과의 분리·확인 버튼의 화면 내 배치도 검사했다. 1600×900·1920×1080·440×956·956×440 화면을 확인했으며 모바일 실기기 검증은 아니다. [최종 화면 검증 기록](GamblePolishEvidence/validation.json)을 참조한다.
