# 퍼즐 대기실 네이티브 구현

작성 2026-10-07. 6단계 구현 기록이다. 네이티브 화면·입력·성능 수락 검증은 9단계 최종 통합 플레이어에서 진행한다.

- `PuzzleHubWindow`는 `tools/new_content_ui.py PuzzleHub`로 만든 `ContentWindowView` 진입점을 사용한다. 공통 창 호스트·안전 영역·색상·글꼴·버튼을 유지한다. 단일 대기실 화면은 스크롤 본문 대신 전체 창 안에 상태/그림/레벨 판/고정 시작·메뉴를 배치하는 어댑터다. 장비 표시와 편집은 기존 소유 창으로 연결한다.
- `GameController.Tutorials`가 계정의 현재 레벨을 준비하고 대기실↔새 도전 시뮬을 연결한다. 실패·클리어는 `RecordPuzzleAttempt`가 저장한 뒤 대기실로 돌아간다. 지난 레벨은 `CreateReplay`의 독립 상태를 사용한다. 필수 튜토리얼은 15레벨 완료 전 마을로 나갈 수 없다.
- `GameUI`가 기존 인벤토리·사냥 칙령·스킬 트리·설정 진입점을 전달한다. 다섯 가짜 페이지를 만들지 않는다. 전환은 0.62초 동안 기존 창과 허브의 위치만 이동하며 세로 화면 X축·가로 화면 Y축 스와이프만 인정한다. 전환 중 상단 상태는 고정한다. 닫기·대기실 버튼은 동일 허브로 복귀한다.
- 상태 두 줄은 첫 줄 HP/자원, 둘째 줄 전체 폭 XP다. 값은 실제 시작 키트/진행 XP를 사용하고 현재·이전 레벨 선택을 저장 진행과 비교한다. 향후 레벨 이동은 잠금 안내만 표시한다. 15레벨 완료 후 마지막 판의 시작 버튼은 마을 이동이다.
- 저장 구독은 `StoreViewBinding`과 현재 영웅/레벨/클리어/힌트/XP/학습·장착의 표시 의존 키를 사용한다. 무변경 저장은 재생성하지 않으며 전환·누름·하위 창 동안 갱신을 보류한다. 언어·해상도 변경 때 실제 배치만 갱신한다.
- `ContentWindowHost`와 기존 월드 카메라 수명주기에서 불투명 메뉴 뒤 월드 렌더링을 중단한다. 효과는 기존 오브젝트의 위치·색/채움만 갱신하고 매 프레임 UI를 재생성하지 않는다. 성능 수치는 최종 실제 플레이어 전후 각 3회 측정으로만 보고한다.
- 시안 브랜치의 필요한 HTML/도구/그림/프롬프트만 가져온다. 과거 전체 스크린샷은 복사하지 않는다. 게임 리소스는 전용 임포터와 텍스처 예산 행을 추가한다. 기존 그림의 모델 출처 `unknown`을 보존한다.

최종 검증: 3직업 × KO/EN × 440×956/956×440/16:9/16:10/21:9, 화살표·재도전·졸업·창 전환·축별 스와이프·저장 후 복귀 입력. 공통 UI/갱신 검사와 관련 저장 바인딩 검사. 전체 EditMode와 네이티브 스모크는 마지막 통합 상태에서 한 번 수행한다. 모바일 실기기는 별도 미검증으로 기록한다.

효과 비용 비교는 동일한 새 허브에서 효과를 끈 실제 빌드와 켠 실제 빌드를 비교한다. 허브가 없던 이전 버전은 같은 화면 조건이 아니므로 비교 기준으로 쓰지 않는다. 두 빌드는 각각 3회 측정하며 소스·입력·해상도·FPS·품질을 기록한다.

구현 연결: 기존 창의 Canvas 루트는 Unity가 위치를 제어하므로 프레임만 이동하고 기존 배경의 CanvasGroup을 전환 중 페이드한다. 상태 레이어 생성은 공통 `ContentWindowView.FixedOverlay`가 소유한다. 복습 인벤토리와 칙령은 `GameStore.Sandbox`의 실제 거래/검증/저장 성공 구독을 사용하되 디스크 쓰기 없이 독립 복사본만 변경한다. 원래 계정에는 복습 거래와 안내 발견을 기록하지 않는다.

집중 검사: `stage6-hub-save-focused-repair.xml`에서 처음 95개 중 91개 통과했다. 시작/마을로 번역 누락과 복습 체크포인트 거부를 수정했고 `stage6-replay-checkpoint-repair.xml`에서 실패한 4개와 제목 화면 11개가 통과했다. 중복을 제외한 106개 통과·건너뜀 0개다. 실제 소유 칙령 저장, 거래 거부 복원, 원래 계정 보존, 저장 바인딩과 스와이프 축을 확인했다. 공통 UI 계약·UI 검사 11개·갱신 검사가 통과했다. 변경 없이 가져온 HTML 시안 검사 382개는 네이티브 플레이어 검증과 구분한다.

2026-10-07 최종 수락: [9단계 통합 결과](Puzzle_Tutorial_Final_Acceptance.md)에서 3직업의 30개 대기실 배치·12개 안전 영역 시뮬레이션과 12개 전체 여정을 확인했다. 실패한 구간만 재검증한 내역과 소스·저장·입력 근거는 그 기록을 따른다.

2026-10-07 가로 배치 보정(병합 후 검증): 병합된 main의 가로·와이드 스크린샷(1280×720, 1600×900, 2100×900)에서 상태 막대가 화면 전체 폭으로 늘어나 레벨 판 뒤에서 XP 글자를 가리고, 레벨 이름 띠가 영웅 얼굴을 덮고, 빛 흐름이 부드러운 그라데이션이 아니라 단색 사각형으로 보였다. 시안의 가로 규칙(상태는 왼쪽 위에 모으고 레벨 판은 위 가운데, 시작 버튼은 오른쪽 아래, 영웅은 판 아래)을 따르도록 배치를 `PuzzleHubLayout`(순수 계산)으로 분리하고 가로 상태 폭 260·레벨 판 폭 200·영웅 높이 62%로 줄였다. 좁은 가로(16:9·16:10)에서는 판이 상태 영역 오른쪽으로 비켜난다. 세로 배치는 그대로다. 빛 흐름은 공유 32×1 부드러운 램프 스프라이트(한 번만 생성)를 쓴다. 좁아진 가로 막대에서 영어 `Resource 100 / 100`이 꺾이거나 테두리를 덮던 것은 글자 폭을 재서 크기를 줄여 한 줄로 맞춘다(Unity의 최적 크기 맞춤은 가로 넘침을 보지 않아 쓰지 않았다). `PuzzleHubTests`가 여섯 크기에서 상태·판·화살표·영웅 얼굴·시작 버튼의 겹침을 검사하고, 네이티브 스모크의 `CheckHub`가 실제 화면에서 같은 겹침과 상태 글자가 막대 폭 안에 들어가는지를 검사한다. 이전의 "버튼이 안전 영역 안에 있다" 검사로는 이 겹침이 잡히지 않았다.

2026-10-08 화면 정리(사용자 스크린샷 지적): ① 대기실에서 연 사냥 칙령·스킬·인벤토리·설정 창이 세로 하단·가로 오른쪽의 고정 탐색 버튼 뒤로 겹쳐 보였다. 탐색이 쓰는 띠(세로 하단 118, 가로 오른쪽 98 단위)를 `UiSafeArea.Reserve`로 예약해 그 위에서 열리는 모든 창이 `UiSafeArea.Current`, 즉 남은 영역에 배치되게 했다. 대기실 자신은 `ContentWindowView`의 `fullArea`로 전체 영역을 계속 쓴다. 예약은 메뉴를 열 때 걸고 홈으로 돌아올 때·대기실이 닫힐 때·소유 객체가 파괴될 때 풀린다. ② 레벨 판을 세로 폭 240·가로 176 단위로 줄이고(이전 350·200) 레벨 이름은 판 아래 부드러운 알약 그늘 위에 둔다. 판·이름·진행 점이 영웅 머리가 있는 위쪽 22%를 가리지 않도록 `PuzzleHubLayout`이 영웅 크기를 정한다(세로 화면에서 영웅이 더 커졌다). ③ 좌우 레벨 버튼은 같은 그림을 쓰고 오른쪽은 좌우로 뒤집는다. 이전에는 공통 버튼 면이 그림을 덮었고 오른쪽에만 글자 기호가 얹혀 두 버튼이 달라 보였다. 갈 수 없는 쪽은 흐리게만 하고, 같은 이유로 가려져 있던 시작·탐색 버튼의 원본 그림이 보이도록 `UiButtonRole.Icon`을 쓴다(누르면 그림이 어두워진다). 선택된 탐색 버튼은 회색 사각 면 대신 뒤의 금빛 은은한 빛과 밝은 글자로 표시한다. ④ HP·자원·XP 막대의 채움은 틀 그림의 투명한 홈(실측: 높이 106 중 37~69 px, 좌우 75 px)에 맞춘 알약 모양이라 틀 밖으로 나오지 않는다. 틀의 양끝 장식은 비율을 유지하고 가운데만 늘어나며 값은 한 줄로 홈 폭에 맞춰 줄어든다. 가로 화면은 막대를 세 줄로 쌓는다. ⑤ 움직이던 빛 띠(`Light flow`)는 시작 버튼과 막대 모두에서 없앴다. 시작 버튼 아래에는 제자리에서 천천히 숨 쉬는 은은한 불빛만 둔다(움직임 줄이기에서는 정지, 다시 도전 버튼에는 없음). `PuzzleHubTests`가 아홉 크기에서 영웅 머리·판·화살표·점의 겹침과 판 크기를 검사하고, 막대 홈 안쪽 여부를 실제 그림의 알파로, 예약 띠의 해제를 소유 객체 파괴까지 확인한다. 네이티브 스모크의 `CheckHub`는 화살표 쌍·막대 채움·움직이는 빛의 부재를, `CheckHubChild`는 모든 해상도·언어에서 열린 창이 탐색 버튼과 라벨 아래로 들어가지 않는지를 실제 화면에서 검사한다.
