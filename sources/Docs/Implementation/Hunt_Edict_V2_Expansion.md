# 사냥 칙령 핵심 옵션 v0.2 개발 기록

작성일: 2026-09-09 · 원본 데이터·공유 형식·가져오기 미리보기 구현

후속 공통 명중 예측과 W03·A01·A02·M03의 조준 후보 구현은 [조준·명중 예측 기록](Edict_Aim_Expansion.md)을 따른다. 해당 조준 결과의 시전 명령 전달과 새 화면·저장 연결은 계속 개발 중이다.

감지한 공격의 예상 HP 손실, 전역 회피 이유와 긴급 상태의 진입·복귀 판단은 [회피·긴급 생존 기록](Edict_Survival_Expansion.md)에 이어서 정리했다. 전체 검사 871개를 통과했으며 실제 회피·방어 행동의 실행 연결은 후속 범위다.

이후 생존 요청을 기존 스킬 실행·보행·물약에 전달하고 전투별 상태를 복원하는 경로를 추가했다. 최신 연결과 검증은 [생존 행동 실행 기록](Edict_Response_Expansion.md)을 따른다. 정기 판단에서 HED2 저장 원본을 전달하는 연결과 새 편집 화면은 아직 남아 있다.

## 현재 결과

[핵심 옵션 v0.2 목록](../Design/HELLSCRIPT_Hunt_Edict_Skill_Option_Catalog.md)의 89개 항목을 새로운 사냥 칙령 원본에 정의했다. 액티브 18개와 직업별 기본 공격 3개에 자동 사용을 포함한 4~5개 옵션을 제공한다. 항목 ID·이름·선택지·기본값을 기획 표와 직접 대조하는 검사가 통과했다.

이번 단계는 원본 데이터와 검증 기능의 구현이다. 새 원본을 현재 설정 저장·프리셋 5칸·편집 화면·실제 전투에 연결하지 않았다. 실행 중인 앱에서 89개 옵션을 편집하거나 해당 옵션에 따른 자동 행동을 확인할 수 있다는 의미는 아니다. 기존 `BuildConfig`와 HED1의 해석은 유지한다.

화면은 [화면 비율·방향 대응 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)을 기준으로 계속 개발한다. 원본은 UI 객체와 분리했으며, 스킬 칸을 이동·교체해도 미장착 스킬의 보관값과 공통 공격 순서를 유지한다. 실제 화면 재배치·입력·확인창·읽던 위치의 보존은 화면 연결 단계에서 별도로 검증한다.

## 원본과 옵션의 소유 범위

| 구성 | 구현한 규칙 |
|---|---|
| 버전 | 자료 구조 2, 콘텐츠 1, 전역 정의 1, 핵심 옵션 정의 2, 고정 판단 정책 1을 각각 명시한다. 지원하지 않는 버전은 거부한다. |
| 사용 스킬 | 빈칸을 포함한 네 칸에 같은 직업의 액티브 ID를 보관한다. 같은 스킬을 중복 장착하지 않는다. 이미 장착한 스킬을 다른 칸에 선택하면 두 칸을 교환한다. |
| 보관 설정 | 현재 직업의 액티브 6개와 기본 공격의 설정을 항상 보관한다. 스킬 해제·교체는 보관값을 지우지 않는다. 미해금 스킬을 직접 장착하려는 요청은 거부한다. |
| 행동 순서 | 전역의 공통 순서는 긴급 생존·회피·우선 회수·공격·전투 후 회수·탐색의 분류를 다룬다. `skillOrder`는 공격 분류 안에서 액티브 6개와 기본 공격을 판단할 공통 순서다. 둘 다 화면의 칸·카드 배치와 구분한다. 스킬 카드마다 별도의 숫자 우선순위를 추가하지 않는다. |
| 옵션 | 모든 값은 정의된 선택 ID 또는 허용 범위의 숫자여야 한다. 스킬 핵심 옵션 중 수치 입력은 도약의 공격 도약 거리이며 2~8m, 0.5m 단위다. |
| 제외한 자료 | 임의 조건식·OR/AND·숨겨진 고급 규칙과 HP·자원·쿨타임·버프·장비 인스턴스·패시브 장착·개인 ID·이름·시각은 새 원본에 넣지 않는다. |
| 편집 방식 | 옵션·스킬 칸 변경 도우미는 검증한 새 사본을 반환한다. 잘못된 선택 때문에 호출 전 원본이 일부만 바뀌지 않는다. |

`HuntEdictV2.Options`가 정의를, `HuntEdictV2`가 원본·구조 검증·순수 편집을 소유한다. 장비나 패시브가 바뀌어도 옵션 항목 수는 늘어나지 않는다. 장비가 없어 사용할 수 없거나 선택끼리 충돌하는 값은 구조상 유효하면 보존하고 별도 검사에서 이유를 제공한다.

## HED2 공유 형식

`HuntEdictV2Codec`은 정규 UTF-8 JSON을 Base64URL로 바꾸고 SHA-256 오류 확인값을 붙인다. 편집 원본에는 옵션 ID를 보관하지만, 공유 문자열에서는 명시한 정의 버전에 따라 값 목록을 기록한다. 반복되는 옵션 키를 줄이되 기본값이나 미장착 스킬의 값을 생략하지 않는다. 수신자의 기본값으로 빈 내용을 채우지 않는다.

| 최대값을 채운 시험 구성 | JSON 크기 | 공유 문자열 길이 |
|---|---:|---:|
| 전사 | 2,075바이트 | 2,837글자 |
| 궁수 | 2,110바이트 | 2,884글자 |
| 마법사 | 2,094바이트 | 2,862글자 |

각 시험은 현재 전역 항목과 직업별 모든 보관 옵션을 포함한다. 생성한 [전사 코드](../../Artifacts/Validation/EdictV2Codes/WARRIOR-maximum.txt), [궁수 코드](../../Artifacts/Validation/EdictV2Codes/RANGER-maximum.txt), [마법사 코드](../../Artifacts/Validation/EdictV2Codes/MAGE-maximum.txt)를 보존했다. 임의 규칙을 담던 HED1과 표현 범위가 다르므로 이 수치를 손실 없는 압축률로 비교하지 않는다. 실제 모바일 클립보드·입력 UI 검증은 남아 있다.

JSON은 최대 32KiB, 중첩은 최대 8단계로 제한한다. 다른 직업, 알 수 없는 스킬·선택, 누락·추가·중복 필드, 미래 버전, 잘못된 UTF-8·Base64URL·오류 확인값, 비정규 숫자·JSON 표현을 거부한다. HED1 코드를 HED2로 간주하여 자동 해석하지 않는다.

## 가져오기와 기존 코드의 간소화 미리보기

`HuntEdictV2Import`는 원본 코드·원본 사본·편집 초안을 구분한다. 같은 직업의 알려진 미해금 스킬은 원래 칸만 비우고, 다른 칸을 당겨 채우지 않는다. 비운 칸의 원래 스킬·해금 레벨을 안내 자료로 남긴다. 전역 참조·공통 공격 순서·미장착 스킬의 옵션은 그대로 유지한다. 미리보기를 만들거나 초안을 바꾸는 과정에서 계정·영웅·실제 저장 파일을 수정하지 않는다.

`HuntEdictV2LegacyPreview`는 기존 개발용 HED1에 한해 간소화 제안을 만든다.

- 전역 값과 네 칸 배치를 복사한다. 기존 규칙에 각 공격이 처음 등장한 순서에서 새 공통 공격 순서를 제안한다.
- 기존 자동 사용과 활성 규칙 유무로 새 자동 사용 값을 제안한다. 개별 조건의 실행 의미까지 동일하다고 표시하지 않는다.
- A03·M02에 기존 규칙이 하나만 있으면 설치 위치를 복사한다. M02의 고정·추적과 대응 가능한 영역 보존·교체 값도 복사 내역으로 구분한다.
- 정확한 대응을 확인하지 않은 핵심 옵션에는 새 기본값을 제안하고 항목별 변경 내역을 남긴다. 기존 규칙마다 조건식·대상·이동·세부 옵션의 제외 내역을 알린다.
- 회수·상자·탐색의 별도 행동 토글이 전역 방침으로 바뀌는 차이도 알린다. HED1 원본 전체는 다시 확인할 수 있도록 보존한다.

`AcceptAsDraft`는 명시적인 **간소화하여 불러오기** 버튼에 연결할 사본 반환 기능이다. 호출해도 실제 설정이나 저장 파일에 반영하지 않는다. 버튼·변경 확인 화면과 현재 `BuildConfig` 저장 자료의 이전은 아직 연결하지 않았다.

## 장비·스킬 조합의 사용 조건

`HuntEdictV2Availability`는 실제 소유 영웅의 장비·세트·패시브와 스킬 장착·해금·자동 사용 상태를 읽어 비활성·사용 불가·대체 판단·선택 충돌을 구분한다. 원래 선택값은 변경하지 않는다.

| 예시 | 검사 결과 |
|---|---|
| 회오리의 도약 후 집중 | SW 4세트와 자동 사용 가능한 도약이 없으면 연속 유지로 판단할 대체 값을 제시한다. |
| 집중 연사 | LA02가 없으면 단일 집중 사격과 집중 명중 위치를 사용할 수 없다고 안내한다. 임의 대체 값을 넣지 않는다. |
| 후퇴 사격의 덫 연계 | LA03과 A03 장착을 요구한다. 직접 덫의 자동 설치를 꺼도 장비 연계 조건은 충족할 수 있다. |
| 화염구의 노출 대상 우선 | SM 4세트가 없으면 꾸준히 공격 방식의 대체 값을 제시한다. |
| 눈보라 추적 | LM01이 없으면 위치 고정의 대체 값을 제시한다. |
| 연쇄 번개의 충전·재방문 | SMB 4세트·LM04가 없을 때 각각 연결되는 적 위주·고유 대상 수의 대체 값을 제시한다. |
| 분쇄의 선택 충돌 | 단독 적 방향과 두 명 이상을 요구하는 무리 처리의 충돌을 안내한다. |

이 검사는 설정의 사용 조건을 설명하는 자료다. 실제 표적·위험·쿨타임·자원·충전을 매 순간 검사하여 시전을 승인하는 기능은 아니다. 실제 전투에 연결할 때 대체 판단의 우선순위와 모든 실행 경계를 다시 검증해야 한다.

## 검증 결과

Unity 6000.6.0f1의 전체 Edit Mode 검사 **780개가 모두 통과**했다. 실행 시각은 2026-09-09 14:06:32~14:08:00 KST이며 약 87.94초가 걸렸다. 새 v0.2 검사 45개와 기존 회귀 검사 735개를 포함한다. [전체 결과](../../Artifacts/Validation/edict-v2-editmode.xml), [실행 로그](../../Artifacts/Validation/edict-v2-editmode.log).

새 검사는 기획 표의 89개 항목 대조, 세 직업의 전체 선택값 왕복, 숫자 경계·언어권 독립성, 슬롯 교환과 미장착 설정 보존, 부분 가져오기, 손상·미래 버전·위장 필드 거부, 실제 장비에 따른 사용 조건과 구형 간소화 미리보기의 원본 보존을 다룬다. 신규 검사와 관련 기존 검사를 묶은 [집중 검사 143개](../../Artifacts/Validation/edict-v2-focused.xml)도 통과했으며, 이후 장비 의존 검사 3개와 화염구 대체 처리는 최종 전체 검사에 포함했다.

첫 시도에서는 현재 NUnit이 `Assert.Multiple`을 제공하지 않아 검사 코드의 컴파일을 고쳤다. 다음 시도의 142개 중 1개 실패는 기획 표 파서가 ‘기본 사격’ 문구를 기본값 표시로 오인한 문제였으며, 기본값 구분 기호를 읽도록 수정했다. [첫 컴파일 로그](../../Artifacts/Validation/edict-v2-focused-compile-attempt1.log)와 [파서 수정 전 결과](../../Artifacts/Validation/edict-v2-focused-spec-parser-attempt2.xml)를 보존한다.

이번 단계에는 C# 7개를 추가했고 기존 C# 110개는 변경하지 않았다. 최종 검사 대상은 총 117개이며 검사 시작 후 소스 변경이 없다. 패키지가 검사 중 자동 변경한 `SENTIS_ANALYTICS_ENABLED` 기호는 [원문 차이](../../Artifacts/Validation/edict-v2-package-define-change.diff)를 기록한 후 단계 시작 값으로 복원했다. 보호 자산 98개와 기준 기획 6개가 단계 시작 해시와 일치하며, 새 소스의 메타 파일과 GUID 중복 여부도 확인했다. [검증 요약](../../Artifacts/Validation/edict-v2-validation-summary.json)과 [검사 소스 기록](../../Artifacts/Validation/edict-v2-source-manifest.json)에 결과를 남긴다. 씬·프리팹·카탈로그·패키지에는 개발 변경이 없다.

이번 단계에서 새 네이티브 앱은 빌드하지 않았다. 이전 실제 전투 동작 보존 빌드와 실행 증거는 [전투 동작 보존 기록](Action_Continuity_Expansion.md)에 있다. 자동 검사 통과를 89개 옵션의 게임 실행이나 모바일 화면 검증 완료로 확대하지 않는다.

## 다음 연결 범위

1. 새 원본에서 전역 방침과 핵심 옵션을 실제 전투 판단으로 변환한다. 고정 판단 정책·대체 처리·진행 중 동작·해금·쿨타임 보존을 함께 검사한다.
2. 현재 `BuildConfig`와 실제 프리셋 5칸의 이전 미리보기, 명시적 저장, 쓰기 실패 시 원본·초안·전투 보존을 연결한다.
3. 모바일 세로·짧은 가로·PC의 같은 편집 화면에 전역 분류·스킬 목록·옵션·저장 영역을 배치한다. 동작이 연결된 옵션부터 공개하고 원본 보관만 가능한 항목을 작동하는 기능으로 표시하지 않는다.
4. 균열 중 액티브 교체, 훈련 A/B와 결과 원인 설명을 새 원본에 연결한다. 화면 방향 설정과 실제 모바일 터치·키보드·복귀 검증은 [화면 배치 개발 기록](Screen_Layout_Expansion.md)의 남은 범위로 유지한다.
