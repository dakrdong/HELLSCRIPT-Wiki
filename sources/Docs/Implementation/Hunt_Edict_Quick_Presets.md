# 사냥 칙령 항목별 간편 프리셋

갱신일: 2026-09-29 · [English](Hunt_Edict_Quick_Presets.en.md)

설정 항목마다 목적이 분명한 프리셋을 제공하고, 마지막에 **직접 설정**을 둡니다. 스킬·기본 공격·공통 공격 순서는 탭에서 설명과 전투 예시를 살펴본 뒤 **프리셋 활성화**로 적용합니다. 활성화와 직접 설정의 옵션 변경은 즉시 저장합니다. 전역 옵션 묶음은 기존 선택 창과 저장·되돌리기를 유지합니다.

## 2026-09-29 진행 균열이 있을 때 저장

마을에 저장된 균열이 남아 있으면 스킬 프리셋 변경을 거부하던 문제를 수정했습니다. 이제 `GameStore.CommitHuntEdict`가 캐릭터 설정과 같은 캐릭터의 진행 균열을 한 번에 저장합니다. 실제 균열을 재개하거나 초기화하지 않고 분리된 복사본에서 기존 칙령 변경 처리를 실행합니다.

- 프리셋을 바꾸어도 균열 ID, 경과 시간, 난수 상태, 위치, 체력 비율, 자원, 재사용 대기시간, 몬스터·전리품·물약 기록을 유지합니다.
- 도약 내려찍기나 마력 회수의 이동 준비 중 사용 방식을 바꾸면 이전 이동 계획만 취소합니다. 발동한 효과는 유지하며, 사용 방식이 같으면 진행 중인 이동 계획도 유지합니다. 전투 중 편집과 성소 편집에 같은 규칙을 적용합니다.
- 저장에 실패하면 캐릭터, 진행 균열, 편집본, 디스크 파일 모두 이전 상태를 유지합니다. 다른 포인트 배분이나 전역 옵션의 미저장 변경은 함께 확정하지 않습니다.
- 종료된 균열의 결과와 다른 캐릭터의 균열은 수정하지 않습니다. 훈련은 기존 전용 저장 경로를 사용합니다.
- [포탈 복귀와 새 균열 시작](Rift_Entry.md) 뒤에도 같은 저장 처리를 사용합니다.

수정 전 저장 거부를 재현한 뒤 관련 Edit Mode **140개**와 macOS 독립 프로세스 저장·재개 검사를 통과했습니다. [전체 검증 범위와 기존 실패 기준선](Rift_Entry.md#포탈프리셋-저장-검증-2026-09-29) · [실제 활성화 화면](EdictPortalSaveEvidence/portal-preset-saved.png).


## 전역 분류 탭과 프리셋 보관함

2026-09-29 갱신: 전투·생존·전리품·가방 정리·탐색·반복 사냥·장비 추천 착용의 내부 묶음을 상단 가로 탭으로 표시합니다. 총 35개 묶음은 기존 옵션 소유를 유지합니다. 전투에는 요청한 네 묶음 외에 기존 **행동 우선순위**도 남겨 모든 옵션에 접근할 수 있습니다.

- 각 묶음은 목적을 나타내는 선 아이콘과 한국어·영어 설명을 갖습니다. 좁은 화면이나 확대 글자에서는 탭을 여러 줄로 배치하고 선택한 본문만 스크롤합니다.
- 검색은 모든 분류의 일치 결과를 본문에 표시하며, 결과를 누르면 해당 분류 탭으로 이동합니다. **변경된 항목** 필터와 묶음별 스크롤 위치를 유지합니다.
- 프리셋·공유 페이지는 스크롤 없이 다섯 슬롯을 표시합니다. 저장된 슬롯은 번호·짧은 이름 입력 영역·디스크 저장 아이콘·공유 코드 보기의 한 줄입니다. 선택한 슬롯은 초록색, 다른 저장 슬롯은 베이지 계열로 구분하고 ‘적용·편집 중’ 문구는 표시하지 않습니다.
- 이름을 처음 누르면 편집할 프리셋을 선택합니다. 선택된 이름을 다시 누르면 그 자리에서 입력할 수 있으며, 입력을 확정하면 `RenameHuntEdictPreset` 거래로 저장합니다. 긴 이름은 입력 영역 안에서만 표시합니다.
- 디스크 버튼은 현재 설정을 해당 슬롯에 보관합니다. 기존 슬롯을 덮어쓰려면 확인이 필요합니다. 슬롯의 공유 코드는 그 슬롯의 저장본을 사용합니다. 코드 가져오기의 검증·다섯 목적지·덮어쓰기 확인 절차도 유지합니다.
- 전체 설정의 적용·되돌리기는 기존 하단 버튼을 사용합니다. 스킬별 프리셋의 즉시 저장 규칙은 아래와 같습니다.
- **기본 세팅 적용** 버튼은 [요약 탭](Hunt_Edict_Overview.md)에 있습니다. 프리셋·공유 페이지에는 중복해서 표시하지 않습니다.

표시 정의는 [HuntEdictUi.json](../../Assets/HELLSCRIPT/Resources/HuntEdictUi.json), 화면은 `HuntEdictWindow.Summary`, `HuntEdictWindow.Presets`, 선 아이콘은 `HuntEdictWindow.Glyphs`와 공통 `SkillTreeGraphic`이 소유합니다. 신규 래스터 리소스는 없습니다.

## 스킬 프리셋 탭과 전투 예시

- 프리셋 세 개와 **직접 설정**을 고정 탭으로 표시합니다. 가로에서는 한 줄, 세로에서는 두 줄로 배치하며 탭 자체는 스크롤하지 않습니다. 설명과 세부 설정 본문만 스크롤합니다.
- 황동색 탭은 지금 보고 있는 페이지이고, 초록색 체크는 실제 저장되어 활성화된 프리셋입니다. 탭을 눌러 둘러보는 것만으로 설정을 바꾸거나 저장하지 않습니다.
- 모든 탭의 같은 위치에 활성화 버튼을 둡니다. 이미 적용한 탭은 **활성 중**으로 표시합니다. 저장에 실패하면 이전 활성 표시와 값이 유지되고 오류를 알려 줍니다.
- 액티브·궁극기 54종의 프리셋 162개에 전투 예시를 제공합니다. 직업별 기본 공격 9개와 공통 공격 순서 3개까지 합하면 174개입니다. 원은 내 캐릭터, 마름모는 적, 화살표는 이동·공격 방향입니다. 무리·정예·표식·제어 상태, 보호막, 자원과 HP 조건, 이동·후퇴·집중·공격 순서를 도해로 표현합니다.
- 예시는 기존 스킬 아이콘과 `SkillTreeGraphic`의 선·원·도형으로 게임 안에서 그립니다. 래스터 이미지나 별도 이미지 생성 모델을 사용하지 않습니다. 조건과 수치는 기존 프리셋·사용 방침 정의를 읽으며, 설명용 배치는 실제 전투를 재실행하거나 결과를 예측하지 않습니다.
- **직접 설정에는 예시 그림을 표시하지 않습니다.** 활성화 전에도 현재 세부 옵션을 볼 수 있고, 활성화하면 값을 바꿀 수 있습니다. 이후 옵션 선택·숫자 확정·공통 공격 순서 드래그가 끝날 때 해당 내용을 즉시 저장합니다.
- 스킬 옵션 화면에는 저장·되돌리기 하단 영역을 두지 않습니다. 가로에서는 장착 스킬을 오른쪽 세로 열에, 세로에서는 아래에 고정합니다. 스킬 트리의 포인트 배분·장착과 다른 분류의 편집은 기존 저장 방식을 유지합니다.

## 적용 범위와 저장

- 전역 설정 25개 묶음의 기존 옵션 130개를 포함합니다. 액티브·궁극기 54종, 직업별 기본 공격 3종, 공통 공격 순서 1종을 더하면 전체 정의는 83개 항목, 249개 프리셋입니다. 창고 부족 대응 묶음은 후속 개편에서 전용 조작으로 표시하며, 전역 선택 창이 있는 묶음은 24개입니다.
- 화면에는 장착한 스킬만 표시합니다. 상시 적용되며 별도 칙령 옵션이 없는 패시브에는 프리셋을 만들지 않습니다.
- 프리셋은 자기 항목의 모든 값을 정하며, 별도 값이 지정되지 않은 필드는 옵션 정의의 기본값을 사용합니다. 생존기 참조는 장착 중인 사용 가능 스킬로 채우며, 해당 스킬이 없으면 미지정 상태를 유지합니다.
- 스킬의 즉시 저장은 실제 소유 구성에 해당 스킬의 사용 방침만 복사한 별도 거래를 사용합니다. 다른 스킬, 미저장 포인트 배분·장착, 전역 옵션과 선택 중인 전체 프리셋 슬롯은 함께 확정하지 않습니다. 편집본에 남아 있던 다른 변경은 유지하고, 되돌리기를 해도 이미 저장한 스킬 방침은 취소하지 않습니다. 편집본에서만 장착한 스킬도 방침을 먼저 저장할 수 있으며, 실제 소유 구성에 그 스킬을 배우거나 장착하지 않습니다.
- 현재 적용 중인 전체 프리셋 슬롯이 있으면 기존 `GameStore.CommitHuntEdict`가 그 슬롯도 갱신합니다. 다른 슬롯을 미리 선택해 둔 상태는 별도로 남깁니다. 실제 전투 중에는 기존 거래가 체력 비율·소비한 재사용 대기시간·일시정지를 보존합니다. 훈련과 비교 구성은 기존 전용 소유자에게 전달합니다.
- 선택한 스킬 탭은 `ClassSkillLoadout.presetSelections`에 선택 사항으로 저장합니다. **직접 설정**을 명시적으로 활성화하면 값이 기존 프리셋과 같더라도 재실행·공유 후 직접 설정으로 돌아옵니다. 이전 저장과 공유 코드에는 이 필드가 없어도 됩니다. 기존 값이 어느 프리셋에도 맞지 않을 때는 그 값을 유지하면서 첫 프리셋을 미리 보여 주고, 직접 설정 탭에 활성 표시를 둡니다.
- 전역 묶음의 직접 설정은 기존대로 현재 값을 유지하며 옵션을 펼칩니다. 검색은 해당 옵션을 직접 설정으로 엽니다. 전역 선택 창의 화면 상태는 저장하지 않습니다.
- 회오리의 **빠른 중앙 침투**는 스킬 전용 `CENTER` 이동을 사용합니다. 선택한 대상에서 5m 이내에 있는 관측된 적들의 중심과 가까운, 이동 가능한 빈자리로 이동합니다. **생존 우선 전투**는 기존 외곽 선회를 사용합니다. 두 방식 모두 위험 판정, 추적 제한, 이동 가능 여부를 확인하며 전역 위치 설정과 이동 속도를 바꾸지 않습니다.

## 구현 소유자

프리셋 값은 `HuntEdictQuickPresets`와 `Resources/HuntEdictQuickPresets.json`이 소유합니다. 신규 스킬은 `Resources/Data/ClassSkills.json`의 한국어·영어 사용 방침을 재사용하며, 마력 회수는 사용 방침과 회복 목표를 함께 지정합니다. `HuntEdictSkillPresets`가 활성 탭 검증과 해당 항목만 복사하는 처리를 담당합니다. `HuntEdictEditSession.SaveSkillPolicy`는 기존 저장 콜백으로 원자적 거래를 실행하며 실패하면 실제 구성과 편집본을 모두 유지합니다.

화면은 기존 `HuntEdictWindow` 안의 어댑터입니다. `HuntEdictWindow.SkillPresets`가 공통 버튼·테마·글꼴·스크롤을 사용하고, `SkillPresetExampleView`가 전달받은 프리셋과 구성으로 읽기 전용 그림을 그립니다. 그림 부품은 계정 저장에 접근하지 않습니다. HED4·HED5는 선택한 탭을 함께 보존하되 기존 코드의 읽기를 유지하며, 알 수 없는 필드는 계속 거부합니다.

## 2026-09-29 탭·즉시 저장 검증

관련 Unity Edit Mode 검사 **146개**, 공통 UI 소유 검사와 회귀 **9개**가 통과했습니다. macOS 개발 빌드의 컴파일 오류는 0개입니다. 전체 게임 검사 결과는 아니며, 이번 UI·프리셋·저장·공유·직업 스킬·번역 범위의 결과입니다.

실제 게임 창에서 uGUI 레이캐스트와 포인터 누름·놓음·클릭으로 프리셋 예시 **174개**를 열고 활성화해 저장했습니다. 세로 440×956, 가로 956×440, PC 1600×900·1600×1000·2100×900에서 한국어·영어, 글자 100%·150%를 조합한 **20개 화면**을 확인했습니다. 네 프리셋 탭과 활성화 버튼·주요 분류가 스크롤 없이 보이고, 탭을 바꿔도 활성화 버튼의 위치가 같았습니다. 직접 설정에는 그림 없이 옵션이 표시됩니다.

저장 실패를 의도적으로 발생시켜 이전 활성 탭과 값이 유지되고 재시도할 수 있음을 확인했습니다. 다른 포인트 배분·전역 옵션이 편집 중이어도 함께 저장되지 않았으며, 공통 공격 순서 카드를 드래그해 놓는 즉시 저장됐고, 별도 게임 프로세스로 재실행해 마지막 직접 설정 값·활성 탭·공격 순서를 복원했습니다. 전역 설정 24개 묶음, 새로 장착한 스킬의 방침 저장, 스킬 장착 메뉴와 포인트 배분의 기존 저장·재실행도 회귀 검사했습니다. 저장 실패 검사의 오류 로그는 보존했고 캡처에서 개발용 콘솔만 숨겼습니다.

현재 연결된 Unity 편집기 인스턴스가 없어 프로젝트의 기존 배치 검사·빌드와 macOS 플레이어를 사용했습니다. 실제 사용자 계정 저장은 건드리지 않았습니다. 휴대전화·태블릿의 터치 입력과 성능은 검증하지 않았습니다.
