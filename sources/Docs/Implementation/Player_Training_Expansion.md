# 실제 캐릭터 훈련 개발 기록

작성일: 2026-09-09 · D4 훈련 연결 진행 중

## 1. 플레이어에게 달라진 점

성소의 훈련장 버튼은 현재 캐릭터의 레벨·장비·패시브·행동을 복사한 훈련으로 진입한다. 현재 HP 기준과 공격력을 진입 화면에 표시하고, 미해금 스킬은 HUD와 규칙 검사에서 같은 레벨로 잠근다. 기존에 일반 훈련의 능력치를 자동으로 30레벨로 계산하던 동작을 분리했다.

[플레이어 훈련 상세안](../Design/HELLSCRIPT_Player_Training_Detail.md)에 따라 세 훈련은 단계 1의 고정 배치·고정 시드를 사용한다. 단일·다수 표적은 공격하지 않고, 위험 훈련은 실제 잿불 사술사의 준비·장판·피해를 사용한다. 위험 훈련의 최초 제안 좌표는 정지한 영웅과 8m가 넘게 떨어져 공격을 시작하지 못했으므로, 적의 사거리를 늘리지 않고 배치를 8m 안으로 조정했다.

일반 훈련은 1,200전투틱, 즉 60전투초에 끝난다. 영웅 사망·표적 전멸·수동 종료가 먼저 발생하면 그때 끝난다. 시간 조건 SC21과 HUD도 60초 기준을 사용한다. 결과 화면에는 훈련 종류·레벨·남은 HP·실제 총 피해·전투 초당 피해를 보여 주며, 균열 승리나 보상 획득으로 표시하지 않는다.

## 2. 저장과 소유 경계

`Hellscript.unity → GameController → CombatSimulation`의 기존 소유 구조를 유지한다. `CombatSimulation`이 일반 훈련의 계정 전체를 깊게 복사하고 실제 영웅·장비와 참조를 공유하지 않는다. 전투·규칙·피해는 `EffectiveLevel`을 사용한다. `trainingUsesOwnedHero`는 기존 자료 구조에 추가한 모드 값이며, 필드가 없는 과거 개발 시험 자료는 기존 전체 스킬 방식으로 읽는다. 일반 훈련을 진행 중 균열로 디스크에 저장하지 않는다.

훈련 중 설정 적용은 복사본만 바꾼다. 현재 HP·자원·남은 CD는 유지한다. 결과 화면에서 명시적으로 슬롯 1~3을 선택하면 시험한 행동과 장비 ID 참조만 실제 프리셋에 저장한다. 실제 장착과 현재 행동은 바꾸지 않는다. 저장 실패 시 새 프리셋을 적용하기 전 목록으로 되돌리고 오류를 표시한다.

개발 전용 `GameController.BeginDeveloperTraining`은 Editor·Development Build에서만 동작하며 일반 훈련 메뉴에서 호출하지 않는다. 기존 개발 검사에서 전체 스킬이 필요한 호출도 이 경로로 구분했다. 보통의 균열·보상 정산·배속 정책은 바꾸지 않았다.

## 3. 검사와 실행 증거

실제 직업 3종의 장비·레벨 복사, 1/3/6/10/15/20/30레벨에서 액티브 6개씩의 해금, 고정 배치, 계정 격리, 설정 적용, 60초·사망·전멸 종료, 실제 위험 패턴과 개발 모드 분리의 집중 검사 34개가 통과했다. `Artifacts/Validation/training-focused-final.xml`이 해당 증거다. 최초 집중 검사에는 복사 후 생성되는 규칙 ID를 잘못 비교한 검사 오류와 앞서 설명한 위험 배치 오류가 있었으며 수정 후 재검사했다.

최종 `training-editmode-verified.xml`의 전체 검사 **456/456개**가 통과했다. 훈련 관련 검사는 40개이며 전체 검사 시간은 63.3891363초다. `training-build-mac-verified.log`에서 macOS 개발 빌드 성공과 오류 0개를 확인했다. 검사·빌드·실행 뒤 C# 76개의 해시가 같음을 `training-final-source-manifest.json`에 기록했다.

첫 전체 검사 450개와 첫 앱 실행은 통과했으나, 실제 재시작 검사에서 슬롯 2 앞의 빈 슬롯 1이 기본 설정으로 채워지는 오류를 발견했다. Unity JSON은 목록의 null을 기본 `BuildConfig` 값으로 직렬화하기 때문에 이름·버전의 빈 값만 확인하던 기존 복원 조건으로 구분할 수 없었다. 단순히 null로 돌려놓는 것만으로는 재저장 뒤에도 빈칸을 유지하지 못했다. 이제 `emptySlot` 값으로 빈칸을 명시하고 화면·불러오기·전투 적용이 같은 기준으로 확인한다. 규칙 스키마·규칙·장착·장비 참조가 없는 구형 빈 슬롯은 이 값으로 이전한다. 현재 스키마에서 명시적으로 비운 설정과 규칙이 있는 구형 설정은 유지한다. 디스크 재읽기·재저장·빈칸 적용 차단의 회귀 검사를 추가했다. 첫 화면의 하단 버튼 배치도 하단 원점에 명시적으로 고정하고 실제 화면 경계 검사를 추가했다.

최종 빌드는 `PlayerTrainingNativeFinalSave`라는 별도 저장 폴더에서 두 번 실행했고, 두 프로세스의 종료 코드는 모두 0이다. 실제 재시작 1회에서 전체 계정의 성장·장비·재화·기록과 명시적으로 저장한 프리셋이 같은지 확인했다. 저장 시각과 선택한 배속은 계정 비교에서 제외했다. 슬롯 1이 빈칸이고 슬롯 2의 목표 거리가 5.5m인지, 훈련이 진행 중 균열로 남지 않았는지도 검사했다.

실제 1레벨 마법사·기본 무기·HP 210으로 단일 표적 훈련을 2배속에서 1,200틱 실행했다. 시간은 59.99937057495117초로 저장되며, 부동소수점 표시 오차를 제외하면 60전투초다. 총 피해는 1,265.36, 결과 화면의 전투 초당 피해는 21.1이었다. 위험 훈련의 실제 예고, 별도 개발용 Lv.30 진입, 재시작 뒤 새 다수 표적 훈련도 확인했다. `PlayerTrainingNativeFinalEvidence`의 Metal 540×960 화면 8장을 검토했고, 캡처마다 하단 버튼이 화면 안에 있는지 검사했다. 첫 빌드에서 잘렸던 훈련 메뉴의 귀환 버튼도 최종 화면에서는 전체가 보인다.

자산·패키지·설정 174개의 시작 전후 해시는 같았다. Unity가 새 C# 2개의 메타 파일을 추가했으며 씬·프리팹·패키지를 변경하지 않았다. 검사 도중 정의 심볼이 바뀌는 중간 상태를 관찰했지만 빌드 후에는 시작 전 설정과 같았다. 실제 앱 검사와 문서·GUID 검사의 요약은 `Artifacts/Validation/training-validation-summary.json`을 따른다. 이 결과는 UI 함수 호출로 검사한 macOS 개발 앱의 증거이며 물리 입력·Android·성능·A/B 비교 완료를 뜻하지 않는다.

## 4. 남은 훈련 작업

현재 총 피해 표시는 실제 누적 피해를 사용한다. A/B 실행을 같은 영웅 스냅샷에 묶는 비교 화면, 스킬별 전체 사용·피해·피격·회피 집계, 장비 교체를 포함한 훈련 편집, 저장 프리셋을 현재 빌드에 적용하는 상세 미리보기는 남아 있다. 이 단계의 복사본 격리만으로 CHK-F01~F04 전체나 D4를 완료했다고 표시하지 않는다.

저레벨 성장 안내의 구체적인 공백도 확인했다. PM01은 화염구에 자기 눈보라 안의 표적 조건이 있으므로, 눈보라를 배우지 않은 1레벨에서는 화염구 규칙이 실행되지 않는다. 이번 단일 표적 앱 결과의 피해는 기본 공격에서 발생했다. 현재 사용자가 저장한 조건을 훈련 진입 때 바꾸지 않았으며, 저레벨 추천안과 적용 미리보기는 CHK-G01의 다음 작업으로 남긴다.

이후의 현재 레벨 추천안과 성장 갱신 작업은 [성장 개발 기록](Growth_Expansion.md)에 이어서 정리한다. 위 훈련 단계의 결과는 당시 설정과 빌드의 증거로 보존한다.
