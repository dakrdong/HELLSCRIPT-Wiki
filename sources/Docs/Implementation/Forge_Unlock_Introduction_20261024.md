# 대장간 콘텐츠 열림 소개 · 2026-10-24

새로 열린 대장간 서비스를 처음 방문했을 때 봉인 해제와 선택 가능한 소개를 보여 준다. 기존에 이용하던 서비스와 심부름에서 배운 첫 강화는 다시 설명하지 않는다.

## 동작과 저장

- 실제 서비스는 속성 재설정(균열35, 탭0), 슬롯 강화(5, 탭1), 장비 강화(1, 탭2), 코어 제작(50, 탭3)의 네 개다. 현재 코드에 없는 다섯 번째 탭을 만들지 않았다.
- 실제 `ForgeHas` 이용 자격을 만족하는 미소개 서비스만 단계 순서로 처리한다. 마을의 룬 소개와 대장간 큐를 위치별로 골라 서로 막지 않는다.
- 대장간 안에서 해당 탭을 자동 선택하고 U-J의 봉인/빛 효과와 `flow.skill_unlock` 효과음을 재사용한다. 약2초 뒤 다음 단계를 활성화하며, 건너뛰기는 처음부터 가능하다. 동작 줄이기는 0.15초다.
- 공용 `PrologueGate`와 `TutorialAnchorRing`으로 서비스 설명, 핵심 버튼, 주의점의 세 단계를 표시한다. 코어 제작은 제작법 선택 전 첫 화면의 실제 `core-refine` 버튼을 강조한다.
- 소개 중 아래 화면의 입력을 차단한다. 화면 닫기·소유자 변경·마을 이탈·계정 변경으로 중단하면 완료를 기록하지 않아 다음 방문에 처음부터 다시 보여 준다.
- 마지막 확인/건너뛰기는 기존 `GameStore.Transact`로 소개 완료와 읽음/보류 기록을 함께 저장한다. 저장 실패 시 게이트와 대기를 보존하여 재시도할 수 있다. 제작·재화·보상·실습 완료를 대신 실행하지 않는다.
- `forgeIntroSeeded`는 기존 플레이어의 실제 이용 가능한 서비스만 조용히 소개 완료로 옮긴다. 과거 전체 해금이 미래의 잠긴 대장간 서비스까지 소개 완료로 쓴 값은 제거한다. `townEnhanced` 또는 실제 강화 실습 완료만 기존 학습 근거이며, 지원금 수령만으로 학습을 추정하지 않는다. 기존 저장 키와 다른 서비스 진행은 보존한다.

## 문구

첫 단계는 “{0} 기능이 열렸네. 봉인을 풀 테니 잠깐 살펴보게. 소개는 언제든 건너뛸 수 있네.”다. 두 번째 단계는 기존 `ContentUnlocks.json`의 안내와 `Tutorials.Definition` 본문을 재사용한다.

주의점은 각각 다음과 같다.

- 강화: “강화 전에는 고른 장비와 비용을 확인하게. 버튼을 누르기 전까지 장비와 재화는 그대로라네.”
- 슬롯 강화: “이 강화는 선택한 장비 부위에 적용된다네. 시작하면 제작 시간이 필요하니, 완료 뒤 결과를 확인하게.”
- 재설정: “바꿀 속성 한 줄을 먼저 고르게. 고정한 줄과 비용을 확인하고, 재설정 결과는 무작위라는 점을 기억하게.”
- 코어 제작: “원하는 장비와 같은 부위의 코어 10개가 필요하네. 제작법과 최종 비용을 확인한 뒤 제작하게.”

모든 신규 문구는 공통 한국어/영어 지역화에 함께 등록했다. 화면 크기나 언어 변경 시 현재 대상과 공용 안내를 다시 배치한다.

## 검증

직접 영향 EditMode 실행 `j-k-i-validation/run2/results.xml`은 332건 중330건 통과,2건 실패였다. 실패는 위치별 소개 큐와 공용 안내의 내레이션 대상에 관한 테스트 기대값이었으며, 각각 실제 위치 큐와 강조 영역을 검사하도록 수정했다. 코어 첫 화면의 버튼 회귀 사례를 추가한 19개 관련 검사가 19/19 통과했다. 변경되지 않은314건과 합쳐 고유333건이 통과했다. 최초 sandbox의 UPM 소켓 거절은 테스트 전 실패로 보존했으며 통과 수에 넣지 않았다. Python3.12/Node22 로컬 데이터/UI 검사8개 단계도 통과했다. Git clean 게이트와 실제 화면 검증은 별도로 남아 있다.

큐/단계/마이그레이션/실습/재방문/저장 실패·재시도/중간 입력 차단을 검사한다. Editor 단위 결과는 실제 macOS 입력, 화면 크기별 한국어/영어 배치, 실기기 성능의 증거가 아니다. 전체 EditMode와 최종 빌드는 실행하지 않았다.

## 실제 리뷰의 추가 수정

Sol/Max 리뷰에서 기존 프롤로그 정리가 활성 대장간 소개를 매 프레임 숨기는 문제와 계정 전환 시 이전 룬 해방 표시가 첫 독 생성에 남는 문제를 찾았다. 소개 소유자를 정리 예외에 추가하고, 계정 전환 및 독 생성 전에 해당 표시 상태를 초기화했다. 실제 프레임 순서에서 스크롤·강조를 보존하는 검사와 계정 전환 전 표시 상태·저장 불변 검사2건을 추가했다. 두 회귀를 포함한 대장간 UI11/11 검사와 새 개발용 수용 드라이버의 컴파일이 통과했다. 실제 화면·최종 결합 검증과 재리뷰는 아직 남아 있다.

개발 전용 `-hellscriptForgeIntroductionProof`는 명시한 폐기용 /tmp 세이브에서만 R5 첫 방문과 KO/EN 크기별 렌더·raycast를 검사한다. 마지막 확인은 합성 입력으로 보내지 않고 실제 macOS 포인터 입력을 기다린다. 최종 릴리스 빌드에는 포함되지 않는다.
