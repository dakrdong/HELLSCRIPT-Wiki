# 캐주얼 UI 스킨 공통 규칙 — 스킬 창 파일럿

작성일: 2026-10-14 · [English](Casual_UI_Skin_Rules_20261014.en.md) · [후속 작업 소유권·검증 큐](Casual_UI_Parallel_Handoff_20261014.md)

정본은 이 문서다. 이번에 적용한 대상은 `SkillTreeD4Window` 한 개다. 다른 창·HUD·출석·재화·보상으로 자동 확장하지 않는다. 다음 UI는 별도 시안을 읽고 해당 화면의 계약과 아래 규칙을 대조한 뒤 작업한다. 미해결 충실도 항목은 [파일럿 결과](Casual_Skill_Window_Skin_20261014.md)에 남긴다.

## 근거와 소유

- 모양 기준: `Docs/Design/D4SkillTree/casual/SkillWindow.casual.locked.dc.html`. Claude 캔버스는 상호작용·색·장식 확인용이며 더 큰 글자 크기를 게임에 적용하지 않았다.
- 원본 잠금판은 보존한다. 실행용 `SkillWindow.dc.html`에는 기준 내부 치수 원복을 반영했다. 색·외곽선·그림자·글꼴 지정은 실행용 시안 → `golden/styles.json` → `tools/build_skill_tree_d4_looks.py` → `Resources/Data/SkillTreeD4Looks.json`으로 간다. FX 색·시점은 `SkillTreeD4Fx.json`을 사용한다.
- `UiTheme`의 전역 Obsidian & Gilt 램프와 `UiFonts.Body/Display/WebBody`는 기존 값을 유지한다. 파일럿은 `D4*`, `CasualDisplay`, `CasualBody`를 선택해서 사용했다. 이후 승인된 화면 작업에는 [선택형 공통 API](Casual_UI_Parallel_Handoff_20261014.md#선택형-공통-api--첫-연결-계약)의 `UiSkin.Casual`을 명시적으로 전달한다. 이 API의 실제 Unity 검증은 별도 큐 대기이며 기존 화면을 전역 전환하지 않는다.
- 규칙·스킬 ID·문구·저장 스키마·회수 제한·재투자·선택·닫기·스크롤은 기존 도메인/호스트 소유다. 스킨 컴포넌트가 이를 재정의하지 않는다.

## 승인된 수용 범위

사용자가 2026-10-14에 승인한 기준은 **위치·크기·글자 크기·기능 유지, 시안에 따른 색·선·모서리 변경만 허용**이다. 본문 400/강조 700·900 결정은 유지한다. raw layout의 색·선·radius 및 그 파생 hash 3,600개는 이 기준으로 수용한다. 골든의 위치·크기 차이 0을 모든 자식 텍스트 영역의 픽셀 동일성으로 확대 해석하지 않는다. CSS 안쪽 링/padding/line-height는 기준 치수로 원복해 36조합의 치수·font-size 차이는 0이다. 현재 스킬 구현은 기존 폭을 최소값으로 두고 일부 내부 글자 칸을 확대했지만, **이 폭 확대는 수용 판단이 남은 파일럿 예외이며 확정 공통 규칙이 아니다**. 연결 칩 두 영문 이름·수정자 순위·능력치 칸의 정확한 이전/현재 값과 원복시 잘림 판단은 [인계 문서](Casual_UI_Parallel_Handoff_20261014.md#별도-수용-결정-남은-내부-폭)에 있으며 다른 UI에 자동 적용하지 않는다. 사용자가 추가로 요청한 게이지 포함·연결선 접점·원둘레·큰 모서리 수리와 하단 범례 제거는 이 스킬 창의 명시적 표시 변경이다.

## 글꼴과 치수

Jua는 제목·탭·숫자·버튼·소제목에, Noto Sans KR 400은 일반 본문, 700/900은 시안에 지정된 강조에 사용한다. 파일은 OFL을 동봉한 프로젝트 전용 이름의 부분집합이다. 한글 KS X 1001 2,350자와 라틴, 현재 시안 문자를 보존한다. Jua에 없는 화살표·곱셈 등 본문 기호는 Noto 본문에서 표시한다.

기존 글자 크기와 기준 사각형을 유지한다. 다음은 CSS 디자인 포인트이며 uGUI의 `2×` 단위 경계를 통해 변환한다.

| 요소 | 가로 / 세로 / PC |
|---|---|
| 창 제목 | 24 / 27 / 26 |
| 탭 | 13 / 14 / 13 |
| 상세 이름 | 16 / 19 / 16 |
| 상세 소제목 | 12.5 / 14.5 / 12.5 |
| 회수·투자 | 13; 차단 이유가 버튼에 들어가면 기존 11.5 |
| 패널 간격 | 4 / 5 / 10 |
| 패널 안쪽 기본 여백 | 12 / 16 / 14 + 기존 테두리 경계 |
| 탭 간격 | 6 / 8 / 6 |
| 닫기·투자·회수 목표 영역 | 기존 44 × 44 및 본래 가로 버튼 폭 |

본문 줄 높이는 원본 값으로 유지한다. 새 글꼴이 더 적은 줄로 표시되더라도 원래 추정 줄 수에 필요한 높이를 최소 공간으로 예약해 패널과 보조 스킬 행의 기존 사각형을 보존한다. 새 글꼴 때문에 한 줄 폭이 달라질 수 있으므로 실제 Canvas 배율을 고려해 연결 칩 텍스트를 잰다. 배치 차이를 숨기기 위해 글자를 축소하거나 테스트 허용오차를 늘리지 않는다. 부분 줄의 너비를 잴 때 색상 태그는 제외하고 굵기 태그의 짝을 맞춘다. 스타일 태그 문자열의 길이를 글자 너비로 계산해 보조 행이 하단 단추를 덮게 하지 않는다. 기존 제목/카드의 fitting 규칙은 유지한다. Noto 파생 파일의 줄 메트릭을 880 / -220 / 0으로 정규화했으며 윤곽·advance는 변경하지 않았다.

## 판·노드·버튼

- 바탕은 하늘 → 크림 그라데이션, 구름/녹색 하단 강조다. 판은 크림색 계열과 남색 외곽선, 아래 방향의 단단한 그림자를 사용한다.
- 시안의 3px 외곽선, 5px 아래 그림자, 6px 안쪽의 2px 점선 바느질, 18px 둥근 젬을 모양 데이터에서 읽는다. 판 모서리는 가로/PC 18, 세로 20이다. 이 모서리 값은 기존 layout 계약에도 포함되어 있어 원래 **raw diff=0과는 충돌**하지만 새 승인 기준에서는 허용된 모서리 변경이다.
- 선택 링·단계 배지·패시브 원형/육각형·순위 호·보조 칸의 면과 테두리는 해당 상태 look ID를 사용한다. 연결선은 3px, 활성 선 밑 남색 선은 7px, 잠긴 선은 점선이다.
- 제목 외곽선은 한 `BaseMeshEffect`와 재사용 vertex 목록으로 그린다. 모든 글자에 uGUI Outline 8개를 붙이지 않는다. 본문에는 제목용 외곽선을 붙이지 않는다.
- 게이지는 테두리를 제외한 둥근 안쪽 면에 4pt 높이로 포함시키며 카드 눌림 배율을 함께 따른다. 모든 연결선의 외곽선을 먼저, 색선을 나중에 그려 접점에 끊김이 생기지 않게 한다. 원형 배경은 원호 메시로, 안쪽 그림자는 원형 안에 그린다. 긴 판은 구석에 원호 꼭짓점을 배치하고 트리/페이드는 판 안쪽의 둥근 마스크 한 개로 자른다. 노드마다 마스크를 만들지 않는다.
- 사용자가 불필요하다고 지정한 하단 상태 범례는 스킬 창에서 숨긴다. 수치·잠김 이유·선택 상태·모델 문자열과 기존 스크롤/프레임 치수는 보존한다.
- 번진 상세 패널 아트 오버레이는 만들지 않는다. 이 파일럿은 스킬 아이콘 원화와 경로를 유지했다. 후속 작업에서 승인된 이미지 교체는 아래 자산 절차를 따른다.
- 회수는 밝은 면, 투자 가능은 초록, 닫기는 코랄이다. 비활성 버튼의 차단 이유·클릭 차단·아래 게임 입력 차단은 기존 계약을 유지한다. 비활성 영역은 클릭 핸들러가 없는 투명 raycast 면으로 받아 다른 수정자나 게임에 입력을 통과시키지 않는다. 하단 버튼은 패널 행보다 위에 그리며 행과 버튼이 겹치지 않는지 검사한다.

## 반응형·입력·접근성

세로는 트리의 세로 스크롤과 고정 상세 패널, 가로는 가로 스크롤과 오른쪽 상세 패널, PC는 전체 트리 맞춤 배율을 유지한다. SafeArea와 `SkillTreeD4Units.Fit` 경계를 유지하고 화면 비율을 위해 별도 게임 규칙이나 픽셀 임의 배치를 만들지 않는다.

장식은 `raycastTarget=false`다. 구매·회수·선택·탭·차단된 버튼·스크롤·닫기는 기존 입력 경로를 사용한다. 기존 목표 영역을 스킨 때문에 줄이지 않는다. 가로 모드의 닫기/하단 단추는 44 디자인 pt, 일반 카드는 38pt, 수정자 소켓은 32pt이다. 모든 터치 영역이 44pt를 충족한다고 주장하지 않는다. 색에만 의존하지 않고 기존 수치/단계/순위/차단 이유와 선택 상태를 함께 보여준다. 기존 키보드 동작을 변경하지 않았다. 화면 낭독기와 실기기 터치 접근성은 이번 macOS 검증으로 인증하지 않는다.

작은 주황 강조 값은 시안 그대로이며 밝은 판 위 대비가 일반 본문 기준에 미달할 수 있다. 대비를 통과했다고 주장하지 않는다. 다음 화면으로 확대하기 전에 강조 값의 대비와 작은 글자의 실기기 가독성을 확인할 필요가 있다.

## 이미지 재사용·제작·교체·정리

2026-10-14 추가 사용자 지시로, 승인된 UI 작업에 필요한 새 컨셉 이미지가 없으면 직접 제작하고 교체·화면 검증이 끝난 미사용 옛 리소스를 정리할 수 있다. 공통 파일 소유권·Unity 단일 검증 큐·기존 세이브 보호는 유지한다. 이 절차는 후속 UI 자산 작업의 기준이며 모든 옛 그림의 일괄 재생성·삭제 지시가 아니다.

1. **재사용 우선:** 원본 체크아웃의 [아트 인계](../Art/Art_Transition_20261014.md)와 [자산 색인](../Art/Art_Transition_20261014_Asset_Index.json)에서 ID·현재판·경로를 찾는다. 색인이 가리키는 `casual-art-brief/DIRECTOR_STATUS.json`의 최신 ID별 승인과 `FINAL_PRIMARY_EXPORTS_QA.json`의 파일 SHA256을 대조한다. 기존 650종/700PNG 납품·보류 목록은 검색의 출발점이며 현재 화면 적용 완료를 뜻하지 않는다. 해당 자산의 최신 승인 바이트를 재사용하고, 문서에 적힌 과거 HEAD만으로 승인판을 정하지 않는다.
2. **없는 이미지의 제작:** 실제 정본 스타일 이미지와 해당 UI 시안의 픽셀을 열어 확인한다. 공통 `STYLE_GUIDE.md` v05·StyleD 타이틀·해당 인물/아이템 정본을 참조하되 사용자 최신 수정과 지정 UI 시안을 우선한다. 새 ID·의미·필요 크기·알파·소비 화면·재사용 후보가 맞지 않는 이유를 기록한 뒤 지원되는 `image_gen`으로 필요한 원화만 제작한다. 단순 필터·임의 도형 대체를 새 원화 제작으로 보고하지 않는다. 유료 외부 서비스 결제·새 계정 연결은 승인 범위에 없다. 공유 자산은 필요한 ID와 소비 화면을 부모에게 전달하고 **단일 제작 소유자**를 배정받아 중복 생성·교체를 막는다.
3. **연결과 화면 검증:** 크기·투명도·작은 실제 아이콘 가독성·선택/잠김/활성 등 상태 의미를 확인한다. 같은 경로의 이미지 교체는 기존 `.meta`와 GUID를 유지한다. 새 ID는 기존 게임 의미·저장 키를 바꾸지 않는 표시 매핑으로 연결한다. Unity import/실제 화면 검증은 부모 큐를 사용하고 입력·상태·KO/EN·필요한 화면 비율의 결과를 남긴다. 생성 파일이 있다는 이유로 적용 완료로 판정하지 않는다.
4. **옛 리소스의 참조 조사:** 교체와 화면 검증을 마친 뒤 프로젝트 전체의 경로·GUID/`.meta`·씬/프리팹/데이터와 코드 로더를 확인한다. `Resources.Load` 문자열·조합된 경로·사용 중인 자산 목록 등 동적 참조는 코드까지 추적한다. 다른 화면과 다른 활성 작업의 의존성도 부모와 확인한다. 정적 검색 결과 0만으로 미사용 판정하지 않으며 참조가 남거나 해소되지 않으면 보존한다.
5. **복구 가능한 정리:** 기존 작업의 자산/수명 기록에 `원본 경로·SHA256·논리 bytes·GUID/.meta`, `새 대응 ID·경로·SHA256`, `화면 검증 근거`, `전체/동적/활성 작업 참조 검사`, `복구 경로·방법·복구 확인`, `소유자·정리 방식·승인 상태`를 남긴다. 정상 제품 복구가 확인된 미사용 파일만 승인 범위에서 정리한다. 유일 원본·사용자 세이브·미커밋 소스와 필요한 검증 근거를 보호한다. Git 이력만으로 비가역 삭제 승인을 가정하지 않는다. **영구 삭제·휴지통 비우기는 정확한 경로와 실측 크기를 부모에게 제시해 별도 승인을 받은 뒤** 수행한다. 대형 백업 사본을 추가하지 않고 기존 복구 가능한 원본·기록을 재사용한다.

정리 직전/직후 같은 볼륨의 실제 `df` 여유 공간과 파일의 논리 크기를 따로 기록한다. 보관 위치 이동·APFS 공유 블록·동시 쓰기를 실제 회수 용량과 혼동하지 않는다. 웹 빌드 취소·원격 push/새 아트 GitHub 공유 제한은 계속 적용한다. 상세 보존 기준은 [산출물 규칙](../../AgentRules/Artifact_Cleanup.md)을 따른다.

## 검증·성능·산출물

2868×1320은 사용자가 지정한 렌더 픽셀 조건이다. 이 Mac 검사에서 모바일 DPR 3과 안전영역 좌/우 102px·하단 54px·상단 0px를 가정한다. 논리 프레임 956×440, 실제 Canvas 배율과 표시 영역을 함께 기록하고 특정 기기 사양·iOS 실기기 결과로 표현하지 않는다.

관련 golden/참조/정적 검사 → 영향을 받는 EditMode → 한 개의 무음 네이티브 개발 플레이어 → 실제 캡처 순서로 확인한다. 기능 데이터의 동일성과 모양 차이를 별도 증거로 기록한다. 실패 검사는 남기고, 임의로 golden이나 허용오차를 합격시키지 않는다.

폰트·look·메시 캐시는 실제 내용/배치가 바뀔 때 갱신한다. 노드별 새 Material과 hot-path 문자열 연결을 피하고 기존 공용 선 메시를 유지한다. CPU/GC 개선 주장은 동일 조건 이전/이후 바이너리를 각 3회 이상 측정한 원자료가 있을 때만 한다. 이번 파일럿 성능은 미측정이다.

실사용자 세이브를 테스트에 쓰지 않는다. 빌드와 캐시는 작업별 경로 하나에서 관리하고 크기·보존 사유·종료 처리를 `artifact-lifecycle.json`에 기록한다. 웹 빌드·공개 배포·GitHub에 새 아트 공유는 이 파일럿에 포함되지 않는다.
