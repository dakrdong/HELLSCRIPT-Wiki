# 완료한 균열의 상세 전투 기록

현재의 최근 100회 기록·실시간 로그·서버 수집 준비는 [전투 기록 확장](Combat_Journal_Server.md)을 따른다. 아래 내용은 최초 구현 당시의 범위와 검증 기록이다.

작성일: 2026-09-13 · [English](Combat_History_Expansion.en.md)

상태: **최근 10회의 상세 기록 저장·조회와 기존 결과 화면 연결을 완료하고, 전체 검사 2,156개와 macOS 실행·재시작 3회를 통과했다.**

## 플레이어가 확인하는 내용

성소의 **전투 기록**에서 최근 10회의 결과를 선택하거나, 방금 끝난 결과 화면의 **전투 상세 기록**을 누른다. 요약에서 스킬·효과별 집계, 마지막 전투 구간, 판단 기록, 종료 시 설정과 장비, 문자 로그를 각각 열 수 있다. 사망 결과의 기존 분석 버튼도 같은 보관 기록으로 연결한다.

스킬별로 시작·발동·완료·중단·적중·피해·실제 HP 피해·자원 부족 판단 횟수를 보여 준다. 실제 HP 피해는 과잉 피해를 제외한다. 자원 부족 횟수는 조건 검사 횟수이므로 자원 소비량이나 실제 동작 중단 횟수와 구분한다. 부분 집계와 전투 중 설정 변경도 표시한다.

마지막 구간에는 실제로 보관된 시간, HP 변화, 피격원별 합계와 비중, 스킬 불발 사유를 표시한다. 시점을 선택하면 위치·대상·진행 동작·피격 내역과 당시 차단된 규칙을 확인한다. 핵심 사냥 칙령을 사용한 불발에는 해당 시점에 실제 사용한 칙령 복사본을 연결한다. 이 정보로 당시 판단 근거를 읽을 수 있으나, 다른 스킬을 사용했다면 반드시 생존했을 것이라고 추정하지 않는다.

종료 시 설정은 전투가 끝난 시점의 장비·스킬·패시브·규칙·활성 칙령 복사본이다. 전투 내내 같은 설정을 사용했다는 뜻은 아니다. 기록을 읽어도 현재 장비·행동 설정·재화·보상은 바뀌지 않으며, 장비를 판매하거나 캐릭터를 바꿔도 과거 복사본은 유지된다. 과거 장비를 다시 지급하거나 잠그는 기능은 아니다.

## 저장과 표시의 경계

`RunRecord.review`에 버전 1의 선택적 상세 정보를 추가했다. 기존 저장 형식의 키를 바꾸지 않는다. 예전 결과는 남아 있는 요약과 문자 로그만 표시하고, 지원하지 않는 새 버전도 해당 요약과 로그를 계속 읽을 수 있다. Unity 직렬화가 누락된 상세 정보를 빈 객체로 복원하는 경우에는 버전 0을 이전 기록으로 정규화한다.

| 항목 | 보관 범위 |
|---|---|
| 결과 | 최근 10회이며, 새 결과가 쌓이면 가장 오래된 결과부터 제거한다. |
| 전투 집계 | 관측된 전체 누적값과 스킬·효과별 누적값을 복사한다. |
| 마지막 구간 | 최근 5전투초이며 표본은 최대 101개다. |
| 상세 사건 | 피격과 불발을 합쳐 최대 512개이며 최근 사건을 먼저 보관한다. |
| 판단 항목 | 최근 80개다. 동일 판단을 묶은 항목은 횟수와 처음·마지막 시각을 유지한다. |
| 당시 칙령 | 보관된 불발이 참조하는 실제 설정을 최대 8개 복사한다. |

상세 사건을 줄여도 관측된 구간의 합계는 줄이지 않으며 한도 도달을 표시한다. 진행 중 전투의 메모리 표본은 저장하지 않는다. 따라서 이어하기 직후 끝난 전투에는 재시작 전의 5초 전체가 남아 있지 않을 수 있다. 실제 보관 시간을 표시하며 없는 구간을 만들어 채우지 않는다. 훈련은 계정의 완료 기록을 추가하거나 수정하지 않는다.

치명타가 발생한 마지막 틱까지 기록한 뒤 완료 기록을 확정한다. 보호막 흡수나 과잉 피해가 있을 때도 HP 손실 비율은 피격원의 실제 HP 손실을 분자로 사용한다. 서로 다른 적 종류의 일반 공격이 하나의 피격원 이름으로 합쳐지는 문제도 수정했다.

화면은 [화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)의 읽기 흐름과 글자 크기 요구를 따른다. 긴 설명의 높이는 내용에 맞춰 늘어나고, 화면 크기·글자 크기·안전 영역이 바뀌면 배치를 다시 계산한다. 기록 화면에서는 자동 반복 대기 시간이 멈추고 결과로 돌아오면 남은 시간이 이어진다.

## 검증과 남은 범위

최종 입력을 고정한 전체 Unity Editor 검사 **2,156개**, 관련 검사 **120개**, macOS 개발 빌드와 독립 실행·재시작 **3회**가 통과했다. [검증 요약](../../Artifacts/Validation/CombatHistory/validation-summary.json), [검사 원본](../../Artifacts/Validation/CombatHistory/Full3.xml), [소스·실행본 해시](../../Artifacts/Validation/CombatHistory/validated-source.json)를 보관한다. 실제 입력은 룬 드롭·합성이 반영된 `9f0489d`와 이번 변경 파일이다. 씬·프리팹·패키지는 수정하지 않았고, 기존 사용자 변경 19개를 보존했다.

새 계정의 전사로 시드 551의 1단계 균열을 진행했다. HP·적·지형·보상·종료 상태를 주입하지 않고 실제 고정 틱으로 진행하여 67.1초에 사망했다. 종료 시 레벨은 3, 처치는 35였으며, 마지막 5초의 표본 100개·스킬 불발 94건·당시 칙령 1개를 보관했다. 자동 반복으로 다음 균열이 시작된 뒤 귀환하고 캐릭터를 바꾼 다음 앱을 다시 실행해 원래 기록 전체가 동일함을 확인했다. 전투를 빠르게 진행한 구간은 일반 프레임 갱신을 꺼 두었으므로 실제 시간 표시는 0.0초다. 자동 반복 대기 시간은 일반 갱신을 켜서 별도로 검사했다.

별도 결과 화면 검사는 살아서 귀환, 시간 초과, 사망, 훈련 사망, 보스와 영웅의 동시 사망 승리를 명시적인 시험 상태로 재현했다. 이 시험을 자연 전투로 집계하지 않는다. 사망 분석 버튼의 표시 조건과 결과로 돌아가는 동작도 확인했다.

한국어·영어, 세로·가로, 글자 크기 140%를 포함한 화면 33장을 캡처하고 배치·번역을 자동 검사했다. 대표 13장을 직접 검토했으며 [화면 검토 기록](../../Artifacts/Validation/CombatHistory/visual-review.json)을 보관한다. [한국어 마지막 구간](../../Artifacts/Validation/CombatHistory/Native4/initial-03-window-ko.png), [확대 영어 설정](../../Artifacts/Validation/CombatHistory/Native4/initial-07-configuration-en-large.png), [수정한 행동 이름](../../Artifacts/Validation/CombatHistory/Native4/initial-09-decisions-en.png)을 확인할 수 있다.

개발 중 구형 기록의 빈 객체 복원, 합쳐진 스킬 이름과 저장된 조건 문구의 번역, 화면 크기 변경 시 읽던 문단 유지, 보조 행동이 기본 공격으로 보이던 표시를 수정했다. 실제 로그 125개와 판단 설명 80개를 번역 회귀 검사 자료로 남겼다. 스킬 불발 집계가 보조 행동을 포함하지 않는 기존 경계도 검사했다.

장비 화면은 이름·아이템 레벨·강화를 표시한다. 장비 원본 전체를 복사하지만 과거 접사 수치를 펼치는 전용 창과 룬 보드 배치 스냅샷은 후속 작업이다. 이 단계는 [완성도 체크리스트](../Design/HELLSCRIPT_Gameplay_Completion_Checklist.md)의 CHK-F03과 CHK-A10을 진전시킨다. 실행하지 않은 모든 대안을 재계산하는 전투 재생, 전투 도중 재시작 전의 상세 표본 복원, 물리 모바일 기기의 터치·성능 검증까지 완료한 것으로 표시하지 않는다.
