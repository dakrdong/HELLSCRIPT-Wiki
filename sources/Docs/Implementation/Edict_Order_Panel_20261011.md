# 행동 우선순위 패널과 공통 판단 순서 · 2026-10-11

`common.order`를 전용 빠른 편집 패널과 실제 전투 판단의 공통 순서로 연결한다. 전투 위치·거리(PR 93), 공격 대상 선택(PR 95)의 공통 프레임, 드래그 카드, 투영 라벨과 예보를 재사용한다. 기준은 `edict-order-panel/design/hud-quick-edit-mockup.dc.html`의 한국어·영어 보드다.

## 동작

긴급 생존은 편집 목록 밖에서 항상 먼저 판단한다. 기본 편집 순서는 **회피 → 버프 유지 → 회수 → 공격 → 목표 진행 → 재정비 → 탐색**이다. 일반 회피와 회피 유지도 순위를 따르며, 더 높은 준비된 행동을 먼저 실행할 수 있다. 물리적인 행동 잠금, 실제 시전 가능 여부와 긴급 행동의 기존 제약은 유지한다.

회수는 `PRIORITY_LOOT` 위치를 쓴다. `PRIORITY`로 설정한 전리품은 회수가 공격 위이면 전투 중, 아래이면 전투가 끝난 뒤에만 회수 후보가 된다. 등급 하나를 우선 회수로 설정해도 다른 등급을 승격하지 않는다. `AFTER_COMBAT`는 전투 종료 조건을, `PASSING`은 지나가면서만 줍는 조건을 그대로 따른다. 상자·성소는 탐색 범주 안에서 기존 `explore.order`로 선택하며, 진행 중인 발견물의 접근 위치도 같은 소유 코드로 계산한다.

버프 유지는 W06 함성·M05 보호막·A06 그림자, 직업 스킬의 자기 버프, 지속시간이 있는 보조 물약을 다룬다. 남은 시간이 `max(1.5초, 실제 지속시간의 15%)` 이하이고 적을 인지했거나 전투 중일 때 후보가 된다. 자동 사용 OFF, 쿨다운, 자원, 원래 자동 조건과 물약 재고를 검사한다. 자기 효과를 갱신할 때 다른 효과를 중첩하지 않으며, 물약은 같은 종류를 갱신한다. 재사용은 남은 시간을 버리고 새 지속시간을 시작한다. 보호막 합계 상한과 다른 보호막의 제약은 유지한다.

목표 진행을 공격보다 위에 두면 적이 있어도 발견한 봉인·운반자·제물·제단으로 이동할 수 있다. 봉인 파괴와 제물 수집·봉헌의 실제 진행에는 기존 `FieldSafe` 조건을 계속 적용한다. 이미 도착했지만 안전하게 진행할 수 없는 목표는 준비된 공격에 양보해 같은 자리에서 계속 대기하지 않는다. 더 높은 행동으로 전환하면 진행을 취소하되 누적 진행의 기존 보존 규칙을 따른다. 동점은 식별자로 가른다.

재정비는 비전투이면서 HP가 `survival.returnHpPercent` 미만이거나 자원이 50% 미만일 때 그 자리에서 기다린다. 둘 다 기준 이상이 되거나 적이 나타나면 끝난다. 최초 시작으로부터 15초 뒤에는 종료하고 같은 저자원 상태에서 다시 시작하지 않는다. 새로운 전투 또는 회복으로 이 상태를 해제한다. 시작 시점·대기·상한 도달 여부·선택 범주·걷기 상태는 `RunState.edictAction` v1에 저장한다. 재개할 때 원래 마감 시점을 유지하며 잘못된 시각·버전·상태 조합은 원본을 보존한 채 거절한다.

직업 스킬의 자동 시전도 `BUFF` 또는 `ATTACK` 후보로 경쟁한다. 순위보다 먼저 자동 공격을 실행하지 않는다. 사거리 때문에 준비되지 않은 자동 공격은 기존 공통 이동 정책으로 접근한다.

## 패널과 미리보기

공통 프레임의 고정 높이·안전 영역·가로 화면 오른쪽 배치를 따른다. 이름표, 설명, 긴급 생존의 금색 고정 안내, 일곱 카드, 되돌리기, 실행·일시정지 버튼을 표시한다. 카드 이동·키보드·▲▼는 기존 드래그 소유 코드를 사용한다. 드래그 중에는 초안 순서로 순번, 실행 중 카드, 영웅 라벨, 전리품의 회수 시점과 전장 표시를 갱신하고 손을 뗄 때 한 번 저장한다. 취소는 저장하지 않고 원래 미리보기를 복원한다. 빠른 편집 목록에는 현재 1순위도 표시한다.

영웅 라벨은 `지금 행동 · N · 행동`이다. 회수·목표·탐색에는 실제 경로를 따라 점선을, 공격에는 금색 화살표를, 버프·재정비에는 영웅 고리를 쓴다. 경로의 모서리를 지키므로 점선이 벽을 가로질러 지름길로 연결되지 않는다. 전리품 라벨은 공격과 회수의 상대 순위로 바뀐다. 새 Canvas·외부 의존성·이미지 에셋은 추가하지 않는다.

`PrepareEdictActionPreview()`는 패널을 열거나 저장한 뒤 후보 일곱 개를 준비한다. `PreviewEdictAction(order)`는 캐시와 초안만 읽는 구조체 결과이며 반복 호출에서 할당하거나 `RunState`를 쓰지 않는다. 목표·상자·성소·탐색의 같은 선택 함수는 `commit:false`에서 진행 상태·탐색 목표·재경로 계산을 변경하지 않는다. 실제 행동은 같은 후보와 순위 판정으로 선택한다.

항상 표시되는 HUD 버튼(PR 91)의 통합 시에는 `quickLive`를 유지한다. 마을 편집은 영웅 설정만 저장하고 전장 미리보기·실행 제어를 켜지 않는다.

통합 후보에는 상시 HUD, 몬스터 도감, 레지스트리·파이프라인 브랜치와 완료된 당일 괴물 8종(`ac5cacf6`)이 포함된다. 들어온 모델·초상화·메타데이터의 Git blob을 보존한다. W16은 보호막 만료 전 감속·속박 대응을 유지한다. M05 최초 사용은 원래 교전·예방 목적을 따르고, 이미 가진 자기 보호막만 유지 갱신의 대상이 된다. 직업 자동 시전은 원래 직업 소유 코드에서 실행하며 준비된 시작 보호막은 실제 행동이 시작될 때 확정한다.

공통 판단의 보완으로 이미 비용을 지불한 행동을 유지하고, 낮은 순위 행동이 회피 도착을 끊지 않게 하며, 선택한 규칙을 현재 대상에 다시 확인한다. 조준·생존 대응의 거절 사유는 판단 기록에 남긴다. 이동은 공통 `HeroPace`를 쓰고 벽 제약 뒤의 실제 변위로 걷기 상태를 계산한다. 마을 편집은 `quickLive` 경계를 유지하고 기존 저장 소유 코드를 사용한다.

## 저장과 공유 코드

전역 버전은 **v8**이다. v7의 여섯 항목 정의는 `Version7Global`에 고정해 이전 HED2 위치를 보존한다. 이전 형식을 그 버전 정의로 먼저 검증한 뒤 다음과 같이 변환한다.

1. `EMERGENCY`, `AFTER_COMBAT_LOOT`를 제거한다.
2. 남은 `DODGE`, `PRIORITY_LOOT`, `ATTACK`, `EXPLORE`의 상대 순서는 유지한다.
3. `BUFF`를 DODGE 뒤, `OBJECTIVE`를 ATTACK 뒤, `REGROUP`을 EXPLORE 앞에 삽입한다.

예전 전투 후 회수가 우선 회수보다 앞이었어도 `PRIORITY_LOOT` 위치를 택한다. 없어진 두 항목의 독립적인 순위는 복구할 수 없다. 실제 등급별 회수 모드는 보존한다. 누락·중복·알 수 없는 값은 삭제로 숨기지 않고 변환 전에 거절한다. 입력 원본은 변경하지 않는다.

영웅 문서, 직업 스킬 `legacyEdict`, 프리셋과 HED2~HED5 공유 코드가 같은 변환을 쓴다. v5 퍼즐 원본은 그대로 두고 변환 경로로 읽는다. 전투 프리셋은 공격을 회수 위, 회수 프리셋은 회수를 공격 위, 생존 프리셋은 기본 순서로 둔다. 전투 프리셋 이름은 ‘공격 후 회수’로 정리했다. E20 안내와 영어 문구를 갱신한다.

## 검증 기록

최종 집중 범위의 미해결 실패는 없다. 사용자가 현재 Mac 잠금을 해제하기 어려워 실제 화면 검증은 대기한다.

- 전체 Edit Mode는 `f2f81f86`에서 한 번 실행했다. 6,015건 중 5,881건 통과·130건 실패·작성/측정용 명시적 건너뛰기 4건이었다. 보완 뒤 실패 및 직접 영향 범위만 재실행했다. 완료된 XML을 전체 검사 이름으로 합친 결과는 **고유 2,068건: 2,066건 통과·작성용 명시적 건너뛰기 2건·미해결 실패 0건**이다. 원래 실패 130건 모두 실제 후속 결과가 있다. 변경되지 않은 통과 결과는 재사용하며 병합·문서 갱신 때문에 전체 검사를 반복하지 않는다.
- 변환·공유 코드, 이전 순서 전체, 우선 회수, 일반/긴급 생존, 버프 유지, 목표 안전 조건, 재정비·재개, 직업 스킬, 대상·필드, 들어온 괴물, 번역, 튜토리얼·퍼즐과 저장 바인딩을 다뤘다. 마지막 회피 도착·직업 시작 보호막 회귀도 통과했다. 선택 범주와 걷기 상태는 저장·재개된다. 이전 v1의 범주 누락은 허용하며 알 수 없는 범주는 원본 체크포인트를 보존한 채 거절한다.
- 공통 UI 계약과 회귀 15건이 통과했고 갱신 검사는 15개 바인딩·181개 UI 소스에서 통과했다. 레지스트리 도구 회귀 10건도 통과했다. 소스·XML 자료에는 커밋, 미커밋 입력 해시, 정확한 필터, 환경과 Unity가 만든 머티리얼 패치를 보존했다.
- 이전 후보의 189건은 당시 근거로 유지한다. 현재 통합 XML·순차 재사용 목록·실행 방법은 `integration-repair-20261012/coverage-ledger-final.json`에 있으며 이전 기록을 최종 후보의 전체 통과로 보고하지 않는다.
- 검사를 통과시키기 위해 전투 수치·물약·보상·시험 적 수치를 조정하지 않았다. L10 조기 개방 검사는 이미 열린 복귀 HP를 50%로 설정해 대기 영향을 구분한다. 별도의 세 직업 검사는 실제 기본 순서와 아래 회복 효과를 확인한다. 행동 순서 편집은 졸업 전 잠금을 유지한다.

패시브 비교는 직전 공격 대상 작업의 결과와 같은 BUILD_REF_SW01/SA01/SM03, 두 시드·20초·group·장비 없음으로 실행했다. 이전·이후 24행 모두 생존했으며 전체 빌드 평균 피해량은 다음과 같다.

전사 두 시드에서 W14 시작은 4회에서 3회, BASIC은 17회에서 18회로 바뀌었다. 이는 짧은 시뮬레이션에서 측정한 행동 순서 결과이며 전체 프레임·실기기 성능 수치는 아니다. 밸런스 조정은 하지 않았다. 행별 비교 키·해시·시전 횟수는 `passive-order-comparison.json`에 남겼다.

`여유 있을 때`는 실제 회복과 물약 대기 뒤 세 직업 모두 클리어하고, 건너뛰기는 목표를 놓친다. 승패를 강제하지 않고 실제 이벤트·상자·저장 보상 소유 코드로 결과를 확인했다. 그 밖에 보완한 튜토리얼·퍼즐 사례는 기획한 결과를 유지한다.

`RuntimeBattleQuickEditSmoke -hellscriptOrderOnly`에는 KO/EN 각각 440×956, 956×440, 1600×900, 1600×1000, 2100×900의 드래그·취소·단일 저장, 키보드·▲▼, 안전 영역·회전, 실행 표시·회수 문구·실행 제어 검사가 구현되어 있다. **최종 macOS 스모크와 화면 캡처는 실행하지 않았다.** 이 검증을 위해 최종 개발 플레이어는 워크트리 밖에 보존한다. 로컬 원본 문서는 갱신하며 공개 위키·사이트 게시는 보류한다.

XML·로그·소스 해시·원본 세이브·복구 목록의 검토일은 2026-10-26이다. 관리형 작업 폴더는 main 통합과 의존성 확인 뒤 보관한다. 영구 삭제나 기존 정기 작업 변경은 승인 범위에 포함하지 않는다.

## 조정할 기본값

- 버프 갱신의 1.5초 / 15%를 그대로 출시할지 실제 비용·효과 길이로 조정할지.
- 재정비의 자원 50%와 15초 상한을 유지할지.
- 일반 회피를 공격 아래로 내리면 준비된 공격 때문에 위험 범위 이탈이 늦어질 수 있다. 긴급 생존은 이 순서 변경으로 내려가지 않는다.

물리 모바일 기기, WebGL 플레이어, 운영 서버 저장, 같은 조건의 CPU 이전·이후 세 번 측정은 이 문서의 macOS 검증 범위에 포함하지 않는다.
