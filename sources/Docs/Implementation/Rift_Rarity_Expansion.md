## 2. 계산과 보존 범위

`t=max(0,R−1)`, `g=t/(t+49)`, `전설=p0+(상한−p0)×g`이다. 전설 기준/상한은 일반 1%/10%, 정예 5%/25%, 보스 15%/45%다. 비전설 등급은 `기준확률×(1−전설)/(1−p0)`로 비례 축소한다. 전부 HELLSCRIPT용 밸런스 초안이다.

전투는 `State.stage`, 소탕은 해당 영웅의 `highestClear`를 사용한다. 일반의 장비 발생 2%, 정예 1회, 보스·소탕 3회, 아이템 레벨 범위, 기존 강화·분해·상점·제작 비용, 골드·재료량, 전설 구성원 가중치와 세트 포함을 유지한다. 상점·제작·상자·오프라인 경로에 새 공식을 연결하지 않았다. 저장된 `Item`, `bossRewarded`, 소탕 영수증과 거래 구조를 유지하여 이미 확정된 아이템을 수령·재접속 때 다시 굴리지 않는다.

## 3. 코드·문서 차이 처리

- 일반·정예·보스의 기존 확률과 추첨 횟수는 첨부와 코드가 일치했다. 이를 1단계 기준으로 그대로 사용했다.
- 코드와 프로젝트 기존 명세에는 재설정 횟수에 따른 비용 증가가 남아 있었다. 첨부의 최신 규칙이 우선하므로 `500×L+50×L×(L−1)`, `L=max(1,아이템 레벨)`로 정정했다. 횟수와 무관하며 L=30의 비용은 매회 58,500골드다. 계수는 테스트 초안이다.
- 프로젝트의 이전 장비 상세 기획에 있는 아이템 레벨 60 상한은 실제 생성 코드에 없다. 이번에는 요청에 따라 기존 코드의 레벨 산정을 유지하고 차이를 표시했다.
- 전설 생성기는 실제로 직업·부위·구성원 가중치를 적용한다. `requiredSkill`은 현재 생성 후보군의 해금 필터가 아니다. 이번 기능은 해금 정책이나 이후 확장된 전설·세트 목록을 변경하지 않는다.
- 첨부 GDD·Excel의 LW04·LA04·LM04 가중치는 1이며, 이후 프로젝트 코드와 장비 상세 기획에서는 이미 10이다. 이번 요청이 전설 내부 가중치를 변경하지 않도록 명시했으므로 실제 코드의 10을 유지하고 첨부의 기존 콘텐츠 행도 이번 기능 범위에서 덮어쓰지 않았다. 신규 등급 확률은 이 별도 구성원 추첨 이전에만 적용한다.
- 첨부 GDD는 가방이 부족한 소탕 보상을 확정 미수령 묶음으로 보관하는 기획을 포함하지만, 현재 코드는 빈칸이 3개 미만이면 추첨 전에 소탕을 거부한다. 기존 저장·중복 방지 구조를 유지하라는 요청에 따라 이번에는 미수령 소탕 보관 기능을 새로 구현하지 않았다. 이미 생성된 실제 전투의 미수령 장비는 저장·재접속 후 그대로 유지되는 것을 검증했다.

## 4. 실행 검증

같은 작업 폴더에서 다른 Unity 검사가 실행 중이어서 소스·패키지·설정을 `/tmp/hellscript-rarity-work/unity`에 복제해 검사했다. 검사 대상 보상 Core 4파일과 테스트 2파일의 SHA256이 원본과 일치한다. Unity 버전은 6000.6.0f1, Test Framework는 프로젝트의 1.8.0이다.

### Unity Edit Mode

`RiftRarityTests`, `ItemizationTests`, `CoreTests`, `LocalizationTests`, `OutcomeTests`의 **115개가 통과했고 실패는 0개**다. 신규 등급 검사는 그중 28개다. 증거는 `Artifacts/Validation/RiftRarity/focused.xml`과 `focused.log`에 보존한다.

- 전설·레어 이상·마법 이상 누적 확률, 경로별 위계, 금지 등급, 조절 파라미터와 잘못된 데이터 거부를 검사했다.
- 실제 전투의 공개 `Tick`에서 일반·정예·보스 처치 보상을 만들고 현재 10단계/최고50단계를 구별하는 결과와 난수 소비를 대조했다.

- 바닥의 미수령 보스 장비를 저장·로드하고 최고 기록 및 새 생성 요청 단계를 바꿔도 결과와 보상 난수 상태가 유지되는지 검사했다. 반복 수령·재접속 시 중복 지급되지 않았다.
- 오프라인 장비 미지급, 재설정 횟수와 무관한 비용 및 재화 부족 시 보존을 검사했다.

### 고정 시드 추첨 실험

각 표본의 허용오차는 확률 단위 `max(0.001, 6×sqrt(p×(1−p)/N))`로 미리 정했다. 0% 등급은 정확히 0건이어야 한다.

| 실험 | 표본·난수 시드 | 결과 |
|---|---|---|
| 경로별 등급 | 3경로 × 1·10·50·1000단계 × 각 100,000회, seed=20260912 | 총 1,200,000회 모두 허용오차 이내. 최대 절대편차 약 0.267464%p |
| 일반 장비 발생 | 1단계·1000단계 각각 50,000처치, seed=918273 | 1,075건(2.15%)·1,080건(2.16%), 기준 2%의 허용오차 이내 |
| 전설 내부 LW04 | 이미 전설인 전사 목걸이 20,000회, seed=112681 | 1,846건(9.23%), 기존 가중치 10/110=9.0909%의 허용오차 이내 |

이는 수학적 확률과 자동 추첨 검증이다. 실제 플레이어의 장기 파밍 분포를 측정한 결과는 아니다.

## 5. 남은 제한

Android/iOS 실기기 실행, 장기 경제 밸런스 및 사용자의 수동 플레이테스트는 수행하지 않았다. 매우 높은 단계의 확률 함수는 검사했지만 그 단계에서의 전체 몬스터 능력치·재화·아이템 수치 체계를 무한 범위로 검증한 것은 아니다. Excel에서 파라미터를 바꾸면 확인표는 갱신되지만 런타임 코드 데이터는 별도로 함께 변경해야 한다. 기존 로컬 저장 권한·중복 방지 구조를 유지했으며 새로운 서버 권한 체계를 추가하지 않았다.

## 6. 기존 기획서 갱신과 커밋 대상 검증

2026-09-12 커밋 요청에 따라 기존 문서도 다시 대조했다. 구현 계획과 콘텐츠 카탈로그에는 첨부 기준본의 프로젝트 저장 위치와 현재 보상 정책을 연결했다. 균열 탐색 상세에는 일반·정예·보스의 단계별 확률, 상자의 적용 제외, 소탕의 선택 영웅 최고 실클리어 단계 기준을 반영했다. 위키 현재 상태와 관련 문서 이력도 갱신했다.

[장비 미결 항목](../Design/HELLSCRIPT_Itemization_Open_Items.md)의 고정 전설 확률 15% 기반 획득 기대값은 과거 계산으로 표시하고, 현재 30단계 공식으로 다시 계산했다. 보스 장비 1회당 전설 확률은 약 26.153846%이며, 목표 직업 목걸이의 부위 확률 1/8과 기존 구성원 가중치 10/110을 적용하면 보스 1판에서 목표 아이템을 하나 이상 얻을 확률은 약 0.888961%다. 평균 112.49판이며 판당 4분을 가정하면 약 7.50시간이다. 이 값은 보스 보상만 계산한 이론값이다. 필드·정예·상자를 합친 기존 추정치는 현재 동선별 횟수를 반영한 재산정이 필요하다고 명시했다. 전설 구성원 가중치는 변경하지 않았다.

다른 기능의 미커밋 변경이 같은 작업 폴더에 있어, 이번 기능만 선별한 커밋 대상 파일을 별도 프로젝트로 내보내 다시 검증했다. 함께 수정된 `CombatSimulation.cs`, `GameUI.cs`, 영어 번역 표에서는 이번 기능에 해당하는 변경만 포함했다. 검증한 코드·테스트·번역 및 메타 파일 16개의 SHA256이 커밋 대상과 일치한다.

- 관련 Unity Edit Mode 검사 115개가 다시 모두 통과했다. 실패·건너뜀은 0개다.
- 해당 소스로 만든 macOS 개발 빌드는 오류 0개로 성공했다.
- 새 실행 파일에서 한국어·영어와 세로·가로 화면, 진행 중인 10단계와 최고 기록 50단계의 구분, 안내 열람 시 계정 불변 검사가 통과했다. 저장된 화면 5장도 확인했다.
- 검증 결과는 `Artifacts/Validation/RiftRarity/publish/`에 보존한다. `publish-focused.xml`, `publish-focused.log`, `publish-build.log`, `publish-source-hashes.json`, `evidence/`가 포함된다. 이 경로는 프로젝트의 기존 규칙에 따라 Git에서 제외한다.
