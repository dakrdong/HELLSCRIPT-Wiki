# 장비 공용 UI 묶음 — 강화 스파크 · 장착 비교 · 분해 설정

갱신일: 2026-10-21 · [English](Gear_Ui_20261021.en.md) · 브랜치 `claude/gear-ui-20261021` · 기준 `main` c6354cbf

사용자가 main c6354cbf 빌드를 테스트해 보고한 세 건(보고 2·8·9)을 한 묶음으로 다룬다. 계산·거래·저장 소유권은 바꾸지 않는다.

## U4 · 대장간 장비 강화 스파크 (보고 2)

**요청.** 강화에 성공하면 강화로 바뀌는 숫자에 스파크가 튀어 눈에 띄게 한다. 사용자 답변: 대상은 강화로 값이 바뀌는 모든 수치이며 기본 범위는 장비 강화 화면이다. 다른 대장간 서비스로 넓힐지는 이후 사용자가 판단한다.

**구현.**
- `ForgeStatSpark`(`BlacksmithWindow.Gear.cs`)는 한 숫자(또는 게이지 오른쪽 끝) 둘레에 금색 네 갈래 별 9개를 0.7초 동안 흩뿌리고 스스로 사라진다. 시간은 `Time.unscaledTime` 기준이며 살아 있는 동안만 다시 그린다. 정점은 매 프레임 같은 규칙으로 만들고 새 객체를 할당하지 않는다.
- `CommitGear`가 `store.EnhanceEquipment` 성공 직후에만 `sparkItem/sparkFrom/sparkTo/sparkStart`를 기록한다. 실패·재오픈·일반 저장·언어 전환은 이 줄을 지나지 않는다.
- 화면을 다시 그릴 때마다(`DrawGearScreen` → `GearCard`·`DrawGearDetail`·`GearPortrait`·`DrawGearDock`) `SparkAge(item)`가 0.0~1.2초 안이고 항목과 강화 단계가 기록과 같을 때만 스파크를 붙인다. 시간 상자 안의 재생성은 같은 위상에서 이어 그리고 처음부터 다시 재생하지 않는다. 시간이 지났거나 선택·탭이 바뀌면 기록을 비운다.
- 숫자별 대상: 강화 +N 줄, 게이지 끝, 현재 능력, 다음 강화(+100에서는 값이 그대로라 제외), 누적 강화 보너스, 세로가 아닌 화면의 +N 배지·목록 카드의 능력치와 +N·하단 강화 줄. 강화 전 값·매 강화마다 증가량·성장 미리보기·견적 버튼 문구는 바뀌지 않거나 숫자 수치가 아니라 제외했다.
- 움직임 줄이기(`StoryDialogueWindow.ReduceMotion`)에서는 같은 숫자 아래 정지 금색 밑줄을 1.2초 동안 둔다. 이동·점멸은 없다. 모든 스파크는 `raycastTarget=false`라 숫자 판독과 클릭을 가리지 않는다.

**검증.** `ForgeGearSparkTests`(새), `ForgePresentationAllocationTests`, `BlacksmithCasualSkinTests`를 Edit Mode로 실행했다. 새 테스트는 스파크 정점이 숫자 근처에 머무르고 끝에서 투명해지는지, 움직임 줄이기가 정지인지, 워밍업 후 할당이 없는지와 성공·저장 실패·최대 강화·연속 강화·선택 변경/재오픈·시간 만료·움직임 줄이기를 직접 확인한다. 기존 링 기준선 검사는 새 효과를 대신하지 않는다.

- 실행: Edit Mode 27개 중 27개 통과(`ForgeGearSparkTests` 11, `ForgePresentationAllocationTests` 7, `BlacksmithCasualSkinTests` 9), 배치 모드, 컴파일 오류 없음. `check_ui_contract.py --verify` 15개 통과, `check_ui_refresh.py` 14개 바인딩 통과. 전체 Edit Mode는 실행하지 않았다.
- 캡처: `GearUiEvidence20261021/`의 `*-contact-sheet.png`(성공 전, 스파크 0~700 ms 9단계, 움직임 줄이기 표시, 만료 뒤)와 `*-sparks.mp4`, 단계 로그 `*-steps.log`. `UiFidelityGearSpark`(배치 모드, 헤드리스)로 만들었다. 배치 모드 Screen이 640×480이라 세로 프레임은 221×480으로 작다. 이 영상은 `ForgeStatSpark.Age`를 단계별로 지정해 이어 붙인 것이어서 **효과가 나타나는 위치·순서·소멸의 근거**이지 실제 재생 시간(프레임 간격)·실기기 성능의 근거가 아니다.
- 확인하지 못한 것: 실제 Game View에서 본 연속 재생, 440×956·956×440 정확 해상도와 PC 16:9·16:10·21:9 캡처, 영어 캡처. 영어 문구는 이번 변경에 없다(새 문구 없음).

**남은 일.** 다른 대장간 서비스(옵션 변경·슬롯·코어)에는 확대하지 않았다. 실기기 성능은 측정하지 않았다. 사용자가 세기·위치를 보고 "조금씩 수정"할 때 쓸 수 있는 조절 값은 `ForgeStatSpark`의 `Life`, `Count`와 별 크기(`h*.3f+4`)다.

## U5 · 아이템 상세·장착 비교·점수 (보고 8)

**요청.** 상세 창이 허술하다. 디아블로4를 참고하되 색은 이 게임의 크림·남색·금색과 등급색으로 다시 그린다. 장착 비교는 착용품과 후보가 한 화면에 보여야 하고, 점수가 좋은지 나쁜지가 초록·빨강으로 한눈에 느껴져야 한다.

**확인한 사실(소스).**
- 옛 갈색/금색은 `ItemDetailPopup`이 크림 창 위에 어두운 `StorageSurface`를 다시 칠하고 금색 제목·버튼을 그리던 것이 원인이었다. 카드 본문(`ItemDetailView`)은 이미 크림·남색이었다.
- 점수의 초록/빨강 계산은 있었다(`ItemTooltip.Score`). 밝은 연두/연어 색이 크림 바탕에서 `UiSkin.OnLight`를 거치며 어두운 갈색으로 눌려 "흐린 붉은색 한 줄"이 된 표시 문제였다.
- 세로(폭 460 미만)는 `EquipmentComparisonView`가 탭으로 한 장씩 보여 주었고, 인벤토리 상세는 세로에서 비교를 열지 않았다.

**구현.** 호출부(인벤토리·상점·창고·추천·보상·훈련)는 `EquipmentComparisonView.Create` 하나를 공유하므로 이 부품과 상세 셸만 고쳤다. 규칙은 [비교 규칙의 2026-10-22 항목](../Design/Equipment_Comparison_Rules.md)에 있다.
- 항상 두 카드(왼쪽 착용 한 개, 오른쪽 후보). 반지 두 개와 주/보조 무기는 버튼으로 하나만 골라 1:1로 본다. 반지는 고른 위치가 교체 대상이다.
- 점수 띠: `장비 점수`와 무기 `무기 구성 점수`를 따로 두고, 초록/빨강/중립 + 부호 + 화살표 + 단어 + 퍼센트로 표시한다. `ItemTooltip.ScorePair`로 같은 비교 기준을 한 곳에서 만들고 `ItemTooltip.Score` 줄도 이것을 쓴다. 단일 상세의 점수 명판도 같은 색 기준을 쓴다.
- 가로·PC는 왼쪽 레일(점수 띠·구성 띠·장비 선택 버튼) + 전체 높이의 두 카드, 세로는 위 띠 + 두 카드. 푸터에는 변화 문장과 `{0}에 장착` 버튼을 둔다.
- `ItemDetailPopup`은 `UiSkin`을 받으면 casual 창·버튼·범위 토글·말풍선을 쓰고, 스킨이 없는 호출부는 옛 셸을 유지한다. `InventoryWindow.ShowDetail`은 미장착 아이템이면 항상 비교로 열고(`장착 비교` 버튼은 없어짐) `ShowComparison`은 이를 호출하는 얇은 별칭이다.
- 사용자 지시로 시안을 두 번 고쳤다: ① 세로에서도 탭 없이 두 카드, ② 가로에서 카드를 쌓지 않고 왼쪽 레일 + 두 카드. 시안 캔버스의 `장착 비교` 보드가 최종 구조다.

**남은 일·한계.**
- 용어: 사용자의 스케치는 가운데를 "비교 대상", 오른쪽을 "원래 장비"로 적었다. 규칙(착용품 왼쪽, 후보 오른쪽)에 맞춰 가운데는 착용 장비, 오른쪽은 후보로 구현했다. 반대 의미였다면 알려 주면 바꾼다.
- 상점 상세는 호스트 폭이 좁아 세로 구조(위 띠)를 쓰는 경우가 있다. 상점·창고·보상·추천·훈련 화면의 실제 캡처는 아직 못 했다.
- 네이티브 스모크(`RuntimeInventorySmoke*`, `RuntimeEquipmentShopSmoke.Layout`, `RuntimeFirstPlayAcceptance`)는 새 구조(탭 삭제·`장착 비교` 버튼 삭제)에 맞춰 고쳤지만 macOS 플레이어에서는 실행하지 못했다.

**검증(U5).** Edit Mode 304개 통과(배치 모드): `ItemComparisonTests` 39(새 5개: 반지·주/보조 한 장씩과 버튼 1:1, 점수 띠 부호·색·단어, 레일/세로 배치), `NativeInventoryTests` 38, `CasualUiSkinTests` 12, `RiftGearOfferWindowTests` 5, `ItemTooltipSettingsTests` 14, `RecommendedEquipmentTests` 92, `StorageCasualSkinTests` 6, `EquipmentShopTests` 30, `LocalizationTests` 34, `SharedUiTests`(고친 1개). `check_ui_contract.py --verify` 15개 통과(색은 `UiTheme.Compare*` 토큰), `check_ui_refresh.py` 14 바인딩 통과.
- 캡처: `GearUiEvidence20261021/compare-*.png`(한국어 세로·가로·PC, 영어 세로·가로). 각 장은 점수 하락·상승·비슷한 점수·반지 두 개·빈 부위·양손 무기(주 무기 + 방패)·착용 중 단일 상세를 담는다. 배치 모드 Screen이 640×480이라 세로 프레임이 221×480으로 작다. 이 캡처는 배치·색 근거이며 정확한 440×956·956×440, PC 16:10·21:9, 실제 터치·포인터 근거가 아니다. 점수 "동점"은 아이템 점수가 임의 옵션으로 달라 캡처에서는 정확히 같지 않았다(동점 색은 단위 테스트가 확인).
- 확인하지 못한 것: 네이티브 스모크 실행, 상점·창고·보상·추천·훈련 화면의 실제 캡처, `RiftResultTests`·`RiftVictorySkinTests`(단독 실행하면 `RiftVictoryWindow`의 정적 초기화가 MonoBehaviour 생성 중 `Resources.Load`를 불러 15개가 실패한다. 이번 변경 이전부터 있는 실행 순서 의존이며, 이 창에는 팝업에 `v.Skin`을 넘기는 한 줄만 바꿨다).

## U6 · 일괄 분해 자동 선택 설정 새 양식 (보고 9)

**요청.** 분해의 자동 선택 설정 창을 새 아트 컨셉의 창으로 교체한다(검정/갈색, 긴 장비 목록, 하단 고정 저장 버튼이 옛 양식).

**확인한 사실(소스).** `InventoryWindow.OpenAutoSettings`가 `EquipmentShopWindow.OpenAutoSettings`의 설정 전용 호스트를 열고, 이 호스트는 옛 `DrawSettings`를 그렸다. 상점에는 새 양식 `DrawMockSettings`가 따로 있었다.

**구현.**
- 설정 전용 호스트가 `DrawMockSettings`를 그린다. 호스트는 빈 캔버스 위에 창 영역만 만들고 상점 재고 준비·거래·`Repaint` 경로를 타지 않는다. 열기만으로 계정 상태가 바뀌지 않는다(테스트로 확인).
- 문구 "상점과 분해가 같은 캐릭터의 자동 선택 설정을 사용합니다."를 유지한다. 편집은 초안(`draft`)에만 적용되고 저장 성공 때 반영한다. 취소·저장 실패는 원본 `Hero.equipmentShop.auto`를 건드리지 않으며, 실패하면 창이 열린 채 하단에 오류를 보인다. 저장은 분해를 실행하지 않는다.
- 하단 고정 줄: `분해 대상 N개`는 상점 판매 수가 아니라 `InventorySalvagePlan.Eligible`(장착·잠금·보석·프리셋 보호)과 `ShopAutoSelect.MatchesFilters(초안)`을 적용한 결과이며 분해 목록과 같은 식이다. 아래에 `보호 장비 N개는 제외됨`을 둔다. 소지품 개수 표시도 같은 기준이다.
- 무기/방어구/장신구는 접이식 묶음이다(무기만 처음에 열림, 세부 설정을 연 종류의 묶음은 항상 열림). 묶음 체크박스는 묶음 전체를 켜고 끈다. 상점의 설정 창은 기존 펼친 목록을 유지한다.
- 설정 의미와 저장 키(`Hero.equipmentShop.auto`)는 그대로다. 옛 설정 전용 분기와 그 문구는 지웠다(`DrawSettings`는 갬블 상점용).

**남은 일·한계.** 시안의 "캐릭터·레벨 칩"은 호스트에 카탈로그가 없어 넣지 않았다. 일괄 분해 확인 창(`ShowSalvage`)의 목록·버튼은 이번 범위가 아니다. 실제 세로 키보드 노출·긴 목록 중간/하단 스크롤·입력 포커스 보존은 Edit Mode에서 확인하지 못했고, 스크롤·포커스는 기존 `MockSettingsChanged`/`ApplySettingsOffset` 경로를 그대로 쓴다.

**검증(U6).** `SalvageSettingsHostTests`(새 6개)가 열기만으로 계정 JSON이 같음, 초안 편집·취소가 원본을 보존함, 저장이 캐릭터 자기 설정만 바꾸고 다른 캐릭터·소지품·골드를 건드리지 않음, 저장 실패가 원본을 보존하고 창이 열려 있음, 대상 수가 분해 목록(`InventorySalvagePlan.AutoSelect`)과 같고 초안 편집 때 다시 셈, 묶음 접기·묶음 체크박스를 확인한다. 위 U5 검증 묶음(304개)에 함께 들어 있다.
- 캡처: `GearUiEvidence20261021/settings-*.png`(한국어 세로·가로·PC, 영어 세로): 처음 상태, 방어구 묶음 열기, 도끼 세부 설정 열기, 일반 등급 끄기(대상 8 → 4). 확인하지 못한 것: 세로 키보드 노출과 저장 버튼 가림, 긴 목록 중간·하단 스크롤과 입력 포커스 보존(실제 키보드·포인터 필요).
- 세로에서는 개수 줄을 버튼 위로 쌓고, 영어처럼 등급 이름이 길면 등급 칩을 두 열로 바꾼다(상점 설정 창도 같은 규칙을 쓴다).
