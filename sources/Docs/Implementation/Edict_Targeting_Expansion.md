# 사냥 칙령 대상 선택·추적 개발 기록

작성일: 2026-09-12 · 이전 단계: [클로드 작업 검토와 후속 수정](Claude_Review_20260912.md)

후속 구현인 [관문 통행 개발 기록](Gate_Passage_Expansion.md)에서 실제 통행 차단·개방을 연결했다. 아래 남은 범위는 대상 선택 단계가 끝난 시점의 기록이다.

## 구현 기준과 범위

[전역 옵션 상세안](../Design/HELLSCRIPT_Hunt_Edict_Global_Options.md)의 공격 대상·추적과 [구현 계약](../Design/HELLSCRIPT_Hunt_Edict_Implementation_Contract.md)을 실제 전투에 연결했다. 능력치와 밸런스 작업은 사용자 요청대로 별도 클로드 작업 폴더에 남겨 두었다. 이번 `GameCatalog.cs` 변경은 진행 중 추적 상태 필드 하나이며 능력치·성장·피해 계산은 수정하지 않았다.

이전 구현은 전역 대상 선택을 기존 열거값 하나로 변환했다. 높은 HP는 가까운 적으로, 보스와 정예는 같은 대상으로 읽혔고, 거리 점수와 HP를 섞어 계산했다. 새 판단은 각 우선순위를 순서대로 비교한다.

## 실제 행동

| 설정 | 현재 동작 |
|---|---|
| 가까운 적 | 감지한 적 중 거리가 짧은 대상을 선택한다. |
| 낮은·높은 HP | 최대 HP 대비 남은 비율을 먼저 비교하고, 비율이 같을 때 거리·적 ID 순으로 정한다. 편집 화면에도 비율 기준을 설명한다. |
| 밀집한 곳 | 선택 반경 안에서 서로 보이는 감지 대상의 수를 먼저 비교한다. 같은 인원이면 거리·적 ID 순으로 정한다. |
| 특수 대상 순서 | 켠 보스·정예·지원형·원거리형을 저장한 순서대로 비교한다. 해당 종류가 없으면 다음 종류와 기본 선택으로 넘어간다. 보스는 일반 정예에 포함시키지 않는다. |
| 원거리·지원형 분류 | 원거리 공격형은 N03·N04·N09·N10, 회복·지원형은 N05·N11이다. 적 콘텐츠의 현재 행동에 따른다. |
| 처치까지 유지 | 관측 중인 유효 대상은 다른 보스·정예가 나타나도 유지한다. 시야 상실·추적 한도와 긴급 생존은 유지보다 우선한다. 방해 가능한 위험 시전은 별도 긴급 대상 판단으로 전환할 수 있다. |
| 우선순위에 따라 변경 | 더 나은 대상이 관측되면 다음 판단 시점에 바꾼다. 기존 0.6초 유지 제한으로 새 보스를 기다리지 않는다. |
| 보스전 대상 | 보스 우선, 현재 보스가 소환한 적 우선, 지원형 우선을 구분한다. 보스 소환수는 현재 보스의 `summonerId`를 가진 적이며 다른 필드 이벤트 적을 포함하지 않는다. 선호 대상이 없으면 보스와 일반 대상으로 이어진다. |
| 위험 시전 방해 우선 | 감지한 위험 공격·회복·보스 소환을 준비 중이며, 실제 자동 사용 가능한 지면 강타(W04) 또는 서리 폭발(M06)이 사거리·시야·자원·쿨타임·조건과 남은 준비 시간을 충족할 때만 우선 대상으로 삼는다. 보스는 이번 제어로 제압 게이지를 완성할 수 있어야 한다. 공격 스킬의 실행 순서 자체를 바꾸는 옵션은 아니다. |
| 추적 중단 | 시야를 잃으면 적의 현재 숨은 위치나 일반 관측 기억을 추적 목표로 사용하지 않는다. |
| 마지막 위치 확인 | 현재 대상의 마지막 관측 좌표까지만 이동한다. 도착 후에도 관측하지 못하면 확인을 끝낸다. 숨은 위치가 바뀌어도 확인 좌표는 바뀌지 않는다. |
| 최대 추적 거리 | 해당 교전의 시작 좌표를 기준으로 한다. 추적 이동이 거리 경계를 넘기 전에 중단한다. |
| 최대 추적 시간 | 사거리 밖 접근과 마지막 관측 위치 확인 중에만 누적한다. 사거리 안 공격·대기와 일반 선회에는 쓰지 않는다. 일시정지·정리 귀환에서도 흐르지 않는다. |
| 추적 종료 후 | 같은 적이 계속 관측되고 사거리 밖에 있는 동안 즉시 같은 추적을 다시 시작하지 않는다. 적이 공격 범위로 들어오거나 시야를 잃었다가 새로 마주치면 다시 대응할 수 있다. |

대상·추적 판단은 발견한 적과 마지막 관측 정보로 처리한다. 보스가 보이지 않을 때는 보스 광장의 알려진 위치로 이동하며 보스의 숨은 현재 위치를 읽어 따라가지 않는다. 추적 종료 사유는 전투 기록의 `EDICT_PURSUIT_END`에 남긴다.

## 저장과 설정 변경

대상 ID·교전 시작점·마지막 관측 위치·추적 누적 시간·확인 중 여부·현재 추적 제외 목록은 `RunState.edictTarget`에 저장한다. 기존 저장은 이 선택 필드가 없어도 열린다. Unity가 누락된 정책을 빈 객체로 복원하는 경우도 있어, 정책 버전 0은 기존 동작, 버전 1은 새 판단으로 구분한다. 더 새로운 버전은 원본 저장을 보존하고 불러오기를 중단한다. 새 전투 동작에는 당시의 정확한 대상 정책 사본을 기록하므로 진행 중인 회오리는 새 원본을 저장하거나 앱을 재시작해도 시작 당시의 대상 방침을 사용한다. 공유 코드에는 현재 추적 대상이나 개인 전투 상태를 넣지 않는다.

사냥 칙령을 끄면 기존 대상 선택을 유지한다. 기존 행동 규칙에서 명시적으로 고른 개별 대상 기준은 그 의미를 보존하며, 전역 상속 규칙에 이번의 정확한 대상 정책을 적용한다. 독립된 새 스킬 판단기로 이전하는 작업과 구분한다.

## 화면 대응

[화면 상세 기획](../Design/HELLSCRIPT_Screen_Layout_Detail.md)에 따라 칙령의 편집 내용과 저장 상태를 유지하면서 가로·세로 화면에 대응했다. 순서 변경 버튼의 폭과 행 높이를 늘리고, 긴 안내문은 실제 문장 길이에 맞춰 행 높이가 늘어나도록 했다. 화면 폭이 바뀌면 읽던 위치를 기준으로 다시 배치한다. 화면을 다시 구성하거나 설정을 바꿀 때에도 새 내용의 높이를 계산한다.

영어 140% 글자 크기에서 작은 화면의 순서 변경 버튼과 긴 경고문이 잘리는 문제를 실제 실행 중 발견해 수정했다. 화면에 모든 선택지를 한꺼번에 넣는 방식이 아니라, 본문을 스크롤하면서 하단 저장·되돌리기 버튼을 사용할 수 있는 구성이다.

## 아직 연결되지 않은 범위

- 황금 고블린 콘텐츠는 아직 없다. 우선 처치를 켜면 편집 화면에서 현재 실행할 수 없음을 알리고 선택값을 보관한다. 고블린 전용 추적 거리·시간은 콘텐츠를 추가할 때 연결한다.
- 스킬별 핵심 옵션 전체와 기존 규칙에 의존하지 않는 실행 판단기는 후속 개발이다. 이 단계는 대상 선택을 이유로 숨은 스킬 규칙을 새로 만들지 않는다.
- 조건부 장비·세트 발동으로 발생할 수 있는 끌어당김이나 제어 연쇄를 위험 시전 방해 수단으로 미리 계산하지 않는다. 이번 직접 방해 수단은 W04·M06이다.
- 균열 관문의 실제 통행 차단·개방, 정수·제물 목표, 자동 정리·반복의 나머지 선택과 온라인 계정은 이전 남은 작업으로 유지한다.

## 검증

Unity 6000.6.0f1에서 검사했다. 증거 폴더는 `Artifacts/Validation/EdictTargets`다.

- 수정 전 대상 선택 검사 15개 중 13개가 기존 구현에서 실패했다. `before.xml`.
- 첫 수정 후 대상·칙령·번역 관련 70개가 통과했고, 시전 방해 선택을 추가한 관련 검사 61개도 통과했다. `first-fixed.xml`, `target-complete.xml`.
- 전체 검사 중 구형 저장의 빈 정책 객체가 새 정책으로 해석되는 회귀 7개를 발견했다. 기존 동작 연속성 검사의 기대값은 유지하고 정책 버전으로 구분했다. 수정 후 관련 105개가 통과했다. 실패 기록 `full-final.xml`, 수정 결과 `migration-fixed.xml`.
- 최종 전체 검사 **1,243개 중 1,243개 통과**, 실패·제외 0개. 2026-09-12 18:12:40–18:16:05 KST. 새 대상·추적 검사는 33개이며, 기존 동작 연속성 검사도 함께 통과했다. `full-verified.xml`.

최종 macOS 개발 실행본은 `Builds/macOS-EdictTargets/HELLSCRIPT.app`이다. `build-verified.log`에서 빌드 성공·오류 0개·정상 종료를 확인했다.

- 표적 선택 실행과 별도 프로세스 재시작 2회가 통과했다. 실제 편집 화면에서 높은 HP를 저장한 뒤 더 가까운 낮은 HP 적 대신 높은 HP 적을 고르고, 추적 도중 저장한 시간을 복원했다. 남은 시간이 끝나면 반복 추적을 멈추며, 적이 사거리 안으로 들어오면 다시 대응한다. 재시작 후 전투 상태는 같은 입력을 준 대조 실행과 일치했다. `native-results.json`.
- 화면 공통 변경에 대한 칙령 편집·저장·공유·재시작 검사 2회도 통과했다. 초안 수정, 순서 이동, 장착 칸, 스킬 설정, 되돌리기, 공유 코드 가져오기와 저장값 복원을 확인했다. `editor-results.json`.
- 최종 실행본의 화면 증거는 22개다. 한국어·영어, 640×360·720×1280·1280×720·1920×1080 창과 영어 140% 글자 크기를 확인했다. 모든 언어·크기 조합을 검사했다는 뜻은 아니다. [큰 글자의 작은 화면 순서 버튼](../../Artifacts/Validation/EdictTargets/Evidence/06-target-order-english-140-compact.png), [한국어 대상 설정](../../Artifacts/Validation/EdictTargets/Evidence/01-target-editor-korean.png), [재시작 후 추적 종료](../../Artifacts/Validation/EdictTargets/Evidence/01-resumed-pursuit-stopped.png).
- 전체 검사 이후 변경은 `GameUI.EdictEditor.cs`, `GameUI.cs`, `RuntimeTargetSmoke.cs`의 화면 배치·검증 보완이다. 전투·저장·검사 코드와 번역은 전체 검사 시점과 같고, 이 세 파일을 포함한 최종 소스는 위 빌드와 실제 실행 4회로 검증했다. 검사 시점과 최종 소스의 해시는 각각 `full-test-source-manifest.json`, `final-source-manifest.json`에 보관했다.
- C# 파일 196개, 기준에 포함된 기존 메타데이터·직렬화 자산·씬·설정·패키지·기획 파일 287개의 보존을 확인했다. 이번 단계의 새 C# 메타 파일은 4개이며 GUID 중복과 C# 메타 누락은 없다. 종합 결과는 `validation-summary.json`이다.

이 증거는 별도 저장 폴더를 사용한 macOS 개발 실행본의 자동 시나리오와 화면 확인이다. 모바일 실기기의 터치 조작, 장시간 성능, 전체 게임 밸런스 검증은 포함하지 않는다.
