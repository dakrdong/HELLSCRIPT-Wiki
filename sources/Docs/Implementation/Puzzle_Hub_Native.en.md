# Native puzzle waiting room implementation

2026-10-07. Stage 6 implementation. Native visual/input/performance acceptance remains scheduled for the final integrated player at stage 9.

`PuzzleHubWindow` uses the generated `ContentWindowView` entry point, shared host, safe area, theme, fonts and buttons. Its one-screen composition adapts the shared body to status, character art, a level board and fixed actions. Existing inventory, Hunt Edict, skill tree and settings remain their actual owners.

`GameController.Tutorials` prepares the current owned level and connects the hub to fresh attempts. Persisted `RecordPuzzleAttempt` results return to the hub. Prior levels use detached `CreateReplay` state. Town access remains locked until all 15 levels clear.

Menu transitions move the hub and existing destination window for 0.62 seconds. Portrait uses the X axis, landscape the Y axis; perpendicular swipes are ignored. The status stays fixed during transitions. Closing a destination or selecting Waiting room returns to the same hub.

The first status row contains actual HP/resource and the second full-width row XP. Selection reads saved progress, locks future levels, and switches the final cleared level action to Town. `StoreViewBinding` compares hero, progress, XP, skills and hint display dependencies and defers repaint during input, transitions and child windows. Language and safe-area changes invalidate layout.

The existing window host/camera lifecycle hides the world behind the opaque hub. Effects modify existing transforms, colors and fills without rebuilding UI each frame. Any performance result requires three matching launches of each real before/after player binary at final validation.

Import only necessary prototype HTML/tools/art/prompts; preserve unknown model provenance. Native textures receive a dedicated importer and ResourceTextureBudget entries. Historical screenshot batches are not imported.

Final acceptance: three classes, KO/EN, portrait 440×956, landscape 956×440, desktop 16:9/16:10/21:9; real arrow, replay, graduation, menu, axis swipe and save/reentry interactions; shared UI/refresh/binding checks. Full EditMode and native smoke run once on final integrated code. Physical mobile remains separately unverified.

Effect cost will compare two actual binaries of the same new hub, with effects disabled and enabled. The previous version has no hub and cannot represent the same screen. Capture three launches per binary with matching source, input, resolution, FPS and quality.

Integration: Unity drives overlay Canvas root geometry, so animate the existing window frame and fade its existing backdrop CanvasGroup. `ContentWindowView.FixedOverlay` owns the fixed status layer. Replay inventory/edict menus use real `GameStore.Sandbox` transactions, validation and commit notifications while changing only a detached copy without disk writes. Replay transactions and guide discoveries leave the original account unchanged.

2026-10-07 landscape layout correction (post-merge verification): in the merged build's landscape and wide screenshots (1280×720, 1600×900, 2100×900) the status bars stretched across the whole width and ran behind the level plate over the XP text, the level-name band covered the hero's face, and the light flow showed as a flat rectangle rather than a soft gradient. The geometry now lives in `PuzzleHubLayout` (a pure calculation) and follows the mockup's landscape rule: status cluster at the top left (260 wide), level plate at the top centre (200 wide), hero below it (62% of the height) and Play at the bottom right. On narrow landscape (16:9, 16:10) the plate steps aside to the right of the status area. Portrait is unchanged. The light flow uses one shared 32×1 soft-edged ramp sprite, created once. The English `Resource 100 / 100` that wrapped or ran over the frame in the narrower landscape bars is sized from its measured width so it stays on one line (Unity best-fit does not react to horizontal overflow, so it is not used). `PuzzleHubTests` checks status, plate, arrows, hero face and Play for overlap at six sizes, and the native smoke's `CheckHub` checks the same overlaps and that each status label fits its bar on the real screen. The earlier "controls are inside the safe area" check could not catch this.

2026-10-08 screen cleanup (user screenshots): (1) Windows opened from the hub (hunt edict, skills, inventory, settings) showed behind the fixed navigation buttons at the bottom in portrait and on the right in landscape. The band the navigation uses (118 units at the bottom, 98 on the right) is reserved with `UiSafeArea.Reserve`, so every window opened above it lays out in `UiSafeArea.Current`, the area that remains. The hub itself keeps the whole area through `ContentWindowView`'s `fullArea`. The reservation is taken when a menu opens and released when the hub returns home, closes or its owner is destroyed. (2) The level plate is smaller (240 units wide in portrait and 176 in landscape, was 350 and 200) and the level name sits under it on a soft pill shade. `PuzzleHubLayout` sizes the hero so the plate, name and progress dots never cover the top 22% of the picture where the head is (the hero is larger in portrait). (3) The two level arrows use the same picture, mirrored for the right one. Before, the shared button face covered the picture and only the right arrow carried a text glyph, so the pair looked different. An arrow that leads nowhere is only dimmed. For the same reason the original pictures of Play and the navigation buttons were hidden; they now use `UiButtonRole.Icon` (a press darkens the picture). The selected navigation button is shown by a soft golden light behind it and a bright label instead of a grey square. (4) The HP, resource and XP fills are pill shapes fitted to the transparent opening of the frame art (measured: rows 37-69 of 106 px, 75 px from each side), so they cannot poke out of the frame. The frame's end ornaments keep their proportions while only the middle stretches, and each value stays on one line that shrinks to the opening. Landscape stacks the bars in three rows. (5) The moving light block (`Light flow`) is gone from Play and from the bars. Under Play there is only a soft light that breathes in place (still under reduced motion, absent on the replay button). `PuzzleHubTests` checks the overlap of hero head, plate, arrows and dots and the plate size at nine sizes, whether the bar track lies inside the opening using the alpha of the real art, and that the reservation is released even when its owner is destroyed. The native smoke's `CheckHub` checks the arrow pair, the bar fills and the absence of a moving light, and `CheckHubChild` checks on the real screen, at every resolution and language, that an opened window never runs under a navigation button or label.
