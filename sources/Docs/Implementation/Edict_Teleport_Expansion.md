# 순간이동 사냥 칙령 개발 기록

작성일: 2026-09-13 · [English](Edict_Teleport_Expansion.en.md)

상태: **M04의 네 핵심 옵션 연결, 전체 검사 1,601개와 실제 macOS 앱의 설정 저장·재시작, 전후 32판 진단을 완료했다.**

## 해결한 문제

순간이동의 생존 경로는 새 사냥 칙령을 읽었지만, 일반 행동 후보에는 이전 자동 행동 규칙이 남아 있었다. 그 결과 전역 긴급 생존·회피가 요청하지 않아도 옛 위험 조건에 따라 준비 중인 공격을 취소할 수 있었다. 이제 사냥 칙령을 켜고 M04를 장착한 영웅은 네 옵션으로 독립적인 판단을 만든다. 이전 규칙이 없거나 꺼져 있거나 조건을 충족하지 않아도 새 설정으로 판단하며, 중복 후보는 하나로 합친다. 저장된 기존 규칙 목록은 유지하고 사냥 칙령을 끄면 다시 사용한다.

일반 거리 조정은 주 행동이 끝난 뒤에만 판단한다. 연쇄 번개를 준비하는 도중 M04의 공통 순서를 올려도 일반 거리 조정으로 공격을 취소하지 않는다. 필요한 생존 대응은 기존 전역 실행기가 중단 가능 구간과 회피기 불가 대응에 따라 처리한다. 기존 생존 경로에서 지원하던 적 없는 환경 위험도 유지했다.

## 전투에 연결한 네 옵션

| 옵션 | 실제 처리 |
|---|---|
| 자동 사용 | ON은 새 후보를 허용하고 OFF는 제외한다. 이미 시작한 준비 동작의 착지점을 설정 변경으로 바꾸지는 않는다. |
| 사용 목적 | SURVIVAL은 전역 긴급 생존·회피가 M04를 요구할 때만 사용한다. DISTANCE는 일반 교전에서 희망 거리와의 오차를 2m 이상 줄이는 후보를 먼저 남기고 도착 위치 선호로 고른다. 진행 중 주 행동·전역 위험 대응·긴급용 보존이 있으면 일반 거리 조정을 하지 않는다. |
| 도착 위치 | SAFE는 같은 1.5초 예고 범위의 예상 HP 손실이 가장 적은 후보, SPARSE는 허용 후보 중 주변 3m에서 보이는 적이 가장 적은 후보, DISTANCE는 전역 희망 거리에 가장 가까운 후보를 고른다. 유효한 감지 대상이 없으면 거리 선호를 SAFE로 대체한다. 일반 거리 조정 자체에는 유효한 전역 대상이 필요하다. |
| 도착지 허용 기준 | GLOBAL은 전역 회피·치명적 위험 판단을 통과한 후보를 쓴다. NO_DAMAGE는 같은 1.5초 예고 범위에 감지된 양의 최종 피해가 하나라도 예상되는 후보를 추가로 제외한다. 감지하지 못한 위험까지 없다고 보장하지 않는다. |

희망 거리는 전역의 직접 지정값 또는 기본 공격 사거리를 사용한다. 마법사의 기본 사거리 선택은 10m이며, 저장된 직접 지정값과 혼합하지 않는다. 일반 거리 조정은 전역에서 실제로 선택한 대상의 거리로 판단하고, 감지되지 않거나 추적에서 제외된 적으로 바꾸지 않는다.

생존용으로 쓰려면 **전역 방침에서 M04를 회피기 또는 대체 생존기로 지정하고 필요한 대응 조건을 켜야 한다.** 새 칙령 문서의 기본값에는 회피기 지정이 없고 긴급 HP·치명적 위험·각 회피 조건이 꺼져 있다. M04의 자동 사용만 켠 상태는 생존 대응을 구성한 상태가 아니다. 한국어·영어 카드 설명에 이 조건을 추가했다. 사용자가 저장한 전역 조건이나 기본값을 임의로 켜지 않았다.

## 시전과 착지의 경계

해금 레벨 10, 준비 0.2초, 재사용 대기시간 9초, 자원 비용 0을 유지한다. 이동 거리 2–8m, 유효 지형, 출발점에서의 시야와 감지한 적 몸체와의 겹침을 검사한다. 자원 비용이 없는 M04는 LC02 비용 할인 충전을 소비하지 않는다. 준비 중 피해를 막는 무적이나 자체 피해를 추가하지 않는다.

준비가 끝나기 직전 확정한 착지점의 거리·시야·지형·적 몸체를 다시 검사한다. 그동안 벽이나 적 때문에 무효가 되면 `ACTION_INTERRUPTED`를 기록하고 이동하지 않으며 쿨타임을 돌려주지 않는다. 설정을 바꿨다고 다른 지점으로 자동 교체하지 않는다. 이미 확정한 유효 착지는 OFF나 목적·선호 변경, 저장 복원 뒤에도 한 번만 실행한다.

이 실제 착지 검사는 이전 규칙의 순간이동에도 적용한다. 옛 대상 위치 규칙이 적의 중심을 요청하면 현재 유효 후보 중 요청 지점에 가장 가까운 곳을 선택한 뒤 시전을 시작한다. 적 몸체에 겹치는 불가능한 착지를 허용하지 않으면서 기존 규칙의 위치 의도를 유지한다. 2m 경계의 부동소수점 오차에는 작은 허용 오차를 적용한다.

도착 후에는 같은 틱에서도 전역 탐색·추적을 다시 시작할 수 있다. 서리 폭발·화염구를 예약하지 않으며 벽 통과·무적·쿨타임 초기화도 추가하지 않는다. 따라서 이동 완료 여부는 실제 `ACTION_END`의 착지 좌표로 확인하고, 이후 영웅이 계속 그 자리에 서 있어야 한다고 가정하지 않는다.

## 연쇄 번개 중단 진단

기존 관측 도구에 실제 중단 사유, 시각, HP 비율, 대체 행동과 직전 전역 위험 판단을 추가했다. 직전 판단은 나중에 같은 틱에서 일어난 사건의 직접 원인과 다를 수 있으므로 실제 행동 사건의 사유를 우선한다. 관측의 비간섭 검사도 유지한다.

클로드의 능력치 통합 이후 개발을 포함한 `e601046`을 이전 코드로 사용했다. 이전·변경 코드에서 각각 기존 규칙 8판과 기본값 사냥 칙령 8판, 총 32판을 실행했다. 과거 결과에서 선택한 시드 인덱스 0·1·2·3·4·5·9·14이며 무작위 표본이 아니다. 레벨 30·20단계·합법적인 8부위 장비를 고정했다. 각 쌍의 시드·지도·적·목표·장비 전체 값·능력치 시트·최대 HP·기본 피해가 일치했고, 이전 코드의 결과 요약은 M03 단계의 보존 자료와 모두 일치했다. 시전·발사·적중·중단 수와 관측 시간도 기존 집계에 맞았다.

| 측정값 | 이전 기존 규칙 8판 | 이전 기본 칙령 8판 | 변경 기존 규칙 8판 | 변경 기본 칙령 8판 |
|---|---:|---:|---:|---:|
| 클리어 / 사망 / 시간 초과 | 0 / 4 / 4 | 0 / 4 / 4 | 0 / 4 / 4 | 0 / 7 / 1 |
| 보스가 등장한 판 | 4 | 2 | 4 | 5 |
| M03 시작 / 중단 / 첫 대상 불발 | 535 / 29 / 6 | 551 / 78 / 13 | 538 / 28 / 6 | 458 / 18 / 2 |
| M03 실제 적중 | 1,740 | 1,754 | 1,761 | 1,752 |
| M04 시전 시작 | 146 | 148 | 149 | 0 |
| 자원 부족 차단 판단 | 0 | 0 | 0 | 0 |

이전 기본 칙령의 중단 78회는 옛 M04 규칙 56회, 옛 M05 규칙 18회, 끌어당김 2회와 사망 2회였다. 변경 뒤 중단 18회는 옛 M05 규칙 16회와 사망 2회였다. 이 자료에서는 직전 전역 긴급 생존·회피 요청이 꺼져 있어도 옛 규칙이 공격을 취소하고 있었다.

**공격 중단은 감소했지만 사망은 4회에서 7회로 늘었으므로 성능 개선으로 판단하지 않는다.** `CreateForHero`는 장착 슬롯을 가져오고 새 전역 기본값을 만든다. 이전 추천 규칙의 HP·위험 조건을 새 문서로 옮기지는 않는다. 이번 칙령 표본은 전역 생존·회피가 꺼져 있고 M04가 SURVIVAL인 기본값 문서다. 수정 후 M04가 0회 사용된 것은 해당 설정을 따른 결과다. 후속 비교에서는 생존 정책을 명시적으로 구성한 문서를 별도 집단으로 검증해야 한다. 이전 규칙에도 실제 착지 검사가 추가됐으므로 그쪽 실행 결과가 완전히 같다고 주장하지 않는다.

전투 수치·접사 가중치를 바꾸거나 기본 생존 옵션을 자동으로 켜서 진단 결과를 보정하지 않았다. 사망과 보스 도달 전 시간을 함께 조사하며, 단독 보스에게 연쇄 번개가 한 번만 맞는 명세도 유지한다.

원자료는 `Artifacts/Validation/EdictTeleport/Baseline16/`과 `After16/`, 짝 비교는 `comparison.json`이다. 수집은 각각 2026-09-12 16:30:14~16:32:09 UTC와 16:32:36~16:34:21 UTC에 완료했다. `RunChainDiagnostics`의 기존 옵션을 사용하며 진단 출력 스키마는 2다.

## 검증과 실행본

M04 신규 검사 35개를 추가했다. 핵심 판단·응답·순서·행동 연속성·번역의 집중 검사 268개가 통과했고, 후속 검사 조건과 화면 설명 수정 뒤 관련 검사 141개도 통과했다. 최종 전체 Edit Mode 검사 **1,601개**는 2026-09-12 16:44:24~16:49:19 UTC에 약 295.44초 동안 실행됐으며, 실패·건너뜀 없이 모두 통과했다.

첫 전체 검사에서는 1,601개 중 1,600개가 통과했다. 실패한 기존 회피 집계 검사는 0.5m 순간이동을 만들어 최소 2m 규칙을 위반했다. 실제 N10 위험 예고 안에 남는 2m 이동으로 고치고, 같은 위험에서 벗어나는 4m 이동과 비교했다. 보호막에 흡수된 피격을 회피 성공으로 세지 않는 원래 검사의 목적은 유지한다. 초기 집중 검사의 배열 API·합성 지도·가시성·착지 경계와 준비 완료 후 보행에 관한 실패 및 수정 이력도 증거 폴더에 남긴다.

| 실제 macOS 앱 검사 | 확인한 결과 |
|---|---|
| 옵션 편집·저장 | 실제 UI 콜백으로 DISTANCE·도착 위치·NO_DAMAGE를 선택했다. 편집 중 원본은 유지됐고 저장 후 메모리와 다시 읽은 파일이 일치했다. 사냥 칙령 사용 전환도 실제 버튼을 사용했다. |
| 시전과 독립 재시작 | 거리 조정 준비 중 SURVIVAL·SAFE·GLOBAL·OFF로 저장했다. 별도 프로세스에서 시간·자원·확정 착지점을 복원해 한 번만 이동했다. 원래 비용 0을 유지하고 후속 공격이나 OFF 상태의 추가 순간이동은 없었다. |
| 적 없는 위험 대응 | M04와 전역 대응을 명시적으로 켜고 적을 감지 범위 밖으로 이동시켰다. 보이는 환경 위험에 대상 식별자 -1의 전역 생존 순간이동을 시작하고 실제 착지를 완료했다. |
| 화면과 정지 상태 | 1280×720·720×1280·640×360, 한국어·영어와 140% 글자에서 문구 높이·번역 누락·하단 안전 영역을 검사했다. 판단 화면의 언어 변경·닫기 뒤 실행 중 또는 수동 정지 상태를 각각 보존했다. |

첫 앱 검사에서 착지 다음에 정상적으로 이어진 전역 추적을 이동 실패로 판정했다. 검사만 실제 완료 사건을 확인하도록 고쳤다. 최종 `Native2`의 두 프로세스는 2026-09-12 16:44:17~16:44:37 UTC에 모두 성공했다. 화면 10장을 보관하고 영어 140% 세로 옵션·작은 가로 설명·한국어 재시작 판단·환경 회피 후 전투 화면을 직접 확인했다. 길어진 화면은 스크롤하며 읽는다. 고정된 전투 배치와 UI 자동 입력의 결과이며 모바일 실기기·자연 플레이 밸런스 검증은 아니다.

실행본은 `Builds/macOS-EdictTeleport/HELLSCRIPT.app`, 증거 폴더는 `Artifacts/Validation/EdictTeleport/`이다. Runtime C# 174개를 포함한 C#·영어 문구 표 247개가 전체 검사와 최종 빌드 소스에 일치한다. C# 메타 누락·자산 GUID 중복은 없다. 진단의 전투 코드는 최종 코드와 같으며, 이후 바뀐 카드 설명·번역·앱 검사·기존 회피 검사 네 파일의 이전 형태를 별도 보관했다.

검증한 기획 입력·원래 설정·소스와 진단 변형을 포함한 662개 파일을 `validated-source.tar.gz`에 보관했다. SHA-256은 `9579f66d65c799ad084a9db79d1782b87d3f9a64cbfa9a142198344e2cb75130`이다. Unity가 사본의 머티리얼에 추가한 URP Editor 버전 자료는 별도 기록하고 원본 자산은 유지했다. 저장 스키마·씬·프리팹·패키지는 변경하지 않았으며, 검사에는 분리된 프로젝트와 전용 저장 폴더를 사용했다.

## 남은 개발

다음은 M05 원소 보호막과 M06 서리 폭발의 독립 핵심 판단이다. 먼저 남아 있는 M05의 옛 조건과 공격 중단을 연결하고, 명시적으로 구성한 생존 정책과 기본값 문서를 구분해 연쇄 제어를 비교한다. 기존 사용자 설정은 자동 교체하지 않는다. 이후 여러 단계의 성장·파밍 효용, 전설·세트의 남은 장착 경계, 모바일 실행과 출시 품질 검증을 이어 간다.
