# 현재 사냥 설정의 저장 개발 기록

작성일: 2026-09-09 · 기존 행동 편집기의 저장 실패 처리 보완

## 변경한 동작

기존 `GameController.CommitBuild`는 실제 영웅·전투 설정을 바꾼 뒤 저장했다. 파일 기록에 실패해도 편집 화면을 닫아, 메모리의 설정과 마지막 저장본이 달라질 수 있었다. 이제 실제 설정의 적용은 `GameStore.CommitCurrentBuild`를 통해 **입력·소유권 검증 → 적용 결과 사전 검증 → 파일 기록 → 실제 상태 반영 → 화면 이동** 순서로 처리한다.

진행 중인 균열은 사본에서 적용 직후의 상태를 먼저 만든다. 이때 재개·맵 재생성·시간 진행·난수 추첨·실제 효과 호출은 하지 않는다. 파일에 기록한 뒤 같은 전환 함수를 실제 전투에 적용한다. 영웅·진행 중 균열·적·기존 지도 객체를 통째로 교체하지 않으며, 기존 경로·화면에서 보관한 참조를 유지한다. 해당 과정은 대기 없는 하나의 호출 안에서 처리한다.

| 상황 | 결과 |
|---|---|
| 성소에서 저장 실패 | 실제 영웅의 설정과 안내 진행, 저장 파일을 유지한다. 편집 화면과 변경값을 남기고 다시 저장할 수 있다. |
| 균열 편집 중 저장 실패 | 위 내용에 더해 HP·자원·쿨타임·현재 행동·장판·덫·투사체·기록을 바꾸지 않는다. 편집을 위한 일시정지도 유지한다. |
| 저장 성공 | 기록한 설정·전투 상태와 실제 반영 결과가 일치한다. 편집 진입 전의 실행·일시정지 상태로 돌아간다. 이전 저장 오류 안내는 지운다. |
| 설정값이 같은 재저장 | 저장 시각에 해당하는 버전 정보만 달라져도 현재 행동을 중단하거나 효과를 제거하지 않는다. |
| 일반 훈련에서 적용 | 훈련 복사본만 바꾼다. 현재 영웅 설정을 저장하지 않고, 명시적인 프리셋 저장 경로는 유지한다. |
| 다른 전투 객체·포탈·아직 열지 않은 중단 균열 | 잘못된 경로의 적용을 거부한다. 해당 캐릭터의 균열을 이어서 연 뒤 행동 수정에서 저장하도록 안내한다. |
| 유효하지 않은 숫자 | 전역 거리·HP·시간과 규칙·조건의 NaN·무한대를 원본 입력에서 검사한다. 설정을 복사하거나 정규화하기 전에 거부한다. |

편집본과 적용본의 비교에서 프리셋 이름·버전 시각·규칙의 임의 식별자를 제외했다. 행동 순서와 값, 획득·반복·상자 정책 등 실제 설정은 계속 비교한다. 값을 원래대로 되돌렸는데 저장 시각 때문에 변경 상태가 남는 문제를 줄인다.

[화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)을 따라 긴 저장 실패 안내의 높이도 내용에 맞춰 늘렸다. 이번 안내창 보완은 전체 화면의 가로·세로 대응을 완료한 것이 아니다.

## 검증

집중 검사 **185개**, 전체 Edit Mode 검사 **696개가 모두 통과**했다. 저장 실패 시 계정·원본 입력·디스크·전투 전체 상태·객체 참조 유지, 재시도, 설정이 같은 재저장, 안내 진행의 함께 저장, 잘못된 입력과 소유권을 검사했다. 기존 행동·장판·패시브·훈련·A/B·프리셋 검사도 함께 통과했다. [집중 검사](../../Artifacts/Validation/current-build-save-focused.xml), [전체 검사](../../Artifacts/Validation/current-build-save-editmode.xml), [검사 당시 소스](../../Artifacts/Validation/current-build-save-core-source-manifest.json)를 보존했다.

첫 집중 검사에서는 181개 중 1개가 실패했다. 전역 숫자 검사가 빠져 NaN을 거부하지 못한 문제를 확인하고 복사 전 입력 검사와 조건 범위 검사를 추가했다. [첫 실패 결과](../../Artifacts/Validation/current-build-save-focused-attempt1.xml)를 남겼다. 첫 실행 화면에서는 재시도 성공 뒤 이전 오류가 남는 문제를 발견해 안내 처리를 보완했다.

최종 macOS 개발 빌드는 오류 0건으로 완료했다. 별도 저장 폴더에서 실제 앱을 실행하고 새 프로세스로 재시작했으며, 두 실행 모두 종료 코드 0과 완료 표식을 확인했다. 화면은 Metal의 720×1280으로 검사했다.

- 성소에서 쓰기 실패를 만들고, 편집 화면·거리 입력·영웅·안내 진행·파일이 유지되는지 확인했다. 재시도 후 저장 내용과 실제 설정이 같았으며 이전 오류 안내가 사라졌다.
- 실제 Lv.1 마법사의 훈련 복사본에 거리 설정을 적용했다. 파일을 쓸 수 없는 상태에서도 실제 계정·파일을 바꾸지 않고 훈련에만 적용했다.
- 자동 생성된 일반 균열에서 자연스럽게 화염구 준비 동작에 진입한 뒤 편집했다. 실패 시 해당 행동·HP·자원·쿨타임·초안이 유지됐고, 재시도 성공 직후 전투 상태가 파일에 기록한 상태와 일치했다.
- 다시 시전 중인 상태에서 사용자가 일시정지한 뒤 설정값이 같은 재저장을 했다. 행동 객체와 준비 상태를 유지하고 계속 일시정지했다.
- 실제 프로세스 재시작 후 계정 전체를 대조했다. 균열을 이어 열 때 재개에 따른 일시정지 해제 외에는 저장된 전투 상태가 같았다.

검사 696개 이후의 변경은 긴 안내문 높이·성공 후 오류 안내 해제와 실행 검증 코드다. [최종 소스 기록](../../Artifacts/Validation/current-build-save-source-manifest.json)과 [검증 요약](../../Artifacts/Validation/current-build-save-validation-summary.json)에 구분했다. 보호 자산 98개는 단계 시작 시점과 모두 같다. 씬·프리팹·패키지·프로젝트 설정은 변경하지 않았으며 기존 실행 앱과 실제 저장 파일도 교체하지 않았다.

위 검사는 UI 콜백과 실제 macOS 렌더링·프로세스 재시작의 증거다. 사람의 물리 입력, 모바일 방향·키보드·터치·운영체제 복귀를 확인한 것으로 표시하지 않는다.

## 후속 구현과 구분할 범위

1. 이번 변경은 기존 `BuildConfig`의 저장 경로다. 핵심 옵션 v0.2의 89개 항목·새 원본·공유 코드·5개 슬롯의 통합은 계속 구현해야 한다.
2. 이 기록의 검사 시점에는 설정값이 실제로 달라진 경우의 행동 중단 정책이 남아 있었다. 후속 변경은 [설정 저장 후 전투 동작 보존 기록](Action_Continuity_Expansion.md)에 구분한다. 이 문서의 696개 검사와 과거 실행 증거를 후속 변경의 검증으로 대신하지 않는다.
3. 일반 균열의 액티브 장착 제한과 미장착 스킬 설정 보관은 아직 기존 방식이다. 안정적인 스킬·행동 참조를 연결한 뒤 새 교체 정책을 적용한다. 패시브·장비 제한과 A/B의 고정 조건은 따로 지킨다.
4. 전체 편집 페이지의 되돌리기·이탈 확인·복합 변경 저장, 기기별 화면 방향 설정·실기기 입력·배치 전환 검사는 남아 있다.

관련 기준은 [사냥 칙령 구현 계약](../Design/HELLSCRIPT_Hunt_Edict_Implementation_Contract.md), [사냥 칙령 개발 기록](Hunt_Edict_Expansion.md), [화면 배치 개발 기록](Screen_Layout_Expansion.md)을 따른다. 이 저장 경로의 통과로 사냥 칙령 전체나 D3~D6를 완료 처리하지 않는다.
