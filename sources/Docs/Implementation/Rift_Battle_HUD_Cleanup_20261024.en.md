# Rift battle HUD cleanup — settings gear border, no graph overlap, content dock, field chest count (2026-10-24)

[한국어](Rift_Battle_HUD_Cleanup_20261024.md) · unit U-G · branch `claude/battle-hud-rift-20261024-c02d25`

## Request
Play test of 2026-10-24 (attachment 10, portrait phone rift battle): (1) remove the white border around the settings button; (2) the battle graphs must never overlap in any fold/unfold combination (unfolding an upper graph pushes the ones below), plus a one-time tutorial at the first rift battle that explains the activity time, live DPS and monster damage graphs; (3) put the content buttons directly under the settings button, closed by default; (4) show the field chest count as text only, with no card of its own.

## Causes found and changes
| Item | Cause (read in the source) | Change |
| --- | --- | --- |
| (1) border | The settings button is a `UiButton`; the cream rounded plate is the button's `Face` ("Button chrome"). The plaza (`ReflowPlazaGear`) turns the `Face` off, the battle's `CompactGear` did not, and the casual battle reflow then called `CombatHudButton(settings, UiSkin.Casual)`, which painted the `Face` again. | `CompactGear` turns the `Face` off (legacy and casual battle alike). The `CombatHudButton(settings…)` call in the casual reflow is gone. |
| (2) overlap | Each of the four windows (activity, DPS, monsters, boss damage) got its lane from the layout and then `DpsHudDrag.Restore()` applied its own saved position, and nothing resolved collisions between windows. | `BattleGraphStack.Resolve` (pure logic): the higher window keeps its place and a colliding window is pushed under it (chained). Display only: saved positions are never rewritten, so folding the upper window brings the lower one back. If the pushed stack would pass the limit above the persistent HUD, the windows return to their approved lanes (never cut off or hidden). Runs at the end of the reflow (`ResolveCasualGraphs`), when a window is dropped (`DpsHudDrag.Dropped`) and when the boss graph appears or goes away. |
| (2) tutorial | none | `GameUI.RiftGraphTutorial.cs`: at the account's first rift battle (not the guide stage, not the training ground) Belina lights the activity time, live DPS and monster damage windows in three taps. Combat waits during the tour (`run.paused`, restored afterwards and before the save so a save never carries the tour's pause). The last step is saved (`AccountGuide.riftGraphLesson`, missing = not done, `GameStore.CompleteRiftGraphLesson`) before the tour ends; on a failed save the third card comes back. |
| (3) dock | The battle dock hung below the fixed Hunt Edict slot (about y=162 on the portrait board), far from the gear, and `contentDockOpen` carried the state opened in town into battle. | The dock arrow hangs one 6 unit gap under the gear (`CasualBattleHudLayout.GearTop/DockTop`). A new battle always starts folded; a rebuild inside the same battle (language, aspect) keeps what the player chose. |
| (4) chest count | `chestCountText` was a child of the minimap card, so an empty card showed it even with no map. | In the casual HUD it is plain text on the third header row, right of the XP line. Its place is "after the XP line, before the shortcut captions (6 units clear of them)" and the XP line yields (full text, then without the next-skill part, then the XP alone, then an ellipsis); fonts are never shrunk. The place is computed from the XP line with every digit as wide as an 8, so a kill that only changes digits never moves it. The text changes only when a number or the language changes. The card remains only for the corner map or a navigation fault line. |

## Decisions for the user (defaults used)
1. Fatigue during the tour: it **keeps running**, like every existing pause (map, menus; the game rule says "fatigue runs while paused"). Stopping it needs a change to `GameController`'s fatigue settlement, which this unit does not touch.
2. A missing account field reads as not done, so **accounts that already played rifts also see the tour once** at their next first rift battle.
3. No Skip button (three taps end it). Add one if wanted.
4. With the dock closed by default, the quick Hunt Edict edit in battle needs the dock opened first (the requested behaviour).
5. The text keeps the existing "Chests N / M" wording (a "Field chests" wording needs one more en entry).
