# 스킬 능력과 장비 연동 구현

수정일: 2026-09-23 · [English](Class_Skill_Runtime.en.md)

**상태: 사냥 칙령 스킬 트리와 플레이어 저장·전투 연결.**

이 작업은 [확정 스킬 기획](../Design/HELLSCRIPT_Class_Skills.md)을 전투 기능으로 구현합니다. 현재 플레이어 UI와 적용 경로는 아래 통합 문서를 따릅니다. 2026-09-23 후속 작업에서 궁극기 전용 패시브와 아이콘 3개를 추가했으며, HTML 스킬 트리의 성장 조건을 별도로 정리했습니다.


**현재 플레이어 화면:** [사냥 칙령 스킬 트리 통합](Hunt_Edict_Skill_Tree.md)이 아래 초기 검증 전용 구성보다 우선한다. 실제 플레이어는 일반 액티브 4칸과 별도 궁극기 1칸, 해금된 패시브 상시 적용, 40레벨 성장과 통합 저장을 사용한다. 아래 버전 1·2 관련 내용은 기존 검증 스냅샷의 호환 기록이다.

## 현재 구현 범위

전사·궁수·마법사는 각각 일반 액티브 16개, 패시브 19개, 궁극기 2개를 조회하고 사용합니다. 기존 36개 기술의 인덱스와 계산 경로를 유지하고, 신규 75개 기술은 문자열 ID로 관리합니다. 신규 전설 18개와 신규 세트 24종의 장비 105개·효과 60단계를 등록했습니다. 이 장비들은 일반 드롭 후보에 넣지 않았습니다.

통합된 플레이어 구성은 40레벨 성장과 신규 기술을 활성화합니다. 초기 검증 전용 구성은 별도 호환 경로에 남아 있습니다. 40레벨의 투자 예산은 39포인트이며, 기존 만렙에서 소실된 경험치를 소급 지급하지 않습니다.

## 저장과 전투 규칙

스킬 ID, 투자 등급, 네 칸의 일반 액티브, 세 칸의 패시브, 선택한 궁극기, 사용 옵션, 자동 사용 여부와 공격 순서를 함께 저장합니다. 기존 인덱스는 W01–W06·A01–A06·M01–M06에 고정했습니다. HED4는 ID별 등급과 궁극기를 포함하며, HED1–HED3의 읽기 경로도 유지합니다.

궁극기는 40레벨에 해금되며 두 항목은 항상 목록의 36·37번입니다. 한 번에 하나만 선택할 수 있고 마을에서만 변경합니다. 공용 쿨타임은 60초, 감소 후 최솟값은 45초입니다. 저장·복원·선택 변경으로 남은 시간을 초기화하지 않습니다.

각 시전과 파생 효과는 원인 스킬과 시전 ID를 갖습니다. 직접 적중, 지속 피해, 분열·소환·장비 추가 피해를 분리합니다. 표식의 피해 증폭 여부, 스킬 출혈과 세트 출혈, 그림자 화살과 새 궁극기의 잔영도 별도로 처리합니다.

## UI 연결 규약

- `ClassSkills.For`는 직업별 37개 정의를 고정 순서로 제공합니다. 한국어·영어 이름과 설명이 포함됩니다.
- `ReadClassSkills`는 해금 여부, 투자 등급과 장비 보너스 등급, 장착 여부, 비용과 대기시간, 계산 수치를 제공합니다.
- `ClassSkillLoadout.Validate`와 `GameStore.CommitClassSkills`는 구성 검증과 원자적 저장을 담당합니다.
- `InspectClassSkill`은 시전 가능 여부와 보류 사유를, `TryCastClassSkill`은 실제 시전을 처리합니다.
- `ReadClassSkillEffects`는 남은 강화·설치물·충전을 읽기용 복사본으로 제공합니다.
- `ClassSkillChanged`는 스킬 ID·원천 ID·시전 ID·대상·위치가 포함된 사건을 전달합니다.

## 2026-09-23 궁극기 패시브 분리

각 궁극기를 강화하는 패시브를 별도 ID로 나누었습니다. WP18·AP18·MP18은 첫 번째 궁극기에만 적용되고 WP19·AP19·MP19는 두 번째 궁극기에만 적용됩니다. 효과 수치와 최대 등급은 유지합니다. 기존 패시브의 실행 해금 레벨은 저장 호환성을 위해 보존하며, HTML의 40레벨·직접 선행 조건은 별도 설계안입니다.

`ClassSkillLoadout` 버전 2는 이전 36개 등급을 검증한 뒤 37개로 변환합니다. 두 번째 궁극기 선택 시 기존 P18의 투자와 장착을 P19로 옮기고 기존 P18은 1등급으로 둡니다. 첫 번째 궁극기 선택 시 기존 투자를 유지합니다. HED4의 무결성과 알 수 없는 필드 거부도 유지합니다. 새 아이콘은 기존 `SkillIconAssets` 조회 경로로 제공합니다.

이번 집중 Edit Mode 검사 352건이 통과했습니다. macOS 실행 파일에서 여섯 궁극기와 전용 패시브의 일대일 효과를 확인했고, 별도 프로세스로 재실행한 저장 복원 7건도 통과했습니다. [현재 검증 기록](../../Prototypes/SkillTree/evidence/validation-summary.json), [Edit Mode 원본](../../Prototypes/SkillTree/evidence/ultimate-split-editmode.xml), [macOS 실행 근거](../../Prototypes/SkillTree/evidence/native/manifest.json)를 참고합니다. 아래 검증 수치는 이전 구현 당시의 기록이며 이번 검사와 합산하지 않습니다.

## 검증 기록

최종 능력·옵션·번역 집중 Edit Mode 검사 369건이 모두 통과했습니다. 스킬 전용 336건에는 전체 90개 빌드 상황, 옵션 비교 18건, 보상 복원과 결계 보호막 준비 선택이 포함됩니다. 능력·장비 집중 Edit Mode 검사 319건과 수정 후 호환 검사 440건이 통과했습니다. 신규 액티브·궁극기 36개의 실제 효과와 거부 조건, 신규 패시브 36개의 장착 전후 차이, 신규 전설 18종, 세트 효과 60단계, 기존 전설·등급·저장 회귀 검사를 포함합니다. 집중 검사끼리 또는 전체 검사와 수를 합산하지 않습니다.

[30개 빌드의 전투 90건](ClassSkillEvidence/Build_Comparison.md)과 [사용 옵션만 바꾼 비교 18건](ClassSkillEvidence/Policy_Comparison.md)을 기록했습니다. 옵션 비교는 도약의 후퇴 여부, 충전 위치와 종료 목표가 실제 공격량·받은 피해·이동·충전 시간을 바꾸는지 확인합니다. 모든 선택이 동등하게 강하거나 최종 밸런스가 완성됐다는 뜻은 아닙니다.

macOS 개발 빌드는 오류 0건으로 생성됐습니다. 실제 실행 파일을 종료하고 새 프로세스로 재시작하여 궁극기 준비, 화살 비행, 구체 만료, 충전, 도약 거리 확보, 출혈 전투의 처치 직전·직후를 복원한 7건이 통과했습니다. 피해·자원·체력·공용 쿨타임·난수·사건·보상·옵션 진행량이 중단 없는 전투와 일치했습니다. 보상 사례는 처치 1회·드롭 1개·골드 30의 실제 수령을 확인했고, 수령 후 저장·재시작한 경우의 재수령 요청은 골드를 늘리지 않았습니다. 정수·ID·수령 여부는 정확히 일치하며, 실수 비교의 최대 관측 차이는 약 1.42×10⁻¹⁴였습니다. [macOS 근거와 소스 지문](ClassSkillEvidence/native/manifest.json)에 기대값과 재실행 결과를 함께 보존합니다.

최종 전체 Edit Mode 검사는 3,275건 중 3,273건 통과·2건 실패·건너뜀 0건입니다. 이 중 스킬 전용 검사 331건은 모두 통과했습니다. 실패한 번역 등록 1건은 문구 표에 추가한 뒤 관련 검사에서 통과했습니다. 남은 1건은 기존 UI Graphic의 CanvasRenderer 선언 검사입니다. 해당 다섯 타입의 파일은 기획 기준 커밋과 바이트 단위로 같으며, 이 작업에서 UI 코드를 수정하지 않았습니다. 전체 검사 통과로 표시하지 않습니다. [전체 원본](ClassSkillEvidence/final-editmode.xml)과 [기존 UI 파일 비교](ClassSkillEvidence/pre-existing-ui-test.json)를 함께 보존합니다.

## 실행 데이터와 호환 계층

`tools/class_skill_runtime.py`가 확정 기획, `runtime_parameters.json`, `use_options.json`에서 실행 데이터를 생성합니다. `ClassSkills.json`은 한국어·영어 이름, 1등급 설명, 수치, 자동 사용 조건, 장비·세트 ID를 함께 제공합니다. 투자 등급에 따른 계산값은 `ReadClassSkills`에서 별도로 반환하며, 장비가 주는 기존 기술 보너스 등급은 투자 예산을 소비하지 않습니다.

기존 `GameCatalog`의 액티브 18개와 `SkillEffects`의 기존 계산을 보존합니다. 원본 기획의 파일 지문은 당시 근거로 남겨 두고, 필드·조회 경로가 추가된 파일은 `legacy_definitions.json`의 기존 생성자 인수와 비교합니다. 기존 장비 수치가 바뀌어도 지문을 새 값으로 덮어서 통과시키지 않습니다.

기본 계정에는 새 아이템을 넣지 않습니다. 신규 장비는 실제 아이템 생성·소유·장착·저장 검증을 거치지만 일반 가중치 추첨 목록에는 포함되지 않습니다. 세트 개수는 직업과 부위가 맞는 장착 아이템의 서로 다른 ID로 셉니다. 상위 단계가 하위 수치를 교체하는 경우 두 수치를 더하지 않습니다.

## 저장 적용과 사건 전달

저장 스키마는 7입니다. HED4는 ID별 투자, 사용 옵션, 자동 사용 순서, 궁극기 선택과 기존 칙령 설정을 포함합니다. 사용 옵션 필드가 없던 초기 HED4도 읽되, 알려지지 않은 필드는 받아들이지 않습니다. 알려지지 않은 ID·필드·버전과 손상된 공유 코드는 거부합니다. 읽을 수 없는 신규 능력 저장은 원본을 덮어쓰거나 이전 백업으로 조용히 대체하지 않습니다.

전투 저장에는 공용 궁극기 쿨타임, 시전 준비 상태, 발사체 진행 상태, 소환·설치물의 만료 시각, 충전, 거리 확보의 남은 시도, 선택별 관찰 기록, 원천별 지속 피해, 내부 대기시간과 난수열을 포함합니다. 복원할 때 예약된 시전과 활성 행동을 같은 시전 ID로 다시 연결합니다. 교체된 구체·소환은 자연 만료 보상을 만들지 않습니다.

`ClassSkillChanged`는 완료된 전투 갱신 단위에서 전달됩니다. 사건 처리자가 저장을 요청해도 직접 피해만 기록되고 후속 지속 피해는 아직 생성되지 않은 중간 상태를 저장하지 않도록 했습니다. 새로 연결하는 UI는 사건을 표시 용도로 사용하고, 피해나 보상을 다시 실행해서는 안 됩니다.

## 자동 전투에서 보완한 규칙

신규 기술은 ID별 공격 순서와 기획의 자동 조건을 사용합니다. 기존 기술은 기존 사냥 칙령의 조준·이동·회복·몰이 판단을 유지합니다. 범위 밖의 적에게 접근해야 하는 공격은 탐색보다 먼저 이동 위치를 정하며, 생존·몰이·전리품 우선순위는 유지합니다.

M17의 기획 조건은 원소 순환 강화를 요구했지만 일부 지정 빌드는 그 강화를 만들 수 없었습니다. 그런 구성에서는 관측한 정예·보스 또는 범위 내 적 4명 조건만으로 사용하도록 보완했습니다. 해당 강화를 만들 수 있는 구성은 기존 강화 조건을 계속 사용합니다.

## 사용 규칙과 실험 선택

[사용 규칙 기획](../Design/Class_Skill_Use_Policies.md)에 55개 옵션 묶음·164개 선택지를 정의했습니다. 액티브·궁극기 54개는 사용 시점·대상·위치·대기 방식을 선택하고, 마력 회수는 종료 목표를 추가로 선택합니다. 패시브 57개는 기존 세 칸의 장착 예산에서 경쟁합니다.

도약 W02는 실제 이동 거리에 따른 추가 피해를 얻습니다. 사용자는 현재 거리에서 도약하거나 최대 2초 동안 먼저 거리를 확보할 수 있습니다. 마력 회수 M13은 가만히 있으면 1등급 기준 마나 회복 속도가 평소의 10배가 됩니다. 쿨타임과 고정 종료 시간은 없으며, 이동·다른 유효한 공격은 취소하고 피격만으로는 취소하지 않습니다. 제자리에서 버틸지 후퇴한 뒤 충전할지, 마나 50%와 90% 중 어디서 공격을 재개할지 선택합니다.

거리 확보는 이미 관측한 적과 위험, 기존 벽·몸체 판정만 사용합니다. 최대 2초 뒤에는 가능한 현재 행동으로 전환하며 무한 후퇴하지 않습니다. 전역 긴급 생존 방침은 유지합니다. DES_LM44의 보호막에는 충전 재시작으로 초기화되지 않는 6초 재발동 간격을 두었습니다. 충분히 준비 선택은 자기 결계와 해당 장비가 준비돼 있으면 마나가 찬 뒤에도 1.5초 집중 조건까지 기다립니다. 짧게 회복 선택은 즉시 공격을 재개합니다. 장비 재발동 대기 중에는 추가로 기다리지 않습니다.

`ClassSkillOptions.For`는 한영 선택지와 이득·손해·관찰 지표를 반환합니다. `WithOption`은 원본을 보존하는 초안을 만들고 `CommitClassSkills`가 마을에서 저장합니다. `ReadClassSkillPolicies`는 보류 이유, 누적 대기 시간, 거리 확보 이동량, 충전 시간과 실제 회복 마나를 읽기용 복사본으로 제공합니다. 여러 스킬의 대기 시간은 겹칠 수 있으므로 합계를 전투 공백으로 해석하지 않습니다.

## UI 작업에 넘길 사용 순서

1. `ClassSkills.For(heroClass)`와 `ReadClassSkills()`로 목록·정렬·해금·투자 등급·보너스 등급·계산 수치를 읽습니다. 궁극기는 일반 액티브 배열에 넣지 않습니다.
2. `ClassSkillOptions.For`로 선택지와 장단점을 읽고 독립된 `ClassSkillLoadout` 초안을 편집합니다. `WithOption`으로 선택을 반영하고 `Validate`로 검사한 뒤 마을에서 `CommitClassSkills`로 저장합니다. 기존 인덱스 배열을 직접 편집해 신규 선택을 덮어쓰지 않습니다.
3. `InspectClassSkill`로 수동 시전 가능 여부를, `InspectClassSkillAutomatic`으로 자동 사용 보류 사유를 읽습니다. 사유 코드와 한국어·영어 설명을 함께 제공합니다.
4. `TryCastClassSkill`에 스킬 ID와 대상·조준점을 전달합니다. 남은 쿨타임·충전·설치물은 조회 API를 사용하고 지속 피해 장부는 `ReadClassSkillDots`로 읽습니다. 반환된 효과 사본을 바꿔도 전투 상태는 바뀌지 않습니다.
5. 이동 입력은 `NotifyClassSkillMovementRequested`로 정지 충전을 취소합니다. 옵션 관찰값은 `ReadClassSkillPolicies`로 읽습니다.
6. `ClassSkillChanged`의 스킬 ID·원천 ID·시전 ID·사건 종류에 표시를 연결합니다. 기본 시전, 직접 피해, 지속 피해, 소환, 분열, 잔영과 장비 파생 피해를 구분합니다.

## 검증 환경과 공개 조건

검증은 주 작업 공간과 분리된 `codex/class-skill-runtime` 작업 공간에서 수행합니다. 일반 계정과 주 Unity Editor를 검증에 사용하지 않습니다. 개발 실행 경로는 `ClassSkills.ValidationBuild`와 검증용 캐릭터 표시를 함께 요구합니다.

30개 빌드는 40레벨·스킬 1등급·장비 30레벨·8개 유효 장비 부위·고정 난수 시드·60초 조건으로 비교합니다. 비교 실험의 훈련 전투는 실제 장착 수치와 전투 계산을 사용하면서 재화 지급을 차단합니다. 처치 보상 복원 검사는 별도의 검증 계정에서 실제 보상 처리 경로를 활성화합니다. 적 하나, 적 8명, 보스 상황별로 피해·자원 부족 시간·생존·시전 횟수를 기록합니다. 결과는 초기 수치의 작동 증거이며 최종 밸런스나 모바일 성능의 합격 기준은 아닙니다.

macOS 검증은 개발 실행 파일을 별도 프로세스로 종료하고 다시 실행하여 준비 중 궁극기, 이동 중 화살, 만료 전 축전 구체, 마나 충전과 도약 전 후퇴를 복원합니다. 결과 파일에는 피해·자원·체력·공용 쿨타임·난수·사건 수·보상 수치를 보존합니다. 이미지·UI·입력 조작·모바일 실기기는 이번 검증 범위에 포함하지 않습니다.

UI 규칙이 확정되면 조회·저장·시전 연결을 적용하고, 신규 드롭 가중치를 별도로 확정한 뒤 일반 플레이의 40레벨 성장·신규 스킬·장비 획득을 함께 활성화합니다. 공개 위키는 이 작업 브랜치를 `main`에 병합하는 작업에서 생성·검사·배포합니다.

## 이미지 제작 인계

사용자 요청에 따라 스킬·전설 장비·세트 장비·위상 네 종류의 별도 작업에 개별 ID와 효과 설명을 전달했고, 이미지별 제작·검수 완료 수량과 남은 항목은 아래 인계 기록에서 확인할 수 있습니다. [이미지 제작 인계 기록](../Art/Skill_Resource_Delegation.md)에 범위와 소유 경계를 정리했습니다. 이미지 완성·UI 배치는 이 능력 검증의 완료 조건과 별도로 관리합니다.
