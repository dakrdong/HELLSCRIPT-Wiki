# 생성 균열의 출구·성소 접근 수정과 6개 빌드 비교

작성일: 2026-09-13 · [English](Edict_Field_Expansion.en.md)

상태: **출구 선택과 성소 앞 왕복을 수정했다. 균열 수정의 360판 비교를 마치고, 룬 완료본을 포함한 최신 메인의 전체 검사와 저장·재시작을 검증했다.**

## 수정한 동작

궁수 옵션을 연결한 `8e9e527`에서 이어서 [균열 탐색 상세안](../Design/HELLSCRIPT_Rift_Exploration_Detail.md)과 [화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)을 적용했다. 클로드의 능력치·접사·밸런스 기록은 메인에 포함되어 있다. 로컬·원격 브랜치와 작업 폴더를 다시 확인했으며 `main`만 남아 있다. [브랜치 확인 기록](../../Artifacts/Validation/EdictField/branch-status.json)을 보관한다.

작업 도중 [룬 성장 완료본](Rune_Mastery_Implementation.md) `d0c8e25`가 메인과 공개 위키에 반영되었다. 해당 코드·문서·DB를 보존하고 최종 전체 검사와 실행본에 포함했다. 아래 360판은 균열 수정의 효과를 분리하기 위해 룬 통합 전 기준을 고정한 대조 실험이며, 룬을 합친 최신 메인은 별도의 24판·전체 검사·실제 앱으로 검증한다.

기존 왼쪽·오른쪽 벽 따라가기는 현재 방 출구의 회전각을 거리 점수에 더했다. 다른 방문 방의 출구에는 이 가산점이 없어, 현재 갈림길의 유효한 길을 건너뛰고 먼 방문 구역으로 돌아가는 선택이 발생했다. 이제 현재 방의 유효 출구를 진입 방향에 따른 좌·우 순서로 먼저 고른다. 현재 방에 유효 출구가 없으면 실제 경로가 가장 가까운 미탐색 분기로 돌아간다.

수정 소유자는 `RiftExploration.Goal`이다. 이미 선택한 유효 경로의 유지, 관찰 지점의 우선순위, 잠긴 보스 입구 제외, 막힌 길과 보류된 출구 제외, 가장 가까운 영역 탐색의 거리 기준은 유지한다. 전투 수치·이동 속도·생성 지형·보스 조건·제한시간·보상·저장 필드는 바꾸지 않았다.

출구 재현 검사 10개 중 수정 전 7개가 실패했고, 수정 후 10개 모두 통과했다. 좌우와 통로 길이, 잠긴 입구, 막힌 길, 보류된 출구, 방문 완료 후 되돌아가기, 저장한 경로 유지까지 검사한다.

이어진 360판에서 성소 앞 왕복으로 시간 초과한 사례 4개를 확인했다. 생성된 접근 지점은 성소에서 1.35m 떨어져 있고, 접근 완료 판정에는 0.25m 여유가 있었다. 따라서 실제 사용 거리 1.5m 밖에서 사용을 시작한 뒤 즉시 취소하고 다시 접근할 수 있었다. `CombatSimulation.TickShrine`이 접근 지점과 실제 사용 거리 조건을 모두 충족한 뒤 사용을 시작하도록 수정했다. 사용 거리·사용 시간 0.5초·축복 지속시간 20초는 그대로다.

성소 경계 검사 6개는 수정 전 4개 실패에서 수정 후 전부 통과로 바뀌었다. 두 성소의 접근 중 저장 복원, 실제 이동 후 한 번의 사용, 사용 도중 실제 거리 이탈에 따른 취소와 무보상까지 확인했다. 추가된 필드 수정 뒤 전체 균열 360판을 다시 실행했다.

## 같은 조건의 360판 비교

각 직업의 기본 빌드 2개를 30개 시드에서 기존 규칙과 핵심 칙령 기본값으로 각각 실행했다. 총 180쌍·360판이다. 모든 쌍은 균열 10단계, 레벨 30, 아이템 레벨 30의 합법적인 8슬롯 장비, 현행 접사 54종을 사용하며 지형·몬스터 배치·능력치·장비가 일치한다. 핵심 칙령의 전역 생존 대응은 실제 새 기본값인 `OFF`를 유지했다.

| 빌드 | 기존 규칙 클리어 | 핵심 기본값 클리어 | 핵심 시간 초과 | 핵심 기타 실패 | 핵심 클리어 중앙값(초) |
|---|---:|---:|---:|---:|---:|
| 전사 · 회오리 생존 | 30/30 | 30/30 | 0 | 0 | 189.8 |
| 전사 · 도약 분쇄 | 30/30 | 30/30 | 0 | 0 | 172.8 |
| 궁수 · 관통 거리유지 | 30/30 | 30/30 | 0 | 0 | 179.1 |
| 궁수 · 맹독 매복 | 30/30 | 29/30 | 0 | 1 | 188.9 |
| 마법사 · 서리 장판 | 29/30 | 30/30 | 0 | 0 | 192.6 |
| 마법사 · 연쇄 제어 | 20/30 | 24/30 | 6 | 0 | 239.8 |

전체 클리어는 기존 규칙 **169/180판**, 핵심 기본값 **173/180판**이다. 종료 결과 전체는 [상세 집계](../../Artifacts/Validation/EdictField/field-summary.json)에 보존한다. 탐색 오류는 기존 0건, 핵심 기본값 0건이다. 이 360판은 양쪽 모두 수정한 탐색을 사용하므로, 출구 수정 전후의 개선율이나 개별 스킬 효과를 분리해 보여 주는 실험이 아니다. 클리어한 판의 시간 중앙값에는 생존자 편향이 있으므로 실패 판의 수와 함께 읽는다.

별도로 같은 24판을 수정 전후 대조했다. 궁수 관통 빌드의 시드 인덱스 1은 핵심 기본값에서 보스 도달이 약 277초에서 191초로 줄고, 300초 시간 초과가 약 254초 클리어로 바뀌었다. 반대로 마법사 연쇄 제어의 같은 인덱스는 핵심 기본값에서 약 206초 클리어가 300초 시간 초과로 바뀌었다. 기존 규칙에서도 두 사례의 성공·실패가 서로 바뀌어, 전후 각각 22/24판 클리어로 같다. 따라서 모든 지형의 속도나 승률이 좋아졌다고 판단하지 않는다. 수정의 근거는 기획한 출구 순서의 정확성이다.

관측기는 전투 상태와 난수를 바꾸지 않는다. 두 방식에서 관측 유무의 전체 균열 결과가 같고, 모든 틱이 한 번만 집계되는지 검사했다. 행동 중·이동 중·회복 중·대상 보유 정지·무대상 정지는 틱 종료 시점의 배타적인 분류다. 이동에는 전투 중 이동도 포함되며, 각 분류를 시간 손실의 원인으로 단정하지 않는다.

## 성소 접근 수정 전후의 360판 대조

출구 수정이 이미 적용된 같은 360판을 성소 수정 전후로 다시 대조했다. 런타임 차이는 성소 접근 판정 한 곳이며, 장비·능력치·지형·몬스터 배치가 모두 일치한다. 기존 규칙의 클리어는 **167→169/180판**, 핵심 기본값은 **171→173/180판**이다. 실제로 왕복 취소 로그를 확인했던 네 사례는 다음과 같다. 번호는 재현에 쓰는 시드 인덱스다.

| 빌드·시드·방식 | 성소 수정 전 | 성소 수정 후 |
|---|---|---|
| 전사 · 회오리 생존 · 15 · legacy | TimeLimit · 300.0s | Cleared · 182.5s |
| 전사 · 도약 분쇄 · 5 · core-default | TimeLimit · 300.0s | Cleared · 153.1s |
| 마법사 · 연쇄 제어 · 9 · core-default | TimeLimit · 300.0s | Cleared · 240.6s |
| 전사 · 회오리 생존 · 24 · legacy | TimeLimit · 300.0s | Cleared · 205.4s |

이 왕복 중에도 캐릭터는 움직여 경로 오류 계수가 0이었다. 그래서 오류 계수만으로 탐색이 정상이라고 판단하지 않고, 발견한 방·처치 수·행동 로그·위치 표본을 함께 확인했다. [원래 왕복 사례](../../Artifacts/Validation/EdictField/shrine-loop-baseline.json)와 전체 전후 대조를 보존한다. 남은 시간 초과·사망을 이 수정으로 모두 해결했다고 판단하지 않는다.

## 실제 앱의 저장·재시작

룬 완료본을 포함한 대표 24판은 6개 빌드·시드 인덱스 0과 1·두 규칙 방식을 사용했다. 보드에 룬을 배치하지 않은 조건에서 클리어·시간·피해·HP·장비·능력치·모든 스킬 집계가 통제 실험과 같았다. 초기 적 상태도 원본을 내보내 대조했다. 룬 추가로 생긴 비어 있는 피해 스냅샷 항목 두 개만 확인해 제외하면 전투 난수·보스 종류·모든 적 상태가 일치한다. [통합 대조 기록](../../Artifacts/Validation/EdictField/integration-check.json)에 범위를 남겼으며, 룬 배치별 밸런스를 검증한 결과로 확대하지 않는다.

별도 저장 폴더에 합법적인 장비를 갖춘 레벨 30 궁수를 만들고, 직전 최고 단계 9에서 실제 10단계 균열을 시작했다. 생성 시드는 `55755`다. 위치·적·지형·경로·HP·제한시간·보상에 덮어쓰기 없이 실제 고정 틱으로 전투를 진행했다.

1. 실제 전투와 방 발견 후 43.8초의 이동 중 출구 경로를 저장하고 앱을 종료했다.
2. 새 앱에서 시간·위치·목적지·HP·자원·방문 방·탐색 상태·전투와 보상 난수의 일치를 확인했다. 이후 실제 보스를 처치해 253.6초에 클리어하고 캐릭터 초회 보상을 기록했다.
3. 마을로 돌아가 저장한 뒤 다시 실행했다. 장비·재화·초회 보상·거래 기록이 그대로이며, 완료한 균열이나 보상이 다시 실행되지 않음을 확인했다.

룬도 함께 검사했다. 시작할 때 미배치 기본 룬 16개가 있었고, 실제 보스 보상 4개를 받아 20개가 되었다. 재시작 후 전체 룬 소유·배치·프리셋·보상 수령 기록이 동일하며 보스 보상 기록은 한 건이다.

화면 5장을 직접 검토했다. 한국어 가로 1280×720, 영어 세로 720×1280과 글자 크기 140%를 포함한다. 하단 버튼의 안전 영역과 누락 번역을 함께 검사했다. [탐색 중 한국어 화면](../../Artifacts/Validation/EdictField/Native3/checkpoint-01-natural-exit-ko.png), [재시작 후 영어 화면](../../Artifacts/Validation/EdictField/Native3/resume-01-restored-route-en.png), [영어 클리어 결과](../../Artifacts/Validation/EdictField/Native3/resume-03-clear-result-en.png)를 확인할 수 있다.

이 실행 검사는 고정 전투 틱을 직접 진행하므로 일반 실행의 실제 시간 계수는 증가하지 않는다. 결과 화면의 ‘실제 0.0초’는 이 검사 방식에서 나온 표시이며, 배속이나 실제 경과 시간을 검증한 결과가 아니다.

## 검증 범위와 다음 작업

전체 Unity Editor 검사 **2,120개**, macOS 앱의 독립 실행·재시작 **3회**가 통과했다. [검증 요약](../../Artifacts/Validation/EdictField/validation-summary.json), [화면 검토](../../Artifacts/Validation/EdictField/visual-review.json), [검증 소스·앱 해시](../../Artifacts/Validation/EdictField/validated-source.json)를 보관한다. 실행본은 `Builds/macOS-EdictField/HELLSCRIPT.app`이다.

균열 대조 실험은 `8e9e527`과 해당 시점의 균열 수정 파일을 [별도 소스 기록](../../Artifacts/Validation/EdictField/field-source.json)으로 고정했다. 최종 전체 검사·실행본은 룬 완료본 `d0c8e25`에 이번 수정 파일을 더한 동일한 입력을 사용한다. 룬 완료본을 임의로 되돌리거나 관계없는 설정·위키 도구를 커밋하지 않았다. 씬·프리팹·패키지를 새로 수정하지도 않았다. 초기 재현용 복제본에 룬 코드 6개가 잠시 복사된 사실과 이후 입력을 고정해 재검증한 과정도 기록했다.

시간 초과가 남는 지형의 탐색·전투 부담, 전설과 세트의 실제 성장·파밍 효용, 처음 15분의 자연 성장, 모바일 실기기의 터치·화면·성능을 후속으로 검증한다. 최대 레벨 장비로 얻은 결과를 자연 성장이나 전체 게임 완성으로 확대하지 않는다. 같은 출입구를 세 번 반복했을 때의 별도 순환 감지까지 이번 수정으로 완료했다고 표시하지 않는다.
