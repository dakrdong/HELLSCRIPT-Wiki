# HELLSCRIPT 균열 밀도와 갈림길 간격 개선

작성일: 2026-09-14 · 지도 버전: 7

[English](Compact_Rift_Expansion.en.md)

## 변경 목적

이전 버전은 모든 방을 순환할 수 있었지만, 방을 큰 원 위에 배치해 내부 공백과 긴 무분기 통로가 남았다. 이번 변경은 방 사이 간격을 줄이고 모든 외곽 방에서 안쪽 동선을 고를 수 있도록 연결한다. 사용자가 첨부한 압축 지도 스케치는 이 두 요구사항의 형태 참고로 사용했다.

이 문서는 [버전 6 구현 기록](Organic_Rift_Expansion.md)의 배치 간격, 횡단 연결, 교차점 여유와 상자 거리 규칙을 대체한다. 곡선 윤곽, 중앙 방, 전체 순환과 주변 보스 소환은 유지한다.

## 강제 생성 기준

| 항목 | 버전 7의 기준 |
|---|---|
| 내부 밀도 | 실제 바닥의 볼록 외곽 안에서 바닥 점유율이 48% 이상이어야 한다. |
| 큰 공백 | 내부의 빈 표본에서 가장 가까운 바닥 표본까지의 거리가 14m 이하여야 한다. |
| 무분기 통로 | 방 출입구와 실제 갈림길 사이의 통로 중심선을 따라 잰 길이가 40m 이하여야 한다. 구부러져도 같은 통로로 센다. |
| 방의 선택지 | 입구와 중앙 방을 포함한 모든 방에 서로 다른 출입구 3개 이상을 연결한다. |
| 중앙·횡단 연결 | 외곽 방 6~8개와 중앙 방 1개를 만든다. 모든 외곽 방에 안쪽 연결을 추가하고, 중앙 연결과 횡단 연결이 실제 X자 교차로에서 만난다. |
| X자 교차점 | 네 방향에 각각 4m의 직선 여유를 확보하고 60~120도 교차 각도와 1.2m 보행 여유를 검사한다. |
| 순환 | 막다른 곁방, 통로 하나에 매달린 구역, 한 방에서만 이어진 두 구역을 금지한다. 모든 방을 한 번씩 거쳐 입구로 돌아오는 경로가 있어야 한다. |

점유율과 공백 거리는 실제 월드 좌표에서 2m 간격으로 표본을 뽑아 측정한다. 방·통로의 다각형 바닥을 사용하며 미니맵 배율이나 사각 경계 상자로 대신 측정하지 않는다. 장식 기둥의 면적은 이 밀도 지표에서 제외하며, 실제 장애물과 보행 여유는 별도 이동 검사로 확인한다. 14m는 연속 지형에서 계산한 정밀 내접원 반경이 아닌 표본 거리의 상한이다.

40m는 **방 밖 통로 구간**의 상한이다. 방 안의 전투·이동 거리와 실제 소요시간을 뜻하지 않는다. 서로 다른 통로가 실제로 만나고 충분히 다른 방향의 가지가 3개 이상일 때만 갈림길로 인정한다. 평행 중첩, 같은 통로의 중복 기록, 단순한 굴곡은 거리를 끊지 않는다.

[RiftDensity.cs](../../Assets/HELLSCRIPT/Runtime/Core/RiftDensity.cs)가 이 조건을 검사한다. 실패한 후보는 콘텐츠 배치 전에 제외하고 다음 후보를 만든다. 무작위 생성 24개 후보 뒤에 사용하는 고정 대체 지도 6종에도 같은 검사를 적용한다. 기준을 완화해 실패 지도를 통과시키는 경로는 없다.

## 배치와 연결

외곽의 기본 반경은 62~66m에서 41.2~43.6m로 줄이고 위치 흔들림도 축소했다. 방의 전투 공간과 통로 폭은 유지한다. 출입구 접근 길이는 9m에서 5.5m로, X자 교차점의 한쪽 여유는 9m에서 4m로 줄여 통로를 잇기 위해 큰 빈 공간을 남기지 않도록 했다.

[RiftCrossRoutes.cs](../../Assets/HELLSCRIPT/Runtime/Core/RiftCrossRoutes.cs)는 외곽 전체의 출입구 조합을 함께 평가한다. 인접 방의 위치와 장애물 때문에 통로가 크게 돌아가는 조합에 비용을 더한다. 중앙을 향한 출입구는 남겨 두며, 벽 중앙이 장애물로 막혔으면 같은 벽의 다른 위치에서 통행 가능한 출입구를 찾는다. 필수 X자 교차점은 횡단 경로 양쪽의 길이가 한쪽에 치우치지 않는 후보를 고른다.

중앙 방에 3~4개 외곽 방을 연결하고 나머지 외곽 방끼리는 안쪽을 가로질러 연결한다. 중앙·횡단 동선이 여러 순환 경로를 만들므로 외곽을 돌면서 계속 내부 경로로 전환할 수 있다. 실제 다각형, 이동 판정, 월드 바닥, 오버레이 지도와 전체 지도는 기존의 공통 지형 데이터를 사용한다.

## 보상·보스·저장

일반 적 110명, 정예 8명, 상자 5~7개, 장비 보상 2개와 합계 골드·재료 예산은 유지한다. 압축된 지도에서도 상자를 배치할 수 있도록 시작점과 상자 앵커의 직선 거리는 새 지도에서 26m 이상으로 조정했다. 시작 방에는 상자를 두지 않고 방 연결상 두 단계 이상 떨어진 방을 사용한다. 개봉 위치까지 실제 이동 거리가 24m 이상인지도 회귀 검사한다. 이전 지도·보스 방 호환 생성의 45m 기준은 유지한다.

보스는 전용 방 없이 처치 게이지 100에서 플레이어 근처의 안전한 바닥에 나타난다. 지도 압축으로 소환 거리나 보스 보상을 바꾸지 않았다.

새 입장은 버전 7을 저장한다. 이미 진행 중인 버전 6 이하의 균열은 저장된 방·통로·보스·탐색 정보를 사용하며 지형을 다시 생성하거나 압축하지 않는다. 새 시야·탐색 기억과 오버레이 설정도 유지한다.

## 검증 결과

Unity 6000.6.0f1에서 [관련 Edit Mode 검사 83개](CompactRiftEvidence/final-tests.xml)가 모두 통과했다. 지형·순환·보스·전투 이동·상자 예산·기존 저장·시야·한영 문구 검사를 포함한다. 측정 결과의 직렬화를 보완한 뒤 [밀도 검사 6개](CompactRiftEvidence/serialization-tests.xml)를 다시 실행해 통과했다. 두 보고서의 검사 수를 합쳐 서로 다른 검사 89개로 해석하지 않는다.

시드 914001~914036은 모두 무작위 후보에서 생성됐으며 고정 대체 지도 사용은 0회였다. [36개 지도 측정](CompactRiftEvidence/density-audit.csv)에서 바닥 점유율은 49.0~58.8%, 최대 공백 표본 거리는 8.0~12.2m, 최장 무분기 통로는 33.6~39.3m였다. 고정 대체 지도 6종도 보상 시드 5개씩 총 30조합에서 같은 생성·보행·보상 검사를 통과했다. 단순 굴곡과 평행 중첩을 가짜 갈림길로 인정하지 않는 검사도 포함했다.

최종 macOS 개발 빌드는 컴파일 오류 없이 완료됐다. 루트와 검증 프로젝트의 C# 파일 377개가 일치했으며 [주요 원본 해시](CompactRiftEvidence/source-sha256.json)와 [빌드·검증 요약](CompactRiftEvidence/verification.json)을 보존한다. 외부 패키지, 씬, 프리팹과 프로젝트 설정은 이번 변경에 포함하지 않았다.

실제 앱을 종료하고 다시 실행해 지도·체력·시간·난수와 탐색 기억이 유지되는 것을 확인했다. 시드 91367의 1단계 균열에서 전사가 1배속으로 자동 이동·전투를 진행했고, 게이지 100에서 약 9.7m 떨어진 곳에 보스가 한 번 나타났다. 상자 4개를 열고 129.00초에 클리어했다. [실행 기록](CompactRiftEvidence/runtime.txt), [실제 앱의 지도 화면](CompactRiftEvidence/runtime-map.png), [주변 보스 소환 화면](CompactRiftEvidence/runtime-boss.png), [결과 화면](CompactRiftEvidence/runtime-result.png)을 남겼다. 지도 화면의 전체 공개는 검증용 표시 마스크에만 적용하고 촬영 후 복원했으며, 실제 탐색 데이터와 전투는 바꾸지 않았다.

런타임 검증에는 30레벨 전사, 아이템 레벨 30의 희귀 장비 8개와 상자 탐색 설정을 사용했다. 플레이 흐름을 확인한 결과이며 자연 성장 난이도나 모바일 실기기 성능을 측정한 결과는 아니다. 기존 진행 중인 균열은 보존하므로 새 형태는 다음 신규 입장부터 적용된다.
