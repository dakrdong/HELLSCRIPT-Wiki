## 통합하면서 맞춘 동작

- 코어 제작의 네 번째 탭과 새 스킬 트리를 유지하면서 공통 버튼의 선택·누름·초점 표시를 적용했다. 보석상과 균열 준비의 선택 목록도 같은 선택 상태를 전달한다.
- 보석은 6종·6등급을 사용한다. 현재 보석상의 **5:1 합성·1:5 분해·골드 비용 없음**을 유지하고, 이전 브랜치에 남은 3:1 설명과 실행 검사 조건을 맞췄다. 제거된 해골의 구매 항목은 표시하지 않는다. 가방 정리 중 보석 합성의 부족 수량도 5개 기준으로 표시한다.
- 통합 저장 형식은 **11**이다. 독립 개발된 균열과 코어 제작이 모두 형식 10을 사용했으므로, 이전 실행 파일이 한쪽 기록을 읽지 못한 채 덮어쓰는 일을 막기 위해 통합 버전을 올렸다. 이전 저장의 재화·기록·성장을 유지한다.
- 제작 결과와 미확인 결과, 피로도 두 종류, 회복 횟수, 균열 최단 기록과 보상 수령 상태, 해골 보석 이관이 같은 저장 파일에서 유지되는 회귀 검사를 추가했다. 제작 확인 후 다시 시작해도 비용을 중복 소비하지 않는다.
- 새 계정의 물약 설정을 생성 시점에 정규화해, 재접속 때 다른 영웅의 저장 내용이 바뀌지 않도록 했다. 시작 물약 지급이나 콘텐츠 활성화 시점은 유지한다. 인벤토리·장비 상세·창고는 Unity의 객체 해제 여부를 확인하는 방식으로 참조를 처리하고, 두 그래픽 부품에는 필수 `CanvasRenderer`를 선언했다.
- 겹친 번역은 키별로 합쳤고, 문서 이력은 본문 해시를 기준으로 중복을 제거한 뒤 시간순으로 보존했다. HTML 코어 카탈로그도 통합된 장비 정의에서 다시 내보냈다.

## 원본 작업 보존

메인 작업 폴더의 기존 이미지 메타데이터 변경 408개는 통합 대상과 겹치지 않는다. 변경 전 파일 해시와 패치를 보관하고 메인 반영 후에도 원본 내용이 같은지 확인한다. 다른 워크트리에서 미커밋 코드나 자료는 발견되지 않았다. Unity 실행으로 검증 폴더에 생기는 가져오기 설정·프로젝트 설정 변경은 기능 커밋에서 제외한다.

## 검증

최종 실행 결과와 범위는 [통합 검증 기록](MainIntegration20260923Evidence/validation.json)에 기록한다. 전체 Edit Mode 검사와 통합 충돌 부위의 집중 검사, macOS 개발 빌드, 독립 저장 경로를 쓰는 실제 플레이어 조작·재시작을 구분한다. 화면 조작은 uGUI 레이캐스트와 합성 포인터·키보드 입력을 사용하며 모바일 실기기 검증은 아니다.

- 초기 통합본 `8a54d626`의 전체 검사: 3,770개 중 3,766개 통과, 4개 실패. 실패 원인은 그래픽 필수 부품 선언, Unity 객체 참조 처리, 새 계정의 물약 설정 초기화였다.
- 위 문제를 수정한 뒤 실패했던 4개를 모두 포함한 관련 검사 **243개 통과, 실패·건너뜀 0개**. 전체 3,770개를 수정 후 다시 실행한 결과로 표현하지 않는다.
- 앞선 통합 집중 검사 346개와 공통 UI 조정 검사 139개도 각각 통과했다. 서로 겹치는 검사는 합산하지 않는다.
- HTML 프로토타입 검사 231개, 공통 UI 계약 검사 9개 통과. 공개 위키는 생성·일치 검사, Python 검사 13개와 문서·DB 경로 검사를 별도로 수행한다.

최종 수정본의 macOS 개발 빌드는 오류 0개로 성공했다. 균열, 코어 제작, 버튼, 스킬 트리, 보석상, 공통 UI, 물약, 보석 6종을 대상으로 **13개 실행·재시작 과정이 모두 통과**했다. 화면 검사는 440×956, 956×440, 1600×900, 1600×1000, 2100×900의 세로·가로·PC 비율과 한국어·영어, 글자 크기 100%·150%를 포함한다. 기능마다 실행 범위가 다르므로 세부 조작과 크기 조합은 각 기록을 따른다. 기존 Unity API 경고와 일부 셰이더·종료 시 메모리 경고는 남아 있다.

## 공개 위키
