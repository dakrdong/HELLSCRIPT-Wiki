# 클로드 작업 검토와 후속 수정

후속 개발: 검토 이후 진행한 대상 우선순위·추적·저장 복원은 [대상 선택·추적 개발 기록](Edict_Targeting_Expansion.md)을 따른다. 이 문서의 검증 결과와 남은 작업 목록은 검토 단계가 끝난 시점의 기록이다.

작성일: 2026-09-12 · 기준 커밋: `22ddf0f` · 작업 브랜치: `codex/claude-review-20260912`

## 검토 범위와 작업 분리

사용자 요청에 따라 9월 9일 마지막 검증본과 클로드의 후속 커밋·소스·검사 기록을 비교했다. 기존 C# 소스 149개 가운데 73개가 바뀌었고 38개가 추가되어 검토 시작 시점에는 187개였다. 사냥 칙령의 저장·편집·공유·전투 연결, 성소 보행, 언어·글자 크기·터치 대응, 사망 전 기록, 밸런스 실행 도구와 던전 봉인 목표를 확인했다. 변경 전체를 새로 실행 검증했다는 의미는 아니다.

클로드의 최신 전체 검사 기록 `diag7.xml`에는 1,193개 통과가 남아 있다. 이를 이번 수정의 검증 결과와 구분한다. 능력치 체계는 별도 `worktree-d4-stat-sheet` 브랜치에서 아직 작업 중이며, 사용자가 해당 작업을 피하도록 요청했다. 그 작업 폴더·소스·검사 프로세스는 변경하지 않는다. 자동 병합이나 밸런스 재측정도 이번 범위에 포함하지 않는다.

## 확인하고 수정한 문제

| 문제 | 원인과 변경 |
|---|---|
| 등급별 회수 선택이 무시됨 | 독립적인 등급별 설정을 획득·추적 하한 두 개로 압축하고 있었다. 마법을 줍도록 하면 무시한 희귀도 주웠고, 일반 전설과 세트를 구분하지 못했다. 장비마다 해당 등급 또는 세트 행을 직접 적용하도록 바꿨다. |
| 전투 후와 지나가며 획득이 구분되지 않음 | 가까운 장비는 교전 여부와 관계없이 주웠고 다른 등급에 우선 회수를 켜면 지나가며 획득할 장비도 추적했다. 전투 후는 감지한 적과 진행 중 위험이 없어질 때까지 기다리고, 지나가며 획득은 이동 목표를 만들지 않는다. |
| 필터·거리·종료 선택이 반영되지 않음 | 직업·부위·최소 아이템 레벨, 필터 예외, 최대 경로 거리와 남은 장비를 두고 종료하는 선택을 장비 회수에 연결했다. 필터 예외는 ‘획득 안 함’을 덮어쓰지 않는다. 위험 해소 대기는 기존 경로 전체의 위험을 확인한다. |
| 전투 중 우선 회수가 기존 대기 조건에 막힘 | 사냥 칙령이 켜져 있을 때 장비 회수 시점은 그 원본을 따른다. 기존 추천 회수 규칙의 ‘적 없음’ 조건으로 우선 회수를 다시 차단하지 않는다. 다른 행동 규칙의 조건은 유지한다. |
| 봉인석이 필드와 지도에 표시되지 않음 | 목표의 상태 계산과 HUD 수치만 있었고 필드 표현·지도 표식이 없었다. 임시 기본 메시로 봉인석, 경비 결박, 파괴 진행 고리와 잔해를 추가했다. 지도에서는 육각형과 완료 체크로 구분한다. 발견하지 않은 지점은 표시하지 않는다. |
| 넓은 화면에서 봉인 개수가 사라짐 | 봉인 개수는 축약 HUD에만 연결되어 일반 갱신이 처치 수로 덮어썼다. 모든 화면 크기에서 봉인 개수와 관문 게이지를 유지하도록 보완했다. |
| 지도를 다시 그린 후 전투가 재개되지 않음 | 지도 화면을 다시 열어 그릴 때 이미 일시정지된 값을 진입 전 상태로 다시 기록했다. 최초 진입 시 상태를 유지해 창 크기·언어 변경 뒤 닫아도 원래 정지 상태로 돌아가도록 했다. |

회수 설정은 전투 시작·설정 적용 시 한 번 해석하며, 프레임마다 원본 전체를 다시 정규화하지 않는다. 사냥 칙령을 끄거나 원본 실행이 중단되면 기존 회수 방식으로 돌아간다. 재화 정산과 가방 보호는 기존 `Economy.AddItem` 경로를 사용한다.

새 사냥 칙령 원본은 모든 장비 부위를 선택한 상태로 시작한다. 기존 원본에 명시적으로 저장된 빈 선택은 바꾸지 않는다. 회수할 부위가 없으면 편집 화면에서 그 사실을 알린다. 저장 버전·장비 ID·클로드의 능력치 번호는 변경하지 않는다.

최신 실행본의 자동 실행 검사는 총 7회이며, 그중 3회는 저장한 상태를 별도 프로세스에서 다시 열었다. 화면은 실제 macOS 창과 Metal 렌더링으로 확인했다. 자동 입력은 UI 콜백을 사용했으며, 모바일 실기기의 터치·회전·성능을 검사했다는 의미는 아니다. 봉인석의 가로·세로 화면과 지도 이미지는 직접 열어 확인했다.

검사 이후 C# 소스 192개의 해시를 기록했다. 기존 메타·씬·직렬화 자산·설정·패키지·상세 기획 등 보호 대상 287개는 검토 시작 시점과 같다. 새 소스의 메타 5개가 존재하며 자산 GUID 중복은 없다. Unity가 검사·빌드 과정에서 바꾼 설정은 원래 값으로 복구했다. `final-source-manifest.json`과 `validation-summary.json`에 최종 증거를 모았다.

## 남은 개발과 검토 우선순위

1. 클로드가 작업 중인 능력치 체계와 밸런스 결과를 별도로 확인한 뒤 통합한다. 이번 작업의 `CombatSimulation.cs` 수정은 회수 처리 구간이며, 능력치 계산·피격·성장 수치는 건드리지 않았다. `Localization/en.txt`는 두 작업이 항목을 추가하므로 통합 시 중복·누락 검사를 다시 수행해야 한다.
2. 사냥 칙령의 나머지 스킬별 옵션과 정확한 대상 우선순위를 연결한다. 현재 전역 정책의 높은 HP·특수 대상 순서 등은 기존 단일 정책으로 근사하며, 다수 옵션은 저장·편집되지만 실제 행동에는 아직 반영되지 않는다. 편집 화면의 존재를 전체 동작 완료로 판단하지 않는다.
3. 장비 외 재화·보석·코어의 개별 필드 회수, 위험을 피해 새 경로를 찾는 선택과 예상 피해 감수, 자동 정리·반복의 모든 선택을 실제 사건에 연결한다. 이번 위험 해소 대기는 기존 경로가 안전해질 때까지 기다리는 처리다. 회수 행동 규칙을 없애거나 비활성화한 사용자 설정에서도 전역 회수만으로 행동을 생성하는 독립 스케줄러는 남아 있다.
4. 던전 관문의 실제 통행 차단·개방, 곁방 탐색과 보상 접근, 정수·제물 목표를 이어서 구현한다. 현재 봉인석 표시 추가는 통행 판정을 바꾸지 않는다. 봉인 수·게이지 기준과 기존 난이도는 그대로 유지한다.
5. 결과·훈련·장비 외 관리 화면의 가로·세로 배치와 긴 영어 문구를 확대 검증한다. 능력치 작업 기록에 남은 좁은 조건 선택 화면의 영어 부제 잘림도 해당 단계에서 확인한다.
6. 온라인 계정·교차 저장, 보석·소켓·장비 품질, 실제 모바일 입력·회전·장시간 성능을 각 기획의 완료 기준에 따라 진행한다. 공개 필수 범위와 아직 필요한 사용자 결정을 구분한다.

`Assets/Plans/next-development-plan.md`는 Unity AI가 만든 초기 인계안으로, 1·2·4배속과 현재 목록에 없는 빌드 명칭 등 실제 기획과 맞지 않는 내용이 있다. 개발 기준은 `Docs/Design`의 담당 상세안과 현재 소스를 사용한다. 최신 화면 기준은 [화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md), 배속은 [배속 접근 상세안](../Design/HELLSCRIPT_Speed_Access_Detail.md)을 따른다.
