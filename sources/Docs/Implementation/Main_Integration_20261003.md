# HELLSCRIPT 2026-10-03 로컬 통합 동작

CPU `ff300129`, 계정·수집 `ca8f1c7b`, 출석 `ab7985f`, UI 갱신 `c8335d1d`를 정상 Git 병합 관계로 보존한다. 이전 `main` 기준은 `14735105`다. 이 기록은 통합 동작과 검증 경계를 설명하며 아직 실행하지 않은 검사를 통과했다고 주장하지 않는다.

로컬 실제 검증: 수정 후 native UI 자동저장 7회(1440×810 3회+네 가지 화면 형태)가 모두 통과했고 13창×KO/EN, 총 182조합에서 무변경 Save 2730회와 실제 controller 자동저장 244회의 컨트롤 생성/제거·재생성은 0이었다. 합성 localhost 계정 최초/재시작 2회는 UID·진행 보존, 가입·Google 연동·checkpoint/session-end·ACK를 통과했다. 추가 native 회귀는 버튼·출석/재시작·상점·NPC·룬 10회·설정/재시작·타이틀 복귀·활동/DPS·절전/재시작·포탈/재시작·월드 표시 총 25/25 실제 exit0다. 실제 검사 binary 소스와 후속 QA 전용 변경의 범위를 각 영수증에 구분해 남긴다. 최종 전체 EditMode·release Web 및 브라우저 완료는 별도 종료 증거로 보고한다. UI 비용 원자료는 같은 크기의 실제 이전/이후 player 각 3회에 한정되며 여러 통합 작업을 포함해 순수 UI 원인만의 성능 향상으로 해석하지 않는다. Mono의 thread GC 원자료가 양쪽 모두 0이어서 GC 개선·무할당을 입증하지 못했다.

계정과 최신 main의 수동 충돌은 번역, 로그아웃, 설정 갱신, 설정 런타임 기록의 네 파일이다. 번역은 양쪽 키를 유지한다. 설정은 균열 중 캐릭터 변경 잠금과 새 Account 탭을 함께 유지한다. 타이틀 복귀는 균열 출석 시간을 정산하고 active 체크포인트 저장 성공을 확인한 뒤 전투·입장 상태를 닫는다. 계정 활동과 session-end 이벤트도 기존 저장 경로로 남기고 계정 저장 준비 상태를 해제한다. WebGL 계정 저장 확인 중에는 프로필 변경을 허용하지 않는다. 실제 균열을 완료 처리하거나 다른 계정의 저장을 덮어쓰지 않는다.

기존 네이티브 계정 검사에는 합성 localhost 서버에서 인증한 계정으로 균열을 시작·일시정지하고, 타이틀 복귀 후 동일 체크포인트와 정확히 한 개의 session-end 이벤트가 디스크에 남는지 확인하는 회귀를 추가한다. 다시 로그인했을 때 UID·캐릭터·균열이 유지되는지도 확인한다. 이는 실제 Google 제공자나 운영 수집 영수증의 증거가 아니다.

전체 EditMode와 바뀐 UI의 네이티브 회귀는 마지막 코드 통합 후 순차 실행한다. UI 갱신 계측은 14735105에 같은 opt-in 검사 파일만 더한 기준선과 최종 통합 소스를 동일 fixture·화면 조건에서 비교한다. 최소 3회 실제 player 실행을 남기며 같은 binary의 key 비활성화 대조군을 실제 전후 결과로 대체하지 않는다. 측정 구간은 동기 Save·binding flush·Canvas 갱신이며 전체 프레임·브라우저·모바일 성능으로 확대하지 않는다. [UI 조사](UI_Refresh_Stability.md)와 [성능 규칙](Performance_Review_Rules.md)의 미검증 범위를 유지한다.

계정 운영 DB·인증 변경과 공개 게임·위키 게시는 이 로컬 작업의 승인 범위 밖이다. 운영 DB 백업·복구 경로를 지원 도구로 확인하지 못해 운영 반영은 보류한다. 로컬 소스 통합, 검사, 웹 빌드 산출물, 실제 서비스 수집 및 공개 배포의 완료 상태를 각각 보고한다. WebGL의 기존 Cloudflare Web Analytics 비콘은 템플릿과 최종 HTML에서 정확히 한 개를 유지한다.

정리 전 각 작업 tip·Git bundle·고유 파일·미저장 Editor 객체 스냅샷의 근거를 보존한다. Editor 객체 JSON은 완전한 세션 복구라고 주장하지 않는다. 통합된 비활성 clean 작업용 워크트리와 브랜치만 정상 제거하고, 별도 Git 저장소인 출석 폴더 내부 WikiMain/WikiDeploy는 복구 경로로 보존한다. 원본 게임·main·필요한 원격 추적 참조는 유지한다.

진단용 `-hellscriptUiRefreshDiagnostic`은 격리 저장·증거 경로를 지정한 개발 빌드에서만 켠다. 표시 키와 실제 데이터, 컨트롤 교체 및 호출 경로를 기록해 최종 네이티브 자동저장 실패를 조사한다. 이 진단은 비용 계측 실행에서 켜지 않으며 원래 안정성 assertion을 유지한다.

첫 최종 native 실행은 인벤토리 자동저장 안정성에서 실패했다. 격리 진단으로 재생성 직전 장비·재화·화면 영역은 그대로이고 튜토리얼 `realTime`만 증가했음을 확인했다. 장비 키를 필요한 갑옷 보호 상태로 좁히며 원래 autosave·누름·중첩창 assertion과 기준 검사 파일을 유지한다. 실패 앱과 실제 종료·데이터·호출 경로는 로컬 증거에 보존한다. 이후 실제 수정 player로 검증 결과를 별도 보고한다.

공통 버튼 native 검사는 이전 소스 `6179471c`와 통합 소스 `ff74a482`에서 동일한 창고 드롭 실패를 보였다. 캡처의 필수 첫 시작 튜토리얼 대화가 슬롯을 가리는 기존 fixture 문제다. 이 검사의 격리 데이터는 명시적인 기존 마을 계정(레벨 30·합성 최고 클리어 15·기존 튜토리얼 면제·룬 수업 완료)으로 구성하며 컨트롤러 자동저장, raycast·드래그·정확한 슬롯 거래 assertion은 유지한다. 첫 시작과 실제 콘텐츠 해금은 전용 회귀에서 검증한다. 남아 있던 1.5 글자 크기 인자와 150 파일 이름도 기본 크기로 정정한다. 실제 사용자 진행·서비스 데이터는 바꾸지 않는다.

설정 native 검사는 CPU 작업의 타이틀 가림 정책 때문에 비활성 게임 카메라를 `Camera.main`으로 찾지 못해 NullReferenceException을 냈다. 개발 검사에서 WorldView가 소유한 카메라를 직접 보존·참조하며, 설정 전후 전체 카메라 객체의 동일성·활성 카메라 한 개·별도 캐릭터 없음·원래 targetTexture 및 실제 플레이어 중심 배치를 확인한다. 숨겨진 게임 카메라를 강제로 켜지 않고 기존 월드·입력·뷰포트·복원 assertion을 유지한다. 실패 로그와 후속 실행은 따로 보존한다.

카메라 검사를 바로잡은 뒤 타이틀 설정·비율·언어 전환은 통과했으나 기존 마을 fixture가 필수 첫 시작 안내를 끝낸 계정이라고 가정해 진입에 실패했다. 설정 전용 fixture는 기존 튜토리얼 면제·알림 숨김 상태를 명시하고 admission 요청을 격리하며 저장 성공과 마을 진입을 그대로 검사한다. 계정·첫 시작·해금 검증은 해당 전용 native 회귀의 범위이며 실제 서비스 입장을 증명하지 않는다.

명시적인 마을 fixture의 다음 중단은 설정 톱니바퀴의 고정 52 canvas-unit 상한이다. 현재 마을은 기존 `GameUI.RefreshPlaza`가 HUD의 크기와 실제 최소 44px를 기준으로 설정·콘텐츠 단축열을 함께 배치한다. 이 페이지 검사를 정사각형·콘텐츠 열과 같은 폭·최소 44px·safe-area 내부의 실제 계약으로 바꾼다. 타이틀·전투의 52-unit 상한은 유지하며 화면 클릭·뷰포트·카메라 복원 검사를 줄이지 않는다.

마을 캡처에서 실제 출석 자동 팝업이 설정 버튼 입력을 막은 추가 fixture 원인을 확인했다. 설정 전용 격리 저장의 로컬 표시 기본 설정으로 주간·월간 팝업을 당일 숨기며 저장 성공을 검사한다. 출석 기록·보상은 변경하지 않고 컨트롤러를 계속 실행한다. 팝업 표시·일괄 수령·재시작은 이미 별도의 출석 native 검사에서 실제 통과했으며, 설정 검사는 차단 창이 없는 설정 경로의 입력을 검사한다.

설정 검사의 마지막 균열 일시정지 snapshot 비교는 전경 실제 입장 시간·피로도 정산을 전투 진행으로 잘못 포함했다. 기존 `SettleRiftAttendance`는 설정/일시정지에서도 실제 시간과 피로도를 같은 영수증으로 정산하고, 시뮬레이션은 뒤의 설정 pause guard에서 멈춘다. 원본 before/after JSON을 보존하며 training은 전체 동일성, Rift는 실제 정산 시간 증가·같은 피로도 감소·realTime/영수증 일치를 추가 확인한 뒤 해당 두 표시/정산 값만 제외한 전체 RunState 동일성을 검사한다. 위치·체력·자원·RNG·행동·로그·통계·phase·pause·receipt 버전/속도는 계속 정확히 비교한다. 제품의 비용·일시정지 정책은 바꾸지 않는다.

활동 HUD native는 실제 전투·30개 HUD 조건·자연 종료·저장 재읽기·결과 그래프까지 통과하고, 합성 15단계 결과에서 반복 설정 바로가기에 실패했다. 현재 실제 반복 탭은 계정 최고 클리어 15도 요구하지만 기존 검사 계정은 12에 둔 채 결과 Run.stage만 15로 바꿨다. 결과 경계 검사의 계정 조건도 명시적으로 충족·assert하고 끝나면 원래 클리어 값을 복원한다. 결과 14/15/16의 표시 잠금·실제 pointer·같은 결과 복귀 검사는 유지하고, 실제 자연 종료한 1단계 활동·피해·시간 기록은 변경하지 않는다.

최종 통합 전체 EditMode의 첫 실제 실행(9a608c11)은 종료 코드 2, 전체 5081개 중 통과 4953개·실패 128개·건너뜀 0개였다. 보존한 출석 작업 실행과 같은 실패 이름이 127개이며, 메시지 차이 1개는 체크아웃 경로와 GameStore 줄 번호만 다르다. 추가 정적 null 패턴 검사 1개는 GetComponent 표현 두 곳을 지적했다. 캔버스 배율 표현은 기존 main 14735105에 이미 있었고 포커스 표현은 c8335d1d에서 추가됐다. 두 표현만 Unity 컴포넌트 ==/!= null 판정으로 바꾸고 배율 기본값·키보드/포인터 모드는 유지한다. 검사는 그대로 두고 원래 실패 XML을 보존하며 해당 guard·binding·캔버스 배율·공통 상세 동작을 별도 집중 검증한다. 전체/native 행렬을 반복하지 말라는 사용자 지시에 따라 이전 실패 전체 검사나 이전 native binary를 최종 전체 통과로 보고하지 않는다.
