작성일: 2026-09-22

[English](Blacksmith_Unity_Integration.en.md)

## 적용 범위

마을 대장장이의 기존 2.8m 상호작용 범위에서 ‘대장간 이용’ 버튼이나 PC의 E키로 대장간을 연다. 옵션 변경·장착 슬롯 강화·장비 강화는 실제 `GameStore`의 장비, 캐릭터 성장과 계정 재화를 사용한다. 제작은 대장간의 제작 버튼으로 기존 화면을 이용하며 각성·걸작·소켓과 투자 재료 기록을 유지한다. 저장과 재화는 기존 로컬 개발 어댑터를 따른다.

구현은 `codex/inventory-play-shortcut`의 커밋된 가방 UI와 두 무기 슬롯을 기준으로 한다. 작업 중인 원래 체크아웃의 미커밋 파일은 가져오거나 덮어쓰지 않는다. HTML 시연의 예시 장비·재화·브라우저 저장은 실제 계정에 복사하지 않는다.

## 게임 규칙과 계산

### 옵션 변경

`ItemGenerator.RerollPool`과 `ItemGenerator.Reroll`의 실제 부위·접두/접미·중복 그룹·직업 가중치·품질 범위를 사용한다. 유료 거래 성공 시에만 `rerollSlotId`가 영구 고정된다. 비용은 기존 `50 × L × (L+9)` 골드이며 같은 아이템 레벨에서 횟수에 따라 오르지 않는다.

자동 변경은 선택한 목표 중 하나가 나오면 즉시 대기한다. 팝업은 옵션·값·가능 범위와 멈추기·남은 횟수로 계속하기를 표시한다. 대기 중에는 추가 결제하지 않는다. 닫기·NPC 범위 이탈·종료 시 자동 진행은 중단하며 이미 성공한 개별 거래는 저장돼 있다. 자동 작업 자체를 재접속 후 재개하지 않는다.

목록은 고정된 줄의 현재 값과 범위 내 위치를 `공격 속도 +7.76% (95.2%)`처럼 붙여 표시한다. 백분율은 `(현재−최소)/(최대−최소) × 100`이며 값이 고정된 범위는 100%다. 품질 배율은 실제 옵션 값과 후보 범위에 반영한다.

### 장비 강화

| 부위 | 매 단계 증가 |
| --- | ---: |
| 무기·방패 외 보조 무기 | 공격력 +2 |
| 머리·방패 | 방어도 +2 |
| 몸통 | 방어도 +3 |
| 손 | 공격 속도 +0.08%p |
| 발 | 이동 속도 +0.05%p |
| 허리 | 최대 생명력 +8 |
| 목걸이 | 모든 원소 저항 +0.04%p |
| 반지 | 치명타 확률 +0.02%p |

최대 +100, 성공 확률 100%, 골드만 사용한다. 각성·걸작 배율은 미강화 기본값에 적용하고 마지막에 강화 보너스를 더한다. 장비의 기본 저항 수치와 전설·세트 효과는 유지한다.

아이템 레벨 `L`, 도달 단계 `N`의 비용은 `ceil((100L+10L²) × (1+0.05(N−1)+0.0025(N−1)²))`다. 정수 연산으로 올림해 부동소수점 오차를 피한다. 조회와 실행 모두 `GearEnhancement`를 사용하며 각 단계 비용을 합한다. +10은 전체 금액이 있을 때만 실행하고 +100 경계에서는 남은 단계까지만 강화한다. 최대 강화는 현재 골드로 가능한 연속 단계까지만 진행한다. 비용표 버튼·팝업은 제공하지 않는다.

예: Lv.30 장비는 +1에 12,000골드, +100 단계에 365,430골드, +0→+10에 155,550골드, +0→+100에 총 14,020,500골드가 든다. 3,000,000골드로 +10 이후 최대 강화를 누르면 +53, 잔액 90,300골드가 된다.

장비가 없어도 적용하며 양손 무기의 빈 보조손도 성장한다. 10부위의 레벨은 캐릭터별로 저장하고 작업 칸 2개는 계정에서 공유한다. 3·4·5번째 칸을 10·50·250다이아로 순서대로 영구 개방한다. 같은 캐릭터·부위에는 작업 하나만 시작할 수 있다.

비용·시간은 **도달 레벨**을 기준으로 누적한다. 1→2는 강화석 10개와 5분, 3~24는 이전 비용에 5개·5분, 25~49는 10개·10분, 50~74는 20개·30분, 75~99는 50개·1시간, 100은 500개·24시간을 더한다. [전체 계산표](../../Prototypes/Blacksmith/slot-enhancement-costs.csv)를 제공한다.

- 부위 하나 Lv.1→100: 강화석 **64,115개**, 작업 시간 **54일 50분**.
- 마지막 99→100: 강화석 **2,620개**, 작업 시간 **2일 19시간 35분**.
- 10부위 총합: 강화석 **641,150개**, 작업 시간 합계 **540일 8시간 20분**.
- 쉬지 않고 같은 작업 칸 수를 사용하는 이론상 최단 기간: 2칸 **270일 4시간 10분**, 5칸 **108일 1시간 40분**. 실제 기간은 접속·재료 공급·작업 시작 간격에 따라 길어진다.

시작 시 강화석을 차감하고 UTC 완료 시각을 저장한다. 완료한 레벨은 한 번만 정산한다. ‘지금 완료’는 클릭 시점의 `floor(max(0,완료시각−현재시각)/60)` 다이아를 사용하며 59초 이하는 무료다. 마을 밖과 앱 종료 중에도 시간이 흐른다. 진행 중 전투의 슬롯 성장 스냅샷은 장비 교체·빌드 변경·레벨 상승·재접속 후에도 유지한다.

### 강화석 획득

강화석은 `AccountSave.enhancementStones`에 저장하는 계정 공용 재화로, 신규 잔액은 0이다. 일반 재료와 합치지 않는다.

| 분해 대상 | 지급량 |
| --- | ---: |
| 일반 / 마법 / 희귀 | 0 / 1 / 5 |
| 세트 | 10 |
| 고유 효과 없는 전설 | 10 |
| 세트가 아닌 카탈로그 고유 효과 장비 | 15 |

세트 여부를 먼저 판정하고, 그 다음 `ItemCatalog.Unique(item.special)`을 확인한다. 고유 효과 장비에 전설 보상을 더하지 않는다. 새 고유 등급을 만들지 않으며 기존 이름 색상을 사용한다. 단건·일괄·자동 분해는 `BlacksmithCatalog.SalvageStones`를 공유한다. 일반 재료·코어·이전 투자 재료 환급은 유지한다. 균열 보스와 소탕은 `10+2×보상 단계`개를 지급한다. 균열은 실제 플레이 단계, 소탕은 기존 `highestClear` 기준을 따른다.

## 거래와 저장 이전

저장 스키마를 8로 올린다. 기존 `Item.enhancement` +5는 새 +5로 유지하고 새 기본 능력 공식으로 계산한다. 옵션 위치 고정, 소켓, 각성, 걸작, 접사 강화, 투자 재료와 환급 원장을 보존한다. 걸작 조건은 +5 이상이다.

- 계정: 강화석 잔액, `ForgeAccount.version`, 개방 작업 칸, 작업 목록.
- 캐릭터: `SlotProgress.version`, 고정 부위 순서의 레벨 10개.
- 작업: 고유 ID, 대상 캐릭터 ID, 부위 ID, 작업 칸, 출발·목표 레벨, 지불 강화석, UTC 시작·완료 시각.
- 기존 저장에 새 필드가 없으면 강화석 0, 작업 칸 2, 작업 없음, 각 부위 Lv.1로 이전한다.
- 중복 작업·불가능한 레벨·미래 버전·잘못된 시각은 검증에서 거부한다. 실패한 거래는 원본 상태와 저장을 보존한다.

장비 강화 견적에는 아이템 전체 스냅샷과 출발·목표 단계·합계 비용을 담는다. `GameStore.Transact`가 소유권, 해금, 마을 상태, 현 잔액과 최신 견적을 재검사하고 한 번 저장한다. 거래 ID로 중복 실행을 막는다. 시간 경과 정산은 완료 작업 ID를 사용해 한 번만 반영한다.

원소 저항의 백분율 보너스는 기존 저항 수치와 별도 `AllResistancePercent` 항목이다. 원소 피해 경감에 가산하고 기존 70% 상한을 유지한다. 물리 방어에는 더하지 않는다. 장비 비교와 전체 능력치 창도 같은 계산을 사용한다.

인벤토리의 공용 [장비 비교 규칙](../Design/Equipment_Comparison_Rules.md)을 따른다. `ItemComparison`은 대장간과 같은 기본 능력 종류와 단위를 사용하고, `EquipmentComparisonView`와 `ItemTooltip`이 인벤토리·상점·창고에 같은 값을 표시한다. 진행 중 전투의 인벤토리 비교에는 해당 전투가 시작될 때의 슬롯 성장값을 사용한다. 공용 자동 선택 설정과 분해 보호 규칙은 유지한다.

주무기 Lv.100의 모든 스킬 +1은 배운 액티브와 장착한 패시브의 유효 레벨만 올린다. 투자 포인트와 투자 상한 5는 유지하며 유효 레벨은 6까지 계산한다. 룬 보너스는 기존 경로에서 별도로 합산한다.

## 검증과 인수

[검증 기록](Blacksmith_Validation.md)에 실제 실행 결과와 확인 범위를 기록한다. HTML 테스트, Unity Edit Mode, 별도 macOS 개발 실행본의 버튼 입력·저장·화면 캡처를 구분한다. 모바일 비율의 macOS 창과 합성 입력 검증은 모바일 실기기 터치 검증을 대신하지 않는다.

공개 위키는 이 작업 브랜치에서 게시하지 않는다. `main`에 병합하는 작업자가 위키 생성·검사·공개 배포와 비로그인 열람 검증을 수행한다.
