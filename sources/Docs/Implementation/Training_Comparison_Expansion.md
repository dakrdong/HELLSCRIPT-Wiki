# 훈련 A/B 비교 개발 기록

작성일: 2026-09-09 · D4 행동 A/B 구현·macOS 실행 검증 완료 · 장비 교체·사냥 칙령 이관은 남음

## 플레이 흐름

[훈련 비교 상세안](../Design/HELLSCRIPT_Training_Comparison_Detail.md)에 따라 성소의 **고정 훈련장 → 같은 조건으로 A/B 비교**에서 단일·다수·위험 패턴 훈련을 선택한다. A를 마치면 화면 아래의 ‘B 설정 만들기’로 행동·스킬·패시브를 편집한다. 변경 목록은 편집 중 갱신되며, 취소하면 A 결과로 돌아온다.

B는 A 시작 직전의 영웅·레벨·소유 장비·강화·접사·배치·시드를 사용한다. HP·자원·쿨타임·효과·피해 기록도 새 훈련 상태에서 시작한다. 실제 계정이 두 시도 사이에 바뀌었다는 이유로 비교 기준을 다시 복사하지 않는다. 실행 중에는 조건을 고정하며, 열람 화면을 닫으면 이전 일시정지 상태로 돌아온다. 화면 제목에서 A/B와 레벨을 확인할 수 있다.

결과는 두 시도의 종료 사유·전투 시간·실제 경과 시간·남은 HP·피해·피격·보호막·이동·자원 부족과 스킬별 기록을 나란히 표시한다. 긴 기록을 읽은 뒤 ‘저장·활용으로’를 누르면 결과 저장과 A/B 설정 선택 버튼으로 이동한다. 한 번의 비교만으로 좋은 빌드나 승률을 판정하지 않는다.

캐릭터별 최근 비교 1개는 사용자가 저장을 눌렀을 때만 남는다. 선택한 A/B 설정을 슬롯에 저장해도 현재 행동은 유지된다. 실제로 사용하려면 행동 편집안으로 불러온 뒤 ‘설정 적용’을 눌러야 한다. 미리보기를 취소하면 현재 설정은 바뀌지 않는다.

## 집계와 저장의 경계

`CombatTelemetry`는 실제 행동·피해·규칙 검사·이동·위험 판정이 발생하는 지점에서 누적한다. 화면용 로그의 최근 일부를 세어 전체 결과를 추정하지 않는다. 사용 시작·발동·중단을 나누고, 실제 피해 출처 ID로 기본 공격·스킬·전설·세트 효과를 구분한다. 피해 계산이나 난수 사용 규칙을 별도로 만들지 않았다.

총 피해는 방어 계산 후의 값이며 실제 HP 피해는 과잉 피해를 제외한다. 전부 보호막으로 흡수한 공격도 피격 판정에 포함한다. 자원 부족은 실행하지 못한 규칙 검사 횟수이므로 소요 시간이나 놓친 공격 횟수로 표시하지 않는다.

회피 평가는 위험 훈련의 잿불 사술사(N10)가 실제로 준비한 공격에 한정한다. 예고 영역 안에서 이동기를 시작한 공격을 연결하고, 첫 실제 피해 판정 때 영역 밖이면 이탈, 안에서 피격하면 실패로 센다. 전부 보호막으로 흡수해도 회피 성공은 아니다. 취소된 공격·연결할 수 없는 위험·종료 시 미발동 공격은 평가에서 제외한다. 일반 보행이나 모든 적의 회피율을 검증한 지표가 아니다.

정상 종료는 60전투초·영웅 사망·표적 전멸이다. 수동 중단·진행 중·중도 설정 변경·내비게이션 오류는 완성한 비교로 저장하지 않는다. 구형 실행에는 로그에서 과거 수치를 복원해 채우지 않으며, 지원하지 않는 비교 버전은 원본을 보존하고 현재 화면에서 평가하지 않는다.

진행 중 비교는 실제 균열 이어하기에 저장하지 않는다. 경험치·골드·재료·장비·강화·실클리어·초회·소탕·균열 기록을 바꾸지 않으며, 명시적 비교 저장·슬롯 저장·실제 설정 적용만 각 경로에서 허용한다. 저장 실패 시 이전 비교 또는 슬롯을 유지한다.

## 소유자와 변경 파일

기존 `Hellscript.unity → GameController → CombatSimulation` 경로를 유지한다. `TrainingComparisonSession`은 기준 복사본·같은 환경 검사·A/B 시도·완료 결과를 소유하고, `GameController.Comparison`은 실행 전환·화면 연결·슬롯 저장을 맡는다. `GameUI.Comparison`은 기존 행동 편집기와 결과 화면을 연결한다.

`CombatStatistics`와 `CombatSimulation.Statistics`가 집계를 담당한다. `BuildEditing`의 공통 전투 설정 비교는 기존 첫 안내와 A/B에서 함께 사용하며, 메타데이터만 달라진 경우를 전투 행동 변화로 처리하지 않는다. `GameStore`는 완료한 결과를 영웅별로 저장한다.

`ProjectBuilder.BuildMac`에는 선택적인 `-hellscriptBuildOutput <.app 경로>`를 추가했다. 기본 출력은 그대로이며, 이번 UI 검증은 `Builds/macOS-Comparison/HELLSCRIPT.app`에서 진행한다. 사용자가 열어 둔 `Builds/macOS/HELLSCRIPT.app`를 종료하거나 덮어쓰지 않는다. 씬·프리팹·패키지·이미지를 새로 만들지 않았다.

최종 앱 시험은 새 Lv.1 마법사의 실제 소유 장비로 시작했다. A의 거리 7m를 B에서 5.5m로 바꾸었고, 두 시도 모두 60전투초·남은 HP 210/210·총 피해 8,379로 끝났다. 실제 걸은 거리는 0.8m와 0m였다. 거리 변경이 이 배치에서 피해 증가로 이어지지 않았다는 한 표본이며, B를 더 좋은 빌드로 판정하지 않는다. 레벨·HP·장비·드롭을 주입하지 않았고, 명시적 설정 선택을 제외한 진행·경제 기록의 불변을 검사했다.

실제 앱 재시작에서는 저장한 비교 전체, 슬롯 2의 거리 5.5m, 현재 행동의 거리 5.5m, 캐릭터·장비·재화·진행 기록을 대조했다. 비교가 진행 중 균열로 복원되지 않는 것도 확인했다. UI 콜백으로 입력 흐름을 검사했으며 물리 터치·Android·사람의 이해도나 밸런스 완료를 뜻하지 않는다.

초기 UI 실행의 저장·재시작 검증 이후 버튼 배치를 보완했다. 그 검사에서는 HUD 갱신이 A/B 제목을 덮어쓰는 문제를 발견해 제목 생성 규칙을 공통으로 수정했다. 다음 검사에서는 화면에 보이는 저장 버튼을 엄격한 사각형 포함 검사가 잘못 거부했다. 최종 실행에서 버튼의 x 범위 18~522와 스크롤 영역의 x 범위 18~522, 버튼 y 범위 342.75~393.75와 영역 y 범위 135~866.25를 기록했다. 화면 좌표 비교에는 기존 화면 경계 검사와 같은 1픽셀 허용 오차를 사용하고 캡처도 함께 확인했다. 두 실패 실행과 당시 소스·실행 파일은 보존하며 완료 증거에 포함하지 않는다.

최종 소스 92개, 611개 검사 이후 수정한 기존 소스 6개와 새 소스 3개, 실행 파일·검사·로그 해시는 [`소스·빌드 기록`](../../Artifacts/Validation/training-comparison-ui-source-manifest.json)에 남겼다. 씬·패키지·설정 등 보호 대상 98개의 불변, 소스 메타와 GUID, 문서 링크의 마지막 검사는 [`검증 요약`](../../Artifacts/Validation/training-comparison-validation-summary.json)을 따른다.

## 남은 범위

장비 교체를 포함한 훈련 편집, 최근 균열 10회의 원인·사망 직전 분석, 시간당 파밍 효율, 신규 사용자의 이해도와 물리 터치·Android 검사는 남아 있다. 같은 장비를 고정하는 현재 A/B를 장비 비교 훈련의 완료로 표시하지 않는다.

현재 비교의 슬롯 연결은 기존 3개 슬롯을 사용한다. 추가 요구인 [사냥 칙령](../Design/HELLSCRIPT_Hunt_Edict_Detail.md)의 5개 슬롯·이름·공유 코드·명시적 저장 및 미저장 이탈 처리와 함께 이 경로도 이관해야 한다. 새 명세가 기존 슬롯 수와 일반 사냥의 스킬 교체 제한을 대체하며, 기존 장비 보호 참조와 저장 내용을 보존한다. D3의 남은 장비 조합과 D4~D6 전체 범위는 [남은 작업표](../Design/HELLSCRIPT_Remaining_Development_Backlog.md)를 유지한다.
