# HELLSCRIPT 행동 규칙 편집·판단 개발 기록

작성일: 2026-09-09 · 범위: D3의 22조건, OR/AND 편집, 규칙별 목표·이동, 판단 기록과 저장

이 기록은 [전투 동작·투사체 확장](Action_Expansion.md) 이후의 구현을 다룬다. 전체 D3나 공개 버전의 완료 기록은 아니다. 기획의 수량·입력 범위·자동 실행 정책은 [플레이 완성도 체크리스트](../Design/HELLSCRIPT_Gameplay_Completion_Checklist.md)와 [상위 구현 기획서](../Design/HELLSCRIPT_Unity_Implementation_Plan.md)를 따른다.

자동 검사 137개, macOS 빌드, 실제 프로그램의 편집·전투·재시작 검사를 통과했다. 앱이 렌더링한 세로 화면도 확인했으며, 실제 마우스·터치와 Android 기기 검증은 남아 있다.

## 1. 장착과 실행 규칙을 분리했다

서로 다른 액티브 최대 4개를 장착하고 각 액티브에 최대 3개의 규칙을 작성한다. 같은 스킬의 여러 규칙은 자원과 재사용 대기시간을 공유한다. 규칙을 삭제하거나 꺼도 장착이 해제되지 않는다. 실행 규칙이 없는 장착 스킬은 편집 화면에서 안내한다.

기본 공격·장비 회수·상자 개봉·탐색과 성소 이용도 순서를 지정하는 행동 행으로 제공한다. 활성 규칙의 합계는 24개까지 허용한다. 꺼 둔 비스킬 행은 이 활성 상한에 포함하지 않는다. 물약은 기존의 독립 회복 채널을 유지한다. 규칙의 위아래 순서가 실제 검사·실행 우선순위이며, 하위 행동을 검사하는 것만으로 이동·상자 상태나 자원을 바꾸지 않는다.

편집기는 규칙의 사용 여부·순서·목표·개별 이동 설정·이동기의 착지 목적을 제공한다. 조건을 바꾼 뒤에도 스크롤 위치를 유지하고, 새로 추가하거나 복제한 규칙으로 화면을 옮긴다. 규칙 하나는 OR 최대 2묶음, 각 묶음에는 AND 조건 최대 3개를 가진다. ‘항상 검사’는 명시적으로 선택하는 별도 값이다. 빈 묶음, 잘못된 값, 미장착 스킬 참조, 중복 식별자와 상한 초과는 적용과 프리셋 저장을 막고 해당 행을 안내한다.

균열 안에서는 기존 장착 액티브·패시브를 유지하면서 규칙만 바꾼다. 프리셋 가져오기는 현재 장착하지 않은 스킬을 가져오지 않으며, 프리셋에 빠진 기존 장착 스킬의 규칙은 보존한다. 직접 규칙을 삭제한 경우에는 삭제를 존중한다. 적용 전 검증에 실패하면 현재 전투의 빌드·HP·자원·진행 중 행동을 변경하지 않는다.

## 2. 22개 조건의 자료와 판정을 공용화했다

`BehaviorRules`가 조건 이름·단위·비교 방식·입력 범위·기본값을 소유한다. 편집기와 실행기가 같은 자료를 읽는다. UI에는 한국어 이름을 표시하며 SC01–SC22는 저장과 검증의 고정 식별자로 사용한다.

| 조건 | 현재 읽는 전투 사실 |
|---|---|
| SC01–SC03 | 현재 최대 HP에 대한 HP·보호막 비율, 최대 100인 자원 비율을 읽는다. |
| SC04 | 보호막·함성·그림자 화살·이동/세트 충전·성소 등 지정 효과의 존재나 남은 시간을 읽는다. 다음 비용 감소처럼 만료시간이 없는 충전을 임의로 10초 후 끝나는 버프로 취급하지 않는다. |
| SC05 | 최근 1/2/3전투초 동안 실제로 잃은 HP를 합산한다. 보호막 흡수량은 별도로 저장하고 이 조건에 더하지 않는다. |
| SC06 | 시야와 12m 감지 범위 안의 적을 대상으로 자기 중심 2/3/5/8m 또는 선택 스킬의 예상 명중 영역 안에 있는 수를 센다. |
| SC07–SC08 | 인지한 정예·보스 존재, 현재 위치의 활성 위험 또는 0.5/1/1.5초 안에 완료될 위험 예고를 구분한다. |
| SC09–SC14 | 해당 규칙이 먼저 고른 후보의 거리·HP·행동 유형·등급·상태/자기 장판·위험 시전을 읽는다. 대상이 없을 때 ‘대상 상태 없음’ 조건을 참으로 처리하지 않는다. |
| SC15–SC16 | 장착·해금한 스킬의 남은 CD와 현재 유지 행동의 연속 시간을 읽는다. |
| SC17–SC19 | 인지한 적이 없는 시간, 허용·추적 필터에 맞는 감지 범위 내 장비, 가방 빈칸을 읽는다. 숨은 적이나 드롭을 미리 탐지하지 않는다. |
| SC20–SC22 | 보스 미등장/인지한 보스와 교전/처치, 균열 남은 시간, 지정 스킬의 최근 실행 확정 시각을 읽는다. 실행 뒤 중단돼도 시작 기록을 완료 기록으로 바꾸지 않는다. |

예상 명중 수는 정지한 현재 감지 대상을 기준으로 계산한다. 관통·다중 사격·화염구는 실제 투사체와 같은 벽 절단 및 선분 충돌을 사용한다. 다중 사격은 발마다 첫 충돌 대상을 찾고 중복 대상을 한 명으로 센다. 화염구는 첫 충돌점의 폭발 범위를 사용한다. 연쇄 번개는 실제 순서·도약 거리·방문 제한을 따른다. 앞으로 움직일 적의 위치나 비인지한 대상을 예측하는 기능은 아니다.

새 규칙의 ‘적 2명 이상’에는 암묵적인 보스 예외가 없다. 필요한 경우 정예·보스 조건을 OR 묶음으로 직접 작성한다. 기존 저장에 있던 숨은 보스 예외만 눈에 보이는 OR 조건으로 옮겨 행동 호환성을 유지한다.

## 3. 규칙별 목표와 이동 요청을 사용한다

각 규칙은 전체 설정, 현재 대상, 가까운 적, 정예·보스, 지원형, 원거리형, 낮은 HP, 밀집 중심, 자기 눈보라/활성 덫 안 우선 중 하나로 후보를 고른다. 후보를 고른 뒤 해당 후보의 HP·등급·상태 조건을 검사하므로 전역 표적의 정보를 잘못 읽지 않는다. 동점은 고정 적 ID로 결정한다.

같은 규칙의 표적은 최소 0.6전투초 유지하며, 가까운 적 선택에서는 이후에도 거리 차이 0.75m 미만의 작은 변동으로 바꾸지 않는다. 다른 규칙이 고른 후보, 생존용 이동, 대상 사망·시야 상실은 이 유지에 묶이지 않는다. 실행 또는 공격 위치 확보를 선택한 규칙 ID와 표적 선정 시각을 저장한다.

전투 이동은 접근·가장자리 선회·거리 유지·제자리·후퇴 중에서 전체 설정을 따르거나 규칙별로 덮어쓴다. 이동기의 위치 목적은 목표 위치, 적이 많은/적은 위치, 위험이 적은 위치, 지정 거리, 자기 덫 방향 등을 제공한다. 착지 가능한 후보와 인지한 위험을 비교하며 동작 실행 중에는 기존 행동 소유권을 유지한다.

여섯 추천 빌드도 같은 OR/AND 자료로 작성했다. 두 도약 규칙, 표식 대상, 관통 예상 영역, 자기 눈보라 안의 화염구 등이 전용 숨은 조건문 없이 편집 자료로 표현된다. 다만 맹독 매복의 추적 예상 경로 조준과 ‘자기 덫이 부여한 중독’의 출처 판정은 후속 효과 통합 작업이다. 여섯 빌드의 모든 설계 의도와 저레벨 성장 흐름이 완료됐다는 뜻은 아니다.

## 4. 실행한 이유와 실행하지 못한 이유를 보존한다

전투 HUD의 현재 행동을 눌러 판단 기록을 연다. 실행 선택, 조건 미충족, 자원 부족, CD, 사거리, 사선 차단, 착지 불가, 행동 잠금, 우선순위에서 밀림, 미해금·미장착·꺼 둔 규칙, 효과 유지 등을 구분한다. 조건 판정에는 실제 수치를, 실행 가능성 검사에는 필요한 자원·남은 CD 등을 표시한다.

일반 판단은 전투 시간 0.2초마다 실행한다. 실측 로그에서 0.2초 타이머의 작은 소수점 잔여값 때문에 0.25초 간격이 되던 문제를 발견해 경계 처리를 보완하고, 20개 전투 틱 동안 판단이 정확히 5번 실행되는 검사를 추가했다.

기록은 규칙 ID·당시 순서·빌드 버전·대상·최초/최종 전투 시각·반복 횟수를 가진다. 같은 사유는 묶고 최근 240개를 저장하며 화면은 마지막 검사 시각 순으로 최신 80개를 보여 준다. 기록을 읽는 동안 전투는 멈추고 닫으면 이전 일시정지 상태를 복원한다. 당시 수치 전체의 불변 스냅샷이나 최근 10회 균열의 종합 분석 화면까지 구현한 것은 아니다. 반복 기록의 상세 수치는 가장 최근 검사값이다.

`ruleSchema=1`에서 독립 장착 목록과 조건 묶음을 저장한다. 구버전은 스킬 행에서 장착 목록을 한 번 추출하고 기본 공격·회수·상자·탐색 행을 추가한다. 변환을 반복해도 행을 중복 생성하지 않는다. 예전 균열에는 관찰 기록이 없으므로 ‘적 없음’ 시간을 균열 시작부터 임의로 누적하지 않고 변환 시각부터 측정한다. 더 새로운 버전은 원본 저장을 보존한 채 거부한다. 계정 스키마 2, 전투 동작 버전 1, 지도 생성기 버전 2는 유지한다.

| 렌더링과 입력 범위 | 위 실제 실행은 배치 모드와 그래픽 비활성 옵션 없이 Metal로 실행했다. 앱 자체가 저장한 540×960 화면에서 조건 목록 상·하단, OR/AND, 요약, 판단 기록과 복원 화면, 균열 결과·상자·장비 화면을 확인했다. 화면 잠금 해제나 외부 브라우저를 사용하지 않았다. UI 검사는 실제 버튼 콜백을 호출한 자동 검사이며 마우스·터치 입력이나 Android 실기기 검증은 아니다. |

초기 배치 실행에서는 Metal 장치를 만들더라도 화면 저장이 실패했다. 일반 실행에는 명시적인 검사 옵션이 있을 때만 백그라운드 진행을 허용했다. 이전에 생성한 그래픽 비활성 PNG를 이번 화면 검증의 근거로 사용하지 않는다. 최초 규칙 검사에서 같은 프레임의 오래된 버튼 또는 잘못된 OR 묶음을 선택하던 검사 도구도 수정했으며, 최종 검사에는 화면 갱신 대기와 정확한 행 선택을 적용했다.

로그에는 심도 효과와 Panini 투영 셰이더가 빌드에서 제외됐다는 URP 경고가 남아 있다. 이번에 확인한 UI와 기본 전투 표현은 렌더링됐지만 후처리 효과까지 검증한 것은 아니다. 낮은 대비의 결과 로그, 도약의 지면 기준 표시, 작은 투사체의 가독성 등 표현 개선은 D6에서 이어 간다.

## 6. 남은 작업

이후 공통 피해 계산·보호막·중독 출처·보스 제압을 연결한 범위는 [전투 효과 통합 기록](Effect_Expansion.md)을 따른다. 이 문서의 137개 검사와 화면 증거는 해당 규칙 개발 시점의 기록이다.

1. macOS 540×960에서 확인한 편집·복원 화면을 다른 화면 비율과 Android 실기기로 확대 검증하고, 실제 마우스·터치 입력과 장시간 편집의 사용성을 확인한다.
2. 자기 덫의 중독 출처, 추적 예상 경로 조준, 소유 효과에 맞는 선택지와 잠금 이유를 완성한다. 위험·사망에 대한 다음 전투 틱의 긴급 재검사와 세부 시야 차단 사유도 후속 대상이다.
3. 출처별 상태이상·버프·흡수·보스 제압, 18패시브·15전설·6세트의 전체 피해 계산 순서를 통합한다. 규칙이 상태를 읽는 것과 상태 효과 전체의 완성은 구분한다.
4. 일반 적 12종·정예 6속성·보스 3종의 개별 준비·실행·회복·위험 예고를 연결한다. 현재 속박은 보행을 제한하지만 기존 돌진 완료 동작 등 모든 패턴에 대한 제어 통합은 남아 있다.
5. D4의 저레벨 추천 빌드·마을·훈련·결과 분석, D5의 서버·계정·보석·결제, D6의 Android 실기기·아트·음향·공개 검증을 이어 간다.

신규 소유 파일은 `BehaviorRules.cs`, `BehaviorPresets.cs`, `CombatSimulation.Rules.cs`, `GameUI.Rules.cs`, `RuntimeRuleSmoke.cs`, `RuleTests.cs`다. 기존 카탈로그·저장·전투·편집 보호·UI·검사 파일을 함께 연결했다. 씬·프리팹·패키지·프로젝트 설정·생성 이미지 원본은 이번 규칙 확장에서 변경하지 않았다.
