# 화염구 사냥 칙령 개발 기록

작성일: 2026-09-12 · [English](Edict_Fireball_Expansion.en.md)

**후속 구현:** 2026-09-13에 [눈보라 M02의 다섯 핵심 옵션](Edict_Blizzard_Expansion.md)도 연결했다. 이 문서는 M01 단계의 검사와 범위를 보존한다.

상태: **M01 핵심 옵션 연결, 전체 검사와 새 macOS 앱 실행·재시작 검증을 완료했다.**

## 해결한 문제

화염구 카드를 ‘꾸준히 공격’으로 저장해도 이전 자동 행동의 눈보라 조건이나 예상 인원 조건이 발사를 막을 수 있었다. 이전 화염구 규칙이 없거나 꺼져 있으면 새 설정만으로는 발사 후보가 생기지 않았다.

이제 사냥 칙령을 켜고 M01을 장착한 영웅은 저장된 핵심 옵션에서 화염구 판단을 만든다. 기존 규칙 목록을 덮어쓰지 않으며, 화염구가 여러 줄 있어도 후보는 하나다. 다른 행동의 순서는 사냥 칙령의 공통 공격 순서를 따른다. 사냥 칙령을 끄면 기존 규칙으로 돌아간다.

## 전투에 연결한 네 옵션

| 옵션 | 실제 처리 |
|---|---|
| 자동 사용 | OFF이면 새 시전 후보를 제외한다. 이미 준비 중인 시전과 발사한 화염구의 조준점·비행·피해는 유지한다. |
| 사용 방식 | STEADY는 유효한 적 한 명부터 공격한다. GROUP은 실제 첫 충돌 지점에서 원 폭발이 맞힐 것으로 예상되는 적이 세 명 이상일 때만 사용한다. EXPOSURE는 SM 4세트가 있고, 자기 영웅의 노출이 준비·비행 시간보다 오래 남는 후보를 먼저 고른다. 그런 후보나 세트가 없으면 기다리지 않고 STEADY로 판단하며 저장 선택은 보존한다. |
| 우선 대상 | 전역 대상, 정예·보스, 지원형, 원 폭발 인원이 많은 후보를 선택한다. 세트 노출 우선이면 유효한 자기 노출 대상군 안에서 적용한다. 원하는 종류가 없으면 전역 대상으로 돌아가며, 사거리 밖의 전역 대상 때문에 공격 가능한 다른 적까지 배제하지 않는다. |
| 조준 방식 | CURRENT는 시전 시작 때의 위치를 사용한다. PREDICTED는 최근 관측 속도에 준비 시간과 비행 시간을 더해 조준하고, 첫 충돌과 원 폭발 인원을 예측한다. 이동 정보가 없거나 오래됐거나 유효하지 않으면 현재 위치로 대체한다. 시작한 공격의 조준점은 바꾸지 않는다. |

사거리 10m, 투사체 속도 14m/s, 충돌 반경 0.25m, 원 폭발 반경 2.5m를 실제 실행과 맞췄다. 관측한 적만 후보로 사용하고 벽과 몸체 충돌을 검사한다. 보이지 않는 적의 위치나 이동 의도는 읽지 않는다. 첫 충돌 뒤의 폭발은 예측 결과를 예약 피해로 사용하지 않고 기존 실행 코드가 다시 판정한다.

LM02의 추가 폭발은 원 폭발 인원이 같은 후보의 동률을 풀 때만 비교한다. GROUP의 세 명 조건에는 더하지 않는다. MP01의 보너스와 SM 4세트 노출 소비는 실제 원 폭발 적중에서 처리한다. 착탄 전에 적이 경로를 바꾸거나 새 적이 끼어드는 경우까지 예측이 보장하는 것은 아니다.

해금, 실제 비용, 쿨타임과 행동 잠금은 기존 실행 검사를 통과해야 한다. 전역 생존 대응이 주 행동을 선택한 회차에는 화염구 판단을 실행하지 않는다. 현재 마법사의 회피기 M04는 자원 비용이 0이므로 회피 자원 보존을 이유로 화염구에 별도 비용을 더하지 않는다. LC02 할인은 실제로 시전을 시작할 때 한 번 소비한다.

사거리 밖이면 화염구의 파생 판단으로 접근할 수 있다. 이전 규칙이 없는 경우에도 접근하며, 자동 사용을 끈 뒤에는 그 접근 지시를 재사용하지 않는다. 진행 중인 시전은 파생 규칙과 조준점을 함께 보관하여 저장 복원 뒤에도 한 번만 발사한다.

## 화면과 저장

화염구 카드에 네 옵션이 전투에 반영된다는 안내를 추가했다. 판단 기록은 임의의 기존 규칙 번호 대신 ‘화염구 사냥 칙령’을 표시하고, 사용 조건 대기와 자동 사용 해제도 읽을 수 있는 문구로 보여 준다. 공유 화면의 오래된 ‘전역 생존 판단만 반영’ 안내를 현재 연결 범위로 고쳤다.

판단 기록 화면에서 언어를 바꿔 다시 그린 뒤 나가도 진입 전의 전투 일시정지 상태를 복원한다. 한국어 원문과 영어 문구를 함께 제공한다. [화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)의 본문 스크롤과 하단 버튼 접근성을 기준으로 앱 검사를 마쳤다.

저장 스키마·아이템 가중치·전투 피해 수치·씬·프리팹·패키지는 변경하지 않았다. `edict:M01`은 실행 중에 파생한 판단의 식별자이며 플레이어의 기존 규칙 목록을 수정하는 값이 아니다.

## 검증

집중 검사 148개가 통과했다. 기존 조건·누락된 규칙·중복된 규칙, GROUP 인원, LM02 동률, SM4 노출 소유자와 만료, 이동 조준과 실제 적중, 관측 정보 대체, 발사 후 OFF, 준비 중 저장 복원, 비용·할인·쿨타임을 검사했다. 후속 검토에서 사용 해제 후 접근 지시를 재사용하지 않는 경계 검사를 추가했다.

최종 **전체 Edit Mode 검사 1,461개**가 2026-09-12 14:43:16~14:47:12 UTC에 통과했다. 실패·건너뜀은 0개이며 약 235.66초가 걸렸다. 글로벌 대상 선택을 검사하는 기존 기본 공격 전용 구성은 M01 자동 사용을 명시적으로 꺼 격리했다. 해당 구성에 활성화된 M01이 남아 있어 파생 후보가 먼저 실행되던 14개 실패를 보존했고, M01 자체의 정확한 전역 대상 선택은 별도 두 검사로 확인했다.

| 실제 앱 검사 | 결과 |
|---|---|
| 저장 전후 | 실제 옵션 버튼으로 GROUP·DENSE·CURRENT를 선택하고 저장했다. 편집 중에는 원본이 유지되고, 저장 뒤 메모리와 다시 읽은 파일의 원본이 일치했다. |
| 실행과 OFF | 표적 한 명에서는 GROUP이 보류되고, 세 명에서는 발사했다. 그 뒤 실제 편집 화면에서 자동 사용을 꺼도 날아가는 화염구는 유지됐다. |
| 별도 프로세스 재시작 | OFF 선택, 비행 거리·방향, 시전 정책, 시간·지불 자원을 복원했다. 원 폭발은 세 명에게 한 번씩 적중했고 새 시전이나 중복 발사는 없었다. |
| 화면 | 1280×720·720×1280·640×360에서 한국어·영어와 140% 글자를 확인했다. 본문을 스크롤할 수 있고 하단 버튼이 안전 영역 안에 있었다. 판단 화면의 언어 변경 뒤에도 실행 중·수동 정지 상태를 각각 복원했다. |

첫 앱 검사에서 영어 140% 부제가 잘리는 문제를 발견해 한국어·영어 부제를 줄였다. 이 문구 수정 이후 **번역 검사 43개**와 수정 앱의 **실행·재시작 2회**가 통과했다. 성공한 실행은 14:47:55~14:48:16 UTC이며 화면 11장을 보관했다. 그중 영어 140% 옵션·판단 화면, 작은 가로 옵션 화면과 한국어 재시작 기록을 직접 확인했다. 이전의 실패한 실행과 화면 9장도 보존한다.

새 개발 앱은 `Builds/macOS-EdictFireball/HELLSCRIPT.app`이다. 최종 증거는 `Artifacts/Validation/EdictFireball/`의 `full-final.xml`, `caption-localization.xml`, `Native2/`에 있다. 전체 검사는 부제 수정 직전 코드를, 후속 번역 검사와 앱 검사는 문구 수정까지 포함한 코드를 검증한다. 검사 도중의 컴파일 오류와 테스트 실패도 보존했다. 잘못된 테스트 API 이름, 부정확한 표적 배치·관측 속도 설정, M04에 유료 비용이 있다는 잘못된 검사 가정을 수정했다.

최종 Runtime C# 168개와 영어 문구 표가 새 앱의 빌드 소스와 일치한다. C# 메타 누락과 중복 GUID는 없다. 검사 소스·기획·설정 636개 파일을 `validated-source.tar.gz`에 보관했으며 압축 파일 SHA-256은 `3069881f696a8eae6c6a6a81be7872f55d37efe0fd0ef77085618c4eec8a97fe`다. Unity가 검사 사본의 머티리얼에 붙인 Editor용 URP 버전 자료만 차이로 남기고, 작업 폴더의 머티리얼과 사용자가 변경한 설정은 유지했다.

## 남은 개발

이 기록은 M01 네 옵션의 연결 범위다. W03·A01·A02·M03의 기존 조준 연결은 유지하지만, 해당 스킬이 예전 규칙 조건 없이 독립적으로 작동하는 구조로 모두 전환한 것은 아니다. M02의 설치 목적·영역 보존·LM01 추적 선택을 비롯한 나머지 스킬의 고정 판단을 순서대로 연결해야 한다. 생존 대응 경로에서 이미 사용하는 일부 스킬 옵션도 있으므로, 미연결 수량을 단순히 89개에서 이번 네 개를 뺀 값으로 표시하지 않는다.

이번 단계는 모바일 실기기 성능·터치와 자연 플레이 밸런스를 확정하지 않는다. 별도로 진행한 20단계 접사 비교는 M01 연결 이전 코드와 기존 자동 행동을 사용한 [접사 대조 실험](Affix_Audit_Expansion.md)의 결과로 구분한다.
