# 마을 균열 입장과 최초 보상 화면

작성일: 2026-09-23 · [English](Rift_Entry.en.md)

마을의 균열 상호작용에서 출전 준비 화면을 연다. 승인된 HTML 시안의 단계 선택·피로도·물약·활성 스킬·궁극기를 실제 캐릭터와 저장 거래에 연결했다. 소탕·훈련·반복 설정은 기존 균열 관리 메뉴로 이어진다.

## 2026-09-30 스크롤 없는 새 배치

새 [HTML 시안](../../Prototypes/RiftEntry/HELLSCRIPT-RiftEntry.html)의 배치를 그대로 옮겼다. 가로·세로 어느 화면에서도 본문이 스크롤되지 않고 모든 정보와 조작이 한 화면에 보인다.

| 방향 | 배치 |
| --- | --- |
| 가로 | 세 열. ① 원화·제목·최초 보상 상자·단계 선택·규칙 문구 ② 피로도·장착 물약 세 칸(세로로 쌓음) ③ 사용 스킬 네 칸·궁극기 막대·소탕/훈련/반복 설정·전투 기록 |
| 세로 | 한 열. 원화 띠(제목 · 단계 선택 · 상자, 아래에 규칙 문구) → 피로도 → 물약 세 칸 → 스킬 네 칸과 궁극기(다섯 번째 칸) → 서비스 버튼 |

- **화면 안에 맞추는 방식:** 공통 창의 본문에 화면 높이와 같은 한 칸만 두고 그 안을 직접 배치한다. 내용이 높이보다 크면 글자·아이콘·간격을 하나의 배율로 함께 줄여 다시 그려 스크롤을 만들지 않는다. 남는 높이는 구역 사이 간격으로 나눈다. 글자 크기가 115%를 넘거나 세로 폭이 좁으면 원화 띠의 제목·상자와 단계 카드를 두 줄로 나눈다. 한 줄 문구는 칸에 맞춰 글자 크기를 줄인다.
- **공통 창 유지:** `ContentWindowView`의 제목줄·탐색 영역·고정 행동 영역을 그대로 쓴다. 시안과 다른 위치는 아래 세 가지뿐이며 이유를 남긴다.
  - 입장 버튼 두 개(일반 · 1.5x)는 시안의 오른쪽 열 하단이 아니라 공통 고정 행동 영역(창 하단 전체 폭)에 둔다. 설정 확인 중·포탈로 이동·균열로 다시 시작 같은 기존 상태 버튼을 같은 자리에서 유지하기 위해서다. 각 버튼은 이름과 부제 두 줄이다.
  - 준비 상태 문구(출전 준비 완료 · 피로도 회복 안내)와 가방 정리 필요 버튼은 탐색 영역, 심연 주화 잔액은 제목줄에 둔다.
  - 소탕·훈련·반복 설정과 전투 기록은 시안에 없는 기존 기능이라 스킬 열 아래(세로에서는 스킬 아래 한 줄)에 유지한다. 저장된 포탈 안내와 다음 콘텐츠 목표도 원화 아래 규칙 문구 옆에 유지한다.
- **제거한 것:** “출전 준비” 제목, “성소 › 균열의 문” 경로 표시, “일반 입장 1배속 · 일시정지 중에도 피로도 차감” 줄(도움말 팝업에 같은 내용이 있다). 캐릭터·1인 탐험 표기는 균열 제목 아래로 옮겼다.
- **피로도 칸:** 남은 시간, 오늘 회복 횟수, 일일·유료 게이지와 범례, 초기화 시각과 남은 시간, 이월 안내를 시안과 같은 순서로 그린다. 유료 회복분은 보라색이다. 피로도가 0이면 게이지 자리에 회복 버튼이 나온다.
- **문구:** 새 문구 13개를 `en.txt`에 영어와 함께 추가하고, 더 이상 쓰지 않는 5개를 지웠다.
- **거래와 저장:** 바뀐 것은 배치뿐이다. 물약·스킬 교체, 회복, 1.5배속 입장, 포탈 복귀·재시작은 기존 `GameStore` 거래를 그대로 쓰며 버튼 이름(`rift-enter-normal`, `rift-enter-fast`, `rift-potion-*`, `rift-skill-*` 등)도 유지했다.

## 2026-09-29 포탈 복귀와 재입장

전투 화면과 관찰 메뉴의 귀환 동작은 **포탈로 복귀**입니다. 확인하면 현재 균열을 실패로 종료하지 않고, 진행 상황을 저장한 뒤 성소로 돌아옵니다. 튜토리얼과 훈련의 기존 종료 방식은 유지합니다.

저장된 균열이 있으면 입장 화면과 기존 성소·균열 관리 메뉴에 두 가지 행동을 표시합니다.

| 행동 | 결과 |
| --- | --- |
| 포탈로 이동 | 중단한 균열을 같은 ID와 진행 상황으로 이어갑니다. 기존 입장 배속을 유지하고 입장 비용을 다시 받지 않습니다. |
| 균열로 다시 시작 | 선택한 단계에서 일반 속도로 새 균열을 시작합니다. 새 입장이 저장된 뒤 이전 포탈을 대체합니다. |

입장 창을 닫거나 입장을 취소하면 포탈이 남습니다. 입장 조건 확인·준비·저장에 실패해도 이전 균열은 유지합니다. 재시작 요청은 해당 캐릭터의 정확한 균열 ID에 연결하므로 오래된 요청으로 새 포탈을 없앨 수 없습니다. 성소에 있는 동안 균열 시간과 참여 피로도는 진행하지 않습니다.

`GameStore.SuspendRift`가 복귀 시 저장을 소유하고, 재입장은 기존 `CommitRiftEntry`를 사용합니다. 물약 출전 준비에도 같은 재시작 대상 ID를 전달합니다. 포탈이 남아 있을 때 [스킬 프리셋을 변경](Hunt_Edict_Quick_Presets.md)하면 재개할 균열에도 저장된 방침이 적용됩니다.

## 화면과 데이터 소유

`RiftEntryWindow`는 신규 콘텐츠 생성기로 만든 진입점이다. `ContentWindowView`의 제목·닫기·탐색·스크롤 본문·고정 입장 행동·안전 영역을 사용하고, 데이터 출처는 `EquipmentViewSource.Owned`다. 배치는 위의 [2026-09-30 새 배치](#2026-09-30-스크롤-없는-새-배치)를 따르며 본문은 스크롤하지 않는다. 선택 팝업도 같은 공통 창의 크기 제한 옵션을 사용한다.

`UiTheme`, `UiFonts`, `SkillIconView`, `PotionArt`를 공유한다. 심연 주화와 성소 원화는 기존 리소스다. 물약 36종은 보석상에 등록된 원본 PNG를 공유한다. [물약 출처와 해시](RiftEntryEvidence/potion-provenance.json)를 보존하며 새 이미지 생성이나 원본의 검토 상태 변경은 하지 않았다. 상자는 황동·올리브 테마의 코드 기반 도형이다.

| 상태 | 소유자와 저장 경로 |
| --- | --- |
| 일일·회복 피로도, 하루 회복 횟수 | 계정의 `RiftFatigue`; `GameStore.RefreshRiftDay`, `RecoverRiftFatigue` |
| 이번 입장의 배속·실제 참여 시간 | 저장된 `RunState.riftAttendance`; `CommitRiftEntry`, `GameController` |
| 단계별 최단 시간·향후 최초 보상 수령 기록 | 캐릭터의 `RiftEntryProgress` |
| 물약 보유 수량·세 슬롯 | 기존 `PotionInventory`, `PotionLoadout`, `GameStore.SetPotionSlot` / `SelectPotionSlot` |
| 활성 스킬 네 칸·궁극기 | 기존 `ClassSkillTree`, `HuntEdictEditSession`, `CommitHuntEdict` |
| 화면의 선택·스크롤 | 창의 일시 상태이며 저장 데이터를 직접 수정하지 않는다. |

저장 성공 알림 `GameStore.Committed` 이후 표시를 다시 읽는다. 통합 저장 형식은 11이며 기존 캐릭터·재화·전투의 소유자를 유지한다. 기존 로컬 개발용 저장 어댑터를 사용하며 운영 서버의 결제·시간 검증은 별도 경계다.

## 피로도와 유료 입장

- 시안의 시간 해석을 유지하여 한국 시간 00:00에 일일 지급분을 120분으로 갱신한다. 남은 일일 지급분은 쌓이지 않는다. 모든 캐릭터가 같은 계정 피로도를 쓴다.
- 균열의 실제 전경 참여 시간을 밀리초로 차감한다. 1.5배속에서도 실제 1분은 피로도 1분이다. 균열 안의 일시정지·공통 창 열기 시간은 포함하고, 마을·훈련·백그라운드 시간은 제외한다. 복귀·사망 때 사용한 시간을 반환하지 않는다.
- 일일 지급분을 먼저 쓰고 회복분을 쓴다. 보라색 회복분은 다음 날 지급되는 120분 외에 남은 만큼 유지한다. 자정을 걸친 참여 시간은 날짜 경계에서 나누어 정산한다.
- 총 피로도가 0이면 입장을 막고 **피로도 회복**을 표시한다. 심연 주화 500개로 20분을 회복하며 하루 3회까지 가능하다. 확인 뒤에도 잔액·피로도·횟수를 다시 검사한다.
- **1.5x 진행하기**는 확인 후 새 입장 스냅샷과 심연 주화 200개 차감을 한 번에 저장한다. 취소·잔액 부족·저장 실패에서는 차감하지 않는다. 저장된 균열 재개는 다시 결제하지 않는다. 반복 사냥의 다음 입장은 일반 속도로 시작한다.
- 더 빠른 성공 종료 기록만 해당 단계의 최단 시간을 갱신한다. 실제 시간 기준이며 자정과 재실행에도 유지한다. 복귀·사망·피로도 소진은 성공 기록을 만들지 않는다. 기존 돌파 단계에 시간 기록이 없으면 시간을 지어내지 않는다.

## 화면 안에서 장착 변경

2026-10-01 변경: 물약 슬롯을 누르면 보유한 기본·제작 물약을 아이콘·효과·수량과 함께 스크롤 목록에 표시한다. 장착 중인 물약도 숨기거나 비활성화하지 않고 체크 표시와 **장착 중 · 슬롯 번호**를 붙인다. 같은 슬롯의 물약을 다시 누르면 해제하고, 다른 슬롯에 있는 물약을 누르면 두 위치를 맞바꾼다. 아직 장착하지 않은 물약은 해당 슬롯에 장착한다. 다른 슬롯에 같은 계열의 다른 등급이 있으면 그 위치와 교환해 계열 중복을 막는다. 재고와 골드는 소비하지 않는다.

선택은 `PotionLoadout.Select`와 `GameStore.SelectPotionSlot`의 거래를 통해 실제 캐릭터의 세 슬롯을 한 번에 저장한다. 저장 실패 시 기존 메모리·디스크·재고를 유지하고 팝업에서 실패를 표시한다. 명시적 대입을 사용하는 기존 `SetPotionSlot` 호출의 의미는 바꾸지 않는다. 저장된 포탈이 있어도 성소에서는 편집할 수 있으며, 포탈 ID와 중단 상태를 다시 확인한다. 재접속과 포탈 재개에서도 새 배치를 사용하고 전투 시간·물약 재사용 시간은 보존한다.

장착한 스킬을 누르면 기존 활성 스킬 교체 창을 연다. 빈 일반·해금된 궁극기 칸에는 **+**가 표시되며 누르면 공통 사냥 칙령의 **스킬 트리**로 이동한다. 균열 입장창은 공통 창 스택에 유지하므로 닫기·뒤로가기로 같은 도전 단계에 돌아온다. 저장 후 스킬 표시는 갱신된다. 기본 세팅 적용 모드에서도 스킬 포인트·장착은 직접 편집할 수 있지만 자동 전투 규칙의 잠금과 기본 세팅 적용 상태는 유지한다. 저장된 균열 포탈의 스킬 구성도 기존 `CommitHuntEdict` 경로에서 함께 갱신한다.

3초 간격의 자동 저장 알림만으로는 화면을 다시 만들지 않는다. 입장창에 표시되는 상태가 실제로 바뀌었는지 비교하고, 중첩 창을 닫은 뒤 필요한 갱신만 한다. 피로도·자정 카운트다운은 기존 텍스트를 갱신하므로 대기 중 버튼·포커스가 반복 생성되지 않는다.

## 보석상 물약과 전투 연결

균열 화면은 보석상의 `GemElixirs` 정의와 `PE-G01-1` 형식의 실제 물약 ID를 그대로 읽는다. 이름·효과·등급·보유 수량·아이콘과 제작 재고를 별도로 복제하지 않는다. 기존 회복·보조 물약 8종과 보석 물약 36종을 함께 유지하며, 보석상에서 제작한 물약을 균열 슬롯에 바로 장착할 수 있다. 장착은 재고를 쓰지 않고 실제 전투 사용 때 소비한다.

능력치·재사용 시간·보호막·자동 사용은 기존 `HeroStats.Elixirs`, `CombatSimulation.Potions`, `PotionLoadout`의 공통 규칙을 따른다. 다이아몬드 계열은 1~6등급 순서대로 최대 생명력의 5·8·12·17·23·30% 보호막을 사용하며, 같은 보호막을 중첩하지 않는다. 인벤토리에서 지정한 공통 물약 사용 순서도 그대로 적용한다. [보석상 구현](Jeweler_Runtime.md)이 제작과 효과의 소유 문서다.

## 최초 보상 상자와 1000단계 목록

상자를 누르면 **균열 단계 + 빈 보상 아이콘 칸**으로 구성한 1~1000단계 목록이 열린다. 선택한 단계 근처에서 시작하고 끝까지 연속으로 스크롤한다. 화면에 보이는 행만 재사용하므로 1000개의 전체 UI 오브젝트를 동시에 만들지 않는다.

- 미클리어: 닫힌 상자를 표시한다.
- 클리어 후 미수령: 상자를 주기적으로 흔든다. 이전 저장의 `firstClears`도 클리어 근거로 읽는다.
- 수령 완료 기록이 있는 단계: 열린 상자를 유지한다.

**신규 최초 보상의 내용과 지급 거래는 비어 있다.** 실제 화면에는 임의의 수령 버튼이나 가짜 지급을 넣지 않았다. 향후 보상이 확정되면 기존 `GameStore` 거래에서 소유 조건·중복 수령·지급을 검증한 뒤 `claimed`를 함께 저장해야 한다. 현재 전투가 이미 자동 지급하는 초회 금화·재료는 별도 기존 기능이며 변경하지 않았다. 열린 상자는 검증용 수령 기록으로 표시와 저장 복원만 확인했다.

## 2026-10-01 입장 조작 수정 검증

관련 Edit Mode 검사 **138/138**, 공통 UI 소유 검사와 검사기 테스트 11개, 오류 없는 macOS 개발 빌드를 확인했다. 기본 글자 크기의 세로 440×956·가로 956×440·PC 16:9/16:10/21:9에서 한국어·영어의 빈 스킬 칸 이동·복귀와 물약 목록을 실제 런타임의 합성 포인터로 확인했다. 대기 중 자동 저장 두 번을 지나도 버튼 객체가 유지됐다. 물약 선택·해제·교환의 디스크 기록, 기본 세팅 모드의 스킬 저장, 별도 프로세스 재실행과 포탈 재개에서 장착 유지도 확인했다. 모바일 실기기는 검증하지 않았다.
