# 자동 반복 사냥과 결과 복원

작성일: 2026-09-13 · [English](Repeat_Hunt_Expansion.en.md)

상태: **로컬 반복 사냥의 종료 조건·자동 정리·결과 복원을 구현하고, 최종 전체 검사 2,198개와 macOS 실행·재시작 4회를 통과했다.**

## 플레이 흐름

성소와 균열 관리자에서 실제 사용하는 설정의 자동 반복 여부, 성공·실패 후 단계, 실패 상한, 완료 횟수·시간·목표, 시작 전 가방 여유와 결과 대기시간을 확인한다. 핵심 사냥 칙령을 켰다면 그 칙령을 사용하고, 껐다면 기본 행동 설정을 사용한다. 결과 화면도 같은 정책을 읽는다. 성공 후 중단을 선택해도 실패 후 재도전은 별도로 동작한다.

결과 화면에는 다음 단계와 남은 대기시간, 세션의 완료 횟수·연속 실패·실제 시간·획득 금화, 자동 정리 결과 또는 중단 사유가 표시된다. 자동 반복 중지는 즉시 현재 세션을 멈추고 실제 사용한 설정의 자동 반복도 끈다. 핵심 칙령을 끄기 위해 관계없는 기본 행동 설정을 덮어쓰지 않는다.

전투 기록, 반복 조건, 가방과 창고를 살펴보는 동안에는 다음 판 대기가 멈춘다. 결과로 돌아오면 남은 시간이 이어진다. 가방·창고에서 결과로 돌아오는 경로도 제공한다. 공통 설정·확인창이 열려 있거나 앱이 백그라운드에 있으면 새 판을 시작하지 않는다. [화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)의 결과 열람 규칙을 따른다.

## 완료와 목표의 계산 기준

| 설정 | 적용 기준 |
|---|---|
| 성공 후 | 같은 단계, 다음 단계, 중단 중에서 선택한다. 다음 단계는 실제 해금 범위를 넘지 않는다. |
| 실패 후 | 같은 단계, 한 단계 하향, 중단 중에서 선택한다. 하향은 1단계 아래로 내려가지 않는다. |
| 연속 실패 | 성공하면 0으로 돌아가며 같은 세션의 앱 재시작으로 초기화되지 않는다. |
| 완료 횟수 | 첫 수동 입장을 포함해 성공·실패를 모두 센다. 0은 제한 없음이다. 같은 runId는 한 번만 센다. |
| 실제 시간 | 전경의 사냥·일시정지·결과와 장비 열람 시간을 단조 증가 시계로 센다. 공통 설정창·백그라운드·앱 종료·복원 전 성소 대기는 제외한다. 전투 배속을 곱하지 않는다. |
| 시간 도달 | 현재 전투를 강제로 끝내지 않고 판이 끝난 뒤 멈춘다. 결과 대기 중 시간 제한에 도달해도 다음 판을 시작하지 않는다. |
| 금화 | 해당 세션의 전투·보스·캐릭터 초회·상자 보상으로 실제 받은 금화를 센다. 잔액 차이가 아니므로 소비로 줄지 않으며 판매·소탕·미실행 보상으로 채워지지 않는다. |
| 전설·세트 | 선택한 전설 효과 또는 세트를 지닌 장비 중 하나를 실제 획득했을 때 완료한다. 세트 전체 완성 조건이 아니다. 생성만 된 보상이나 놓고 온 장비는 세지 않는다. 획득 후 정리해도 획득 사실은 유지한다. |
| 단계 | 지정 단계 이상을 성공으로 끝냈을 때 완료한다. 해당 단계에 입장하거나 실패한 것만으로 완료하지 않는다. |
| 결과 대기 | 기본 행동은 기존 5초를 유지한다. 핵심 칙령은 0~30초, 0.5초 단위의 설정을 사용하며 기본값은 3초다. |

여러 종료 조건이 동시에 충족되면 수동 중지, 반복 꺼짐, 결과별 중단, 연속 실패, 완료 횟수, 실제 시간, 금화, 장비, 단계 순으로 대표 사유를 표시한다. 어떤 조건이든 충족되면 추가 판을 시작하지 않는다. 새 수동 입장은 새 세션을 만든다. 이미 끝난 결과의 정책은 그 결과에 보관한 정책으로 확인하고, 현재 설정을 바꿨다고 과거 정책을 다시 작성하지 않는다.

## 가방 정리와 다음 판 준비

핵심 칙령에서 지정한 정리 귀환 또는 매 균열 종료 후 정리를 연결했다. 등급별 가방 보관·판매·분해·창고 이동을 각각 적용하며 세트 행은 일반 전설 행을 덮어쓴다. 모든 정리는 기존 저장 거래의 사본에 적용하고, 저장에 성공한 뒤 실제 소유 목록을 바꾼다. 실패한 일괄 정리는 앞에서 처리한 판매까지 되돌리며 재시도에도 보상을 중복 지급하지 않는다.

잠금·장착·현재 설정 또는 다른 캐릭터의 프리셋이 참조하는 장비는 보호한다. 강화·지정 전설 효과·지정 세트의 추가 보호를 적용한다. 전설·세트의 판매·분해에는 별도 허용이 필요하다. 창고 이동은 기존 400칸 한도를 사용하며 공간이 없으면 장비를 가방에 남긴다. 사용자가 고른 창고 부족 방침에 따라 유지하거나 반복을 중단하고, 판매·분해로 임의 전환하지 않는다.

설정한 가방 빈칸이 확보되지 않았거나 저장·지도·칙령 오류 또는 미완료 정리가 있으면 다음 판을 시작하지 않는다. 정리·오류 복구 후 준비 다시 확인을 눌러 같은 세션을 이어간다. 가방이 계속 가득 찼을 때 ‘획득을 제한하고 계속’을 선택했다면 이미 가진 장비를 삭제하지 않고 새 장비 획득을 제한한다. 이후 빈칸이 생기면 새로운 드롭의 획득을 재개한다. 사용자가 별도로 지정한 시작 전 빈칸 수는 이 선택과 관계없이 충족해야 한다.

## 저장 소유권과 재실행

`AccountSave.repeatHunt`에 버전 1의 현재 세션을 추가했다. 캐릭터·세션·현재 runId·마지막으로 계산한 runId, 횟수·시간·금화·정책·남은 대기·정리 보고서와 한 개의 완료 결과를 저장한다. 진행 중 전투는 기존 `suspendedRun`을 사용하며, 완료 결과를 활성 전투인 것처럼 저장하지 않는다. `RunState.earnedGold`는 실제 균열 보상과 같은 확정 경로에서 갱신하고 상자 거래에도 함께 저장한다.

앱을 다시 열면 성소에서 저장된 결과를 확인할 수 있다. 결과 확인만으로 자동 반복을 시작하지 않으며, 이어가기를 눌렀을 때 남은 대기시간부터 재개한다. 진행 중인 판을 이어갈 때에는 같은 세션의 횟수·금화·실패 횟수를 유지한다. 다음 판은 이전 결과를 저장하고 다음 전투의 저장에도 성공한 뒤 화면에 표시하고 진행한다. 저장에 실패하면 이전 결과와 획득물을 유지한다.

예전 저장에는 세션을 만들어 넣지 않는다. 업그레이드 전 진행 중이던 균열의 과거 금화는 잔액으로 추정하지 않으며, 새 코드가 관측한 보상부터 센다. 지원하지 않는 세션 버전은 원본 파일을 보존한 채 불러오기를 중단한다. 캐릭터나 runId가 맞지 않는 상태와 잘못된 정책은 자동 실행 대상으로 인정하지 않는다.

## 검증과 남은 범위

최종 입력을 고정한 전체 Unity Editor 검사 **2,198개**, macOS 개발 빌드와 독립 실행·재시작 **4회**가 통과했다. [검증 요약](../../Artifacts/Validation/RepeatHunt/validation-summary.json), [전체 검사 원본](../../Artifacts/Validation/RepeatHunt/Full4.xml), [소스·실행본 해시](../../Artifacts/Validation/RepeatHunt/validated-source.json)를 보관한다. 실제 입력은 `7aa3312`와 이번 소스 변경이다. 씬·프리팹·패키지는 수정하지 않았으며, 기존 사용자 변경 19개를 보존했다. 보완 전 관련 검사 162개도 보관했고, 최종 전체 검사에는 이후 시간 콜백과 오류 안내 수정까지 포함했다.

새 계정의 전사로 시드 551의 1단계 균열을 일반 화면 갱신과 1배속으로 진행했다. HP·적·지형·보상·종료 상태를 주입하지 않았으며, 67.1전투초와 약 67.1실제초에 사망했다. 레벨 3, 처치 35회, 금화 234개를 기록했다. 결과를 살펴본 시간까지 합친 세션은 약 72.8초이며, 결과 열람 중 다음 판 대기는 멈췄다. 이 자연 전투에서는 상자를 열지 않았다. 상자 금화의 확정·실패·재시도·재실행 후 중복 방지는 Editor의 거래 검사로 검증했다.

네 실행 과정에서 핵심 칙령의 완료 결과 복원, 자동 반복으로 생성한 새 지도, 진행 중 판의 이어하기와 중복 없는 횟수 집계, 기본 행동 설정의 결과 복원·중지를 확인했다. 단계 하향·횟수·시간·금화 목표·자동 정리·가방 부족·저장 실패는 별도의 명시적 시험 상태로 재현했다. 자동 정리 판매는 사냥 금화 목표를 채우지 않았으며, 저장·가방 오류가 해결된 뒤 준비를 다시 확인해야 이어졌다. 백그라운드 시간 제외는 `OnApplicationPause` 콜백을 직접 호출한 검사다.

한국어·영어, 세로·가로, 글자 크기 140%를 포함한 최종 화면 **14장**을 캡처하고 모두 직접 검토했다. [화면 검토 기록](../../Artifacts/Validation/RepeatHunt/visual-review.json), [확대 영어 안내](../../Artifacts/Validation/RepeatHunt/Native4/initial-02-details-en-portrait.png), [복원한 결과](../../Artifacts/Validation/RepeatHunt/Native4/restart-01-restored-result-en.png), [영어 저장 실패 안내](../../Artifacts/Validation/RepeatHunt/Native4/resume-active-06-save-blocked-en.png)를 확인할 수 있다. 기존 반응형 열람 배치를 적용해 긴 부제의 잘림을 수정했다. 결과 목록 아래 항목은 고정 하단 버튼 위의 영역을 스크롤해서 읽는다.

Unity가 누락된 중첩 객체를 빈 객체로 복원하면서 기본 행동 세션을 읽지 못하거나 실행하지 않은 정리 결과가 표시되던 문제를 수정했다. 저장 오류의 내부 경로는 진단 자료에 보존하되, 게임 화면에는 저장 공간·접근 권한 확인과 재시도 안내를 표시한다. 실제 모바일 기기의 터치·기기별 안전 영역·장시간 성능을 확인한 결과는 아니다.

이 작업은 CHK-F05와 CHK-S02의 로컬 반복·복원 동작을 진전시킨다. 온라인 서비스의 연결 오류·서버 소유 세션·서버 시간과 다중 기기 충돌 검증은 별도 구현이 필요하다. 보석 보호는 실제 보석 소유 데이터가 아직 없어 완료로 표시하지 않는다. 가방 정리 시작의 여유 칸 트리거와 교체 가치 순위의 모든 확장 선택, 장시간 기기 성능 측정도 후속 범위다. 전투·이동·편집 시간을 종류별로 나눈 시간당 효율 통계까지 완료한 것은 아니다.
