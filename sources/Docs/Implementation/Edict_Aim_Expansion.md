# 사냥 칙령 조준·명중 예측 개발 기록

작성일: 2026-09-09 · 공통 명중 예측 연결 · 핵심 옵션의 조준 단계 구현

## 목적과 실제 연결 범위

[핵심 옵션 v0.2](../Design/HELLSCRIPT_Hunt_Edict_Skill_Option_Catalog.md)는 선택한 방향·착지점·설치 위치를 기준으로 예상 인원을 계산하고, 연쇄 번개의 예측과 실제 실행이 같은 연결 규칙을 사용하도록 요구한다. 새 설정을 전투에 연결하기 전에 기존 `PredictedHits`와 실제 투사체·연쇄 실행을 대조했다.

기존 연쇄 예측은 가까운 적부터 재방문했지만, 실제 연쇄는 아직 맞히지 않은 적을 먼저 골랐다. A→B 다음에 가까운 A와 아직 맞히지 않은 C가 있는 상황에서 예측이 실제 고유 대상 수를 적게 셀 수 있었다. 또한 다중 사격의 기존 예측은 고유 대상 수만 반환하여 단일 집중 사격의 예상 화살 수를 판단할 수 없었다.

이번 변경은 기존 전투의 예상 명중 조건을 새 공통 계산에 연결한다. 연쇄 실행과 예측이 같은 다음 대상 선택 함수를 사용하고, 다중 사격의 발사각 계산도 공유한다. 새로운 `PlanEdictAim`은 W03·A01·A02·M03의 핵심 옵션을 읽어 조준 후보를 만든다. 이 결과를 새 사냥 칙령의 시전 명령으로 자동 전달하는 연결은 아직 없다. 현재 설정 저장·새 편집 화면·전역 8분류의 전체 실행까지 완료한 단계가 아니다.

## 공통 명중 예측

`AttackForecast`는 공격 시작점·조준점·충돌 또는 영역 중심과 적중 대상 ID 목록을 반환한다. 고유 대상 수, 총 타격 수, 특정 대상의 적중 수와 관통 순서를 구분할 수 있다. 반환 목록은 변경할 수 없으며 적 객체의 이후 변경에 따라 내용이 바뀌지 않는다.

| 공격 | 계산 기준 |
|---|---|
| 관통 사격 | 실제 투사체 폭과 지형 충돌, 몸체와 충돌하는 순서, 기본 5명·AP03의 7명 상한을 사용한다. 선택 대상이 상한 뒤에 있으면 해당 조준 후보에 포함됐다고 세지 않는다. |
| 다중 사격 | 세 화살 각각의 첫 충돌을 구하고, LA02 유무에 따른 발사각과 같은 대상의 1회·3회 상한을 적용한다. 이미 동일 대상 상한에 도달했더라도 부딪힌 화살이 뒤의 적을 관통한다고 계산하지 않는다. |
| 화염구 | 조준 거리·최대 비행 거리와 첫 적·벽 충돌로 원 폭발 중심을 정한다. 원 폭발의 예상 인원을 계산하며 LM02 후속 폭발을 원 폭발 인원에 합치지 않는다. |
| 연쇄 번개 | 아직 맞히지 않은 적을 먼저 고르고 거리·ID로 동률을 정리한다. MP03·SMB 충전의 실제 최대 타격 수, LM04의 비연속 재방문과 적별 최대 2회 조건을 반영한다. |
| 자기 중심·부채꼴·착지 공격 | 해당 후보의 시작점·공격 방향·착지점에서 실제 범위와 벽을 검사한다. |
| 설치 영역 | 같은 설치 후보와 현재 관측 인원으로 계산한다. 별도 시작점에서 검토할 때도 설치 위치와 인원 계산이 그 시작점을 함께 사용한다. 설치 직후 피해·발동이 보장된다는 뜻은 아니다. |
| 기본 공격 | 근접의 거리·시야, 원거리의 첫 투사체 충돌을 계산한다. 추가 관통·연쇄 효과를 부여하지 않는다. |

예측은 현재 감지한 적만 읽는다. 호출자가 전체 적 목록이나 같은 ID의 별도 객체를 넘겨도 감지 범위를 넓히거나 다른 위치를 주입하지 못한다. 예측을 호출해도 전투 시간·난수·피해·충전·자원·초안·계정은 변경하지 않는다.

공격 형태의 예측과 실제 시전 자격은 구분한다. 특히 기존 연쇄의 예상 인원 조건은 사거리 검사보다 먼저 평가되므로, 형태 예측 안에서 첫 대상의 사거리를 이유로 인원을 0으로 바꾸면 접근 행동이 사라질 수 있다. 기존 규칙은 다음 단계의 `RANGE` 검사에서 접근 여부를 결정하도록 유지했다. 새 조준 단계는 처음 맞힐 수 있는 거리의 후보군을 먼저 추린다.

이 자료는 현재 배치가 유지된다는 조건의 기하 예측이다. 준비·비행 중 적의 이동·사망, 새로 합류한 적, 실제 피해와 장비 발동까지 확정하지 않는다. 실제 연쇄는 타격할 때마다 살아 있는 대상을 다시 확인하며 예측 목록을 예약 명령으로 실행하지 않는다.

## 핵심 옵션의 조준 후보

`PlanEdictAim`은 새 원본의 장착·해금·자동 사용 상태를 확인한 뒤 아래 범위를 처리한다. 공통 대상 선택 단계가 고른 적을 입력받으며, 이 함수가 전역 추적·생존·자원 정책을 대신하지 않는다.

| 스킬 | 이번 단계에서 처리하는 조준과 사용 방식 |
|---|---|
| W03 분쇄 일격 | 현재·특수·낮은 HP 대상 선택, 우선 대상 중심·많은 적·한 명만 포함하는 방향, 무리 인원 조건과 실제 분쇄 충전 전용 조건을 계산한다. 고립 방향의 인원에 다른 방향의 인원을 섞지 않는다. |
| A01 관통 사격 | 현재·특수·자기 덫 출처 중독의 대상 선호, 대상 방향과 대상을 관통 상한 안에 포함하는 방향, 1명·2명·특수 적 예외를 계산한다. LA01 장착 시 같은 인원 후보에서는 선택 대상의 유효 관통 순서도 비교한다. |
| A02 다중 사격 | 현재·특수 대상 선호, 즉시 공격·무리 정리·동일 대상 2발 이상의 집중 목적에 맞춰 방향을 비교한다. 집중 목적·집중 위치에는 실제 LA02를 요구한다. 사격 위치로 이동하는 판단은 후속 연결 범위다. |
| M03 연쇄 번개 | 전체·정예/보스·지원형의 유효 첫 대상군 안에서 고유 대상 또는 총 타격 수를 비교한다. 충전 수명이 1초 이하인 경우의 단독 적 허용과 장비 미충족 시 대체 방식을 계산한다. |

방향 후보는 적의 중심뿐 아니라 몸체·부채꼴의 각도 경계와 그 사이를 포함한다. 다중 사격에서는 대상 중심을 향하면 1발만 닿지만 약간 비틀면 2발이 닿는 후보를 찾을 수 있다. 각 후보를 같은 명중 예측 함수로 다시 검사한다. 이 후보 생성이 모든 지형에서 연속 공간의 전역 최적해를 보증하는 것은 아니며, 실제 장애물과 후보 수에 따른 검토는 후속 이동 연결에서 계속한다.

반환값의 `available`은 해당 조준과 스킬 목적을 만족하는 후보가 있다는 뜻이다. 현재 행동 잠금·자원·CD·일반 회피·긴급 대응·추적 한도·생존용 자원 보존을 통과했다는 뜻이 아니다. 이 조준 단계만으로 비용을 지불하거나 공격을 시작하지 않는다. 다른 스킬 요청에는 미지원 사유를 반환한다.

## 관측 속도를 이용하는 조준 위치

화염구와 마법사 기본 공격이 사용할 `ObservedProjectileAim`을 추가했다. 최근 관측 속도, 시전 준비 시간과 투사체 비행 시간을 이용해 조준 위치를 계산하고 지형 안의 이동으로 제한한다. 이동 정보가 없거나 오래됐거나 유효하지 않은 경우, 실제 이동이 봉쇄된 경우에는 현재 위치를 사용한다. 적의 다음 목표나 미래 이동 경로를 읽지 않는다.

이 계산은 조준 위치만 제공한다. 아직 화염구·번개탄의 새 핵심 옵션과 시전 시작에 연결하지 않았고, 움직이는 적들의 미래 충돌·폭발 인원을 완전히 예측하는 기능도 아니다. 이미 시작한 공격의 조준을 매 틱 바꾸거나 유도탄 효과를 추가하지 않는다.

## 검증과 남은 연결

최종 전체 Edit Mode 검사 **819개가 모두 통과**했다. 신규 검사 39개와 기존 검사 780개를 포함하며, Unity 6000.6.0f1에서 2026-09-09 14:34:17~14:36:02 KST에 약 104.58초 동안 실행했다. [검사 결과](../../Artifacts/Validation/edict-aim-editmode.xml)와 [실행 로그](../../Artifacts/Validation/edict-aim-editmode.log)를 보존했다.

앞선 집중 검사 177개와 전체 검사 818개도 통과했다. 이후 검토로 발견한 연쇄 접근 경계는 별도 회귀 검사에서 예상 인원 2명 대신 0명을 반환하는 실패를 재현한 뒤 수정했고, 최종 전체 검사에 포함했다.

[집중 검사](../../Artifacts/Validation/edict-aim-focused.xml), [접근 수정 전 전체 결과](../../Artifacts/Validation/edict-aim-before-approach-editmode.xml), [접근 경계 실패 결과](../../Artifacts/Validation/edict-aim-approach-regression.xml)를 보존했다. 적을 정지시킨 전투 시뮬레이션에서 시전·비행·적중까지 진행하여 관통·다중 사격·화염구·연쇄·도약의 결과를 비교했다. 연쇄 도중 실제로 죽은 적을 재방문하지 않는 처리, 숨은 적과 지형, 조준 후보의 원본 불변·저장 복원, 충전 만료 경계도 검사했다.

이번 단계에는 C# 4개를 추가하고 기존 전투 소스 4개를 수정했다. 최종 검사 대상 121개의 해시가 검사 시작 이후 동일하다. 보호 자산 98개와 기준 기획 6개도 단계 시작 해시와 일치한다. Unity 패키지가 자동 변경한 설정 기호는 원문 차이를 남기고 단계 시작 값으로 복원했다. [검증 요약](../../Artifacts/Validation/edict-aim-validation-summary.json)과 [소스 기록](../../Artifacts/Validation/edict-aim-source-manifest.json)에 연결 범위와 보존 결과를 기록했다.

이 단계는 새 화면·씬·프리팹·저장 스키마를 추가하지 않는다. [화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)에 따라 판단 자료는 표시 방향과 분리한다. 실제 모바일 방향 전환·터치·키보드·PC 창 조절이나 새 네이티브 앱 실행을 완료했다는 의미는 아니다.

후속 작업은 전역 대상·추적·생존 판단, 나머지 스킬의 고정 옵션 처리, 조준 결과의 시전 명령 전달, 명시적 저장과 편집 화면의 순서로 연결한다. 개발이 끝나기 전에는 조준 단계만 완성된 옵션을 실제로 작동하는 UI로 공개하지 않는다. 전체 사냥 칙령의 데이터·공유·이전 상태는 [핵심 옵션 v0.2 기록](Hunt_Edict_V2_Expansion.md)을 함께 확인한다.

## 후속 연결

조준 결과를 시전 명령에 전달하는 경로는 2026-09-11의 [조준 시전 연결 기록](Edict_Aim_Wire_Expansion.md)에서 구현했다. 사냥 칙령을 켠 영웅에 한해 네 스킬의 시전 전에 이 계획을 묻고 조준점을 전달한다.
