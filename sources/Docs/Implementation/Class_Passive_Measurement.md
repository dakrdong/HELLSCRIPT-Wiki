# 패시브 스킬 실측과 조정

갱신일: 2026-10-05 · [English](Class_Passive_Measurement.en.md)

“패시브를 측정해서 약한 것부터 조정해 달라”는 요청에 따라, 세 직업의 패시브 57개가 실제 전투에서 얼마나 도움이 되는지 하나씩 빼 보며 쟀고, 약한 것부터 수치와 발동 조건을 올렸습니다. 이 문서는 측정 방법, 조정 내용, 조정해도 남은 문제를 적습니다. 모든 수치는 **레벨 40·스킬 등급 1·장비 수준 30(세트·전설 없음) 영웅이 균열 10단계와 15단계에서 기본 사냥 칙령으로 싸운 150초 전투**의 시뮬레이션 결과입니다. 실기기나 실제 계정으로 잰 값이 아닙니다.

## 한눈에 보기

- **기준.** 일반 액티브에 스킬 포인트를 1개 더 쓰면 초당 피해가 평균 +1.7%(중앙값 +0.2%) 늘고, 빌드마다 가장 좋은 액티브는 평균 +6.4% 늘어납니다. 패시브가 평균 +1.7%보다 약하면 그 포인트를 패시브에 쓸 이유가 약합니다.
- **조정 전.** 57개 중 35개가 이 평균보다 약했습니다(보통 10, 양호 7, 강함 5).
- **조정.** 44개(첫 줄 패시브 12개, 새 패시브 32개)의 수치를 올렸고, 그중 8개는 발동 조건도 완화했습니다. 약한 것부터 고친 뒤 다시 쟀고, 아직 약한 것을 한 번 더 고쳤습니다.
- **조정 후.** 약한 패시브가 35개에서 **21개**로 줄고, 양호·강함은 12개에서 **26개**로 늘었습니다.
- **남은 21개.** 대부분 숫자를 더 올려도 풀리지 않는 구조 문제입니다(아래 “남은 문제”). 효과의 종류를 바꾸는 일이라 이번에는 손대지 않았고 결정을 남깁니다.

## 측정 방법

1. **빼 보기.** 같은 영웅·같은 난수 시드로 전투를 두 번 돌립니다. 한 번은 패시브를 켜고, 한 번은 그 패시브만 뺍니다. 두 결과의 차이가 그 패시브의 기여입니다. 세트·전설 효과가 없는 영웅이라, 완성된 빌드에서는 패시브 하나의 몫이 달라질 수 있습니다.
2. **전투.** 균열 10단계와 15단계를 150초 사냥하며, 모든 시전은 기본 사냥 칙령이 정합니다. 15단계에서 영웅의 최저 HP는 평균 43~45%이고 전투의 76~85%가 HP 50% 아래까지 내려가지만, 전체 1,044번의 전투 중 영웅이 죽은 것은 2번뿐입니다.
3. **세 가지 구성.** ① 설계 빌드 30개(기획한 전체 빌드, 시드 5~8개), ② 패시브마다 표준 구성 57개(패시브가 쓰는 액티브와 직업 기본 스킬만 넣은 구성, 시드 4개), ③ 보조 구성 23개(패시브가 기다리는 보조 스킬의 사용 옵션을 켠 구성, 시드 4개; 6개는 켤 옵션이 없어 ②와 같은 결과). 조정 전후 비교는 ②와 ③의 평균으로만 하며, ①은 조정 전에만 쟀습니다. 조정 후는 시드 3개(첫 조정)와 5개(두 번째 조정)입니다.
4. **지표.** 피해·치명·비용·쿨타임·이동·보조형은 **초당 피해가 얼마나 늘었는지(%)**, 방어·보호막형은 **받은 피해를 줄인 비율과 보호량 비율 중 큰 쪽(%)**, 회복형은 **회복량이 받은 피해에서 차지하는 비율(%)**입니다. 방어·회복 지표는 공격 지표와 단위가 달라 같은 %여도 같은 가치는 아닙니다. 자원·보호·회복량과 발동 횟수는 전투 기록에서 **분당 직접 집계**도 했습니다.
5. **잡음.** 같은 설정을 시드만 바꿔 돌리면 피해 지표가 ±1~3%포인트 흔들립니다. 그래서 **약 ±3% 안쪽의 차이는 실제 변화로 보지 않습니다.** 피해가 작게 늘어나는 패시브는 직접 집계(발동·자원·보호)를 우선했습니다.
6. **판정.** 평균(+1.7%)보다 약하면 *약함*, +3%까지 *보통*, 가장 좋은 액티브 1포인트(+6.4%)까지 *양호*, 그 이상 *강함*입니다. 기준은 설계 빌드 29개에서 액티브마다 포인트 1개를 더한 116쌍(균열 10단계, 시드 2개)으로 쟀습니다.
7. **조정 방식.** 발동은 잦은데 효과가 작으면 **수치**를 올렸고, 발동 조건이 좁아 거의 켜지지 않으면 **조건**을 풀었습니다(기본 공격 3→2회, 정지 1→0.5초, 자원 80→60%, HP 50→70%, 거리 7→6m). 첫 조정 뒤 다시 재서 아직 약하거나 구성마다 편차가 컸던 9개(WP07, WP09, WP14, WP17, AP01, AP12, MP07, MP09, MP17)를 한 번 더 고쳤습니다. 이미 강한 패시브는 건드리지 않았습니다.

4. **조건이 좁거나 닿는 몫이 작은 패시브.** WP12 전투 준비는 조건을 풀어도 분당 0.5회만 발동합니다(전사의 기본 공격은 이 구성에서 분당 1.7회). MP17 초과 마력은 첫 직접 적중에만 적용되고 자원이 높아야 해, 가산 피해를 +20%에서 +100%로 올려 시험해도 초당 피해가 +2.3%(±4.4)만 달라졌습니다. MP11 과부하·AP15 독과 서리·AP04 덫 사냥꾼·WP01 군중 속으로·WP02 끝나지 않는 회전은 닿는 몫이 작거나 시드 잡음 안쪽입니다. 이동속도 패시브(AP02 탈출의 발걸음·AP08 사냥감의 발자취)는 피해로 이어지는 경로가 약해 보입니다.
5. **대상 수를 늘리는 패시브.** AP03 꿰뚫는 시선은 관통 사격이 맞히는 최대 대상을 5명에서 7명으로 늘리지만 효과가 거의 측정되지 않았습니다. 한 직선에 적이 6~7명 서는 일이 드물기 때문으로 보이나 확인하지는 않았고, 수치를 더 올릴 값이 없는 형태입니다.
6. **자원 회복.** 이 패시브들의 가치는 분당 회복량에 거의 비례합니다. 표준 구성에서 분당 40~70 안팎을 회복하는 WP07 낙인 추격·WP09 반격의 호흡·MP07 점화의 되먹임·AP10 독의 순환은 +5% 안팎이고, MP12 축전 회수는 구체가 자연 만료하는 경우가 분당 0.4회뿐이라 30을 줘도 분당 12, WP18 선조의 유산은 궁극기에 붙어 분당 4.5입니다. WP13 거친 호흡과 MP13 결계의 호흡은 조건이 맞는 동안 회복 속도만 늘려 회복량이 작습니다.
7. **너무 강한 패시브.** WP04 피의 회복 +38.5%, WP10 함성의 여운 +27.8%, MP10 얼음의 잔향 +24.3%, WP11 바위 같은 착지 +17.3%는 일반 액티브 1포인트의 최대치(+6.4%)를 크게 넘습니다. 방어·회복 지표라 단위가 다르지만 격차가 커서 보고만 합니다. → **낮출지 결정해 주세요.**
8. **측정 한계.** 한 영웅(레벨 40·등급 1·장비 수준 30)과 균열 10·15단계만 재었습니다. 방어 패시브는 영웅이 더 위험해지는 단계에서, 공격 패시브는 세트·전설을 갖춘 빌드에서 달라질 수 있습니다. 특히 비용 감소(상한 50%)·받는 피해 감소(합산 상한 50%)·치명 확률(상한 75%)은 장비·세트와 상한을 나눠 쓰므로, 세트·전설을 갖춘 영웅에서는 이를 올리는 패시브(WP02, WP03, WP12, WP16, AP05, AP06, AP07, AP16, MP08, MP14, MP15)가 측정값보다 덜 늘어납니다. 시드가 3~8개라 ±3%p 안쪽은 구분하지 못합니다. 사용 옵션을 바꾼 구성은 23개만 쟀습니다. 이번 수치는 한 번의 균형 조정일 뿐 최종 균형이 아닙니다.

## 검증

검사는 작업 폴더를 복제한 별도 프로젝트에서 했고, 열려 있는 Unity 편집기와 계정 저장은 쓰지 않았습니다. 같은 검사를 병합 전 브랜치와 병합한 트리에서 각각 한 번씩 했습니다.

- **데이터·생성물.** `class_skill_runtime`·`class_skills`·`class_skill_options`·`class_skill_reports`의 `check`, `node tools/build_skill_tree.cjs --check`, `node Prototypes/SkillTree/build.cjs`(111개 모두 레벨에 도달 가능), `engine.test.cjs`, 공통 UI 검사(`check_ui_contract.py`·`test_ui_contract.py`·`check_ui_refresh.py`)가 통과했습니다. 병합한 트리에서도 같은 검사를 다시 했고 생성물이 달라지지 않았습니다.
- **Unity Edit Mode 전체, 병합 전 브랜치.** 명시 실행 전용인 측정 도구를 뺀 5,162개를 클래스 묶음 여러 번으로 나눠 한 번씩 실행했습니다. 첫 실행에서 9개가 실패했고 모두 옛 패시브 수치를 코드에 박아 둔 검사였습니다(예: 속박 시간 1.875초, 보호막 배율 1.2, 피해 감소 0.25). 값을 `SkillEffects.PassiveBase`와 스킬 데이터에서 읽도록 고친 뒤 해당 클래스를 다시 돌려 모두 통과했습니다. 실행 기록과 실패·수정 목록은 [editmode-runs.json](ClassPassiveMeasurementEvidence20261005/editmode-runs.json), 패시브·스킬 중심 666개의 보고서는 [passive-tuning-editmode.xml](ClassSkillEvidence/passive-tuning-editmode.xml)입니다.
- **Unity Edit Mode 전체, 병합한 트리.** `origin/main`(17dc75e9, 튜토리얼 연대기와 아이템 카드 장식 병합 포함)에 스킬 트리 브랜치와 이 브랜치를 합친 트리에서 5,236개를 6개 묶음으로 실행해 5,235개가 통과했습니다. 나머지 1개(`ObjectiveProgressTests.ExplorationWalksToEveryKnownOfferingAndDeliversWithoutTeleporting`)는 기본 제한 180초를 넘겨 실패했습니다. 병합 전 `origin/main`에서도 같은 조건에서 190.0초로 똑같이 실패하고(병합한 트리는 189.9초) 병합 전 브랜치에서는 176.4초로 간신히 통과했으므로, 이번 변경과 무관한 한계선 시간 초과입니다.
- **macOS 개발 빌드 스모크.** 병합한 트리와 `origin/main`을 같은 방식으로 빌드해 같은 계획의 스모크 8개를 돌렸고 결과가 모두 같았습니다. 스킬 트리(노드 37개·슬롯 4개·고정 컨트롤 위치)·스킬 초기화·스킬 프리셋·클래스 스킬 4개는 시작과 재시작 모두 통과했습니다. 스킬 메뉴·칙령 구역(반복 사냥 탭이 잠겨 있음)·빠른 프리셋(새 포션 그룹이 고급 옵션을 처음부터 펼침)·튜토리얼(재시작 뒤 생존 안내 목표를 기다리다 시간 초과) 4개는 `origin/main`에서도 같은 이유로 실패하는 기존 문제입니다. 트리 계열 스모크는 단계별 공개(93d59959) 이후 계정이 기존 사용자로 취급되지 않아 슬롯·스타일·프리셋이 숨겨져 모두 깨져 있었기에, `RuntimeSkillTreeSmoke.ExistingTrees`에서 기존 사용자 접근을 켜는 두 줄을 넣어 고쳤습니다. 기록은 [merge-validation.json](ClassPassiveMeasurementEvidence20261005/merge-validation.json)입니다.
- **결과 기록 갱신.** `ClassSkillRuntimeTests`가 쓰는 [빌드 비교 90건](ClassSkillEvidence/Build_Comparison.md)과 [사용 규칙 비교 18건](ClassSkillEvidence/Policy_Comparison.md)을 새 수치로 다시 만들었습니다. 빌드 90건 중 51건이 달라졌고 피해는 평균 +2.1%(−4.4~+14.8%)이며, 90건 모두 영웅이 살아남았습니다.
- **측정 근거.** [passive-measurement.json](ClassPassiveMeasurementEvidence20261005/passive-measurement.json)(57개의 전후 표), [probes.json](ClassPassiveMeasurementEvidence20261005/probes.json)(깊은 단계·큰 값 시험·기본 칙령의 시전 빈도).
- **하지 않은 것.** 실기기와 macOS 개발 빌드에서 바뀐 설명 문구를 눈으로 보지 않았습니다. 병합 뒤 `main`에서 다시 돌리는 전체 검사는 없습니다. 위 기록이 병합 직전 트리의 결과입니다.

## 다시 측정하는 방법

측정 도구는 `ClassSkillPassiveMeasurement`(Edit Mode 검사, `Explicit`)이며 평소 검사 묶음에는 들어가지 않습니다. 열려 있는 Unity 편집기는 프로젝트를 잠그므로 **작업 폴더의 복제본**에서 실행합니다(macOS의 `cp -Rc`로 빠르게 복제). 환경 변수 전체는 파일 맨 위 주석에 있습니다.

```bash
# 패시브 하나를 표준 구성으로, 균열 10·15단계, 시드 4개, 150초
HELLSCRIPT_MEASURE_OUT=/tmp/passive-kit HELLSCRIPT_MEASURE_KITS=1 HELLSCRIPT_MEASURE_BUILDS=WP07,AP12 \
HELLSCRIPT_MEASURE_SEEDS=4 HELLSCRIPT_MEASURE_SECONDS=150 HELLSCRIPT_MEASURE_SCENARIOS=rift10,rift15 \
/Applications/Unity/Hub/Editor/<버전>/Unity.app/Contents/MacOS/Unity -batchmode -nographics -projectPath <복제본> \
  -runTests -testPlatform EditMode -testFilter Hellscript.Tests.ClassSkillPassiveMeasurement
```

- `HELLSCRIPT_MEASURE_VALUES="WP07=8;MP07=12"`로 후보 수치를 데이터 재생성 없이 시험합니다(새 패시브는 `value`, 첫 줄 패시브 xP01~xP06은 `SkillEffects.PassiveBase`의 퍼센트).
- `HELLSCRIPT_MEASURE_ASSIST=1`은 보조 구성, `HELLSCRIPT_MEASURE_YARDSTICK=only`는 기준(액티브 포인트 1개)을 잽니다. 결과 `passive-measurement.json`을 순서대로 합산하는 스크립트는 저장소에 두지 않았고, 정리된 결과는 [측정 근거](ClassPassiveMeasurementEvidence20261005/passive-measurement.json)에 있습니다.
- 수치를 고칠 때는 `Docs/Design/ClassSkills/runtime_parameters.json`(새 패시브)·`SkillEffects.PassiveBase`(첫 줄 패시브)와 `catalog.json` 설명을 함께 바꾸고 `python3 tools/class_skill_runtime.py build`, `python3 tools/class_skills.py build`, `node Prototypes/SkillTree/build.cjs`를 실행합니다. 첫 줄 패시브의 설명은 게임 안 `GameCatalog.PassiveDescriptions`와 `Localization/en.txt`에도 있으므로 같이 맞춥니다.
