-hellscriptEdictSmoke                            checkpoint, -hellscriptEdictResume
-hellscriptTrainingEquipmentSmoke                checkpoint, -hellscriptTrainingEquipmentResume

Those last two were moved onto the unified window in a third pass, since both reach the editor through
shipped buttons. RuntimeEdictSmoke now covers what the window's own smoke does not: the window opens on
the saved document, editing moves only the draft, a save reaches the file and the hero together and a
fresh GameStore read agrees, leaving dirty asks and reverting restores, a damaged preset code is refused,
and a separate process reads it all back. RuntimeTrainingEquipmentSmoke drives the B draft through the
window and separates B from A by turning the basic attack's automatic use off, which is what it
measured before the control went missing. Loading a recorded document back into the editor was broken and is fixed: it
opened the window and drew the legacy page underneath, leaving both on screen and neither reachable.

Both missing controls were then added to the window. A skill's automatic use is the first row under each
skill on the hunt edict page, and the hunt edict on/off switch opens the presets tab. The option was not
only absent from the UI: HuntEdictLoadout.Canonical forced every skill's option 1 back to ON, with a
comment saying the editor had no control for it, so the draft could never hold the value. That line is
gone and an Edit Mode test pins the value through the loadout, a preset and a share code.

-hellscriptComparisonSmoke                       checkpoint, -hellscriptComparisonResume

The comparison smoke was repaired in a fourth pass. Four expectations had drifted. The battle title
"TRAINING / A · Lv.1" was never produced by BattleHeading, which has composed "TRAINING / A" since the
first commit while the level lives in the subtitle, so the header and the subtitle are now read
separately. The baseline distance of 7 and the "7m -> ..." preview string were read from the run instead
of assumed. The battle screen reaches the build editor through the observation menu, and a comparison
run sends that entry to the fixed-conditions screen. And the B editor is now the edict variant for any
hero on the hunt edict, so this smoke, which covers the behaviour-build comparison and its distance
slider, puts its hero on the pre-edict rule engine explicitly; the edict comparison path is covered by
the training equipment smoke. The hero's one-time potion grant also lands on the first sanctuary visit,
which the flow triggers partway through, so that visit is made before the progression baseline is taken.
