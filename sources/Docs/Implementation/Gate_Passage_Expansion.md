# 균열 관문 통행 개발 기록

작성일: 2026-09-12 · 이전 단계: [대상 선택·추적](Edict_Targeting_Expansion.md)

후속 [정수 운반자·제물 운반 개발 기록](Objective_Chains_Expansion.md)에 두 목표의 자동 진행·저장·표현과 결과의 목표·시간 기록을 추가했다. 아래 구현과 남은 범위는 관문 통행 단계 당시의 기록이다.

## 범위와 기준

[던전 구성 상세 기획](../Design/HELLSCRIPT_Dungeon_Composition_Detail.md) 6·8·10·11장의 관문을 실제 이동·관측·저장에 연결했다. 이전에는 닫힌 관문이 보스 광장을 탐색 후보에서만 제외했고, 통로는 그대로 열려 있었다. 기존 코드를 대상으로 한 검사 4개에서 이동·시야·투사체 차단과 폐쇄 중 도달성이 모두 실패했다.

능력치·성장·전투 밸런스는 클로드의 별도 작업으로 남긴다. 봉인 수 2개, 봉인 처리 1.5전투 초, 관문 게이지 대체 조건 100과 목표 경로의 현재 생성 기준은 바꾸지 않는다. 관문 통행을 먼저 검증한 뒤 정수 운반자·제물 운반을 이어서 구현한다.

## 구현 내용

- 새로 생성하는 목표 균열에서는 보스 광장으로 연결된 모든 출입구에 각각 관문을 저장한다. 고리의 반대편 출입구나 추가 연결로 우회하지 못해야 한다.
- 닫힌 관문은 보행·시야·투사체와 관문 위 착지를 차단한다. 보스 광장 외의 방, 봉인 접근 지점과 게이지를 채울 수 있는 적은 계속 접근 가능해야 한다.
- 봉인을 모두 부수거나 처치 게이지가 100에 도달하면 같은 관문 상태가 길찾기에도 적용된다. 이전에 실패한 이동 경로를 폐기하고 열린 통로를 다시 계산한다.
- 기존 지도 버전 1·2의 진행 중 저장에는 관문을 추가하지 않는다. 이미 저장한 위치를 새 장애물로 가두지 않도록 원래의 통행 상태를 보존한다. 새 지도 버전은 3이다.
- 생성 검사는 닫힌 상태에서 목표와 게이지 경로가 남아 있는지, 열린 상태에서 적과 보스 지점에 모두 갈 수 있는지를 따로 검사한다.
- 관문 모델은 자체 제작한 기둥·철제 문·상태 불빛으로 구성했다. 닫혀 있을 때는 문과 보라색 불빛이 보이고, 열리면 문이 사라져 통행이 가능해지며 불빛은 초록색으로 바뀐다. 모델과 지도 표식은 발견한 관문만 보여 준다. 화면 표시가 탐색 상태를 변경하지 않는다.
- 관문이 실제로 열리는 전환에서만 알림을 띄운다. 열린 저장을 복원하거나 화면을 다시 그릴 때 알림을 반복하지 않는다. 지도에는 한국어·영어 상태와 표식 설명을 추가했다.

## 검증

Unity 6000.6.0f1에서 검증했다. 최신 실행본은 `Builds/macOS-GatePassage/HELLSCRIPT.app`이고, 증거는 `Artifacts/Validation/GatePassage`에 있다.

| 검사 | 결과와 증거 |
|---|---|
| 기존 구현의 문제 재현 | 새 검사 4개 모두 실패. `before.xml` |
| 첫 통행 수정 | 관문·균열·봉인·필드 관련 44개 통과. `first-fixed.xml` |
| 전체 자동 검사 | **1,261 / 1,261 통과**, 실패·제외 0개. 2026-09-12 18:56:53–19:00:44 KST, `full.xml` |
| 새 관문 검사 | 18개. 두 테마·방 6/7/8개를 섞은 지도 100개와 비상용 고정 지도 6개, 양쪽 통행 상태·봉인/게이지 개방·한 번의 알림·구형 저장·발견 범위를 검사했다. |
| 최종 빌드 | 성공, 오류 0개, 정상 종료. `build.log` |
| 실제 앱 실행 | 별도 저장 폴더에서 실행 1회와 재시작 2회 모두 통과. `native-results.json` |
| 화면 | 한국어·영어, 1920×1080·1280×720·720×1280·640×360에서 화면 12개를 기록했다. 모든 언어·크기 조합을 검사했다는 뜻은 아니다. |

실제 실행은 **닫힌 관문 저장 → 재시작 후 폐쇄 유지 → 게이지로 개방 → 열린 상태 저장 → 두 번째 재시작 후 자동으로 광장 진입** 순서로 확인했다. 첫 재시작의 개방 과정은 같은 입력을 준 별도 전투 실행과 상태가 일치했다. 창 크기 변경과 지도 재구성은 관문·탐색·전투 상태를 변경하지 않았으며, 지도에서 돌아왔을 때 원래의 일시정지 상태도 유지했다.

[닫힌 관문](../../Artifacts/Validation/GatePassage/Evidence/02-closed-gate-wide.png) · [열린 관문](../../Artifacts/Validation/GatePassage/Evidence/02-opened-wide.png) · [재시작 후 광장 진입](../../Artifacts/Validation/GatePassage/Evidence/02-open-resume-arena-portrait.png)

전체 검사 이후 변경은 실행 검증용 `RuntimeGateSmoke.cs`의 도착 확인 시점과 작은 창의 추가 캡처뿐이다. 게임에 적용되는 코드는 전체 검사 시점과 같다. 최종 빌드와 실제 실행은 이 검증 코드 보완까지 포함한다. `tested-source-manifest.json`과 `final-source-manifest.json`에 각각의 소스 해시를 남겼다.

C# 파일 200개를 확인했고, 이번 단계 시작 시점의 기존 메타데이터·씬·직렬화 자산·설정·패키지·기획 파일 296개는 유지했다. 새 메타 파일 4개에 GUID 중복이나 C# 메타 누락은 없다. 전체 요약은 `validation-summary.json`이다.

## 남은 범위

정수 운반자·제물 운반, 결과 화면의 목표 종류·진행 시간 기록은 후속 작업이다. 이번 검증은 통행 조건을 분리한 macOS 개발 실행본의 자동 시나리오이며, 모바일 실기기 터치·장시간 성능·전체 게임 밸런스 검증을 포함하지 않는다. 이 기록을 균열 목표 세 종류나 게임 전체의 개발 완료로 읽지 않는다.
