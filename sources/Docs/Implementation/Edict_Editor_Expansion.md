# 사냥 칙령 v0.2 항목별 편집 화면 개발 기록

작성일: 2026-09-10 · P0 4단계 · 전역·사용 스킬·순서·스킬 설정 편집 · 갱신: macOS 앱 실행 확인 추가

## 적용 범위

[저장 연결](Edict_Storage_Expansion.md), [전투 연결](Edict_Drive_Expansion.md), [공유 화면](Edict_Share_Expansion.md)에 이어 원본의 모든 항목을 화면에서 직접 고치는 편집기를 만든다. [스킬 옵션 화면 상세안](../Design/HELLSCRIPT_Hunt_Edict_Skill_Options.md)의 화면 구성을 따라 전역 설정, 사용 스킬 칸과 공통 공격 순서, 스킬별 핵심 옵션의 세 분류로 나눈다.

성소의 **사냥 칙령 v0.2 편집**으로 들어가며, 공유 화면과 서로 오갈 수 있다. 이 화면은 원본을 편집하는 곳이고, 자동 판단을 켜고 끄는 스위치는 공유 화면에 그대로 둔다.

## 편집본은 항상 정규 원본이다

화면은 저장된 원본의 사본을 편집본으로 들고 있다. 값을 하나 바꿀 때마다 `HuntEdictV2Editing`의 도우미가 정규화된 새 원본을 만들어 돌려주며, 거부된 값은 편집본을 절반만 바꾼 상태로 남기지 않는다. 그래서 편집 중 어느 시점에도 편집본은 코덱·비교·검사 함수에 그대로 넘길 수 있다.

| 도우미 | 하는 일 |
|---|---|
| `WithGlobal` | 전역 설정 한 항목을 정의의 정규 규칙으로 검증해 바꾼다. |
| `Stepped` | 숫자를 선언된 단위만큼 올리거나 내린다. `decimal`로 계산해 0.1 단위가 세 번 누른 뒤에도 격자를 벗어나지 않는다. 범위 끝에서는 멈춘다. |
| `NextChoice` | 선택지를 순환한다. 마지막 다음은 첫 번째다. |
| `MovedInOrder` | 순서 목록에서 이웃과 자리를 바꾼다. 첫 항목은 위로, 마지막 항목은 아래로 갈 수 없다. |
| `ToggledInSet` | 복수 선택을 넣거나 뺀다. 결과는 누른 순서가 아니라 선언된 순서로 정렬한다. |
| `WithSkillOrderMoved` | 공통 공격 순서의 스킬 자리를 바꾼다. |

사용 스킬 칸과 스킬별 옵션은 기존 `WithSlot`·`WithOption`을 그대로 쓴다. 칸을 누르면 해금한 다음 스킬로 넘어가며, 이미 다른 칸에 있는 스킬을 고르면 기존 규칙대로 두 칸이 맞바뀐다. 균열 진행 중에는 칸을 바꾸지 않는다. 원본의 칸이 실제 장착과 어긋나면 [전투 연결](Edict_Drive_Expansion.md)의 차단 규칙에 걸리기 때문이다.

## 한국어 표시 이름

전역 설정의 선택값은 저장 형식에서 `AFTER_COMBAT`, `NEAREST_UNSEEN` 같은 식별자로 남는다. 화면에서는 [전역 옵션 상세안](../Design/HELLSCRIPT_Hunt_Edict_Global_Options.md)의 트리에 적힌 이름으로 읽도록 `EdictOptionLabels`에 표를 두었다. 같은 뜻의 값을 쓰는 항목은 표 하나를 공유한다. 등급별 회수·정리, 피해 유형별 회피, 일반·봉인 상자가 그렇다. 전설·세트 ID는 장비 화면에서 이미 보는 식별자이므로 그대로 표시한다. 분류 아홉 개에도 상세안의 이름을 붙였다.

표가 빠진 값이 생기지 않도록, 모든 전역 선택·복수 선택·순서 항목의 모든 값에 이름이 있는지 검사가 확인한다. 저장 형식은 바뀌지 않는다.

## 화면 구성

| 분류 | 내용 |
|---|---|
| 전역 설정 | 아홉 분류를 고르고 그 분류의 항목을 종류별 위젯으로 편집한다. 켜기·끄기 버튼, −/+ 단계 버튼, 순환 선택, 항목별 켜기·끄기의 복수 선택, ▲▼ 순서 이동, 직업 스킬 참조다. |
| 사용 스킬·순서 | 네 칸과 공통 공격 순서다. 미장착 스킬의 자리도 순서에 보관한다. |
| 스킬 설정 | 기본 공격과 직업 스킬 여섯 개 중 하나를 골라 핵심 옵션을 편집한다. 첫 옵션은 자동 사용이다. |

제목 아래에는 저장하지 않은 변경 수를 표시한다. 장비·장착 기준으로 비활성·대체·충돌 상태인 항목이 있으면 개수를 알리고, 해당 항목 아래에 사유와 현재 판단값을 함께 적는다. 이 사유는 기존 `HuntEdictV2Availability.Inspect`가 만든다.

저장은 [공유 화면](Edict_Share_Expansion.md)과 같은 `GameStore.SaveHeroEdict` 경로를 쓴다. 파일에 먼저 기록하고 성공했을 때만 메모리에 적용한다. 진행 중인 균열이 있으면 저장 뒤 `RefreshEdict`로 그 판이 새 원본을 읽게 한다. 편집기가 열리기 전에 준비한 사본을 그대로 쓰지 않기 위해서다.

변경이 남은 채 나가려 하면 저장하고 나가기, 저장하지 않고 나가기, 계속 편집하기 중에서 고른다. 바뀌는 값 목록을 함께 보여 준다. 공유 화면으로 넘어가는 것도 변경을 정리한 뒤에만 허용한다.

화면을 다시 그릴 때 스크롤 위치를 유지한다. 분류나 스킬을 바꿀 때만 맨 위로 돌아간다.

## 실제 앱 확인

이 프로젝트의 화면 검사 관례인 런타임 스모크를 `RuntimeEdictSmoke.cs`로 추가했다. 개발 빌드를 `-hellscriptEdictSmoke` 인자로 띄우면 격리된 저장 폴더에서 실제 버튼을 이름으로 찾아 누르고, 예외가 나면 종료 코드 1로 끝난다. `Builds/macOS-Edict/HELLSCRIPT.app`을 새로 빌드해 실행했고 첫 실행과 별도 프로세스 재시작이 모두 종료 코드 0으로 끝났다.

| 확인한 동작 | 결과 |
|---|---|
| 편집기 진입 | 성소 버튼으로 열리고 새 편집본이 ‘저장된 설정과 같습니다’로 읽힌다. |
| 전역 위젯 | 켜기·끄기, −/+ 단계, ▲▼ 순서, 스킬 참조 순환, 복수 선택 항목, 선택 순환이 각각 편집본의 값을 바꾸고 변경 수가 오른다. 편집 중 저장 파일과 계정은 바뀌지 않는다. |
| 사용 스킬·순서 | 공격 순서 이동이 첫 스킬을 한 칸 내리고, 칸을 누르면 해금한 스킬이나 빈칸으로만 바뀐다. |
| 스킬 설정 | 기본 공격의 자동 사용을 끄고 다음 선택지로 넘기면 비활성 사유가 화면에 나타난다. |
| 저장 | 파일이 먼저 바뀌고 영웅에 적용되며, 같은 폴더를 다시 읽은 저장본이 메모리와 일치한다. |
| 나가기·되돌리기 | 변경이 남은 채 나가면 세 가지 선택이 나오고, 계속 편집하기는 편집본을 지키며, 되돌리기는 저장본으로 돌아간다. |
| 공유 내보내기 | 복사한 코드가 `HED2.`로 시작하고 저장된 정규 원본으로 되읽힌다. |
| 공유 가져오기 | 바뀌는 값의 개수가 옵션 변경 1개에 잠긴 칸 정리 수를 더한 값과 같고, 비우는 칸이 안내되며, 적용 뒤 잠긴 스킬이 칸에 남지 않는다. 손상된 코드는 화면 문구로 보고된다. |
| 사용 스위치 | 켠 뒤 다시 읽은 저장본에도 켜져 있다. |
| 재시작 | 새 프로세스가 원본·스위치·계정을 그대로 읽고 편집기가 변경 없음으로 연다. |

1280×720, 720×1280, 640×360 창에서 스크린샷 12장을 남겼다. 하단 버튼이 안전 영역 안에 있는지도 각 캡처에서 확인했다. 편집기 캡처는 첫 항목 위치로 스크롤한 뒤 찍었지만 공유 화면 캡처는 화면 위쪽만 담겨, 가져오기 미리보기 문구는 스크린샷이 아니라 스모크의 문구 검사로만 확인된 상태다. `Artifacts/Validation/EdictEditorEvidence`에 스크린샷, 두 실행의 플레이어 로그, 확인 목록을 보존했다.

첫 두 번의 실행은 스모크 자체의 기대값 오류로 멈췄다. 전역 탭이 마지막에 본 분류를 기억하는데 스모크가 다른 분류의 항목을 찾은 것과, 레벨 1 캐릭터의 가져오기에서 잠긴 칸 정리가 바뀌는 값에 함께 세어지는 것을 스모크가 반영하지 않은 것이다. 둘 다 편집기의 의도된 동작이라 스모크만 고쳤다.

## 분류 선택 높이 조정 (2026-09-11)

첫 스모크의 스크린샷에서 가로 1280×720의 문제를 확인했다. 탭 한 줄, 안내 한 줄, 분류 세 줄이 위를 차지해 첫 항목은 접힌 영역 바로 아래에서 시작하고 첫 버튼의 윗부분 12픽셀만 보였다. 항목은 정상적으로 그려지고 스크롤로 닿았지만, 사용자가 화면을 열었을 때 편집할 것이 보이지 않는 상태였다.

분류 아홉 개를 세 줄 세 개에서 두 줄 다섯·네 개로 바꾸고 줄 높이를 54에서 44로, 탭 줄을 60에서 50으로, 안내 문구를 66에서 44로 낮췄다. 스킬 선택 줄도 44로 맞췄다. 분류 하나는 여전히 한 번 눌러 닿는다.

스모크에 스크롤하지 않은 상단 캡처를 추가해 다시 빌드하고 실행했다. 같은 1280×720에서 이제 첫 두 항목인 켜기·끄기 버튼과 −/+ 단계 줄이 접힌 영역 위에 온전히 보인다. 두 실행 모두 종료 코드 0이었고 버튼 이름이 바뀌지 않아 스모크는 수정 없이 통과했다.
