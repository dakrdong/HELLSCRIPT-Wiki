## Method

Every board of a mockup canvas (Claude Design) is rendered on a local server and every text, box and image rect is extracted in board pixels (`tools/ui_fidelity/measure.html`). The same values are extracted from the real window at the same size (a floating Unity Game View resized to 440×956 / 956×440 / 1600×900, `UiFidelityDump`) and compared with `compare.py` (text matched by string, boxes by IoU). Boards: portrait 440×956, phone landscape 956×440, PC 1600×900.

## Shared cause and shared fix

- Earlier windows used game units (`UiTheme.Scale`) with ad-hoc constants that followed the mockup "in proportion" only: on the same board text was about 2 px small and cells, tabs and gaps differed.
- `UiMock` (board class + `UiTheme.Scale / reference scale`) makes one canvas unit equal one mockup pixel on the reference board and scales the board proportionally elsewhere. A window uses the mockup CSS tokens (`--cell`, `--head`, `--fs` …) directly.
- `StorageSurface.shadowOutside` and an extended button chrome hang the box-shadow outside the box, so the layout rect equals the mockup border-box.
- `EquipmentSlotView.Paint(…, CellRecipe)` draws the inner slot layout (art 86% at 7%/5%, level .17, chips .14/.2/.22) proportionally; other windows keep their look without a recipe.
