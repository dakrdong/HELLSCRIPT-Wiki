# Hunyuan 몬스터 READY 자동 파이프라인

작성일: 2026-10-12 · [English](Hunyuan_Monster_Ready_Pipeline.en.md)

Tencent Hunyuan 텍스트-3D 원본 GLB 하나를 게임용 `HELLSCRIPT_HUNYUAN_READY_V1` 폴더로 바꾸는 명령 한 번짜리 도구다. 매일 약 20마리를 무인으로 처리하는 루틴이 쓴다. 같은 GLB와 인자는 같은 FBX·PNG 바이트를 만든다.

```
python3 tools/hunyuan_monster_ready.py --glb raw/N19.glb --id N19 --spec tools/monster_pipeline/monster_specs.json --out <작업폴더>
python3 tools/hunyuan_monster_install.py --id N19 --from <작업폴더> [--id ... --from ...] --clone <스크래치>/proj
```

종료 코드: 0 = QA 통과, 1 = QA 실패(다른 후보·설정으로 재시도), 2 = 실행 오류. 설치 도구는 QA 통과와 FBX SHA를 확인한 뒤 `Resources/World/HunyuanReady/<Characters|Bosses>/<ID>/`에 복사하고, Unity 클론에서 `HunyuanReadyBuilder.BuildFromCommandLine`과 EditMode `HunyuanMonsterReadyTests`를 실행한 뒤 Unity가 만든 `.meta`·`Model.prefab`·`LOD*_World.mat`을 되가져온다.

## 단계

1. **정규화:** GLB를 정점 병합으로 읽고, 땅 받침(가장 낮은 1.5%의 평평한 면적이 발목 높이 상자보다 넓음)을 잘라 낸 뒤 키·발 높이·엉덩이 원점을 맞춘다. Hunyuan은 정면을 지키지 않으므로(N01·N16 옆, N11·B04 뒤) 방향을 자동으로 고른다: 직립형은 몸통 띠의 어깨 축과 발끝(발바닥이 둘로 갈라질 때만), 사족형은 머리 쪽 부피, 거미형은 가장 높은 점(꼬리·배)을 뒤로.
2. **LOD:** 원본에서 각각 6000/3000/1500(보스 12000/6000/3000) 삼각형으로 축소한다. 구멍이 많은 원본은 단순 축소가 약 3000에서 멈추므로 키의 0.5% 복셀 리메시 뒤 축소한다(목표 +3%까지 허용). Smart UV(1.5 px 여백)와 Cycles 굽기로 A/C/N/ORM 512 px(보스 1024)를 만든다.
3. **리그:** 단면 분석으로 원형별 `Pivot_*`를 놓고, 열 가중치→2회 평활→영향 2개 정규화를 한다. 여러 변형(어깨 위치 3종 × 팔·옆구리 분리 0.10/0.16 H/없음, 소매형 팔 고정)을 같은 굽기 결과에 각각 입혀 아래 게이트를 계산하고, 통과하는 변형 중 움직이는 팔 → 가장 작은 최악 늘어남 순으로 고른다.
4. **QA:** 정면·측면·후면·게임 49° 시점과 걷기·윈드업·타격 자세의 대조 시트, `qa/qa.json`.

## 방패·받침·덩어리 (2026-10-12)

- **들고 있는 큰 방패:** 15–85% 단면에서 몸통이 아닌 길고 얇은 단면이 같은 자리·같은 길이로 0.3 H 넘게 이어지면 방패로 본다(비스듬한 칼·도끼·지팡이는 단면이 칼날을 따라 옮겨 가거나 짧다). 방패는 골격 분석·대칭·정면 판정에서 빼고, 가장 가까운 아래팔에 100% 가중치를 주어 한 덩어리로 움직인다. 몸에서 떨어진 방패 조각은 '떨어져 나감'으로 세지 않는다. 방패가 몸 앞이나 뒤에 뚜렷이 있으면 그쪽이 정면이다.
- **설계에 포함된 받침(흙더미, 바닥에 감긴 꼬리):** Blob·Worm·Serpent에서 0–10% 띠의 바닥 면적이 35–60% 띠의 1.3배 이상이면, 면적이 줄어드는 높이까지를 움직이지 않는 루트 뼈 `Pivot_Base`에 100% 묶는다. 받침과 몸 사이는 찢지 않고 섞는다.
- **덩어리(Blob):** ActorRig의 Blob처럼 엉덩이·배·머리(+실제로 찾은 팔)만 쓴다. 척추 사슬과 기본 팔 배치가 0.6 m 구더기 떼를 비틀어 찢었다.
- 삼각형 면적 증가(모든 동작의 극단 자세)도 LOD별로 기록한다. 정상 모델도 관절에서 면적이 늘어나 그 자체로는 구분력이 없었고, 파편화는 키 대비 늘어남 기준이 잡는다.

## 붙은 부위 처리

Hunyuan은 "팔다리를 몸에서 약간 떼라"는 프롬프트에도 손을 허벅지에, 팔 안쪽을 옆구리에, 무기 끝을 발에 붙여 낸다. 선형 블렌드 스키닝에서 이런 면은 팔을 155° 드는 윈드업 때 고무막처럼 늘어난다.

- 서로 먼 뼈(사슬 3단계 이상, 팔·다리 말단과 다른 사지, 좌우 팔)를 잇는 면은 찢고, 찢긴 복제 정점은 자기 쪽 가중치를 받는다.
- 어깨 관절에서 `flank`×키보다 먼 곳에서는 팔 정점이 몸통 가중치를, 몸통 정점이 팔 가중치를 갖지 않고 둘을 잇는 면을 찢는다. 관절 근처의 두 뼈 블렌드는 그대로 둔다. 그 결과 옆구리에 붙은 팔은 윈드업 때 옆구리를 끌지 않고 떨어진다.
- 찢긴 틈은 **부모-자식 관절(팔꿈치, 어깨 근처)** 에서만 게이트로 잰다. 관절에서 먼 틈(허벅지에서 떨어지는 손, 엉덩이에서 떨어지는 칼, 옆구리에서 떨어지는 팔)은 기존 절차형 모델의 강체 부품 사이 틈과 같은 자연스러운 분리로 본다.
- 소매가 로브에 붙어 팔을 떼면 몸의 8% 넘게 떨어져 나가는 경우(B02, B05)에만 팔을 몸통에 고정한 변형을 허용한다.
- 다리가 갈라지지 않는 로브는 엉덩이를 따르고, 허벅지·정강이는 발만 옮긴다.

## 게이트와 근거

| 게이트 | 기준 |
| --- | --- |
| LOD 삼각형 | 목표의 95–103% |
| UV 겹침 / 사용률 / 빈 텍스처 | < 3% / ≥ 20% / 최대 채널 > 0.03 |
| 가중치 | 빈 정점 0, 영향 ≤ 2, 열 가중치 실패 ≤ 25% |
| 최대 변 늘어남(Idle 걷기 8위상, Windup .8, Release .45) | 2 m 이상 키의 15%, 2 m 미만 0.30 m × √(키/2 m) |
| 관절 찢김 틈 | 위와 같음 |
| 몸에서 떨어져 나간 비율(로브 발 제외) | ≤ 8% |
| 오른쪽 뼈 +X, 뒤쪽 뼈 −Z 5 cm 뒤 | importer 축 계약 |
| 어깨·다리 대칭 | ≤ 키의 25% |
| 땅 받침 남음 | 평평한 바닥 면적 / 발목 상자 ≤ 1.0 |

**0.30 m 기준 재검토 (2026-10-12).** 같은 자세에서 도구의 ActorRig 이식으로 기존 READY 모델을 잰 결과다(Unity 실측 `HunyuanMonsterReadyTests`와 ±0.01 m 일치).

| 모델 | 원형 | 키 | 최대 | 99.9% | > 0.3 m 변 |
| --- | --- | --- | --- | --- | --- |
| N02 | Quadruped | 1.04 m | 0.144 | 0.102 | 0 |
| N12 | Hover | 2.0 m | 0.139 | 0.088 | 0 |
| BOSS03 | Quadruped | 4.3 m | 0.215 | 0.162 | 0 |

기존 선례에는 팔을 155° 드는 피부 스키닝 이족형이 없다(N12는 팔이 짧은 부유형, 절차형 art3d 모델은 강체 부품이라 늘어남이 0이고 관절에 틈이 생긴다). 그래서 0.30 m를 낮추거나 백분위 기준으로 바꾸지 않고 그대로 둔다. 바꾼 것은 두 가지다. (1) 키 비례: 같은 회전에서 변위는 크기에 비례하므로 2 m 이상은 키의 15%(4.5 m 보스 0.675 m)로 둔다. 처음에는 작은 쪽을 0.30 m로 고정했으나 0.6 m 구더기 떼(N21)가 0.19 m 파편으로 부서진 채 통과해, 2 m 미만은 키의 제곱근에 비례하게 줄였다(0.6 m → 0.164 m, 1.9 m → 0.292 m, 2026-10-12). 완전 비례(15%)는 N02(1.04 m)의 LOD1 실측 0.22 m와 1일차 N04(1.9 m, 0.285 m)를 근거 없이 떨어뜨려 쓰지 않았다. Unity `HunyuanMonsterReadyTests`는 기존 수용 모델의 안전망으로 이전 식(0.30 m × max(1, 키/2 m))을 유지한다. (2) 관절에서 먼 찢김 틈은 늘어남으로 세지 않는다(위 근거). 첫 실행에서 실패한 N03·N06·N08·N17은 이 처리 뒤 늘어남 0.18–0.26 m로 통과했고, 대조 시트의 윈드업 칸에서 옆구리 끌림 없이 팔이 올라가는 것을 확인했다.

## 루틴이 확인할 것

- `qa/contact_sheet.png`의 front 칸이 실제 정면인지(자동 방향은 QA가 검증하지 못한다). 틀리면 `--yaw`.
- 윈드업 칸에서 무기·팔이 몸에 붙어 따라오는지, 떨어져 날아가는 조각이 없는지.
- 손에서 멀리 매달린 소품(사슬 철퇴·향로·종)은 가까운 몸 부위를 따른다.
- 메모 `arms frozen`은 팔이 움직이지 않는 모델이다.
- C·ORM 맵은 셰이더가 읽지 않지만 Resources에 포함된다(텍스처 용량 약 2배).
- 미검증: 실기기, APK 크기, 프레임, Spider·Worm·Serpent의 실제 모델 다수.
