# HELLSCRIPT 장비 확장 개발 기록

작성일: 2026-09-08 · 상태: 장비 확장 1차 구현 및 검증. 전체 게임이나 D1–D6의 완료를 뜻하지 않는다.

## 적용한 변경

| 영역 | 구현 내용 |
|---|---|
| 장비 정의 | B01–B24, AF01–AF24, 개별 전설 15종, 세트 6종·24부위를 고유 ID로 정의했다. SWB/SAB/SMB는 추천안을 개발 기준으로 적용한 추가 범위다. |
| 접사 생성 | 접두·접미 배분, 부위 필터, 같은 그룹 중복 금지, 직업별 가중치, T1/T2/T3, 정수 품질 0–10000을 적용했다. 발·무기의 불가능한 접두 3개 배분은 추첨 전에 제외한다. |
| 값과 이름 | 평면형만 아이템 레벨로 성장한다. 실제 값은 소수 둘째 자리까지 저장하고 표시값과 분리한다. 일반 장비는 대표 접사로 이름을 만들며 전설·세트의 고유 이름은 유지한다. |
| 재설정·강화 | 원하는 접사 한 줄을 선택한 뒤 그 슬롯과 접두/접미 종류를 고정한다. 생성 당시 직업으로 재추첨하며 결과를 즉시 적용한다. 강화 재료의 실제 투자량과 80% 회수량을 저장한다. |
| 장비 보호 | 소유권·착용 레벨·직업을 검사한다. 장착·잠금·프리셋 참조 장비를 판매·분해·자동 교체에서 보호한다. 창고 이동 시 참조를 유지하고 상세 화면에서 참조를 해제할 수 있다. |
| 화면 | 장비 목록·필터, 옵션의 종류·티어·가능 범위, 교체 후 전체 능력치, 세트 개수와 해제 경고, 전설·세트 도감, 한 줄 재설정 화면을 추가했다. 장비 상세 하단에 장착 버튼을 고정했다. |
| 로컬 거래 | 장비 화면의 장착·잠금·강화·재설정·판매·분해·창고 이동·가방 확장 및 상점 제작은 계정 복사본에서 검증한 뒤 파일 저장에 성공할 때 반영한다. 요청 ID와 작업 내용을 기록해 같은 요청의 중복 적용을 막는다. |
| 저장 이관 | 계정 스키마를 2로 올렸다. 기존 장비의 ID·수치·강화·잠금·재설정 위치를 보존하고 변경 전 파일을 별도로 남긴다. 새 그룹 제한에 맞지 않는 기존 옵션은 레거시 값으로 보존한다. 손상된 원본과 백업, 더 새로운 저장 형식은 새 계정으로 덮어쓰지 않는다. |
| 이미지 | 내장 이미지 생성 도구로 베이스 장비 24종의 아이콘을 만들고 목록·상세 화면에 연결했다. PNG 생성 메타데이터의 `gpt-image` / `2.0` 표기를 확인했다. [프롬프트와 출처](Equipment_Atlas_Prompt.md)를 별도로 보존했다. |

## 전투에 연결한 범위

- 세트별로 서로 다른 장착 부위 수를 계산한다. SW 2부위와 SWB 2부위는 각각 2세트다.
- SWB는 도약 쿨타임 감소와 도약 적중 후 분쇄 추가 피해를 적용한다.
- SAB는 관통 비용 감소와 후퇴 후 잔영 사격을 적용한다. 잔영은 생성 시 공격값을 보존하고 그림자 화살 충전을 추가로 소비하지 않는다.
- SMB는 연쇄 비용 감소와 서리 폭발 후 연쇄 확장 충전 2개를 적용한다. 번개 패시브를 함께 사용하면 최대 7회이며, 단독 대상에게 자기 자신을 연속 방문하지 않는다.
- SW의 회오리 보행 충전, SA의 독 지속 효과 분리, SM의 연속 노출·표식·대상별 대기시간을 연결했다. 모든 경계 사례의 검증을 끝낸 상태는 아니다.
- LM04의 제한된 재방문, LW03과 LA01의 가산 피해 구간을 보완했다. 기존 실행 객체에만 있던 효과 타이머를 균열 저장 상태로 옮겼다.

도약은 여전히 즉시 판정 후 표현 위치를 보간하는 방식이다. 준비·체공·착지의 정식 상태 전이, 전체 전설·패시브의 발동 시점과 중첩 규격은 후속 작업이다. 이 기록을 전설 15종과 세트 효과 전체의 최종 검증으로 해석하지 않는다.

## 검증 증거

| 검사 | 결과·산출물 |
|---|---|
| Unity 자동 검사 | 31개 통과. `Artifacts/Validation/itemization-editmode.xml`과 같은 이름의 로그에 기록했다. 생성·경계값·세트 혼합·클래스 제한·재설정·이관·저장 실패·중복 요청·추가 세트 동작을 포함한다. |
| 추첨 분포 | 직업 3 × 부위 8 × 등급 4의 96조합을 각각 10만 번, 총 960만 개 생성했다. I30, 시드 820260908이다. 티어·배분·직업 보정·고유 장비 가중치가 6표준편차 + 2개 허용 범위를 통과했다. `itemization-distribution.csv`와 요약 파일을 보존했다. |
| 기존 값 보존 | 같은 아이템의 ID·9.3/12.7/4.1 옵션 값·강화 +5·잠금·재설정 슬롯과 투자 재료 620을 이관 후 재저장·재로딩해 확인했다. |
| 거래 실패 | 저장 경로에 쓰기 오류를 발생시켜 재화·장비·거래 원장이 변경되지 않는 것을 검사했다. 같은 요청의 재실행과 다른 내용으로의 재사용도 검사했다. |
| 실행 파일 | `itemization-build-mac.log`의 `HELLSCRIPT_BUILD Succeeded errors=0`을 기준으로 판정한다. 마지막 화면 수정 후 재빌드도 오류 0개로 성공했다. |
| 화면 | 실제 macOS 플레이어에서 장비 상세와 접미사 선택·확정·비용 차감·새 옵션 적용을 확인했다. 최종 실행에서도 통과했고, 능력치 비교·4세트 해제 안내·장착 버튼·재설정 화면을 캡처했다. `ItemizationScreens`와 `itemization-player.log`를 따른다. |

분포 검사는 아이템 생성 규칙을 검증한다. 여섯 빌드의 전투 밸런스·최적 장비·클리어율을 입증하는 검사는 아니다. 실제 실행 점검은 별도 `ItemizationSmokeSaveReviewed` 디렉터리에서 수행하며 플레이어의 원래 진행 기록을 시험 데이터로 바꾸지 않는다.

## 남은 작업과 다음 연결

1. **자동 생성 균열과 상자:** 후속 작업에서 6–8방 생성 명세·보행·상자와 예약 보상을 연결했다. 현재 상태와 별도 검증은 [자동 생성 균열 개발 기록](Rift_Expansion.md)을 따른다. 장비 생성기를 상자 보상의 공통 생성기로 사용한다.
2. **행동·스킬 판정:** 복합 조건 22종, 전체 행동 규칙, 이동·시전·착지, 보스 제압, 정예 속성, 플레이어용 훈련과 개발 훈련의 구분이 남아 있다.
3. **장비 효과와 빌드 검증:** 전설의 내부 대기시간 분리, 보호막 인스턴스·흡수 누적, 지속 피해와 전염, 모든 세트 경계 사례, 6빌드의 동일 시드·동일 투자량 비교를 마쳐야 한다. 세트가 4부위라는 이유로 무조건 더 좋은 것으로 안내하지 않는다.
4. **장비 화면 보완:** 빌드별 목표 장비 지정, 효과에 필요한 모든 스킬의 비활성 사유, 상한 초과분 표시, 상세 능력치 선택, 프리셋 장비의 일괄 복원이 남아 있다. 현재 프리셋 저장은 행동과 장비 참조를 보존하며 장비를 일괄 교체하지 않는다.
5. **정산·서비스:** 전투 보상·소탕·미실행 보상의 전체 거래 전환, 서버 권한·계정·교차 저장·서버 시각·결제, 보석 자료 확정과 실제 Android 기기 검증이 남아 있다. 현재 파일 원장은 한 기기의 로컬 개발용이다.

전체 요청은 계속 진행 중이다. 세부 완료 기준은 [후속 개발 상세 기획](../Design/HELLSCRIPT_Development_Expansion_Plan.md), [장비 상세안](../Design/HELLSCRIPT_Itemization_Detail.md), [균열 상세안](../Design/HELLSCRIPT_Rift_Exploration_Detail.md), [게임 완성 체크리스트](../Design/HELLSCRIPT_Gameplay_Completion_Checklist.md)를 유지한다.
