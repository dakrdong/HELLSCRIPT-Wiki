# 방치 사냥과 미접속 보급

갱신일: 2026-09-24 · [English](Idle_Offline_Supplies.en.md)

앱을 켜 둔 **방치 사냥**은 일반 전투와 같은 보상을 받는다. 앱을 떠난 동안의 보상은 **미접속 보급**으로 부르며, 골드와 강화석만 실제 사냥 수급 속도의 **1/20**로 지급한다. 둘은 같은 시간을 중복 정산하지 않는다.

## 실제 방치 사냥

`GameController`의 기존 0.05초 `CombatSimulation`을 계속 실행한다. 이동·탐색·스킬·물약·상자·전리품 회수·보스전·레벨업을 생략하지 않는다. 절전 화면은 표시만 줄인다. 진행 중인 판의 실제 상태를 그대로 보여 주는 잠깐 보기와 10초 후 복귀도 유지한다.

저장한 사냥칙령의 반복 여부, 성공 시 동일/다음 단계, 실패 시 동일/이전 단계/중단, 실패 한도, 횟수·시간·골드·장비·단계 목표를 `RepeatHunt`가 적용한다. 성공 보상과 결과를 저장한 후 가방 정리·물약 출전 준비·결과 대기를 거쳐 다음 단계에 입장한다. 조건이 충족되지 않으면 이유를 표시하고 멈춘다. 방치 진입 자체가 반복 설정을 켜거나 가방 정책을 바꾸지는 않는다.

PC에서는 창의 포커스를 잃어도 실행한다. 기기 절전이나 OS의 앱 실행 중단을 방치 사냥으로 계산하지 않는다. 앱 전환·중단은 현재 전투를 보존하고, 복귀 후 사용자가 재개한다. 방치 중 출석 날짜가 바뀌어도 출석 팝업을 자동으로 띄워 사냥을 멈추지 않는다.

## 미접속 보급 수치

균열 1단계 클리어 후 계정에 열린다. 계정 전체에서 **마지막으로 정상 클리어한 캐릭터와 단계**를 기록한다. 다른 캐릭터로 바꾸거나 더 높은 단계를 선택하거나 실패해도 기준은 바뀌지 않는다. 훈련·소탕·보스 처치 후 전리품을 포기한 종료도 기준을 갱신하지 않는다.

| 항목 | 적용값 |
| --- | --- |
| 기준 골드 | 마지막 정상 클리어에서 회수한 필드 골드. 적·보스·보물 고블린의 회수분을 포함한다. |
| 기준 강화석 | 같은 판에서 실제 회수한 강화석 |
| 기준 시간 | `max(전투 틱 시간, 실제 전투 경과 시간) + max(5초, 설정한 결과 대기시간)` |
| 지급률 | 위 기준 수급 속도의 5% |
| 누적 한도 | 접속 사이 최대 12시간 |
| 정산 기준 | 마지막 저장 시각과 콘텐츠 개방 시각 중 늦은 시각부터 접속 시각까지 |
| 소수점 | 1개 미만의 골드·강화석은 다음 정산으로 이월 |
| 지급 제외 | 초회 보상, 일반 상자 및 보상 상자, 판매·분해 수익, 일반 재료, 장비, 보석, 룬, 코어, 심연 주화, 경험치 |

`지급량 = floor(이전 소수점 잔액 + 기준 획득량 × 인정 미접속 초 / (기준 시간 × 20))`

예를 들어 한 판의 기준 시간이 200초이고 골드 2,000·강화석 20을 회수했다면, 실제 기준 수급은 시간당 골드 36,000·강화석 360이다. 미접속 1시간에는 **골드 1,800·강화석 18**, 12시간에는 **골드 21,600·강화석 216**을 지급한다. 12시간 보급은 같은 기준 사냥 36분에 해당한다. 같은 조건으로 2시간 동안 성공적으로 반복 사냥했을 때 수입의 30%이며, 실제 실패·정리 시간이 포함되면 비교 비율은 달라진다. 장비·보석·경험치 성장에는 적용되지 않는다.

단계만으로 모든 캐릭터에게 같은 시급을 주지 않는다. 실제 처치 수·회수 정책·골드 획득 보너스·사냥 속도가 달라지므로, 새 정상 클리어마다 수치가 갱신된다. 고블린 같은 확률 사건이 있는 마지막 판은 그 결과가 다음 보급 기준에 반영된다. 속도만 지나치게 높아지는 것을 막기 위해 다음 판 대기는 최소 5초로 잡는다.

### 이전 저장의 전환

저장 스키마 14부터 전용 기록을 보존한다. 이전 저장에는 완료된 판의 재화 원장이 없으므로 마지막 정상 클리어 기록의 캐릭터·단계를 우선 사용한다. 그 기록도 없으면 선택 캐릭터의 최고 클리어를 쓴다. 다음 정상 클리어까지 화면에 추정 기준임을 표시한다.

이전 저장의 임시 기준은 일반/정예 적의 보스 게이지 100점에 해당하는 기본 골드와 보스 골드, 현재 보스 강화석 공식을 사용한다. 1~5단계는 게이지 2배를 반영하고 105초, 6단계 이상은 185초를 기준으로 한다. 기록된 실제 클리어 시간이 더 길면 그 시간을 사용한다. 다음 표는 **이전 저장의 전환용 기본값**이며 새 플레이의 고정 보상표가 아니다.

## 저장과 화면

정산액·시각·소수점 잔액·지급 영수증을 한 거래로 저장한다. 저장 실패 시 정산 구간을 고정하고 다른 거래가 이를 건너뛰지 못하게 한다. 저장 시각은 과거로 되돌리지 않는다. 재접속·중복 정산·지급 창을 여러 번 열거나 확인하는 행동은 추가 보상을 만들지 않는다. 재화가 정수 보유 한도에 도달한 경우 한도를 넘는 정수 보상은 버리며, 계정을 저장 실패 상태에 가두지 않는다.

마을에서도 3초 간격으로 실행 중임을 저장하므로 마을에서 켜 둔 시간을 미접속으로 바꾸지 않는다. 정상 종료와 앱 중단 시에도 저장한다. 강제 종료는 마지막 성공한 체크포인트 기준이며 최대 체크포인트 간격의 오차가 남는다.

복귀 시 `미접속 보급` 창에 이미 지급된 골드·강화석, 정산 시간과 단계, 현재 시간당 수급량을 표시한다. 성소 메뉴에서도 다시 열 수 있다. `OfflineSuppliesWindow`는 공통 `ContentWindowView`, 테마·폰트·스크롤·고정 확인 영역을 사용하며 화면은 지급하지 않는다. 확인은 `GameStore`의 영수증 확인 거래만 실행한다.

## 서버 검증 모듈과 운영 경계

현재 게임에는 실제 계정 인증·백엔드·서버 시계가 없다. 로컬 개발 빌드는 기기 시각과 로컬 저장을 사용하므로 파일이나 기기 시각 변조를 막는 운영 보안으로 보지 않는다.

`AuthoritativeRiftVerifier`는 Unity Editor 검사 및 `UNITY_SERVER` 빌드에서만 포함되는 서버용 모듈이다. 호스트가 인증한 계정의 **서버가 보유한 입장 완료 스냅샷**에서 실제 `CombatSimulation`을 재실행한다. 요청에는 임대 식별자·균열 ID·순번·누적 틱만 있고, 피해·보상·장비·단계·시드·시각을 보고하는 필드는 없다.

- 서버 경과 시간보다 많은 전투 틱, 다른 계정·임대·균열, 순번 누락, 내용이 달라진 재전송을 거부한다.
- 요청당 최대 200틱, 마지막 승인 이후 30초의 임대 유효기간을 적용한다. 만료 구간을 전투로 몰아서 계산하지 않는다.
- 계정·보상·틱 커서·순번을 `IHuntAuthorityRepository.CompareExchange`로 함께 저장한다. 오래된 작업자와 저장 실패는 결과를 채택하지 않는다.
- 정상 종료는 같은 `RepeatHunt`로 다음 단계와 중단 조건을 계산한다. 보상과 미접속 기준은 서버 재실행 결과에서만 나온다.

**아직 배포되지 않은 부분:** 호스트의 인증, 계정별 단일 임대 발급·인계, 서버 시드/입장 발급, 실제 DB의 원자적 저장, 네트워크 전송, 포탈 정리·물약·새 균열 입장 명령 연결, 앱 이탈/재접속의 서버 시각 정산. 이 모듈을 로컬 클라이언트 안에서 실행한다고 치팅이 막히지는 않는다. 운영 연결 시에는 클라이언트 저장 업로드를 계정 원본으로 받지 않아야 한다. 서버 시간으로 같은 `OfflineSupplies` 계산을 수행하고 온라인 임대 종료 시각과 겹치지 않는 구간만 지급해야 한다.

## 검증

Unity 6000.6.0f1에서 관련 Edit Mode 검사 **276개가 통과**했다. 본 검사 179개, 빌드·프리셋 저장 회귀 검사 45개, 보상·종료 회귀 검사 52개를 합한 수다. 보급·서버 재실행, 반복·시계·개방·피로도·출석·코어 제작을 포함한다. 서버 재실행은 10초마다 저장·재시작해도 일반 전투와 처치 43회, 골드 2,288, 강화석 12, 경험치·클리어·보상 난수 결과가 같았다. 저장 실패, 중복·변조 요청, 다른 계정, 시간 가속, 임대 만료와 시계 역행을 검사했다.

macOS 개발 플레이어에서 새 전사와 시작 장비로 **실제 1배속 224.33초(3분 44초)** 동안 균열 1→2단계를 연속 클리어했다. 실패 0회, 레벨 1→6, 골드 4,704·강화석 26·일반 재료 30을 실제 획득했다. 장비 자동 장착이나 성장 재화 주입은 하지 않았다. 칙령의 `NEXT`와 2회 종료, 방치 중 출석 날짜 전환을 확인했다. 사냥 중의 출석 보상은 수령하지 않았다.

마지막 2단계의 기준은 골드 1,250·강화석 14, 실제 전투 약 114.85초와 결과 대기 5초를 더한 **119.85초**였다. 미접속 1시간을 주입한 검사에서 **골드 1,877·강화석 21**, 잔액은 골드 약 0.34668·강화석 약 0.02628로 계산됐다. OS 시각을 바꾼 검사가 아니며, 지급 창 확인·재열기·저장 재접속에서 중복 지급이 없었다.

세로 440×956, 가로 956×440, PC 1600×900·1600×1000·2100×900에서 한국어·영어, 100%·150% 글자 크기를 조합한 **20개 화면**의 스크롤·문구 높이·고정 확인 버튼·실제 UI 포인터 이벤트를 확인했다. 캡처의 영어 `hours credited`는 이후 더 짧은 `h credited`로 문구만 다듬었다. 게임 동작과 배치는 같다. 모바일 실기기의 절전·발열·배터리 검증은 별도 범위다.

1~1000단계 기획 모델의 기존 미접속 일반 재료 수급도 제거하고, 제안된 반복 필드 골드·강화석 수급의 5%로 다시 계산했다. 계산 검사 23개가 통과했으며 180일·하루 2시간 가정에서 모델의 골드·일반 재료·강화석 부족 구간은 없다. 이는 기획 모델 검증이며 실제 1000단계 전투 완료 증거는 아니다.
