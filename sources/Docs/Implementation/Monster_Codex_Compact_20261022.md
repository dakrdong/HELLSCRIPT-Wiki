# 몬스터 도감 모서리·세로 상세 압축 (2026-10-22)

[English](Monster_Codex_Compact_20261022.en.md) · 시안: 캔버스 「몬스터 도감 · 캐주얼」(Detail 보드 `c.*` 값, 보드 「세로 · 짧은 화면 704」 2장 추가)

## 사용자 지적과 원인

1. **목록 타일 모서리** — 시안은 CSS `overflow:hidden`으로 그림을 둥근 안쪽 모서리에 맞춰 잘랐지만 게임은 사각 `RawImage`를 둥근 테두리 위에 그대로 올려 모서리가 테두리를 덮었다. 시안은 바꾸지 않았다(이미 맞음).
2. **세로 상세가 불필요하게 크고 스크롤됨** — 신원 카드 260 + 통계 카드 75.6×2 + 방어 + 기술 최소 200이 쌓여 높이 704 화면(실기기 세로 비율 0.625)에서 넘쳤다. 페이지 콘텐츠도 본문보다 56 크게 잡혀 길이가 충분해도 스크롤이 생겼다.
3. **그림 아래가 잘림** — 정사각 그림을 카드 폭 그대로 `cover`로 깔고 아래 62%를 크림 그라데이션으로 덮었다.

## 검증 범위와 한계

- EditMode `MonsterCodexWindowTests` 34개 통과(목록 모서리 클립, 세로 440×956·704·640·540 한/영의 일반·정예·보스 상세에서 "기술 패널이 최소 120을 못 지킬 때만 페이지 스크롤"·그림 전체·클립 안 배치·글자 폭, 가장 넓은 영문 통계 메모, 가로 신원 카드). 실제 보드 크기는 화면에 따라 달라 테스트는 `MonsterCodexWindow.fitOverride`(비공개 정적, 게임에서는 null)로 440 폭 보드를 고정한다. 전체 Edit Mode는 실행하지 않았다.
- 배치 모드 렌더로 실제 창을 440×704(한/영)·956×440에서 캡처해 눈으로 확인했다(목록 모서리, 일반·정예·보스 상세, 긴 영문 이름). 캡처용 임시 실행기는 커밋하지 않았고 PNG는 보존하지 않았다.
- 계획 단계의 제안 중 세로 `Fit` 배율을 440 폭에 고정하는 변경은 요청 범위 밖이라 채택하지 않았다.
- 마스크는 카드마다 스텐실 한 단계가 추가된다(136장). 렌더 비용은 **측정하지 않았다**. 실기기·성능은 별도 확인이 필요하다.
- 마지막 슬라이더 `최고 N`과 끝값 숫자가 겹치는 기존 문제(최고 클리어가 큰 계정)는 이번 범위가 아니다.
