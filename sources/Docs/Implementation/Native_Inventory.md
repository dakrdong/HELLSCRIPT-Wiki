# HELLSCRIPT 가방 UI와 두 무기 슬롯

작성일: 2026-09-21

수정일: 2026-09-22

## 적용 범위

플레이 화면의 캐릭터 버튼에서 HTML 시안의 가방을 Unity uGUI로 연다. 화면은 실제 `GameStore` 계정과 아이템을 사용한다. 가방에서는 장착·해제, 장착 비교, 전체 능력치, 잠금, 선택 분해와 일괄 분해를 처리한다. 창고, 보석 관리, 룬 보드, 판매는 각 관리 화면에서 처리한다.

기존 버튼 연결 이후 남아 있던 디자인과 장착 체계를 이식했다. HTML 시안은 시각·상호작용 참고 자료이며 예시 아이템이나 브라우저 저장소를 실제 계정 데이터로 사용하지 않는다. 계정 저장은 프로젝트의 기존 로컬 개발 어댑터를 따른다.

## 화면과 입력

| 항목 | 가로 | 세로 |
| --- | --- | --- |
| 기준 비율과 논리 크기 | 16:9, 800×450 | 9:16, 405×720 |
| 헤더 | 높이 34 | 높이 34 |
| 캐릭터 영역 | 왼쪽 폭 258 | 위쪽 높이 230 |
| 소지품 열 | 8열 | 6열 |
| 장착·소지품 슬롯 | 모두 54×54 | 모두 52×52 |

기기 안전 영역 안에 같은 비율로 배치한다. 회전할 때만 가로·세로 배치를 다시 정하고, 선택·필터·잠금·비교·분해에 따라 창 크기를 바꾸지 않는다. 안내 문구와 선택 분해 버튼은 처음부터 자리를 확보한다. 모든 팝업은 가방 프레임 안에 있고, 긴 본문은 내부에서 스크롤한다.

장착 부위 `허리`의 표시 이름은 `벨트`로 통일한다. 소지품의 등급·정렬 버튼을 누르면 고정 크기의 목록이 위에 겹쳐 열린다. 등급은 체크박스로 하나 이상 선택하며, 선택한 등급 중 하나에 해당하는 아이템을 표시한다. `모든 등급`으로 전체 선택을 복원할 수 있다. 정렬은 위치순·최근순·오래된 순·등급순·레벨순 중 하나를 고르면 적용하고 목록을 닫는다. `새 아이템`·`각성` 필터 버튼은 표시하지 않는다. 소지품 표시 필터는 상점·분해의 캐릭터별 자동 선택 설정과 독립적이다.

소지품 아이템을 캐릭터 영역이나 해당 장착 칸으로 끌어 놓으면 장착한다. 상세창의 장착 버튼도 같은 거래를 사용한다. 두 위치를 모두 사용할 수 있고 이미 둘 다 차 있다면 비교창에서 교체할 손 또는 반지를 선택한다. 장착 중인 아이템은 소지품에서 빠지고 장착 칸에만 표시된다. 양손 장비의 연결 칸은 별도 아이템이 아니다.

마우스는 일반 드래그로 장착한다. 터치에서 바로 밀면 목록을 스크롤하고, 0.18초 이상 누른 뒤 끌면 아이템을 옮긴다. 분해 선택 중이거나 분해 미리보기 안에서는 슬롯 위를 밀어도 목록이 스크롤된다. 드래그 그림은 처음 누른 위치의 오프셋을 유지한다.

## 두 무기 슬롯

사용자가 정한 HELLSCRIPT의 두 슬롯 규칙을 따른다. Diablo IV의 야만용사 무기고 전체나 도적의 양손 활 체계를 그대로 복제한 것은 아니다.

| 직업 | 주무기 | 보조 위치 |
| --- | --- | --- |
| 전사 | 한손 도검·도끼 | 한손 도검·도끼 또는 방패 |
| 전사 | 양손 대검 | 같은 아이템이 두 칸을 점유 |
| 마법사 | 한손 지팡이 | 오브·마법 스크롤 또는 방패 |
| 마법사 | 양손 지팡이 | 같은 아이템이 두 칸을 점유 |
| 궁수 | 활 | 화살 |
| 궁수 | 단검 | 방패 |
| 궁수 | 양손 쇠뇌 | 같은 아이템이 두 칸을 점유 |

주무기를 교체하면 호환되지 않는 보조 장비도 소지품으로 돌아간다. 양손 장비를 장착하면 기존 두 손의 장비가 돌아간다. 소지품 공간이 부족하면 거래 전체를 거절하고 기존 장비를 유지한다. 주무기 해제 시에도 그 무기가 필요한 오브·스크롤·화살을 함께 해제한다. 잠금은 장착을 막지 않는다.

기존 B01~B24는 ID를 유지한다. B25 한손 지팡이, B26 오브, B27 마법 스크롤, B28 방패, B29 화살, B30 단검을 실제 아이템 베이스에 추가한다. 일반·마법·레어 생성 후보에 포함되며, 기존 전설 무기 효과가 임의의 보조 장비에 붙지 않도록 보조 장비는 기존 전설 생성 후보에서 제외한다. 새 보조 아이콘은 기존 벡터 아이콘 체계를 사용한다.

공격 무기가 두 개면 기본 공격력과 기본 공격속도는 두 무기의 평균을 사용한다. 오브·스크롤·화살의 기본 수치는 공격 기준에 더하고, 방패의 기본 수치는 방어도에 더한다. 아이템별 접사·보석·특수 효과는 각 인스턴스를 한 번씩 읽는다. 양손 장비를 두 번 더하지 않는다. 무기 숙련은 주무기를 기준으로 선택한다.

## 능력치와 비교

전체 능력치는 `StatCatalog`의 **57개**를 모두 표시한다. 0인 수치도 숨기지 않는다. 아직 게임에서 사용하는 곳이 없는 능력치는 그 이유를 함께 표시한다. 수치의 계산과 단위는 기존 `HeroStats.Sheet`와 `FormatSheet`를 사용한다.

소지품 반지를 비교하면 장착된 왼쪽·오른쪽 반지를 함께 보여 준다. 한쪽이 비어 있으면 장착된 반지만 표시한다. 각 위치에 교체했을 때의 실제 전체 능력치 변화와 소지품으로 돌아갈 장비를 계산한다. 현재 장착한 아이템의 상세창에는 장착 비교 버튼을 표시하지 않는다.

비교는 [장비 비교 공통 규칙](../Design/Equipment_Comparison_Rules.md)을 따른다. **왼쪽은 장착 중, 오른쪽은 선택한 장비**다. 후보의 수치 뒤에 증감을 붙이고, 후보에 없는 기존 속성은 아래의 `장착 시 사라지는 속성`에 표시한다. 두 반지가 장착돼 있으면 두 착용품과 후보를 함께 표시하며, 위쪽에서 왼쪽/오른쪽 교체 기준을 고른다. 창 크기를 유지하면서 각 카드 본문만 스크롤한다. 맨 아래 장착 버튼은 실제 교체 위치를 명시한다.

## 잠금과 분해

상세창에서 잠금을 켜거나 끌 수 있다. 잠긴 아이템은 분해 선택 화면과 일괄 분해 대상에서 제외한다. 장착 중이거나 보석이 들어 있거나 현재 설정·프리셋에서 참조하는 장비의 기존 보호 조건도 유지한다.

`분해`를 누르면 슬롯 오른쪽 위에 선택 상자가 표시되고 버튼은 `분해 취소`로 바뀐다. 하나 이상 고르면 소지품 오른쪽 아래 고정 위치에 `선택 분해`가 나타난다. 확인창에는 선택한 아이템을 슬롯으로 보여 주고, 승인한 뒤에만 분해한다. 취소하면 선택 표시와 선택 상태를 없앤다.

일괄 분해의 최상단에는 **상점과 공유하는 자동 선택 설정**과 설정 버튼을 표시한다. `Hero.equipmentShop.auto`의 등급·19종 장비 분류·능력치 제외 조건을 상점과 분해가 함께 읽고 수정한다. `ShopAutoSelect.MatchesFilters`는 공통 판정을 담당하고, 판매·분해 가능 여부는 각 거래에서 다시 확인한다. 예전 `AccountSave.salvage`는 저장 호환성을 위해 남기되 판정에 사용하거나 상점 설정에 덮어쓰지 않는다.

분해 선택 모드의 **자동 선택**은 체크만 갱신한다. 설정창이나 승인창을 자동으로 열지 않고 아이템을 소비하지 않는다. **자동 선택 설정**은 상점과 같은 초안 편집 화면을 사용한다. 명시적으로 저장하면 양쪽에 적용되고 닫으면 취소된다. 같은 캐릭터에서 공유하며 다른 캐릭터의 설정은 유지한다. 이후 `선택 분해` 또는 `일괄 분해` 확인창에서 승인해야 실제 분해한다. 대상 영역은 빈 목록에서도 세 줄이며, 네 번째 줄부터 내부 스크롤한다. 아이템을 누르면 작은 정보창이 열린다.

분해 미리보기는 인스턴스와 수치를 고정한다. 승인 전에 잠금·소유권·보석·프리셋·수치가 바뀌면 전체 거래를 거절한다. 같은 승인 요청을 반복해도 보상을 중복 지급하지 않는다. 전설·세트는 해당 부위 코어를, 나머지는 기존 등급별 재료와 강화 투자 환급을 받는다.

## 저장과 기존 기능 연결

장착 위치는 `Item.equipIndex`로 구분한다. 무기·반지를 제외한 부위는 항상 0이다. 프리셋은 아이템 ID와 나란히 위치를 저장하므로 나중에 손이나 반지를 바꿔 장착해도 원래 위치로 복원한다. 예전 프리셋의 위치 목록이 없으면 호환 가능한 빈 위치에 배치한다. 훈련 장비 복사본과 비교 기록도 최대 10개 인스턴스를 지원한다.

저장 스키마는 7, 아이템 콘텐츠 버전은 5다. 기존 아이템 ID·강화·접사·잠금·획득 기록을 유지한다. 화면을 읽거나 다시 그리는 동작으로 아이템을 생성하지 않는다. 상세 열람과 비교는 기존 읽음 표시와 첫 플레이 안내 기록에 연결한다.

가방이 열려 있는 동안 게임 시간은 기존 공통 UI 게이트로 정지한다. 저장된 일시정지 값과 마을 위치를 유지하고 닫으면 원래 화면으로 돌아간다. 전투 중 장비를 바꾸면 장비 능력치만 다시 계산하며 쿨타임을 초기화하거나 생명력을 회복하지 않는다. 낮아진 생명력·자원 상한은 거래에 함께 저장한다.

## 구현 소유자

- `GameUI.PlayInventory`가 플레이 버튼과 닫기 복귀를 소유한다.
- `InventoryWindow`와 세 partial 파일이 고정 배치·상세·분해·입력을 담당한다.
- `EquipmentSlots`가 두 손·두 반지의 장착 계획과 검증을 담당한다.
- `InventoryEquipment`가 실제 계정 거래, 분해 미리보기와 전투 능력치 갱신을 담당한다.
- 씬·프리팹을 복제하지 않고 기존 런타임 UI 생성 경로를 사용한다.

### 2026-09-21 최초 이식

2026-09-21, Unity 6000.6.0f1에서 확인했다.

- 관련 Edit Mode **297개 통과, 실패 0개, 건너뜀 0개**: 두 손·두 반지, 장착 교체와 용량, 저장 실패 시 원상태 유지, 잠금·분해 중복 승인, 품질 계산, 창고·프리셋·훈련·상점·갬블·번역을 검사했다. [검사 원본](NativeInventoryEvidence/editmode.xml)
- 전체 회귀 검사는 수정 전 **2,807개 중 2,803개 통과, 4개 실패**였다. 무기 베이스와 버전 확장으로 오래된 검사 데이터가 된 세 항목은 수정 후 관련 검사에서 통과했다. 남은 한 항목은 기존 타이틀·캐릭터 선택의 네 Graphic 클래스에 `CanvasRenderer` 요구 선언이 없는 문제다. 해당 소스는 이번 작업에서 변경하지 않았다. 최종 전체 회귀 통과로 보고하지 않는다. [수정 전 원본](NativeInventoryEvidence/regression-before-final-fixes.xml)
- macOS 개발 실행본에서 한국어·영어, 가로 1600×900·세로 810×1440, 고정 배치, 57개 능력치 스크롤, 잠금, 선택·일괄 분해, 필터 재접속 저장, 두 반지·한 반지 비교, 상세 장착·해제, 드래그 오프셋과 장착, 빠른 터치 스크롤·길게 누른 드래그, 전투 정지·닫기 복귀를 확인했다. 실제 uGUI 핸들러와 레이캐스트, 격리된 실제 계정 저장을 사용했다. [실행 결과](NativeInventoryEvidence/runtime.txt)
- 현재 프로젝트의 Unity Editor에서도 플레이 씬의 캐릭터 버튼을 레이캐스트로 찾아 클릭 이벤트를 전달했다. 가방 열기와 광장 복귀를 확인했고, 테스트를 위해 시작한 Play Mode를 종료했다. Console 오류는 0개였다.
