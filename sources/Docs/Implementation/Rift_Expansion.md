# HELLSCRIPT 자동 생성 균열 개발 기록

작성일: 2026-09-08 · 상태: 생성 균열과 상자 핵심 구현·검증. 전체 D2 또는 전체 게임의 완료를 뜻하지 않는다.

이 문서는 지도 버전 1을 검증한 시점의 기록이다. 이후 추가한 성소·저주 상자, 상호작용 몸체의 통행 판정, 적의 마지막 발견 위치와 지도 버전 2의 검증은 [필드 확장 개발 기록](Field_Expansion.md)을 따른다. 아래 수치와 남은 작업 목록은 당시 기준으로 보존한다.

## 적용한 범위

| 영역 | 구현 내용 |
|---|---|
| 지도 명세 | 2테마·방 템플릿 12종, 6–8방, 90도 회전, 템플릿별 장애물 변형 3종을 정의했다. 기본 고리와 사용 가능한 출입구의 추가 연결 0–2개를 생성한다. 같은 템플릿의 중복 인스턴스는 회전·변형을 다르게 선택한다. |
| 연결과 보행 | 실제 출입구에서 폭 4m의 통로를 연결한다. 방 사이를 통과하지 않도록 통로 경로를 구하고, 보행·시야·투사체·착지를 별도 판정한다. 영웅 반지름은 0.45m, 보스는 1.2m다. 시뮬레이션의 위치와 표현용 모델을 분리한다. |
| 난수와 복원 | 지도 구조·장식·무리·전투·보상 흐름을 분리하고, 시드뿐 아니라 전체 방·통로·장애물·배치·예약 보상을 저장한다. 이전 고정 8방의 진행 기록은 레거시 지도에서 재개한다. 새 형식으로 조용히 다시 생성하지 않는다. |
| 적 배치 | 일반 110명과 정예 8명으로 기본 150점을 구성한다. 시작방에는 일반 10명, 보스 방에는 외곽 일반 8명을 배치한다. 시작점에서 적까지 10m 이상을 확보하고 정예는 방당 최대 2명이다. 무리 원형·정예 특성 조합과 연결 짝을 저장한다. |
| 보스 | 영웅의 직전 보스를 제외해 추첨한다. 미리 비워 둔 광장의 중심과 사방 6m 후보를 검사해 게이지 100에서 한 번 등장한다. 공간 오류 때 진행 상태와 보상을 보존하고 자동 반복을 멈춘다. |
| 자동 탐색 | 방 진입과 관찰 지점을 기록하고, 선택한 출구로 향하는 경로를 유지한다. 좌·우 벽, 가까운 미탐색 지점, 적 추적 설정을 제공한다. 접근이 막히면 경로를 다시 구하고 목표를 일시 보류한다. |
| 상자 | 방 수에 따라 4/5/6개를 배치한다. 일반 CH01은 게이지 30, 봉인 CH02는 게이지 70과 경비 무리 처치 후 열린다. 시작방에서 그래프 두 방 이상·거리 45m 이상인 위치에 분산한다. 보상 예산과 장비 2개는 입장 때 고정한다. |
| 자동 개봉 | 안전할 때 접근하고 1/1.5전투 초 동안 연다. 피격·위험·거리 이탈은 개봉을 중단하고 진행률을 초기화한다. 일시정지와 포탈에서는 진행률을 보존한다. 종류별 허용·최대 접근 거리·보스 등장 후 회수를 설정할 수 있다. |
| 지급과 가방 | 상자 지급은 같은 요청 ID로 재화·드롭·개봉 상태를 함께 저장한 뒤 적용한다. 저장 실패는 재화나 상자를 소비하지 않는다. 가방이 차면 발생한 드롭을 유지하고 기존 포탈·교체·무시 정책에 맡긴다. |
| 표현과 결과 | 생성 명세에서 바닥·벽·장애물을 만들고, 상자는 몸체와 회전 뚜껑으로 표현한다. 미니맵·확대 지도에 발견한 방과 상자·보스 방향을 표시한다. 결과와 최근 기록에 개봉 수를 남긴다. 보스 처치 후 미개봉 상자를 무료로 열지 않는다. |
| 바닥 이미지 | 내장 이미지 생성기로 석재 바닥을 만들고 실제 방 바닥에 적용했다. PNG의 `gpt-image` / `2.0` 메타데이터를 확인했으며, [원본·최종 프롬프트·가져오기 설정](Rift_Stone_Prompt.md)을 보존했다. |

기존 순수 C# 전투 모델이 저장과 재현의 기준이므로 같은 모델에서 길을 찾는다. NavMesh 오브젝트나 화면 프레임의 위치를 저장의 기준으로 바꾸지 않았다. 시야와 통과 판정은 짧은 구간 표본만으로 판단하지 않고 선분과 실제 바닥·장애물의 교차를 검사한다.

상자 지급의 원자성은 현재 한 기기의 로컬 파일 저장 범위다. 온라인 세션 소유권, 서버 비공개 보상 키, 다른 기기의 중복 요청 조정, 서버 시각은 후속 서비스 구현이다. 전투 전체의 재화·경험치·보스 보상이 모두 서버 거래로 전환되었다고 표시하지 않는다.

## 발견하고 수정한 문제

- 가방 포탈을 시전하는 동안 다음 탐색 목표로 걸어가 드롭 획득 거리에서 벗어나는 문제를 수정했다.
- 장애물 모서리에서 선분 표본 사이의 좁은 경계를 놓칠 수 있어 연속 선분 검사와 최종 도착점 검사를 적용했다.
- 0.6초마다 출구 목표를 다시 평가하면서 이미 방문한 방을 지날 때 되돌아가는 문제를 수정했다. 0.6초는 유효 경로를 폐기하는 기한으로 사용하지 않는다.
- 목표 적과 유지하려는 거리의 위치가 장애물 안에 있으면 멈추던 문제를 수정했다. 같은 적을 공격할 수 있고 실제로 접근 가능한 주변 위치를 선택한다.
- 저장 복사본에서 비어 있는 예약 장비가 빈 Item 객체로 복원되는 경우를 정규화했다. 미래 지도·장비 형식은 원본을 보존하고 불러오기를 중단한다.
- 연속된 시드와 직전 보스 제외 조건을 함께 적용할 때 나타나는 추첨 편향을 확인했다. 보스 선택에 사용하는 난수에 추가 혼합을 적용하고, 10만 번의 전이 분포를 검사했다. 적 배치가 소비하는 난수 개수는 유지한다.

실행 시험은 `RiftSmokeSave`라는 별도 디렉터리에서 수행했다. 레벨 30 전사에게 아이템 레벨 30 희귀 장비 8개를 지급한 개발용 상태이며, 단계 1·시드 91367·상자 접근 거리 30m·보스 등장 후 상자 회수를 사용했다. 사용자 계정에 이 장비나 보상을 지급하지 않았다. 이 성공 한 번을 시작 계정의 난이도나 전체 빌드의 클리어율로 해석하지 않는다.

검증 대상 C# 26개 파일의 SHA-256은 `Artifacts/Validation/rift-source-manifest.json`에 기록했고 검증 후 변경이 없음을 확인했다. 통합 수치 요약은 `rift-validation-summary.json`, 바닥 PNG의 원본 정보는 `rift-stone.json`에 따로 보존했다. 개발 문서의 로컬 링크 대상도 모두 존재했다.

## 이 검증 시점에 남아 있던 D2·연계 작업

1. 정예 6특성 전체의 피해·내부 대기시간·사체 소비·연결 효과를 정식 전투 사건에 연결한다. 배치 데이터가 있다는 이유로 모든 특성의 전투 효과가 완성됐다고 보지 않는다.
2. 적의 마지막 발견 위치, 미니맵 정예 표식, 좌·우 벽의 반복 출구 횟수, 모든 목표 접근 실패의 오류 전이를 더 정밀하게 연결한다. 현재의 관찰 지점 탐색과 목표 보류를 최종 탐색 명세 전체로 간주하지 않는다.
3. 상호작용 모델의 몸체 충돌과 동적 점유 회피를 보완한다. 현재 상자의 보상 판정은 열기 위치와 거리로 처리하며, 표현용 상자 몸체가 통행을 막는 동적 물리 오브젝트는 아니다.
4. 성소 SH01·SH02와 선택 저주 상자 CH03은 상자 핵심 검증 다음에 구현한다. 현재 필드에는 이 기능이 있다고 안내하지 않는다.
5. 직업별 두 빌드를 같은 투자량·동일 단계에서 비교한다. 레벨만 30으로 올리고 시작 무기를 유지한 탐색 검사는 이동 오류를 찾는 용도이며 클리어율·성장 밸런스의 증거가 아니다.
6. 초반 성장, 장기 반복 수입, 실제 모바일 화면과 기기 성능, 온라인 중단·복원은 후속 검증이다. macOS의 별도 시험 계정을 사용자 진행 기록에 합치지 않는다.

설계 기준은 [균열 상세 기획](../Design/HELLSCRIPT_Rift_Exploration_Detail.md), [후속 개발 순서](../Design/HELLSCRIPT_Development_Expansion_Plan.md), [게임 완성 체크리스트](../Design/HELLSCRIPT_Gameplay_Completion_Checklist.md)를 따른다. 장비 구현·그림 출처는 [장비 확장 기록](Itemization_Expansion.md)에 분리해 보존했다.
