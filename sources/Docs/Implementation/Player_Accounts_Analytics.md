# 계정 UID와 플레이 이벤트 분석

갱신일: 2026-10-03

[English](Player_Accounts_Analytics.en.md) · [Google 로그인](Google_Login.md) · [Sites 서버](Sites_Player_Logs.md) · [전투 기록](Combat_Journal_Server.md)

이 문서는 **로컬 구현과 배포 후보**를 설명한다. 운영 마이그레이션·Worker 배포·가입 활성화·최종 웹 공개는 별도 승인과 아래 수신 검증을 마쳐야 한다. 로컬 검사 성공을 운영 적용 완료로 표시하지 않는다.

## 계정과 저장

일반 게스트도 아이디와 비밀번호로 계정을 만든다. 이메일이나 추가 닉네임은 요구하지 않는다. 아이디는 ASCII 영문·숫자·밑줄 3–24자이며 대소문자를 구분하지 않는다. 비밀번호는 Unicode 문자 15–128개, UTF-8 512바이트 이하이며 제어 문자·불완전한 surrogate를 허용하지 않는다. 비밀번호는 32바이트 난수 salt와 PBKDF2-SHA256 600,000회로 해시하며 원문을 저장하거나 로그에 남기지 않는다. 호스트가 지원하지 않으면 가입·로그인을 거절하고 반복 수를 낮추지 않는다.

서버가 만든 32자리 계정 UID가 소유 기준이다. 타이틀의 계정 창과 설정의 계정 탭에서 `HS-` 접두사의 문의 번호를 확인·복사한다. UID는 로그인·비밀번호 재설정·권한 증명으로 사용하지 않는다. 이메일 복구·UID만으로 복구·비밀번호 재설정·진행의 클라우드 동기화는 제공하지 않는다. 가입 안내에서 이 범위와 서버 전송 항목을 표시한다.

첫 가입은 기존 `AccountProfiles` 색인의 **폴더 참조만 원자적으로 연결**한다. 게스트 캐릭터·재화·단계·전투 대기 원본은 같은 폴더에 남는다. 새 게스트에는 새 폴더를 배정하며 다른 계정 저장을 합치거나 덮어쓰지 않는다. 동일 계정이 이미 연결돼 있으면 해당 저장을 연다. 로그인만 처음 하는 기기는 기존 게스트 연결과 새 기기 저장 중 하나를 고른다. 잘못된 색인이나 저장 실패에는 진입을 중단하고 원본을 보존한다.

세션은 메모리에만 두고 12시간 만료된다. 다시 실행하면 로그인하며 새 로그인은 그 계정의 이전 서버 세션을 철회한다. 비밀번호·Bearer·Google 이메일은 PlayerPrefs, 저장 JSON, 소유 색인, 브라우저 localStorage/IndexedDB에 기록하지 않는다. 브라우저에서는 소유 색인과 저장의 `FS.syncfs` 성공 후에만 캐릭터 선택과 업로드를 시작한다. 실패하면 같은 계정으로 재시도하며 디스크 원본을 보존한다.

설정의 Google 연동은 기존 로그인 세션과 PKCE/state를 요구한다. 서버가 Google 서명·issuer·audience·nonce·만료를 확인한 뒤 **현재 UID에 Google identity만 연결**한다. 다른 UID가 가진 Google identity는 409로 거절하며 양쪽 계정·저장·기존 로그인 세션을 보존한다. 재시도는 같은 세션 결과를 반환한다. 기존 v1 Google 교환은 v2 연동 요청을 처리할 수 없다. 새 Google 응답에는 이메일 대신 계정 아이디 또는 `Google` 표시명만 준다.

## 수집과 정확한 지표 범위

새 `player_events`는 원본 세이브, 비밀번호, 이메일, 입력 문장, IP, 기기 광고 ID를 담지 않는다. 서버가 인증에서 계정 소유를 결정하고 이벤트·세션 난수 ID, 종류, 클라이언트 UTC/서버 수신 시각, 초, 단계, 튜토리얼 단계, 소비량·통화·출처와 해시만 저장한다. 기존 Google 기록의 `google:` namespace를 유지한다. 로컬 계정은 `player:`이며 Google 연동 후에도 바뀌지 않는다. QA 전용 토큰은 서버가 `qa:`로 분류한다. 집계는 `player`와 `google`만 포함하고 내부적으로 같은 UID를 정규화한다.

| 지표 | 구현과 한계 |
| --- | --- |
| DAU | 날짜별 실제 `activity`가 있는 인증 계정 수. 가입·로그인만 한 계정 수는 별도이며 방문 페이지 통계와 다르다. |
| 재방문 | 과거 7일의 활동 날짜가 있는 계정 수. `analytics_retention.sql`은 수집 시작 후 새 계정의 UTC 달력 D1/D7 코호트를 별도로 계산하며 미성숙 분모를 제외한다. 이는 설치나 수집 전 게스트의 첫 방문 코호트가 아니다. |
| 플레이 시간 | 화면이 보이는 동안 타이틀 이외 캐릭터 선택·게임·설정의 실제 시간. 약 60초마다 출처별 묶음을 저장한다. 배경 탭·포커스 상실은 제외한다. 비정상 종료 때 마지막 미저장 구간이 최대 약 60초 누락될 수 있다. |
| 세션 길이 | 플레이 세션 난수별 활동 초의 합. 일별 export는 UTC 자정에서 나눈 session slice 평균이다. 로그인~로그아웃 벽시계 차이 또는 닫힌 세션만의 평균으로 오해하지 않는다. 종료 이벤트는 최선 노력이며 누락될 수 있다. |
| 전투 행동 시간 | 기존 시뮬레이션 관측에서 공격·회피 행동으로 분류한 실제 시간. 모든 이동·근처 적 존재 시간을 뜻하지 않는다. 기존 균열 `simulationSeconds`와 `attendanceSeconds`는 별도다. 배속 시뮬레이션 초를 실제 플레이 초로 합치지 않는다. |
| 균열 입장·클리어 | 커밋된 일반 균열 저장 전환에서 `rift_enter`, 완료 전투 요약에서 승리와 보스 처치. 전투 중단은 입장과 완료 수가 달라질 수 있다. 모든 값은 `client_observed`이며 치팅 판정 근거가 아니다. |
| 튜토리얼 이탈 | 저장 성공 후 프롤로그 단계 0–6과 완료 100. 단계 0부터 관측한 24시간 코호트만 이탈 계산에 넣는다. 기존 완료·중간 진행은 초기 snapshot으로 표시하며 이탈로 계산하지 않는다. 룬 보드·콘텐츠 안내 전체의 세부 이탈은 아직 포함하지 않는다. |
| 재화 소비 | 성공한 상점 구매·재구매, 물약 구매, 대장간 작업·강화, 균열 회복 거래의 확정된 감소만 기록한다. 보상이나 임의 지갑 차이는 소비로 만들지 않는다. 금·심연의 주화·강화석·재료를 구분한다. 코어 제작·룬 승급/재형성 등 추가 소비 소유자는 별도 이벤트 연결이 필요하다. |

`session_start/end`, `progress_snapshot`, `activity`, `tutorial_step`, `rift_enter`, `currency_spent`, `collection_gap`만 허용한다. 저장 실패·중복 거래는 새 소비/진행 이벤트를 만들지 않는다. 큐는 계정 저장과 함께 최대 2,048개를 보존한다. 한도 초과 때 기존 대기 원본을 삭제하지 않고 누락 수를 증가시켜 다음 여유 때 `collection_gap`을 보낸다. 계정 전환 때 업로드를 중단하고 다음 소유 계정의 큐만 연다.

업로드는 최대 64개/64 KiB이며 일치하는 원본 배치 SHA-256과 이벤트 ID 목록의 ACK 뒤에만 큐를 저장해 제거한다. 같은 이벤트 ID의 다른 본문은 전체 배치를 거절한다. 응답 유실·인증 만료·네트워크 실패·ACK 저장 실패에는 원본을 보존하고 최대 300초 대기 후 재시도한다. 기존 전투 큐는 별도 R2 원본·D1 요약·runId/hash ACK 경로를 유지한다. 거절 전투는 `.rejected`로 보존하며 수신 성공으로 세지 않는다.

## 무료 분석 연결과 크기

현재 저장은 Sites의 D1(SQLite 계열) 요약/계정 DB와 R2 전투 원문이다. 운영 `/ops`는 기존 권한으로 관리하며 분석 UI는 아직 추가하지 않았다. Cloudflare Web Analytics는 게임 페이지 방문 측정으로 이 서버 이벤트를 대신하지 않는다. 이전 Railway 볼륨 백업을 운영 분석 DB로 연결하지 않는다.

준비한 `analytics_daily.sql`, `analytics_tutorial.sql`, `analytics_retention.sql`은 **SELECT 전용**이다. UTC 범위·조회 시각·실제 수집 시작 시각을 바인딩하며 결과는 날짜·건수·시간·소비량뿐이다. 계정 UID·아이디·이메일·Bearer·세이브·R2 원문은 결과에 없다. 수신과 30일 이상 차이 나거나 서버 시각보다 5분 이상 미래인 클라이언트 시각은 수신 날짜로 대체하고 일별 대체 건수를 표시한다. 지연 업로드는 과거 날짜의 집계를 바꿀 수 있다. 알려진 운영 검증 계정은 별도로 QA로 식별/제외한 뒤 일반 사용자 분석을 시작해야 한다.

첫 연결은 이 작은 익명 결과를 내부 CSV로 검토하고, 승인 후 개인 Google Sheets에 올려 Google Data Studio/Looker Studio의 무료 차트로 연결하면 된다. Google 계정이 필요하지만 D1에 직접 SQL 접속하는 연결은 아니다. Metabase OSS의 SQLite 연결은 로컬 파일 경로를 요구하므로 D1/R2에는 집계 복제 DB와 별도 호스팅·운영이 필요하다는 판단이다. 기존 Site에 고정 집계와 차트만 추가하면 추가 분석 계정 없이 볼 수 있지만 그 UI 작업은 이번 구현에 포함하지 않는다. D1/R2 비밀키나 운영 Bearer를 BI 도구에 주지 않는다. [Google 무료 요금](https://cloud.google.com/data-studio), [Sheets 연결](https://docs.cloud.google.com/data-studio/connect-to-google-sheets), [Metabase SQLite 연결](https://www.metabase.com/docs/latest/databases/connections/sqlite)을 확인했다.

초기 규모에서는 일별 약 20개 숫자와 소수 튜토리얼/코호트 행이면 충분하다. 매 프레임/원본 전투의 외부 지속 전송은 필요 없다. 실시간 운영 결정을 하거나 매일 수동 CSV가 부담스러워진 뒤에만 일별 덮어쓰기/중복 방지 업로드를 승인한다. 한 시간 플레이에 최소 약 60개 활동 이벤트에 출처 분할·거래·단계 이벤트가 더해진다. 실제 플레이어가 없으므로 행 크기·접속 빈도·전투 파일 크기에서 운영 비용을 확정할 수 없다. D1/R2/Sites 저장량·요청·CPU 한도와 BI 정책을 운영 계정에서 확인한다. 무료 차트가 게임 서버 저장을 무료로 만드는 것은 아니다.

**현재 검증된 운영 데이터**는 2026-10-02 조사에서 QA 전투 15건(승리 14, 패배 1)이며 일반 Google 전투는 0건이었다. 새 일반 플레이 이벤트의 운영 수신은 아직 검증하지 않았다. 로컬 Node/workerd/네이티브 합성 결과는 실제 일반 사용자 데이터가 아니다. 새 저장/수집 코드는 존재하지만 실제 운영 사용자 존재·완전한 수집 범위를 증명하지 않는다.

이 변경은 서버 자동 삭제·TTL을 도입하지 않는다. 기존 원문과 운영 DB를 보존한다. 새 이벤트의 장기 보존 기간, 백업/복원, 익명 집계 장기 보존은 운영 활성화 전에 정해야 하며, 삭제는 별도 승인 작업이다. 클라이언트 큐 한도와 서버 보존 정책은 서로 다르다.

## 운영 변경 승인안과 검증 게이트

1. 동일한 기존 Sites 프로젝트의 DB 백업/현재 버전을 확인하고 `0001_narrow_sue_storm.sql` 및 `0002_colorful_warstar.sql`을 적용한다. 새 세 테이블과 `auth_attempts`의 추가 필드, 통화 필드만 추가하며 기존 행을 수정/삭제하지 않는다.
2. 최종 커밋의 `server/sites`만 기존 Worker에 배포한다. Google OAuth callback·scope·기존 secret·운영자/QA 키는 유지한다. 브라우저 CORS는 `https://hellscript-game.github.io`의 플레이어 API에만 허용하며 `/ops`는 같은 원점/CSRF 보호를 유지한다.
3. 가입 플래그를 끈 상태에서 존재하지 않는 무작위 합성 아이디로 `/v1/accounts/login` 3회를 요청해 **동일 호스트 KDF/CPU를 사전 검증**한다. 각 요청은 유효한 합성 비밀번호·requestId·proof를 메모리에서만 만들며 계정·세션·이벤트를 생성하지 않는다. 임시 `auth_rates` 행은 생성된다. `401 credentials_rejected`는 600,000회 연산 완료, `503 password_kdf_unavailable` 또는 호스트 CPU 오류는 중단 조건이다. HTTP 결과·집계 CPU/벽시계만 기록한다. 통과 후 별도 승인으로 `HELLSCRIPT_LOCAL_ACCOUNTS_ENABLED=true`와 검증 계정 생성을 진행한다. 추가 과금·플랜 변경·새 Site/DB·새 자격증명이 필요하면 정확한 변경과 비용을 먼저 승인받는다.
4. 승인된 검증 계정으로 실제 호스트 가입·로그인 반복, 12시간 만료/즉시 철회, 브라우저 저장 재시작, 실제 Google callback/연동·충돌, 웹 이벤트/전투 수신 건수와 namespace를 확인한다. 토큰·UID·세이브 원문을 보고서나 외부 서비스에 남기지 않는다. 검증 계정과 QA 자료를 일반 사용자 지표에서 분리한다.
5. 위 게이트와 다른 작업의 main 통합을 마친 다음 최종 웹 빌드를 만들고 공개 수신을 확인한다. 웹 빌드만으로 서버 적용을 완료했다고 표시하지 않는다.

로컬 workerd 2026-10-02에서 600,000회 가입 3회·로그인 3회·이벤트 수신이 성공했고 인증 벽시계는 46–60ms였다. **공개 workerd는 반복 수/CPU 한도를 적용하지 않아 이 검사는 운영 Sites 제한 통과 증거가 아니다.** [PBKDF2 구현](https://github.com/cloudflare/workerd/blob/main/src/workerd/api/crypto/pbkdf2.c%2B%2B), [호스트 검사 호출](https://github.com/cloudflare/workerd/blob/main/src/workerd/api/crypto/impl.c%2B%2B), [로컬 무제한 enforcer](https://github.com/cloudflare/workerd/blob/main/src/workerd/server/server.c%2B%2B)를 구분한다. 운영 한도를 우회하거나 반복 수를 줄여 통과시키지 않는다. 지원할 수 없는 경우에는 보안 강도와 지원 런타임을 모두 만족하는 인증 실행 위치/방식을 승인받아야 한다.

가입 중단 롤백은 활성화 값을 `false`로 돌리고 **새 계정의 로그인·세션·이벤트 호환 Worker는 유지**하는 방식이다. 새 계정이 생긴 후 과거 DB 백업이나 구버전 클라이언트/Worker로 단순 복원하면 계정/진행을 잃거나 로그인할 수 없으므로 허용하지 않는다. 추가한 테이블·소유 색인·대기 로그를 삭제하지 않는다. 기존 클라이언트는 일반 Google v1과 기존 전투 namespace를 유지한다.

## 재현과 UI 소유

로컬 서버 전체 34/34, Unity 계정·인증·타이틀·번역 집중 64/64, 공통 UI 검사와 검사 도구 11/11을 통과했다. 네이티브 합성 서버에서 실제 클라이언트의 계정 2개, 플레이 이벤트 26건, 전투 1건/R2 원문 1개를 확인했다. 이는 운영 사용자가 아닌 합성 fixture다. 가입·응답 유실 재시도·오프라인 보존·Google 연동/충돌·별도 프로세스 재로그인을 확인했다. 타이틀 조작 검사 21개와 한국어/영어 5개 화면 비율의 계정 UID·복사·설정 5개 탭/닫기 검사를 통과했다. 최종 통합 담당이 마지막 main 병합 후 전체 EditMode/native/WebGL 검사를 수행한다.

격리 worktree의 전체 위키 생성은 기존 문서가 참조하는 Git 제외 `Artifacts/Validation` 근거가 없어 중단됐다. 계정 문서·영문판·자체 이력은 보존하고, 과거 원문 링크를 삭제하거나 임의 자료로 대체하지 않는다. 원래 근거가 있는 통합 작업 폴더에서 build/check 및 전체 위키 검사를 다시 수행해야 한다. 공개 게시는 아직 하지 않았다.

서버 검사는 `cd server/sites && npm test`, 빌드는 `npm run build`다. `node test_workerd.mjs /absolute/path/to/workerd`는 로컬 공식 바이너리만 사용하며 배포·설치를 하지 않는다. `account_fixture_server.mjs`는 localhost 메모리 SQLite/R2와 명시적 합성 Google 서명을 사용하고 모든 외부 fetch를 차단한다. 네이티브 `RuntimePlayerAccountSmoke`는 `-hellscriptServerBase http://127.0.0.1:<port>/` 및 별도 저장/증거 경로가 필수이며 비로컬 주소를 거절한다. 토큰/비밀번호가 저장되지 않는지 확인한다. 일반 빌드에서 오프라인 무계정 입장은 제공하지 않으며 개발 빌드의 명시적 `-hellscriptOfflineQa`만 기존 회귀 스모크에 허용한다.

화면은 새 콘텐츠 창이 아니라 기존 타이틀 인증 모달과 공통 설정 창의 어댑터다. 타이틀의 Plate/Caption/Google 브랜드 버튼과 공통 `UiTheme`/`UiFonts`/설정 스크롤을 재사용하고 실제 계정 변경은 `GameController`와 `GameStore`가 소유한다. 기본 글자 크기만 사용한다. 한국어·영어에서 440×956, 956×440, 1280×720, 1440×900, 1720×720의 입력·문의 UID·복사·연동·스크롤 조작을 검증한다. macOS 창의 모바일 비율/인셋 검사는 iOS/Android 실기기나 실제 웹 Google 로그인 검증을 대신하지 않는다.
