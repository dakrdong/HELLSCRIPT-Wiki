# 사냥 칙령 조작 정비와 균열 장비 추천

갱신일: 2026-10-01 · [English](Hunt_Edict_Control_Refinement.en.md)

사냥 칙령의 팝업은 바깥을 누르면 X와 동일하게 닫습니다. 바깥 클릭은 뒤에 있는 버튼으로 전달하지 않으며, 적용하지 않은 목록·숫자·순서 선택과 저장 확인은 취소합니다. 원래 편집본은 유지합니다. 말풍선 스킬 메뉴도 같은 규칙을 사용합니다.

## 추천 장비 자동 장착

- 공통 설정은 제목 옆의 On/Off 토글로 켭니다. On은 초록색과 오른쪽 손잡이, Off는 회색과 왼쪽 손잡이로 표시합니다.
- Off에서는 아래 공통 설정과 부위별 세부 설정이 흐려지고 입력할 수 없습니다. 값은 유지하며 On으로 돌아오면 복원됩니다.
- 교체 장비는 목록 상자에서 창고 보관·분해·판매를 선택합니다. 창고가 가득 찼을 때의 바로가기는 창고 보관일 때만 표시합니다.
- 추천 착용 예외는 주무기·보조무기·헬멧·가슴 방어구·장갑·신발·허리띠·목걸이·왼쪽 반지·오른쪽 반지의 체크 목록입니다. 체크한 위치에는 자동 장착하거나 교체하지 않습니다. 양손 무기나 호환되지 않는 보조 장비의 교체로 예외 위치가 함께 해제되는 경우도 막습니다.
- 전설·세트 효과 유지와 장비 점수 도움말 항목은 제거했습니다. 잠금과 판매·분해 보호, 공통 아이템 상세의 점수 표시는 유지합니다.

예외 목록은 `autoEquip.excludedSlots`에 저장합니다. 전역 칙령 버전 5는 버전 1~4를 검증한 뒤 새 기본값을 추가합니다. 기존 효과 유지 필드는 과거 정규 공유 코드 검증을 위한 알려진 필드로만 보존하며 현재 자동 교체 조건에는 사용하지 않습니다.

## 균열 전투의 추천 장비

일반 균열에서 장비를 획득하는 기존 거래 안에서, 착용 가능한 후보의 실제 교체 후 점수가 현재 구성보다 높은지 확인합니다. 무기는 주무기·보조무기를 함께 계산하는 공통 `EquipmentScore.Replacement`를 사용합니다. 자동 장착된 아이템과 장착 불가·점수 미달 아이템은 수동 추천에 추가하지 않습니다. 훈련·튜토리얼에서는 이 추천을 표시하지 않습니다.

전투 화면에는 부위별로 작은 장비 슬롯을 표시합니다. 기존 `BattleHudTopOnPage` 경계를 사용해 하단 캐릭터·스킬 HUD 위에 놓으며, 전투 로그의 펼침·접힘에도 함께 재배치합니다. 한손·양손·보조 장비는 무기 그룹 하나, 반지 두 위치는 반지 그룹 하나로 묶습니다. 각 그룹에서 아이템 점수가 가장 높은 미확인 후보 하나만 표시하며, 다른 부위는 함께 표시합니다.

아이콘을 누르면 공통 장비 상세와 장착 비교·장착·닫기 조작이 나옵니다. 비교는 읽기 전용이며 착용품은 왼쪽, 후보는 오른쪽입니다. 장착 성공 또는 사용자의 닫기 조작은 해당 아이템을 확인 완료로 기록하고 다음 후보를 표시합니다. 가장 높은 장비를 장착해도 이미 획득 시점에 추천 대상으로 기록된 나머지 후보는 한 번씩 확인할 수 있습니다. 화면 이동이나 재배치 때문에 닫힌 상세는 확인 완료로 처리하지 않습니다.

`DropState.gearRecommended`는 획득 시점의 추천 여부, `gearHandled`는 장착·닫기 여부입니다. 획득·장착·확인 상태는 기존 `GameStore`의 파일 저장 거래에 포함됩니다. 실패한 저장은 추천을 소모하지 않습니다. 진행 균열을 다시 열어도 확인한 장비를 반복 추천하지 않습니다. 오래된 저장의 두 필드는 기본 false이므로 옛 획득품이 갑자기 추천되지 않습니다.

## 프리셋 탭의 활성화

별도 활성화 버튼을 제거하고 각 탭 오른쪽에 단일 선택 상자를 둡니다. 활성 탭 한 개만 초록 체크를 표시합니다. 상자를 누르면 해당 탭으로 이동하고 그 스킬 정책만 즉시 저장합니다. 탭 본문을 누르면 기존처럼 미리보기만 바뀌며 저장하지 않습니다. 직접 설정도 같은 선택 방식입니다. 다른 미저장 스킬 배분·전역 편집 내용은 함께 저장하지 않습니다.

## 소유 코드와 검증

`HuntEdictWindow`의 공통 Dialog/말풍선 생성 경로가 바깥 닫기를 소유합니다. `HuntEdictWindow.Equipment`와 `HuntEdictWindow.SkillPresets`가 조작 UI를 소유합니다. 예외의 실제 판정은 `EquipmentRecommendation`, 추천 대기열과 저장은 `RiftGearRecommendations`·`GameStore`, 전투 슬롯은 `GameUI.GearRecommendations`가 담당합니다.

새 상세 진입점 `RiftRecommendationWindow`는 `tools/new_content_ui.py`로 만든 공통 창 경로를 사용하며 `ContentWindowView`, `EquipmentSlotView`, `ItemDetailView`, `EquipmentComparisonView`, `UiTheme`과 `UiFonts`를 재사용합니다. 아이템·비교 부품이 저장 상태를 직접 바꾸지 않습니다.

최종 통합 검증은 아래 기록에 한 번으로 묶습니다. 기본 글자 크기만 검사하며 글자 크기별 검사를 추가하지 않습니다. macOS 합성 포인터 검증과 모바일 실기기 검증은 구분합니다.

### 2026-10-01 검증 기록

- [검증 근거](HuntEdictControlsEvidence/validation.json): 관련 Edit Mode 261개는 최초 258개 통과·3개 실패 후 해당 3개만 수정·재검사해 모두 통과했습니다. 공통 UI 소유 검사와 검사기 테스트 11개도 통과했습니다.
- macOS 개발 플레이어에서 실제 EventSystem 레이캐스트와 포인터 이벤트를 사용했습니다. 440×956·956×440·1600×900·1600×1000·2100×900 각각 한국어·영어에서 On/Off, 목록 상자, 탭 선택 상자, 미리보기와 저장 분리, 공통 상세 조작을 확인했습니다.
- 작은 추천 슬롯의 HUD 겹침을 수정한 뒤에는 해당 배치와 장비 대기열만 재검사했습니다. 위 10개 조합에서 전투 로그를 펼치고 접어도 추천 슬롯이 HUD 위와 안전 영역 안에 남았습니다. 앱을 새 프로세스로 다시 열어 예외 위치·활성 프리셋·확인한 장비·다음 대기 후보의 저장도 확인했습니다.
- 전체 Edit Mode는 이미 실행한 4,960개 완료 기록을 재사용했습니다. 반환된 기존 실패 25개는 ActionContinuity 기준 실패와 일치하지만 목록이 25개로 제한됐고 최종 통과·실패·건너뜀 집계가 반환되지 않았습니다. 전체 통과로 보고하지 않으며 전체 검사를 다시 실행하지 않았습니다.
- 검증은 별도 저장을 사용했습니다. 글자 크기별 검사는 실행하지 않았으며 모바일 실기기 검증은 미실행입니다.
