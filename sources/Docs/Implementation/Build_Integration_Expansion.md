# 빌드 비교와 경로·추천 규칙 보완

작성일: 2026-09-09 · 단계: D3 진행 중

## 1. 기획과 소유자

[전설·세트와 빌드 통합 검사 기준](../Design/HELLSCRIPT_Build_Integration_Detail.md)을 작성하고, 각 직업의 실제 8부위 장비로 생성 균열을 비교하는 편집기 검사를 추가했다. 이후의 기능별 작업·예외·완료 기준은 [남은 개발 작업표](../Design/HELLSCRIPT_Remaining_Development_Backlog.md)에 모았다.

`BuildIntegrationValidation.Compare`는 임시 계정과 카탈로그로 전투를 실행하고 `Artifacts/Validation`에 보고서를 쓴다. 플레이어 저장·씬·프리팹·패키지를 변경하지 않는다. 실제 장비 생성과 `Economy.Equip`, 기존 추천 규칙과 `CombatSimulation`을 사용한다. 전투 도중 HP·공격력·위치·제한시간·보상을 덮어쓰지 않는다.

이동의 권한은 기존 `RiftNavigation`, 추천안의 권한은 `BehaviorPresets`, 실제 화면과 배속·저장의 연결은 `GameController`에 유지했다. 새로운 전투·이동 관리자를 만들지 않았다.

## 2. 발견한 오류와 수정

### 벽 모서리의 반복 정지

시드 91367의 PW02 희귀 구성은 약 211초부터 적 49를 앞에 두고 멈췄다. 300초에 실패했지만 `navigationError`는 비어 있었다. `(-29.1651363, 34.1105156)`에서 목적지 `(-28.6629524, 36.3353081)`까지 유효한 우회 경로가 있었으며, 다음 우회 지점까지의 거리가 0.2m보다 작았다.

기존 이동은 가까운 지점을 먼저 건너뛴 뒤 다음 직선이 벽에 막힌 것을 발견했다. 경로를 다시 만들어도 같은 지점을 건너뛰어 정지가 반복됐다. 가까운 지점을 건너뛰기 전에 그다음 구간의 몸체 통과 여부를 검사하도록 수정했다. 벽·몸체 반경과 이동속도를 바꾸지 않고 실제 우회 지점까지 이동하게 한다.

수정 전 재현 검사는 실패했다. 수정 후 0.05/0.13/0.21/0.4m 이동 간격과 중간 JSON 복원 사례를 포함해 균열 검사 17개가 통과했다. 같은 전체 균열에서 PW02 희귀 구성은 268.71초에 클리어했다.

### 서리 장판의 단독 보스 연계

경로 수정만 적용한 PM01은 보스에게 눈보라·화염구 피해를 한 번도 주지 않고 기본 공격만 사용했다. 눈보라의 적 3명 조건과 화염구의 자기 눈보라 조건이 연결되어, 단독 보스에서는 두 스킬 모두 사용할 수 없었다.

새 추천안의 눈보라 조건을 ‘예상 적중 3명 이상 또는 현재 대상이 보스’로 보완했다. 실제 편집 가능한 SC12의 OR 조건이며 숨은 보스 예외가 아니다. 화염구 조건·스킬 수치·비용·CD와 사용자의 기존 저장 규칙은 보존한다. 단독 보스의 실제 눈보라→화염구 피해, 일반 적 한 명, 감지하지 못한 보스, 기존 사용자 규칙의 복원을 검사했다. 행동 규칙 검사 54개가 통과했다.

### 장비 설명 정합성

`Itemization.cs`의 설명을 실제 조건에 맞췄다. LA03은 0.5초 무장·8초 대기·발동 후 3초 피해, LC01은 비전투 회수 이동 보너스를 명시한다. LW04의 생존·HP 경계·CD, LM03의 보호막별 흡수 기준, LM04의 두 번째 방문 절반 피해, LC02의 유료 사용·기한·충전·CD도 안내한다. 이 설명 변경을 해당 효과의 전체 조합 검사 완료로 해석하지 않는다.

## 3. 동일 조건의 12회 비교

1단계·시드 91367·지도 `c8beaf52`·레벨 30·아이템 레벨 30·강화 0을 사용했다. 6프리셋마다 희귀 8부위와 세트 중심 8부위를 비교했다. 같은 직업의 희귀 장비군은 같은 장비 추첨 시드를 사용한다. 세트 장비군은 접사도 달라 순수 세트 배율 비교가 아니다.

| 추천 빌드 | 희귀 구성 | 세트 구성 |
|---|---|---|
| 회오리 생존 | 클리어 283.45초 | 클리어 277.21초 |
| 도약 분쇄 | 클리어 268.71초 | 클리어 258.26초 |
| 관통 거리유지 | 클리어 289.75초 | 클리어 271.66초 |
| 맹독 매복 | 클리어 283.35초 | 클리어 261.01초 |
| 서리 장판 | 클리어 285.35초 | 클리어 289.90초 |
| 연쇄 제어 | 시간 초과, 보스 HP 1,257.1 | 시간 초과, 보스 HP 1,073.7 |

모든 구성은 상자 2개를 열었다. 연쇄 제어는 경로 정지 수정 후에도 제한시간에 보스를 잡지 못했다. 단독 적 반복 타격이나 임의 피해 보정을 추가하지 않았으며, 여러 시드·성장 단계에서 보스 도달 시간과 군중전·단일 화력을 비교할 후속 항목으로 남긴다. 10개 구성의 클리어를 6빌드 밸런스 완료나 승률로 표시하지 않는다.

원본 보고서는 다음과 같다. 오류가 있었던 원본은 덮어쓰지 않았다.

- `Artifacts/Validation/BuildComparisonInitial`: 최초 12회 비교다.
- `Artifacts/Validation/BuildComparisonNavigation`: 경로만 수정한 12회 비교다.
- `Artifacts/Validation/BuildComparisonBossRule`: 경로와 PM01 추천안을 반영한 12회 비교다.

각 폴더의 `comparison.json`과 최종 전투 JSON으로 장비·행동·피해·적·상자·지도를 확인할 수 있다. 후속 두 보고서에는 경로 재시도, 행동 없이 접근 위치에 머문 최장 시간, 보스 생성 시각·남은 HP·스킬별 보스 피해를 추가했다. 경로 재시도 횟수만으로 오류나 정상 여부를 단정하지 않는다.

## 4. 전체 검사와 실행 빌드

`Artifacts/Validation/builds-editmode-final.xml`에서 Unity Edit Mode **393/393개 통과**, 59.3352817초를 확인했다. 기존 384개에 경로 회귀 5개와 추천 규칙·복원 4개를 추가했다. 검사한 C# 72개는 `builds-final-source-manifest.json`에 해시로 기록했다.

`builds-build-mac-final.log`에서 macOS 개발 빌드 성공과 오류 0개를 확인했다. 기존 `ProjectBuilder.BuildMac`의 프로젝트 구성·빌드 경로를 사용했다. 최종 런타임 DLL의 SHA-256은 `f4fa60f53c5d040fd6eaac90d3d9357147d3d151622128c46e0cbf22bc74218c`이며, 자동 검사와 실행이 끝난 뒤 C# 72개의 해시가 같은지 다시 확인했다. 소스 변경은 비교 도구 추가와 기존 이동·추천안·장비 설명·검사 코드에 한정하며 씬 YAML이나 프리팹을 직접 수정하지 않았다.

격리된 저장 폴더 두 개에서 일반 앱을 총 네 번 실행하고 두 번 실제로 재시작했다. 네 프로세스 모두 종료 코드 0이다. 각 실행은 레벨 30·희귀 8부위·단계 1·시드 91367의 같은 비교 장비와 추천 규칙을 사용했다. 재시작 직후 전투 ID·지도·HP·시간·난수가 체크포인트와 같음을 확인했다.

| 실행 | 배속 | 결과 | 실제 실행 증거 |
|---|---|---|---|
| 도약 분쇄 | 1.5배 | 268.71초 클리어, 82처치, 상자 2개 | `BuildWarriorNativeEvidence`, `builds-native-warrior-start.log`, `builds-native-warrior-resume.log` |
| 서리 장판 | 2배 | 285.35초 클리어, 82처치, 상자 2개 | `BuildMageNativeEvidence`, `builds-native-mage-start.log`, `builds-native-mage-resume.log` |

각 폴더의 `runtime-rift-smoke.txt`와 `final-run.json`에 완료 상태를 보존했다. 두 결과의 전투 시간·처치·누적 피해·최종 HP·자원·이동 거리·종료 상태는 같은 장비의 편집기 비교와 모두 같았다. 재시작 검사를 위해 전투 성능을 높이거나 보스를 제거하지 않았다.

Metal로 렌더링한 540×960 화면 10장을 확인했다. 균열 HUD·복원한 미니맵·상자 접근/개봉 시점·클리어 결과를 포함한다. 상자 캡처는 HUD 갱신 시점에 따라 직전 진행률이 보이는 프레임도 있으므로, 개봉 완료의 증거는 최종 JSON과 결과 화면의 상자 2개 기록으로 확인한다. 이 검사는 앱 내부 UI 호출이며 실제 손가락·마우스 조작, 긴 전설 설명의 전체 화면 검사, Android·접근성·성능 검사가 아니다.

`Artifacts/Validation/builds-validation-summary.json`에 세 단계의 비교 결과, 검사·빌드 해시, 실제 실행·재시작·이미지와 문서 검사를 모았다. 로컬 문서 링크 175개, C# 메타 파일, 자산 GUID 중복 검사를 통과했다. 이전 패시브 단계의 384개 검사 기록은 당시 증거로 보존한다.

## 5. 이어서 할 작업

LW01의 끌어당김·몸체 경계와 LW02·LW03의 실제 장착 검사는 [전사 전설 통합 기록](Legendary_Expansion.md)에 이어서 정리했다. 전설 15종·6세트의 전체 합법적 조합, 여섯 빌드의 실제 편집·장착·배속·다중 시드 검증은 계속 진행한다. 연쇄 제어의 단독 보스 화력·도달 시간과 세트의 역할도 이 단계에 포함한다.

D4의 실제 성장·마을·장비 정리·플레이어 훈련·결과 분석, D5의 온라인·보석·구매, D6의 Android·표현·음향·접근성·성능은 [남은 개발 작업표](../Design/HELLSCRIPT_Remaining_Development_Backlog.md)를 따른다. 이번 경로·규칙 수정으로 D3~D6 전체를 완료했다고 표시하지 않는다.
