# Unity에서 튜토리얼 테스트 계정 초기화

갱신일: 2026-10-04

English: [Tutorial account reset](Tutorial_Account_Reset.en.md)

Unity 상단 **HELLSCRIPT → 테스트 → 튜토리얼 계정 초기화 (Tutorial Reset)**에서 로컬 진행을 초기화한다. 이미 튜토리얼을 마친 계정으로 첫 경험과 사냥 칙령의 단계 공개를 다시 검사하기 위한 Editor 전용 도구다. 게임 빌드에는 포함되지 않는다.

## 사용 방법

1. Unity Play를 멈추고 같은 저장을 사용하는 별도 플레이어도 닫는다.
2. 메뉴에서 도구를 열고 실제 초기화할 **계정 저장**과 표시된 전체 경로를 확인한다. 기본 저장과 `accounts/google-*`, `accounts/guest-*`의 저장을 각각 고를 수 있다. 가장 최근 저장이 먼저 표시된다.
3. **선택 계정 백업 후 초기화**를 누르고 확인한다. 다음 실행에서 같은 계정에 진입하고 직업을 선택하면 첫 필수 튜토리얼이 시작된다. 테스트 도구는 게임이나 Play를 자동으로 시작하지 않는다.

기본 위치는 `Application.persistentDataPath`이며 Unity에 `-hellscriptSavePath <directory>`를 전달했다면 동일한 경로를 사용한다. 테스트할 로그인 계정이 다르면 그 계정의 저장을 선택해야 한다. 브라우저와 다른 기기의 저장을 원격으로 초기화하지 않는다.

## 초기화와 보존 범위

선택한 계정의 `hellscript-local-v1.json`, `.bak`, `.tmp`만 기기 저장 아래 `tutorial-account-backups/<UTC-time>-<unique-id>/`로 이동한다. 기존 복구 백업이 남아 이전 진행을 다시 읽는 문제를 막는다. 새 계정은 기존 `GameStore` 생성·스킬 초기화 경로를 그대로 사용하므로 캐릭터·재화·균열·튜토리얼·사냥 칙령 공개 진행이 새로 시작된다. 튜토리얼 플래그만 되돌려 고레벨·기존 장비와 섞지 않는다.

다른 계정 저장, 로그인 소유 관계, 게스트 인증, 언어·화면·오디오 등 기기 설정, 전투 기록 원본과 인증 파일은 건드리지 않는다. 백업에는 이동한 저장과 경로·시각·파일 크기·SHA-256을 담은 `backup.json`이 있다. 원본 계정 저장은 비공개이며 위키에 게시하지 않는다. 백업은 사용자가 복구 필요성을 판단한 뒤 정리하며 자동 삭제하지 않는다.

플레이·컴파일·임포트 중에는 실행하지 않는다. 잘못된 계정 경로, 심볼릭 링크, 파일 자리에 있는 디렉터리는 거절한다. 백업 기록 생성에 실패하면 원본을 이동하지 않으며, 이동 도중 실패하면 이미 이동한 파일을 되돌린다. 실패 시 표시한 경로와 백업을 확인하고 다른 플레이어의 접근이나 파일 권한을 해결한 뒤 재시도한다.

## 원래 진행으로 복구

Play와 별도 플레이어를 멈춘 뒤 **전체 백업 폴더 열기** 또는 **이번 백업 폴더 열기**를 사용한다. `backup.json`의 `profileDirectory`가 원래 저장 위치다. 현재 테스트 진행도 필요하면 도구로 먼저 백업한 뒤, 복구할 폴더의 저장 파일을 원래 위치에 복사한다. 다음 실행은 보관했던 캐릭터와 진행을 읽는다. 백업을 소비하거나 덮어쓰지 않으며 여러 초기화의 백업은 서로 다른 폴더에 남는다.

## 구현과 검증

소유 코드는 `Assets/HELLSCRIPT/Editor/TutorialAccountReset.cs`다. 계정 데이터는 파일 단위로 보관하며 런타임 저장·튜토리얼 판정·로그인 구현을 변경하지 않는다. Editor의 표준 메뉴·선택·확인 창을 사용하므로 게임의 공통 콘텐츠 창에 별도 예외나 새 화면을 추가하지 않는다. 모든 안내는 한국어와 영어를 함께 표시한다.

`TutorialAccountResetTests`는 실제 저장을 초기화한 뒤 세 직업의 1레벨·첫 튜토리얼 v3·잠긴 후속 기능을 확인하고, 원래 저장의 바이트·다른 계정·소유 관계·기기 설정·인증 파일 보존과 복구, 저장 경로 오류·백업 실패를 검사한다. 실제 사용자 계정 대신 임시 fixture를 사용한다. 검증 결과는 이번 작업 기록에 남기며 기존 튜토리얼의 미완료 네이티브 수용 검사를 완료 처리하지 않는다.

2026-10-04 Unity 6000.6.0f1의 관련 EditMode 3개 중 2개는 첫 실행에서 통과했다. 나머지 1개는 신규 생성 표시를 스킬 초기화 후에 검사한 테스트의 시점 오류를 수정하고 해당 검사만 재실행해 통과했다. 세 직업의 v3 시작 조건과 원래 계정 복구를 확인했다. macOS Unity 실제 창에서 확인창·초기화 완료·백업 열기 버튼을 확인하고, 이동한 본문·복구 백업의 SHA-256과 기기 설정 보존을 대조했다. 사용자 계정은 초기화하지 않았다. 취소 버튼의 실제 입력은 확인하지 않았으며, 전체 게임 검사·새 플레이어 빌드·기존 튜토리얼 수용 검사는 다시 실행하지 않았다.

공통 UI 계약 검사·11개 계약 회귀·UI 갱신 검사도 통과했다. 검증용 Editor는 `Artifacts/Validation/TutorialAccountReset20261004/fixture`를 저장 위치로 사용한다. 이 Editor에서 계속 테스트하는 동안 해당 저장과 백업은 활성 입력으로 보존하며 자동으로 지우지 않는다. Unity를 평소 실행 방식으로 다시 열면 기본 기기 계정 저장으로 돌아간다.
