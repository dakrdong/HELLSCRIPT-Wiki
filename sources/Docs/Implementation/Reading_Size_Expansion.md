# 글자 크기 설정 개발 기록

작성일: 2026-09-11 · P4 1단계 읽기 크기 100~140%

## 범위

[다음 개발 계획서](../../Assets/Plans/next-development-plan.md)의 P4는 모바일·반응형 최적화이며 세 가지를 요구한다. 이번 단계는 그중 첫 번째인 100%부터 140%까지의 글자 크기 조절을 구현한다. 최소 터치 영역 48dp와 노치·홈 바 여백 보강은 다음 단계로 남긴다. [화면 설정·공통 안내](Screen_Settings_Expansion.md)에서 만든 설정 창에 항목을 추가하는 방식이라 새 화면을 만들지 않았다.

## 글자만 키우지 않고 화면 전체를 키우는 이유

이 게임의 화면은 고정 좌표로 놓인 상자 위에 글자를 얹는다. 글자 크기만 늘리면 상자는 그대로이므로 긴 문장이 잘리거나 버튼 밖으로 밀려난다. 그래서 기준 해상도 자체를 선택한 비율로 나눠 상자와 글자를 같은 비율로 함께 키운다. 상자와 글자의 비율이 변하지 않으므로 어떤 크기에서도 잘림이 생기지 않고, 한 화면에 보이는 항목이 줄어드는 대신 나머지는 기존 스크롤로 이어서 읽는다. 설정 화면에도 이 동작을 그대로 설명해 둔다.

| 화면 종류 | 적용 방식 |
|---|---|
| 성소와 목록처럼 세로로 긴 화면 | 기준 해상도 720×1280을 선택 비율로 나눈다. 창 크기에 맞추는 기존 계산은 그대로 둔다. |
| 전투와 반응형 화면 | 기기 밀도로 정한 픽셀 배율에 선택 비율을 곱한다. |
| 설정·안내 창과 프리셋 창 | 자체 캔버스를 가지므로 같은 함수로 같은 배율을 받는다. |

네 곳 모두 하나의 함수에서 배율을 받으므로 화면마다 다른 크기로 보이지 않는다. 기본값 100%에서는 이전과 완전히 같은 값을 사용한다.

## 선택과 저장

단계는 100%, 115%, 130%, 140%이다. 누르면 곧바로 화면에 적용하고 이 기기에 저장한다. 저장 파일은 `hellscript-interface-scale-v1.json` 하나이며 계정 저장과 화면 방향 설정 파일을 건드리지 않는다.

| 상황 | 처리 |
|---|---|
| 저장값이 없음 | 기본 100%로 시작하고 파일을 새로 만들지 않는다. |
| 파일이 손상되었거나 모르는 값 | 기본 100%로 시작하고 원본 파일을 그대로 보존한 뒤 읽지 못했다고 알린다. 1KB를 넘는 파일도 같게 처리한다. |
| 단계에 없는 값을 요청 | 가장 가까운 단계로 맞춘다. 저장 함수 자체는 단계가 아닌 값을 거부한다. |
| 저장 실패 | 선택한 크기는 화면에 그대로 적용하고, 저장하지 못했다는 사실과 다음 실행에 사용할 값을 함께 알린다. 같은 크기를 다시 누르면 저장만 다시 시도한다. |

## 읽던 자리 유지

크기를 바꾸면 설정 창의 카드와 본문을 다시 계산해야 한다. 이때 창을 새로 만들지 않고 위치만 바꾸며, 기존의 읽기 위치 보존 장치를 그대로 사용해 읽던 문단을 유지한다. 여기에 더해 방금 누른 선택 줄을 화면 안으로 되돌린다. 이 처리가 없으면 140%에서 선택 줄이 본문 아래로 밀려나 자신이 누른 결과를 볼 수 없었다.

## 검증

| 검사 | 결과 |
|---|---|
| Edit Mode 전체 | 1144개 통과. 이번에 23개를 추가했고 기존 1121개는 그대로다. |
| 단계·환산 | 계획의 100%와 140%가 양 끝이며 순서와 중복을 확인한다. 단계 밖 값은 가장 가까운 단계로 맞춘다. |
| 저장 격리 | 크기를 저장해도 계정 파일의 바이트와 화면 방향 파일이 변하지 않는다. |
| 손상 복구 | 빈 객체, 다른 판본, 범위 밖 값, 깨진 문자열, 1KB 초과를 모두 기본값으로 처리하고 원본을 보존한다. |
| 저장 실패와 재시도 | 실패해도 선택한 크기가 화면에 남고, 재시도가 성공하면 한 번만 저장한다. |
| 네이티브 스모크 | macOS 개발 빌드에서 종료 코드 0. 기본값에서는 설정 파일을 만들지 않고, 140%를 누르면 같은 머리말 버튼의 화면 높이가 1.4배가 되며, 누른 선택 줄이 화면 안에 남고, 계정은 변하지 않는다. |
| 다른 프로세스 재시작 | 새 프로세스가 저장된 140%로 성소를 다시 그린다. 창 크기가 달라도 같은 창의 100% 배율 대비 1.4배인지로 확인한다. |

증거는 `Artifacts/Validation/ReadingSizeEvidence`에 있다. 스크린샷 33장과 창 크기별 배치 검사 기록이 들어 있으며, `00-restart-town-at-140.png`는 재시작 후의 성소, `29`와 `30`은 같은 창에서의 100%와 140% 비교다.

## 남은 것

- 최소 터치 영역과 노치·홈 바 여백은 P4의 다음 단계다. 현재 안전 영역은 화면 전체에 적용하고 있으나 배경까지 함께 잘라 내며, 세로로 긴 화면의 버튼은 기기 밀도 기준으로 48dp에 미치지 못한다.
- 640×360처럼 아주 작은 창에서 140%를 쓰면 설정 창의 본문 높이가 크게 줄어 스크롤이 길어진다. 글자가 잘리지는 않는다.
- 실기기 확인은 하지 않았다. macOS 창 크기 변경으로만 검증했다.
