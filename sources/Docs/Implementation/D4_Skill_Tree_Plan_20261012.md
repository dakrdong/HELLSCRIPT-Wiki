## 1. 목표

- 지금의 클래스 스킬 트리를 디아블로4식 스킬 트리로 바꾼다. 지금 트리는 직업당 37칸이고, 레벨로 해금하며 계보로 잇고, 만렙은 40이다.
- 시안의 스킬창을 게임 안에서 **같은 모양, 같은 동작**으로 만든다. 들어갈 것:
  - 직업 탭
  - 5단 티어
  - 보조 스킬 3칸이 달린 액티브 카드
  - 은색 패시브 메달과 금색 육각 핵심 패시브
  - 연결선
  - 상세 패널의 투자·회수 버튼
  - 일회성 연출
- 포인트·티어·보조 스킬·패시브 규칙과 전투 효과를 실제 게임에 넣는다. 전투 효과는 보조 스킬 84종, 패시브 30종, 궁극기 3랭크다.
- 단계마다 `main`이 계속 동작해야 한다. 새 체계는 마지막 전환 단계 전까지 플래그 뒤에 둔다(14장).

## 5. 데이터와 ID

### 5.1 ID 규칙

- 남는 스킬은 기존 id를 그대로 쓴다(W01, WP13…). 이름도 같다.
- **새로 만드는 본 스킬은 없다.** 모태가 있는 두 스킬은 옛 id를 이어 쓴다: 원소 주입 = **A06**(옛 그림자 화살), 원소창 = **M07**(옛 잿불창). 옛 동작은 각각 보조 스킬 1번(`A06-1` 그림자 주입, `M07-1` 잿불창)이 된다.
  - 이유: A06 코드(참조 약 570건)와 M07 코드(약 350건)를 새 id로 바꾸지 않아도 되고, 옛 6칸 층(`x01–x06`)에서 궁수의 A06 자리가 비지 않는다.
- 핵심 패시브는 **WP20/WP21, AP20/AP21, MP20/MP21**이다.
- 보조 스킬 id는 `<본 스킬 id>-<1|2|3>` 형식이다(예: `W01-3` 빠른 회전). 보조 스킬은 저장할 때 본 스킬의 (선택 번호, 레벨)로 둔다. id는 아이콘, 문구, 칙령 표시에만 쓴다.
- 아이콘 원본 파일 이름은 JSON의 `iconId`다(`A_IMBUE`, `M_LANCE`, `WK1`…). 게임에 넣을 때는 파일 이름을 `id`로 바꾸고 내용은 바이트 그대로 둔다. 원래 이름은 manifest에 적는다. `A_IMBUE`→`A06.png`, `M_LANCE`→`M07.png`는 같은 이름의 옛 아이콘 파일을 덮어쓴다(옛 그림은 git 이력에 남는다).
- `ClassSkillTree.Display` 같은 id 정규식이 `A06-2`, `WP20` 형식을 알아보는지 확인한다.

### 5.3 데이터 파이프라인

- **원본:** `Docs/Design/D4SkillTree/skill_tree_d4.json`. 시안에서 `extract.js`로 내보낸 파일이고, 구현이 시작되면 이 JSON이 게임 쪽 기준이 된다.
  - 밸런스로 수치를 바꾸면 이 JSON을 고친다. 시안과 수치가 어긋나도 이 JSON을 따른다.
  - 구조·규칙·문구를 바꾸게 되면 사용자에게 알려 시안도 함께 고치게 한다.

- **생성기:** `tools/build_skill_tree_d4.py build|check`를 새로 만든다.

  - 출력 내용: 직업별 티어, 스킬 id, 티어, 최대 랭크, **랭크별 값 배열**(5.4), 보조 스킬 값 배열, 패시브 해금 레벨, 핵심 여부, 연결 대상, 한국어·영어 이름과 효과 문구, 아이콘 id.
  - `check`는 출력이 원본과 같은지 비교한다. 기존 `class_skill_runtime.py`·`build_skill_tree.cjs`와 같은 방식이다.
- **런타임:** `Runtime/Core/SkillTreeD4/`에 데이터 읽기와 규칙 엔진(6장)을 둔다. 모델과 규칙은 **검증된 C# 이식본**(`golden/csharp/SkillTreeD4.Model.cs`, `.Rules.cs`)을 옮긴 것으로 시작한다. 화면, 칙령 빠른 편집, 전투 모두 이 엔진 하나만 쓴다.
- 생성기가 `SkillTreeD4.json`에 **담지 않는 것**: `designSample`, `designSelection`, `behaviourKo`(시안 전용). **담는 것**에 `legacyRemap`(이전에 쓴다)과 화면 문구 `strings`를 더한다.

### 5.4 랭크별 수치

- **액티브 능력치:** Lv1의 `rank1`부터 최대 랭크의 `rankMax`까지 선형으로 보간한다.
  - 피해 %는 기존 `SkillEffects.Power`의 +10%/랭크와 결과가 같다(D50% → D70% = ×1.4).
- **정수 개수**(명·회·발 등):
  - 처음과 끝의 차이가 2면 Lv3과 Lv5에서 +1이다. 흩뿌림 3→5, 도탄 1→3, 연쇄 표식 1→3, 다시 당기는 시위 4→6, 과부하 연쇄 6→8, 되튀김 2→4.
  - 차이가 4면 랭크마다 +1이다. 관통 갈고리 3→7, 교차 쇠뇌 6→10.
- **궁극기와 궁극기 보조:** Lv1/2/3 선형이다. 예: 선조의 전쟁 D65/78/91%, 쿨다운 60/55/50초.
- **패시브:** Lv1→Lv5 선형이다.
- **보조 스킬:** 보조 스킬 레벨은 보조 효과 값만 바꾼다. 스킬 피해 배율은 본 스킬 랭크를 따른다.
- **`value` 단위:** `D%` 무기 피해 대비, `x` 배율, `%p` 퍼센트포인트, `초`, `m`, `m/s`, `명`, `회`, `발`이다. 앞에 `−`가 붙은 값은 감소다.
- **값이 바뀌지 않는 능력치도 있다.** 예: 철벽 쿨다운 14→14초. 표시 형식은 그대로 둔다.

## 6. 규칙 엔진

시안 `apply()`를 그대로 옮긴다. **같은 내용의 검증된 코드가 `golden/csharp/SkillTreeD4.Rules.cs`에 있고**(규칙 정답 32,208개 일치), 아래는 그것을 글로 적은 것이다. 시험 `SkillTreeD4RulesTests`는 `golden/rules_golden.json`을 읽는다.

- `tierPts[t]`는 티어 t 액티브의 (본 랭크 + 보조 랭크) 합이다.
- `spent`는 tierPts 합에 패시브 랭크 합을 더한 값이다.
- `before(t)`는 spent에서 tierPts[t..4]를 뺀 값이다.
- `left`는 영웅 레벨 − spent다.

**투자(액티브 본체):**
1. `before(tier) < gate`이면 `tier`로 막고, 모자란 포인트 수를 함께 알린다.
2. `rank >= max`이면 `max`로 막는다.
3. `left == 0`이면 `pts`로 막는다.
4. 통과하면 rank를 1 올린다.

**투자(보조 스킬 m):**
1. 티어 검사는 본체와 같다.
2. 본 rank < 1이면 `base`로 막는다.
3. 다른 보조가 이미 골라져 있으면 `swap`으로 막는다.
4. 고른 보조 랭크가 min(max, 본 rank)에 닿았으면 `max` 또는 `cap`으로 막는다.
5. `left == 0`이면 `pts`로 막는다.
6. 통과하면, 아직 아무것도 고르지 않았을 때는 이 보조를 고르고 Lv1로 둔다. 이미 고른 보조면 1 올린다.

**투자(패시브):**
1. 영웅 레벨 < 해금 레벨이면 `lv`로 막고, 필요한 레벨을 함께 알린다.
2. rank >= 5면 `max`로 막는다.
3. 핵심 패시브이고 다른 핵심 패시브에 포인트가 있으면 `key`로 막는다.
4. `left == 0`이면 `pts`로 막는다.
5. 통과하면 1 올린다.

**회수:**
- 본체: rank > 0이고 rank > 보조 랭크일 때 1 내린다.
- 보조: 고른 보조이고 랭크 > 0일 때 1 내린다. 0이 되면 선택을 해제한다.
- 패시브: rank > 0일 때 1 내린다.
- 셋 다, 회수한 뒤 모든 티어가 `tierPts[t] > 0 → before(t) >= gate[t]`를 지키지 않으면 회수를 되돌린다.

**티어 열림 표시:** `before(t) >= gate[t] || tierPts[t] > 0`.

**막힌 이유 문구** (투자 버튼에 표시. 세로는 버튼 아래 작은 글씨, 가로·PC는 버튼 글자를 바꾼다):

| 사유 | 한국어 | English |
|---|---|---|
| max | 최대 레벨 | Max rank |
| tier | {n}pt 더 필요 | {n} more pt / {n} more pts |
| base | 스킬 Lv1 먼저 | Skill Lv1 first |
| swap | 마을에서 교체 | Swap in town |
| cap | 스킬 Lv 한도 | Skill Lv cap |
| key | 핵심 1종만 | One key only |
| lv | Lv{n} 필요 | Requires Lv{n} |

`pts`(남은 포인트 없음)는 글자로 보이지 않는다. 머리의 남은 포인트가 이미 0으로 보이기 때문이다. 이때 투자 버튼은 비활성이고 글자는 "투자" 그대로다. 규칙 엔진은 계속 `pts`를 돌려준다(버튼 비활성화와 테스트용).
**테스트:** 시안 검사 스크립트의 규칙 테스트를 EditMode `SkillTreeD4RulesTests`로 옮긴다.
- 레벨 24, 24포인트 배분에서 회오리 회수 → Lv4, 다시 투자 → Lv5
- 빠른 회전을 고른 동안 다른 보조는 막힘
- 빠른 회전을 다 회수하면 선택 해제, 그 뒤 빠른 이동 선택 가능
- 피의 회복(Lv15)은 투자 가능, 결전의 비축(Lv25)은 막힘
- T1에 2포인트만 있을 때 철벽(T3)은 막히고 회오리(T2)는 가능
- 회오리를 붙잡고 있는 찢어낸 상처를 1로 내리는 회수는 거부
- 핵심 패시브는 하나만
- 탭을 바꿔도 직업별 배분 유지

## 7. 저장과 이전

근거는 읽기 전용 조사 `research/save_migration.md`다. **순서와 알고리즘은 그 문서 D장, 시험 방법은 E장**이다. 작업서는 단계별 작업서 5장.

- **배분 저장:** `ClassSkillLoadout`에 version 5를 추가한다.
  - 저장 내용: 직업마다 `ranks` 20개 = 액티브 10(일반 8 + 궁극기 2) + 패시브 10(일반 8 + 핵심 2). 항목은 모두 `SkillInvestment {id, rank, modifier(-1..2), modifierRank}`이고, 패시브 항목은 `modifier = -1`, `modifierRank = 0`으로 두고 쓰지 않는다.
  - 기존 필드 이름(저장 키)은 바꾸지 않고, 필드를 새로 더한다. `JsonUtility`는 없는 키에 필드 초기값을 유지하므로 `modifier = -1`이 옳은 기본이다(0은 "보조 1 선택").
  - `JsonUtility`는 null을 복원하지 않는다. 비어 있는 배열은 "옛 저장"으로 읽힐 수 있으니 기존 `IsAbsent` 방식으로 구분한다.
  - `Rank(id)`는 v5에서 **없는 id에 0**을 돌려준다(지금은 1). `Canonical`은 **버전을 보존**한다(v2 검증용 영웅이 수백 개 시험에서 쓰인다). 변환은 계정 수준에서 한다.
  - **v5 로드 검증:** `ranks`는 직업마다 **10+10 = 20개 항목**이다(`skill_tree_d4.json` 순서로 액티브 10개 = 일반 8 + 궁극기 2, 그다음 패시브 10개 = 일반 8 + 핵심 2). 항목은 모두 같은 `SkillInvestment`이고 패시브 항목은 `modifier == -1`·`modifierRank == 0`이다. 그 밖에 랭크 ≤ 최대(5, 궁극기 3), `modifier == -1`일 때만 `modifierRank == 0`, `modifierRank ≤ min(최대, 랭크)`, 패시브 랭크 > 0이면 해금 레벨 ≤ 영웅 레벨이고 핵심은 하나만, `Spent ≤ level`, 티어 문은 `SkillTreeD4Rules.Valid`, 장착한 스킬은 랭크 > 0이고 4번 칸은 궁극기, 레벨 ≤ 60.
- **이전 v3/v4/없음 → v5:**
  - 기본값은 **전부 회수**다(D4). 장착 칸은 비운다. 배우지 않은 스킬은 장착할 수 없기 때문이다.
  - **이전 위치는 `GameStore.Read()`에서 `Normalize` 앞이다.** 로드 뒤 변경(`ActivateSkillTrees`)은 `Write()`의 칙령 경계 검증에 "플레이어 편집"으로 잡혀 시작이 실패할 수 있다.

## 8. 전투

**구현의 세부는 [전투 명세](D4_Skill_Tree_Combat_Spec_20261012.md)가 정한다.** 공통 틀(두 엔진, `ClassSkillCast` 확장, 정리 규칙, 시험 틀), 보조 스킬 84종의 분류(A 7, A\* 4, B 58, C 15)와 구현 지점, 패시브·핵심 패시브, 궁극기, 코드만으로 정할 수 없는 질문과 기본값이 거기 있다. 이 장은 요약이다.

### 8.1 본 스킬

- 남는 id는 기존 효과 코드를 다시 쓴다. 능력치 표의 값만 랭크별 값으로 바꾼다.
- **A06 원소 주입:** 기존 A06 그림자 화살 코드를 그대로 바탕으로 한다. 기본 효과는 "다음 3발 추가 피해 +25%→+35%"다. 원소와 추가 효과는 보조 스킬이 정한다(그림자 폭발 / 맹독 4초 / 서리 둔화).
- **M07 원소창:** 기존 M07 잿불창·M09 빙하창·M12 접지창의 공통 투사체다. 보조 스킬이 원소를 정한다. 잿불창은 화염 3명 관통+연소, 빙하창은 냉기 둔화→빙결, 접지창은 번개 12m 관통에 연쇄 번개 중계점이다. 보조를 고르지 않았을 때 속성은 17장 D8.

### 8.2 보조 스킬 84종

- 각 보조 스킬은 `shapeKo/shapeEn`(형태가 어떻게 바뀌는지)과 `value`(랭크별 값)로 구현한다.
- `behaviourKo`는 처음 기획 문장이고 숫자가 `effectKo/value`와 다를 수 있다. 수치가 다르면 `effectKo/value`를 따른다.
- `absorbsLegacyId`가 있는 20종은 흡수한 기존 스킬의 효과 코드를 다시 쓴다. 예: W10 피의 회수 → 찢어낸 상처의 피의 회수.
- 보조 스킬마다 결정적 전투 시뮬레이션 EditMode 테스트를 하나 이상 둔다. 같은 시드에서 보조 없음과 보조 있음의 차이가 문구대로 나는지 확인한다.

### 8.3 패시브 30종

- 남는 id(직업당 8)는 기존 메커니즘을 두되, 수치와 조건은 새 `effectKo`에 맞춘다.

| 전사 | 피의 광란: 출혈 치명, 출혈 대상 처치 폭발 D40%→D80% / 끝없는 투지: 스킬 종류를 번갈아 쓰면 피해 +6%→+10%, 3중첩 |
| 궁수 | 정밀: 치명 3회마다 다음 핵심 스킬 확정 치명, +30%→+50% / 독사의 축복: 중독된 적이 받는 피해 +10%→+18% |
| 마법사 | 산산조각: 빙결이 풀릴 때 받은 피해의 30%→50% 폭발 / 원소 정렬: 세 원소를 모두 맞은 적 D60%→D100% 붕괴 |

### 8.4 궁극기

- 랭크 3, 효과는 랭크마다 +20%, 쿨다운은 60/55/50초다.
- 궁극기 공용 쿨다운과 최소 45초 규칙(`CS.ultimateRemaining`)은 유지한다.
- 궁극기 보조 2종은 8.2와 같은 방식이다.

### 8.5 자동 전투 주의점

- **빠른 이동 회오리, 따라오는 눈보라:** 효과가 영웅의 이동 경로에 달려 있다. 사냥 칙령의 이동 규칙과 함께 확인한다.
- **응시 사격:** 0.9초 동안 조준한다. 조준하는 동안 자동 이동을 멈추고, 끊기면 취소한다.
- **미끼 투영, 교차 쇠뇌, 축전 구체(3분할):** 설치물 수의 상한과 소멸 시점을 정한다.
- **피해 간격 ×0.5(빠른 회전):** 틱 수가 늘어난다. 전투 틱 성능을 확인한다. 성능을 주장하려면 실제 바이너리를 이전·이후 3회씩 돌린 CPU·GC 원자료가 필요하다.

### 8.6 랭크 보너스

장비 +1 랭크(`MaximumEffectiveRank` 6)와 룬 스킬 레벨의 적용 범위는 17장 D5다.

### 9.4 배치별 차이

- **세로:**
  - 트리가 위아래로 스크롤된다.
  - 티어 표지 → 액티브 행(카드 + 보조 홈) → 그 티어에 속하는 패시브 캡슐 순서다.
  - 패시브는 "해금 레벨에 이미 열려 있는 티어"에 둔다. 티어 i는 Lv max(1, gate[i])에 열린다.
  - 연결선은 홈 오른쪽 레일을 따라 내려간다.
  - "패시브 보기" 상태로 열면 첫 연결 패시브가 보이게 스크롤한다(`passTop − 200`).
- **가로:**
  - 티어마다 열이 하나다. 액티브가 3개 이상인 티어(마법사 T2)는 두 줄로 나눈다.
  - 패시브는 열 아래 은색 선반에 한 줄 3개다.
  - 판이 좁으면 트리가 가로로 스크롤된다.
- **PC:**
  - 배치는 가로와 같다.
  - 트리 전체를 min(1.5, 846/innerW, 530/innerH)배로 키워 판 가운데에 둔다. 스크롤하지 않는다.
  - 패널은 오른쪽 240×564다.

### 9.5 조작

- 카드, 보조 칸, 패시브, 패널의 보조 스킬 행을 누르면 선택된다.
- 보조 스킬 칸이나 행을 누르면 설명 자리가 그 보조 스킬의 형태 변화 문장으로 바뀐다. 본 스킬 카드를 누르면 본 스킬 설명으로 돌아온다. 투자·회수는 지금 보이는 문장의 대상에 적용된다.
- 투자·회수는 선택한 대상에 적용된다.
- 직업 탭을 바꿔도 직업별 선택과 배분이 남는다.
- 처음 선택값: 시안은 회오리·관통 사격·화염구다. 실제 게임에서는 마지막으로 고른 대상, 없으면 첫 투자 가능 액티브다.
- 투자·회수는 즉시 저장하고(`GameStore` 커밋), 저장한 뒤 UI 갱신 규칙(`AgentRules/UI_Refresh.md`)을 따른다.

- 트윈 라이브러리가 없다. `Time.unscaledTime`으로 직접 애니메이션하고, 창 하나에 갱신기 하나만 둔다.
- 연출 갱신·변화 없는 프레임·메시 그리기는 할당하지 않는다. 클릭 한 번의 거래 프레임(저장·배치·뷰모델)은 할당해도 되고 한 번만 한다(화면 명세 4.5).
- 같은 상태로 다시 그릴 때는 전환을 다시 시작하지 않는다.
- 곡선(cubic-bezier)과 키프레임 수치는 원본 12–97행을 따른다.

### 9.7 성능과 갱신

- 노드 뷰는 (직업, 배치, 언어)가 바뀔 때만 다시 만든다.
- 투자·회수·선택은 기존 뷰의 상태만 바꾼다. 지금 `HuntEdictWindow`처럼 매번 `Clear`하고 다시 그리지 않는다.
- 선은 상태 색별로 메시를 묶어 그린다. 선분마다 GameObject를 만들지 않는다.
- 다시 그리기는 `visibleState` 키가 바뀔 때만 한다. 누르거나 스크롤하는 동안에는 미루고, 끝나면 스크롤 위치를 되돌린다.

## 10. 문구와 다국어

- **화면 문구:** `skill_tree_d4.json`의 `strings.ko/en`을 `Assets/HELLSCRIPT/Resources/Localization/en.txt`의 새 구역 `# D4 skill tree`에 넣는다. 형식은 한국어 원문, 탭, 영어다. 조합 문구는 `Loc.F`로 만든다.
- **저장 문구 함정:**
  - `"{0}pt 더 필요"`처럼 구멍으로 시작하는 템플릿은 저장된 로그 문장을 삼킬 수 있다(`Loc.StoredText`).
  - `StoredLocalizationTests`가 실패하면 앞뒤에 고정 글자를 붙이는 방향으로 고친다. 고친 문구는 사용자에게 알린다.
- **스킬 이름과 효과:** 카탈로그가 한국어·영어를 함께 들고 있다(`ClassSkills`의 name/nameEn 방식). en.txt에 넣지 않는다.
- **스킬 설명과 보조 스킬 형태 문장(새 필드):** `SkillTreeD4.json`의 액티브마다 `descKo`/`descEn`, 보조 스킬마다 `shapeKo`/`shapeEn`을 둔다(생성기가 명세 JSON에서 복사). 둘 다 상세 패널의 설명 자리에만 보이고, 패시브는 효과 문장이 설명을 겸한다.
  - `ClassSkills.json`의 기존 `description/descriptionEn`은 수치와 판정 규칙이 든 긴 규칙 문장이다. 위키와 다른 곳이 쓰고 있으니 **바꾸거나 새 창에 보이지 않는다.**
  - 형태 문장을 쓰는 규칙: 형태가 **어떻게 바뀌는지**를 말한다. 랭크마다 변하는 수치는 쓰지 않고(수치 효과 줄이 따로 있다), 랭크와 무관한 값(3번째 시전, 360°, 3중첩 상한)만 쓴다. 한국어는 "~합니다"체, 영어는 완결된 한 문장이다.
  - 길이: 시안의 가장 긴 설명은 한국어 43자·영어 70자, 가장 긴 형태 문장은 한국어 43자·영어 64자다. 보조 스킬 이름과 " — "까지 붙여도 세로 2줄, 가로 2줄, PC 3줄에 들어간다. 이보다 길어지면 패널 아래가 잘린다. 스모크가 모든 액티브와 보조 스킬을 차례로 골라 넘침을 확인한다(13장).
- **누락 처리:** 영어가 비면 한국어로 대신 보이고 `Loc.Missing`에 기록한다. 빈 문자열이나 키 이름을 화면에 내보내지 않는다.
- **이전 안내와 회수 위치 문구:** 7장 이전 안내, 17장 D3의 "마을에서 회수"는 새 문구다. 두 언어를 함께 넣는다.

## 15. 알려진 함정

- **두 스킬 체계:** 레거시 18칸 배열과 id 기반 트리가 `ProjectLegacy`로 이어져 있다. id 하나를 지우면 배열 인덱스 쪽이 조용히 어긋날 수 있다.
- **지문 검사:** `tools/class_skills.py`는 `GameCatalog.cs`·`SkillEffects.cs`·`SkillProgression.cs`·`Itemization.cs`의 sha256을 고정해 둔다. 이 파일을 고치면 check가 실패한다.
- **위키 고정값:** `wiki.py`의 `expected` 개수와 `test_wiki.py`의 레벨·이름 단언은 개수만 바뀌어도 실패한다.
- **Balance1000:** 트리 파일이 바뀌면 산출물이 stale로 나온다(`--check`).
- **저장 문구 템플릿 함정:** 구멍으로 시작하거나 끝나는 템플릿은 저장 로그를 삼킨다(10장).
- **JsonUtility:** null을 복원하지 않는다. 빈 배열과 "필드 없음"을 구분해야 한다.
- **칙령 창:** 열면 Overview 탭으로 열린다. 스모크는 `SelectTab("skills")`를 먼저 부른다. `Repaint`가 열린 대화 상자를 닫는 함정이 있다.
- **`.meta`:** Unity가 `.png.meta`를 다시 쓰면 guid를 확인하고 함께 커밋한다.
- **스모크 빌드:** `cp -Rc` 복제본에서 배치모드로 빌드하고 스모크 플래그로 실행한다. 인자는 배열로 넘긴다.
- **기준선:** 전체 EditMode와 스모크에는 이미 실패하는 항목이 있을 수 있다. 새 실패라고 하기 전에 같은 조건의 `main` 결과와 비교한다.
- **정답 파일은 디자인 담당의 것:** `golden/`, `skill_tree_d4.json`, `SkillWindow.dc.html`을 구현 작업에서 고치지 않는다. 의심되면 실패한 검사 이름과 입력을 보고한다. 시안이 바뀌면 디자인 담당이 `build_golden.js`로 다시 만들고 참조 구현과 이식본이 같은 검사를 통과하는지 확인한다(`golden/README.md`).
- **`*.csproj`는 git이 무시한다**(Unity 템플릿): 이식본 시험 프로젝트(`golden/csharp/GoldenTests.csproj`)는 `git add -f`로 넣었다. 출력은 `Directory.Build.props`가 무시되는 `Temp/`로 보낸다.
- **화면의 함정 15가지는 화면 명세 15장, 전투의 함정(정리 규칙, 하드코딩 id, 예보 = 해제)은 전투 명세 2.4·2.5, 저장의 함정은 `research/save_migration.md` 0장**이다.
- **동시 작업:** 이 문서를 쓴 시점(2026-10-12)에 Codex가 `codex/guide-tutorial-segment2`에서 가이드 튜토리얼을 작업 중이었다. 그 계획은 W01 첫 적중을 계기로 쓴다. W01이 T2로 옮겨 가니 6단계에서 맞춘다. 공유 체크아웃에서 브랜치를 바꾸지 않는다.

## 16. 하지 말 것

- 규칙을 화면 코드에 따로 넣지 않는다. 스킬창, 빠른 편집, 칙령, 전투가 같은 엔진을 쓴다.
- 시안 hex를 Presentation 코드에 직접 쓰지 않는다. `UiTheme` 토큰을 쓴다.
- 새 글꼴 파일을 넣거나 글꼴을 따로 만들지 않는다. D6이 정해질 때까지 그렇다.
- 아이콘을 리사이즈하거나 다시 생성하거나 배경을 지우지 않는다.
- 글자 크기 조정 검사나 확대 글자 스모크를 다시 넣지 않는다.
- 단계마다 전체 EditMode나 스모크 묶음을 돌리지 않는다.
- 기존 저장 키 이름을 바꾸지 않는다.
- 작업 브랜치에서 위키를 생성하거나 게시하지 않는다.
- `ADAPTERS`나 검사 목록을 통과용으로 넓히지 않는다. 새 창 하나만 이유와 함께 등록한다.
- `Docs/Design/D4SkillTree/golden/`, `skill_tree_d4.json`, `SkillWindow.dc.html`을 구현 작업에서 고치지 않는다(디자인 담당).
- 보조 스킬을 사용 옵션 체계에 싣지 않는다. 시안에 없는 현행 덤 효과를 몰래 옮기지 않는다(D23).
- `SkillTreeD4.Enabled`가 꺼진 빌드에서 저장 이전·스키마 22·만렙 60을 일으키지 않는다(D18).
