# 전염·보스 제어 경계와 같은 틱 사망 정산

작성일: 2026-09-09 · 단계: D3 진행 중

## 1. 변경 목적과 기준

전염이 같은 적에게 전달됐다는 이유로 서로 다른 원 표적의 정상 발동까지 막히던 문제를 고쳤다. 보스의 감속 적립은 강한 효과가 끝난 뒤 남는 약한 효과까지 시간 구간별로 계산한다. 보스 처치 직후 전리품 상태로 전환해 같은 틱의 남은 투사체·장판 피해가 빠지던 구조도 수정했다.

기준은 [장비 상세 명세](../Design/HELLSCRIPT_Itemization_Detail.md)의 LA04·제압 규칙과 [플레이 완료 기준](../Design/HELLSCRIPT_Gameplay_Completion_Checklist.md)의 CHK-C03·CHK-C06이다. 이전 세트 예약·비용 감소 구현과 197개 검사 결과는 [충전 개발 기록](Charge_Expansion.md)에 보존한다.

## 2. 판정과 저장 규칙

| 영역 | 구현한 동작 |
|---|---|
| LA04 전염 | 원 공격 ID와 원 표적 ID 조합당 한 번 발동한다. 서로 다른 원 표적 두 명에서 같은 수신 적으로 전염되는 것은 허용한다. 한 원 표적에서 가까운 순·ID 순으로 최대 두 명을 고르고, 방어 전 암흑 공격값의 50%에 수신 적의 저항을 한 번 적용한다. 원 표적은 피해 사건의 `triggerTargetId`에도 남긴다. |
| 전염의 빈 결과 | 유효한 암흑 추가 피해에서 전염 조건을 충족했지만 주변 수신 적이 없었던 경우에도 그 원 공격·원 표적의 발동 기회는 끝난다. 같은 발동을 다시 제출해 나중에 접근한 적에게 전염시키지 않는다. 다른 원 공격은 새로 판정한다. |
| 이전 전염 기록 | 구형 원장은 수신 적만 저장해 원 표적을 정확히 복원할 수 없다. 구형 기록이 남은 원 공격에 한해 추가 전염을 막고, 이후 새 원 공격부터 원 표적별 규칙을 적용한다. 원 표적을 임의로 추정하거나 과거 전염을 다시 실행하지 않는다. 새 원장에는 `originScoped`를 저장한다. |
| 감속과 제압 | 한 틱을 감속의 각 만료 시점에서 나눈다. 각 구간의 최강 감속 비율×실제 시간×10을 합산하며 감속 비율 상한은 80%다. 제압 면역이 틱 도중 끝나면 끝난 뒤의 구간만 적립한다. 무력화 종료 틱에 10초 면역을 시작하는 기존 규칙은 유지한다. |
| 구형 보스 제어 | 효과 버전 0~2의 보스에 남은 기절·빙결·속박 스칼라 값을 남은 시간×10으로 한 번 변환하고 직접 제어 필드를 비운다. 출처가 있는 구형 상태는 이미 적립된 원 공격·정의 조합이면 다시 적립하지 않는다. 무력화·면역 중인 보스는 추가 적립을 받지 않는다. 원 지속시간을 알 수 없어 남은 시간만 사용한다. |
| 구형 보스 감속 | 남은 스칼라 감속을 `LEGACY_SLOW`, 감속 35%로 한 번 옮긴다. 이후 현재 감속과 같은 최강값 규칙으로 제압에 기여하며 보스 이동속도를 직접 낮추지 않는다. 일반 적의 구형 제어는 이번 변환 대상이 아니다. |
| 피해와 사망 | 피해는 기존 액션·투사체·덫·장판 처리기를 사용한다. HP 0이 된 적은 즉시 죽은 대상으로 표시하고, 사망 정산 대기 상태를 저장한다. 같은 틱의 나머지 피해 처리기를 모두 실행한 뒤 적 ID 순으로 사망 기록과 일반 적 보상을 확정한다. 영웅 HP도 0 아래로 내려가지 않으며 사망 기록은 한 번만 남긴다. |
| 처치 회복 | WP04는 해당 틱의 사망을 모은 뒤 생존한 영웅에게 한 번 적용한다. 같은 틱의 다른 피해로 이미 사망한 영웅을 되살리지 않는다. 1초 내부 간격과 회복 증가 배율을 유지한다. |
| 승패 우선순위 | 피해 처리가 끝난 뒤 보스 사망→영웅 사망→제한시간 순으로 판정한다. 보스와 영웅이 함께 죽거나 제한시간 경계에 보스를 처치하면 보스 클리어를 우선한다. 보스 처치가 없으면 영웅 사망은 실패다. 이미 발사된 투사체와 생성된 장판의 해당 틱 피해는 빠뜨리지 않는다. |
| 정산 이후 | 전리품 상태에서는 전투 시간을 더 진행하지 않으며 남아 있는 공격을 새로 처리하지 않는다. 드롭·초회·전투 기록은 기존 중복 방지 상태를 유지한다. 훈련에서의 보스 사망은 실제 초회·재화·드롭을 지급하지 않는다. |

실행 소유자는 계속 `GameController → CombatSimulation`이다. 정산 순서만 `CombatSimulation.Outcomes.cs`로 분리했다. `EnemyState.pendingDeath`와 `RunState.heroDeathRecorded`는 기존 균열 스냅샷에 포함한다. 정산 대기 상태를 복원하면 시간을 더 진행하기 전에 먼저 처리한다. 이미 죽어 있던 구형 적에게 대기 상태를 임의로 붙이지 않아 과거 보상을 다시 지급하지 않는다. 효과 버전은 3이며 계정·지도·행동 버전은 바꾸지 않았다.

로컬 저장 어댑터는 이번 시작에 실제로 지급한 미실행 골드·재료를 읽기 속성으로 제공한다. 재시작 검사에서는 이를 보스 보상과 별도로 대조한다. 미실행 보상 계산·지급 정책을 바꾼 것이 아니며 서버 영수증 구현도 아니다.

이번 처리는 같은 틱에 처리 대상이 된 피해의 승패·보상·사망 정산을 통합한 것이다. 아직 발사되지 않은 공격의 준비·취소는 기존 액션 규칙을 따른다. 일반 적·정예·보스의 미구현 개별 패턴까지 완성했다고 집계하지 않는다.

## 3. 화면

전투 효과 상세 화면은 영웅 사망 여부와, 보스 동시 사망으로 클리어 보상을 지급한 경우를 설명한다. 같은 틱에 받은 피해와 가한 피해는 기존 상세 기록에서 각각 확인한다. 새 화면은 기존 UI로 제작했으며 새 래스터 이미지나 모델을 추가하지 않았다.

## 4. 검증

| 검증 | 결과와 증거 |
|---|---|
| Unity Edit Mode | `Artifacts/Validation/outcomes-editmode-final.xml`과 로그에서 **220/220개 통과**, 32.9164418초를 확인했다. 기존 197개와 이번 23개 사례다. 서로 다른 전염 원 표적·빈 전염·구형 원장, 감속 만료·면역 부분 구간·상한·분할 시간, 효과 버전 0~2 변환과 재변환 방지, 양방향 투사체·치명 장판·사망 회복 금지·타이머 경계·처치 순서와 보상 추첨·정산 복원·훈련 보상 격리·미실행 지급액 구분을 포함한다. |
| 최종 빌드와 소스 | `outcomes-build-mac-verified.log`에서 macOS 개발 빌드 `Succeeded`, 오류 0을 확인했다. `outcomes-final-source-manifest.json`에 C# 55개·검사 XML·빌드된 `Hellscript.Runtime.dll`의 해시를 기록했고 모두 일치했다. 55개 스크립트에 메타 파일이 있으며 GUID 중복이 없다. 검사 후 게임 코드나 UI 코드를 변경하지 않았다. |

최종 네이티브 정산 검사는 `outcomes-final-checkpoint.log`, `outcomes-final-resume.log`, `outcomes-final-verify.log`와 `OutcomeFinalEvidence`를 사용했다. 실제 화염구 행동으로 투사체를 생성한 뒤 전투 0.75초에 충돌 직전 상태를 저장·종료했다. 실제 프로세스를 다시 실행해 실행 ID·시간·HP·자원·RNG와 투사체·장판의 개별 필드를 대조하고 2배속으로 진행했다. 다음 0.80초 틱에서 화염구·적 투사체·장판 피해 3건과 보스·영웅 사망 2건을 모두 기록했고 영웅 HP 0에서 전리품 상태로 전환했다.

정산 후 앱을 다시 종료·실행하여 재화·드롭·사망 기록을 복원했다. 보스 반복·초회 보상은 합계 골드 1,950·재료 15, 장비 3개·초회 1건·전투 기록 1건으로 끝났다. 재시작 사이의 별도 로컬 미실행 보상은 골드 2·재료 0이었으며 보스 지급액과 혼합하지 않고 대조했다. 실행 ID는 `a8a2e8ab72ea4fafa0588b06f91adb16`이다. `runtime-outcomes-smoke.txt`의 PASS와 세 프로세스의 정상 종료를 확인했다.

이 검사는 레벨 30 마법사·기본 무기·정지한 무해한 보스를 사용했다. 실제 생성된 화염구를 충돌 직전 위치로 옮기고 보스 HP 1·영웅 HP 10, 이미 생성된 적 투사체·장판의 치명 피해를 설정했다. 전리품 복원 검사를 위해 가방 용량을 제한했다가 두 번째 재시작 뒤 해제했다. 사용자 저장과 분리한 `OutcomeFinalSave`를 사용했으며 자연 성장·빌드 밸런스 검사가 아니다.

전체 자동 생성 균열은 같은 최종 빌드의 `outcomes-rift-checkpoint.log`, `outcomes-rift-resume.log`, `OutcomeRiftEvidence`에서 통과했다. 실제 프로세스 재시작 후 지도·HP·시간·RNG를 대조하고 자동 탐색·일반 적 처치·상자 개봉·보스 처치·전리품 정리를 끝까지 실행했다. 결과는 283.35전투초, 처치 87, 장비 13개, 상자 4/6개 개봉이다. 저장된 결과 기록과 실제 VICTORY 화면의 값이 일치한다. 실행 ID는 `31b7a36a1e684ee6a884da8ef653cecc`, 지도 지문은 `c8beaf52`다.

균열 검사는 레벨 30 전사·아이템 레벨 30 희귀 장비 8개·1단계·시드 91367·상자 우회 30m·보스 등장 후 상자 방문을 사용했다. 최종 정산 검사와 합쳐 일반 그래픽 실행 프로세스 5개, 실제 재시작 3회, 화면 10장을 남겼다. Metal, 540×960에서 동시 사망 안내·복원된 피해 기록·지도·개봉 동작·두 클리어 결과를 확인했다. 새 안내 문구의 겹침이나 잘림은 없었다.

상자 개봉 직후 캡처 한 장은 HUD 갱신 전 프레임을 포함하므로 해당 파일명만으로 완료를 판정하지 않는다. 개봉 4회는 실행 보고서·저장된 결과·최종 화면으로 대조했다. 기존 결과 로그의 배경 대비와 URP 심도 효과·Panini 셰이더 제외 경고는 남아 있다. UI 화면 열기는 검사 도구가 해당 메서드를 호출했으며 물리 마우스·터치, Android 실기기나 성장 밸런스의 증거는 아니다. 종합 결과는 `Artifacts/Validation/outcomes-validation-summary.json`에 기록했다. 최종 소스·실행 파일·검사 XML의 해시가 일치하며 문서 로컬 링크 107개에 누락된 대상이나 절 제목 연결 오류가 없었다.

기존 충전 검사는 저장 버전 2를 고정값으로 기대하고 있어 현재 효과 버전을 확인하도록 수정했다. 최초 네이티브 정산 복원 검사에서 보인 1골드 차이는 초회 보상의 중복이 아니라 기존 로컬 미실행 지급액이었다. 저장의 골드 1,951·재료 15·초회 1건을 대조한 뒤, 미실행 지급액을 읽기 속성으로 제공하고 보스 지급액과 별도로 검증하도록 고쳤다. 위 220개 결과에는 이 보강이 포함된다.

## 5. 남은 작업

1. LM01의 고정/추적 선택과 조준 설정, SA/SM의 노출·갱신·만료와 복원은 이후 [장판·세트 개발](Area_Expansion.md)에서 확장했다. 나머지 패시브·전설·세트의 실제 장비 조합 검증은 계속 진행한다.
2. 일반 적 12종·정예 6속성·보스 3종의 독립 패턴, 정확한 공격 출처와 방향 판정을 연결한다. 각 신규 패턴은 같은 틱 사망 정산에도 포함해 회귀 검사한다.
3. D4의 성장 안내·마을·훈련 비교·결과 분석, D5의 보석·온라인 계정·교차 저장·결제, D6의 Android 실기기·입력·음향·성능 검증을 진행한다.

씬·프리팹·패키지·프로젝트 설정·이미지 원본은 이번 판정 변경의 편집 대상이 아니다. macOS 개발 실행을 온라인 서비스나 Android 검증으로 간주하지 않는다.
