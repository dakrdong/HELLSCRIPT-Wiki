# 걸어 다니는 성소 광장 개발 기록

작성일: 2026-09-11 · P2 1단계 보행 광장 · 2단계 균열 관리자 화면·정거장 탭·바닥 확장

> 이 문서는 초기 광장의 이력입니다. 2026-09-14부터 적용되는 타이틀, 원형 조이스틱, NPC 6명, 중앙 오른쪽 포탈과 명시적 상호작용은 [숲속 정착민 마을](Forest_Settlement.md)을 따릅니다. [English](Forest_Settlement.en.md).

## 적용 범위

[남은 개발 작업표 4장](../Design/HELLSCRIPT_Remaining_Development_Backlog.md)과 체크리스트 CHK-U01·U02를 따른다. 성소는 지금까지 생성 배경 위의 메뉴였다. 이 단계는 작은 보행 광장을 만들고, 목적지를 누르면 영웅이 자동으로 걸어가 도착한 곳의 서비스를 여는 흐름을 연결한다. 메뉴는 그대로 남아 같은 서비스를 즉시 연다.

## 보행 모델

`TownWalk`은 광장의 보행 상태만 가진다. 렌더링·저장·난수가 없고 세션 동안만 살아 있다. 광장은 벽이 없는 사각형 하나라서 길찾기 실패가 생기지 않으며, 그래서 이동이 서비스 사용을 막는 일도 없다.

| 동작 | 규칙 |
|---|---|
| 목적지 요청 | 이전 요청을 교체하고 아직 넘기지 않은 도착도 버린다. 이미 도착 반경 안에 서 있으면 걷지 않고 곧바로 도착으로 처리한다. 이동을 서비스의 강제 대기시간으로 만들지 않기 위해서다. |
| 이동 | 초당 5.5m로 목표를 향해 직진하고 광장 경계 안에 머문다. 도착 반경 1.4m에 들어오면 멈춘다. |
| 도착 전달 | 도착은 한 번만 넘겨지고, 받은 쪽이 서비스를 연다. |
| 취소 | 이동과 대기 중인 도착을 모두 버린다. |

정거장은 다섯 곳이다. 대장장이, 재설정 담당, 수수께끼 상인, 균열 관리자, 공유 창고이며 서로의 도착 반경이 겹치지 않는다.

## 화면과 표현

성소 메뉴의 **성소 거닐기 · NPC 방문**으로 광장에 들어간다. 광장 화면은 전투 화면처럼 배경을 그리지 않고 세계 카메라 위에 하단 버튼 여섯 개와 상단 상태 문구만 둔다. 하단 버튼은 정거장 다섯 개와 메뉴다. 상태 문구는 이동 중인 목적지, 남은 거리, 그곳의 서비스를 보여 준다.

세계 표현은 균열과 같은 임시 자산을 그대로 쓴다. 바닥과 테두리 벽은 기본 메시, 정거장은 기둥·화로·불빛, 담당자는 균열의 영웅 몸체와 같은 통자 임시 모델이다. 영웅도 같은 몸체를 쓰므로 정식 모델로 교체하면 두 곳에서 함께 바뀐다. 이동 중인 목적지에는 파란 고리를 켜 준다.

컨트롤러는 전투가 없을 때만 광장을 갱신하며 실제 경과 시간으로 걷게 한다. 도착하면 다음 화면을 연다.

| 정거장 | 여는 화면 |
|---|---|
| 대장장이 | 장비 화면. 강화·일반 제작·분해가 이미 여기에 있다. |
| 재설정 담당 | 장비 화면. 접사 재설정은 장비 상세의 ‘한 줄 재설정’이며, 보석은 자료 검증 전이라 제공하지 않는다고 알린다. |
| 수수께끼 상인 | 상점 화면. |
| 균열 관리자 | 균열 관리자 화면. 단계 선택, 균열 진입 또는 이어하기, 최고 단계 소탕, 고정 훈련장, A/B 비교를 성소 메뉴와 같은 호출로 연다. 2단계에서 추가했다. |
| 공유 창고 | 계정 창고 화면. |

어느 정거장도 접근만으로 비용을 쓰거나 장비를 바꾸지 않는다. 메뉴 버튼과 정거장은 같은 화면을 같은 조건으로 연다.

## 2단계: 균열 관리자 화면, 정거장 탭, 바닥 확장 (2026-09-11)

균열 관리자는 전용 화면을 얻었다. 현재 직업·레벨·최고 실클리어, 오늘 소탕 사용 횟수, 가방 빈칸을 먼저 보여 주고 입장 자격을 문장으로 알린다. 단계 −/+와 상한, 균열 진입·이어하기, 최고 단계 소탕, 고정 훈련장, A/B 비교는 성소 메뉴의 버튼과 같은 함수를 호출한다. 소탕 자격은 `Economy.Sweep`이 검사하는 조건과 같은 조건으로 읽어 안내만 하고, 실제 판정과 정산은 그 함수가 한다. 성소 메뉴에도 같은 화면으로 가는 바로가기를 두었다.

광장에서는 하단 버튼 없이 정거장을 직접 누를 수 있다. 정거장 오브젝트에는 충돌체가 없으므로 다섯 정거장을 화면 좌표로 투영해 손가락 크기의 반경 안에서 가장 가까운 것을 고른다. 반경은 창 높이의 7%와 44픽셀 중 큰 값이다. 화면 위 버튼을 누른 경우는 UI가 받으므로 세계 탭으로 처리하지 않는다. 고르는 규칙은 순수 함수로 두어 카메라 없이 검사했다.

첫 스모크의 스크린샷에서 출발점 근처의 카메라가 광장 바닥 밖의 어둠을 비추던 문제는 벽 바깥까지 바닥을 넉넉히 넓혀 없앴다. 걸을 수 있는 영역은 그대로다.

## 검증

전체 Edit Mode 검사 **1,121개**가 통과했다. 이 중 보행 모델 검사는 10개이며, 2단계에서 탭 선택 규칙 검사를 더했다. 반경 안의 가장 가까운 정거장을 고르고, 두 후보 가운데 더 가까운 쪽을 택하고, 멀리 떨어진 탭은 아무것도 고르지 않고, 거리가 같으면 앞의 정거장을 유지한다. 정거장의 고유성과 반경, 초기 상태, 도착과 한 번만 전달되는 규칙, 선언한 속도와 맞는 이동 시간, 요청 교체, 서 있는 곳의 즉시 도착, 취소, 경계 유지와 방향, 결정성을 확인했다.

`RuntimePlazaSmoke`를 개발 빌드 `Builds/macOS-Plaza/HELLSCRIPT.app`으로 실행했고 종료 코드 0이었다. 메뉴에서 광장이 열리고, 대장장이를 누른 뒤 0.6초 만에 영웅이 출발점을 떠났으며, 도착하자 장비 화면이 열렸다. 상인으로 가는 중에 창고를 누르면 목적지가 바뀌어 창고가 열렸다. 창고 앞에서 창고를 다시 누르면 곧바로 열렸다. 상인 기둥의 화면 위치를 누르면 상인이 목적지가 되고 빈 땅을 누르면 걷지 않았다. 균열 관리자 정거장은 전용 화면을 열었고 여섯 버튼이 모두 있었으며, 광장으로·성소 메뉴·메뉴 바로가기가 각각 제 화면으로 이어졌다. 이 모든 과정에서 계정 저장 내용은 바뀌지 않았다. 스크린샷 7장과 실행 기록을 `Artifacts/Validation/PlazaEvidence`에 보존했다.

## 남은 범위

| 남은 항목 | 내용 |
|---|---|
| 정식 표현 | 담당자와 영웅은 통자 임시 모델이고 광장은 기본 메시다. 정식 마을·NPC 모델은 이미지·모델 생성 도구가 있는 환경에서 만들어야 한다. |
| 나머지 정거장 화면 | 대장장이·재설정 담당은 장비 화면을, 상인은 상점을 그대로 연다. 재설정 담당의 보석 서비스는 자료 검증 뒤에 연결한다. |
| 터치 확인 | 세계 탭은 화면 좌표 계산으로 구현했고 macOS 창에서 좌표를 넣어 확인했다. 실제 터치 입력과 손가락 크기 반경은 실기기에서 확인해야 한다. 조이스틱과 직접 공격 조작은 기획대로 넣지 않는다. |
| 앱 복귀·서비스 닫힘 | 서비스 화면에서 광장으로 돌아오는 경로는 메뉴의 광장 버튼이다. 앱 복귀 시 이동 상태는 세션 안에서만 유지된다. |
| 실기기 | macOS 창에서 버튼 호출로 확인했다. 모바일 화면 크기와 터치는 확인하지 않았다. |
