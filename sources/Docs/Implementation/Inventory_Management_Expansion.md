# 장비 목록·비교·일괄 정리 개발 기록

작성일: 2026-09-09

## 적용 범위

[화면 비율·방향 상세 기획](../Design/HELLSCRIPT_Screen_Layout_Detail.md), [장비 상세 기획 9장](../Design/HELLSCRIPT_Itemization_Detail.md), [남은 개발 작업표의 장비 관리 항목](../Design/HELLSCRIPT_Remaining_Development_Backlog.md)을 기준으로 장비·가방·창고의 목록과 상세, 비교, 필터, 일괄 정리를 연결한다.

현재 장비와 후보의 기본값·강화분·접두·접미·티어·가능 범위·전설 효과·필수 스킬·세트 장착 수를 확인한다. 교체 후 전체 능력치와 사라지는 세트·전설 효과는 기존 `HeroStats` 계산을 재사용한다. 창고 장비도 현재 캐릭터의 복사본으로 비교하며, 실제 장착은 가방으로 옮긴 뒤 수행한다.

## 화면과 선택 상태

너비 820 미만에서는 목록과 상세를 전환한다. 너비 820 이상에서는 목록과 상세를 함께 보여 주며, 1440 이상에서는 현재 장비·교체 후 비교를 별도 영역으로 펼친다. 경계는 안전 영역과 표시 밀도를 반영한 논리 너비다. PC는 배율 1을 사용하고 모바일 밀도는 실제 기기 검증 전의 구현값이다. 짧은 가로 화면도 818/820/844 너비에서 전환 경계를 검토한다.

창 크기를 바꿀 때 목록·상세·비교 객체를 새로 만들지 않는다. 비교 문단은 같은 객체를 다른 읽기 영역으로 옮기며, 사용자가 마지막으로 읽던 영역의 문단과 문단 안의 위치를 복원한다. 버튼은 본문과 분리된 하단 영역에 둔다. 내용 높이는 한국어 줄바꿈에 맞춰 계산한다.

필터·정렬·선택 장비와 목록 위치는 캐릭터와 가방/창고별로 구분해 실행 중에 유지한다. 아이템 ID를 기준으로 연결하며, 설정 화면을 열거나 가로·세로 배치가 바뀌어도 게임 명령을 다시 실행하지 않는다. 처리되어 사라진 장비는 선택을 해제하며, 남은 목록의 읽던 위치를 가능한 범위에서 유지한다. 선택한 장비가 현재 필터에서 빠져도 상세를 유지하고 그 이유를 표시한다.

부위·등급·사용 직업·세트·접사 효과·전설 및 세트 효과·새 장비 여부를 조합해 좁힐 수 있다. 정렬은 장착·부위순, 최근/오래된 획득순, 아이템 레벨순, 등급순을 제공한다. 목록을 정렬해도 실제 저장 배열과 아이템의 옵션 순서는 바꾸지 않는다.

## 획득순과 새 장비

실제로 계정에 들어오는 장비에 단조 증가하는 획득 순번을 기록한다. 시작 장비, 실제 전리품 회수, 소탕, 제작·미확인 상점에 연결했다. 장비를 만들었으나 아직 회수하지 않았거나 가방에 넣지 못한 경우에는 획득한 것으로 기록하지 않는다. 중복 획득 거절과 거래 재시도도 순번을 늘리지 않는다.

창고와 캐릭터 사이에서 옮겨도 이미 발급한 순번을 유지한다. 장비 상세를 선택해 읽으면 새 장비 표시를 해제한다. 이 표시와 순번은 아이템 ID에 연결해 저장한다. 화면 크기를 바꿨다는 이유로 읽음 처리하지 않는다.

기존 저장에 순번이 없는 장비는 0을 유지하고 획득 순서를 모르는 장비로 표시한다. 획득순 정렬에서는 기록이 있는 장비 뒤에 안정적인 순서로 놓는다. 임의의 획득 날짜를 만들거나 기존 장비를 새로 발급하지 않는다. 실제 서버 발급 시각·획득원·계정 권한의 정식 기록은 온라인 단계의 남은 범위다.

## 판매·분해와 저장

일괄 정리는 현재 목록 필터에 해당하는 일반·마법·희귀 장비를 대상으로 한다. 판매와 분해를 미리보기에서 전환할 수 있다. 전체 처리 대상, 장착·잠금·현재 설정·다른 캐릭터의 프리셋 참조 때문에 제외된 항목, 개별 처리할 전설·세트, 예상 골드·재료를 모두 읽을 수 있다. 분해 환급은 실제 강화 재료 투자량의 80%이며 골드는 환급하지 않는다.

확정은 미리보기의 아이템 ID와 상태를 재검사한 뒤 기존 `GameStore.Transact`의 계정 사본에 적용한다. 중간에 장비가 바뀌거나 보호 상태가 달라지면 전체 처리를 중단한다. 미리보기에 없는 장비를 뒤늦게 포함하지 않는다. 같은 요청의 재실행은 이미 기록한 거래로 처리하며 재화나 분해를 중복 적용하지 않는다. 예상 합계가 재화의 저장 범위를 넘으면 처리하지 않는다.

저장 실패에서는 원래 계정·장비·디스크와 같은 미리보기를 유지해 재시도할 수 있다. 미리보기를 갱신하는 버튼으로 변경된 대상과 보상을 다시 확인할 수 있다. 단일 판매·분해도 확인 화면을 거치고, 보호 장비의 해당 버튼은 비활성화한다. 강화·재설정 등 단일 장비 명령도 표시 당시의 장비 상태를 대조한다.

포탈 가방에서는 기존 균열을 유지하면서 정리와 창고 이동을 제공한다. 장착·강화·재설정은 허용하지 않는다. 실제 거래에서도 기존 소유권·보호·진행 중 균열 제한을 적용한다.

## 구현 소유자

| 파일 | 책임 |
|---|---|
| `InventoryManagement.cs` | 필터·정렬, 획득 순번, 일괄 처리 미리보기와 확정 전 재검사를 담당한다. |
| `GameCatalog.cs` | 계정의 획득 순번과 아이템의 순번·읽음 여부를 선택 필드로 저장한다. |
| `Economy.cs`, `GameStore.cs` | 실제 획득과 거래·저장에 순번을 연결하며 기존 전투·영웅 객체를 유지한다. |
| `InventoryLayout.cs` | 화면 너비에 따른 목록·상세·비교와 고정 버튼 영역을 계산한다. |
| `GameUI.InventoryLayout.cs` | 화면 상태·읽던 위치·선택·필터·미리보기와 기존 장비 명령을 연결한다. |
| `GameUI.Items.cs` | 아이콘·장비 설명·능력치 비교·상점·도감의 기존 소유자다. 기존 고정 장비 페이지와 재설정 화면은 새 화면 경로로 정리했다. |

## 검증 진행

첫 전체 Edit Mode 검사 1,026개가 통과했다. 이후 특수 효과 필터와 단일 명령의 상태 대조를 보완했으며, 실제 macOS 실행과 최종 검사를 진행 중이다. 검증이 끝난 범위와 남은 범위를 아래에 기록한다.

이 작업은 전체 SCR-01~08이나 모바일 지원 완료를 뜻하지 않는다. 성소·사냥 칙령·도감·상점·결과·훈련 비교 등 나머지 페이지의 전체 재배치, 실제 모바일의 회전·터치·키보드·노치·복귀, 장시간 성능과 서버 소유권 검증은 남아 있다.
