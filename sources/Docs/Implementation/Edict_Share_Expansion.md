# 사냥 칙령 v0.2 공유 코드 화면 개발 기록

작성일: 2026-09-10 · P0 3단계 · 코드 내보내기·가져오기와 저장 경로

## 적용 범위

[저장 연결](Edict_Storage_Expansion.md)과 [전투 연결](Edict_Drive_Expansion.md) 위에 사용자가 원본을 주고받는 경로를 만든다. 코덱은 이미 있었고 화면과 저장 경로가 없었다.

이 단계에서 원본을 항목별로 편집하는 화면은 만들지 않는다. 편집은 P0 4단계다.

## 저장 경로

`GameStore.SaveHeroEdict`는 기존 프리셋 저장과 같은 순서를 따른다. 소유권과 원본을 검증하고, 계정 사본에 반영한 뒤 파일에 먼저 기록하고, 성공했을 때만 실제 계정에 적용한다. 기록에 실패하면 영웅은 이전과 똑같이 싸운다. 디스크에 닿지 못한 설정으로 전투가 달라지면 안 되기 때문이다.

해금 레벨은 이 지점에서 다시 검사하지 않는다. 기존 `BuildConfig.activeSkills`는 아직 해금하지 않은 스킬을 그대로 담고 해당 규칙만 꺼 두므로, 원본에만 더 엄격한 기준을 적용하면 영웅 자신의 설정이 거부된다. 사용 칸을 직접 고르는 경로는 `WithSlot`이, 받은 코드는 `Import.Prepare`가 이미 해금을 강제한다.

`SetHeroEdictEnabled`는 같은 경로로 사용 여부만 바꾼다. 저장된 원본이 없으면 켜지 않는다.

## 바뀌는 값 비교

`HuntEdictV2Diff.Describe`는 현재 원본과 받은 원본을 각각 정규화한 뒤 비교한다. 정규화를 먼저 하므로 표기 차이가 변경으로 보이지 않는다. 직업이 다르면 그 사실만 알리고 더 비교하지 않는다. 그 밖에는 사용 스킬 네 칸, 공통 공격 순서, 전역 설정, 스킬별 핵심 옵션을 항목 이름과 함께 비교한다.

## 화면

성소의 **사냥 칙령 공유 · v0.2 사용**으로 들어간다.

| 구역 | 하는 일 |
|---|---|
| 자동 판단 사용 | `useEdict`를 켜고 끈다. 현재 담당 범위와 아직 기존 설정을 따르는 범위를 함께 표시한다. |
| 내보내기 | 현재 원본의 코드와 길이를 보여 주고 클립보드로 복사한다. |
| 가져오기 | 클립보드의 코드를 읽어 검사하고, 적용 전에 바뀌는 값을 보여 준다. |

코드가 수백 자에 이르므로 입력란 대신 시스템 클립보드를 사용한다. 아무도 검토하지 않을 긴 문자열을 손으로 다루게 하지 않는다.

가져오기는 확인과 적용을 분리한다. 확인 단계에서 해금하지 않아 비우게 될 칸과 바뀌는 값을 먼저 보여 주고, **이 코드로 적용**을 눌러야 저장한다. 바뀌는 값이 많으면 12개까지 보여 주고 나머지는 개수로 알린다.

실패는 모두 문구로 남긴다. 클립보드가 비었을 때, 코드가 손상됐을 때, 다른 직업일 때, 저장이 실패했을 때를 구분해 표시한다.

## 검증

전체 Edit Mode 검사 **1,069개**가 통과했다. 이 중 공유 검사는 11개다.

| 검사 | 확인한 결과 |
|---|---|
| 왕복 | 저장된 원본의 코드를 되읽으면 같은 정규 원본이 되고 차이가 없다. |
| 차이 목록 | 바꾼 두 값만 정확히 집어내고 같은 원본끼리는 비어 있다. |
| 가져오기 저장 | 파일과 메모리에 모두 반영되고 다시 열어도 유지된다. |
| 기록 실패 | 원본과 저장 파일이 둘 다 그대로 남고, 원인을 없앤 뒤 다시 저장된다. |
| 다른 직업 | 사유와 함께 거부된다. |
| 손상된 코드 | 빈 문자열·잡문자·깨진 본문이 예외 대신 사유로 보고된다. |
| 위조된 코드 | 본문을 한 글자 바꾸면 해시 검사에서 걸린다. |
| 미해금 스킬 | 해당 칸을 비우고 필요 레벨을 알린 뒤 적용된다. |
| 사용 전환 | 저장되고 다시 열어도 유지되며, 원본이 없으면 켜지지 않는다. |

`Artifacts/Validation/edict-share-final-editmode.xml`에 보고서를 보존했다.

검사 중 하나는 처음에 실패했다. 저장 경로가 해금 레벨을 다시 검사해 레벨 1 캐릭터의 기본 원본을 거부했기 때문이다. 기존 로드아웃 규칙과 어긋나는 검사여서 제거했다.
