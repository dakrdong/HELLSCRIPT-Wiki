# 공통 UI와 신규 콘텐츠 개발 규칙

갱신일: 2026-09-24
최신 인벤토리를 장비 표시의 기준으로 삼는다. 신규 콘텐츠는 아래 공통 부품을 조합해 만든다. 화면별로 같은 규칙을 다시 구현하지 않는다. 특수한 배치와 콘텐츠의 게임 규칙은 유지한다.

영어판: [Shared UI contract](Shared_UI_Contract.en.md)

## 화면 기준

| 요소 | 단일 관리 위치와 규칙 |
| --- | --- |
| 색상 | `UiTheme`: 어두운 올리브 배경, 황동색 선택·주요 행동, 아이보리 본문. 위험 행동과 이득·손실은 의미 색을 유지한다. |
| 글꼴 | `UiFonts.Body`를 공유한다. 타이틀의 영문 로고에만 `UiFonts.Display`를 쓴다. 공유 폰트를 개별 창에서 파괴하지 않는다. |
| 크기 | 제목 20, 소제목 15, 본문 12, 보조 10을 기본으로 읽기 배율을 적용한다. 특수 HUD와 기존 큰 화면의 배율은 해당 어댑터가 변환한다. |
| 슬롯 | 세로 52, 가로 54, 간격 6. 같은 안전 영역에서는 `UiTheme.Scale`을 사용한다. 공간이 줄면 열 수를 줄이고 저장 슬롯 번호·정원·위치는 바꾸지 않는다. |
| 창 | 제목·닫기 → 탐색 → 스크롤 본문 → 고정 행동 영역. `ContentWindowHost`가 표시 순서·배경 입력·뒤로가기·중첩 일시정지를 관리한다. |
| 장비 상세 | `ItemTooltip`의 같은 문장 순서·수치·범위·고유 효과·소켓·강화·잠금 표시를 `ItemDetailView`로 그린다. 외곽 크기는 고정하고 본문을 스크롤한다. |
| 장비 비교 | `EquipmentComparisonView`와 `ItemComparison`을 사용한다. 반지 두 위치, 양손 교체, 보조 무기 호환과 전체 능력치 차이를 같은 규칙으로 보여 준다. |
| 캐릭터 장착 | `CharacterEquipmentView`가 10개 위치를 배치한다. 인벤토리·창고 프리셋은 실제 장비를, 슬롯 강화는 반투명 부위 표식을 표시한다. |
| 상태 | `EquipmentSlotView`가 등급 테두리·강화 단계·잠금·장착·선택을 표시한다. 작업 중 표시는 대장간의 `ForgeWorkingPulse`를 사용한다. |

원소, 직업, 룬 등급, 체력·마나, 위험 범위와 지도 기호의 의미 색은 배경 테마로 덮지 않는다. 대장간의 가로 세 영역은 1:1:1, 창고는 양쪽 보관함, 룬 보드는 육각 배치를 유지한다.

## 데이터와 조작의 소유자

| 기능 | 공통 소유자 | 연결 원칙 |
| --- | --- | --- |
| 기본·보너스 능력치 | `HeroStats`, `StatCatalog`, `ItemComparison` | 화면에서 능력치나 반올림 공식을 복제하지 않는다. |
| 장착과 위치 | `EquipmentSlots`, `Storage` | 반지·양손·보조 장비 판정은 실행 시에도 다시 검사한다. |
| 보호와 자동 선택 | `InventoryBulkPlan`, `InventorySalvagePlan`, `ShopAutoSelect`, `EquipmentShop.SaleExclusion` | 판매·분해·이동의 허용 조건을 같다고 가정하지 않는다. 공통 소유권·보호 근거를 사용하되 행동별 조건은 유지한다. |
| 목록과 선택 | `InventoryQuery`, `ShopAutoSettings`, 창별 UI 상태 | 판매·분해 자동 선택 설정을 공유한다. 선택·필터·스크롤은 해당 화면이 보관한다. |
| 거래 | 기존 `GameStore` 실행 함수와 비용 조회 | 미리 본 가격을 신뢰해 차감하지 않는다. 실행 시 상태·잔액·조건을 검사하고 한 번에 저장한다. |
| 확정 상태 갱신 | `GameStore.Committed`, `StoreViewBinding` | 성공한 저장만 알린다. 중복 거래는 다시 알리지 않는다. 모달 편집 중이면 갱신을 보류하고 닫은 뒤 반영한다. |
| 편집과 프리셋 | `HuntEdictEditSession`, 기존 룬·장비·훈련 편집 모델 | 현재 적용본·편집본·저장본을 구분한다. 화면 재배치가 저장이나 되돌리기를 실행하지 않는다. |
| 드래그 | 기존 인벤토리·창고·룬·칙령 입력 어댑터 | 모두 uGUI 포인터 시작·이동·종료·취소 수명 주기를 따른다. 슬롯 이동·육각 점유·순서 변경의 유효성은 각 모델에서 검사한다. |
| 접근 | `TownWalk`, `ContentUnlocks` | 실제 NPC 거리와 해금 사유를 사용한다. 표시와 실행 경로 모두 검증한다. |
| 시간 | `UiTime`과 각 기능의 시계 | 표기만 공유한다. UTC 작업 완료 시간과 일시정지 가능한 전투 시간을 섞지 않는다. |
| HUD·기록 | `GlobalHudSnapshot`, `SkillIconView`, 저장된 전투·훈련 스냅샷 | 이름·아이콘 조회를 공유한다. 과거 기록을 현재 장비로 재계산하지 않는다. |
| 설정·안전 영역 | `UiSafeArea`, `Loc`, 기존 화면·읽기 크기·오디오 설정 | 기기 설정과 계정 저장을 분리한다. 언어와 방향을 바꿔도 편집본을 유지한다. |

`EquipmentViewSource`는 `Owned`, `Draft`, `BattleSnapshot`, `Catalog`, `RewardSnapshot` 중 하나로 표시 데이터의 출처를 명시한다. 상세와 비교는 입력된 아이템을 복사한다. 도감 정의에는 실제 획득 수치가 없으므로 임의의 아이템을 굴려 소유 장비처럼 보여 주지 않는다. 제작 결과와 획득 기록은 `RewardSnapshot`으로 당시 확정된 수치를 표시한다.

공통 UI 부품은 계정 저장을 읽거나 변경하지 않는다. 콘텐츠 제어 코드가 데이터와 행동을 전달한다. 표시 수명 주기 때문에 실패한 저장을 성공으로 바꾸거나 이미 저장한 거래를 재실행하지 않는다.

## 사냥 칙령

기존 25개 묶음·130개 전역 옵션의 ID·값·범위와 전투 동작을 유지한다.

- 가로에서는 분류·요약 목록·선택한 묶음 편집을 나란히 배치한다. 목록과 편집 본문은 각각 스크롤한다.
- 세로에서는 요약 목록과 상세를 슬라이드로 오가며 기존 목록 위치를 복원한다.
- 검색은 옵션 이름·설명·ID로 전체 분류를 조회한다. 변경된 묶음만 볼 수 있다.
- 선택·숫자·복수 선택·우선순위는 현재 값을 요약하고 눌렀을 때 편집한다. 적용 불가 사유는 행 아래에 표시한다.
- 스킬 탭은 확정된 직업별 37개 스킬 트리와 일반 액티브 네 칸·별도 궁극기 한 칸을 보여 준다. 해금된 패시브는 상시 적용하고, 슬롯 메뉴에서 해당 스킬의 칙령 편집으로 이동한다.
- 하단에는 변경 상태·되돌리기·저장을 고정한다. 분류 이동은 편집본을 유지하며 창 닫기와 프리셋 교체는 미저장 내용을 확인한다.

## 신규 콘텐츠를 만드는 순서

1. 공통 UI가 병합된 최신 `main`을 포함한 작업 폴더에서 `python3 tools/new_content_ui.py FeatureName`을 실행한다. 오래된 작업 폴더에 미완료 변경이 있으면 원본을 보존하고 별도 작업 폴더를 만든다. 기존 파일은 덮어쓰지 않는다.
2. 생성된 진입점에 제목의 한국어·영어 문구, 데이터 출처, 읽기 배율과 표시 함수를 전달한다. 편집본은 표시 함수 바깥의 제어 코드가 소유한다.
3. `Navigation`, `Body`, `Actions`에 공통 부품을 조합한다. 계정 쓰기는 기존 도메인 거래에 연결한다.
4. 특수 배치가 필요하면 이유와 공통 소유자 연결을 이 문서에 기록한다. 독립 폰트·수치 계산·장비 카드·캔버스를 무단 복제하지 않는다.
5. 공통 검사, 관련 Unity 검사, 실제 macOS 조작 검증을 수행한다. 변경 범위의 그림과 전후 상태·저장 결과를 남긴다.

`python3 tools/check_ui_contract.py`는 새 창의 진입점, 캔버스 소유, 공용 폰트, 기존 장비 화면의 공통 부품 연결, 표시 부품의 계정 접근을 검사한다. `python3 tools/test_ui_contract.py`는 규칙 위반을 실제로 주입해 검사가 잡는지 확인한다. 같은 검사를 GitHub Actions에서도 실행한다.

자동 검사는 UI를 자동으로 다시 그리지 않으며, 화면의 겹침이나 번역의 자연스러움까지 증명하지 않는다. 시각·조작 검증을 통과해야 개발을 완료한 것으로 본다. 저장소 규칙은 이후 작업에서도 자동으로 읽히지만 외부 도구가 규칙을 무시한 코드를 생성하지 못하게 하는 운영체제 수준의 제한은 아니다.

## 완료 검사

- 동일 장비의 이름·등급·수치·범위·소켓·고유 효과가 모든 상세 경로에서 일치한다.
- 두 반지·양손 무기·보조 장비·프리셋의 위치가 일치하며 저장 번호를 바꾸지 않는다.
- 세로 440×956, 가로 956×440, PC 16:9·16:10·21:9에서 고정 행동과 스크롤 영역이 겹치지 않는다.
- 한국어·영어와 확대 글자에서 닫기·뒤로가기·저장에 접근할 수 있다.
- 칙령의 모든 옵션에 접근하고 검색·분류·방향·언어 변경으로 편집 내용이 사라지지 않는다.
- 실패한 저장, 중복 요청, 재화 부족, 오래된 비용 표시에서 잘못된 차감·성공 표시가 없다.
- 중첩 창을 닫으면 원래 전투 일시정지 상태와 입력 상태를 복원한다.
- macOS 합성 포인터 검증과 모바일 실기기 검증을 구분한다.

통합 전 개발분과 스킬 기획 제외 근거는 [개발분 통합 기록](Completed_Work_Integration.md)을 따른다. 현재 구현 검증 기록은 [공통 UI 통합 검증](Shared_UI_Validation.md)에 남긴다.

## 대장간 코어 제작

`BlacksmithWindow.Cores`는 기존 대장간 어댑터의 네 번째 탭이다. 별도 창·캔버스 없이 공통 장비 칸·등급 색·상세창·글꼴·배율과 창 관리자를 사용한다. 정의의 범위는 `ItemTooltip.CatalogRanges`와 `ItemDetailView.AppendCatalog`로 표시하고 제작 결과에는 저장된 아이템을 전달한다. 세로 단계 이동과 가로 1:1:1 배치, 품질 게이지를 기존 대장간 안에 유지하는 이유와 검증 범위는 [코어 제작](Core_Crafting.md)을 따른다.

## 위상 각인석

`AspectStoneWindow`는 신규 콘텐츠 템플릿에서 시작하며 `ContentWindowView`를 `EquipmentViewSource.Owned`로 연다. 공통 탐색·스크롤 본문·고정 행동 영역 안에 `CharacterEquipmentView`, `EquipmentSlotView`, `ItemDetailView`를 조합한다. 가로는 장비·도감·상세의 세 열, 세로는 세 단계로 배치한다. 확인 단계 안의 착용 장비 목록에서 부위를 바꿔도 위상 선택을 유지한다. 선택·필터는 `AspectStoneSession`, 수집·레벨업·각인 거래는 `GameStore`가 소유한다. 룬석 문양과 빨간 레벨업 점은 콘텐츠의 의미 표시이며, 글꼴·슬롯·창 배율·패널 색은 공통 소유자를 사용한다. 필드 배치 탭은 두지 않는다.

## 버튼과 탭

상태·역할·입력의 공통 계약은 [공통 버튼과 탭의 상호작용](Button_UX.md)을 따른다. 새 버튼은 `ContentWindowView.Button`을 사용하고, 선택 상태는 `UiTheme.Choice`로 전달한다. 화면마다 버튼 색이나 포인터 전환을 다시 구현하지 않는다.


공통화는 모든 조작을 같은 사각 틀에 넣는다는 뜻이 아니다. 보관함은 `UiButtonRole.Icon`과 `StorageChestGraphic`으로 열린 상자·닫힌 상자·구매·잠금을 표현한다. 공통 입력 상태, 테마와 폰트는 유지하고 선택·거래는 `StorageWindow`와 `GameStore`가 소유한다. 아이콘으로 의미가 명확하지 않은 필터는 문구를 유지한다.

## 마을·전투 HUD 배치

`GlobalHudLayout`은 지속 표시되는 생명력·스킬·물약의 화면 좌표를, `GameUI.Plaza`와 `TownJoystick`은 마을 제목·바로가기·이동 입력을 소유한다. 이 HUD는 콘텐츠 창이 아니므로 기존 캔버스와 화면 비례 배치를 유지하는 어댑터다. 물약 뒷판과 제목 배경은 `StorageSurface` 및 `UiTheme` 색상을 재사용하며 별도 래스터 이미지를 만들지 않는다. 표시 변경은 계정 저장·물약 소비를 실행하지 않는다. 세로 하단 기준선·중앙 이동 패드·글자 확대에 따른 배치 근거는 [마을 HUD 검증](Town_Hud_Responsive.md)을 따른다.

## 스킬 트리 어댑터

기존 `HuntEdictWindow`가 편집본을 소유하고 `UiTheme`, `SkillIconView`, `ContentWindowHost`, 고정 행동과 독립 스크롤을 유지한다. 새 창 체계를 만들지 않는다. [통합 기록](Hunt_Edict_Skill_Tree.md)을 따른다.

항목별 간편 프리셋도 같은 편집본과 선택 창을 사용한다. 프리셋은 해당 항목의 옵션 값만 교체하며, 직접 설정을 열거나 화면을 전환하는 동작은 저장하지 않는다. 적용 범위와 검증은 [간편 프리셋 기록](Hunt_Edict_Quick_Presets.md)을 따른다.

## 균열 입장 어댑터

`RiftEntryWindow`는 `ContentWindowView`의 실제 소유 데이터 진입점을 사용한다. 가로 화면에서는 성소 원화·단계 선택을 고정하고 준비 항목만 독립적으로 스크롤한다. 이는 입장 조건과 단계 선택을 동시에 확인하기 위한 배치다. 선택 팝업은 공통 창의 선택적 최대 크기를 사용하며 별도 캔버스나 창 수명 주기를 만들지 않는다. `UiTheme`의 유료 피로도 의미 색, `PotionArt`, `SkillIconView`, 기존 `GameStore` 거래를 공유한다. 최초 보상은 `RewardBoxCatalog`의 상자 지급과 `ContentUnlocks`의 개방 단계를 같은 재사용 목록에서 표시한다. 상세 팝업에서 기능 개방 상태와 상자 수령 상태를 분리하고, 실제 지급은 `GameStore` 거래로 실행한다. [구현과 검증](Rift_Entry.md)을 따른다.
## 인벤토리 물약 배치

사용자 지정에 따라 물약 칸만 세로 32·가로 28의 작은 크기로 표시한다. 장비 칸의 세로 52·가로 54 기준은 유지한다. `EquipmentSlotView`를 작은 표시 어댑터로 재사용하고, `CharacterEquipmentView`의 무기 줄 옆에 배치해 별도 줄을 늘리지 않는다. 슬롯별 선택과 공통 사용 순서 설정을 구분하며 톱니바퀴는 그룹 옆에 하나만 둔다. [물약 슬롯 검증](Potion_Slots.md)에 화면·입력·저장 결과를 기록한다.

## 보석상

`JewelerWindow`는 `ContentWindowView`, `EquipmentViewSource.Owned`, `StoreViewBinding`과 `GameStore` 거래를 사용한다. 종류·등급별 보석 수량 행렬은 장비 위치가 아닌 콘텐츠 전용 표시다. 가로에서는 두 목록을 독립 스크롤하고 세로에서는 탐색 탭으로 전환하며, 제조 행동은 공통 하단 영역에 고정한다. 소켓 장비 상세는 기존 공통 표시를 유지한다. 자세한 규칙은 [보석상 NPC 콘텐츠](Jeweler_Runtime.md)를 따른다.

## 출석 이벤트

`AttendanceWindow`는 신규 창 템플릿의 `ContentWindowView`를 사용한다. 일차별 보상 타일은 실제 소유 장비가 아닌 보상 정의이며, 출석·수령 상태는 계정에서 전달한다. 공통 본문 스크롤과 탐색 영역을 사용하고 하단에는 숨김 체크박스·선택 보상·수령 버튼을 고정한다. 글자 확대 시 하단 높이와 타일 열 수를 조정한다. `AttendanceSwipe`는 가로 입력을 페이지 이동에, 세로 입력을 기존 본문 스크롤에 전달한다. 전투 일시정지는 `ContentWindowHost`, 계정 쓰기는 `GameStore`, 저장 후 표시 갱신은 `StoreViewBinding`이 소유한다. [출석 이벤트](Attendance_Events.md)에 날짜·보상·검증 규칙을 기록한다.

## 전투 기록

`CombatRecordsWindow`는 신규 창 템플릿의 `ContentWindowView`와 `EquipmentViewSource.BattleSnapshot`을 사용한다. Unity의 공통 `Dropdown`으로 승패를 고르고, 목록 본문만 스크롤한다. 선택·필터는 창이, 기록 파일과 거래 후 내보내기는 `GameStore`가 소유한다. 기존 상세 분석 화면을 재사용하며 하단 실시간 로그는 전투 HUD 어댑터로 배치한다. [전투 기록과 서버 수집](Combat_Journal_Server.md)에 보관·신뢰·검증 범위를 기록한다.

## 로그인 전 타이틀 어댑터

`TitleScreenView`의 Google 로그인 창은 로그인 전 화면을 소유하는 기존 타이틀의 일부다. 게임 안의 콘텐츠 창을 새로 열지 않고 기존 안전 영역·본문 스크롤·고정 닫기를 유지하며, `UiFonts`, `UiTheme`, `UiButton`을 공유한다. `GoogleLoginClient`가 인증을, `GameController.Accounts`와 `AccountProfiles`가 저장 연결을 맡는다. 표시 부품은 로그인 성공을 만들거나 저장 소유권을 직접 변경하지 않는다. Google 버튼의 공식 색상과 Roboto 영문 글꼴은 `UiButtonRole.GoogleSignIn` 표시 역할과 `UiFonts.GoogleSignIn`에서 관리하는 제공자 브랜드 예외다. 범위와 검증은 [Google 로그인](Google_Login.md)에 기록한다.

## 튜토리얼 안내

`TutorialJournalWindow`는 공통 창 템플릿을 사용한다. 실습 선택은 실제 소유품과 제작 정의를 구분하고 `ItemDetailView`를 재사용한다. 필수 장착은 기존 인벤토리와 `GameStore` 거래가 소유한다. `TutorialAnchorRing`은 실제 버튼의 논리 ID와 소유 아이템 칸에 연결되는 표시 부품이며 입력을 가로채거나 계정 상태를 변경하지 않는다. 전투 중의 짧은 안내와 HUD 진입 버튼은 기존 전투 HUD의 어댑터를 사용한다. [튜토리얼 구현](Tutorial_Progression.md)을 따른다.
