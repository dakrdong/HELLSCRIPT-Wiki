# 공통 UI와 신규 콘텐츠 개발 규칙

갱신일: 2026-09-30
최신 인벤토리를 장비 표시의 기준으로 삼는다. 신규 콘텐츠는 아래 공통 부품을 조합해 만든다. 화면별로 같은 규칙을 다시 구현하지 않는다. 특수한 배치와 콘텐츠의 게임 규칙은 유지한다.

영어판: [Shared UI contract](Shared_UI_Contract.en.md)

## 화면 기준

| 요소 | 단일 관리 위치와 규칙 |
| --- | --- |
| 색상 | `UiTheme`의 흑요석·금박 단계를 쓴다: 따뜻한 흑요석 바탕, 한 가닥 청동 선, 선택·주요 행동에만 쓰는 금색, 아이보리 본문. 화면 코드에 바탕·테두리·금색을 16진수로 직접 적지 않는다. 위험 행동과 이득·손실, 등급·원소는 의미 색을 유지한다. [양식 개편 기록](Ui_Style_Obsidian_Gilt.md) |
| 글꼴 | `UiFonts.Body`를 공유한다. 타이틀의 영문 로고에만 `UiFonts.Display`를 쓴다. 공유 폰트를 개별 창에서 파괴하지 않는다. |
| 크기 | 제목 20, 소제목 15, 본문 12, 보조 10을 기본으로 사용한다. 사용자 글자 크기 배율은 제공하지 않는다. 특수 HUD와 기존 큰 화면의 배율은 해당 어댑터가 변환한다. |
| 슬롯 | 세로 52, 가로 54, 간격 6. 같은 안전 영역에서는 `UiTheme.Scale`을 사용한다. 공간이 줄면 열 수를 줄이고 저장 슬롯 번호·정원·위치는 바꾸지 않는다. |
| 창 | 제목·닫기 → 탐색 → 스크롤 본문 → 고정 행동 영역. `ContentWindowHost`가 표시 순서·배경 입력·뒤로가기·중첩 일시정지를 관리한다. |
| 장비 상세 | 인벤토리와 결과창의 상세 창틀은 `ItemDetailPopup`을 공유한다. `ItemTooltip`의 같은 문장 순서·수치·범위·고유 효과·소켓·강화·잠금 표시를 `ItemDetailView`로 그린다. 외곽 크기는 고정하고 본문을 스크롤한다. |
| 장비 비교 | `EquipmentComparisonView`와 `ItemComparison`을 사용한다. 반지 두 위치, 양손 교체, 보조 무기 호환과 전체 능력치 차이를 같은 규칙으로 보여 준다. |
| 캐릭터 장착 | `CharacterEquipmentView`가 10개 위치를 배치한다. 인벤토리·창고 프리셋은 실제 장비를, 슬롯 강화는 반투명 부위 표식을 표시한다. |
| 상태 | `EquipmentSlotView`가 등급 테두리·강화 단계·잠금·장착·선택을 표시한다. 작업 중 표시는 대장간의 `ForgeWorkingPulse`를 사용한다. |

원소, 직업, 룬 등급, 체력·마나, 위험 범위와 지도 기호의 의미 색은 배경 테마로 덮지 않는다. 대장간의 가로 세 영역은 1:1:1, 창고는 양쪽 보관함, 룬 보드는 육각 배치를 유지한다.

## 데이터와 조작의 소유자

| 기능 | 공통 소유자 | 연결 원칙 |
| --- | --- | --- |
| 기본·보너스 능력치 | `HeroStats`, `StatCatalog`, `ItemComparison` | 화면에서 능력치나 반올림 공식을 복제하지 않는다. |
| 장착과 위치 | `EquipmentSlots`, `Storage` | 반지·양손·보조 장비 판정은 실행 시에도 다시 검사한다. |
| 보호와 자동 선택 | `InventoryBulkPlan`, `InventorySalvagePlan`, `ShopAutoSelect`, `EquipmentShop.SaleExclusion` | 판매·분해·이동의 허용 조건을 같다고 가정하지 않는다. 공통 소유권·보호 근거를 사용하되 행동별 조건은 유지한다. |
| 목록과 선택 | `InventoryQuery`, `ShopAutoSettings`, 창별 UI 상태 | 판매·분해 자동 선택 설정을 공유한다. 선택·필터·스크롤은 해당 화면이 보관한다. |
| 거래 | 기존 `GameStore` 실행 함수와 비용 조회 | 미리 본 가격을 신뢰해 차감하지 않는다. 실행 시 상태·잔액·조건을 검사하고 한 번에 저장한다. |
| 확정 상태 갱신 | `GameStore.Committed`, `StoreViewBinding` | 성공한 저장만 알린다. 중복 거래는 다시 알리지 않는다. 모달 편집 중이면 갱신을 보류하고 닫은 뒤 반영한다. |
| 편집과 프리셋 | `HuntEdictEditSession`, 기존 룬·장비·훈련 편집 모델 | 현재 적용본·편집본·저장본을 구분한다. 화면 재배치가 저장이나 되돌리기를 실행하지 않는다. |
| 드래그 | 기존 인벤토리·창고·룬·칙령 입력 어댑터 | 모두 uGUI 포인터 시작·이동·종료·취소 수명 주기를 따른다. 슬롯 이동·육각 점유·순서 변경의 유효성은 각 모델에서 검사한다. |
| 접근 | `TownWalk`, `ContentUnlocks` | 실제 NPC 거리와 해금 사유를 사용한다. 표시와 실행 경로 모두 검증한다. |
| 시간 | `UiTime`과 각 기능의 시계 | 표기만 공유한다. UTC 작업 완료 시간과 일시정지 가능한 전투 시간을 섞지 않는다. |
| HUD·기록 | `GlobalHudSnapshot`, `SkillIconView`, 저장된 전투·훈련 스냅샷 | 이름·아이콘 조회를 공유한다. 과거 기록을 현재 장비로 재계산하지 않는다. |
| 설정·안전 영역 | `UiSafeArea`, `Loc`, 기존 화면·언어·오디오 설정 | 기기 설정과 계정 저장을 분리한다. 언어와 방향을 바꿔도 편집본을 유지한다. |

`EquipmentViewSource`는 `Owned`, `Draft`, `BattleSnapshot`, `Catalog`, `RewardSnapshot` 중 하나로 표시 데이터의 출처를 명시한다. 상세와 비교는 입력된 아이템을 복사한다. 도감 정의에는 실제 획득 수치가 없으므로 임의의 아이템을 굴려 소유 장비처럼 보여 주지 않는다. 제작 결과와 획득 기록은 `RewardSnapshot`으로 당시 확정된 수치를 표시한다.

공통 UI 부품은 계정 저장을 읽거나 변경하지 않는다. 콘텐츠 제어 코드가 데이터와 행동을 전달한다. 표시 수명 주기 때문에 실패한 저장을 성공으로 바꾸거나 이미 저장한 거래를 재실행하지 않는다.

## 사냥 칙령

기존 25개 묶음·130개 전역 옵션의 ID·값·범위를 유지한다. 창고 부족 대응은 추천 착용과 자동 정리가 공유하며, 창고가 가득 찼을 때의 반복 중단도 이 공통 설정에서 결정한다. [장비 추천 착용](Recommended_Equipment.md)은 같은 창에 전용 탭을 추가하며, 10개 묶음과 추천 착용 20개·창고 입고 1개의 전역 옵션을 더해 총 35개 묶음·151개 전역 옵션을 제공한다. 변경은 기존 편집본과 고정 저장·되돌리기를 거친다.

- 가로에서는 분류·요약 목록·선택한 묶음 편집을 나란히 배치한다. 목록과 편집 본문은 각각 스크롤한다.
- 세로에서는 요약 목록과 상세를 슬라이드로 오가며 기존 목록 위치를 복원한다.
- 검색은 옵션 이름·설명·ID로 전체 분류를 조회한다. 변경된 묶음만 볼 수 있다.
- 선택·숫자·복수 선택·우선순위는 현재 값을 요약하고 눌렀을 때 편집한다. 적용 불가 사유는 행 아래에 표시한다.
- 스킬 탭은 확정된 직업별 37개 스킬 트리와 일반 액티브 네 칸·별도 궁극기 한 칸을 보여 준다. 해금되고 등급이 배분된 패시브는 상시 적용하고, 슬롯 메뉴에서 해당 스킬의 칙령 편집으로 이동한다.
- 스킬 옵션 화면을 제외한 편집 화면은 하단에 변경 상태·되돌리기·저장을 고정한다. 스킬 프리셋 탭은 고정된 활성화 버튼과 기존 거래를 통한 항목별 즉시 저장을 사용하므로 별도 저장 하단 영역을 두지 않는다. 다른 미저장 포인트·장착·전역 옵션은 보존하며 함께 확정하지 않는다. 분류 이동은 편집본을 유지하며 창 닫기와 전체 프리셋 교체는 미저장 내용을 확인한다.
- 창을 열면 **요약** 탭이 먼저 나온다. 요약 탭은 전투 방식 세 가지, 지난 사냥 조언, 장착 스킬과 사용 방식, 전투 판단 7개 묶음, 자동 관리 상태를 보여 준다. 전투 방식은 기존 간편 프리셋의 조합이며, 조언은 저장된 전투 기록만 읽는다. 두 기능 모두 편집본만 바꾸고 기존 저장·되돌리기를 거친다. 기준과 검증은 [요약 화면 구현](Hunt_Edict_Overview.md)을 따른다.

스킬 옵션 화면은 설명용 전투 도해를 `SkillTreeGraphic`과 `SkillIconView`로 그리는 기존 창의 어댑터다. 좁은 화면에서는 프리셋 탭을 두 줄로 고정하며, 직접 설정에는 그림 없이 세부 옵션만 표시한다. 실제 저장 상태와 미리 보는 탭을 구분하는 이유, 저장 범위와 검증은 [간편 프리셋](Hunt_Edict_Quick_Presets.md)을 따른다.

## 신규 콘텐츠를 만드는 순서

1. 공통 UI가 병합된 최신 `main`을 포함한 작업 폴더에서 `python3 tools/new_content_ui.py FeatureName`을 실행한다. 오래된 작업 폴더에 미완료 변경이 있으면 원본을 보존하고 별도 작업 폴더를 만든다. 기존 파일은 덮어쓰지 않는다.
2. 생성된 진입점에 제목의 한국어·영어 문구, 데이터 출처, 기본 배율과 표시 함수를 전달한다. 편집본은 표시 함수 바깥의 제어 코드가 소유한다.
3. `Navigation`, `Body`, `Actions`에 공통 부품을 조합한다. 계정 쓰기는 기존 도메인 거래에 연결한다.
4. 특수 배치가 필요하면 이유와 공통 소유자 연결을 이 문서에 기록한다. 독립 폰트·수치 계산·장비 카드·캔버스를 무단 복제하지 않는다.
5. 공통 검사, 관련 Unity 검사, 실제 macOS 조작 검증을 수행한다. 변경 범위의 그림과 전후 상태·저장 결과를 남긴다.

`python3 tools/check_ui_contract.py`는 새 창의 진입점, 캔버스 소유, 공용 폰트, 기존 장비 화면의 공통 부품 연결, 표시 부품의 계정 접근을 검사한다. `python3 tools/test_ui_contract.py`는 규칙 위반을 실제로 주입해 검사가 잡는지 확인한다. 같은 검사를 GitHub Actions에서도 실행한다.

자동 검사는 UI를 자동으로 다시 그리지 않으며, 화면의 겹침이나 번역의 자연스러움까지 증명하지 않는다. 시각·조작 검증을 통과해야 개발을 완료한 것으로 본다. 저장소 규칙은 이후 작업에서도 자동으로 읽히지만 외부 도구가 규칙을 무시한 코드를 생성하지 못하게 하는 운영체제 수준의 제한은 아니다.

## 완료 검사

글자 크기 비율 조정은 2026-09-30에 제거했다. 이후 크기별 조합과 확대 글자 전용 검사는 수행하지 않는다. 화면 크기와 안전 영역에 따른 배치·기본 크기 문구 잘림·실제 입력 검사는 유지한다. [제거 범위](Text_Size_Option_Removal.md)를 따른다.

- 동일 장비의 이름·등급·수치·범위·소켓·고유 효과가 모든 상세 경로에서 일치한다.
- 두 반지·양손 무기·보조 장비·프리셋의 위치가 일치하며 저장 번호를 바꾸지 않는다.
- 세로 440×956, 가로 956×440, PC 16:9·16:10·21:9에서 고정 행동과 스크롤 영역이 겹치지 않는다.
- 기본 글자 크기의 한국어·영어에서 닫기·뒤로가기·저장에 접근할 수 있다.
- 칙령의 모든 옵션에 접근하고 검색·분류·방향·언어 변경으로 편집 내용이 사라지지 않는다.
- 실패한 저장, 중복 요청, 재화 부족, 오래된 비용 표시에서 잘못된 차감·성공 표시가 없다.
- 중첩 창을 닫으면 원래 전투 일시정지 상태와 입력 상태를 복원한다.
- macOS 합성 포인터 검증과 모바일 실기기 검증을 구분한다.

통합 전 개발분과 스킬 기획 제외 근거는 [개발분 통합 기록](Completed_Work_Integration.md)을 따른다. 현재 구현 검증 기록은 [공통 UI 통합 검증](Shared_UI_Validation.md)에 남긴다.

## 대장간 코어 제작

`BlacksmithWindow.Cores`는 기존 대장간 어댑터의 네 번째 탭이다. 별도 창·캔버스 없이 공통 장비 칸·등급 색·상세창·글꼴·배율과 창 관리자를 사용한다. 정의의 범위는 `ItemTooltip.CatalogRanges`와 `ItemDetailView.AppendCatalog`로 표시하고 제작 결과에는 저장된 아이템을 전달한다. 세로 단계 이동과 가로 1:1:1 배치, 품질 게이지를 기존 대장간 안에 유지하는 이유와 검증 범위는 [코어 제작](Core_Crafting.md)을 따른다.

## 위상 각인석

`AspectStoneWindow`는 신규 콘텐츠 템플릿에서 시작하며 `ContentWindowView`를 `EquipmentViewSource.Owned`로 연다. 공통 탐색·스크롤 본문·고정 행동 영역 안에 `CharacterEquipmentView`, `EquipmentSlotView`, `ItemDetailView`를 조합한다. 가로는 장비·도감·상세의 세 열, 세로는 세 단계로 배치한다. 확인 단계 안의 착용 장비 목록에서 부위를 바꿔도 위상 선택을 유지한다. 선택·필터는 `AspectStoneSession`, 수집·레벨업·각인 거래는 `GameStore`가 소유한다. 룬석 문양과 빨간 레벨업 점은 콘텐츠의 의미 표시이며, 글꼴·슬롯·창 배율·패널 색은 공통 소유자를 사용한다. 필드 배치 탭은 두지 않는다.

## 버튼과 탭

상태·역할·입력의 공통 계약은 [공통 버튼과 탭의 상호작용](Button_UX.md)을, 모양은 [흑요석·금박 양식](Ui_Style_Obsidian_Gilt.md)을 따른다. 새 버튼은 `ContentWindowView.Button`을, 탐색 탭은 `ContentWindowView.Tab`을 사용하고, 선택 상태는 `UiTheme.Choice`로 전달한다. 탭을 주요 행동으로 그리지 않고, 머리글의 닫기는 `×` 조용한 버튼으로 둔다. 자체 머리글을 쓰는 어댑터는 `UiHeaderRule`로 공통 구분선을 붙인다. 화면마다 버튼 색이나 포인터 전환을 다시 구현하지 않는다.


공통화는 모든 조작을 같은 사각 틀에 넣는다는 뜻이 아니다. 보관함은 `UiButtonRole.Icon`과 `StorageChestGraphic`으로 열린 상자·닫힌 상자·구매·잠금을 표현한다. 공통 입력 상태, 테마와 폰트는 유지하고 선택·거래는 `StorageWindow`와 `GameStore`가 소유한다. 아이콘으로 의미가 명확하지 않은 필터는 문구를 유지한다. 상자 원화는 `Art/Storage`의 투명 PNG 두 장을 쓰며, `StorageChestOverlay`가 구매·잠금 표식과 드래그 진행 표시를 그린다. 이는 사용자 요청으로 교체한 콘텐츠 그림이며 공통 버튼 스킨을 바꾸지 않는다. 제작 출처와 고정 크기·입력 검증은 [버튼 검증 기록](Button_UX.md)을 따른다.

## 스킬 트리 어댑터

2026-09-27 개편부터 트리는 세 계열의 줄기와 레벨 단계 관문, 선행 스킬 연결선을 그리는 전용 배치다. 줄기·연결선·빛 번짐은 텍스처 없는 `SkillTreeGraphic` 메시가, 노드 위치는 표시 전용 `SkillTreeLayout`이 정한다. 해금·등급·장착 판정은 `ClassSkillTree`가 계속 소유한다. 노드와 장착 칸은 창고 상자처럼 `UiButton`의 `Icon` 역할을 쓰고, 장식 그래픽이 공통 버튼의 마우스·누름·초점 상태를 읽는다. 선택은 테두리 대신 빛으로 표시한다. 아이콘은 `SkillIconView`가 그리고, 장식 테두리·배경·포인트 보석은 사용자 요청으로 GPT가 생성한 콘텐츠 그림이다. 공통 버튼 장식에 래스터를 쓰지 않는 규칙과 별개이며, 테두리의 투명한 안쪽 폭을 측정해 아이콘을 맞춘다. 제작 근거와 검사는 [스킬 트리 화면 이미지 제작 기록](../Art/SkillTreeUi/Skill_Tree_UI_Art.md)에 있다.

장착 스킬의 행동 메뉴는 같은 창 안에서 누른 칸에 붙는 작은 상자로 표시한다. 기존 버튼·테마·뒤로가기·편집본을 공유하고, 화면 재배치 후에는 같은 칸의 새 좌표를 읽는다. 바깥 클릭을 받는 투명한 층은 화면을 어둡게 만들거나 뒤의 조작을 실행하지 않는다. 저장 확인과 일반 옵션 선택창의 중앙 배치는 유지한다.

전역 묶음의 간편 프리셋은 기존 편집본과 선택 창을 유지한다. 스킬 옵션은 고정 미리보기 탭과 별도의 활성화 버튼을 사용하며 해당 항목만 즉시 저장한다. 활성 체크는 실제 저장 상태를 따르고, 탭을 둘러보는 동작은 저장하지 않는다. `SkillPresetExampleView`는 공통 아이콘과 그래픽으로 읽기 전용 전투 도해를 그리며, 직접 설정에는 그림 없이 세부 옵션을 표시한다. 좁은 화면에서는 고정 탭을 여러 줄로 배치한다. 기존 창의 어댑터로서 다른 미저장 변경과 공통 테마·글꼴·창 관리자를 유지한다. 적용 범위와 검증은 [간편 프리셋 기록](Hunt_Edict_Quick_Presets.md)을 따른다.

## 균열 승리 결과 어댑터

`RiftVictoryWindow`는 공통 창의 `RewardSnapshot` 진입점을 사용한다. 결과 전체를 한 화면에서 확인하도록 본문을 고정 배치하고 획득 아이템 목록만 독립 스크롤한다. 세로는 정복 기록·전투 돌아보기·성장과 전리품을 위아래로 쌓고 행동을 하단에 고정한다. 가로와 PC는 정복 기록 | 성장과 전리품+전투 돌아보기 | 획득 아이템의 세 열 옆에 세로 행동 레일을 둔다. 영역 구분선은 공통 `UiHeaderRule`을 쓴다. 네 일반 스킬과 궁극기는 전투 스냅샷을 읽고 `RiftSkillShareView`가 그린다. 반복 표시의 두 그림(모래시계, 반복 횟수)은 사용자 요청으로 Codex가 그린 흰 단색 콘텐츠 그림(`Art/RiftResult`)이며, 전용 임포터와 `ResourceTextureBudget`이 크기를 정하고 텍스처가 없으면 벡터 기호로 대신한다. 공통 슬롯·상세·아이콘·안전 영역과 버튼을 유지하며 별도 캔버스를 만들지 않는다. 큰 장식 수치에는 공유 `UiFonts.Display`를 쓰고 고정 크기를 유지한다. 완료 결과 페이지는 `ContentWindowHost`의 입력·뒤로가기를 유지하면서 반복 시계 차단만 해제한다. 중첩 창은 기본 차단을 사용한다. [소유 경계와 검증](Rift_Victory.md)을 따른다.

균열과 인벤토리의 아이템 상세 하단은 `ItemDetailPopup.SetFooter`가 문맥·안내·행동 수에 맞춰 계산한다. 콘텐츠에서 하단 높이·버튼 좌표를 별도로 만들지 않는다. 균열 실패는 같은 결과 어댑터와 공통 `UiTheme` 실패 색을 사용하며, 스킬 피해 카드는 대상별 집계를 읽는 비대화형 표시다.

중첩 상세창을 닫을 때 `ContentWindowHost`는 이전 선택과 입력 방식을 함께 복원한다. 마우스·터치 선택을 키보드 포커스로 바꾸지 않는다. 장비의 등급 테두리는 유지하고 키보드 탐색으로 연 경우에만 포커스 표시를 복원한다.

문자 로그는 `CombatLogWindow`의 `ContentWindowView`/`BattleSnapshot` 모달로 연다. 원래 결과 페이지를 유지하고 하단은 닫기만 제공한다. 스킬 기여도는 공통 `CombatStatistics`와 스킬 정의의 표시 역할을 읽으며 화면에서 전투 이벤트를 재계산하지 않는다.

‘상세 보기’의 `RiftReviewDetailWindow`는 신규 창 템플릿에서 시작한 `ContentWindowView`·`BattleSnapshot` 창이다. 세로는 목표·스킬 피해 비중·받은 피해 탭을, 가로와 PC는 탭 없이 목표 단계 시간과 받은 피해 순위를 나란히 보여 준다. 순위 그리기는 `IncomingDamageRanking`이 맡는다. 출처별 누계와 Top 목록 비중은 `CombatStatistics.TopIncoming`이, 목표 단계 시간은 `RiftObjectives.RecordStep`이 기록한다. 화면은 정렬·집계나 저장 변경을 복제하지 않는다.
## 자동 사냥 절전 HUD

`GameUI.Idle`의 기존 캔버스는 실제 사냥을 계속하는 절전 HUD 어댑터다. 배경에는 일시정지를 걸지 않고, 창고·인벤토리·새 `IdleEquipmentDetailWindow`만 공통 창 관리자의 중첩 일시정지를 사용한다. 장비 칸은 `EquipmentSlotView`, 과거 상세는 `ItemDetailView`와 `RewardSnapshot`, 검은 배경 위의 글꼴·색·배율은 `UiFonts`·`UiTheme`을 사용한다. 독립 스크롤은 전체 기록을 보관하면서 보이는 행만 생성한다. 표시가 거래를 실행하거나 과거 장비를 현재 소유품으로 다시 조회하지 않는다. [절전 모드](Idle_Display.md)에 실행과 검증 범위를 기록한다.

위치·행동 표시는 `IdleHuntStatus`가 실제 `RunState`·`RepeatHuntSession`을 읽는다. 목표 수는 `RiftObjectives`, 얼굴 인장은 `GlobalHudView.CreateSeal`·`Portrait`, 레벨·경험치는 `GlobalHudSnapshot.ReadGrowth`를 재사용한다. 절전 화면 갱신을 위해 일반 HUD 전체의 스킬·물약·효과 목록을 다시 만들지 않는다.
## NPC 대화

`NpcDialogueWindow`는 공통 템플릿과 `ContentWindowView`를 사용하며, 표시 출처는 `EquipmentViewSource.Catalog`다. 인물 그림과 인사말은 콘텐츠 정의이며 계정 상태를 읽거나 변경하지 않는다. 필드를 최대한 드러내기 위해 공통 창의 `bottomDock` 옵션으로 안전 영역 하단에 배치한다. 높이는 안전 영역의 30% 이하이며 전체 화면을 어둡게 덮지 않는다. 2026-09-28부터는 아래의 이야기 장면(`StoryDialogueWindow.Scene`)으로 그린다. 인물 그림은 띠 밖으로 솟되 안전 영역 안에 있고 인사말·행동과 겹치지 않는다. 인사말만 스크롤하며 서비스·종료 행동은 띠 아래쪽에 고정한다. 기존 중앙형 창은 기본 배치와 배경을 유지한다. `GameController.NpcDialogue`가 거리와 기존 서비스 접근을 재검증한다. [NPC 초상화와 대화](Npc_Dialogue_Portraits.md)에 인물·이미지 출처·검증을 기록한다.

## 이야기 대화창과 튜토리얼 연출

`StoryDialogueWindow`는 인물이 말하는 장면의 공통 대화창이다. `ContentWindowView`의 `bottomDock`을 사용하므로 안전 영역·입력 차단·뒤로가기·일시정지 임대는 창 관리자가 계속 소유한다. 화면 폭 전체의 대사 띠(위는 투명 그라데이션, 글자 뒤는 불투명), 금색 선 가운데의 장식 이름표, 띠 밖으로 솟은 투명 배경의 큰 인물(가로 화면은 오른쪽에 어둡게 선 주인공 포함), 가운데 정렬의 한 글자씩 표시, 다음·건너뛰기와 마지막 줄의 선택지를 제공한다. 버튼은 `ContentWindowView.Button`, 색은 `UiTheme`, 글꼴은 `UiFonts`를 사용한다. 한 글자씩 표시는 `Text.text`를 바꾸지 않고 글자 사각형의 투명도만 조절한다. `NpcDialogueWindow`는 `ContentWindowView.Open`에 `StoryDialogueWindow.Scene`을 넘겨 같은 장면을 그린다. 모든 문구는 한국어 원문을 전달하고 그릴 때 번역한다.

튜토리얼 연출 층(`TutorialCinematic`)은 전투 HUD 위에 띠·암전·제목 카드·목표 알림·짧은 대사·장비 획득을 그리는 표시 전용 캔버스다. 캔버스는 기존 소유자인 `GameUI.cs`가 정렬 130으로 만들며, 콘텐츠 창(400 이상)보다 아래에 있다. 장비 획득은 `EquipmentSlotView`와 `EquipmentGradePalette`, 장식은 `EquipmentRevealGraphic`을 재사용한다. 계정을 읽거나 바꾸지 않으며 진행은 기존 `GameController` 명령이 소유한다. 전투 대화는 월드 표시를 이어 가도록 `blocksGameplay:false`로 열되 일시정지 임대는 유지한다. [튜토리얼 연출](Tutorial_Staging.md)에 흐름과 검증을 기록한다.

2026-09-29: 전역 설정의 35개 묶음은 기존 좌우 목록 대신 상단 고정 아이콘 탭을 사용합니다. 탭은 좁은 화면에서 줄바꿈하고 선택한 본문만 스크롤합니다. 프리셋·공유는 다섯 고정 행과 입력형 이름·디스크 저장·슬롯별 공유를 사용하며 페이지 스크롤을 만들지 않습니다. 기본 추천 정책 On/Off는 요약 상단에 배치하고 `GameStore.SetRecommendedEdict`를 통해 영웅의 실행 모드만 저장합니다. `HuntEdictDefaults`가 읽기용 정책을 만들며 화면 부품은 원본 설정을 변경하지 않습니다. 자세한 동작은 [프리셋](Hunt_Edict_Quick_Presets.md)과 [요약](Hunt_Edict_Overview.md)을 따릅니다.

## 훈련장

`TrainingGroundWindow`(로비)와 `TrainingGroundResultWindow`(결과)는 신규 창 템플릿의 `ContentWindowView`를 사용한다. 로비는 실제 소유 데이터(`EquipmentViewSource.Owned`)를 읽는다. 가로 화면에서는 두 구역의 제목(개수, 적 추가 버튼)을 고정 탐색 행에 두고 사용 스킬과 등장 적을 각각 독립적으로 스크롤하는 두 열로 놓는다. 사냥 칙령 설정 바로가기는 스킬 열 아래에, 균열 단계 줄(슬라이더)은 적 열 위에 고정한다. 21:9 이상에서는 훈련장 배경 패널이 왼쪽에 붙는다. 스킬 체크와 적 구성을 한 화면에서 함께 보기 위한 배치이며, 세로 화면은 배경 패널·스킬·적을 공통 본문 스크롤 하나에 쌓는다. 적 추가는 같은 창 관리자가 여는 최대 크기 창(`Catalog`)이다. 세팅 편집본은 로비 제어 코드가 소유하고 `GameStore.SaveTrainingGroundSetup`으로 영웅 저장에 보관한다. 스킬별 칙령 수정은 기존 `HuntEdictWindow`와 `GameStore.CommitHuntEdict`를 그대로 쓴다. 결과는 균열 결과처럼 전투 스냅샷(`BattleSnapshot`) 페이지로 열리며 반복 시계를 막지 않는다.

전투 중 DPS 패널과 일시정지 창은 기존 전투 HUD 캔버스(`GameUI`)의 어댑터이고, 그래프는 텍스처 없는 `TrainingDpsChart` 메시를 `TrainingChartView`가 감싼다. `TrainingChartView`는 스킬 사용 시점 아이콘(`SkillIconView`)과 결과 화면의 조사 툴팁(마우스 올림·터치, 세로로 문지르면 페이지 스크롤로 넘김)을 더한다. 글자 없는 버튼(연필·접기·삭제)은 `UiIconButton`, 목록 상자(등급·마릿수)는 `UiDropdown`, 슬라이더는 기존 `SettingsStepSlider`, 스킬별 피해 카드는 균열 결과와 공유하는 `RiftSkillShareView`를 쓴다. 아이콘 그림은 Codex가 그린 흰색 픽토그램(`Resources/Art/TrainingGround/Icons`)에 색을 입혀 쓰며, 새 선 아이콘을 `StorageGlyph`에 더하지 않았다. 글꼴·색·버튼·스킬 아이콘은 `UiFonts`, `UiTheme`, `ContentWindowView.Button`, `SkillIconView`를 공유한다. [구현과 검증](Training_Ground.md)을 따른다.
