# 사냥 칙령 개발 기록

작성일: 2026-09-09 · 로컬 프리셋 5칸 연결 · 핵심 옵션 v0.2와 공유·확장 실행은 개발 중

최신 핵심 옵션 89개·HED2 원본·공유 형식·부분 가져오기·구형 간소화 미리보기와 전체 검사 780개의 결과는 [핵심 옵션 v0.2 개발 기록](Hunt_Edict_V2_Expansion.md)을 따른다. 아래 HED1은 이전 설계의 기록이며, 새 원본의 화면·저장·전투 연결은 개발 중이다.

## 현재 결과

사냥 칙령은 [공통 명세](../Design/HELLSCRIPT_Hunt_Edict_Detail.md)와 [구현 계약](../Design/HELLSCRIPT_Hunt_Edict_Implementation_Contract.md)에 따라 진행한다. HED1 기초 모델과 가져오기 미리보기를 만든 뒤, 기존 `BuildConfig`를 보관하는 로컬 프리셋 5칸·이름 저장 화면을 연결했다. 새 사냥 칙령 원본과 공유 코드는 아직 `GameStore`·실제 전투에 연결하지 않았다. 후속 편집 범위는 총 89개인 [핵심 옵션 v0.2](../Design/HELLSCRIPT_Hunt_Edict_Skill_Option_Catalog.md)를 따른다. 이전 524개 목록과 HED1 검사 결과는 이전 설계의 개발 이력이며 새 옵션의 완료 증거가 아니다.

현재 실행 중인 기존 앱은 마을의 **자동 행동 설계**를 사용한다. 새 사냥 칙령 화면을 확인할 수 있는 빌드는 아직 만들지 않았다. 사용자가 열어 둔 기존 앱을 앞으로 표시해 마을 화면을 확인했으며, 실행 파일을 덮어쓰지 않았다. 이미 완료한 행동 A/B 기능의 별도 실행본과 검증은 [훈련 비교 개발 기록](Training_Comparison_Expansion.md)을 따른다.

## HED1 기초 모델의 구현 범위

| 구성 | 동작 |
|---|---|
| 사용 스킬 배치 | 네 칸 각각에 안정적인 스킬 ID 또는 빈 문자열을 보관한다. 칸 이동과 교체는 전체 규칙의 실행 순서를 바꾸지 않는다. |
| 스킬 보관 설정 | 미장착 스킬의 규칙, 자동 사용 여부와 전용 설정을 남긴다. 다른 스킬을 선택해도 원래 스킬의 설정을 덮어쓰지 않는다. |
| 설정 정의 | 전역 8분류와 공통 우선순위, 기존 조건 22종의 안정적인 선택 ID, 요약안의 일부 스킬 전용 키와 확장 조건 4종을 정의했다. 새 전체 옵션표의 완전한 구현은 아니다. |
| 규칙 제한 | 액티브와 기본 공격은 각각 3규칙, 규칙마다 OR 2묶음·AND 3조건을 검증한다. 현재 실행 가능한 활성 규칙은 24개이며 숨겨진 규칙은 이 수에 포함하지 않는다. |
| 공유 형식 | 현재 개발용 `HED1`은 정규화한 UTF-8 JSON, Base64URL, SHA-256 오류 확인값으로 구성한다. 직업·배치·보관 규칙·설정을 담으며 계정·캐릭터 개인 ID·장비 인스턴스·재화·패시브 장착·이름·시각은 넣지 않는다. |
| 가져오기 미리보기 | 같은 직업의 알려진 미해금 스킬은 그 칸만 비운다. 원래 칸 번호·스킬·해금 레벨을 안내 자료로 남기며 다른 칸을 당겨 채우지 않는다. 전부 빈 구성도 허용한다. |
| 원본 보호 | 가져온 원본과 편집본을 분리한다. 부분 가져오기나 수동 대체는 원본 코드와 현재 영웅을 바꾸지 않는다. 이후 레벨이 올라도 미리보기의 빈칸을 자동으로 채우지 않는다. |
| 잘못된 입력 | 다른 직업, 알 수 없는 스킬·선택값, 새 버전, 누락·추가·중복 필드, 손상된 문자·검사값·UTF-8, 과도한 크기·중첩과 잘못된 숫자를 거부한다. |

`HuntEdict`가 원본 모델과 배치를, `EdictOptions`가 옵션 정의를, `EdictValidation`이 원본 검증을 소유한다. `HuntEdictCodec`은 문자열 변환만 담당하고 `HuntEdictImport`는 영웅의 실제 해금 조건을 바탕으로 미리보기를 만든다. 이 기초 모델을 만든 단계에서는 기존 씬·컨트롤러·전투 소유 경로에 변경을 가하지 않았다.

확장 조건의 저장 성공은 실행 성공을 뜻하지 않는다. 현재 확장 조건을 기존 실행 자료로 바꾸려 하면 명시적으로 미지원 오류를 낸다. 미해금 참조를 포함한 AND 묶음을 실행하지 않는 처리, 다른 OR 묶음의 계속 실행, 회피기·자원 보존의 참조 해제는 후속 실행 연결에서 확인해야 한다.

## HED1 기초 모델의 검사 기록

Unity 6000.6.0f1의 Edit Mode에서 `Hellscript.Tests.HuntEdictTests` **48개가 모두 통과**했다. 최종 실행은 2026-09-09 11:52:32~11:52:33 KST이며 소요 시간은 약 0.652초다. 세 직업의 왕복 복원, 설정·칸 순서의 의미, 미해금·전체 빈칸 가져오기, 원본 불변, 기존 조건 22종, 손상된 입력, 큰 정수와 언어권 독립성, 숨긴 규칙과 기본 공격 상한을 검사했다. [검사 결과](../../Artifacts/Validation/hunt-edict-schema-focused.xml), [실행 로그](../../Artifacts/Validation/hunt-edict-schema-focused.log).

이 시험은 현재 등록된 옵션을 최댓값으로 채우고 각 규칙에 조건을 최대로 넣은 구성이다. 아직 매핑하지 않은 전체 옵션표의 향후 최대 크기까지 보증하지 않는다. 매우 긴 코드의 실제 입력·클립보드 처리는 검사하지 않았으므로 배포 가능한 공유 기능으로 표시하지 않는다.

첫 128KiB 검사에서는 47개 중 44개가 통과하고 최대 크기 3개가 실패했다. 용량을 256KiB로 늘린 뒤 당시 114규칙의 세 직업 구성까지 47개 모두 통과했다. 그 후 새 상세 기획의 기본 공격 3규칙 제한을 반영해 현재 93규칙 구성과 거부 시 원본 불변 검사를 추가했다. [첫 실패 결과](../../Artifacts/Validation/hunt-edict-schema-attempt1.xml)와 [기본 공격 정책 변경 전 결과](../../Artifacts/Validation/hunt-edict-schema-before-basic-cap.xml)는 별도로 보존했다.

현재 소스와 검사 결과의 해시, 기존 소스·보호 자산의 대조 결과는 [소스 기록](../../Artifacts/Validation/hunt-edict-schema-source-manifest.json)과 [검증 요약](../../Artifacts/Validation/hunt-edict-schema-validation-summary.json)에 남긴다. 기존 전체 전투 검사를 이번 새 기능의 통과 수에 합산하지 않는다. 이번 단계는 실제 전투·화면에 연결하지 않았으므로 새 실행본의 화면 검증도 주장하지 않는다.

기존 C# 92개는 모두 동일하고 신규 C#은 6개다. C# 메타 누락과 자산 GUID 중복은 없다. 이전 A/B 단계의 보호 자산 98개와 비교하면 97개는 같고 `ProjectSettings/ProjectSettings.asset` 1개는 다르다. 이번 단계 시작 기록에는 해당 설정 파일의 원문을 별도로 보관하지 않아 변화 전체를 이번 검사 탓으로 확정할 수 없다. 현재 파일에는 기존 AppUI 패키지가 편집기 초기화 시 관리하는 `APP_UI_EDITOR_ONLY` 기호가 있으며, 현재 설정 원문과 Git 차이를 기록하고 임의로 되돌리지 않았다. 씬·프리팹·패키지 파일은 비교 기준과 동일하다.

## 로컬 프리셋 5칸과 이름 저장

기존 슬롯 1~3을 보존하고 4~5를 빈칸으로 추가했다. 일반 편집기·훈련 결과·A/B 결과의 슬롯 선택을 모두 5개로 통일하고 이름 입력과 덮어쓰기 확인을 연결했다. `GameStore.SaveBuildPreset`과 `RenameBuildPresets`는 저장할 계정 사본을 먼저 검증·기록하고 성공한 뒤에만 실제 슬롯 목록을 바꾼다. 저장 실패 시 기존 슬롯과 입력 초안을 유지하며 다시 저장할 수 있다. 이름 변경은 설정·패시브·장비 보호 참조를 바꾸지 않는다.

이 단계는 기존 `BuildConfig`의 로컬 보관 기능이다. 새 스키마의 코드 보관·공유·부분 가져오기까지 완성한 것은 아니다. 이후 `GameController.CommitBuild`를 파일 저장 성공 후 실제 설정을 반영하는 경로로 바꿨다. 실패 시 편집본·전투 상태와 안내 진행을 유지하는 결과는 [현재 설정 저장 개발 기록](Current_Build_Save_Expansion.md)을 따른다. 성공한 설정 변경에서 진행 중 공격을 유지하고 회오리를 정상 경계에서 종료하는 후속 작업은 [전투 동작 보존 기록](Action_Continuity_Expansion.md)에 구분한다. 새 스키마와 액티브 장착 교체까지 완료한 것은 아니다.

프리셋 저장·이름 검증과 기존 훈련·비교를 포함한 초기 집중 검사 104개, 이후 전체 Edit Mode 검사 **682개가 통과**했다. [전체 검사 결과](../../Artifacts/Validation/hunt-edict-storage-editmode.xml)와 [검사 당시 소스](../../Artifacts/Validation/hunt-edict-storage-core-source-manifest.json)를 기준으로 한다. 이후 대화창 배치 변경은 별도 macOS 실행으로 검사하며 이 682개에 포함된 UI 검증으로 표시하지 않는다.

첫 macOS 슬롯 실행과 실제 프로세스 재시작은 5번째 슬롯 저장·이름 변경·실패 후 재시도·불러오기 미리보기·계정 복원을 통과했다. [실행 기록](../../Artifacts/Validation/PresetNativeEvidence/runtime-preset-smoke.txt)은 UI 콜백과 렌더링의 증거다. 시각 검토에서 작은 창의 글자 흐림과 일부 이모지 누락을 발견했으며, 배치 보완과 환경별 검증은 [화면 배치 개발 기록](Screen_Layout_Expansion.md)에 이어서 남긴다. 물리 입력·모바일 키보드는 아직 확인하지 않았다.

## 이어서 구현할 범위

1. [스킬별 핵심 옵션 v0.2](../Design/HELLSCRIPT_Hunt_Edict_Skill_Option_Catalog.md)의 89개 편집 항목을 새 스키마와 고정 실행 판단에 매핑한다. 스킬별 규칙 추가·임의 OR/AND·숨긴 고급 편집기를 제공하지 않는다. 이전 524개 항목 목록은 이력으로 보존하고 현재 구현 대기 목록으로 사용하지 않는다.
2. 기존 추천 구성과 사용자 설정을 보존하는 이관·실행 변환을 만든다. 기존 3칸을 5칸으로 늘리는 로컬 이관은 검사했다. 핵심 옵션으로 정확히 옮길 수 없는 값은 원본을 보존하고 변경·제외 내용을 보여 준 뒤 명시적으로 간소화하여 불러온다.
3. 기존 설정에 연결한 저장 성공 후 적용 경로를 새 핵심 옵션으로 확장한다. 일반 균열의 액티브 교체 시 HP·자원·스킬 ID별 쿨타임·이미 시작한 동작·투사체·장판·덫을 보존한다. A/B의 고정 조건은 유지한다.
4. 연결한 로컬 5칸·이름 저장을 새 스키마·코드와 통합한다. 편집본·현재 저장본·슬롯 복사본을 분리하고, 전체 편집 페이지의 되돌리기·미저장 이탈·복합 변경의 원자적 저장을 확인한다.
5. 스킬 카드, 전역 설정, 부분 가져오기 안내와 공유 입력을 연결한다. 코드 길이를 개선하고 PC·모바일의 실제 복사·붙여넣기·이름 입력을 확인한다.
6. 전역 회피·생존·몰이·추적·회수·자동 정리·탐색·반복과 스킬별 신규 판단을 실제 전투 사건에 연결하고 검증한다.

사냥 칙령 전체와 D3~D6의 완료 여부는 [남은 작업표](../Design/HELLSCRIPT_Remaining_Development_Backlog.md)를 유지한다. 이번 기초 검사 통과로 해당 범위를 완료 처리하지 않는다.
