# 일일 퀘스트

작성일: 2026-10-01

2026-09-30 요청을 반영한 계정 단위 콘텐츠다. 마을·전투의 기존 **이벤트 → 일일 퀘스트**에서 7일/28일 출석과 오갈 수 있다. 자동 로그인 출석 팝업은 기존 두 트랙만 유지한다.

| 활동 | R0–5 목표 | R6–24 목표 | R25 이상 목표 | 심연 주화 |
|---|---:|---:|---:|---:|
| 장비 판매 | 30개 | 40개 | 40개 | 20 |
| 균열 클리어 | 기본 20회 | 기본 12회 | 기본 12회 | 40 |
| 장비 강화 | 2단계 | 2단계 | 1단계 | 15 |
| 상점에서 골드 사용 | 500G | 2,000G | 2,000G | 15 |
| 물약 소비 | 10개 | 15개 | 15개 | 10 |
| **하루 일일 퀘스트 총 지급** | | | | **100** |

각 활동은 하나의 목표만 갖는다. 전체 완료 보너스는 없으며, 기존 출석·최초 클리어 보상까지 하루 100개로 제한하는 기능도 아니다. 달성한 항목은 버튼으로 직접 받는다. 진행률, 수령 완료, 오늘 수령한 총량, 다음 KST 00:00까지의 시간을 표시한다.

## 목표 데이터와 30분 기준

원본은 `Assets/HELLSCRIPT/Resources/Data/DailyQuests.json`이다. 목표·보상·진행 구간·목표 시간·최소 표본·최대 판수를 여기서 조정한다. 다섯 개의 서로 다른 활동, 양수 목표와 보상 합계 100을 검증한다. **당일 처음 준비할 때** 모든 영웅의 최고 클리어로 티어를 선택하고 목표·보상을 저장한다. 그날의 캐릭터 교체, 단계 상승이나 데이터 조정으로 이미 받은 보상을 다시 받을 수 없다.

균열 목표는 `ceil(기본 판수 × max(1, 현재 배속))`이다. 현재 `CombatSpeedAccess`는 1배속만 허용하고 저장·거래 시 다른 배속은 1로 정규화한다. 향후 기존 배속 정책에서 1.5배속을 허용하면 산식상 초보 30회, 중간 18회가 되며 이번 구현이 잠긴 배속을 해금하지 않는다. 최근 정상 승리 기록 10개 안에서 15초 이상 2시간 이하인 실제 클리어 시간 표본이 3개 이상 있으면 `ceil(1800 / 중앙값 초)`까지 상향한다. 최종 상한은 120회다. 시간 조건은 목표 산정에만 쓰며 보상 받기 위해 30분 타이머를 기다리는 조건은 없다. 이미 저장된 당일 목표는 변하지 않는다.

최신 초반 밸런스의 저장된 생산용 시뮬레이션 기록에서 전사 R1–5의 5승은 481.35초, 궁수 516.85초, 마법사 545.50초였다. 전사 R6–10의 5승은 822.50초다. 같은 판당 시간을 유지한다고 **산술 환산**하면 초보 20승은 약 32.09–36.37분, 중간 12승은 약 32.90분이다. 향후 1.5배속이 허용되는 경우 판수를 30/18로 늘려 같은 기준 시간을 목표로 하는 산식이다. 근거는 [초반 균열 밸런스](../Design/HELLSCRIPT_Early_Rift_Balance.md)와 `RiftOnboardingEvidence`의 보존된 기록이며 새 사람이 20/12판을 플레이한 실측이 아니다.

판매·물약·골드 수급은 균열 중 함께 진행되므로 별도 시간을 합산하지 않는다. 강한 장비로 낮은 단계를 반복하거나 당일 배속·장비를 바꾸면 더 빨리 끝날 수 있다. 최근 표본도 다음 플레이를 보장하지 않는다. 초보 실패·튜토리얼·마을 정리는 더 오래 걸릴 수 있다. **실제 플레이 시간 30분 이상은 보장하지 않으며**, 후반 전 단계와 모바일 실기기의 자연 진행 시간도 아직 측정하지 않았다.

기존 균열 피로도는 하루 무료 120분이다(`RiftEntryRules.DailyMinutes`). 통상 32–36분 기준은 이 예산 안에 있으며 유료 회복·입장이나 새 대기 조건을 요구하지 않는다. 다른 플레이로 이미 피로도를 소모했거나 실패/긴 전투가 많으면 그날 모든 목표 완료를 보장하지 않는다. 기존 피로도 정책도 바꾸지 않았다.

첫 다섯 균열의 저장된 획득량은 직업별 32–33개, 실제 물약 소비는 28–41개였다. 판매 30/40개와 소비 10/15개는 자연 진행 일부만 요구한다. 무료 시작 물약은 기존 수량을 유지한다. 초반 상점 지출은 500G로 낮추고, 강화는 기존 해금 이후에만 가능하다. 균열 목표 진행 중 해금할 수 있으며 해금을 우회하지 않는다. 1레벨 장비 첫 두 강화의 비용은 226G지만 20레벨은 12,315G, 60레벨은 86,205G로 올라가므로 고레벨 구간은 한 단계만 요구한다. 현재 캐릭터의 저단계 여분 장비도 가능하다. 모든 장비가 최대 강화라면 목표를 강제로 진행시키지 않으며 신규 장비 획득·해금이 필요하다. 사용자 기존 강화 비용·드랍·구매 정책은 바꾸지 않았다.

## 성공한 이벤트의 범위

- 판매: 소유권과 잠금/착용/프리셋/소켓 보호를 검증한 뒤 장비 한 개가 실제 제거되고 골드를 받은 때. 가방·창고·자동 판매를 포함하며 분해·버리기는 제외한다.
- 균열: 생산용 `CombatSimulation.Finish`에서 정상 승리로 전리품 정리를 마친 때. 동일 런 기록 중복, 실패, 중도 귀환, 훈련·튜토리얼은 제외한다. 일시중단/복원 자체는 카운트하지 않는다.
- 강화: 검증된 가격으로 완료한 장비 강화 단계. +10 실행이 실제 열 단계를 완료하면 열 단계다. 취소·오래된 견적·재호출·재련·부위 강화는 제외한다.
- 골드: 장비 상점·되사기·마을 장비/보석/룬·미확인 장비·유료 물약 보충의 실제 결제 가격. 자동 판매 환급 후 순 골드 차이를 사용하지 않는다. 강화·재련·제작 비용, 무료 최초 물약은 제외한다.
- 물약: 실제 재고를 소비한 정상 균열 물약. 사용 실패·쿨다운·재고 없음·훈련·튜토리얼을 제외한다. 재생·로딩·미리보기는 진행을 추가하지 않는다.

금융 거래에서 진행과 골드/아이템은 같은 `GameStore.Transact` 저장 단위다. 거절이나 저장 실패면 함께 롤백한다. 전투의 소비/승리는 기존 계정과 전투 저장 흐름을 따른다. 진행은 목표에서 멈추며 별도 UI 갱신이 소비를 만들지 않는다. 복제한 미리보기 계정에는 진행 시계가 연결되지 않는다.

## 초기화·영속성

출석의 `AttendanceClock`, `Attendance.Day`와 `RiftEntryRules.Midnight`를 그대로 재사용한다. 현재 구현은 UTC 기기 시각을 KST 일자로 계산하는 로컬 개발 저장 경계다. 새 서버 인증이나 자격증명, 임의의 서버 시간 체계는 추가하지 않았다. 기기 시계 조작에 대한 서버 권위 검증은 기존 출석과 마찬가지로 별도 운영 경계다.

자정 이후 다음 실제 이벤트/로그인/열린 창 갱신에서 새 세트를 준비한다. 접속하지 않은 날의 진행·보상을 소급 지급하지 않는다. 이전 날짜로 돌아가면 진행과 수령을 거절한다. 수령은 날짜+항목의 안정된 거래 ID, 저장된 `claimed`, 100개 상한을 함께 검사한다. 오래된 창은 다음 날 보상을 받지 못한다. 거래 영수증이 정리돼도 `claimed`가 중복 지급을 막는다. 재접속·앱 재시작·캐릭터 교체로 지갑과 수령 상태를 유지한다.

저장 스키마는 20이며 이전 저장의 계정 재화와 장비를 보존해 빈 일일 상태를 추가한다. 지원하지 않는 미래/손상 일일 상태는 원본을 보존하고 불러오기를 중단한다. 이전 게임 버전은 신규 스키마를 거부하므로 새 상태를 잃은 뒤 보상을 다시 지급하는 다운그레이드를 방지한다. 코드 되돌림만으로 신규 저장을 이전 스키마에 쓰지 않는다.

## 구현과 검증 경로

핵심 소유자는 `DailyQuests`, `GameStore.DailyQuests`다. `DailyQuestWindow`는 신규 창 생성기로 만든 `ContentWindowView`를 사용하고 기존 `UiTheme`, `UiFonts`, 공통 탭/버튼/창 호스트/스크롤을 따른다. 뷰는 거래 명령만 보낸다. 골드/소비 훅은 기존 성공 지점에 연결한다. 한국어·영어를 함께 제공한다.

`DailyQuestTests`는 데이터 합계·티어·배속·기간 고정·정확한 성공 이벤트·판매/강화/구매 실패·저장 실패 재시도·동일 날짜 반복·자정·오프라인·시계 역행·캐릭터 변경·미래 상태 보존을 검사한다. 개발 전용 `RuntimeDailyQuestSmoke`는 독립 저장에서 실제 거래 경로, 수령/초기화, KO/EN 세로·가로·작은 화면의 잘림/고정 행동/레이캐스트 버튼/목록 드래그와 새 프로세스 재시작을 검사한다. 합성 입력은 물리 모바일 터치를 증명하지 않으며 합성 전투 fixture는 사람의 30분 플레이 검증이 아니다. 최종 실행 결과는 [최적화·통합 검증](Optimization_20260930.md)에 남긴다.
