# 일일 퀘스트

2026-10-01 사용자 결정에 따라 모든 계정에 같은 다섯 미션과 같은 목표를 매일 제공한다. 출석 이벤트 창의 일일 퀘스트 탭에서 확인하고 보상을 직접 받는다.

## 고정 목표 데이터와 기존 저장

원본은 `Assets/HELLSCRIPT/Resources/Data/DailyQuests.json`의 버전 2다. 각 활동에 하나의 `target`과 `reward`가 있다. 서로 다른 다섯 활동, 양수 목표와 보상 합계 100을 검증한다. 목표 수치의 조정은 모든 계정에 공통인 데이터 변경으로만 한다.

이미 준비된 버전 1의 당일 미션도 기존 저장 거래를 통해 고정 목표로 전환한다. 날짜·지갑·수령 완료와 보상은 유지한다. 미완료 항목의 누적 진행은 새 목표까지 보존하고, 이미 달성했거나 수령한 항목은 새 목표에서도 완료로 유지한다. 이전 준비 영수증이 전환을 건너뛰지 않도록 준비 거래 ID에 데이터 버전을 포함한다. 창을 열 때, 실제 활동이 저장될 때와 보상을 받을 때 전환하며 저장 실패는 원본 상태를 보존하고 재시도할 수 있다. 전환 자체는 보상을 지급하지 않는다.

모든 날의 목표는 같은 30/20/2/500/10이다. 플레이 시간·전투 배속·장비·최근 기록에 따른 목표 증가나 대기 시간은 없다. 기존 피로도, 판매·강화·구매 가격, 보급·물약 소비와 콘텐츠 해금 규칙을 그대로 사용한다.

## 성공한 이벤트의 범위

- 판매: 소유권과 잠금/착용/프리셋/소켓 보호를 검증한 뒤 장비 한 개가 실제 제거되고 골드를 받은 때. 가방·창고·자동 판매를 포함하며 분해·버리기는 제외한다.
- 균열: 생산용 `CombatSimulation.Finish`에서 정상 승리로 전리품 정리를 마친 때. 동일 런 기록 중복, 실패, 중도 귀환, 훈련·튜토리얼은 제외한다. 일시중단/복원 자체는 카운트하지 않는다.
- 강화: 검증된 가격으로 완료한 장비 강화 단계. +10 실행이 실제 열 단계를 완료하면 열 단계다. 취소·오래된 견적·재호출·재련·부위 강화는 제외한다.
- 골드: 장비 상점·되사기·마을 장비/보석/룬·미확인 장비·유료 물약 보충의 실제 결제 가격. 자동 판매 환급 후 순 골드 차이를 사용하지 않는다. 강화·재련·제작 비용, 무료 최초 물약은 제외한다.
- 물약: 실제 재고를 소비한 정상 균열 물약. 사용 실패·쿨다운·재고 없음·훈련·튜토리얼을 제외한다. 재생·로딩·미리보기는 진행을 추가하지 않는다.

금융 거래에서 진행과 골드/아이템은 같은 `GameStore.Transact` 저장 단위다. 거절이나 저장 실패면 함께 롤백한다. 전투의 소비/승리는 기존 계정과 전투 저장 흐름을 따른다. 진행은 목표에서 멈추며 별도 UI 갱신이 소비를 만들지 않는다. 복제한 미리보기 계정에는 진행 시계가 연결되지 않는다.

## 초기화·영속성

출석의 `AttendanceClock`, `Attendance.Day`와 `RiftEntryRules.Midnight`를 그대로 재사용한다. 현재 구현은 UTC 기기 시각을 KST 일자로 계산하는 로컬 개발 저장 경계다. 새 서버 인증이나 자격증명, 임의의 서버 시간 체계는 추가하지 않았다. 기기 시계 조작에 대한 서버 권위 검증은 기존 출석과 마찬가지로 별도 운영 경계다.

자정 이후 다음 실제 이벤트/로그인/열린 창 갱신에서 새 세트를 준비한다. 접속하지 않은 날의 진행·보상을 소급 지급하지 않는다. 이전 날짜로 돌아가면 진행과 수령을 거절한다. 수령은 날짜+항목의 안정된 거래 ID, 저장된 `claimed`, 100개 상한을 함께 검사한다. 오래된 창은 다음 날 보상을 받지 못한다. 거래 영수증이 정리돼도 `claimed`가 중복 지급을 막는다. 재접속·앱 재시작·캐릭터 교체로 지갑과 수령 상태를 유지한다.

저장 스키마는 20이며 이전 저장의 계정 재화와 장비를 보존해 빈 일일 상태를 추가한다. 지원하지 않는 미래/손상 일일 상태는 원본을 보존하고 불러오기를 중단한다. 이전 게임 버전은 신규 스키마를 거부하므로 새 상태를 잃은 뒤 보상을 다시 지급하는 다운그레이드를 방지한다. 코드 되돌림만으로 신규 저장을 이전 스키마에 쓰지 않는다.

핵심 소유자는 `DailyQuests`, `GameStore.DailyQuests`다. `DailyQuestWindow`는 신규 창 생성기로 만든 `ContentWindowView`를 사용하고 기존 `UiTheme`, `UiFonts`, 공통 탭/버튼/창 호스트를 따른다. 본문은 아래 고정 배치 어댑터를 사용한다. 뷰는 거래 명령만 보낸다. 골드/소비 훅은 기존 성공 지점에 연결한다. 한국어·영어를 함께 제공한다.

## 스크롤 없는 고정 배치 — 2026-10-01

승인한 [HTML 시안](../../Prototypes/DailyQuests/HELLSCRIPT-DailyQuests.html)을 기존 `DailyQuestWindow`에 적용한다. 시연 상태·기기 선택 도구는 게임에 포함하지 않는다. `ContentWindowView`와 `ContentWindowHost`가 제목·닫기·출석 탐색·고정 행동·안전 영역·뒤로가기를 계속 소유한다. 창 최대 크기를 1200×1600으로 조정해 세로 공간을 사용한다.

균열 결과창처럼 일퀘 본문의 `VerticalLayoutGroup`, `ContentSizeFitter`, `ScrollRect`만 비활성화하고 본문을 가용 영역에 고정한다. 세로는 보상 요약·다섯 카드·공통 규칙, 가로는 요약 아래 3×2(판매/균열/강화, 골드/물약/규칙)다. 실제 창 비율로 방향을 결정하고 공통 배율 위에 전체 본문에 하나의 비례 단위를 적용한다. 작은 가로 화면도 같은 배치이며 스크롤 예외·글자 크기 설정·공통 창 API 변경은 없다.

요약은 저장된 수령 주화·달성한 목표 수·현재 일자의 수령 가능한 보상 합계를 읽는다. 준비 실패 시 빈 상태와 재시도 설명을 표시하며, 거래 오류·성공 안내는 고정된 별도 공간에 둔다. 진행 중은 비활성, 수령 가능은 공통 초록 강조, 수령 완료는 체크와 비활성 버튼이다. 보상은 기존 `ClaimDailyQuest` 거래의 저장 성공 뒤에만 바뀐다. 저장 실패·날짜 변경·시계 역행·중복 클릭 규칙과 고정 목표·합계 100개·해금·저장 스키마를 바꾸지 않는다. 방향·언어·드래그는 계정 상태를 바꾸지 않는다.

`UiTheme`/`UiFonts`/공통 버튼을 사용하고 주화 그림은 `CurrencyIconView`의 기존 심연 주화 자산이다. 활동 표식은 승인한 SVG를 기존 `StorageGlyph`의 다섯 `daily-*` 경로로 옮겼다. 새 래스터 이미지는 없다. 압축 설명과 요약 문구는 기존 번역 표에 한국어·영어를 함께 등록한다.

`RuntimeDailyQuestSmoke`에서 클릭 전 자동 스크롤과 목록 스크롤 성공 검사를 제거했다. 모든 카드·문구·버튼의 프레임/본문 내 노출, 레이캐스트 적중, 카드·문구 겹침, 드래그 뒤 위치 유지, 실제 상태 요약을 검사한다. 기본 글자 크기에서 6개 화면(440×956, 956×440, 1440×810, 1440×900, 1680×720, 640×360) × KO/EN × 안전 영역 유무 × 시작/혼합/모두 달성/모두 수령/빈 상태를 검사한다. 표시 fixture는 독립 저장의 시각 검사만을 위한 것이며 실제 지급 검사는 별도로 성공한 활동 거래·개별 수령·저장 실패 후 재시도·자정·시계 역행·7일/28일 탭 왕복·닫기/뒤로가기·새 프로세스 복원으로 검증한다.

최종 검증은 마지막 코드와 `main` 통합 뒤 전체 Edit Mode와 필요한 macOS 일퀘/출석 스모크를 한 번으로 묶는다. 실패하면 실패 항목과 직접 영향 범위만 다시 확인한다. 모바일 실기기와 WebGL 재배포는 별도 범위다. 실제 완료 결과와 캡처는 최종 검증 후 아래 기록에 추가한다.
