# 사냥 칙령 v0.2 공격 순서·자동 사용 전투 연결 개발 기록

작성일: 2026-09-11 · P0 전투 연결 2/3 · 규칙 판단 순서와 자동 사용 반영

## 적용 범위

[전역 정책 연결](Edict_Policy_Expansion.md)에 이어 원본의 공통 공격 순서, 공통 행동 우선순위, 스킬별 자동 사용을 규칙 판단에 연결한다. 기존 규칙 편집기의 규칙은 그대로 두고, 사냥 칙령이 켜진 영웅에게는 그 규칙을 검사하는 순서와 검사 여부를 원본이 정한다.

## 연결 방식

기존 판단은 `State.build.rules`를 적힌 순서대로 검사해 실행 가능한 첫 규칙을 고른다. 이제 검사 전에 `EdictRuleOrder.Order`가 순서를 정한다. 원본이 없으면 적힌 순서와 같고 어느 규칙도 건너뛰지 않으므로 꺼진 상태의 동작은 그대로다.

원본이 있으면 세 겹으로 정렬한다.

| 겹 | 기준 |
|---|---|
| 분류 | `common.order`의 순서다. 스킬·기본 공격 규칙은 공격, 회수 규칙은 회수, 상자·탐색 규칙은 탐색 자리에 놓는다. 회수는 어느 등급이든 전투 중 우선으로 회수하면 우선 회수 자리에, 아니면 전투 후 회수 자리에 놓는다. |
| 공격 안 순서 | 공통 공격 순서에서 그 스킬이 차지한 자리다. 기본 공격도 이 순서에 들어 있다. |
| 적힌 순서 | 같은 스킬의 여러 규칙은 원래 순서를 지킨다. |

정렬은 규칙 객체를 바꾸지 않고, 각 규칙이 원래 몇 번째 행인지도 함께 돌려준다. 그래서 판단 기록의 “N번 규칙이 먼저 실행됩니다”는 여전히 편집기의 행을 가리킨다.

자동 사용을 끈 스킬의 규칙은 검사하지 않는다. 대신 `EDICT_OFF` 코드와 사유를 판단 기록에 남겨 왜 그 규칙이 쓰이지 않는지 읽을 수 있게 했다. 기본 공격도 자기 자동 사용 스위치를 따른다. 미장착 스킬은 기존 `NOT_EQUIPPED` 처리를 그대로 거친다.

긴급 생존과 회피는 [전투 연결](Edict_Drive_Expansion.md)에서 규칙 판단보다 먼저 실행되므로 `common.order`의 앞 두 항목은 이미 그 위치에 있다.

## 검증

전체 Edit Mode 검사 **1,104개**가 통과했다. 이 중 순서 연결 검사는 10개다.

| 검사 | 확인한 결과 |
|---|---|
| 원본 없음 | 적힌 순서와 행이 그대로이고 건너뛰는 규칙이 없다. |
| 공격 순서 | 원본에서 앞으로 옮긴 스킬의 규칙이 먼저 오고 행 번호는 원래 규칙을 가리킨다. |
| 자동 사용 끔 | 해당 규칙은 사유와 함께 남되 검사 대상에서 빠진다. 기본 공격도 같다. |
| 회수 자리 | 기본값에서는 공격 뒤, 어느 등급이든 전투 중 우선이면 공격 앞에 놓인다. |
| 공통 우선순위 | 탐색을 공격 앞으로 옮기면 탐색 규칙이 먼저 검사된다. |
| 불변 | 정렬이 규칙 객체를 바꾸지 않는다. |
| 실제 시전 중단 | 조건 없는 두 규칙에서 원본이 화염구를 끄면 400틱 동안 화염구 시전이 0회이고 연쇄 번개는 계속 쓰이며 `EDICT_OFF`가 기록된다. |
| 실제 첫 시전 | 사거리·비용이 같은 두 규칙에서 적힌 순서는 화염구를, 원본이 연쇄 번개를 앞세운 실행은 연쇄 번개를 먼저 시전한다. |
| 결정성 | 같은 순서의 두 실행이 같은 상태에 도달한다. |

`Artifacts/Validation/edict-order-final-editmode.xml`에 보고서를 보존했다.

두 실전 검사는 처음에 기존 마법사 추천 설정으로 썼다가 실패했다. 추천 설정의 화염구 규칙에는 밀집 조건이 있어 단일 적에게는 쓰지 않기 때문이다. 기능 결함이 아니라 검사 전제의 오류였으므로 조건 없는 두 규칙으로 고정했다.

## 남은 범위

| 남은 항목 | 내용 |
|---|---|
| 조준 | `PlanEdictAim`의 결과가 시전 명령에 전달되지 않는다. 다음 단계다. |
| 규칙 조건 | 규칙의 조건식은 여전히 기존 편집기의 것이다. 원본의 스킬별 핵심 옵션 가운데 사용할 상황·우선 대상 같은 값은 아직 조건에 반영되지 않는다. |
| 회수 세부 | 우선 회수와 전투 후 회수의 구분은 규칙 자리로만 반영된다. 회수 규칙 자체의 조건은 바뀌지 않는다. |
| 실제 앱 확인 | Edit Mode 검사로만 확인했다. |
