# HELLSCRIPT 창고 UI 구현

갱신일: 2026-09-20 · 최초 작성일: 2026-09-16 · [English](Storage_UI.en.md)

현재 화면은 [HTML 기준 창고 UI 적용 기록](Storage_Reference_Parity.md)의 2026-09-20 구현을 따른다. 데이터·이동·구매·프리셋 정책은 유지한다. 아래의 화면 설명·검증 표·캡처는 2026-09-16 당시 기록이며, 최신 외형과 검증 결과는 연결 문서에서 확인한다. 기존 스킨 대신 `StorageSurface`와 `StorageGlyph`를 사용하고, 정렬은 펼침 목록으로 바뀌었다. 보관함 이름 변경과 기록·안내 기능도 추가했다.

상태: 데스크톱 개발 빌드에서 구현·검증을 마쳤다. 실기기(휴대폰·태블릿)에서는 확인하지 않았다. 검증 항목과 미수행 항목은 아래 [검증](#검증)에 구분해 적었다.

## 목표와 범위

계정 공용 창고와 현재 영웅의 소지품을 한 화면에 두고, 두 목록 모두 한 줄에 8칸인 정사각 슬롯 그리드로 보여 준다. 가로 화면은 `창고 | 중앙 이동 조작 | 소지품`, 세로 화면은 `창고 → 이동 조작 → 소지품`이다. 특정 휴대폰 해상도나 고정 화면 비율을 강제하지 않고, 사냥 칙령 창과 같은 방식으로 실제 안전 영역에 맞춰 배율을 정한다.

첨부된 `HELLSCRIPT-Storage-Reference.html`은 외형과 조작의 기준으로만 썼다. 아이템의 이름·이미지·능력치·옵션·등급·장착 부위·룬 블럭·보석은 모두 프로젝트의 기존 정의(`ItemCatalog`, `GemCatalog`, `RuneMasteryCatalog`)와 실제 보유 인스턴스에서 읽는다. HTML의 예시 배열, `localStorage`, 시연 도구, 캐릭터 소개 줄, 검색 입력창은 옮기지 않았다.

## 데이터 구조와 저장

- `Item.storageTab`, `Item.storageSlot`: 컨테이너 안의 실제 칸. 소지품은 탭이 하나이므로 `storageSlot`만 쓰고, 창고는 탭 0~4와 칸을 함께 쓴다. 착용 중인 장비는 칸을 차지하지 않으므로 `storageSlot = -1`이다.
- `Item.origin`: 착용되기 직전에 있던 보관처(`bag:0:12`, `warehouse:2:7`). 프리셋 교체로 해제될 때 이 위치로 돌아간다. 값이 없으면 현재 영웅의 소지품 첫 빈칸으로 돌아간다.
- `AccountSave.warehouseCapacity`: 탭별 구매 정원 5개. 0은 잠긴 탭이다. 새 계정은 `{50,0,0,0,0}`이다.
- `AccountSave.premium`: 유료재화 잔액.
- 위치 규칙은 `Core/Storage.cs`의 `Storage` 한 곳에서만 쓴다. `GameStore.Normalize`가 불러오기와 모든 거래의 스테이징에서 `Storage.Normalize`를 호출해 빠진 칸·중복 칸을 고치고, `ValidateItems`가 `Storage.Validate`로 중복을 거부한다.
- 획득(`Economy.AddItem`, `TownTrade.BuyEquipment`)은 첫 빈칸을 배정하고, 수동 장착(`Economy.Equip`)은 들어오는 장비의 칸을 빠지는 장비에 그대로 넘긴다.

### 기존 저장 호환

- 위치 필드가 없는 저장은 불러올 때 목록 순서대로 첫 빈칸을 배정한다. 아이템은 하나도 삭제하지 않는다.
- 이전 규칙(창고 400칸 상수)으로 50개를 넘게 보관한 저장은 1번 탭의 임시 초과 칸에 그대로 둔다. `52 / 50`처럼 표시되며 꺼내기와 확장 구매는 가능하고 일반 입고만 막힌다. 구매 권한을 새로 부여하거나 박탈하지 않았다.
- `warehouseCapacity`가 손상된 저장은 10 단위·50~100으로 맞추고, 순서가 비면 앞 탭을 기본 50칸으로 채워 어떤 탭도 잠그지 않는다.
- 스키마 번호는 올리지 않았다. 새 필드는 `JsonUtility` 기본값으로 읽히며 이전 빌드가 이 저장을 읽어도 알지 못하는 필드를 무시한다.

## 구매와 확장

| 탭 | 초기 | 개방 비용 | 10칸 확장 1회 | 정원 |
|---|---|---:|---:|---|
| 1 | 개방 | 무료 | 골드 1,000 | 50→100 |
| 2 | 잠김 | 골드 5,000 | 골드 5,000 | 50→100 |
| 3 | 잠김 | 골드 100,000 | 골드 50,000 | 50→100 |
| 4 | 잠김 | 유료재화 500 | 유료재화 100 | 50→100 |
| 5 | 잠김 | 유료재화 2,000 | 유료재화 500 | 50→100 |

값은 `StorageRules`에만 있고 UI와 로직이 함께 읽는다. 2→3→4→5 순차 개방이며 이전 탭의 확장은 필요 없다. 확장은 같은 탭에서 회차와 무관하게 고정 비용이고 탭마다 독립적으로 5회까지다. 확장 전용 칸은 빈칸을 포함한 마지막 보관 칸 다음(임시 초과 칸이 있으면 그 뒤)에 하나만 두며, 선택·드래그 출발·드롭·집계에서 제외하고 100칸이 되면 사라진다. 승인창은 비용·보유·승인 후 잔액·확장 전후 정원을 보여 주고, 승인한 순간에만 잔액과 현재 정원을 다시 검증한다(`ExpandStorageTab`은 확인창이 본 정원을 함께 전달해 오래된 확인이 두 번째 단계를 사지 못하게 한다). 취소·재화 부족·중복 클릭은 차감하지 않는다.

## 이동 규칙

- 개별 이동: 상세창의 `꺼내기`/`창고에 넣기`는 반대편에서 현재 선택한 탭의 실제 첫 빈칸으로 옮긴다.
- 지정 칸 드롭: 빈칸이면 그 칸으로, 아이템이 있으면 두 자리를 한 거래로 교환한다. 대상 아이템은 끌어온 아이템의 원래 칸으로 간다. 같은 보관함 안, 창고↔소지품, 창고 탭 사이 모두 같다.
- 탭 버튼·패널 여백 드롭: 해당 탭의 첫 빈칸. 잠긴 탭, 확장 칸, 화면 밖은 취소.
- 일반 만석(50/50)은 1:1 교환이 가능하고 빈칸 입고는 불가하다. 초과 탭은 외부 입고와 되돌아오는 교환을 막고, 꺼내기와 같은 탭 안의 자리 정리(칸 수가 늘지 않는 경우)만 허용한다. 빈 임시 초과 칸에는 놓을 수 없다.
- 일반 이동은 임시 초과 칸을 만들 수 없다. 예외는 프리셋 자동 복귀만이다.
- 일괄 이동: 중앙 버튼이 `일괄 이동 → 일괄 이동 취소(0개) → 옮기기(1개 이상)`로 바뀐다. 첫 선택 쪽으로 방향이 고정되고 반대쪽을 누르면 정확히 `이동은 한쪽으로만 가능합니다`를 표시하며 기존 선택을 유지한다. 목적지에 전체를 넣을 수 없으면 한 개도 옮기지 않는다. 전체 선택은 현재 탭의 표시 항목만 대상이며 숨은 선택 수를 알린다. 선택이 있으면 출발지 탭은 바꿀 수 없고 목적지 탭은 바꿀 수 있다.
- 정렬은 표시 순서만 바꾼다. 분류 전체·등급 전체·정렬된 화면에서 지정 칸 드롭에 성공하면 그때의 화면 순서를 실제 칸에 반영(`Storage.Reorder`)한 뒤 위치순으로 전환한다. 취소된 드래그는 아무것도 바꾸지 않는다. 필터 중에는 보이는 아이템의 실제 칸을 대상으로 하며 숨은 아이템을 빈칸으로 보이지 않는다.
- 잠금은 파괴 방지이며 이동을 막지 않는다. 잠금·옵션·강화·보석·프리셋 참조는 이동 후에도 같은 인스턴스에 남는다.

## 프리셋 적용과 장비 복귀

`GameStore.ApplyEquipmentPreset`이 영웅 프리셋 슬롯의 `equipmentIds`를 하나의 거래로 적용한다.

1. 등록 ID를 소지품과 창고에서 찾는다. 중복 등록·같은 부위 두 개는 거부한다. 없는 장비는 `missing`, 다른 캐릭터가 들고 있거나 레벨·직업 조건에 맞지 않는 장비는 `unusable`로 보고하고 그 부위는 비운다.
2. 새로 착용할 장비를 보관처에서 먼저 모두 꺼내며 각자의 출발 위치를 `origin`에 기록한다. 그대로 유지되는 장비는 건드리지 않는다.
3. 유지되지 않는 착용 장비를 해제한다. 등록이 없는 부위의 장비도 해제한다.
4. 해제된 장비는 자기 `origin`으로 돌아간다. 그 칸이 차 있으면 같은 탭의 첫 빈칸, 탭이 가득 차 있으면 임시 초과 칸이다. 예: 검 A가 창고 2번 탭에서 착용됐고 소지품의 검 B로 교체하면, A는 소지품이 아니라 창고 2번 탭으로 돌아간다.
5. 마지막에 모든 컨테이너의 초과 칸을 정리하고 저장한다.

등록 장비가 하나도 없는 프리셋은 적용하지 않는다(영웅을 빈손으로 만드는 대신 거부). 장착 변경은 기존 정책대로 성소에서만 가능하고 균열 진행 중에는 거부하며, 균열 중 창고↔소지품 이동은 허용한다. `현재 장비 등록`은 착용 중인 인스턴스 ID를 그 슬롯의 `equipmentIds`에 쓰고, 같은 슬롯의 사냥 칙령 프리셋에도 같은 목록을 쓴다.

## 임시 초과 수납

구매 정원과 실제 보유량을 분리한다. 51개면 `51 / 50`으로 표시하고 분모는 늘리지 않는다. 초과는 그 탭에만 적용되며 다른 탭은 정상이다. 초과 탭도 확장 구매를 허용해 `52/50`이 `52/60`이 되면 제한이 풀린다. 사용량이 정원 이하로 내려오면 표시와 제한이 사라진다. 정리(`Storage.Settle`)는 임시 칸의 아이템을 빈 정규 칸으로 옮기고 남은 임시 칸을 연속 번호로 다시 붙일 뿐, 정규 칸의 사용자 배치는 압축하지 않는다.

## 화면

`Presentation/StorageWindow.cs`(배치·그리드·탭·분류·중앙 조작), `StorageWindow.Drag.cs`(셀 입력·드래그), `StorageWindow.Dialogs.cs`(상세·구매·확장·프리셋·등급 목록)로 나눴다. 사냥 칙령 창처럼 별도 캔버스(정렬 320)에 그리고, 안전 영역 대비 기준 크기(가로 844×390, 세로 430×840)로 배율을 구한 뒤 논리 크기 = 안전 영역 ÷ 배율로 전체 화면을 쓴다.

- 헤더: 제목, `계정 공용 창고 · {직업} 소지품`, 균열 중이면 `일시정지 · 남은 시간`, 닫기. 캐릭터 소개 줄·검색창은 없다.
- 패널 머리줄: 이름, `사용 / 정원`(초과 시 `초과`), 등급 체크 버튼, 정렬 순환 버튼, 소지품에는 작은 `프리셋` 버튼.
- 창고 탭 1~5: 잠긴 탭은 비용 또는 `순차 개방`, 초과 탭은 `!`.
- 분류 7개: 전체·무기·방어구·장신구·재료·룬 블럭·보석. 무기=부위 0, 방어구=1~5, 장신구=6~7.
- 그리드: 8열, 칸 크기 = (폭 − 간격×7) ÷ 8, 각각 독립 세로 스크롤. 탭·필터·중앙 버튼은 스크롤에 밀리지 않는다.
- 셀: 실제 장비 아이콘, 등급색 테두리, 강화·레벨, 잠금 글리프, 선택 모드의 오른쪽 위 체크박스, 초과 표시.
- 중앙 조작(가로는 세로 막대, 세로는 한 줄): 방향·선택 수·여유 칸, 3상태 버튼, 선택 해제.
- 하단: 골드·유료재화 잔액.
- 등급 목록은 버튼 아래 오버레이 체크박스(전체 선택 부분 상태·5등급·개수·표시 수). 체크 즉시 반영하고 열린 채로 여러 번 바꿀 수 있다. 바깥 누름·Esc로 닫고 상태는 유지한다. 창고·소지품은 각자 상태를 가진다.
- 상세창: 실제 이름·등급·직업 제한·부위·아이템 레벨·요구 레벨·주능력·접사(티어)·품질·소켓·전설/세트 설명·보호 상태·현재 위치·이동 목적지, `꺼내기/창고에 넣기`, 잠금 토글, 현재 장비와 전체 시트 비교.
- 재료·룬 블럭·보석 분류: 계정 공용 재고를 창고 패널에 표시(소지품 패널은 `계정 공용 보관 · 소지품에는 없습니다`). 상세는 실제 정의를 읽는다.
- 탭·분류·등급·정렬·일괄 선택은 `GameUI.storageStates`에 영웅별로 남아 회전·재진입에도 유지된다. 기존 인벤토리 화면의 필터도 세션 메모리에만 두므로 같은 정책이다.

## 입력

- 마우스: 누른 채 끌면(uGUI 드래그 문턱) 집어 든다. 터치: 0.24초 이상 누른 뒤 끌면 집어 들고, 그 전에 움직이면 목록 스크롤로 넘긴다. 셀은 시작 판정만 하고, 들고 있는 동안은 창이 포인터를 직접 읽어 패널을 다시 그려도 제스처가 끊기지 않는다.
- 개방된 창고 탭 위에서 연속 1초 머무르면 탭이 열린다(고정값 `TabHoverSeconds`). 벗어나거나 다른 탭으로 가면 대기가 초기화된다. 이 단계는 탭 전환만 하며 출발 컨테이너·탭·칸은 시작 시 값으로 유지된다.
- 잡은 썸네일·목적지 이름·판정 문구가 따라다니고, 대상 칸·패널은 유효(초록)/교환(황금)/불가(적갈)로 강조된다. 미리보기 레이어는 포인터를 가로채지 않는다.
- 목록 가장자리에 0.15초 머무르면 자동 스크롤한다. Esc·창 닫기·화면 크기 변경·잘못된 드롭은 취소한다. 드롭 직후 상세창이 덧열리지 않는다.
- 드래그는 한 아이템(또는 한 묶음)만 옮긴다. 일괄 선택이 남아 있으면 반대편 빈칸 이동만 허용하고 교환·같은 쪽 정리는 거부한다.

## 일시정지

마을·균열·전투 어디서나 열 수 있다. 균열에서 열면 `RunState.paused = true`로 전투와 던전 시간이 함께 멈추고(`GameController.Update`는 `paused`이면 시뮬레이션을 진행하지 않는다), 닫을 때는 열기 전 값으로 되돌려 다른 화면의 정지 이유를 덮어쓰지 않는다. 창 자체의 대기시간·자동 스크롤·토스트는 `Time.unscaledTime`으로 동작한다. 창고 개방과 프리셋 교체는 회복·쿨타임을 바꾸지 않으며, 창고 체류 시간은 미실행 보상으로 계산되지 않는다(`lastSeenUtc`는 저장 시각만 기록).

## 검증

Edit Mode 검사는 `Tests/Editor/StorageTests.cs` 22개를 추가했다. 새 계정 초기 상태, 위치 없는 기존 저장의 무손실 이관, 손상된 정원 배열 복구, 순차 구매·고정 비용·중복 요청 무차감, 재화 부족 거부, 탭별 독립 확장과 100칸 상한, 첫 빈칸 이동, 지정 칸 이동과 원자적 교환, 만석 교환, 초과 탭의 입고·교환 차단과 출고·정리, 확장으로 초과 해소, 전체-또는-무 일괄 이동, 정렬 화면 고정 후 드롭, 필터·정렬의 무변경, 수동 장착의 칸 인계, 창고에서 착용하고 원래 보관처로 복귀, 만석 복귀의 임시 초과, 누락·사용 불가 등록의 빈 부위, 균열 중 프리셋 거부와 쓰기 실패의 무변경, 프리셋 등록, 자동 정리의 첫 개방 탭 보관, 중복 배치 검증, 이동 전후 ID 집합·수량·속성 보존을 확인한다.

### 미수행과 제약

- 실기기(iOS·Android)의 물리 터치, 실제 노치·홈 바, 키보드 조작은 확인하지 않았다. 안전 영역은 `UiSafeArea`를 통해 계산되며 데스크톱 창 크기 변경으로만 검증했다.
- 유료재화는 지급·결제 경로가 없어 실제 플레이에서는 4·5번 탭을 열 수 없다. 검사와 스모크는 잔액을 직접 넣어 규칙만 확인했다.
- 재료·보석·룬은 이 프로젝트에서 계정 공용 재고이며 영웅 소지품에 존재하지 않는다. 그래서 창고↔소지품 이동 대상이 아니고 창고의 분류 탭에서 표시·상세만 제공한다. 이동 규칙은 장비에만 적용된다.
- 장착 변경은 기존 정책대로 성소에서만 가능하다. 균열 중에는 프리셋 적용을 거부하고 창고↔소지품 이동만 허용한다.
- 등급 체크·정렬 상태는 기존 인벤토리 화면과 같이 세션 메모리에만 두고 기기 파일에 저장하지 않았다.
- 기존 실패 검사 두 개는 이 작업 전부터 실패한다. `LocalizationTests.EveryKoreanLiteralInTheRuntimeHasAnEntry`는 진행 중인 사냥 칙령 WIP 파일(`CombatSimulation.HuntEdictChanges.cs`, `SkillProgressionInfo.cs`)의 미번역 문구 때문이고, `RepeatHuntTests.FreeingBagSpaceRestoresPickupForNewDrops`는 제 변경을 제외한 기준선 클론에서도 실패함을 확인했다. 두 검사는 건드리지 않았다.

## 결정이 필요한 사항

- 유료재화 잔액 필드 `premium`을 추가했다. 지급·결제 연동 방식과 아이콘은 정해야 한다.
- 이전 규칙으로 50개 넘게 보관한 저장은 1번 탭 임시 초과로 이관한다. 대신 필요한 탭을 무료 개방하는 방안을 원하면 `Storage.Normalize`의 이관 분기 한 곳을 바꾸면 된다.
- 등록 장비가 하나도 없는 프리셋은 적용을 거부한다. 문서 원안(모든 부위를 빈칸으로)을 원하면 `Storage.PlanPreset`의 첫 검사를 제거하면 된다.
