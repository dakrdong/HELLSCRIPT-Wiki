# 언어 설정 개발 기록

작성일: 2026-09-11 · 한국어·영어 전환과 영어 텍스트

## 범위

설정 창에 언어 선택을 넣고, 게임에 들어 있던 한국어 문장 전체에 대응하는 영어 문장을 추가한다. 지금 고를 수 있는 언어는 한국어와 영어 두 가지이며, 세 번째 언어는 목록에 한 줄과 번역 파일 하나를 더하는 작업으로 끝난다. 화면 방향·글자 크기와 같은 기기 설정이므로 [화면 설정·공통 안내](Screen_Settings_Expansion.md)에서 만든 설정 창에 항목을 추가했고 새 화면은 만들지 않았다.

## 원문을 열쇠로 쓰는 이유

이 프로젝트의 문장은 모두 소스 코드 안에 한국어로 적혀 있었다. 문장마다 `settings.title` 같은 열쇠를 새로 만들면 2천 개가 넘는 이름을 발명해야 하고, 코드를 읽을 때 실제 문장을 볼 수 없게 된다. 그래서 한국어 원문 자체를 열쇠로 사용한다.

| 결과 | 내용 |
|---|---|
| 코드 가독성 | 소스에는 한국어 문장이 그대로 남는다. 번역이 없으면 원문이 화면에 나오므로 어떤 상황에서도 빈 화면이 되지 않는다. |
| 기본 언어 | 한국어는 표를 읽지 않는다. 표가 없는 언어이므로 기존 동작과 완전히 같은 경로로 문장을 만든다. |
| 새 언어 | `LanguageOptions.All`에 한 줄을 넣고 `Resources/Localization/<코드>.txt`를 추가하면 된다. 게임 코드는 어떤 언어가 있는지 알지 않는다. |

[프로젝트 지침](../../CLAUDE.md)은 문자열을 코드에 적지 말고 표에 키로 넣으라고 적고 있다. 이 구현은 그 문구를 그대로 따르지 않고 원문을 열쇠로 삼았다. 지침이 함께 요구하는 "빠진 번역은 한국어로 대신 보여 주고 키 이름이나 빈 문자열을 내보내지 않는다"를 구조적으로 보장하기 때문이다. 추상 키를 쓰면 한국어 표에 빠진 항목이 생길 때 키 이름이 화면에 나온다.

대신 이 선택에는 약점이 하나 있다. 한국어 문장을 고치면 열쇠가 바뀌므로 그 줄의 번역이 조용히 사라진다. 그래서 표를 두 구역으로 나누고, 앞 구역의 모든 열쇠가 지금도 소스에 존재하는지 검사한다. 문구를 고치면 그 줄이 검사에서 실패하므로 번역을 함께 손보게 된다.

## 화면에 글자가 놓이는 자리는 한 곳이다

모든 화면의 글자는 `GameUI.Label`에서 만들어진다. 이 한 함수에서 선택한 언어를 읽으므로, 문장을 넘기는 수백 개의 호출부는 바뀌지 않았다. 이때 게임오브젝트의 이름은 번역하지 않은 원문으로 남긴다. 이름으로 버튼을 찾는 코드와 런타임 스모크 화면이 언어와 무관하게 같은 이름을 보기 때문이다.

화면을 그린 뒤에 글자를 다시 쓰는 31곳은 `Loc.T`를 거치게 했다. 프리셋 이름을 입력하는 칸은 예외로 두었다. 그 칸의 내용은 그대로 저장되는 값이므로, 표시 언어에 따라 저장될 이름이 달라지면 안 된다.

## 문장을 조립하는 자리

`$"처치 {kills}"`처럼 조립된 문장은 완성된 결과가 표의 열쇠와 일치하지 않는다. 그래서 조립하는 자리를 모두 서식 문자열 호출로 바꿨다.

```
$"처치 {run.kills} · 게이지 {meter} / 100"   →   Loc.F("처치 {0} · 게이지 {1} / 100", run.kills, meter)
```

`Loc.F`는 서식 문자열과 **문자열 인자를 함께 번역한다.** 스킬 이름이나 규칙 사유처럼 한국어를 담고 다니는 값이 인자로 들어오기 때문이다. 이 처리가 없으면 `"Whirlwind · 준비"`처럼 두 언어가 한 줄에 섞인다. 번역문이 자리표를 잃어버려 서식 조립이 실패하면 원문 서식으로 한 번 더 시도하고, 그것도 실패하면 원문을 그대로 내보낸다. 화면을 그리는 중간에 예외가 나가지 않는다.

| 상황 | 처리 |
|---|---|
| 문장을 통째로 넘기는 호출 | `Label`에서 번역한다. 호출부는 바뀌지 않았다. |
| 보간·연결로 조립하는 388곳 | `Loc.F`로 바꿨다. 인자로 들어온 한국어도 함께 번역된다. |
| 타입이 열릴 때 한 번 조립되는 문장 | 그 시점의 언어로 굳으므로 조립하지 않는다. 세트 부위 이름과 두 줄 설명은 읽을 때 조립하고, 전리품 회수 항목의 이름은 원문을 보관한 뒤 표시할 때 번역한다. |
| 저장 파일에 들어가는 이름 | `Loc.Source`로 원문 언어에서 조립한다. 언어를 바꿔도 저장된 바이트가 달라지지 않으며, 완성된 이름을 표에 등록해 표시할 때 번역한다. |

## 선택과 저장

선택하면 곧바로 적용하고 이 기기에 저장한다. 저장 파일은 `hellscript-language-v1.json` 하나이며 계정 저장·화면 방향·글자 크기 파일을 건드리지 않는다.

| 상황 | 처리 |
|---|---|
| 저장값이 없음 | 한국어로 시작하고 파일을 새로 만들지 않는다. |
| 파일이 손상되었거나 모르는 언어 | 한국어로 시작하고 원본 파일을 그대로 보존한 뒤 읽지 못했다고 알린다. 1KB를 넘는 파일도 같게 처리한다. |
| 번역 파일이 없거나 읽히지 않음 | 언어는 그대로 적용하고, 번역이 없는 줄은 한국어로 보여 준다는 사실을 함께 알린다. |
| 저장 실패 | 선택한 언어는 화면에 그대로 적용하고, 저장하지 못했다는 사실과 다음 실행에 사용할 언어를 함께 알린다. 같은 언어를 다시 누르면 저장만 다시 시도한다. |

## 보고 있던 화면 다시 그리기

문장은 화면을 그릴 때 쓰이므로, 언어를 바꾸면 지금 보고 있는 화면을 다시 그려야 한다. 32개 화면의 그리기 함수가 각각 자신을 다시 실행하는 방법을 기억해 두고, 언어가 바뀌면 설정 창을 닫고 그 함수를 다시 호출한 뒤 같은 분류로 설정 창을 열고 언어 선택 줄을 화면 안으로 되돌린다. 이름을 입력하던 창은 화면을 다시 그리면서 닫히므로 설정 화면에 그 사실을 적어 두었다.

## 번역 표

`Assets/HELLSCRIPT/Resources/Localization/en.txt`는 한 줄에 한 항목을 담는다. 왼쪽이 한국어 원문, 탭 하나, 오른쪽이 영어 문장이다. 줄바꿈은 `\n`으로, 탭은 `\t`으로 적는다. `#`으로 시작하는 줄은 주석이다. 항목 수는 2,496개이며 그중 2,170개는 소스의 한국어 문장이고 나머지 326개는 코드가 실행 중에 조립하는 열쇠다. 두 무리는 주석 한 줄로 구분해 두었으며, 구분 기준은 그 문자열이 지금 소스에 있는지 여부다. 파이프로 이어진 선택 목록은 목록 전체와 각 항목을 함께 등록하고, 등급 이름과 항목 이름을 붙여 만드는 전리품 항목, 추천 빌드 이름 6종×30레벨도 함께 등록한다.

용어는 다음과 같이 옮겼다.

| 한국어 | 영어 |
|---|---|
| 균열 / 잿빛 성소 / 성소(전투) | Rift / Ashen Sanctuary / Shrine |
| 사냥 칙령 / 행동 설계 / 규칙 | Hunt edict / Behavior design / Rule |
| 처치 게이지 / 제압 / 잔향 | Kill gauge / Stagger / Echo |
| 접두·접미 / 분해 / 강화 / 한 줄 재설정 | Prefix and suffix / Salvage / Enhance / Reroll one line |
| 전사·궁수·마법사 | Warrior, Ranger, Mage |

## 검증

| 검사 | 결과 |
|---|---|
| Edit Mode 전체 | 1,183개 통과, 실패 0. 이번에 32개를 추가했고 기존 1,151개는 그대로다. |
| 표의 형식 | 탭이 하나가 아닌 줄과 중복 열쇠가 없다. 모든 열쇠에 한글이 있고 모든 번역문에는 한글이 없다. 자리표 집합과 선택 목록의 항목 수가 양쪽에서 같다. |
| 네이티브 스모크 | macOS 개발 빌드에서 종료 코드 0. 기본값에서는 설정 파일을 만들지 않고, 설정 창을 열어 둔 채 영어를 누르면 창과 그 아래 화면이 함께 다시 그려진다. 성소·행동 설계·규칙 편집기·조건 선택·행동 추가·성장·장비·균열 관리자·사냥 칙령 편집기 세 분류·전투·판단 기록에서 남은 한국어와 항목이 없는 줄, 칸을 넘치는 글자를 모두 검사하고, 한국어로 되돌린 뒤 다시 영어로 저장한다. 별도의 프로세스가 저장된 영어로 성소를 다시 그린다. |
| 버려진 항목 검사 | 표 앞 구역의 모든 열쇠가 지금도 소스의 문자열과 일치하는지 확인한다. 한국어 문장을 고쳐 번역이 떨어져 나가면 실패한다. |
| 누락 검사 | 런타임 어셈블리의 소스를 직접 읽어 한국어 문자열을 모두 찾고, 표에 항목이 있는지 확인한다. 한국어를 보간한 문자열이 남아 있으면 실패한다. 언어 이름을 담은 `Localization.cs`와 스모크 파일은 제외한다. |
| 저장 격리 | 언어를 저장해도 계정 파일의 바이트, 화면 방향 파일, 글자 크기 파일이 변하지 않는다. |
| 손상 복구 | 빈 객체, 다른 판본, 모르는 언어, 깨진 문자열, 1KB 초과를 모두 기본값으로 처리하고 원본을 보존한다. |
| 저장 실패와 재시도 | 실패해도 선택한 언어가 화면에 남고, 재시도가 성공하면 한 번만 저장한다. |
| 번역 실패 내성 | 자리표를 잃은 번역문은 원문 서식으로 조립하고, 표를 읽지 못하는 언어도 적용된다. |

증거는 `Artifacts/Validation/LanguageEvidence`에 있다. 스크린샷 12장과 두 개의 PASS 기록이 들어 있으며, `00-restart-town-in-english.png`는 재시작 후 영어로 그린 성소, `01`과 `04`는 같은 화면의 한국어와 영어, `11`은 한국어로 되돌린 결과다.

## 남은 것

- 전투 기록의 로그 줄은 만들어질 때 조립되므로 그 시점의 언어로 저장된다. 나중에 언어를 바꾸면 과거 로그는 그때의 언어로 남아 있다. 같은 기록의 직업 이름과 결과 사유는 원문으로 저장하므로 표시할 때 번역된다.
- 글꼴은 기존 CJK 우선 목록을 그대로 사용한다. 영어 전용 글꼴로 바꾸거나 자간을 조정하지 않았다.
- 영어 문장의 길이는 한국어보다 긴 경우가 있다. 네이티브 스모크는 화면을 찍을 때마다 모든 글자가 자기 칸보다 높으면 실패한다. 고정 칸에 위젯을 촘촘히 넣는 규칙 편집기와 사냥 칙령 편집기를 포함해 방문한 모든 화면에서 잘림을 확인했다.
- 번역은 개발자 번역이며 원어민 교정을 받지 않았다.
- 같은 한국어 낱말이 두 맥락에 쓰이면 영어 낱말 하나로 정해야 한다. `돌진`은 적의 상태와 대상 행동 유형에 모두 쓰이므로 양쪽에서 `Charge`로 읽는다.
- 이 기록의 영어판은 [Language setting development record](Localization_Expansion.en.md)에 있다.
