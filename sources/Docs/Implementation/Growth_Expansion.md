# 성장 정산과 저레벨 추천 행동 개발 기록

작성일: 2026-09-09 · D4 성장 연결 진행 중

## 1. 바뀐 전투 처리

[성장 상세안](../Design/HELLSCRIPT_Growth_Detail.md)에 따라 일반 적·정예·보스의 경험치를 전투 틱의 정산 경계에 모아 반영한다. 기존에는 일반 적 처치 때마다 능력치를 다시 계산했고 현재 HP의 절대값을 유지했다. 보스 경험치로 레벨이 오르면 전투 능력치는 그대로 남아 있었다. 이제 두 보상 경로 모두 같은 갱신 함수를 사용한다.

레벨이 오르면 정산 직전 HP 비율을 새 최대 HP에 적용한다. HP 0은 그대로 유지하며 현재 자원·CD·진행 중 행동·이미 생성된 투사체와 보호막은 초기화하지 않는다. 해금한 스킬과 변경 전후 XP·HP는 `GrowthEvent`에 남긴다. 경험치가 최대 레벨을 넘으면 기존 30레벨 상한 규칙을 따른다.

`RunState.pendingExperience`는 아직 반영하지 않은 확정 경험치를 보존한다. 전리품 정리로 이어 받은 저장이나 수동 귀환에서도 처리하며, 반영 뒤에는 0으로 비운다. `Hellscript.unity → GameController → CombatSimulation`의 기존 소유 구조와 레벨·장비 수식을 유지한다.

## 2. 추천안과 화면

완성 빌드 `GameCatalog.Preset`은 유지했다. `BehaviorPresets.ForLevel`은 현재 카탈로그의 해금 레벨을 읽어 새 추천안을 만들고 미해금 규칙만 꺼 둔다. 새 계정을 실제 게임 카탈로그로 생성할 때 이 추천안을 사용한다. 기존 저장은 다시 만들지 않는다. 카탈로그 없이 호출하는 기존 개발용 계정 생성 함수는 종전 완성 프리셋을 유지한다.

PM01의 1~2레벨 추천 화염구는 예상 명중 2명 이상 또는 보스를 공격한다. 눈보라를 배운 뒤에는 장판 연계 추천안을 별도로 제시한다. 사용자가 저장한 규칙을 레벨업으로 자동 교체하거나 켜지 않는다.

추천 버튼은 바로 편집안을 덮어쓰지 않고 목적·사용/잠금 스킬·행동 행·목표·이동·물약·패시브의 차이를 보여 준다. 불러오기를 선택해도 편집안만 바뀌며 실제 적용은 기존 설정 적용 버튼을 사용한다. 균열에서는 장착을 유지한 후보를 먼저 계산해 보여 준다.

성소와 전투 HUD에서 성장 화면을 열 수 있다. HUD의 레벨·XP·다음 해금이 갱신되며 성장 화면은 배움·장착·켜진 규칙을 구분한다. 최근 레벨업의 HP 비율과 해금도 확인할 수 있다. 성장 화면을 닫을 때 이전 일시정지 상태를 복원한다.

## 3. 검증

첫 집중 검사 55개가 통과했다. 6빌드 × 7개 해금 경계, 실제 저레벨 화염구의 표적 조건과 피해, 3직업의 여러 레벨 상승, 동시 처치·보스·사망, 진행 중 효과 보존, 정산 대기 저장과 최대 레벨을 포함한다. 이후 새 계정/기존 저장의 구분과 일시정지 중 수동 귀환 정산 검사를 추가했다.

첫 실제 앱 검사에서 기본 다수 표적 훈련의 화염구가 발동하지 않았다. 재현 검사에서 예상 명중이 계속 1명인 것을 확인했다. 기존 열 3m·행 2m 간격에서는 앞 표적에 충돌한 화염구가 다음 표적까지 닿지 않았다. 일반 훈련만 열 2m·행 1.5m로 조정해 밀집 표적을 시험하는 목적에 맞췄다. 화염구의 피해 범위와 추천 조건, 기존 개발용 훈련 배치는 유지했다. 기본 배치·현재 레벨·현재 장비 그대로 발동을 확인하는 검사를 추가한 뒤 집중 검사 58개가 통과했다. 실패 기록은 `growth-training-repro.xml`과 `growth-native-start.log`에 보존했다.

전체 검사 **514개가 통과**했다. 그중 성장 검사는 58개다. macOS 실제 앱에서 추천 미리보기·취소·편집안 불러오기·명시적 적용을 연결했고, 일반 훈련에서 1레벨 화염구의 피해와 미해금 눈보라의 비발동을 확인했다.

빠른 해금 검증을 위해 별도 저장을 2레벨·XP 174로 설정한 뒤, 실제 자동 생성 균열에서 적을 처치했다. 4전투초에 경험치 20을 얻어 3레벨·XP 19가 되었으며, HP는 152.75/235에서 169/260으로 바뀌어 65%를 유지했다. 눈보라 규칙은 여전히 꺼져 있었고, 성장 화면에서 현재 레벨 추천안을 직접 적용한 뒤에만 켜졌다. 적용 시 장착·HP·자원·CD가 유지되는지도 확인했다.

앱을 완전히 종료하고 새 프로세스로 실행해 XP·HP·난수·전투 시각·성장 기록이 중복 없이 복원됨을 확인했다. 이후 3레벨 일반 훈련에서 눈보라와 화염구의 실제 피해가 발생했고 실제 영웅의 XP는 유지됐다. 이 설정은 새 계정의 자연 성장 속도나 1단계 밸런스 완료의 증거로 사용하지 않는다.

첫 화면 검토에서 성장 알림이 스킬 설명과 겹쳤다. 알림을 스킬 영역 위로 옮기고 배경을 추가했으며, 입력을 가로채지 않도록 했다. 이 화면 수정 뒤 다시 빌드해 동일한 실제 앱 흐름을 검사했다. 최종 빌드의 **2개 프로세스·실제 재시작 1회**가 모두 정상 종료했고 화면 7장을 직접 확인했다. 알림 줄 잘림·스킬 설명 겹침과 하단 버튼 경계도 검사했다.

전체 검사 뒤 바꾼 소스는 알림 표현과 해당 화면을 확인하는 실행 검사 두 파일뿐이다. 전투·저장·추천 계산과 자동 검사 소스는 514개 검사를 통과한 상태와 같다. 최종 화면 변경은 재빌드와 실제 앱 검사로 검증했다. 기존 에셋·패키지·프로젝트 설정 176개의 내용은 개발 시작 시점과 같으며 씬·프리팹·생성 이미지도 바꾸지 않았다. 실제 앱 검사는 Metal·540×960이며, UI 콜백을 실행한 검사다. 물리 입력·Android·실기기 성능·온라인 검증은 포함하지 않는다.

## 4. 이어서 할 일

첫 15분의 단계별 안내·건너뛰기·재열람, 성장 구간별 여러 시드 비교, 훈련 A/B와 전체 스킬별 집계는 남아 있다. 전설·세트의 남은 조합, 장비 정리·마을·서비스·기기 품질은 [남은 개발 작업표](../Design/HELLSCRIPT_Remaining_Development_Backlog.md)를 유지한다.
