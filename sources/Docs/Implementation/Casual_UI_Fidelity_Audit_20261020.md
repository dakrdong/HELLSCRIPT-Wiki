# 캐주얼 UI 시안 일치 점검 — 2026-10-20

[English](Casual_UI_Fidelity_Audit_20261020.en.md)

## 방법

시안 캔버스(Claude Design)의 보드를 로컬 서버에서 렌더링해 모든 글자·상자·이미지의 크기와 위치를 보드 픽셀로 뽑고(`tools/ui_fidelity/measure.html`), 같은 크기의 게임 화면(Unity Editor의 떠 있는 Game View를 440×956 / 956×440 / 1600×900으로 맞춤, `UiFidelityDump`)에서 같은 값을 뽑아 `compare.py`로 비교한다. 글자는 문자열로, 상자는 겹침(IoU)으로 짝짓는다. 보드는 세로 440×956, 폰 가로 956×440, PC 1600×900이다.

## 공통 원인과 공통 수정

- 지금까지의 창은 게임 단위(`UiTheme.Scale`)에 임의 상수를 곱해 시안 "비율만" 반영했다. 같은 보드에서 글자가 약 2px 작고 칸·탭·여백이 달랐다.
- `UiMock`(보드 판별 + `UiTheme.Scale / 기준배율`)을 추가했다. 기준 보드에서 캔버스 1단위가 시안 1px이 되고 다른 화면은 보드를 비례 확대한다. 창은 시안 CSS 토큰(`--cell`, `--head`, `--fs` …)을 그대로 쓴다.
- `StorageSurface.shadowOutside`와 버튼 칩 확장으로 시안의 box-shadow가 상자 밖에 걸리게 해, 레이아웃 사각형이 시안의 border-box와 같다.
- `EquipmentSlotView.Paint(…, CellRecipe)`: 칸 안쪽 배치(그림 86% · 7%/5%, 등급 글자 .17, 칩 .14/.2/.22)를 칸 크기에 비례해 그린다. 다른 창은 `recipe` 없이 기존 모양을 유지한다.

## 창고 창 (적용 완료)

기존 대비 측정(세로 보드): 제목 22.8→25, 탭 8.7→11, 분류 10.9→13, 소지품 제목 19.6→16(시안 16), 하단 재화 11.9→16px로 맞췄고 칸 56.5→52, 보관함 탭 38→46, 분류 줄·well·rail·footer 위치를 시안에 맞췄다. 최종 측정: 세 보드의 일반·일괄 이동 상태는 글자 크기 오차 ≤0.5px(정수 글꼴 반올림), 상자 위치·크기 오차는 대부분 ≤2px이고 PC 도구 칩과 사용량 알약만 최대 약 5~9px다. 대화상자는 틀 너비·글자 크기가 시안과 같고 칸 확장은 프레임 높이 382px까지 일치, 도움말·탭 개방은 높이 ±5px다. 필터 팝오버는 위치가 일치하고 높이는 +14px였던 것을 보정했으나 보정 뒤에는 다시 재지 않았다.

남은 차이(알려진 것): 끌기 고스트·일시정지 알약·토스트 상태 보드는 아직 측정하지 않았다. 상세·프리셋 대화상자의 내부는 공유 부품(`ItemDetailView`, `CharacterEquipmentView`)이 소유한다. 브랜드 글자 간격은 `UiTextSpacing`으로 그리지만 측정 도구는 효과 적용 전 글자 폭을 읽는다. 사용량 알약 너비는 칸 수 문자열에 따라 시안 예시(12 / 60)와 다를 수 있다.

## 룬 장인 (적용 완료)

`RuneMasterWindow.Layout.cs`가 재형성·승급 탭을 시안 CSS 픽셀(보드별 머리·꼬리·칩·슬롯·재료 칸·합성 버튼)로 그린다. 최종 측정: 재형성 세 보드와 PC 대기·쌍·오류 상태는 글자 12~13개 중 1~2개만 어긋나고(브랜드 글자 간격 폭과 가로 보드의 긴 안내문 폭 4%) 세로 보드 상자 오차는 0이다. 이번 점검에서 고친 실제 차이: 하단 연출 제거 버튼 높이(가로 +4, 세로 +2), 가로 보드 승급 그룹 행 높이 51→53, 승급 칸 합계 글자 높이를 정수 반올림이 아닌 시안 값으로, 등급 칩의 두 자리 수가 줄바꿈되던 것(세로), 스크롤바 시작 위치. 남은 차이: PC·가로 보관함의 맨 아래 빈 칸이 시안 DOM과 높이가 달라 보이는 것은 뷰포트 잘림(원본 높이 91.6 일치)이고, 사용량 알약 너비는 숫자 폭에 따라 약 3px, 승급 보드는 시안의 그룹 상태(보드마다 다른 칸 수가 등록된 상태)와 구동 상태가 달라 등록 재료 행은 공식(재료 칸·결과 칸 높이)으로만 맞췄다.

## 공통 확인창·알림 (적용 완료)

`CasualNoticeLayout`이 시안 CSS 픽셀에 `UiMock.CanvasScale`을 곱한 물리 픽셀로 계산한다(`For(safe, scale)`, 기기 값은 `Current()`). 이전에는 `Screen` 물리 픽셀 그대로라 DPR 3 폰에서 시안의 약 1/3로 그려졌다. 카드는 시안처럼 border-box(테두리가 패딩 바깥), 알림은 세로·가로 보드가 같은 테두리·그림자·여백·간격(9px)을 쓰고(`.o-land .tst,.o-port .tst`), 정보 배지와 글자가 한 묶음으로 가운데 정렬되며, 배지는 예전 스프라이트 대신 시안의 흰 원+남색 고리+파란 i(`CasualNoticeInfo`)로 그린다. 측정(세 보드): 글자 크기 오차 0, 글자 위치 ≤3px, 알림 상자 크기 일치. 알림의 세로 위치는 실제 HUD 윗변을 따라가므로 측정하지 않았다. 1:1 에디터 보드에서 글자 폭이 약 4% 좁은 것은 레거시 `Text`의 정수 글리프 전진폭 반올림 때문이며, 기기 배율에서는 1% 미만이다.

## 마을 광장 (부분 적용)

기존 구현은 시안과 글자 크기가 이미 같고 상자 위치가 대체로 맞았다. 이번에 고친 것: 상호작용 카드의 상세 글이 첫 줄에 놓이도록(+10px), 대화 버튼에 시안의 말풍선 아이콘을 넣어 묶음 가운데 정렬, 제목 판의 그림자 3px를 사각형에 포함, PC 시설 안내 패널의 테두리 3px 안쪽 간격과 높이 556px. 의도적으로 남긴 차이: 우상단 톱니·콘텐츠 독·이벤트 단추는 PR #144(2026-10-18)에서 정한 "그린 톱니 아래 정렬"과 `menu-*` 메달 아트를 따르므로 시안의 평면 톱니·독 위치와 다르다. 공유 HUD(`GlobalHudView`)의 글자 크기와 세로 보드 슬롯 줄은 아래 "공유 HUD"에서 맞췄다. 장소 이름은 Jua 부분집합에 없는 글자("잿")가 있어 Noto로 대체되어 너비가 약 +9px다. 카드와 이름표는 변환 배율(cardScale/scale)로 키우므로 작은 캔버스(세로 0.54배)에서 글자가 캔버스 해상도로 그려진 뒤 확대된다(흐림 가능, 후속).

## 일일 퀘스트·출석 (적용 완료)

세 페이지는 `EventsPlate`(시안의 크림 판·머리·탭 3개·바닥 띠)와 `ContentWindowView`의 맞춤 모드(`Open(..., fit)`, 장식 없이 판 하나만 그리는 `RepaintFitted`)로 다시 그린다. 크기는 전부 시안 CSS 픽셀이고 `UiMock.WindowScale`(화면 전체 기준 배율)과 `UiMock.Plate`(안전 영역 −8px, PC 1500×810 상한)가 판 위치를 정한다. 이전 구현은 화면 비율로 제각각 늘어났다. 최종 측정: 일일 퀘스트는 세로 글자 32/37·PC 37/43개가 시안과 같은 크기·위치(나머지는 ≤4% 폭 차이와 Jua 부분집합에 없는 글자 대체), 7일 출석 PC 21/21, 28일 출석 17/17. 탭의 대기 점·바닥 띠·남은 시간(HH:MM:SS)·수령 알림은 시안 그대로 넣었다. 시안의 `.dq button{margin:0;font:inherit;color:inherit}` 때문에 시안 DOM에서는 탭과 수령 단추 글자가 남색 Noto 14px, 제목은 금색 Jua로 그려져 DOM 덤프를 기준으로 삼았다. 남은 차이: 덤프가 읽지 못하는 그림자(UiWindowFrame +5px)와 잘린 스크롤 내용, 일일 퀘스트 수령·갱신 알림과 닫힌 상태는 측정하지 않았다.

## 사냥 칙령 창 (구형, 부분 적용)

구형 `HuntEdictWindow`는 곧 없앨 예정이라 사용자 지시로 중간에 멈췄다. 적용한 것: 시안의 border-box 틀(테두리 3px 안쪽에서 패딩, 머리줄·구분선·탭 영역 간격, 꼬리 영역은 점선+버튼만), 판 그림자를 칸 밖으로 빼서 칸 크기가 시안 상자와 같게(`UiButtonFace.ShadowOutside`, `HuntEdictSurface.shadowOutside`), 머리 제목 알약, 탭 아이콘·글자 위치, 요약 탭의 전환 줄·전투 방식 카드, 그룹 편집기(검색 줄·그룹 칩·흰 카드·간편 프리셋 묶음·옵션 행), 스킬 관리 목록·장착 스킬 독, 정책 페이지 머리·프리셋 탭·세로 독. 측정: PC 전투·전리품·가방·반복·탐색(직접 설정) 탭은 글자 대부분이 시안과 같은 크기·위치이고 상자 편차는 1~2개다. 남은 차이는 Jua 부분집합에 없는 가운뎃점('·')이 든 문구가 Noto로 대체되어 폭이 +3~14px 넓은 것과 `.5` 글자 크기 반올림이다. 하지 않은 것: 프리셋·장비 추천 착용·대화상자·생존 팝업(위험·회피 방식) — 구형이라 건너뜀. 이 작업 중 발견: 창의 팔레트 필드가 `MonoBehaviour` 필드 초기화에서 `Resources`를 읽어 첫 사용 때 글자가 투명해지는 문제를 사용 시점에 읽도록 고쳤다.

## 설정 창 (적용 완료)

설정 캔버스가 `ApplyScaler(..., *.5)` 때문에 폰에서 시안보다 약 20% 작게 그려지던 것을 `UiMock.CanvasScale`(1 캔버스 단위 = 시안 1px)로 바꾸고, 보드별 크기표 `SettingsLook`(패딩·간격·글자·탭 높이·칩·단추·막대·인장)으로 틀(머리 제목·닫기·구분선·탭 줄·스크롤 본문), 카드 패딩, 섹션 머리, 본문·보조 글(줄 높이 포함, `SettingsParagraph`), 안내 상자, 슬라이더(막대 `barh`, 마커 17px, 눈금), 선택 카드(지도·언어·영웅), 단추, UID 줄을 시안 치수로 맞췄다. 본문 스크롤바(12px)는 내용이 넘칠 때만 폭을 차지하고, 소리 탭은 음량 줄(간격 0)과 음소거 카드(체크 상자+두 줄)로, 캐릭터 탭은 영웅 카드를 한 카드에 묶었다. 측정: PC 화면 탭은 글자 17/19, 언어 11/12가 시안과 같고 소리·캐릭터·계정은 구조가 맞으며 글자 7~9개가 같은 크기·위치다. 남은 차이: 값의 `%`를 숫자와 따로 그리는 표시, 소리 막대 마커, 계정 UID·대기 건수(구동 데이터 차이), 안내 상자 줄 수(글자 폭 차이)이고, 게임 안내·전투 상태 탭은 같은 크기표를 쓰지만 시안과 따로 측정하지 않았다. 설정 테스트(`CasualSettingsTests`)는 시안 단위 기준으로 고쳤다(탭 폭·높이, UID 줄, 슬라이더 터치 영역).

## 장비 상점 (적용 완료, PC 시안 1440×810)

시안(`장비 상점 · 캐주얼`)은 현재 화면과 구조가 달라 값만 고치지 않고 시안 픽셀로 다시 그렸다(`EquipmentShopWindow.Mock*.cs`, 상점 도박 상인·분해 공용 자동 선택 설정은 기존 배치 유지). 표시 단위는 시안 1px = 캔버스 1단위이며 PC 기준 폭이 1440이라 `UiMock.WindowScale(safe, 1440)`을 새로 두었다. 새로 만든 것: 머리줄(브랜드·위치·제목·닫기), 탭 줄과 다음 입고 카운트다운, 등급 선택·정렬 선택(작은 목록 팝업)·분류 막대, 56px 상품 줄과 "소폭 개선" 표시, 소지품 격자(8열 50칸·분류·다중 선택 막대·자동 선택 안내 띠), 구매·판매·되사기 비교 팝업 두 장(차이값·사라지는 속성·업그레이드 정보·사실 표)과 하단 도크, 꼬리줄(골드·보석·상태·기록·안내), 내용이 넘칠 때만 폭을 차지하는 얇은 스크롤바, 대화상자 틀(일괄 판매 확인·아이템 정보·프리셋·기록·안내)과 자동 선택 설정(등급 칩·장비 종류·세부 설정·제외 조건). 기록은 구매·판매·되사기를 최신순 30건 저장하는 `EquipmentShopState.ledger`(저장 추가 필드, 옛 저장은 빈 목록)가 맡는다. 사용자 요청으로 비교 팝업의 장비 그림은 시안(40px)보다 크게 그렸다(PC 72px, 폰 52px). 측정: PC 구매·판매·일괄 판매·자동 선택 설정·세부 설정 보드에서 글자·상자 위치가 0~1.5px 안이고 칸 크기는 같다(격자 63px, 상품 줄 56px, 팝업 425.5px). 남은 차이: Jua 부분집합에 없는 가운뎃점 때문에 제목·위치 글자가 Noto로 대체(폭 +3~14px)되고 Jua 숫자 폭이 약 10% 넓은 것, 등급 칩에 '고유'(저장 호환용 예약 비트라 선택 불가)를 넣지 않은 것, 시안의 EN/KO 전환 단추는 언어 설정이 맡아 넣지 않은 것, 장비 이미지 확대(요청). 새 글자 60개는 `en.txt`에 영어를 채웠다.
