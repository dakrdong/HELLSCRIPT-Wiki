# 스킬 개편 후 전체 검사 실패 수정

[English](EditMode_Regression_Repair_20261004.en.md)

작성일: 2026-10-04. [스킬 개성 재설계](Skill_Identity_Rework.md)의 이전 검증에서 남긴 실패 128개를 수정하는 후속 작업이다. 기존 실패라는 분류는 완료 조건의 예외가 아니다. 이전 전체 검사와 실패 대조 자료는 당시 결과로 보존한다.

## 수정 원인과 동작

| 원인 | 수정 | 보존하는 계약 |
| --- | --- | --- |
| Unity JSON이 없던 DPS 그래프를 빈 객체로 복원 | 새 그래프는 명시적으로 버전 1을 부여한다. 버전 0의 빈 객체는 부재로 정규화하고 기존 표본이 있는 그래프는 이관한다. | 시작 직후 저장한 새 그래프는 유지한다. 그래프가 없던 과거 기록에 빈 그래프를 만들지 않는다. |
| 없는 전투 기록 객체가 미리보기 복제 중 생성 | 공통 복제와 빌드·사냥칙령 미리보기가 부재를 유지하고 유효한 기록만 이벤트를 받는다. | 미리보기와 실제 적용이 같은 전투 상태를 만든다. 훈련에는 균열 기록을 추가하지 않는다. |
| 재개 시 이동 경로 캐시를 새로 계산 | 기존 내비게이션 소유자가 경유점·다음 인덱스·실패 경로 재시도 시각·발판 반경을 전투 저장에 기록한다. 관문과 지형 변경 시 기존 무효화 경로로 함께 지운다. | 같은 저장·시드에서 영웅과 적이 같은 위치로 이동한다. 경로가 막힌 상태도 보존한다. |
| 재개 시 전투 기록의 중복 억제 시각 초기화 | 판단별 시각과 마지막 이동 기록 키·시각을 저장한다. | 같은 전투가 불필요한 판단·이동 기록을 추가하지 않는다. 실제 플레이어 재개는 별도 RESUME 이벤트를 정확히 한 번 남긴다. |
| 훈련을 시작한 후 균열 플래그만 바꾸는 검사 설정 | 유효한 과거 균열 체크포인트를 복원해 검사한다. 단계 0 설정은 유효한 단계 1로 교체하고 보상 검사에는 실제 LiveOps 스냅샷을 준다. | 시전·투사체·채널·설정 적용·저장 실패의 기존 비교와 예외 검사를 유지한다. |
| 철벽의 보호막 연계 예시가 실제 위험에 반응하지 못함 | 가까운 근접 적의 공격 예고를 사용하고 공격 준비 중 방어 전환을 허용한다. 이 조건을 KO/EN 설명에 표시한다. | 수호의 맹약을 실제로 준비하고 그 보호막이 끝난 뒤 자동 철벽이 보호막을 만든다. |

구현은 [그래프 정규화](../../Assets/HELLSCRIPT/Runtime/Core/TrainingGround.cs), [저장 정규화](../../Assets/HELLSCRIPT/Runtime/Core/GameStore.cs), [이동 경로](../../Assets/HELLSCRIPT/Runtime/Core/RiftNavigation.cs), [전투 기록](../../Assets/HELLSCRIPT/Runtime/Core/CombatJournal.cs), [실제 프리셋 조건](../../Assets/HELLSCRIPT/Resources/SkillPresetScenarios.json)을 따른다. 테스트 비활성화·삭제·Ignore 추가·비교 허용 오차 확대는 하지 않았다. 전투 동일성 검사는 `recordResume:false`로 순수 복원을 비교하며 실제 재개 이벤트는 별도 검증한다.

## 검증 결과

최종 전체 Edit Mode 검사 5,122개 모두 통과했다. 실패 0개·건너뜀 0개·판정 보류 0개이며 1,923.9초가 걸렸다. 마지막 통합 게임 소스에서 필터 없이 한 번 실행했고 입력 소스 3,923개가 빌드·실행·검사 사이에 변경되지 않았다. 집중 재검사의 최신 결과는 서로 다른 130개 모두 통과이며 전체 검사 결과를 대신하지 않는다. 신규 회귀 검사 2개는 새 빈 그래프의 저장·재개, 과거 부재 그래프, 기존 버전 없는 피해·시전 표본의 보존을 확인한다.

macOS 개발 플레이어 빌드는 Unity 6000.6.0f1에서 `Succeeded`, 빌드 오류 0개다. 검증한 입력 소스 3,923개의 지문은 `0d6e8748374383c73a0e8f0f4b8fd254b10544af5270ba635de57940011b3729`다. 빌드로 생긴 프로젝트 설정 변경은 원본과 대조해 복원했고 패키지는 변경하지 않았다.

균열 1·5·12를 실제 생성해 200틱에서 로컬 저장한 뒤 별도 플레이어 프로세스에서 100틱을 더 진행했다. 위치·경유점·RNG·체력·쿨다운·DPS·전투 기록을 포함한 전체 저장 JSON이 중단 없이 진행한 300틱 결과와 각각 같은 SHA-256이다. 실제 플레이어 재개는 RESUME 한 건과 재개 횟수 1만 추가하고 진행 중 동작을 유지한다.

| 균열 | 300틱 결과의 SHA-256 |
| --- | --- |
| 1 | `cb0cbca4b2937d15c6192419d6a79f7b09bec3d4fb4081dd0a4e5f5af72cd430` |
| 5 | `e0940b2a46a58433fdb76bc6abc281b0ca620214988fa5c3a4d48149cb793b96` |
| 12 | `325cf835548ce7259a6d5565f11a4b2efa1968a73e5a87ab2d6241e8e2cb2f9a` |

철벽의 보호막 이어 쓰기를 실제 uGUI raycast와 합성 pointer down/up/click으로 선택했다. 자동 전투에서 이전 보호막과 겹치지 않고 철벽 보호막 628이 생기는 것을 확인했고, 현재 게스트 프로필 저장 경로를 다시 읽어 정책의 저장을 확인했다. 440×956·956×440·1600×900·1600×1000·2100×900의 KO/EN 10장과 안전 영역 모의 1장을 남겼다. 공통 UI 계약, 계약 검사 11개, 저장 갱신 정적 검사도 통과했다. 모바일 실기기 검사나 성능 개선으로 표현하지 않는다.

첫 프로세스 재개 비교는 화면 검사가 마지막으로 저장한 EN 설정 때문에 실패했다. 대조 전투의 KO 로그와 새 EN 로그를 전체 JSON으로 비교한 검사 조건 문제였다. 격리된 검사 저장의 언어를 KO로 맞춰 실패한 재개 범위만 재실행했고 3개 모두 통과했다. 첫 실패 로그도 보존한다.

## 재현과 자료 수명

[macOS 검증 코드](../../Assets/HELLSCRIPT/Runtime/Presentation/RuntimeSkillTreeSmoke.Identity.cs)의 `-hellscriptRegressionRepairSmoke`와 `-hellscriptRegressionRepairResume`을 사용한다. 두 실행 모두 `-hellscriptOfflineQa`, 작업 전용 `-hellscriptSavePath`, 같은 `-hellscriptEvidence`를 준다. 처음에는 새 evidence 폴더를 사용한다. 각 비교 실행 전에 격리된 save 폴더의 `hellscript-language-v1.json`을 `{"version":1,"language":"ko"}`로 맞춘다. 실제 계정·서버·클라우드 저장을 사용하지 않는다.

[검사·저장·화면 근거](EditModeRepairEvidence20261004/EditMode_Repair_Evidence_20261004.md)를 소스와 공개 위키에 보존한다. 실행 파일과 빌드 중간 출력은 이 작업의 `Artifacts/Validation/EditModeRepair20261004`에만 둔다. 비교용 플레이어는 재현을 위해 2026-10-11에 보존 필요를 재검토하고, 보고서·로그·해시·레시피는 2026-11-04에 검토한다. 만료일은 삭제 승인이 아니다. 기존 소스·이미지·사용자 저장·공유 캐시를 삭제하지 않았다. 공개 위키의 약 3GB 임시 복사에는 macOS의 `/bin/cp -c`를 사용해 같은 APFS 볼륨에서 독립적인 복제 파일을 만든다. 다른 플랫폼은 기존 파일 복사를 사용하며 이전 공개 트리는 새 트리 생성이 끝날 때까지 보존한다.
