# 룬 보드 해방과 플레이어블 가이드

갱신일: 2026-10-24 · [English](Rune_Board_Unlock_Tutorial.en.md)

균열 10단계 이상을 정상 클리어한 뒤 균열을 나와 **마을에 처음 도착하면** 룬 마스터 **인젤 미르**가 안내한다(전투와 결과창에서는 시작하지 않는다). 그 전까지 우측 상단 콘텐츠 메뉴의 룬 보드 칸에는 잠긴 아이콘이 있고, 누르면 "균열 레벨 10 달성 시 오픈됩니다"가 나온다. 인사 선물(룬 블럭 세트)을 받으면 자물쇠가 풀리고 빛이 번진 뒤 룬 보드 인장이 그 칸에 안착한다. 기존 5단계 플레이어블 가이드에서 NPC 설명과 직접 플레이를 번갈아 진행한 후 실제 보드를 자유롭게 사용한다. 2026-10-24에 15단계에서 10단계로 옮겼다([변경 기록](Rune_Unlock_Rift10_20261024.md)).

균열 1~9단계에서는 일반·정예·보스 룬 블럭 보상이 없습니다. `RuneEconomy.MinimumDropStage`가 `ContentUnlocks`의 룬 보드 해방 단계(10)를 읽고, `RuneGrowth`가 실제 균열 단계로 지급을 판정합니다. 이미 해방한 계정의 낮은 단계 반복에도 적용하며, 기존 보유 룬·숙련 경험치·중복 지급 방지 기록은 유지합니다.

## 플레이 흐름

1. 해방 전에는 마을·전투의 콘텐츠 메뉴에 룬 보드 자리에 잠긴 아이콘(`menu-rune-board-locked`)을 두고, 누르면 토스트를 보여 준다. 해방 뒤에도 안내가 시작되기 전에는 "마을에서 룬 보드 안내를 마치면 열립니다."를 보여 준다. 칸의 위치는 같아서 해방 때 독이 움직이지 않는다.
2. 균열 10단계 이상 도달 → 균열 결과 처리 → **마을 광장에 처음 도착**하면 안내가 한 번 시작된다. 다른 팝업·튜토리얼이 열려 있거나 중단된 균열이 남아 있으면 조용해질 때까지 기다린다. 앱을 재시작해도 대기 상태가 유지된다. 자동 반복과 반복 전 정리는 안내 중 멈춘다.
3. 인젤 미르가 룬이 무엇이고 어디서 얻는지 설명한 뒤 **룬 블럭 세트**를 선물한다. 수령 거래는 고정 ID 상자를 만들어 같은 거래에서 열고 G0 한 칸 룬 다섯 종류를 실제 보관함에 넣는다. 첫 클리어 상자와는 무관하며 숙련 경험치는 지급하지 않는다.
4. 저장 성공 후 자물쇠가 깨지며 빛이 번지고(새 기능 개방 알림·효과음), 룬 보드 인장이 우측 상단으로 날아가 그 칸에 안착한다. 착지 상태를 저장한 뒤부터 아이콘을 정상 표시한다. 동작 줄이기 설정은 짧은 연출을 사용한다.
5. 표시된 콘텐츠 아이콘을 눌러 기존 네이티브 룬 보드를 연다. 룬 마스터가 **각 단계의 규칙·조작·목표를 설명한 뒤** 플레이어블 가이드를 진행한다. 직접 목표를 달성해야 **다음**이 열린다.
6. 다섯 단계를 모두 마치면 룬 마스터가 실제 무기별 보드와 저장 방법을 소개하고 **원하는 무기에 자유롭게 룬을 배치해 보세요**라고 안내한다. 튜토리얼을 종료하고 보드를 열린 채로 두며 모든 조작을 풀어 준다.

| 단계 | NPC 설명과 플레이 | 다음 단계 조건 |
| --- | --- | --- |
| 1 | 같은 색 블럭의 한 칸 간격, C자 배치 | 연습 블럭을 유효한 자리에 배치 |
| 2 | 같은 색 기존 블럭 두 개와의 간격, 마름모 배치 | 연습 블럭을 유효한 자리에 배치 |
| 3 | 다른 색과는 맞닿아도 됨, 파란 블럭 배치 | 연습 블럭을 유효한 자리에 배치 |
| 4 | 선택·회전·배치, 같은 색 능력 활성 | 빨간 능력 2칸 활성 |
| 5 | 두 색 블럭을 번갈아 선택·회전·배치 | 각 색 능력 2칸씩 활성 |

대화의 빠른 넘김은 문장만 넘긴다. 필수 가이드에서는 상단 단계 점프·이전·닫기·배경 클릭·뒤로가기로 실습을 건너뛸 수 없다. 실습은 기존 `RunePracticeModel`의 연습 블럭만 사용하므로 지급한 실제 룬·무기 배치·숙련·개방 상태를 바꾸지 않는다. 종료 후 도움말에서 다시 여는 가이드는 기존처럼 자유롭게 탐색·종료할 수 있다. 한국어·영어 대사와 기존 NPC 초상화를 사용한다.

## 소유와 저장

`AccountGuide.runeBoard`가 `Waiting → Reward → Emblem → OpenBoard → Practice → Complete`와 다음 실습 페이지(0~5)를 계정 단위로 저장한다. 지급된 실제 룬 ID도 기록한다. `RuneBoardTutorial`은 진행 판정을, `GameStore.Transact`는 보상과 진행의 원자적 저장을 소유한다. 일회성 요청 ID로 재시도 시 중복 지급·중복 단계 진행을 막으며 저장 실패는 성공 상태를 채택하지 않는다.

룬 블럭 세트(`RewardBoxes.json`의 `rune-starter`)는 첫 클리어 약속이 아니라 안내 자체가 준다. `GameStore.ClaimRuneBoardTutorial`이 고정 ID `rune-lesson-starter` 상자를 만들어 같은 `Transact`에서 열고(재시도·저장 실패 롤백 보장), 균열 15단계 첫 클리어 상자에서는 이 세트를 뺐다(서버 계약 `server/testdata/liveops-contract.json`과 생성 스키마를 같이 맞췄다). 일반 상자 개봉·운영 지급을 해방 보상으로 오인하지 않는다. 옛 15단계 결과창 방식으로 `Reward` 단계에 머문 저장은 저장된 15단계 약속의 세트를 소비하고 두 번째 세트를 주지 않는다.

UI는 기존 `StoryDialogueWindow`, `PrologueGate`, `TutorialAnchorRing`, `RuneBoardWindow`와 5단계 `RunePracticeModel`을 연결한다. 새로운 창 프레임·배치 검증기·퍼즐을 만들지 않는다. 필수 실습 모드만 완료 조건·탐색 제한·진행 저장을 적용한다. 실제 무기 편집은 기존 `RuneBoardSession`과 `GameStore.CommitRuneBoardState`를 사용한다. [공통 UI 계약](Shared_UI_Contract.md)의 룬 어댑터를 따른다.

재시작하면 저장된 단계부터 재개한다. 시작 전 대기는 `ContentUnlockState.introduced`(안내를 마친 콘텐츠 목록)와 `introSeeded`로 판정한다. 필드가 없는 기존 저장은 처음 읽을 때 이미 열려 있던 콘텐츠를 모두 "안내 마침"으로 기록하므로 룬 보드를 이미 연 계정(균열 15 이상, 전부 개방, 수업 진행·완료)은 안내를 다시 받지 않고 잠기지도 않는다. 룬 보드가 아직 닫혀 있던 균열 10~14 계정은 읽는 즉시 보드가 열리고 마을 첫 도착에 안내를 한 번 받는다. 수령 후 착지 전 종료되면 자물쇠 해제와 인장 연출부터, 가이드 진행 중 종료되면 아직 완료하지 않은 페이지의 NPC 설명·연습부터 다시 시작한다. 이미 완료한 페이지는 반복하지 않는다.
