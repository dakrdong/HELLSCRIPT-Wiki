# 사냥 칙령 v0.2 저장 연결 개발 기록

작성일: 2026-09-10 · P0 1단계 · 원본 보관과 구형 저장 이관

## 적용 범위

`Assets/Plans/next-development-plan.md`의 P0 항목은 사냥 칙령 v0.2를 화면·전투와 연결하도록 요구한다. 그런데 지금까지 `HuntEdictV2Document`를 보관할 자리가 없었다. 원본을 만들고 검사하는 함수는 있었지만 계정 저장에는 들어가지 않아 편집도 실행도 이어질 수 없었다. 이 단계는 그 자리를 만든다.

이 단계에서 전투 판단은 바뀌지 않는다. 저장된 원본을 읽는 곳은 아직 없으며, 기존 `BuildConfig` 규칙이 그대로 영웅의 행동을 결정한다.

## 보관 위치

`HeroSave.edict`에 직업별 원본 하나를 보관한다. 계정이 아니라 영웅에 두는 이유는 원본이 직업 고유의 스킬 ID를 담기 때문이다. 저장 형식의 버전은 올리지 않았다. 필드가 하나 늘어날 뿐이며 기존 필드의 뜻은 그대로다.

## 구형 저장 이관

`HuntEdictV2Storage.Normalize`가 계정을 읽을 때 영웅마다 실행된다.

| 저장 상태 | 처리 |
|---|---|
| 원본이 없음 | 직업 기본값으로 새로 만든다. |
| 다른 직업의 원본 | 이 영웅에게 적용할 수 없으므로 기본값으로 바꾼다. |
| 더 새로운 버전 | 불러오기를 중단한다. 저장 파일은 건드리지 않는다. |
| 읽을 수 없는 원본 | 불러오기를 중단한다. 조용히 기본값으로 되돌리면 영웅의 전투 방식이 말없이 바뀐다. |
| 정상 원본 | 정규화만 하고 값은 유지한다. |

`JsonUtility`는 없는 직렬화 클래스를 `null`이 아니라 빈 객체로 만든다. 따라서 부재 판정은 참조가 아니라 내용으로 한다. 이 함정은 기존 `suspendedRun`과 프리셋 칸 처리에서도 같은 방식으로 다룬다.

새 원본의 사용 스킬 네 칸은 영웅이 이미 사용하는 `BuildConfig.activeSkills`에서 가져온다. 그렇게 하지 않으면 이관 직후의 원본이 영웅의 실제 장착과 어긋난 채로 시작한다.

## 검증

전체 Edit Mode 검사 **1,045개**가 통과했다. 이 중 저장 연결 검사는 8개다.

| 검사 | 확인한 결과 |
|---|---|
| 새 계정 | 영웅 3명이 각각 자기 직업의 정규 원본을 갖는다. |
| 사용 칸 이관 | 네 칸이 기존 장착 스킬 순서를 따른다. |
| 구형 저장 | 원본이 없는 저장을 읽으면 직업별로 새로 만든다. |
| 직업 불일치 | 다른 직업의 원본은 이 영웅의 기본값으로 바뀐다. |
| 새 버전 | 불러오기를 중단하고 저장된 원본을 그대로 둔다. |
| 손상된 원본 | 되돌리지 않고 불러오기를 중단한다. |
| 왕복 보존 | 바꾼 옵션이 저장과 불러오기를 거쳐 유지된다. |
| 정규 원본 | 다시 정규화해도 내용이 달라지지 않는다. |

`Artifacts/Validation/edict-storage-editmode.xml`에 보고서를 보존했다.
