# 보석 효과·소켓 보호·저장 기반

> 2026-09-23: 아래 초기 구현 기록의 3:1·골드 합성은 현재 보석상에서 5:1 합성·1:5 분해, 골드 비용 없음으로 바뀌었다. 과거 검증 기록은 보존한다. 현재 규칙은 [보석상 NPC 콘텐츠](Jeweler_Runtime.md)를 따른다.

작성일: 2026-09-13 · [English](Gem_Socket_Foundation.en.md)

상태: 효과·장비 보호·저장과 화면 연결을 구현했고, 최종 전체 검사 2,380개와 macOS 앱 실행·재시작·복구 검사 3회를 통과했다. 보석 획득과 보관함·거래 서비스 전체의 완료 기록은 아니다.

## 이번 구현 범위

[보석·소켓 상세안](../Design/HELLSCRIPT_Gem_Socket_Detail.md)의 보석 7종·6단계·세 부위별 표를 `GemCatalog`에 등록했다. 손·발·허리를 제외한 무기·머리·몸통·목걸이·반지에만 희귀 이상 장비당 소켓 하나를 허용한다. 일반·마법 장비, 중복 소켓과 잘못된 소켓 번호는 거부한다. 보석이 없는 기존 장비의 접사와 수치는 유지한다.

장착한 보석만 실제 능력치를 바꾼다. 무기 속성 피해는 기존 가산 피해 구간에 합산하고, 해골의 극대화 피해는 기본 150%에 더한다. 최대 HP·자원 회복·이동·저항·물약 회복·보호막 생성량은 기존 능력치 계산을 사용한다. 해골의 방어도 비율은 힘·장비 기본값·강화·접사로 계산한 방어도 전체에 적용한다. 장착을 해제하면 해당 기여가 사라지며 보석은 원래 장비에 남는다.

청옥의 방어구 효과는 다른 버프와 같은 피해 감소 50% 상한을 쓴다. 일반 장비의 피해 감소 능력치에 중복으로 더하지 않는다. 취옥의 방어구 효과는 반복 피해에 별도로 곱해지며 기존 전체 감소 계산의 상한을 유지한다. 현재 적용 대상은 일정 간격으로 피해를 주는 적의 위험 구역과 반복되는 기존 지면 효과다. 한 번의 폭발·근접 타격·투사체에는 적용하지 않는다. 캐릭터에게 부착되는 중독 등 새로운 상태이상은 이번에 추가하지 않았다.

위험 예측과 실제 피격은 보석의 피해 감소와 반복 피해 판정을 공유한다. 기존 반복 지면 효과는 마지막 피해까지 반복 속성을 유지하며 저장 후에도 이어진다. 위험 예측의 기존 범위인 이미 예고된 공격·현존하는 효과를 유지하며, 아직 일어나지 않은 적의 판단이나 확률 회피를 새로 예측하지 않는다.

## 장비 보호와 비교 화면

보석이 박힌 장비는 개별 판매·분해, 일괄 판매·분해, 가방 부족 시 기존 장비를 버리는 자동 교체에서 제외한다. 일괄 처리 미리보기 뒤 소켓 상태가 바뀌면 기존 확인을 적용하지 않는다.

자동 정리의 `bag.protectSocketed` 옵션은 보석 장비의 **창고 이동까지 막는 추가 보호**로 연결했다. 이 옵션을 꺼도 보석을 파괴하는 판매·분해는 허용하지 않는다. 기존 기획의 ‘추가 보호 선택’과 ‘보석 분리 전 판매·분해 금지’를 이렇게 함께 만족시킨다. 추가 보호를 끄고 창고로 옮겼다가 다른 가방으로 돌려보내도 소켓과 보석을 유지한다.

장비 상세의 접사 아래에 소켓 유무, 보석 종류·단계와 현재 부위의 효과를 표시한다. 교체 미리보기는 보석을 포함한 실제 HP·피해·방어도·저항·회복 수치를 계산하고, 교체로 빠지는 보석 효과와 그 보석이 기존 장비에 남는다는 안내를 제공한다. 능력치 화면에는 청옥·취옥의 별도 감소 항목을 표시한다. 한국어·영어와 기존 반응형 장비 열람 구조를 사용하며, 이미지·사운드 리소스와 씬·프리팹은 새로 만들지 않았다.

장비 화면 하단은 번역된 버튼 문구의 실제 높이에 맞춰 공간을 확보한다. 좁은 화면에서는 ‘뒤로’·‘보관함’처럼 짧은 문구를 사용한다. 보석 장착 상태와 장착하기 동작도 서로 다른 번역 키로 구분했다.

## 저장과 복구

`Item.sockets`에 소켓 번호·보석 ID·단계를 저장한다. 소켓이 없는 기존 파일은 빈 목록으로 읽는다. 장비 데이터 버전은 3으로 올렸으며 소켓이 있는 장비를 저장할 때에도 최소 버전 3을 기록한다. 소켓 필드를 모르는 이전 실행본은 기존의 새 장비 버전 차단 경로로 중단하도록 한다.

알 수 없는 보석 ID나 범위 밖 단계는 장비를 남기고 빈 소켓으로 복구한다. 복구한 값을 저장하기 전에 원본 파일을 별도 `*.gem-recovery-*.json`으로 복사한다. 원본 보관에 실패하면 불러오기를 중단한다. 장비 종류·소켓 개수·소켓 번호 자체가 지원 범위를 벗어나면 임의로 줄이거나 오래된 계정으로 돌아가지 않고 원본을 보존한 채 중단한다. 정상 복구 시 게임 시작 안내에 복구 사실을 표시하며 내부 경로는 안내 문구에 노출하지 않는다.

계정 거래는 기존의 사본 검증·파일 확정·실제 객체 반영 순서를 유지한다. 이번 단계에서 계정이나 캐릭터에 보석 보관함을 임의로 추가하지 않았다.

## 합성과 드롭의 자료 기준

`GemStacks`는 보관함 소유자와 독립적인 묶음 계산을 담당한다. 묶음당 999개, 같은 종류·단계의 기존 묶음 채우기, 빈칸을 이용한 초과분 보관과 3개를 소비해 1개를 만드는 합성을 처리한다. 수량·골드·출력 공간이 부족하면 입력 묶음과 골드를 바꾸지 않는다. 이 기능을 실제 계정 거래에 연결하는 일은 보관 방식을 결정한 뒤 진행한다.

합성 비용 공식 `300 × 3^(k−1)`은 유지했다. 기존 문서의 합계만 36,300에서 **364,500골드**로 정정했다. 1단계 243개로 6단계 한 개를 만들 때 각 단계에서 총 72,900골드씩 다섯 번 소비한다. 단계별 한 번의 합성 비용은 900·2,700·8,100·24,300·72,900골드다.

일반 적 1.5%, 정예 8%, 보스 2개 확정과 단계별 추첨 표는 카탈로그의 시작값으로 등록했다. 생성 함수는 같은 시드에 같은 결과를 내며 4단계 이상을 추첨하지 않는다. **현재 균열·소탕 보상에 보석을 지급하도록 연결한 상태는 아니다.** 상자·미실행 보상에도 추가하지 않았다.

## 검증

Unity 6000.6.0f1의 [최종 전체 검사](../../Artifacts/Validation/GemSockets/Full3.xml)는 **2,380개 모두 통과**했다. 같은 소스로 만든 `Builds/macOS-GemSockets/HELLSCRIPT.app`의 최초 실행·별도 재시작·잘못된 보석 값 복구 검사도 각각 종료 코드 0으로 끝났다. 복구용 원본 사본이 손상된 시험 파일과 바이트 단위로 같은지 확인했다. 앞선 관련 검사 378개는 중간 단계 기록이며 최종 판정은 전체 검사 결과를 따른다.

최종 앱의 한국어·영어, 세로·짧은 가로, 글자 크기 140%, 장비 비교·능력치·복구 안내 화면 **9장**을 직접 검토했다. [검증 요약](../../Artifacts/Validation/GemSockets/validation-summary.json), [화면 검토 기록](../../Artifacts/Validation/GemSockets/visual-review.json), [검사 소스와 실행 파일 해시](../../Artifacts/Validation/GemSockets/validated-source.json)를 남겼다. 기존의 관계없는 변경 파일 19개는 그대로 보존했다. 로컬·원격 브랜치와 작업 폴더는 `main`만 유지하며 클로드의 병합 기록도 포함되어 있다.

## 남은 연결과 확인할 결정

계정 공용 보석이라는 원칙과 기존 캐릭터별 장비 가방의 칸 규칙이 서로 맞지 않아 보관 방식을 확인 중이다. 권장안은 **계정 공용 보석 가방을 별도로 두고 기본 50칸, 묶음당 999개로 사용하는 방식**이다. 다른 선택은 캐릭터별 장비 가방의 칸을 함께 사용하고 공용 창고로 공유하는 방식이다. 아직 사용자 결정으로 확정하지 않았다.

결정 후 보관함의 실제 소유권·용량·저장 필드를 연결하고, 균열·소탕의 중복 없는 보석 보상과 가방 부족 처리를 구현한다. 재설정 담당의 소켓 내기·장착·교체·분리·합성 화면, 비용 확인과 재시도, 빈 소켓을 눌러 보석을 고르는 흐름도 남아 있다. 장비 품질 체계와 실제 장기 파밍 측정은 별도 후속 작업이다.
