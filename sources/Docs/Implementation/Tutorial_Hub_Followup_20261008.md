# 튜토리얼 대기실 후속 정리와 영웅별 튜토리얼

갱신일: 2026-10-08 · [English](Tutorial_Hub_Followup_20261008.en.md)

사용자의 요청 여섯 가지를 한 PR에서 처리했다. 대기실의 구현 기록은 [퍼즐 대기실 네이티브 구현](Puzzle_Hub_Native.md), 전투·마을의 공통 바로가기는 [플레이 콘텐츠 독](Play_Content_Dock.md), 사냥 칙령 창은 [사냥 칙령 요약](Hunt_Edict_Overview.md)이 소유한다. 이 문서는 이번에 바뀐 위치·크기·규칙과 검증 범위를 한곳에 모은다.

## 1. 대기실에는 진행할 레벨만 보인다

레벨 이름판 양옆의 좌우 버튼과 키보드 좌우 화살표를 없앴다. 지난 레벨을 다시 풀 이유가 없으므로 대기실은 항상 지금 풀어야 할 레벨(복습은 복습하는 레벨)만 보여 준다. 이름판의 가로 위치는 상태 영역(가로 화면에서 왼쪽)과 겹치지 않는 범위에서 가운데에 둔다. `hub-left`, `hub-right` 버튼과 `PuzzleHubWindow.MoveLevel`, 영웅 준비용 `prepare` 콜백이 사라졌다. 네이티브 스모크는 두 버튼이 없고 키보드 좌우 입력이 레벨·재화를 바꾸지 않는지 확인한다.

## 2. HP·자원·경험치 영역이 페이지와 함께 움직인다

상태 영역은 고정 오버레이(정렬 순서 600)라서 다른 메뉴로 넘어갈 때 슬라이드하지 않고 전환이 끝난 뒤에 갑자기 사라졌다. 슬라이드 중 위치를 `상태 오프셋 = 페이지 위치 − 홈 위치`로 맞춰 페이지와 같은 방향·속도로 밀려 나가고 밀려 들어온다. 전환이 끝나면 오프셋을 0으로 되돌린다. 스모크 `CheckStatusSlides`가 슬라이드 0.2초 시점에 오프셋이 페이지 오프셋과 같은지(나갈 때와 들어올 때) 확인한다.

## 3. 하단 메뉴: 스킬 → 대장간, 스킬은 사냥 칙령 안으로

대기실 하단 메뉴가 `인벤토리 · 사냥 칙령 · 대기실 · 대장간 · 설정`이 됐다. 버튼 이름 `hub-menu-0…4`는 그대로이고 3번이 스킬에서 대장간으로 바뀌었다.

- **대장간**: 기존 `BlacksmithWindow`를 그대로 연다(`PuzzleStore`를 쓰므로 복습 중에는 임시 계정). 서비스 네 가지는 마을과 같은 균열 해금 조건을 따른다. 튜토리얼 계정은 해금이 없어 지금은 봉인 화면과 해금 조건 안내가 보인다. 튜토리얼 레벨에서 어떤 서비스를 열지는 `ContentUnlocks` 규칙으로 정하면 창이 그대로 내용을 보여 준다. 아이콘은 `Docs/Art/PuzzleHub/ui-kit-4-*`에 프롬프트·출처가 있는 새 그림(`Resources/Art/PuzzleHub/ui/icon-blacksmith.png`)이다.
- **사냥 칙령 창의 탭**: 튜토리얼에서 `요약` 탭은 전투 방식 카드가 열리는 레벨(L4부터)에서만 보이고, 그 전에는 `스킬 · 전투 · 생존`(이후 열리는 줍기·가방·탐색 등)만 보인다. 창이 처음 열릴 때 선택되는 탭은 그 레벨의 스킬을 아직 익히지 않았으면 `스킬`, 익혔으면 첫 규칙 탭이다. `요약`을 완전히 없애지 않은 이유는 L4 "전투 성향"의 답(공격적/균형/신중 카드)이 요약 탭에 있고 기존 스모크가 그 카드를 누르기 때문이다.
- **첫 스킬 강제 안내(L1)**: 가리키는 버튼이 `hub-menu-3`에서 `hub-menu-1`(사냥 칙령)로 바뀌었다. 안내 문구는 "사냥 칙령을 열어 스킬 탭에서 첫 번째 힘을 익혀라."로 바꿨다(`GameUI.TutorialPit.cs`). `PuzzleHubWindow.SkillButton`은 `MenuButton(int)`로 일반화했다.

## 4. 전투 화면의 설정 톱니·콘텐츠 바로가기·이벤트 아이콘이 스킬 아이콘 크기가 된다

가로 854×450에서 도크 아이콘은 약 17픽셀, 스킬 아이콘은 약 38픽셀이었다(도크는 페이지 단위 44로 고정). 마을이 이미 쓰던 식을 `GlobalHudLayout.ShortcutIcon`으로 꺼내 전투도 같이 쓴다. 크기 = 스킬 아이콘의 화면 크기 × 1.15(엠블럼 그림이 사각형의 약 13%를 투명 여백으로 두므로 보이는 원이 스킬 아이콘과 같아진다)이며, 여섯 개가 HUD 위에 들어가는 높이로 제한한다. 최소값은 마을이 44화면 픽셀, 전투가 원래 고정이던 44 페이지 단위다. 가로 16:9 화면에서는 해상도와 관계없이 88.3 페이지 단위(1600×900에서 88픽셀)다.

- 설정 톱니는 마을처럼 판 없이 같은 크기로 키웠고, 그 아래로 도크가 접히고 펼쳐진다. 관찰 메뉴(☰)·절전 모드·탈출·지도 패널·위쪽 문구는 이 열의 너비만큼 왼쪽으로 물러난다(지도 패널의 `68`·`208`·`120` 상수가 도크 너비에서 나온 값이 됐다). 왼쪽의 이벤트 아이콘도 같은 크기다.
- 세로 화면은 스킬 아이콘이 가로 구성을 폭에 맞춰 줄인 크기라 1.15배가 원래 고정값 44 페이지 단위(44.7)와 거의 같다. 그래서 세로의 배치는 거의 그대로이고(440×956에서 24픽셀, 스킬 아이콘 21픽셀), 지도 패널과 보스 상태 폭도 달라지지 않는다. 전투에 마을의 44화면 픽셀 바닥을 쓰면 작은 시험 창에서 열이 두 배로 넓어져 지도 패널과 보스 상태가 좁아지므로 쓰지 않았다.

## 5. 영웅마다 튜토리얼 진도를 따로 진행한다

계정의 튜토리얼 필드 다섯 개(`mapComplete`, `mapHero`, `armorId`, `tutorialRun`, `puzzle`)는 **선택한 영웅의 몫**이다. 다른 영웅의 몫은 `guide.tutorialSlots`에 보관한다. 영웅을 바꾸는 곳(캐릭터 선택 화면 `SaveEntryCharacter`, 게임 안 `SwitchCharacter`, 개발용 `SelectHero`)은 `Tutorials.Switch(계정, 이전, 다음)`을 거쳐 이전 영웅의 몫을 슬롯에 넣고 다음 영웅의 몫을 꺼낸다. 시작하지 않은 영웅은 처음부터 시작한다. 기존 코드 150여 곳이 읽는 `guide.puzzle`·`Tutorials.Mandatory` 같은 필드는 그대로이고 가리키는 영웅만 바뀐다.

- 튜토리얼 중에는 설정에서 `캐릭터 변경` 탭을 없앴다(`GameController.CanChangeCharacterFromSettings`도 막는다). 다른 캐릭터를 하려면 로그아웃하고 다시 들어와 캐릭터 선택 화면에서 고르면 그 캐릭터의 튜토리얼 진도를 이어서 한다. 로그아웃(`타이틀로 이동`)은 원래 `캐릭터 변경` 탭 안에 있었으므로 튜토리얼 중에는 `계정` 탭 맨 위로 옮겼다. 타이틀·캐릭터 선택 화면에서 여는 설정은 그대로 캐릭터 탭이 있다.
- 저장 이전: 튜토리얼 슬롯 버전(`tutorialSlotVersion`)이 0인 저장은 처음 읽을 때 한 번 정리한다. 튜토리얼을 끝낸 계정은 이미 있는 영웅 모두 끝낸 것으로 본다(이전 규칙에서 계정 전체가 해제됐기 때문). 진행 중이던 튜토리얼은 그 영웅의 슬롯으로 보내고, 지금 선택된 다른 영웅은 새로 시작한다. 면제 계정은 그대로 면제다.
- 보관한 몫도 선택한 몫과 같은 검사를 거친다(몫을 꺼내 검사하고 되돌린다). 영웅이 없는 몫은 버리고 영웅마다 하나만 남긴다. 잘못된 몫은 기존처럼 "원본 저장 보존" 예외로 읽기를 거부한다.
- 한 영웅이 졸업해도 다른 영웅의 튜토리얼은 그대로 남는다. 졸업 보상 금화(1,000)와 졸업 장비는 거래 키에 영웅 ID가 있어 영웅마다 한 번 지급된다.

## 6. 효과음

- 대기실의 그림 버튼은 모두 `Icon` 역할이라 #76 이후 클릭음이 `ui.click`으로 바뀌었다. `UiButton.SoundCue`로 의미를 지정한다(시작 = `ui.click_primary`, 하단 메뉴 = `ui.tab`).
- 메뉴 전환 슬라이드는 열 때 `ui.open`, 돌아올 때 `ui.close`를 낸다(같은 프레임의 클릭음은 기존 규칙대로 양보한다).
- 튜토리얼 도전이 시작될 때(`ContinueTutorial`) 균열 진입음 `flow.rift_enter`를 낸다. 전투 함성은 튜토리얼이므로 내지 않는다.
- 새 효과음 파일은 만들지 않았다. ElevenLabs 접근 수단이 이 세션에 없었다. 새로 만들 후보와 프롬프트는 이 문서 아래에 적었다.

| 후보 ID | 장면 | 지금 쓰는 소리 | 만들 소리(프롬프트 초안) |
| --- | --- | --- | --- |
| `puzzle.page` | 대기실 메뉴 슬라이드 | `ui.open`/`ui.close` | 두꺼운 돌문이 미끄러지는 낮은 쓸림 0.4초, 끝에 짧은 철 울림 |
| `puzzle.start` | 레벨 시작 | `flow.rift_enter` | 구덩이 철문이 올라가는 사슬 소리와 짧은 모래 바람 1초 |
| `puzzle.hint` | 힌트 공개 | 없음(대화 넘김) | 양피지를 펴며 울리는 작은 종 한 번 0.5초 |

| `hazard.pull` | L7 인력 붕괴 끌림 | 없음 | 공기가 한곳으로 빨려드는 낮은 소용돌이 2초(주기마다) |

## 튜토리얼 문구 담당에게 전달할 UI 변경

버튼 위치와 이름이 바뀌어 안내 문구와 가리킴(링)이 영향을 받는다.

1. 대기실 하단 메뉴 3번이 스킬에서 대장간으로 바뀌었다(`hub-menu-3`). 스킬은 `hub-menu-1` 사냥 칙령 안의 `edict-tab-skills`에서 배운다.
2. 사냥 칙령 창의 탭은 `스킬 · 전투 · 생존`이다. `요약`(`edict-tab-overview`)은 L4 이후 전투 방식 카드가 열릴 때만 보인다. L1에서는 `스킬` 탭 하나뿐이다.
3. 대기실에 레벨 좌우 버튼(`hub-left`, `hub-right`)이 없다.
4. HP·자원·경험치 영역은 메뉴를 넘길 때 페이지와 같이 움직인다.
5. 전투 화면 오른쪽 위: 설정 톱니, 그 아래 도크(`콘텐츠 메뉴`, `사냥 칙령` …), 왼쪽의 이벤트 아이콘(`field-events`)이 모두 스킬 아이콘 크기로 커졌다. 위치가 아래로 내려갔다.
6. 설정에서 튜토리얼 중에는 `캐릭터 변경` 탭이 없고 `계정` 탭에 `타이틀로 이동`이 있다. 영웅마다 튜토리얼 진도가 따로다.
7. 첫 스킬 안내 문구 한 줄을 바꿨다(`GameUI.TutorialPit.cs`의 `PitSkillLessonStep`, `en.txt`).

- Edit Mode 전체 1회(최종 코드 기준): 5,643개 중 5,641 통과·0 실패·2 건너뜀(`MeasureEveryDesignBuild`, `Capture`는 원래 건너뛰는 검사).
- 집중 검사: `TutorialHeroSlotsTests`(영웅별 몫 교환·저장 이전·보관한 몫 검사·저장 후 읽기·게임 안 캐릭터 전환), `GlobalHudTests`(아이콘 크기 식), `PuzzleHubTests`(화살표 없는 배치), 번역 검사(원본 문구와 영어 대응), 공통 UI 검사.
- `check_ui_contract.py --verify` 15개, `check_ui_refresh.py` 14개 바인딩, 소리 은행 검사(283종·문제 0)와 `elevenlabs_audio.py --check` 통과.
- macOS 개발 플레이어(실제 포인터 입력): 전체 튜토리얼 스모크(L1~졸업) 전사 한국어 1600×900(대기실 10개 배치·안전 영역 4개 포함), 궁수 영어 956×440, 마법사 한국어 440×956이 모두 끝까지 통과했다. 새 검사는 하단 메뉴의 대장간(`BlacksmithWindow`가 하위 창으로 열리고 탐색 띠 옆에 놓임), 사냥 칙령의 탭 구성, 설정의 탭 구성, 상태 영역 슬라이드, 레벨 화살표 부재, L4의 요약·스킬·전투·생존 탭이다. 전투 배치 스모크(전투 아이콘 세 개의 크기 포함)·지도 표시 스모크·화면 설정 스모크도 통과했다.
- 로그아웃 후 다른 영웅을 고르는 실제 흐름(대기실 설정 → 계정 → 타이틀로 이동 → 게스트 → 다른 영웅 시작 → 다시 로그아웃 → 첫 영웅 시작)과 메뉴·도전 시작의 소리도 통과했다. 이 흐름에서 타이틀로 나가도 대기실 창이 타이틀 위에 남아 버튼을 가리는 오류가 발견되어 고쳤다(`ShowTitle`이 대기실을 먼저 닫는다). 대기실 설정에서 로그아웃하는 길은 이전에도 있었지만 그 뒤 타이틀 화면의 버튼을 눌러 본 적이 없던 경로였다.
- 기준 빌드(`f05bbc28`)에서도 이미 실패하는 스모크: 콘텐츠 독 스모크(새 계정이 필수 튜토리얼과 출석 팝업으로 막혀 마을 독을 못 봄), 전투 탈출 스모크("Expected two captions"). 이번 변경과 무관하며 수정하지 않았다.
- 전체 검사 뒤 스모크 파일만 고쳤으므로 Edit Mode 전체는 다시 돌리지 않았고 관련 튜토리얼 스모크만 다시 실행했다.

### 검증하지 않은 것

- 휴대폰·태블릿 실기기에서 보지 않았다. 화면은 macOS 개발 플레이어의 창 크기로만 확인했다.
- 새 효과음 파일은 만들지 않았고 청음 시험은 하지 않았다.
- 대장간 창의 서비스 화면은 튜토리얼 계정에서 봉인 상태만 확인했다.
- 오래된 클라이언트가 이 저장을 다시 저장하면 다른 영웅의 튜토리얼 몫을 잃는다(새 필드를 모른다). 한 번에 같은 빌드를 쓰는 개발 단계에서는 문제가 되지 않는다.
