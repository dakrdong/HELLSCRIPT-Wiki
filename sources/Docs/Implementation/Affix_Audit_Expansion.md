# 접사 분포 검사와 20단계 대조 실험

작성일: 2026-09-12 · [English](Affix_Audit_Expansion.en.md)

상태: **검증 도구·접사 분포 검사와 체계당 600판의 확대 전투 비교를 완료했다. 밸런스 수치 조정과 자연 성장 검증은 남아 있다.**

## 구현한 내용

클로드 변경을 합친 `92d5812`를 기준으로, [남은 작업표](../Design/HELLSCRIPT_Remaining_Development_Backlog.md)의 접사 희석과 20단계 재측정을 진행했다. 게임의 접사 가중치·전투 수치·저장 형식은 유지하고 Unity Editor의 검사 도구를 보완했다.

- 기존 밸런스 보고서는 사망과 시간 초과를 같은 원인으로 집계하고, 포탈 등으로 중단된 판도 시간 초과로 표시했다. 이제 승리·사망·시간 초과·포기·기타 실패·길 막힘·포탈 정리·일시정지·검사 틱 한도를 구분한다. 완료되지 않은 판은 `incomplete`로 따로 센다.
- 새 대조 도구는 판마다 지도, 초기 적의 상태를 요약한 해시, 장착 장비 8개, 능력치 57개, 스킬별 누적 기록, 보스 도달·남은 HP, 관문 상태와 최근 로그를 저장한다. 장착 실패를 무시하지 않는다.
- 장비 부위마다 독립된 난수 줄기를 사용한다. 한 부위에서 접사 추첨 횟수가 달라져도 다음 부위의 베이스가 달라지지 않는다. 지도·초기 적·장착 베이스·세트가 다르면 비교 보고서 생성을 거부한다.
- 접사 검사는 실제 `ItemGenerator.Create`를 호출한다. 별도의 계산기는 허용 부위, 직업 가중치, 접두·접미 배분, 같은 그룹 중복 금지를 반영해 각 옵션이 장비 하나에 붙을 확률을 계산한다.

소유 파일은 `BuildIntegrationValidation.cs`, 새 `BuildIntegrationValidation.BalanceAudit.cs`, `AffixDistributionValidation.cs`, Editor 검사 두 파일과 `tools/analyze_affix_audit.py`다. 새 코드는 기존 Editor·테스트 어셈블리에 둔다. 씬·프리팹·패키지를 변경하지 않았다.

## 접사 분포 결과

현재 54종과 비교용 24종 각각에서 **3직업 × 8부위 × 4등급 × 100,000개 = 9,600,000개**를 생성했다. 두 체계 합계는 **19,200,000개**이며 아이템 레벨은 30이다. 일반 등급의 접사 0개도 검사에 포함한다.

접사·배분·티어에 대한 **12,864개 비교가 모두 통과**했다. 접사와 배분은 장비 개수, 티어는 실제 추첨된 옵션 줄 수를 분모로 사용한다. 각 비교는 Bernstein 기준과 항목당 유의 수준 `1e-8`을 사용하며 확률 0·1인 사건은 정확한 개수를 요구한다. 고정 난수 표본에 대한 진단 기준이며 난수 독립성을 증명한 결과는 아니다.

아래는 **전사 전설 등급**의 예다. 특정 옵션이 장비 한 개에 붙을 확률이며, 전설 등급 자체의 드롭 확률이나 옵션 값의 크기가 아니다.

| 부위·옵션 | 24종 예상 / 관측 | 54종 예상 / 관측 |
|---|---:|---:|
| 무기·힘 AF11 | 52.65% / 52.53% | 43.49% / 43.15% |
| 무기·치명타 확률 AF16 | 50.11% / 50.36% | 23.04% / 23.19% |
| 몸통·최대 생명력 AF01 | 38.10% / 38.23% | 16.76% / 16.62% |
| 발·이동 속도 AF22 | 75.00% / 74.97% | 53.26% / 53.09% |

기존 옵션의 출현율 감소를 확인했다. 새 접사의 개별 가중치가 35~55라는 이유만으로 기존 옵션이 유지된다고 설명할 수 없다. 추첨 결과는 현재 정의로 계산한 분포와 맞으므로, 이번 검사에서 생성기의 잘못된 추첨은 발견하지 않았다. 새 방어·회복·조건부 피해 옵션의 이득과 성장·파밍 효용을 함께 확인한 뒤 가중치를 조정해야 한다.

54종 체계에서는 발에 세 번째 접두 그룹이 생겨 전설의 P2S2·P3S1·P1S3이 60%·20%·20%로 나온다. 24종 체계의 발은 P3S1을 만들 수 없어 나머지 둘이 75%·25%였다. [장비 기획](../Design/HELLSCRIPT_Itemization_Detail.md)과 [능력치 기획](../Design/HELLSCRIPT_Attribute_System_Detail.md)의 설명을 이 결과에 맞췄다.

## 전투 비교의 조건과 완료 결과

현재의 능력치 57개·지도·해금·전투 규칙을 두 사본에서 동일하게 유지한다. 비교 사본에서만 AF25~AF54의 정의 30개를 제외한다. 비교용 제거는 메인 소스나 실행 앱에 반영하지 않는다. 따라서 클로드의 능력치 구현 이전 전체 게임과 비교하는 실험은 아니다.

영웅 레벨 30, 아이템 레벨 30, 강화 0, 기존 추천 행동과 합법적인 세트 구성을 사용한다. 새 판의 기존 초기화 규칙을 유지하고 사망·시간 초과까지 자연 진행한다. 승리를 위해 HP·피해·시간·위치를 바꾸지 않는다. 새 계정과 검사 기록만 사용하며 사용자 저장에는 쓰지 않는다.

예비 실행은 6빌드 × 2시드, 체계당 12판이다. 지도·적·96개 장착 부위가 일치했고, 현재 54종은 승리 4·사망 1·시간 초과 7회, 비교용 24종은 승리 6·사망 2·시간 초과 4회였다. 미완료·길 막힘은 없었다. 이 표본은 도구 작동 확인용이며 난이도 결론으로 사용하지 않는다.

**6빌드 × 100시드, 체계당 600판을 모두 마쳤다.** 현재 54종은 2026-09-12 14:40:02 UTC, 비교용 24종은 14:38:28 UTC에 정상 종료했다. 두 헤더 모두 `status=complete`, `completedRuns=600`이다. 지도·초기 적이 같은 600쌍과 장착 부위 4,800쌍의 일치를 검사한 뒤 최종 보고서를 생성했다. 미완료·포탈 중단·길 막힘은 두 체계 모두 0회였다.

각 칸은 **승리 / 사망 / 시간 초과** 횟수이며, 빌드·체계마다 100판이므로 승리 횟수와 승률(%)의 숫자가 같다.

| 빌드 | 현재 54종 | 비교용 24종 | 승률 차이 |
|---|---:|---:|---:|
| 전사 · 회오리 생존 | 59 / 0 / 41 | 64 / 0 / 36 | -5%p |
| 전사 · 도약 분쇄 | 47 / 0 / 53 | 51 / 0 / 49 | -4%p |
| 궁수 · 관통 거리유지 | 25 / 3 / 72 | 31 / 2 / 67 | -6%p |
| 궁수 · 맹독 매복 | 35 / 19 / 46 | 40 / 21 / 39 | -5%p |
| 마법사 · 서리 장판 | 22 / 1 / 77 | 24 / 1 / 75 | -2%p |
| 마법사 · 연쇄 제어 | 0 / 22 / 78 | 2 / 23 / 75 | -2%p |
| 합계 600판 | **188 / 45 / 367** | **212 / 47 / 341** | **-4.0%p** |

현재 체계의 승률은 31.33%, 비교용은 35.33%다. 같은 판에서 현재 체계만 승리한 경우는 29회, 비교용만 승리한 경우는 53회였다. 차이는 주로 시간 초과 증가로 나타났다. 표본의 Wilson 95% 구간은 각각 27.75~35.15%, 31.61~39.24%다. 대응 승패의 탐색적 McNemar 양측 p값은 전체 0.0106이며, 여섯 개별 빌드의 p값은 모두 0.21 이상이었다. 다중 비교로 확정한 출시 기준이나 직업 순위로 해석하지 않는다.

현재 체계의 평균 초기 최대 HP는 1,320.99로 비교용 1,419.27보다 낮았고, 기본 피해도 85.09 대 87.09였다. 조건부 피해·방어·회복 발동과 자원·경로가 함께 작용하므로 이 두 평균만으로 승패 원인을 단정하지 않는다. 현재 체계의 시간 초과 367회 중 308회는 보스가 출현한 뒤 끝났다. 연쇄 제어는 두 체계 모두 보스 출현이 45회였고 승리가 0회·2회에 그쳤다. 이 구성의 실제 스킬 가동과 시간 소모를 접사 전체의 문제와 분리해 조사한다.

이 실험은 `c0708b5` 검증 소스와 기존 추천 규칙을 사용했고 사냥 칙령은 꺼져 있다. 이후 연결한 [화염구 사냥 칙령](Edict_Fireball_Expansion.md)의 밸런스 결과로 재사용하지 않는다. 접사 가중치나 피해 수치는 이번 결과만으로 바꾸지 않았다.

레벨 30 고정 검사에서는 경험치 옵션의 성장 이득을 평가하지 못한다. 세트 구성 하나씩의 비교만으로 직업 순위, 희귀 장비 성장 구간이나 모든 전설 조합의 성능을 확정하지 않는다. 과거 보고서의 20단계 승리 12→6회도 현재 통합본의 성능으로 재사용하지 않는다.

## 검증과 재현

| 검사 | 완료 결과 |
|---|---|
| 집중 Editor 검사 | 32개 통과. 결과 판별, 장착 재현성, 그룹별 확률 계산, 배분 경계와 통계 검사를 포함한다. |
| 전체 Editor 회귀 | **1,422개 통과**, 실패·건너뜀 0개. 2026-09-12 13:46:51~13:51:08 UTC에 실행했다. 기획서 파일이 빠진 첫 검사 사본을 보완한 뒤 전체를 다시 검사했다. |
| 보고서 도구 | 실제 예비 표본 대조와 5개 오류·수학 경계 확인을 통과했다. 중복 판·진행 중 표본·다른 적·부위 충돌을 거부한다. |
| macOS 앱 | 기존 `macOS-AttributeIntegration` 앱에서 능력치 실행 검사를 다시 통과했다. 화면 10장을 남겼고 영어 140% 화면을 확인했다. 새 실행 앱을 만들었다는 의미는 아니다. |
| 소스·메타데이터 | Runtime C# 166개가 기존 앱 검증본과 일치한다. 새 검사 사본의 전체 C# 230개가 작업 소스와 일치하며, 누락된 C# 메타와 중복 GUID가 없다. |

증거는 `Artifacts/Validation/AffixBalance/`에 있다. `distribution-summary.json`과 `Full/*/cells.jsonl`은 완료한 분포 결과, `Pilot/`와 `pilot-comparison.json`은 예비 전투 결과다. `Full/*/runs.jsonl`과 헤더는 완료한 확대 실행 원본이다. `comparison.json`은 대조 결과이며 `completion.json`은 종료 시각·정상 종료·보고서 해시를 보관한다. `legacy24-only.patch`는 비교 사본에만 적용한 변경이며, `setup.json`은 검사 위치·기준 커밋·소스 해시를 기록한다. 소스·설정·기획서·분석 도구 631개 파일을 `audited-source.tar.gz`에 보관하고 개별 파일과 압축 파일의 해시를 확인했다. 초기 컴파일 오류와 기획서 누락 검사도 별도 폴더에 보존했다.

Unity의 정적 진입점은 `Hellscript.Editor.BuildIntegrationValidation.RunAffixAuditSuite`다. `-hellscriptAuditOutput`, `-hellscriptAffixProfile`, `-hellscriptAuditStage`, `-hellscriptAuditSeeds`, `-hellscriptDistributionSamples`로 새 출력 폴더와 조건을 명시한다. 프로필 이름과 실제 컴파일된 접사 목록이 맞지 않으면 시작하지 않는다. 기존 결과 파일을 덮어쓰지 않는다.

완료한 원본으로 `python3 tools/analyze_affix_audit.py <current54 출력 폴더> <legacy24 출력 폴더> <새 보고서.json>`을 실행해 대조를 재현할 수 있다. 공개 밸런스 확정, 모바일 실기기 성능과 실제 성장 검증은 남아 있다.
