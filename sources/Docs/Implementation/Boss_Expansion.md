# 보스 3종의 전용 패턴 구현

작성일: 2026-09-09 · 단계: D3 진행 중

## 1. 기준과 변경 범위

[보스 전투 상세 시험안](../Design/HELLSCRIPT_Boss_Combat_Detail.md)을 먼저 작성한 뒤, 집행자·합창자·포식자의 공통 동작을 각 전용 패턴으로 교체했다. [일반 적·정예 개발 기록](Enemy_Expansion.md)의 행동 상태·위험 형상·공격 출처와 [효과 통합](Effect_Expansion.md)의 보스 제압, [같은 틱 정산](Outcome_Expansion.md)을 이어 쓴다. 새 전투 관리자나 별도 이동 권한은 추가하지 않았다.

패턴의 계수는 단계·보스 종류 보정이 끝난 적 공격력에 한 번만 곱한다. 기존 보스 HP·공격 배수는 그대로이며 추가한 준비·속도·배치 수치는 상세 시험안의 개발값이다. 이번 구현을 6빌드 밸런스나 Android 공개 기준 완료로 해석하지 않는다.

## 2. 보스별 동작

| 보스 | 연결한 패턴 |
|---|---|
| 묘지의 집행자 | 고정된 전방 120도 내려찍기, 후반 단계의 0.7초 추가타 예고, 독립 직선 갈고리와 최대 2m 끌어당김을 사용한다. |
| 종말의 합창자 | 준비 시작에 유효 소환 위치를 예약하고 실행 때 다시 검사한다. 자기 부하를 한 번에 최대 4명, 생존 최대 8명까지 소환한다. 고정 광선은 2초 동안 0.25초 간격으로 8번 피해를 준다. |
| 균열의 포식자 | 벽에서 멈추는 실제 돌진, 후반 단계의 0.8초 재조준·두 번째 돌진을 사용한다. 연속 폭발은 세 원을 먼저 예고하고 1.3·1.65·2.0초에 순서대로 폭발시킨다. |

기본 근접·첫 패턴·둘째 패턴은 독립 CD를 가진다. 준비 시작부터 시간이 흐르며 준비·실행·유지 중 다른 주 행동을 시작하지 않는다. 유효한 첫 패턴→둘째 패턴→기본 공격 순으로 고른다. 합창자는 8m 안에서 위치를 유지하고, 필요할 때 기존 보스 속도의 35%로 접근한다.

HP가 50% 이하가 되는 순간 후반 전환을 예약한다. 현재 행동을 마친 뒤 다음 행동 선택부터 적용하며 중간 회복으로 예약을 취소하지 않는다. 이미 예고한 내려찍기나 돌진에 추가타를 끼워 넣지 않는다. 후반 상태·예약·이번 행동의 횟수와 조준을 각각 저장한다.

제압은 준비·돌진·유지 동작을 중단하고 각 CD의 남은 값을 보존한다. 이미 나온 갈고리와 생성된 광선·후속 폭발은 독립 상태로 남는다. 보스 사망 때도 같은 틱에 이미 예정된 다른 피해를 정산한 뒤 전투를 종료한다. 종료 이후에는 새 공격이나 효과 시간을 진행하지 않는다.

갈고리는 실제 투사체 충돌 뒤 저장된 발사 위치를 향해 끌어당긴다. 보행 벽과 살아 있는 몸체 앞에서 멈추고, 끌림이 일어나면 영웅의 진행 중 행동을 중단한다. 이미 쓴 자원과 CD는 복구하지 않는다. 이동기 도중 현재 위치가 보행·착지에 부적합하면 끌림을 생략해 벽 속 착지를 막는다.

부하는 소환자 ID를 가지며 자기 소유의 살아 있는 부하가 있을 때만 합창자의 피해 감소 20%를 적용한다. 다른 사건의 소환 적과 다른 소환자의 부하를 계산에 넣지 않는다. 부하 처치는 처치 수·전투 기록에 남지만 XP·게이지·골드·아이템·일반 사체를 생성하지 않는다. 소환 위치가 준비 도중 막히면 그 자리의 소환을 생략하고 다른 곳으로 몰래 옮기지 않는다.

## 3. 폭발 배치와 피난 경로

영웅의 현재 위치와 양쪽 3.5m를 세 폭발 후보로 삼고 방향을 유한하게 탐색한다. 반경 0.65m 피난 지점 두 곳이 모든 폭발 원 밖에 있고 서로 1.5m 이상 떨어져 있어야 한다. 보행·착지·도달 가능·몸체 간격과 경로를 검사한다. 첫 폭발까지의 1.3초에서 0.2초 판단 간격을 제외한 시간과 실제 이동속도·현재 감속으로 이동 가능한 경로만 허용한다.

이미 예고되었거나 진행 중인 알려진 적 공격·장판·투사체도 후보 경로에서 검사한다. 유효한 배치가 없으면 폭발 CD를 소비하지 않고 1초 후 재검토한다. 그동안 다른 유효한 공격은 사용할 수 있다. 경로·피난 지점·폭발 순서는 행동 상태에 저장해 복원 때 다시 정하지 않는다.

파란 윤곽 두 곳은 이 폭발의 범위 밖이라는 뜻이다. 이후 다른 적이 새로 만드는 공격을 무효화하거나 플레이어의 행동 규칙을 강제로 바꾸는 보호 구역은 아니다. 자동 이동·회피기는 기존 위험 조건과 같은 형상을 사용하며, 위험을 감수하고 공격을 계속하는 설정도 유지한다.

## 4. 저장·화면·구현 소유자

행동 동작 버전은 2에서 3으로 올렸다. 보스의 독립 CD·후반 단계·전환 예약, 진행 중 준비·돌진·유지·추가타, 광선·폭발·갈고리와 피난 경로를 저장한다. 효과 버전 4와 행동 규칙 버전 2는 유지했다.

기존 저장에 남아 있는 공통 보스의 준비는 이미 예고한 위치와 남은 시간으로 한 번 마무리한 뒤 새 패턴을 선택한다. 기존 소환을 반복하지 않는다. 소환자 ID가 없던 구형 부하는 한 균열에 보스 한 명이라는 기존 계약 안에서 읽고, 새 부하에는 명시적 소환자 ID를 기록한다. 더 새로운 행동 버전은 기존 보호 경계에서 불러오기를 거절한다.

전투 HUD에 보스 이름·HP·전반/후반·현재 행동·남은 예고 시간을 추가했다. 시야 밖의 보스는 현재 행동과 HP 대신 위치 확인 안내를 표시한다. 기존 제압 게이지는 유지한다. 적 상태 상세 화면에서도 제압·면역·소환 부하 수·피난 지점을 확인한다. 보스 임시 모델은 중장갑·지원형·돌진형의 서로 다른 실루엣을 사용하고 실제 고정 방향을 바라본다.

| 파일 | 책임 |
|---|---|
| `BossCombat.cs` | 패턴 정의, 저장 가능한 보스 상태·피난 경로, 공통 예고와 폭발 후보 검사를 소유한다. |
| `CombatSimulation.Bosses.cs` | 패턴 선택·CD·전환·소환·돌진·갈고리 강제 이동을 처리한다. |
| `EnemyCombat.cs`·`CombatActions.cs` | 기존 적 행동·독립 효과와 보스 상태·투사체 끌림을 연결한다. |
| `CombatSimulation.Effects.cs`·`Damage.cs`·`Projectiles.cs` | 제압 중단·부하 피해 감소·갈고리 충돌을 기존 처리에 연결한다. |
| `GameUI.Enemies.cs`·`WorldView.Enemies.cs` | 보스 HUD·상태와 공통 판정 자료의 윤곽을 표현한다. |

씬·프리팹·패키지·프로젝트 설정과 이미지 원본을 직접 편집하지 않았다. 기존 프로젝트 구성 도구로 같은 씬·카탈로그를 갱신해 개발 빌드를 만든다. 새 패키지·골격 애니메이션·래스터 이미지는 추가하지 않았다.

## 5. 자동 검사

최종 Unity Edit Mode 결과는 `Artifacts/Validation/bosses-editmode-finalproof.xml`의 **341/341개 통과**, 59.6872443초다. 기존 303개와 보스 검사 38개를 포함한다. 패턴별 준비·CD, 체력 경계·회복, 제압 취소·비용 보존, 고정 조준·벽, 부하 소유·상한·무보상, 광선 8틱, 폭발 세 시점과 두 피난 지점, 준비·유지·돌진·투사체의 같은 미래 상태 복원을 확인했다.

두 테마 각각 12개 시드의 실제 생성 맵, 총 24개에서 보스 방의 두 피난 지점과 보행 경로를 검사했다. 별도 공간 부족·기존 위험 사례에서는 잘못된 배치를 강행하지 않고 해당 패턴을 미루는 것을 확인했다. 이는 모든 시드·적 조합의 안전성이나 기기 성능을 통계적으로 보장한 결과는 아니다.

갈고리의 회오리 중단 검사는 초기 준비에서 감지·목표 선택을 생략한 탓에 탐색 이동이나 유효 적 없음 종료를 함께 측정하고 있었다. 근처 유효 목표와 현재 목표를 갖춘 실제 채널 상태로 시험 배치를 고치고, 끌림 직전의 행동 사건 위치와 끌림 이동 사건을 대조했다. 최종 결과는 회오리가 비용을 사용한 뒤 갈고리로 중단되고 정확히 2m 이동하는 것을 확인한 검사다.

첫 네이티브 폭발 복원 검사에서는 마지막 피해가 끝난 뒤 피난 표시가 한 프레임 남아 검사가 실패했다. 단순히 시간 허용 오차를 늘리는 것만으로는 전투 256초 이후의 누적 차이를 해결하지 못하므로, 표시 수명을 실제 준비·독립 폭발 효과의 종료에 연결했다. 시작 시각 0·128·256초에서 마지막 폭발과 같은 고정 틱에 표시가 제거되는 검사를 보완했다. 위 최종 341개 결과는 이 수정 이후다. 초기 `BossNativeEvidence`, 중간 `BossNativeFinalEvidence`와 최종 실행 증거를 구분해 보존한다.

## 6. 실행 빌드와 실제 재시작 검증

최종 `bosses-build-mac-finalproof.log`에서 macOS 개발 빌드 성공과 오류 0개를 확인했다. 검사 당시의 C# 68개가 빌드 후에도 같은 내용인지 대조하고 `bosses-final-source-manifest.json`에 소스와 실행 DLL의 해시를 기록했다. 이 버전의 실행 증거는 `Artifacts/Validation/BossNativeVerifiedEvidence`에 있다. 초기 실패·중간 수정 빌드의 폴더와 구분한다.

네 번의 일반 앱 실행과 세 번의 실제 프로세스 재시작이 모두 종료 코드 0으로 끝났다. 별도 저장 경로의 30레벨 전사에게 합법적인 희귀 장비 8부위를 장착하고, 패턴별로 고정한 보스 체력·공격력·위치를 사용했다. 후반 패턴은 체력 50%에서 시작한다. 저장 직전과 복원 직후의 전투 ID·시간·난수·HP·자원·영웅 행동·각 적 상태·독립 위험 효과가 같음을 확인했다.

| 사례 | 최종 실행 결과 |
|---|---|
| 집행자의 후반 내려찍기 | 1.25초에 첫 타격과 0.7초 추가타 준비를 저장했다. 재실행 후 1.5배속에서 1.95초에 두 번째 타격을 마쳤으며 총 피해 사건은 정확히 2회다. |
| 집행자의 갈고리 | 실제로 날아가는 투사체를 화면에서 확인했다. 한 번 적중해 정확히 2m 끌어당겼다. 진행 중 채널의 중단·비용 보존은 별도 자동 검사로 확인했다. |
| 합창자의 부하와 광선 | 자기 소유 부하 4명을 소환했다. 광선의 두 번째 피해 이후인 2.90초에 저장하고 재실행했다. 2배속에서 4.40초까지 정확히 8회 피해를 주고 광선이 사라졌다. |
| 포식자의 후반 돌진 | 첫 돌진 후 0.8초 재조준 예고를 표시했다. 두 번째 돌진까지 총 피해 사건 2회를 확인했다. |
| 포식자의 연속 폭발 | 세 원과 피난 지점 두 곳을 예고했다. 1.35초 첫 폭발 이후 남은 두 효과를 저장하고 재실행했다. 1배속에서 2.05초에 마지막 효과와 피난 표시가 함께 사라졌다. 고정된 영웅에게 첫 중앙 폭발만 적중했으며, 복원 때문에 다시 적중하거나 다른 폭발 위치가 바뀌지 않았다. |

Metal 렌더러의 540×960 화면 15장과 각 중간 상태 JSON, `runtime-bosses-smoke.txt`를 보존했다. 공격 예고·추가타·날아가는 갈고리·광선·피난 표시·상태 화면을 확인했다. 앱 내부 화면 전환과 실제 전투를 실행한 결과이며 물리 마우스·터치 입력 검증은 아니다. 피난 경로의 보행 가능성은 자동 검사의 대상이며 이 고정 위치 실행에서 자동 회피 성공률을 측정하지 않았다.

현재 임시 모델의 큰 보스 머리가 상단 HUD에 일부 가려지고 어두운 바닥의 위험 윤곽 대비가 낮은 화면이 있다. D6에서 카메라 구도·대비·형태 표식을 보완해야 하며, 이번 화면 확인을 최종 아트·접근성 완료로 집계하지 않는다.

같은 최종 빌드에서 기존 전체 균열 검사도 별도 저장 경로로 실행했다. 자동 생성 시드 `91367`, 맵 지문 `c8beaf52`, 전투 ID `79444d7688c9458389f1227ac79a56d6`의 탐색 도중 앱을 실제로 종료하고 재시작했다. 맵·HP·시간·난수를 복원한 뒤 자동 전투·상자 개봉·새 포식자 보스·클리어·결과 저장까지 통과했다. 전투 시간 286.5535583초, 처치 87명, 상자 4/6개, 장비 획득 13개이며 캐릭터 초회 보상 사건도 기록됐다.

전체 균열의 증거는 `BossRiftNativeEvidence`, 저장은 `BossRiftNativeSave`, 로그는 `bosses-native-rift-checkpoint.log`·`bosses-native-rift-resume.log`에 있다. 30레벨 전사·희귀 장비 8부위·1단계·상자 탐색 30m·보스 후 회수 설정을 사용한 흐름 검사다. 낮은 레벨부터의 자연 성장이나 6빌드의 균형을 입증한 결과는 아니다. 전체 균열의 두 실행도 종료 코드 0이며, 이번 단계의 최종 실행 증거는 총 6프로세스·4회 실제 재시작·화면 20장이다.
