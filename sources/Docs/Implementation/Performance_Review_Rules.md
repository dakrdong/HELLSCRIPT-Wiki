# CPU 재발 방지와 성능 리뷰 규칙

갱신일: 2026-10-03 · [English](Performance_Review_Rules.en.md)

메뉴·월드 표시, 프레임 갱신, UI·레이아웃과 성능 관련 변경에 적용하는 개발·리뷰 지침이다. [2026-10-02 CPU 실측 기록](CPU_Optimization_20261002.md)의 원인을 다시 만들지 않으며, 기존 [공통 UI 계약](Shared_UI_Contract.md)과 게임플레이·저장·보상 동작을 보존한다.

## 확인된 원인과 결과 범위

| 확인된 원인 | 유지할 구현 기준 |
| --- | --- |
| 불투명한 타이틀·캐릭터 선택 UI 뒤에서 월드 카메라와 지형이 계속 렌더링됐다. | 전체 화면에 가려진 월드 표시는 기존 `World.SuspendPresentation()`으로 쉬게 하고, 실제 월드가 다시 필요한 경로에서 기존 `ResumeCamera()`로 복원한다. 메뉴 UI와 애니메이션은 유지한다. |
| Controller와 UI가 같은 프레임에 `RefreshPlaza()`를 중복 호출했다. | 이동 이후 `GameUI.LateUpdate`의 한 소유자가 연속 상태를 반영한다. 행동 직후의 필요한 갱신은 유지하되 다른 프레임 콜백에 같은 주기 갱신을 추가하지 않는다. |
| 마을 버튼을 매 갱신마다 false→true로 바꿔 활성화와 UI 작업이 반복됐다. | 포탈·NPC·상점 우선순위에서 최종 상태를 먼저 계산하고 한 번 반영한다. 같은 상태에서는 활성화 전환·본문 생성·레이아웃 재구축을 발생시키지 않는다. |

동일 조건 개발 플레이어에서 메뉴 CPU/프레임 감소와 마을 GC 할당 감소를 확인했다. 마을·인벤토리·전투 CPU, 메모리와 프레임시간에는 일관된 개선을 확인하지 못했다. 메뉴·전투의 일부 할당은 증가했다. 이 결과를 전체 장면, 출시 foreground 브라우저, Safari/Firefox 또는 모바일 실기기의 CPU·배터리 개선으로 확대하지 않는다. 수치와 반복 범위는 위 실측 기록을 참조한다.

## 구현과 리뷰 체크리스트

- **표시 수명과 복원:** 월드가 완전히 가려졌는지 먼저 확인한다. 투명·부분 창 또는 표시 중인 전투 월드에 메뉴 최적화를 적용하지 않는다. 기존 카메라 소유자를 재사용하고 별도의 전역 카메라 스위치를 만들지 않는다. 타이틀↔캐릭터 선택, 메뉴 종료·재진입, 마을↔전투 포탈, 절전 진입·해제와 peek/unlock에서 필요한 카메라·UI·입력·오디오·프레임 정책이 복원되는지 확인한다.
- **프레임 갱신 소유권:** 새 `Update`/`LateUpdate` 호출 전에 기존 호출자를 확인한다. 이동 거리·근접 대상처럼 매 프레임 변할 수 있는 값은 이동 후 한 번 갱신한다. 변하지 않은 텍스트·색·버튼·창 배치는 실제 상태가 바뀔 때 반영한다. 주기 중복을 없애면서 행동 직후 표시와 저장 성공 알림 후의 즉시 갱신을 빠뜨리지 않는다.
- **무효화와 공통 부품:** 캐시를 추가하면 언어, 장비/캐릭터, 저장 완료, 창 열기·닫기, 해상도/배치와 근접 대상 변경 등 해당 표시의 모든 의존성을 명시한다. 값이 같은지 확인하려고 매 프레임 같은 문자열이나 목록을 다시 만드는 비용도 측정한다. 기존 표시 함수·공통 UI·버퍼를 먼저 재사용하며, 근거 없이 새 캐시 계층을 만들지 않는다.
- **할당과 레이아웃:** 프로파일에서 반복 비용이 확인된 경로의 문자열 포맷·LINQ·임시 컬렉션·UI 생성/삭제·활성화 전환·레이아웃 갱신을 검토한다. 필요 없는 작업만 제거하고, 버퍼 재사용의 소유권과 초기화를 보존한다. 코드 줄 수가 줄었다는 이유로 최적화 완료를 선언하지 않는다.
- **도메인 정확성:** 전투 틱·RNG·밸런스, 가격/입장 조건, 저장 시점, 거래 승인·중복 방지·실패/재시도·보상 검증을 보존한다. 기존 최종 검증을 캐시된 UI 값으로 대체하거나 검증 빈도를 줄이지 않는다. 화면은 기존 거래와 저장 성공 후 갱신한다.
- **Ponytail lite:** 요구사항을 보존하고 기존 코드 재사용·불필요 반복 제거·작은 변경을 적용한다. 이번 실측은 설치된 4.10.0 지침을 수동 적용한 기록이며 공식 CLI audit 통과를 뜻하지 않는다. 다음 사용 시 실제 버전과 사용 지침을 기록한다. audit나 가독성 검토는 회귀 검사와 CPU 실측을 대체하지 않는다.

## 전후 측정과 근거 보존

1. **최신 기준과 작업 소유권을 확정한다.** checkout/커밋/dirty 상태, 실행 중인 게임·Editor·브라우저와 디스크 여유를 확인한다. 사용자 게임이나 다른 작업자의 프로세스를 종료하거나 작업을 되돌리지 않는다. 필요한 최소 격리 폴더를 사용하며, 대용량 사본 여러 개와 병렬 Unity 빌드를 만들지 않는다.
2. **비교 입력을 고정한다.** 같은 머신, 플랫폼·빌드 모드·백엔드, 장면·세이브·시드·진행 상태, 해상도·DPR·품질, 프레임 상한·VSync·백그라운드 정책과 노출/포커스 상태를 기록한다. 메뉴·마을 idle·전투·UI 열린 상태를 각각 비교한다. Editor, 네이티브 개발/출시 플레이어와 웹 Renderer·GPU·브라우저 프로세스를 구분한다.
3. **실제 페이싱을 확인한다.** 설정값 60FPS만으로 동일 조건이라고 판단하지 않는다. 실제 FPS, 워밍업 후 프레임 간격과 웹의 표시/포커스·주사율 추정·스케줄러 변화를 확인한다. 숨겨진 페이지의 저속 표본이나 조건이 바뀐 표본은 제외 사유와 함께 보존하고 같은 조건으로 다시 측정한다. FPS·해상도·품질을 낮춰 얻은 절감은 로직 개선과 별도로 보고한다. 측정용 스케줄러를 배포 코드의 정책으로 옮기지 않는다.
4. **산출물을 고정한다.** 작업별 고유 출력 경로와 before/after 경로를 사용하고 소스 커밋·빌드 설정·실행 인자를 남긴다. 완성한 플레이어와 웹 HTML/loader/framework/data/WASM의 해시를 측정 전후 확인한다. 계측 패치가 필요하면 배포 출력과 분리된 개발 산출물에 적용하고 패치 이후 해시를 고정한다. 실행 파일이 바뀌거나 덮인 표본을 이전 baseline과 섞지 않는다. 오래된 근거는 덮지 않고 별도 경로에 보존한다.
5. **반복과 지표를 함께 남긴다.** 같은 워밍업·표본 길이로 상태별 전후 최소 3회 실행하고 실행 순서 편향을 확인한다. 측정 중 다른 빌드·전체 검사를 실행하지 않는다. CPU ms/프레임·사용률, GC 바이트/프레임·수집 횟수, 관리 힙·Unity 할당·프로세스 RSS/웹 JS 힙, 평균·p95 프레임 간격을 원본 표본과 반복 범위로 남긴다. CPU 사용률의 코어 기준과 측정 창을 명시한다.
6. **작업량과 대기를 구분한다.** 실제 프로세스 CPU 시간과 Profiler 구간을 함께 보고 `WaitForTargetFPS`·wall time을 CPU 작업으로 더하지 않는다. 중첩 marker를 합산하지 않고, `Update`에서 `LateUpdate`로 이동한 비용을 marker 감소만으로 판정하지 않는다. Editor CPU 감소를 게임 최적화 증거로 쓰지 않는다.
7. **확인된 범위만 보고한다.** 중앙값뿐 아니라 반복 범위와 개별 전후 쌍을 검토한다. 겹치는 범위·일관되지 않은 차이는 개선 미확인으로 남기고, 증가한 할당·메모리나 느려진 표본도 공개한다. 새 플랫폼·장면·출시 모드·모바일 실기기의 효과는 별도 검증 전까지 미확인이다.

## 완료 조건

- 바뀐 표시와 갱신의 소유자, 제거한 반복, 복원·무효화 조건과 보존한 도메인 동작이 리뷰에서 확인된다.
- 관련 회귀와 실제 플레이어 검증으로 메뉴·포탈·절전 전환, 연속 이동 HUD, 포탈/NPC/상점 우선순위, 안정된 버튼 활성 상태와 거래·저장 실패/재시도를 확인한다. UI 변경은 공통 계약·기본 글자 크기·KO/EN·기존 해상도 검증을 유지한다.
- 기존 전체 검사 절차에 따라 마지막 코드 변경과 마지막 `main` 병합 뒤 한 번 검증한다. 최신 baseline의 실패 이름과 이번 실패를 비교하며, 과거의 실패 개수만으로 기존 실패로 분류하지 않는다. 실패를 숨기려고 검사를 약화시키지 않는다.
- 동일 조건의 원본 측정·해시·전후 반복 비교와 미검증 범위를 남긴다. 실측하지 못했다면 차단 원인과 코드 검토 결과만 보고하며 성능 개선을 확정하지 않는다.
- 문서·지침만 바꾼 작업은 링크·이력·정적 검사를 수행하며 게임을 다시 빌드하거나 실행할 필요는 없다. 위키 생성·게시와 커밋 범위는 루트 지침 및 해당 요청의 승인 범위를 따른다.
