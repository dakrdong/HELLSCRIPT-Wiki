# 사냥 칙령 생존 행동 실행 개발 기록

작성일: 2026-09-09 · 생존 요청의 실행 경로와 전투 상태 저장 확장

## 실제 연결 범위

[회피·긴급 생존 판단](Edict_Survival_Expansion.md)을 실제 전투 행동으로 전달하는 `PlanEdictSurvival`과 `ExecuteEdictSurvival`을 추가했다. 계획은 읽기 전용이며, 실행 요청은 최신 상태로 다시 판단한 뒤 기존 `StartHeroAction`에 전달한다. 보호막·도약·순간이동·후퇴·범위 제어·덫은 기존 준비 시간, 이동, 피해·상태 효과, 비용과 재사용 대기시간을 사용한다. 보행 후퇴는 실제 전투 이동 처리에 연결했다.

이 단계는 **생존 명령을 받아 실행하는 경로**를 구현한 것이다. `GameController`와 전투의 정기 판단은 아직 HED2 저장 원본을 이 함수에 전달하지 않는다. 기존 앱에 새 전역 생존 설정이 자동으로 적용됐거나, 새 설정 화면에서 동작을 확인할 수 있다는 의미는 아니다. 새 원본의 저장·이전과 전체 행동 우선순위 연결 이후에 해당 경로를 공개한다.

실행 요청은 일시정지·포탈·결과 정리·전투 종료·사망·진행 오류 상태에서 아무것도 변경하지 않는다. 요청 원본의 스킬 배치가 현재 전투와 다르면 미적용 초안으로 처리하고 실행하지 않는다. 이 배치 검사만으로 원본이 디스크에 저장됐음을 입증할 수는 없으므로, 후속 호출자는 명시적 저장에 성공한 원본만 전달해야 한다. 실행 함수 자체는 원본·현재 설정·계정 파일을 저장하지 않는다.

## 생존 수단의 실행

| 수단 | 실행 조건과 처리 |
|---|---|
| W05·M05 보호막 | 자동 사용·장착·해금·CD·비용·행동 구간을 검사한다. 같은 출처의 보호막이 남았거나 합계 상한으로 추가 생성량이 없으면 시작하지 않는다. 일반 회피의 대체 수단으로 사용해도 스킬의 긴급 전용·다른 방어 효과 대기·교전 종류 제한을 지킨다. 긴급 지정 요청에서는 허용된 일반 대기·교전 제한을 해제한다. 실제 생성은 0.2초 준비 뒤이며, 생성 배율과 합계 상한은 기존 효과 처리를 따른다. |
| W02 도약 | 공격 진입 전용이면 생존 참조에서 제외한다. 생존 이탈 전용은 긴급 대응에서만 사용한다. 공격 도약 최소 거리를 긴급 이탈에 적용하지 않는다. 실제 준비·체공·착지 공격과 장착 효과를 유지한다. |
| A04 후퇴 도약 | 감지한 기준 대상이 있어야 한다. 2~6m의 유효 착지 후보를 검토한다. 일반 회피에서는 일반 사용 꺼짐·거리 오차 2m 개선·덫 연계·관통 연계의 조건을 적용하고, 긴급 요청에서는 일반 사용 조건을 해제한다. LA03의 출발점 덫과 AP02·SAB의 착지 효과는 기존 실행 시점에 발생한다. 이동 거리를 보행으로 집계하지 않는다. |
| M04 순간이동 | 2~8m의 유효 지점과 시야를 검사한다. 적 없이 환경 위험만 감지한 상황에도 생존 후보를 찾는다. 전역 위험 기준과 감지 피해 없음 조건을 구분하고, 이동을 무적이나 벽 통과로 처리하지 않는다. |
| W04·M06 제어 | 자기 중심 3m와 벽, 현재 제어 잔여 상태를 검사한다. 생존용 제어 후보는 새로 제어할 일반·정예 적이나 이번 적중으로 제압을 완성할 보스가 있어야 한다. 실제 제어는 준비 뒤 적중할 때 발생하며 예측만으로 적 행동을 취소하지 않는다. |
| A03 덫 | 선택한 설치 위치·인원·기존 덫 유지/교체·새 대상 조건을 검사한다. 매복을 긴급 제어 설치로 바꾸지 않는다. 실제 설치 뒤 무장과 적 진입을 거쳐 속박하므로 즉시 제어 성공으로 표시하지 않는다. |
| 보행 후퇴 | 전역 위험 기준을 만족하고 현재 위험이나 근접 압박을 줄이는 후보의 경로를 검사한다. 목적지와 남은 실행 시간을 전투 상태에 보관하고 실제 보행 속도·둔화를 적용한다. 새 주 행동을 시작하거나 설정을 실제로 바꾸면 기존 보행 요청을 끝낸다. |

착지 후보는 현재 감지한 위험과 적만 사용한다. A04·M04의 위험·주변 적 수·희망 거리 선호와 A04의 자기 덫 선호를 반영한다. 자기 덫이나 거리 기준 대상이 없으면 위험 기준으로 비교한다. 선택 후보는 재현 가능한 순서로 정리하며, 모든 지형에서 최적의 지점을 찾는다고 보증하지 않는다.

W02 착지 후 다음 공격 선호, A04 착지 후 희망 거리까지의 추가 보행, 일반 교전에서 해당 스킬의 사용 기회를 정하는 전체 판단은 후속 스킬 실행 단계에 남아 있다. 이번 생존 요청의 성공을 해당 스킬의 모든 핵심 옵션 완료로 표시하지 않는다.

## 순서·중단·물약

긴급 대응은 사용자가 정한 방어기·회피기·보행 순서로 확인한다. 지정 회피기가 불가능하면 보행·다른 생존기·전투 유지 중 원본의 대체 방침을 적용한다. 전투 유지를 명시한 경우에는 뒤에 보행 항목이 있다는 이유로 임의 후퇴를 실행하지 않는다. 각 시도의 불가 이유와 최종 선택을 구분해 반환한다.

일반 회피는 걷기 우선·회피기 우선·걷기로 어려울 때 회피기를 구분한다. 걷기로 어려운지는 현재 이동 속도와 경로 길이, 첫 감지 피격까지의 시간으로 비교한다. 긴급용 회피기는 일반 회피에서 보존하며, 같은 회피기를 대체 스킬 칸에 지정해도 보존을 우회하지 않는다.

보행 경로는 도착점뿐 아니라 중간 위치에 새로 추가되는 금지 위험을 확인한다. 현재 위험에서 빠져나오는 경로는 허용하되 도착 전에 피격될 수 있음을 구분한다. 이는 고정 위치별 예고를 이용한 보수적인 경로 검사다. 영웅·투사체의 미래 이동을 모두 함께 진행하는 예측, 보이지 않는 위험의 안전 보장, 무피해 탈출 보장은 아니다.

준비 중인 공격과 회오리 유지는 허용된 생존 전환에서 중단할 수 있다. 체공·이동 및 회복 구간은 중단하지 않는다. 이미 시작한 생존 동작도 같은 요청을 반복했다고 계속 취소하고 다시 시작하지 않는다. 일반 회피의 ‘현재 공격 완료 후’가 회오리에 적용되면 다음 0.25초 경계에서 종료하며, 다음 피해 틱 비용을 새로 내지 않는다. 이 종료 요청은 저장·복원되며 구형 규칙이 먼저 끼어들어 중단하지 못하게 한다.

물약은 주 행동과 독립적으로 기존 회복·CD·LC03 처리를 실행한다. 물약으로 실제 회복한 뒤 긴급 조건을 다시 계산하므로, 회복으로 해소된 체력 위기 때문에 불필요한 생존 스킬을 추가로 쓰지 않는다. 같은 요청을 반복해도 이미 시작한 물약 CD를 무시하지 않는다.

## 저장과 화면 기획

전투 동작 저장 버전은 5다. 버전 4의 진행 중 정책·시점·비용을 유지하며, 기존 버전 3 이전 정책 복원도 보존한다. 새 회오리 종료 표시와 명시적 생존 행동 정책이 저장된다. `EdictResponseState`는 영웅·전투에 귀속된 긴급 기억과 보행 요청을 담으며 공유 원본에 넣지 않는다. 더 새로운 전투·생존 상태 버전과 유효하지 않은 저장 위치·시간은 거부한다.

[화면 배치 상세안](../Design/HELLSCRIPT_Screen_Layout_Detail.md)에 따라 판단·명령·진행 상태를 UI 객체와 분리했다. 화면 재배치가 이 실행 함수를 다시 호출하는 구조를 만들지 않는다. 현재 행동의 이유는 실제 실행 로그에 남기고, 미선택 후보를 실행 원인으로 표시하지 않는다. 모바일 방향·PC 창 크기·미저장 입력·확인창·일시정지 사유 보존은 화면 연결 단계에서 별도로 검증할 항목이다.

## 검증

Unity 6000.6.0f1의 최종 전체 Edit Mode 검사 **917개가 모두 통과**했다. 신규 46개와 기존 871개를 포함한다. 2026-09-09 15:33:24~15:35:12 KST에 약 108.22초 동안 실행했다. [전체 결과](../../Artifacts/Validation/edict-response-final-editmode.xml)와 [실행 로그](../../Artifacts/Validation/edict-response-final-editmode.log)를 보존했다.

새 검사는 실제 시뮬레이션 틱의 준비·이동·착지·보호막·덫·제어·비용·물약과 전투 상태의 직렬화·복원을 다룬다. 자기 보호막 중복·합계 상한, 행동 구간별 중단, 대상 없는 환경 회피, 이동 불가와 지정 대체 행동, 실제 자원 경계, 일반 사용 제한과 긴급 예외, 미적용 배치·일시정지의 실행 거부, 오래된 미리보기의 재사용 방지도 포함한다.

앞선 [집중 검사 131개](../../Artifacts/Validation/edict-response-corrected-focused.xml)와 사용 제한을 보완한 [집중 검사 47개](../../Artifacts/Validation/edict-response-policy-focused.xml)가 통과했다. 첫 생존 집중 검사에서는 M05에 자원 비용이 있다고 잘못 가정한 시험을 수정했다. 카탈로그의 실제 M05 비용 0은 유지하고, 유료 M06의 자원 19·20 경계를 별도로 검사했다. [첫 집중 결과](../../Artifacts/Validation/edict-response-focused.xml)를 보존한다.

앞선 [전체 검사 911개](../../Artifacts/Validation/edict-response-editmode.xml)에서는 기존 첫 플레이 재시작 검사 한 건이 실패했다. 저장 시각이 1초 갱신된 것을 계정 변경으로 판정한 문제였다. 해당 시험은 의도적으로 10초 이전 저장 시각을 기록한 뒤, 재실행 시각의 정상 갱신과 나머지 계정·안내·경제 정보의 정확한 보존을 각각 확인하도록 고쳤다. 게임의 시각·저장·정산 구현을 변경하지 않았다.

최종 검사 대상 C# 130개는 검사 시작 이후 동일하다. 신규 소스 4개와 기존 소스 9개를 변경했으며, 기존 변경 중 2개는 검사 파일이다. 보호 자산 98개와 기준 기획 6개가 단계 시작 해시와 일치하고 메타 파일 누락·GUID 중복이 없다. Unity 패키지가 자동으로 제거한 설정 기호는 [원문 차이](../../Artifacts/Validation/edict-response-package-define-change.diff)를 남기고 복원했다. [검증 요약](../../Artifacts/Validation/edict-response-validation-summary.json)과 [소스 기록](../../Artifacts/Validation/edict-response-source-manifest.json)에 연결 범위와 한계를 남겼다.

이번 단계는 새 네이티브 앱이나 모바일 실기기 실행을 완료했다는 의미가 아니다. 다음 단계에서는 성공적으로 저장한 HED2 원본을 정기 판단에 전달하고, 공통 대상·추적·행동 순서와 나머지 핵심 옵션을 연결한다. 화면 배치·입력·실제 앱 실행 증거는 그 연결 이후 별도로 남긴다.
