작성일: 2026-09-12  
문서 유형: Work 구현 전달용 변경 명세  
적용 대상: 기존 HELLSCRIPT 프로젝트의 코드·기획서·콘텐츠 데이터표  
상태: 사용자가 전달을 요청한 설계안. 단계·레벨 수치는 테스트 초안. 실제 프로젝트 구현과 플레이 검증은 별도 작업이다.

## 0. 이 문서의 적용 방법과 우선순위

이 문서는 새 게임을 만드는 기획서가 아니라, 기존 HELLSCRIPT에 콘텐츠 공개 순서를 추가하는 변경 명세다.

1. 실제 Work 프로젝트의 현재 파일, 작업 지침, 진행 중인 수정 내역을 먼저 확인한다.
2. 이번 변경 범위인 기능 해금·안내·전투 콘텐츠 등장 구간은 본 명세를 적용한다.
3. 그 밖의 규칙은 Work 프로젝트의 최신 승인 상태를 유지한다.
4. 함께 전달한 `reference_baseline/HELLSCRIPT_GDD_v0.1.md`와 `HELLSCRIPT_Content_v0.1.xlsx`는 이 대화에서 확인한 참고 스냅샷이다. Work의 최신 파일을 통째로 덮어쓰는 용도가 아니다.
5. 참고 스냅샷에는 옵션 재설정 고정 비용 변경이 반영돼 있지만, 별도로 요청했던 ‘균열 단계별 아이템 등급 확률’ 작업의 최신 결과는 들어 있지 않다. 그 작업을 구버전 고정 확률로 되돌리지 않는다.
6. 프로젝트에 기존 두 문서가 없을 때만 첨부 기준본을 프로젝트 문서 규칙에 맞는 위치에 저장한다. 기존 문서가 있으면 본 변경을 병합하고 실제 저장 경로를 보고한다.
7. 여기서 정한 공개 단계는 HELLSCRIPT 자체 설계다. DoE나 디아블로4의 실제 해금 순서를 복제·검증한 것으로 표시하지 않는다.

## 1. 설계 목표

첫 전투부터 ‘전투 규칙을 설정하고 결과를 비교하는 게임’이라는 정체성을 보여준다.

성장 기능의 공개 순서:
전투 설정 → 단순 강화 → 부족한 부위 제작 → 보석 세팅 → 옵션 보정
→ 미확인 장비 구매 → 반복 보상 편의 → 전설 재활용.

주요 성장 메뉴는 15단까지 공개한다. 20단 이후에는 새로운 메뉴를 억지로 잠가두기보다 기존 장비·세트·전설·보석·스크립트의 조합과 복합 전투 대응을 깊게 만든다.

서로 다른 세 가지를 구분한다.
- 기능 해금: 실제 이용 권한이 생기는 시점.
- 사용법 안내: 이미 쓸 수 있는 기능을 설명·강조하는 시점.
- 전투 콘텐츠 출현: 현재 던전에서 어떤 테마·적·보스가 생성되는지 결정하는 조건.

## 2. 진행도와 조건의 정확한 정의

| 값 | 정의 | 사용하는 곳 |
| --- | --- | --- |
| A | 계정 내 영웅들의 검증된 최고 실제 균열 클리어 단계 중 최댓값. 기록이 없으면 0 | 계정 공통 성장 메뉴 해금 |
| H | 현재 선택한 영웅의 검증된 최고 실제 균열 클리어 단계. 기록이 없으면 0 | 소탕 보상·기존 영웅별 진행도 |
| R | 현재 던전 실행 또는 보상 영수증에 저장된 균열 단계 | 적·테마·보스 후보와 실제 전투 보상 |
| P | 해당 영웅의 레벨 | 액티브 스킬과 패시브 슬롯 |
| FirstRunEnded | 실제 첫 균열 시도가 성공 또는 실패로 끝난 이력 | 진행 이력을 보존한다. 2026-09-14부터 훈련장 접근에는 요구하지 않는다. |
| GemAcquired | 계정이 보석을 정상 획득한 이력 | 보석 조기 해금 |
| CoreReady | 계정의 부위별 코어 중 어느 한 부위라도 10개 이상인 상태를 정상적으로 달성한 이력 | 전설 코어 제작 조기 해금 |

- ‘N단 클리어 후’는 보스를 처치하고 클리어가 확정된 이후다. N단 입장·도달만으로 해금하지 않는다.
- 단계 조건은 `A >= N`으로 평가한다. `A == N`인 이벤트에만 의존하지 않는다.
- 단계 점프, 오래된 저장 불러오기, 다른 기기에서의 진행도 동기화도 처리한다.
- 해금 상태는 영구 유지한다. 코어를 쓰거나 보석을 잃거나 낮은 단계로 이동해도 다시 잠그지 않는다.
- 현행 프로젝트의 검증·저장 권한 구조를 따른다. 클라이언트 UI 값만 바꿔 해금시키지 않는다.
- 전투 단계가 변경될 수 없는 실행 스냅샷과 보상 영수증을 기준으로 처리한다.

## 3. 기능 해금표

ID는 명세 식별자이며, 실제 프로젝트에 대응 ID가 있으면 매핑해서 사용한다.

| 명세 ID | 기능 | 적용 범위 | 기본 조건 | 조기 조건 / 예외 |
| --- | --- | --- | --- | --- |
| UL00_BASE | 직업 선택·생성, 균열, 장비 장착, 스크립트 편집, 결과 로그, 기본 안전·편의 기능 | 계정/영웅의 기존 범위 | 시작부터 | 결과 로그는 첫 기록이 생긴 뒤 내용을 표시한다 |
| UL01_TRAIN | 훈련장 | 계정 | 마을 도착부터 상시 이용 | 첫 균열 시도나 클리어를 요구하지 않는다. 2026-09-14 마을 동선 요청을 반영했다. |
| UL02_ENHANCE | 장비 강화 | 계정 | A >= 1 | 비용·강화 상한·실패/파괴 없음은 기존 규칙 유지 |
| UL03_OFFLINE | 오프라인 보상 | 계정 | A >= 1 | 기존 정책 유지. 해금 이전 시간에 소급 보상하지 않는다 |
| UL04_RARE_CRAFT | 부위 선택 기본 제작 | 계정 | A >= 3 | 기존 레어 제작 기능. 세트·전설을 새로 제작하게 하지 않는다 |
| UL05_GEM | 보석 장착·교체·합성 메뉴 | 계정 | A >= 5 | OR GemAcquired. 소켓·레시피·재료 충족은 별도 이용 조건 |
| UL06_REROLL | 옵션 재설정 | 계정 | A >= 8 | 기존 한 줄 지정·고정, 횟수 무관 비용 유지 |
| UL07_UNIDENTIFIED_SHOP | 미확인 장비 상점 | 계정 | A >= 10 | 골드 사용·상시 재고 등 기존 거래 규칙 유지 |
| UL08_SWEEP | 소탕 메뉴 | 계정 | A >= 12 | 실제 실행은 해당 영웅 H >= 1 필요. 보상 기준은 H |
| UL09_CORE_CRAFT | 전설 코어 제작 | 계정 | A >= 15 | OR CoreReady. 같은 부위 코어 10개 필요. 서로 다른 부위를 합산하지 않는다 |

A가 20 이상이 되어도 이 표 외의 새로운 성장 메뉴를 자동 생성하지 않는다.

### 처음부터 잠그지 않는 항목

- 3개 직업 선택과 각 직업 영웅 생성. 특정 직업의 선행 고단계 클리어를 요구하지 않는다.
- 스크립트의 상세 편집, 추천 프리셋과 기존 프리셋 저장 슬롯. 기본 화면은 단순화할 수 있으나 상세 기능은 임의 봉인하지 않는다.
- 장비 잠금, 공용 창고의 기존 이용 권한, 수동 분해·판매, 획득 필터, 가방 가득 참 처리, 자동 정리·포탈, 재도전·반복 설정.
- 장비의 전설·세트 효과. 기존 직업·착용 레벨·장착 조건만 적용하고 별도 균열 단계 잠금은 추가하지 않는다.
- 기존 무료 스킬·특성 재설정. 새 성장 해금표 때문에 유료화하거나 늦게 열지 않는다.

주의: ‘처음부터 창고를 쓸 수 있음’은 유료 창고 탭이나 유료 인벤토리 탭을 무료 개방한다는 뜻이 아니다. 기존 구매 권한과 칸 확장 비용을 그대로 유지한다.

대장장이·비술사 전체를 통째로 잠그지 않는다. NPC 내부의 기능별로 조건을 적용한다. 분해·장비 보호 기능이 강화나 코어 제작 잠금에 함께 막히지 않도록 한다.

## 4. 안내 순서와 화면 동작

| 안내 시점 | 안내할 내용 | 실제 권한과의 관계 |
| --- | --- | --- |
| 첫 전투 | 추천 설정으로 전투 후 물약 기준 또는 주력기 대상 조건 1개를 바꿔보기 | 상세 스크립트는 시작부터 사용 가능 |
| 1단 클리어 | 강화·분해 안내, 오프라인 보상 활성화 알림 | 분해를 새로 잠금 해제하는 것이 아님 |
| 3단 클리어 | 기본 제작, 훈련장 A/B 비교, 프리셋 활용 | 훈련장은 첫 시도 종료 후부터 가능, 프리셋은 시작부터 가능 |
| 5단 클리어 또는 첫 보석 획득 | 보석 장착·교체와 합성 메뉴 안내 | 더 일찍 받은 보석을 단계 제한으로 못 쓰게 하지 않음 |
| 8단 클리어 | 바꿀 옵션 한 줄, 다른 줄 보존, 비용 확인 | 이전 결과 보존·선택 방식 등 다른 미정 규칙은 임의 변경하지 않음 |
| 10단 클리어 | 부위 선택 구매와 기본 제작의 차이 | 확률형 구매와 확정 등급 제작을 구분 |
| 12단 클리어 | 직접 클리어한 영웅의 최고 단계 반복 보상 | 소탕으로 새로운 최고 단계가 생기지 않음 |
| 15단 클리어 또는 같은 부위 코어 10개 달성 | 전설 분해·부위별 코어·전설 재추첨 | 전설 분해 코어는 제작 해금 이전에도 정상 지급 |
| 첫 전설·첫 세트 획득 | 고유 효과 또는 2·4세트 효과 안내 | 장비 사용 권한을 이 시점에 새로 제한하지 않음 |
| 첫 실패 | 실패 로그, 훈련장, 설정 수정 안내 | 생존에 필요한 실험 도구를 고단계 조건으로 잠그지 않음 |

- 안내 완료 상태와 기능 해금 상태를 별도로 저장한다.
- 안내를 닫거나 건너뛰어도 기능은 정상 해금된다.
- 게임 내 기능 예고에는 다음 해금 기능과 조건을 표시한다.
- 잠긴 메뉴에 이유를 표시한다. 예: “계정 내 영웅으로 균열 8단계 클리어 시 개방”.
- UI 표시뿐 아니라 실제 강화·제작·재설정·소탕 요청 처리에서도 권한을 검사한다.
- 여러 조건이 동시에 충족되어도 팝업을 연속 강제 표시하지 않는다. 요약 후 개별 안내를 다시 볼 수 있게 한다.
- 기능 해금은 즉시 기록할 수 있지만, 새 성장 메뉴 사용이나 강제 튜토리얼은 안전한 결과 화면·마을 전환에서 안내한다.
- 던전 중 자동 포탈 정리로 동결한 상태에서 강화를 하거나 장비를 바꾸는 기존 금지 규칙을 우회하지 않는다.
- 이미 계정에서 확인한 설명을 다른 영웅마다 강제로 반복하지 않는다. 영웅별 스킬 설명은 해당 영웅에게 별도로 안내할 수 있다.

## 5. 영웅 레벨 기반 스킬·패시브

액티브:
- 기존 영웅 레벨 1·3·6·10·15·20 해금 초안을 유지한다.
- 최대 장착 액티브 4개를 유지한다.
- 균열 3단과 영웅 3레벨을 같은 조건으로 취급하지 않는다.

패시브 슬롯 — 이번에 추가하는 테스트 초안:
- 영웅 3레벨: 1개 슬롯.
- 영웅 6레벨: 2개 슬롯.
- 영웅 10레벨: 3개 슬롯.
- 최대 3개 장착 규칙 유지.
- 이 수치는 슬롯 수에 대한 조건이다. 개별 패시브 6종의 새로운 해금 순서를 별도로 발명하지 않는다.
- 현재 코드에 개별 패시브 조건이 있다면 대조해서 기존 규칙을 보존한다. 없으면 새 조건은 슬롯 수만 제어한다.
- 아직 배운 적 없는 스킬을 전제로 하는 설명은 미충족 조건을 안내한다. 그렇다고 주력 스킬을 이번 작업에서 조기 강제 해금하지 않는다.
- 기존 저장에서 정당하게 열린 슬롯·장착 패시브를 이번 도입 때문에 강제로 해제하지 않는다. 새 계정/영웅의 기본 정책과 레거시 권한 보존을 분리한다.

## 6. 현재 균열 단계에 따른 전투 콘텐츠 배치

이 표는 계정 영구 메뉴 해금표가 아니다. 던전 생성 시 그 실행의 R을 사용한다.

| 현재 단계 R | 테마·적·보스 구성 방향 | 설계 목표 |
| --- | --- | --- |
| 1~5 | 첫 테마 중심. 적의 역할과 위험 조합을 단순하게 제시. 첫 보스를 사용 | 물약·주력기·기본 장비 교체를 익힘 |
| 6~10 | 원거리·장판·지원형 등 기존 적의 조합 확대 | 대상 우선순위와 이동 설정을 시험 |
| 11 이상 | 두 번째 테마와 두 번째 보스를 적합한 생성 후보에 추가 | 다른 지형·패턴에서도 기존 설정을 검증 |
| 20 이상 | 정예 특성 최대 2개 조합. 기존 회피 불가능 조합 금지 유지 | 생존·공격·이동 규칙의 충돌 해결 |
| 21 이상 | 세 번째 보스를 적합한 생성 후보에 추가 | 무리 처리와 보스 대응을 함께 요구 |

- 최초/두 번째 테마와 보스는 기존 GDD 및 실제 프로젝트 ID에 연결한다.
- 참고 GDD의 테마는 ‘잊힌 묘지’, ‘붕괴한 성채’이고, 보스 ID는 BOSS01/BOSS02/BOSS03이다. 실제 프로젝트에서 이름·ID가 변경됐다면 매핑한다.
- “후보에 추가”는 해당 단계에서 매번 그 보스를 강제 생성한다는 뜻이 아니다.
- 이전 테마·보스를 전부 삭제하지 않는다. 테마·보스·방의 호환 조건과 기존 생성 검증을 보존한다.
- 20단에서 21단으로 넘어갈 때 정예 2특성 규칙이 사라지지 않는다. 각 조건은 누적 적용한다.
- 50단을 깬 계정이 5단을 돌면 5단의 전투 콘텐츠 규칙을 적용한다.
- 적·정예·보스 자체의 능력치와 스킬 효과, 처치 점수, 보상 수량은 임의 변경하지 않는다.
- 이 작업 때문에 이동기를 아직 배우지 않은 직업이 통과할 수 없는 패턴을 만들지 않는다. 초반 직업별 해금 상태로 검증한다.
- 구체적인 몬스터 후보 목록·구간별 가중치가 비어 있으면 기존 콘텐츠 안에서 최소 변경안을 데이터로 만들고 테스트 초안으로 표시한다. 새 적·던전 제작으로 범위를 확장하지 않는다.

## 7. 조기 획득·저장·계정 공유 예외

보석:
- 5단 전 첫 정상 획득 시 계정 보석 기능을 조기 해금한다.
- 기존 저장을 불러올 때 보석 보유 상태와 정상 획득 이력으로 누락된 해금을 복구한다.
- 보석을 분해·합성·이동했다고 해금 상태를 제거하지 않는다.
- 메뉴 해금과 특정 장비의 유효 소켓 보유 여부는 별개다.

코어:
- 전설 제작이 잠겨 있어도 전설 분해는 부위 코어를 지급한다.
- 조기 해금은 ‘같은 부위 10개’로 판정한다. 무기 5개 + 머리 5개는 충족하지 않는다.
- 코어 제작 후 수량이 줄어도 기능은 유지한다.
- 코어 수량을 해금 비용으로 먼저 차감하지 않는다. 실제 제작 비용은 제작 시에만 기존 방식으로 한 번 차감한다.

소탕:
- 계정에서 메뉴가 열렸어도 H가 0인 영웅은 소탕할 수 없다.
- 전사 H=50, 궁수 H=3이면 궁수 소탕은 3단 보상이다.
- 별도 작업의 단계별 등급 확률이 이미 적용돼 있다면 동일한 3단 보스 확률을 사용한다.
- 다른 영웅의 최고 기록을 새 영웅의 개인 기록으로 복사하지 않는다.
- 일일 횟수·기준 시각·공간 부족 시 확정 보상 보존 등 기존 정책은 유지한다.

기존 이용자:
- 적법하게 이미 열린 기능, 저장 슬롯, 구매 권한을 회수하지 않는다.
- 저장 버전과 확인 가능한 기존 권한을 기준으로 한 번만 마이그레이션한다.
- 이미 열린 기능은 합집합 방식으로 보존한다. 없는 권한·미구매 탭을 임의로 부여하지 않는다.
- 최고 단계와 보유품 재평가로 놓친 해금만 보충하고, 대량 안내는 요약 처리한다.
- 크로스디바이스 동기화·동일 클리어 이벤트 재전송으로 안내·보상이 중복되지 않도록 한다.

## 8. 해금 직후 이용 가능성 검증

“메뉴가 열렸다”와 “실제로 이용할 재료·장비가 있다”를 나눠 검사한다.

- 1단 강화에 필요한 골드·일반 재료를 확보할 수 있는가?
- 3단 기본 제작에 필요한 골드·재료를 확보할 수 있는가?
- 5단 보석 체험에 유효 보석·소켓 장비가 존재하는가?
- 합성 기능에 실행 가능한 레시피·재료·결과 데이터가 있는가?
- 8단 옵션 재설정을 시도할 수 있는 적합한 장비와 골드가 있는가?
- 15단 코어 제작에 해당 부위 코어를 얼마나 보유하는가? 메뉴 공개와 10개 달성은 같은 사건으로 강제하지 않는다.

특히 기존 참고 문서의 보석 종류·단계별 값·소켓·레시피에는 검증 대기가 있다. 기능 UI만 보이게 만든 뒤 보석 구현까지 끝났다고 보고하지 않는다.

부족한 체험 재화나 미정 보석 데이터를 발견하면:
- 부족한 조건과 현재 확보 가능한 양을 결과에 남긴다.
- 기존 경제 수치, 코어 10개 조건, 전설 드롭량을 임의로 변경하지 않는다.
- 최소한의 계정 1회 체험 지원이 필요하면 추가 제안으로 분리한다. 미승인 보상을 기본 보상에 몰래 추가하지 않는다.
- 조건과 필요 자원을 UI에서 설명한다. 해금이 소비 조건 충족을 의미하는 것처럼 표시하지 않는다.
- 구현 가능한 해금·안내 작업은 끝내고, 미완료 의존 항목을 구체적으로 보고한다.

## 9. 반드시 보존할 기존 규칙

- 옵션 재설정은 한 줄 지정 후 고정.
- 재설정 시도 횟수에 따른 비용 증가 없음.
- 현재 대화 기준 비용 초안: `500 × L + 50 × L × (L - 1)` 골드, `L = max(1, 아이템 레벨)`.
- 같은 아이템 레벨에서는 첫 시도부터 반복 시도까지 동일 비용. 계수는 밸런스 초안.
- 일반 장비 강화 비용·강화 단계·재료 반환 규칙은 이번 변경 범위가 아님.
- 실제 전투 드롭은 해당 실행 R, 소탕은 해당 영웅 H 기준이라는 기존 작업 방향 유지.
- 이전 ‘균열 단계별 아이템 등급 확률’ 작업이 코드·문서에 반영돼 있으면 그대로 보존.
- 그 작업이 아직 진행 중이면 인터페이스를 일치시키되 본 해금 작업에서 새로운 등급 확률을 또 정의하지 않음.
- 전설별 구성원 가중치·부위별 후보 검증과 기존 직업·착용 레벨 조건 유지.
- 전설·세트의 드롭 후보를 콘텐츠 소개 시점까지 숨기는 추가 단계 제한 없음.
- 오프라인은 골드·일반 강화 재료만. 장비·보석·코어·보스 보상 추가 금지.
- 계정 공통 기능과 영웅별 진행도·레벨·장비·인벤토리·유료 권한 구분.
- 보상·제작·구매의 기존 중복 처리 방지 유지.
- 새로운 펫·용병·룬·PvP·전용 성장 던전·시즌 초기화·유료 해금 기능을 이번에 추가하지 않음.

## 10. 구현 구조와 문서·엑셀 병합

기존 구조에 맞춰 기능 판정 로직을 공통화한다. 이름은 프로젝트 관례를 따른다.

예시 데이터 필드:
`feature_id / scope / trigger_type / threshold / early_unlock_condition /
 persistent / guide_id / prerequisite / data_version`

- 기능별 조건은 데이터로 관리한다. 여러 화면·NPC에 서로 다른 단계 상수를 하드코딩하지 않는다.
- 기능 사용 가능 여부와 안내 표시 여부를 서로 다른 상태로 저장한다.
- 계정·영웅·실행 단계를 명시적으로 전달한다.
- 기존 서버/클라이언트/로컬 프로토타입 구조를 존중하고, 새 백엔드를 불필요하게 만들지 않는다.
- 기존 저장 데이터와 마이그레이션 정책을 검토한다.
- 임시 디버그 전체 해금은 배포 기본값과 분리한다.
- 클래스·스킬·장비 슬롯 등 이미 있는 기능을 재구현하지 않는다.

GDD:
- 기존 개발 순서 P0~P4를 유저의 콘텐츠 해금 순서로 오해하지 않는다.
- 별도 ‘콘텐츠 공개 및 해금’ 절에 본 명세를 병합한다.
- 계정 공통/영웅 레벨/현재 전투 단계별 표를 분리한다.
- 기존 문서와 어긋나는 설명·FAQ·UI 조건도 갱신한다.
- 기존 확정 원칙과 이번 단계·레벨 밸런스 초안을 구분한다.

엑셀:
- 기존 ID·시트·수식·서식을 보존한다.
- 현재 워크북 마지막 사용 번호 뒤에 충돌하지 않는 해금 데이터·검증 시트를 추가하거나, 기존 동등 시트에 병합한다.
- 기존 24개 시트라고 단정해 고정 시트 번호로 덮어쓰지 않는다. Work에서 추가한 등급 확률 시트가 있을 수 있다.
- 적어도 기능 ID·적용 범위·기준값·조기 조건·영구 여부·안내 조건·상태·출처를 포함한다.
- 기존 검증 시트를 유지하고 필요한 테스트를 추가한다.
- 코드와 엑셀에 동일 조건을 이중 하드코딩하지 않도록 기존 원본 데이터·내보내기 방식을 따른다.

## 12. 완료 산출물과 보고 형식

Work의 완료 보고에는 다음을 포함한다.

1. 수정한 실제 파일 경로와 핵심 변경 지점.
2. 사용한 기준본과 기존 작업 병합 방식.
