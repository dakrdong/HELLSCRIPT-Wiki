# 관찰용 전역 HUD 구현 계획

작성일: 2026-09-14

현재 단계: 리소스·기획 전달 후 대기한다. 아래 항목은 앞으로 수행할 계획이며 완료한 구현으로 표시하지 않는다.

## 1. 프로젝트 기준과 연결 지점

현재 프로젝트는 Unity `6000.6.0f1`, uGUI `2.6.0`, Input System `1.20.0`을 사용한다. 새 UI 프레임워크나 패키지를 추가하지 않고 기존 uGUI와 현지화·화면 설정 구조를 확장한다.

| 현재 소유 코드 | 확인한 역할 | 구현 방향 |
|---|---|---|
| `GameController.Awake()` | `GameUI`를 생성하고 초기화한다. | 같은 소유 관계에서 HUD를 초기화한다. 별도 전역 싱글턴을 만들지 않는다. |
| `GameUI.Initialize()` | sortingOrder 100의 화면 Canvas를 만든다. | 본문 삭제 범위 밖에 유지되는 HUD 루트를 둔다. |
| `GameUI.Base()` | `root`·`shell`의 자식을 지운다. | HUD를 이 두 루트의 자식으로 만들지 않는다. |
| `GameUI.BattleLayout.cs` | 전투 HUD와 `BattleViewport`를 구성한다. | 기존 HUD를 대체할 때 중복을 제거하고 HUD 높이를 카메라에서 차감하지 않는다. |
| `UiSafeArea`·화면 설정 | 선택 화면 비율, 안전 영역, 글자 크기를 관리한다. | 실제 표시 영역을 재사용한다. 노치·레터박스 바깥으로 그리지 않는다. |
| `GameUI.Effects.cs` | 실제 효과를 모으고 상세 조회 시 일시정지한다. | 플레이어 효과 어댑터와 설명 연결을 분리한다. |
| `GameUI.Growth.cs`·`Economy` | 레벨·XP와 훈련 상태를 읽는다. | 같은 데이터 원본을 쓴다. |
| `RunState`·`HeroSave`·`BuildConfig` | 전투·영웅·장착 정보를 가진다. | HUD 표시 모델은 읽기 전용으로 만든다. |

기존 프리셋·화면 설정·대기 화면 Canvas는 110·120·140 등의 순서를 사용한다. HUD 순서는 전체 레이어를 확인한 뒤 정하며 숫자만 높여 모든 팝업 위를 덮지 않는다. 별도 작업에서 추가하는 중앙 오버레이 지도와는 지도 아래의 전투, 지도, 하단 HUD, 상세 창의 관계를 정리한다. 지도는 중앙을 사용하고 HUD는 하단 좌우에 유지하며, 지도 표시 설정을 HUD가 변경하지 않는다. 겹치는 입력은 열린 상세 창이 우선하고, 읽기 전용 HUD 그림은 지도의 입력을 가로채지 않는다.

## 2. 구현 시작 전 결정 항목

| 항목 | 권장 방향 | 확정 전 제한 |
|---|---|---|
| 패시브 3개 → 1개 | 요청한 장착 1개를 새 계약으로 정하고 기존 저장·프리셋·해금을 함께 이전한다. 선택하지 않은 패시브를 조용히 버리지 않고 사용자 재선택 또는 명시적 이전 정책을 적용한다. | 실제 캐릭터에 새 HUD를 켜지 않는다. |
| 물약 1종 → 3종 | 인벤토리 수량, 종류별 자동 사용, 회복/효과, 공급, 저장 이전을 먼저 확정한다. | HP 무한 물약을 임의의 유한 수량으로 바꾸지 않는다. |
| 자원 명칭 | 클래스별 실제 자원 이름을 확인해 두 언어로 등록한다. | 전부 MP로 통일하지 않는다. |
| 총 쿨타임·효과 ID | 이번 사용의 유효 총 시간과 안정된 효과 식별자를 시뮬레이션에서 제공한다. | UI에서 임의 계산한 값으로 게임 상태를 대체하지 않는다. |

이 결정은 전투·성장·저장 정책에 영향을 주므로 구현을 시작하라는 지시를 받은 뒤 구체적인 이전안과 시험값을 검토한다. 이번 단계에서 경제 수치나 저장 파일은 변경하지 않는다.

## 3. 제안 구성

```text
GameUI / existing controller ownership
├─ Existing page UI
├─ GlobalHudRoot                 Base() 삭제 범위 밖
│  └─ SafeArea / selected aspect area
│     ├─ Seal + level
│     ├─ Vitals: HP / resource / shield
│     ├─ StatusStrip
│     │  ├─ ScrollRect + RectMask2D + pooled entries
│     │  └─ ExpandCollapse         마스크 밖
│     ├─ Skills: passive + active ×4
│     ├─ Potions ×3
│     └─ XP track + ticks
└─ Existing detail/modal ownership
```

`GlobalHudSnapshot`은 캐릭터·세션 ID, 생존 정보, 스킬/물약 배열, 레벨·XP, 효과와 데이터 유효 상태를 전달하는 제안 모델이다. `GameUI.GlobalHud`에서 현재 프로젝트의 루트·갱신·해제를 관리하고, 순수 변환 로직과 표시 컴포넌트를 분리한다. 이 이름들은 계획이며 현재 코드에 존재한다고 가정하지 않는다.

지속시간과 쿨타임은 하나의 전투 시계를 사용한다. 1배·2배·일시정지를 반영하며 UI가 별도 타이머를 시작하지 않는다. 값이 바뀔 때만 숫자와 목록을 갱신하고 프레임 사이에는 필요한 채움만 보간한다. 화면 크기·안전 영역·확장 상태가 달라질 때 레이아웃을 계산한다. 표시용 `Image`의 raycast는 끄고 효과 탐색에만 입력을 허용한다.

## 4. 단계별 작업과 완료 조건

| 단계 | 작업 | 검증과 완료 조건 |
|---|---|---|
| A. 선행 계약 | 패시브·물약·쿨타임 원본·효과 ID·저장 이전을 확정한다. | 구버전 저장·프리셋·자동 사용의 호환 정책과 예시가 문서화된다. |
| B. 리소스 임포트 | `Resources/v1/png`에서 선택한 파일을 계획된 `Assets/HELLSCRIPT/Resources/Art/GlobalHUD/v1`에 임포트한다. 기존 아틀라스는 재사용한다. | 알파·마스크·PPU·슬라이스·9-slice·필터를 Editor에서 확인한다. `.meta`는 Editor가 생성하고 안정된 GUID를 보존한다. |
| C. 독립 배치 | 읽기 전용 시험 데이터로 가로·세로와 안전 영역을 구성한다. | 필수 8개 정보, 가로 120%/75%, 중앙 여백과 실제 배경 표시를 확인한다. |
| D. 데이터 연결 | 현재 영웅·전투·마을·훈련·결과를 하나의 HUD 모델로 변환한다. | 실제 수치, 세션 교체, 이벤트 해제, 페이지 전환 시 유지가 맞는다. |
| E. 상태 탐색 | 4.5/8칸, 좌우 스크롤, +/−, 선택 설명, 만료 처리와 텍스트까지 감쇠를 구현한다. | 0·4·5·8·12·40개와 모든 경계 상태에서 누락·잘림·입력 충돌이 없다. |
| F. 기존 화면 정리 | 기존 전투 HUD 중복과 카메라 하단 예약 공간을 제거하고 중앙 지도·팝업과 조율한다. | 선택 비율을 보존하면서 배경이 끝까지 보이며 위험 표지와 지도·HUD가 함께 읽힌다. |
| G. 검증과 전달 | 한국어/영어, 편집기·런타임·기기 검증 후 기록과 위키를 갱신한다. | 아래 검증표를 충족하고 확인하지 못한 기기를 별도 기록한다. |

새 프리팹이나 씬 참조가 필요하면 Editor에서 만들고 기존 씬의 직렬화 내용을 손으로 재작성하지 않는다. 구현 단계마다 해당 작업 변경만 커밋·푸시하고 공개 위키에 동기화한다.

## 5. 검증표

| 구분 | 확인할 내용 |
|---|---|
| Edit Mode | 장착 ID 매핑, 0초 쿨타임, 숫자 올림, XP 분모·레벨 전환, 4.5/8칸 폭, 스크롤 기준 보존·범위 보정, 감쇠 폭을 검사한다. |
| Play Mode | 마을·전투·가방·설정·효과 상세·결과, 캐릭터 교체, 재시작, 일시정지·배속, 훈련 복사본, 반복 진입 후 중복 HUD·이벤트 누수를 확인한다. |
| 시각 | 16:9·20:9·9:16·태블릿·작은 창·노치, 밝고 어두운 지형, 텍스트 확대, 중앙 지도 표시·숨김, 팝업 입력을 확인한다. |
| 알파 | 그림·프레임·시간·중첩이 함께 사라지고 +/−는 선명한지 확인한다. RenderTexture로 HUD 전체를 매번 합성하는 방식을 기본 해법으로 삼지 않는다. |
| 성능 | 대상 모바일 기기에서 새 HUD 전후의 프레임 시간·UI 재빌드·메모리·할당을 같은 장면으로 측정한다. 측정 전 성능 개선 수치를 주장하지 않는다. |
| 빌드 | 기존 macOS 개발 빌드 런타임 스모크와 대상 모바일 기기의 가독성·드래그를 확인한다. |
| 문서·공개 위키 | build/check, Python·Node 위키 검사, 전체 읽기 전용 사본의 배포·비로그인 확인을 수행한다. |

## 6. 이번 전달 단계의 정지점

이미지 파일·기능별 한영 기획·리소스 매니페스트·구현 순서까지 준비한다. 게임 코드·셰이더·프리팹·씬·저장 이전은 착수하지 않는다. 다음 구현 지시를 받으면 A단계부터 진행한다.
