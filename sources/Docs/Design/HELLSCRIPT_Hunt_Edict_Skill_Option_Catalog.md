# HELLSCRIPT 사냥 칙령: 스킬별 핵심 옵션

작성일: 2026-09-09 · 버전: v0.2 · 상태: 스킬당 옵션을 줄인 재설계안입니다. 게임 화면·저장 형식·실행 코드의 구현 완료 기록은 아닙니다.

**직접 조절하는 옵션은 스킬당 4~6개를 권장하고, 어떤 장비 조합에서도 최대 8개를 넘지 않습니다.** 이번 구성은 액티브 18종과 기본 공격 3종을 모두 4~6개 안에서 설계합니다. 패시브 18종에는 별도 편집 옵션을 만들지 않고 장착 효과를 자동으로 반영합니다.

v0.1의 524개 설정·연계·정보 항목을 다시 분류했습니다. 고유한 사용 방식을 고르는 항목은 남기고, 반복되는 전투 기준은 전역에서 한 번만 정하며, 실제 실행 가능 여부는 시스템이 검사합니다. 이전 상세 선택지를 접힌 메뉴 안에 그대로 두지 않습니다. 기존 상세안은 위키의 문서 이력으로 남으며, 현재 스킬 옵션의 기준은 이 v0.2입니다.

## 옵션을 세는 기준

- 자동 사용 On/Off도 옵션 1개입니다. 표의 한 행은 단일 선택 하나 또는 수치 입력 하나입니다.
- ‘사용 조건’ 한 행 아래 HP·적 수·거리 슬라이더를 숨기면 각각 따로 셉니다. 이번 표에는 그런 하위 편집 항목을 두지 않습니다.
- 스킬별 규칙 추가, 사용자 OR/AND 조합, 별도의 고급 조건 편집기를 제거합니다. 같은 스킬을 규칙 3개로 나누어 각기 6개씩 설정하는 방식도 제공하지 않습니다.
- 장비·세트·패시브를 바꾸어도 행 수는 늘어나지 않습니다. 기존 행에서 관련 선택지를 활성화하거나, 그 선택의 효과 계산을 현재 장비에 맞춰 보완합니다.
- 이름·설명·피해·사거리·남은 충전·실행 불가 사유는 읽기 전용입니다. 정보를 열어도 새로운 편집 항목은 나오지 않습니다.
- 스킬 선택·교체·해제와 저장·되돌리기·프리셋은 공통 작업입니다. 옵션을 다른 탭으로 옮겨 스킬당 개수에서 제외하지 않습니다. 이번 전역 이관은 모든 스킬이 같은 값을 참조하는 항목에만 적용합니다.

표의 `HEC-W01-01` 등은 새 설계 항목의 식별자입니다. 예전 `HED-*` 항목 ID와 다른 뜻으로 구분하며, 실제 스킬 ID W01 등은 그대로 유지합니다. 선택지의 기본값·고정 판단 수치는 설계 제안이며 효과 수치를 바꾸는 기능이 아닙니다.

## 무엇을 남기고 어디로 합치는가

| 이전 항목 묶음 | 새 처리 | 사용자가 결정하는 내용 |
|---|---|---|
| 스킬 자동 사용과 여러 규칙의 On/Off | 스킬별 자동 사용 하나로 통합합니다. | 이 스킬을 자동 사냥에 사용할지 정합니다. |
| 대상 등급·HP·관통 인원·고립 여부 등 | 해당 스킬의 공격 방식·목표·필요 인원 중 의미가 다른 항목만 남깁니다. | 광역 처리와 단일 집중 등 실제 용도를 고릅니다. |
| 조준 반경·선행 시간·관통 순서·충돌 확인 | 조준 방식 한 선택과 자동 예측으로 통합합니다. | 어느 결과를 우선할지 고르고 세부 계산은 맡깁니다. |
| 자신의 HP·예상 피해·최근 피해·회피기 보존 | 기존 전역 회피·긴급 생존을 함께 참조합니다. | 모든 스킬에 적용할 생존 기준을 한 번 정합니다. |
| 각 스킬의 자원 하한·사용 후 잔량·할인 중복 조건 | 전역 생존용 자원 보존과 실제 비용 검사로 통합합니다. | 자원 회복이 핵심인 스킬의 발동 기준만 개별 항목으로 남깁니다. |
| 추적 거리·시간·실패 시 이동·공격 중단 | 전역 이동·추적·중단 방침과 고정 실행 검사로 통합합니다. | 고유한 이동·착지·설치 목적만 스킬에서 고릅니다. |
| 버프 이름·남은 시간·최근 스킬·충전 횟수 조건 | 필요한 스킬에만 연계 방식 한 선택을 남깁니다. | 연계를 활용할지 고르고 실제 발동·예약 시점은 자동 확인합니다. |
| 효과량·고유 CD·속박 시간·내부 CD | 읽기 전용으로 옮깁니다. | 편집하지 않습니다. |
| 임의 조건식·미세한 예측 여유·다중 실패 정책 | 사용자 편집 기능에서 제외합니다. | 이번 간소화안에서는 제공하지 않습니다. |

회피·생존·추적의 전역 설정을 스킬마다 복제하지 않습니다. [전역 옵션](HELLSCRIPT_Hunt_Edict_Global_Options.md)의 같은 설정값을 사용하며 스킬 목록을 다시 펼쳐 각각 예외를 조절하는 전역 하위 메뉴도 추가하지 않습니다. 전체 행동 순서도 한 목록을 공유하고, 카드별 별도 우선순위 입력은 두지 않습니다.

## 적은 옵션으로도 동작이 분명해야 하는 기준

1. **사용 안 함은 완전한 자동 사용 중지입니다.** 전역에서 생존기로 선택했더라도 해당 스킬을 자동 발동하지 않습니다. 전역에 사용 불가 이유를 표시합니다.
2. **선호와 필수 조건을 구분합니다.** ‘우선’은 해당 후보가 없으면 표에 정의한 일반 방식으로 돌아갑니다. ‘전용·때만’은 조건이 없으면 이 스킬을 보류합니다. 어떤 선택도 다른 스킬의 판단을 무기한 막지 않습니다.
3. **생존 기준과 실제 실행 자격이 먼저입니다.** 해금·장착·자원·CD·사거리·사선·안전한 착지·현재 행동 잠금을 통과해야 합니다. 선택한 방식이 피해·사거리·무적·제어 효과를 새로 지급하지 않습니다.
4. **공격·설치 후보와 예측의 기준을 맞춥니다.** 선택한 방향·착지·설치 위치를 기준으로 인원과 충돌을 계산합니다. 다른 후보의 예측값을 가져와 발동시키지 않습니다. 감지하지 못한 적이나 확정되지 않은 미래를 읽지 않습니다.
5. **연계는 실제 사건으로 판단합니다.** 시전 시작·발사·적중·착지 성공·충전 획득을 구분합니다. 후속 행동의 일반 검사에서 채널 잠금 때문에 서로 기다리는 구성은 만들지 않습니다. 채널 종료를 검토할 때만 정상 종료 직후 상태를 가정하고, 종료 뒤에는 다시 실행 자격을 확인합니다.
6. **자동 보완이 효과 소유권을 대신하지 않습니다.** 장비·세트·패시브의 피해·시간·충전은 실제 착용 구성대로 계산합니다. 같은 부위의 전설 두 개나 서로 다른 4세트 두 개를 동시에 요구하지 않습니다.
7. **기본 사냥은 준비 상태가 없어도 시작할 수 있어야 합니다.** 할인이나 연계 충전을 만드는 행동에 이미 그 충전이 있어야 한다는 조건을 걸지 않습니다. 선택 가능한 엄격한 전용 방식은 필요한 선행 조건과 보류 사유를 명시합니다.
8. **긴급용 보존이 일반 연계보다 우선합니다.** 도약·후퇴·순간이동을 공격에 쓰는 방식도 전역 보존을 지킵니다. 동작 중단과 이미 생성한 효과의 처리는 기존 전투 규칙을 유지합니다.

스킬 표는 **남긴 편집 항목**, 그 아래 설명은 **사용자가 조절하지 않는 고정 처리**입니다. ‘자동 처리’ 문장 안에 새 슬라이더나 토글을 추가하지 않습니다. 여러 설정의 조합이 실행 불가하면 사유를 보여 주고 다음 유효 행동을 판단합니다.

**특성:** 이동하면서 0.25초마다 자원을 사용해 자기 중심 2.5m를 공격하며, 오래 유지하거나 실제로 걸으면 장착 효과에 따른 비용 감소·도약 충전을 활용할 수 있습니다.

**고정 자동 판단:** 실제 공격 범위에 0.5초 동안 적이 없거나 다음 틱 비용을 낼 수 없으면 종료하며, 전역 생존·자원 보존 판단도 따릅니다. WP02·SW 2세트·LC02의 비용 감소, LW01 끌어당김과 SW 4세트의 보행 충전은 실제 장착 효과와 발생 시점에 따라 계산합니다. 도약 연계는 후속 행동을 예약하지 않고, 충전을 만들려고 위험한 왕복 보행을 강제하지 않습니다.

**설정 예:** 자동 사용 `켜기` · 시작할 교전 `무리 상대` · 회전 중 이동 `무리 가장자리 선회` · 회전 종료 방식 `3초씩 끊기`.

## 저장·프리셋·구형 설정의 처리

명시적 저장, 되돌리기, 미저장 이탈 확인, 프리셋 5칸, 사용 스킬 4칸과 옵션의 동시 복원, 미보유 스킬을 빈칸으로 두는 정책은 유지합니다. [공통 명세](HELLSCRIPT_Hunt_Edict_Detail.md)에 따라 불러오기는 편집본만 바꾸고 저장 성공 뒤 실제 사냥에 반영합니다.

새 프리셋의 원본은 **전역 설정·스킬 배치·공통 행동 순서·스킬별 핵심 옵션값**입니다. 임의 OR/AND 규칙과 이전 고급 조건을 숨겨 붙이지 않습니다. 미장착 스킬의 간소화 옵션도 보존하며, 빈칸에 대체 스킬을 넣으면 그 스킬 자신의 값을 사용합니다. 현재 발동 중인 충전·버프·HP·자원·CD는 공유 코드로 복제하지 않습니다.

특정 장비나 스킬이 필요한 선택지를 가져왔는데 조건을 충족하지 못하면 원래 선택값과 이유를 보존합니다. 해당 선택의 전용 연계만 사용할 수 없고, 표에 명시한 일반 대체 행동이 있으면 그 행동을 사용합니다. 대체 행동이 없는 ‘전용·때만’ 선택은 해당 스킬을 보류합니다. 이 구분을 미리보기와 실행 사유에 표시하며 값을 몰래 일반 선택으로 저장하지 않습니다.

v0.1의 상세 옵션과 기존 `HED1` 규칙을 새 4~6개 값으로 항상 손실 없이 바꿀 수는 없습니다. 다음은 후속 구현 시의 이관 원칙입니다.

| 상황 | 처리 |
|---|---|
| 새 간소화 코드 | 옵션 정의·선택값·고정 판단의 버전을 함께 저장합니다. 같은 버전·코드면 같은 정책과 값을 재현하며 수신자의 기본값으로 바꾸지 않습니다. |
| 기존 규칙과 의미가 같은 선택이 있음 | 검증된 정확한 매핑만 간소화 편집본으로 옮깁니다. 원본 프리셋은 그대로 보존합니다. |
| 기존 규칙이 여러 선택에 걸치거나 세부 조건이 사라짐 | 원본을 보존하고 변경·제외되는 항목을 미리 보여 줍니다. 사용자가 ‘간소화하여 불러오기’를 선택하면 변환안을 편집본에 넣으며, 실제 반영은 저장 후입니다. |
| 변환을 취소함 | 현재 편집본·저장본·원본 프리셋을 바꾸지 않습니다. |
| 알 수 없는 버전·손상된 코드 | 간소화 명목으로 값을 버리며 불러오지 않습니다. 기존 호환성 오류 처리를 따릅니다. |

새 공유 자료에는 별도 스키마 버전이 필요합니다. 예전 HED1 해석을 바꿔 같은 코드가 조용히 다른 행동을 만들지 않습니다. 내부 실행용 규칙을 생성하는 방식을 쓰더라도 간소화 옵션을 원본으로 삼고, 기존 스킬당 3규칙·OR 2묶음·AND 3조건·전체 활성 24규칙 상한을 바꾼 것으로 간주하지 않습니다. 변환으로 표현되지 않는 동작은 후속 구현 설계에서 해결하며, 그 이유로 사용자에게 고급 조건 편집을 다시 요구하지 않습니다.

## 완료 기준과 근거

이번 재설계의 문서 검사와 이후 게임 구현 검사는 구분합니다. 이후 화면·실행 구현은 다음을 만족해야 합니다.

1. 기본 공격을 포함한 모든 스킬의 편집 항목은 자동 사용을 포함해 최대 8개입니다. 현재 설계는 전부 4~6개이며 어떤 선택·장비 조합에서도 숨은 추가 입력이 없습니다.
2. 각 선택지의 발동·대상·대체 행동이 설명대로 다릅니다. 동일한 행동을 이름만 바꾼 선택지와 ‘자동으로 적절히’라는 미정 정책을 남기지 않습니다.
3. 공통 생존·자원 보존·추적 값을 스킬별로 다시 설정하지 않습니다. 고정 실행 검사는 사용자가 꺼서 무효화할 수 없습니다.
4. 연계 충전이 없는 최초 교전, 보스 한 마리, 모든 유료 스킬의 자원 부족, 후속 스킬 미보유에서도 다음 행동과 보류 사유가 분명합니다.
5. 고립 공격·다중 사격·장판 보존·연쇄 재방문·보호막 중복 제한 등 각 스킬의 실제 특성이 유지됩니다. 장비가 없는 선택은 필요한 효과를 지급하지 않습니다.
6. 편집·불러오기·저장 실패·되돌리기·재장착으로 전투 상태가 초기화되지 않습니다. 같은 코드의 원본 값과 부분 적용한 편집본을 구분합니다.
7. 예전 상세 옵션이 일반·고급·장비 전용 메뉴나 다른 전역 페이지에서 다시 노출되어 실제 조절 수가 늘어나지 않습니다.

효과 근거는 [콘텐츠 카탈로그](HELLSCRIPT_Content_Catalog.md), [패시브 명세](HELLSCRIPT_Passive_Combat_Detail.md), [장비 명세](HELLSCRIPT_Itemization_Detail.md), [충전 처리](../Implementation/Charge_Expansion.md)와 현재 `Assets/HELLSCRIPT/Runtime/Core`의 스킬·행동·투사체·장판 구현입니다. 고정 효과는 이 자료를 따르고, 이 문서의 새로운 사용 방식·자동 예측·간소화 저장 연결은 별도 구현이 필요한 설계입니다.
