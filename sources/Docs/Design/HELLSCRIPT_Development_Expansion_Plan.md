# HELLSCRIPT 후속 개발 상세 기획

버전 1.2 · 작성일 2026-09-08 · 상태: 후속 개발 진행 중. 아래 항목의 구현 여부는 개발 기록과 검증 결과를 따른다.

## 1. 이번 기획의 목표

플레이어가 **원하는 빌드의 장비를 찾아 행동을 조정하고, 구성이 달라지는 균열에서 그 선택을 시험하는 게임**으로 완성한다. 전투가 자동으로 진행되는 것에 더해, 장비 발견·위험 대응·탐색 경로·보상 정리마다 선택과 결과가 보여야 한다.

사용자가 이번에 요청한 내용은 직업·빌드의 콘셉트에 맞는 장비, 접두사·접미사를 활용한 랜덤 옵션, 전설·세트, 매번 구성이 달라지는 자동 생성 균열, 필드 곳곳의 보물 상자다. 이 기능들이 성장·전투·탐색·경제·화면 흐름과 연결되도록 상세 규칙과 완료 기준을 먼저 작성한다.

기획 착수 당시 첫 빌드에는 자동 전투·장비 추첨·고정 고리 지도·로컬 저장의 골격이 있었다. 같은 이름의 기능이 화면에 있다는 이유로 아래 상세 기획까지 구현된 것으로 보지 않는다. 이후 구현한 범위와 검증은 [장비 확장 기록](../Implementation/Itemization_Expansion.md), [자동 생성 균열·상자 기록](../Implementation/Rift_Expansion.md), [성소·저주 상자 기록](../Implementation/Field_Expansion.md)과 실제 소스를 기준으로 판단한다. [첫 플레이 빌드 기록](../Implementation/Playable_Build.md)은 최초 상태를 보존한다.

### 확정 수준과 문서 우선순위

- **사용자 확정:** 기존 정책과 이번 요청에서 명시한 기능 방향이다. 3직업·8부위·레벨 30·완전 자동 전투·5분 균열·캐릭터별 초회·온라인 서비스를 유지한다. 배속 이용 권한은 2026-09-09 변경한 [배속 잠금·사용권 정책](HELLSCRIPT_Speed_Access_Detail.md)을 따른다. 현재 1배속만 제공하며, 초기 과금 범위와 향후 구독·이벤트 해금을 구분한다.
- **상세 시험안:** 이번에 구체화한 접두/접미 배분, 티어·가중치, 상자 수량·보상, 탐색 판단, 이벤트 수치 등이다. 개발과 플레이 검증의 시작값이며 밸런스가 검증된 수치는 아니다.
- **개발 기준:** 후속 개발 진행 요청에 따라 추천안인 총 6세트로 구현을 시작한다. 이는 별도 선택 답변을 받았다는 기록이 아니라, 개발 담당자가 명시하고 적용한 가정이다. 추가 3세트·12부위의 수치는 시험값으로 검증한다.
- **후순위 제안:** 재미를 강화하되 다음 구현의 필수 통과 조건으로 삼지 않는 기능이다. 승인되지 않은 거래·PvP·시즌·랭킹·펫·용병은 추가하지 않는다.

사용자 결정 기록을 가장 먼저 적용한다. v1.2 상세 문서는 기존 정책을 보존하면서 처리 방식의 공백을 채운다. 기존 시험값을 바꾸는 경우에는 담당 상세 문서에 변경 전·후와 이유를 적는다. 한 기능의 확률·상태 전이·정산 규칙은 담당 문서 한 곳에서 관리하고, 다른 문서에서는 링크로 참조한다. 기존 카탈로그의 정의 수량 178개는 v1.1 기준이며 신규 콘텐츠가 이미 구현되었다는 집계가 아니다.

## 2. 플레이어가 경험해야 할 변화

| 현재 첫 빌드 | 후속 버전의 플레이 경험 |
|---|---|
| 장비의 등급과 숫자를 확인한다. | 자신이 선택한 빌드에서 그 옵션이 필요한 이유, 지금 장비와의 교환 조건, 다음에 찾을 장비를 확인한다. |
| 적 위치가 달라지는 고리 지도를 돈다. | 방의 연결·진입 방향·장애물·적 무리·정예·상자 위치가 함께 달라지며 탐색 설정에 따라 경로가 달라진다. |
| 처치하고 다음 적에게 이동한다. | 위험 회피, 목표 선택, 상자 회수, 보스 진입 사이의 우선순위가 행동으로 드러난다. |
| 전설·세트 이름을 얻는다. | 추가 타격·착지 효과·거리 유지·장판 연계처럼 실제 전투 방식이 바뀌며, 효과가 발생한 이유를 확인한다. |
| 실패 후 다시 시작한다. | 피해 원인과 막힌 행동을 확인하고 장비 또는 조건 한 가지를 바꿔 훈련·재도전으로 비교한다. |

### 2.1 여섯 가지 빌드의 파밍 목적

| 빌드 ID | 전투 콘셉트 | 장비에서 찾는 것 | 반드시 남겨 둘 약점·선택 |
|---|---|---|---|
| PW01 회오리 생존 | 적 무리 가장자리를 돌며 회오리를 유지한다. | 자원 유지, 회오리 연계, 방어·보호막과 비상 도약을 지원하는 옵션을 찾는다. | 무리 밀도가 낮으면 효율이 떨어진다. 공격 진입에 도약을 쓰면 탈출 수단을 잃는다. |
| PW02 도약 분쇄 | 착지와 근접 공격의 짧은 기회에 화력을 집중한다. | 도약 착지 효과, 직접 피해, 재사용 대기시간과 생존을 보완한다. | 회피용 도약과 진입용 도약이 같은 재사용 대기시간을 공유한다. |
| PA01 관통 거리유지 | 적을 사선에 모으고 일정 거리를 유지한다. | 관통·다중 사격, 공격 속도, 극대화와 목표 표식을 활용한다. | 적이 퍼져 있거나 퇴로가 좁으면 정렬·거리 유지가 어려워진다. |
| PA02 맹독 매복 | 이동 경로에 덫을 깔고 독·암흑 효과를 연계한다. | 덫·후퇴 도약·중독 출처와 맞물리는 전설, 지속 피해와 자원 옵션을 찾는다. | 덫을 벗어나는 적, 배치가 어긋난 경로에서는 효율이 떨어진다. |
| PM01 서리 장판 | 장판 안에 적을 유지하고 화염구를 연계한다. | 냉기·화염 연계, 장판 점유, 자원과 보호막을 보완한다. | 이동이 많은 전투에서는 장판 재배치에 비용을 쓴다. |
| PM02 연쇄 제어 | 군중제어와 연쇄 공격으로 여러 적을 순서대로 처리한다. | 연쇄 대상, 번개 피해, 재사용 대기시간과 방어 수단을 보완한다. | 부하가 없는 단독 보스에서는 군중전과 같은 연쇄 효율을 얻지 못한다. |

전설·세트가 없어도 각 빌드의 기본 행동이 성립해야 한다. 핵심 기술을 특정 초희귀 장비 하나의 획득 여부로 잠그지 않는다. 장비 화면은 ‘공격력 상승’ 하나만으로 세트 해제, 생존 옵션 손실, 자원 고갈을 더 좋은 장비라고 판정하지 않는다. 정확한 부위별 목표와 전설 조합은 장비 상세안에서 관리한다.

### 2.2 한 판의 예시

1. 플레이어가 맹독 매복 빌드와 ‘안전할 때 상자 열기’를 선택하고 가방 여유·실패 정책을 확인한다.
2. 새 시드로 생성한 균열에 들어간다. 영웅은 알고 있는 길과 감지한 적만 사용해 다음 구역을 탐색한다.
3. 지원형 적과 독 덫의 배치가 맞물리면 처치 속도가 빨라진다. 적이 다른 길로 들어오면 경로와 목표를 다시 평가한다.
4. 탐색 중 발견한 상자가 우회 경로에 있다. 자동 행동은 상자 종류, 도달 거리, 전투 위험과 잔여 시간을 기준으로 방문 여부를 정한다.
5. 상자에서 나온 장비가 가방에 들어간다. 접두/접미의 실제 값과 전설 효과는 보상이 확정된 뒤 바뀌지 않는다.
6. 처치 게이지가 차면 보스 안내가 활성화된다. 남은 시간과 설정에 따라 전투·상자 방문·보스 이동을 이어 간다.
7. 결과에서 전투 시간과 실제 경과 시간, 상자에서 얻은 보상, 자원 부족·경로 복구·사망 원인을 확인한다. 플레이어가 장비나 규칙을 수정한 뒤 같은 훈련 조건에서 비교한다.

이 예시는 모든 판에 특정 상자나 특정 아이템을 보장한다는 뜻이 아니다. 자동 행동에 상자와 탐색을 연결하는 경험의 기준이다.

## 4. 화면과 자동 행동의 연결

| 행동 편집 | 자연어 요약과 실제 조건 값, 목표·이동·상호작용 우선순위를 편집한다. | 조건이 항상 거짓이거나 실행할 행동이 없는 규칙을 저장 전에 검출한다. |

전투 중 장비를 줍더라도 자동 장착하지 않는다. ‘새 장비가 생겨서 다음 판의 행동을 바꾼다’는 선택은 마을에서 플레이어가 한다. 한 번의 편집에서 수치·장비·스킬을 모두 바꾸지 않고도 결과 차이를 확인할 수 있도록 변경 요약을 남긴다.

## 5. 성장과 경제를 검증하는 기준

### 5.1 처음 15분의 목표 경험

시간은 UX 검증용 목표이며 보상 지급 조건이나 레벨 보장이 아니다. 배속·실패·편집 시간에 따라 달라진다. 실제 스킬 해금과 경험치는 상위 기획서를, 구간별 안내·완료 조건은 [게임 완성 체크리스트 2장](HELLSCRIPT_Gameplay_Completion_Checklist.md#2-첫-15분과-여섯-빌드의-성장)을 따른다.

첫 경험에서는 완전 자동 전투 이해, 현재 행동의 이유 확인, 장비 비교와 조건 한 개 수정, 훈련 후 재도전의 네 가지를 확인한다. 드롭을 얻지 못한 경우에도 실제 아이템을 지급하지 않는 비교 안내를 제공할 수 있다. 처음 15분에 완성 빌드나 세트 획득을 보장하지 않는다.

처음부터 모든 시스템을 동시에 설명하지 않는다. 기능을 처음 이용할 때 짧은 안내를 제공하고 다시 볼 수 있게 한다. 튜토리얼 완료 보상·무료 전설·강제 세트 지급을 새로운 경제 정책으로 추가하지 않는다. 진행이 막히면 난이도·기본 공격·해금 전 추천 규칙을 먼저 조정한다.

### 5.2 하나의 보상 예산으로 관리

몬스터, 상자, 선택 사건, 보스의 보상을 별도 구현하더라도 **한 판에서 얻는 총량과 실제 시간당 수입**으로 함께 검증한다. 상자 등급별 확률·수량은 균열 상세안이 기준이며 소탕은 기존의 보스 반복 보상만 지급한다. 상자 보상을 소탕이나 앱 미실행 보상에 자동 추가하지 않는다.

| 측정 항목 | 측정 목적 |
|---|---|
| 단계·빌드별 클리어율, 사망·시간 초과 비율 | 생존 실패와 화력·경로 실패를 구분한다. |
| 장비 개수·희귀/전설/세트 비율과 획득 출처 | 상자가 몬스터·보스를 압도하거나 특정 경로만 유효해지는지 확인한다. |
| 첫 유효 장비 교체, 첫 전설, 첫 2/4세트까지의 시간 | 파밍 목표가 너무 빠르게 소진되거나 지나치게 멀어지는지 확인한다. |
| 슬롯별 전설 후보 확률, 특정 빌드에 맞는 옵션 비율 | 전설 등급 확률과 원하는 전설 확률을 혼동하지 않는다. |
| 획득·이동·전투·상자·가방 정리·실패에 쓴 시간 | 배속과 편의 옵션이 실제 시간당 수입에 미치는 영향을 확인한다. |
| 강화·제작·재설정·가방 확장에 쓴 재화 | 자원 부족으로 기본 진행이 막히거나 순환 이득이 생기는지 확인한다. |
| 상자만 열고 포기하기, 저단계 고속 반복, 분해→제작 | 정상적인 파밍보다 유리한 악용 경로가 생기는지 확인한다. |

첫 평가 표본은 동일한 콘텐츠 버전·장비 수준·조건에서 6빌드 각각 30개 시드를 사용한다. 이는 개발 비교용 시작 표본이며 정확한 모집단 승률을 보장하지 않는다. 그다음 약점이 드러난 빌드·단계·시드로 확대한다. 희소 아이템의 확률 검증은 한두 판의 관찰 대신 추첨 로직의 이론값과 별도의 충분한 표본을 사용한다.

배속은 보상에 별도 배율을 곱하지 않지만 실제 시간당 판수가 달라진다. 1배·1.5배·2배를 모두 측정한다. 같은 시드와 같은 전투 시간 기준에서 행동 결과가 달라진다면 프레임 의존 판정·난수 호출·입력 시점을 먼저 확인한다.

## 6. 자산 제작 방향

사용자의 요청에 따라 배경·장비·전설·세트·상자·아이콘 같은 래스터 이미지는 내장 이미지 생성기를 적극 활용한다. 버튼 배치·프레임·게이지·조건 편집 컨트롤은 Unity UI로 제작하고, 움직이는 영웅·적·상자는 간단한 통자 모델과 분리 가능한 부품으로 기능을 검증한다.

| 자산군 | 다음 제작 단위 | 승인·교체 기준 |
|---|---|---|
| 장비 | 기존 베이스 24종, 전설 15종, 세트 부위별 아이콘을 정의 ID에 연결한다. | 같은 부위가 작은 화면에서도 읽히고 직업·세트 계열을 구분할 수 있어야 한다. 세트 확장 시 추가 12부위를 별도 집계한다. |
| 균열 | 2테마·12방의 벽·바닥·기둥·연결구·장식 조합을 만든다. | 장식이 통행·시야·위험 판정과 어긋나지 않아야 한다. 새 배경 그림 한 장만으로 맵 변화를 대신하지 않는다. |
| 상자 | 종류별 닫힘·열기·열림과 미니맵 표시를 만든다. | 뚜껑 회전 등 간단한 움직임으로 상태를 구분하고 보상 생성은 논리 상태가 결정한다. |
| 캐릭터·적 | 직업 3종·일반 적 12종·보스 3종을 형태와 표식으로 구분한다. | 단순 몸체 상태에서도 예고·실제 타격·사망과 이동 방향이 읽혀야 한다. |
| 전투 효과 | 스킬 18종, 정예 6속성, 전설·세트 발동의 핵심 표식을 제작한다. | 바닥 예고와 공격 범위를 가리지 않으며 2배속에서도 읽을 수 있어야 한다. |
| 소리 | 메뉴·타격·위험·회피·상자·등급별 획득·보스·결과 소리를 사건에 연결한다. | 동시 타격 음량을 제한하고 무음 상태에서도 핵심 위험·보상을 이해할 수 있어야 한다. |

생성 이미지에는 원본·프롬프트·파일 경로·사용 ID·검토 상태를 기록한다. 현재 내장 도구가 모델 버전을 공개하지 않는 한 `gpt-image-2` 사용을 검증한 자산이라고 표기하지 않는다. 투명 이미지가 필요할 때는 네이티브 알파 결과를 요청하고 실제 알파를 확인한다. 이번 문서 작업에서 이미지나 모델을 새로 제작한 것은 아니다.

## 7. 개발 순서와 완료 조건

아래 D1–D6은 첫 플레이 빌드 이후의 작업 순서다. 상위 기획서의 P0–P5 전체가 완료되었다는 뜻이 아니다. 각 단계는 게임을 플레이하며 확인할 수 있는 결과를 남긴다. 기간은 작업량과 검증 결과를 확인하기 전에는 약속하지 않는다.

| 단계 | 구현 묶음 | 다음 단계로 넘어갈 증거 |
|---|---|---|
| **D1 장비와 행동의 연결** | 정의/인스턴스·접두/접미·추첨·비교·재설정·보호 규칙을 구현하고, 전사 두 빌드로 전설/세트 효과 경로를 먼저 검증한다. 복합 조건·도약의 진입/탈출 규칙·시전/착지·효과 사건의 최소 기반과 보상 영수증·저장 버전 계약을 먼저 갖춘다. | 접사 수·중복·부위·티어가 맞고, 같은 장비 복원 시 값이 유지된다. 장비 교체로 행동·자원·피해가 의도대로 변하며 세트 해제와 전설 연쇄 제한이 확인된다. |
| **D2 매번 달라지는 한 판** | 한 테마에서 시작해 두 테마·12방의 생성 계약, 길 찾기·미니맵, 상자·보스·결과 정리를 완성한다. 선택 사건은 이 기반을 통과한 뒤 별도 시험한다. | 연결·도달성·최소 처치 점수·보스 공간을 통과한 맵만 입장된다. 여러 판의 구조가 달라지고 재접속하면 같은 판이 복원된다. 상자 중복 보상과 가방 루프가 없다. |
| **D3 여섯 빌드와 전투 패턴** | 전 직업 액티브·패시브, 전체 조건·프리셋, 적·정예·보스, 전설 15종과 선택한 세트 범위를 연결한다. | 6빌드가 편집 화면에서 재현되고 1배·1.5배·2배의 세 옵션에서 작동한다. 같은 적을 다른 규칙으로 상대했을 때 의도한 행동 차이를 로그로 설명할 수 있다. |
| **D4 성장·정리·분석 흐름** | 첫 이용 안내, 레벨·장비 목표, 4NPC와 창고, 강화·제작·상점, 훈련 A/B·최근 로그, 실패·반복 UI를 완성한다. | 새 계정에서 안내→균열→장비 비교→설정 수정→재도전이 이어진다. 미소유 장비·미해금 스킬을 지급하지 않고 보호 장비도 잃지 않는다. 경제 관찰표가 작성된다. |
| **D5 공개용 데이터와 계정** | 검증한 보석 표·소켓·경제를 연결하고 실제 온라인 계정·세션·교차 저장·서버 시각·소탕·미실행·구매/환불을 완성한다. | 중복 요청·통신 중단·2기기·시계 변경·스키마 변환 시험을 통과한다. 공급자·운영비·상품·지원 지역은 이 단계의 착수 자료로 검토한다. |
| **D6 기기와 공개 품질** | 정적 이미지·임시 모델·효과·음향을 정리하고 Android 빌드·터치·글꼴·배속·프레임·발열·중단 복귀를 검증한다. | 대표 실제 기기의 측정 보고서와 전체 회귀 결과가 있다. 보석·온라인 등 공개 필수 항목이 빠진 상태를 출시 완료로 처리하지 않는다. |

장비와 상자 보상은 D1부터 같은 정산 규칙을 쓰고, D5에서 서버를 붙일 때 아이템을 다시 생성하지 않는다. Android 모듈과 시험 기기 확보는 D1부터 병행할 준비 항목이며, 실제 기기 검증을 D6에 처음 시작하지 않는다. 자산 제작도 기능별로 병행하되 최종 효과가 확정되기 전에 모든 고급 애니메이션을 제작하지 않는다.

### 7.1 다음 코드 변경의 경계

기존 `GameCatalog.cs`의 배열 인덱스 기반 장비·접사는 안정적인 정의 ID에 연결한다. `Economy.cs`는 접사 생성과 공통 보상 정책의 현재 소유자이며, 새 정의가 생겨도 별도 상점·상자마다 다른 추첨을 복제하지 않는다. `RiftMap.cs`의 고정 좌표는 생성된 방·연결·보행 데이터로 대체하고, `WorldView.cs`는 그 결과를 표현한다. 적·상자·장비 판정의 사실을 화면 오브젝트에만 저장하지 않는다.

`CombatSimulation.cs`는 행동·효과·위험의 전투 시간 상태를, `GameStore.cs`는 로컬 개발용 저장을 담당한다. 실제 계정 권한은 이 로컬 저장이 제공한다고 가정하지 않는다. 기존 저장을 변환할 때 장비 ID·실제 접사 값·보상 기록을 보존하며, 변환 실패를 이유로 조용히 새 계정을 만들거나 장비를 재추첨하지 않는다.

씬·프리팹·ScriptableObject는 기존 Unity 자산 ID를 보존하면서 편집 도구로 갱신한다. 이번 기획 보완에는 소스 코드·씬·패키지·프로젝트 설정 변경이 포함되지 않는다.

## 9. 상세 기획 작성 시점의 검증 기록

기획 작성 시점에 코드와 기존 문서를 읽어 구현 공백을 확인했고, 상세 문서의 링크·기존 ID·수량·상태 표기·문서 간 규칙을 대조한다. 아래 상세안의 생성기·상자·접두/접미·확장 세트는 이번에 실행하거나 검증한 기능이 아니다. 이전 빌드의 자동 검사 13개 통과를 새로운 기능의 검증 결과로 사용하지 않는다.

2026-09-08 문서 검사 결과, 관련 문서 7개의 로컬 링크·절 연결과 표 열 수에서 오류가 없었다. 장비 상세안의 접사 24개·전설 15개와 체크리스트 작업 48개의 개수·중복을 확인했다. 대상 조건의 평가 순서, 정예의 속성 수, 드롭 아이템 레벨과 선택 사건의 개발 범위를 문서 사이에 맞췄다. `Assets/HELLSCRIPT`, `Packages`, `ProjectSettings`의 파일 내용을 작업 전후 비교한 결과가 같았으며, 게임 구현·씬·설정을 변경하지 않았다.

후속 구현 상태는 [장비 확장 개발 기록](../Implementation/Itemization_Expansion.md), [자동 생성 균열 개발 기록](../Implementation/Rift_Expansion.md), [성소·저주 상자 개발 기록](../Implementation/Field_Expansion.md), [전투 동작·투사체 개발 기록](../Implementation/Action_Expansion.md), [행동 규칙 편집·판단 개발 기록](../Implementation/Rule_Expansion.md), [전투 효과 통합 기록](../Implementation/Effect_Expansion.md)으로 이어진다. 각 문서 작성 당시의 검사 결과와 이후 코드 검증을 구분한다. D3의 동작·투사체·22조건 편집에 더해 공통 피해 계산·원천별 보호막·중독 출처·보스 제압을 연결했다. 세트 충전·전체 패시브·적별 패턴의 통합은 계속 진행한다.

이후 SW/SWB/SAB/SMB의 시전 예약과 LC02·AP05, 후퇴 시작 시 덫 생성은 [충전·비용 효과 개발 기록](../Implementation/Charge_Expansion.md)으로 이어진다. 이 단계는 자동 검사 197개와 최종 macOS 빌드의 충전·보호막·제압 재시작 검사를 통과했다. 전체 세트의 조합·장판 노출 경계와 적별 패턴, D4~D6의 완료 조건은 계속 검증한다.

전염의 원 표적별 중복 방지와 보스 제어 만료·구형 저장, 같은 틱의 피해·사망·승패 정산은 [전염·사망 정산 개발 기록](../Implementation/Outcome_Expansion.md)에 이어서 기록한다. 이 단계는 자동 검사 220개, 동시 사망 전후의 실제 재시작, 자동 생성 균열의 상자 4개 개봉·보스 클리어 검사를 통과했다. D3의 남은 장비 효과·개별 적 패턴과 D4~D6는 계속 진행한다.

LM01의 고정/추적·설치 위치, SA 독 갱신과 SM 연속 노출·표식 소모는 [장판·세트 시간 처리 개발 기록](../Implementation/Area_Expansion.md)에 정리했다. 후속 검사 256개와 실제 앱 재시작 2회를 통과했다. D3의 다음 작업은 개별 적·정예·보스 패턴과 남은 장비 조합 검사다.

일반 몬스터 12종·정예 특성 6종은 [적 전투 상세 시험안](HELLSCRIPT_Enemy_Combat_Detail.md)에 세부 수치를 정한 뒤 구현했다. [적 콘텐츠 개발 기록](../Implementation/Enemy_Expansion.md)에 303개 검사와 돌진·사망 효과의 실제 재시작 2회 결과를 기록했다. D3의 다음 작업은 보스 3종의 정식 패턴과 남은 패시브·장비 조합 검사다. 앞선 단계의 검사 숫자는 각 시점의 기록으로 유지한다.

보스 3종은 [보스 전투 상세 시험안](HELLSCRIPT_Boss_Combat_Detail.md)에 추가타·광선·소환·갈고리·피난 경로의 기준을 정하고 전용 패턴을 구현했다. 검사 341개, 실제 재시작 4회와 새 패턴이 적용된 전체 균열 클리어를 통과했다. 상세 증거와 남은 범위는 [보스 개발 기록](../Implementation/Boss_Expansion.md)을 따른다. 이어서 전체 패시브·전설·세트 조합과 6빌드의 행동 차이를 검증한다.

패시브 18종의 발동 시점·만료·구성 변경·저장 기준은 [패시브 상세 시험안](HELLSCRIPT_Passive_Combat_Detail.md)을 따른다. 현재 코드의 시간·체력 경계와 원소 기록 방식, 화면 설명·장비 조합 검증은 [패시브 개발 기록](../Implementation/Passive_Expansion.md)에 이어서 정리한다.

전설·세트의 실제 8부위 구성과 6빌드 비교는 [빌드 통합 검사 기준](HELLSCRIPT_Build_Integration_Detail.md)을 따른다. 첫 비교에서 발견한 벽 모서리 반복 정지와 PM01의 단독 보스 대응 공백, 후속 검사 결과는 [빌드 통합 개발 기록](../Implementation/Build_Integration_Expansion.md)에 정리했다. 기능별 남은 흐름·예외·완료 기준은 [남은 개발 작업표](HELLSCRIPT_Remaining_Development_Backlog.md)에서 이어서 확인한다.

현재 캐릭터 훈련에 이어 전투 중 경험치 정산·레벨업과 저레벨 추천 행동을 연결했다. 처리 기준은 [성장 상세안](HELLSCRIPT_Growth_Detail.md), 검사 514개와 실제 앱의 성장·재시작 결과는 [성장 개발 기록](../Implementation/Growth_Expansion.md)을 따른다. D4의 첫 이용 안내·장비 정리·마을·훈련 비교, D3의 남은 조합과 D5~D6의 서비스·기기 검증은 계속 진행한다.

첫 이용 안내는 아홉 단계의 기록·숨기기·재열람과 실제 전투 → 비교 → 수정 → 훈련 → 재도전을 구현했다. 해당 단계의 전체 검사 542개와 macOS 앱의 실제 재시작·화면 검증은 [첫 플레이 개발 기록](../Implementation/First_Play_Expansion.md)을 따른다. 신규 사용자 관찰은 남아 있다.

이후 [훈련 A/B 비교 상세안](HELLSCRIPT_Training_Comparison_Detail.md)에 따라 기준 영웅·장비·배치를 고정한 행동 비교와 전체 집계·명시적 저장을 연결했다. Core 집중 검사 69개·전체 회귀 611개와 그 뒤 추가한 UI의 실행 검증은 [훈련 비교 개발 기록](../Implementation/Training_Comparison_Expansion.md)을 따른다. 장비 교체 훈련·사냥 칙령의 5개 슬롯과 공유·최근 10회 분석, D3의 남은 조합과 D4~D6 전체 범위는 계속 진행한다.
