# 균열 단계별 아이템 등급 확률

작성일: 2026-09-12. 상태: HELLSCRIPT용 밸런스 초안. [English](HELLSCRIPT_Rift_Rarity_Detail.en.md).

## 1. 목적과 기준

획득 경로와 실제로 플레이하는 균열 단계로 장비 등급을 결정한다. 높은 단계에서는 전설 확률과 레어 이상 누적 확률이 증가한다. 장비 매직 찬스 옵션이나 최고 기록에 누적되는 영구 능력치는 추가하지 않는다. 디아블로4는 어려운 전투에 더 좋은 보상 기회를 주는 방향만 참고하며, 아래 수치는 그 게임의 실제 공식이나 수치가 아니다.

사용자가 2026-09-12 제공한 [GDD 기준본](HELLSCRIPT_GDD_v0.1.md)과 [콘텐츠 데이터표](../Data/HELLSCRIPT_Content_v0.1.xlsx)를 프로젝트에 저장해 반영한다. 일반·정예·보스 1단계 기준값은 첨부와 현재 코드에서 일치했다. 아래 상한과 증가 속도는 사용자 확정값이나 플레이테스트 완료값이 아니다.

## 2. 공통 계산식과 데이터

`R`은 이번 전투의 균열 단계이며 1 미만은 1단계로 취급한다. `t=max(0,R−1)`, `K=49`, `g=t/(t+K)`이다. 전설 기준 확률을 `p0`, 전설 상한을 `c`라고 하면 `p=p0+(c−p0)×g`를 사용한다. 각 비전설 등급의 기준 확률 `b`는 `b×(1−p)/(1−p0)`로 조정한다.

| 경로 | 일반 기준 | 마법 기준 | 레어 기준 | 전설 기준 p0 | 전설 상한 c |
|---|---:|---:|---:|---:|---:|
| 일반 몬스터 | 55% | 25% | 19% | 1% | 10% |
| 정예 몬스터 | 0% | 60% | 35% | 5% | 25% |
| 보스 | 0% | 0% | 85% | 15% | 45% |

전설 증가분은 비전설 등급의 기존 비율을 보존하며 가져온다. 일반 몬스터는 55:25:19, 정예는 60:35, 보스는 레어에서만 가져온다. 레어 단독 확률은 감소할 수 있지만 레어 이상 누적 확률은 증가한다. 정예의 일반 등급과 보스의 일반·마법 등급은 계속 0%다.

50단계에서 증가분의 절반에 도달하고 이후 완만하게 상한에 접근한다. 이 방식은 무한 단계에서 음수나 100% 초과 확률을 만들지 않고, 여러 구간표 없이 성장 속도를 조절할 수 있다. `K`는 세 경로가 공유한다. 경로별 기준과 상한을 순서대로 유지하면 모든 단계에서 보스 ≥ 정예 ≥ 일반의 전설 확률을 보장한다.

기존 `ItemCatalog`의 코드 정의 데이터 방식에 맞춰 `RiftRarityBalance.cs`에서 `K`와 경로별 기준·상한을 관리하고, `RiftRarity.cs`에서 계산·추첨한다. 유효하지 않은 기준 합계, 음수·비유한값, 금지 등급, 역전된 경로별 전설 기준·상한과 100% 상한은 데이터 생성 시 거부한다. 엑셀은 같은 파라미터를 참조하는 확인용 수식을 사용하며, 런타임에 엑셀을 자동으로 읽는 기능은 추가하지 않는다. 밸런스 변경 시 코드 데이터와 엑셀 파라미터를 함께 수정하고 대조한다.

## 4. 적용 경로와 보상 확정

- 실제 전투에서는 저장된 `RunState.stage`를 사용한다. 최고 50단계를 클리어한 영웅이 10단계를 반복해도 10단계 확률이다.
- 일반 몬스터 장비 드롭 자체 확률은 2%, 정예는 장비 1회, 보스는 장비 3회 추첨을 유지한다. 보스 전설 1개 이상 확률은 `1−(1−p)^3`이며 `3p`는 기대 개수다.
- 소탕은 선택 영웅의 `highestClear`에 해당하는 보스 보상 1묶음이다. 장비 3회 각각 같은 단계의 보스 확률을 적용하며 별도 가산, 기록 갱신, 초회 재지급, 경험치 지급을 추가하지 않는다.
- 오프라인은 기존 골드와 일반 강화 재료만 지급한다. 미확인 상점·코어 제작·기본 제작·균열 상자·이벤트는 이번 단계 보정에서 제외한다.
- 등급이 결정된 뒤 기존 아이템 생성기가 부위·직업에 맞는 전설과 세트를 기존 개별 가중치로 선택한다. 세트는 전설 등급 안에 포함하며 극희귀 구성원만 별도로 우대하지 않는다.
- 일반·정예는 처치 보상 생성 때, 보스는 `bossRewarded`로 보호되는 보상 확정 때, 소탕은 수령 처리 때 한 번만 추첨한다. 바닥의 `DropState.item`에는 완성된 아이템을 저장한다. 수령·재접속·최고 기록 갱신 시 이미 저장된 아이템을 재추첨하지 않는다. 소탕 영수증과 기존 저장 구조를 유지한다.

## 5. 유지하는 규칙과 원본·코드 차이

아이템 레벨은 기존 코드의 `max(1,R−2)~R+2` 균등 정수 추첨을 유지한다. 옵션 수·값 범위, 전설 내부 가중치, 강화·분해 비용, 골드·재료량, 스킬·특성·몬스터 능력치도 그대로다. 장비 재설정은 첨부 기준본의 최신 규칙인 `L=max(1,아이템 레벨)`, `500×L+50×L×(L−1)` 골드를 사용한다. 동일 레벨은 매회 동일 비용이며 500·50은 테스트 계수다. 프로젝트 코드에 남아 있던 구형 횟수 배율을 이 최신 기준으로 정정했다.

프로젝트의 기존 장비 상세 기획에는 아이템 레벨 60 상한이 있으나 현재 생성 코드에는 없다. 또한 전설 후보의 `requiredSkill` 정보가 생성 단계의 해금 필터로 쓰이지 않는다. 이 차이를 이번 작업에서 확대 수정하지 않고 실제 생성 방식과 가중치를 보존한다. 첨부 초기 콘텐츠와 이후 프로젝트 확장 콘텐츠의 차이 역시 이번 기능의 적용 범위가 아니다.

## 6. 화면과 검증

성소와 균열 관리자의 단계 선택 위치에서 **단계별 등급 확률**을 연다. 한국어·영어로 현재 단계의 세 경로와 별도의 소탕 기준 단계를 표시한다. 일반 장비 드롭 2%와 등급 조건부 확률을 구분하고 보스의 3회 각각 적용과 전설 1개 이상 확률을 설명한다.

검증의 실행 결과, 표본·시드·오차 기준과 미실행 항목은 [개발·검증 기록](../Implementation/Rift_Rarity_Expansion.md)에 남긴다. 수학적 확률, 고정 시드 추첨 실험, 자동 전투 처리 검사, 실제 플레이어 화면 검사와 장기 플레이테스트는 구분한다.
