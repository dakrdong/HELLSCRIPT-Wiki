# HELLSCRIPT 화면 비율·방향 대응 상세 기획

작성일: 2026-09-09 · 버전: 1.0 · 상태: 지원 방향 확정, 세부 구성은 개발 전 설계안

## 1. 목적과 적용 범위

**모바일 가로·세로 두 가지 UI 구성을 마련하고, PC는 모바일 가로 구성을 바탕으로 창 크기와 화면 비율에 맞게 재배치한다.**

HELLSCRIPT는 영웅의 이동과 공격을 직접 조작하기보다 장비·스킬·사냥 칙령을 관리하고 자동 전투의 결과를 관찰하는 게임이다. 화면 설계의 중심은 조작 패드를 배치하는 일이 아니라, 정보를 읽고 비교하고 설정을 수정하는 일을 편하게 만드는 데 있다.

앞으로 새로 만들거나 수정하는 UI는 모바일 가로·모바일 세로·PC에서 같은 기능을 사용할 수 있도록 설계한다. 기존 화면도 이 기준으로 전환한다. 이번 작업은 기획 문서 작성이며 게임 코드·씬·프로젝트 설정의 개발과 실행 검증은 다른 개발 작업에서 진행한다.

### 1.1. 확정 사항과 설계 제안

| 구분 | 내용 |
|---|---|
| 사용자 확정 | PC, 모바일 가로, 모바일 세로를 모두 지원하는 UI를 설계한다. |
| 사용자 확정 | UI 작업 단계부터 모바일의 가로·세로 배치를 함께 고려한다. |
| 사용자 확정 | 설정에서 가로·세로 형태를 선택할 수 있도록 한다. |
| 사용자 확정 | PC는 모바일 가로 구성을 재사용하고, PC 화면에 맞는 비율과 크기로 조정한다. |
| 설계 제안 | 모바일 최초 실행은 세로로 시작하고, 이후에는 해당 기기에 저장한 방향을 사용한다. 기존 세로 중심 기획과의 연속성을 위한 시작안이다. |
| 설계 제안 | 모바일은 선택한 방향을 유지한다. 기기를 돌렸다는 이유만으로 가로·세로 구성을 자동 교체하지 않으며, 자동 회전 옵션은 이번 필수 범위에 추가하지 않는다. |
| 설계 제안 | PC는 가로 공통 구성을 사용하고 창 크기에 자동 대응한다. 모바일용 방향 선택 대신 현재 적용 방식을 안내한다. |

아래의 배치·전환·저장·검증 기준은 확정한 방향을 개발 가능한 수준으로 구체화한 설계안이다. 최초 방향, 화면별 열 수, 최소 크기와 전환 경계는 UI 시안과 실제 기기 검증으로 조정할 수 있다. 이미 구현하거나 검증한 기능으로 표시하지 않는다.

### 1.2. 기존 기획과의 관계

[상위 구현 기획서](HELLSCRIPT_Unity_Implementation_Plan.md)의 ‘Android 세로 화면 우선’이라는 화면 설계 기준을 이 문서의 세 가지 환경 대응 기준으로 확장한다. Android 검증 우선순위와 PC·iOS의 출시 시점, 계정·교차 저장 정책까지 변경하는 것은 아니다.

화면 방향과 배치 규칙은 이 문서를 따르고, 기능의 동작과 권한은 각 담당 기획을 따른다. 특히 [사냥 칙령 상세안](HELLSCRIPT_Hunt_Edict_Detail.md)의 명시적 저장·되돌리기·미저장 이탈 확인·프리셋 5칸·스킬 설정 보존 규칙은 모든 화면 방향에서 동일하다.

## 2. 화면 방향·비율·크기의 구분

| 개념 | 의미와 처리 |
|---|---|
| 화면 방향 | 모바일을 가로 또는 세로로 사용하는 선택이다. 선택에 따라 UI 배치와 기기의 표시 방향을 함께 맞춘다. |
| 화면 비율 | 실제 표시 영역의 가로 길이와 세로 길이의 비다. 16:9나 9:16은 대표 예시이며, 화면을 특정 비율로 강제 고정하는 옵션을 뜻하지 않는다. |
| 화면 크기 | 같은 비율에서도 표시 영역의 크기와 밀도가 다를 수 있다. 물리 해상도만으로 글자와 버튼의 사용 가능 크기를 판단하지 않는다. |
| 안전 영역 | 노치·카메라 구멍·둥근 모서리·시스템 표시와 조작 영역을 피해 UI를 배치할 수 있는 공간이다. 방향이나 창 크기가 바뀌면 다시 계산한다. |

가로와 세로는 같은 정보를 다른 위치와 묶음으로 보여 준다. 세로 화면 전체를 가로로 늘리거나 글자·버튼을 일괄 축소하는 방식만으로 대응하지 않는다. UI 데이터와 실행 기능은 공유하고, 사용 가능한 너비와 높이에 따라 목록·상세·비교 영역을 재배치한다.

PC는 가로 구성의 확장형이다. 넓어진 공간은 목록과 상세의 동시 표시, 비교 항목, 적절한 여백에 사용한다. 모바일 화면을 중앙에 작게 고정하거나 모든 요소를 화면 너비만큼 늘리는 것을 기본 동작으로 삼지 않는다.

## 3. 공통 UI 설계 원칙

1. **기능을 동일하게 제공한다.** 방향에 따라 한 번에 보이는 정보량과 접근 단계는 달라질 수 있지만 저장·비교·편집·훈련·결과 확인 기능이 사라져서는 안 된다.
2. **정보의 우선순위를 유지한다.** 현재 위치·선택 대상·중요 상태·주요 실행 버튼은 먼저 보이게 한다. 긴 설명과 세부 기록은 펼침·탭·스크롤로 읽는다.
3. **가로·세로 시안을 함께 만든다.** 각 화면은 모바일 세로, 높이가 짧은 모바일 가로, 넓은 PC에서의 구성을 한 묶음으로 검토한다.
4. **작은 화면에서도 읽고 누를 수 있어야 한다.** 공간이 부족하면 열을 줄이고 보조 패널을 접거나 별도 상세 화면으로 옮긴다. 글자와 터치 영역을 계속 줄이는 것으로 해결하지 않는다.
5. **긴 내용과 확장된 글자 크기를 수용한다.** 사냥 칙령의 조건문, 장비 효과, 결과 표는 줄바꿈과 내용에 맞는 높이를 사용한다. 생략 표시를 사용하면 전체 내용을 열 수 있어야 한다.
6. **중요 버튼은 내용과 분리한다.** 저장·되돌리기·닫기·비교·진입 등 해당 화면의 핵심 버튼에 항상 접근할 수 있도록 한다. 고정 버튼 영역은 마지막 콘텐츠를 가리지 않는다.
7. **모바일 입력을 기능의 기준으로 삼는다.** 설명·비교·메뉴를 마우스 올리기나 우클릭만으로 열게 하지 않는다. PC는 클릭·휠 등으로 같은 기능을 편하게 이용하도록 보완한다.

## 4. 환경별 기본 구성

| 영역 | 모바일 세로 | 모바일 가로 | PC |
|---|---|---|---|
| 전체 구조 | 위에서 아래로 읽는 구성을 사용한다. 한 번에 하나의 주요 작업에 집중한다. | 좌우 공간을 나누어 목록·상세 또는 전투·관리 정보를 함께 보여 준다. | 가로 구성을 확장하고 필요한 경우 보조 패널을 함께 표시한다. |
| 상단 | 제목·현재 영웅·핵심 상태를 간결하게 표시한다. | 높이를 줄여 본문과 전투 영역을 확보한다. | 같은 정보를 유지하며 창 너비에 맞춰 간격을 조정한다. |
| 탐색 | 탭이나 하단 메뉴로 주요 영역을 전환한다. | 얇은 상단 탭이나 측면 메뉴를 사용한다. | 가로 탐색 구조를 공유한다. 여유 공간이 있으면 메뉴 이름을 충분히 표시한다. |
| 목록·상세 | 목록에서 대상을 고른 뒤 상세로 이동한다. 돌아오면 원래 선택과 위치를 복원한다. | 너비가 충분하면 목록과 선택한 상세를 나란히 표시한다. | 목록·상세·비교를 사용할 수 있는 폭에 맞춰 배치한다. |
| 팝업 | 짧은 확인은 대화창, 긴 편집은 화면을 넓게 쓰는 상세 창으로 표시한다. | 짧은 높이를 고려해 본문만 스크롤하고 버튼은 접근 가능하게 둔다. | 읽기 좋은 최대 너비를 유지하고 화면 전체로 무제한 확대하지 않는다. |

가로 모드라도 폭이 부족하면 상세 패널을 접고 선택했을 때 열 수 있게 한다. PC 창을 좁혀도 기능과 읽기 순서를 유지한다. PC의 좁은 창에서 한 열로 접히는 것은 가로 공통 구성의 반응형 처리이며, 모바일 방향 설정을 변경하는 동작은 아니다.

### 4.1. 주요 화면별 배치

| 화면 | 모바일 세로 | 모바일 가로 | PC 확장 기준 |
|---|---|---|---|
| 성소·영웅 | 영웅 요약과 서비스 바로가기를 세로로 배치한다. 주요 관리 메뉴에 바로 진입한다. | 영웅·성소 영역과 서비스 목록을 좌우로 나눈다. | 가로 구조를 유지하고 성장·장비 요약에 여유 폭을 준다. |
| 장비·가방·창고 | 가방 목록에서 장비를 선택해 상세와 비교를 연다. | 목록과 상세를 나란히 놓고 비교는 같은 영역에서 전환한다. | 폭이 충분하면 현재 장비와 후보를 나란히 비교한다. 아이템 수와 긴 설명에 따라 내부 스크롤을 제공한다. |
| 사냥 칙령 | 전역 설정·사용 스킬·프리셋의 탐색 구조를 유지하고 선택한 항목을 세로로 편집한다. 저장·되돌리기 영역을 확보한다. | 분류·스킬 목록과 선택한 옵션을 좌우로 배치한다. | 같은 목록·편집 구조에 요약을 함께 표시할 수 있다. UI 배치 순서를 실제 행동 우선순위로 해석하지 않는다. |
| 균열 준비 | 단계·빌드·가방·획득·실패·반복 정책을 순서대로 보여 주고 진입 버튼에 접근할 수 있게 한다. | 주요 선택과 출발 전 요약을 좌우로 나눈다. | 모바일 가로와 같은 항목을 보여 주며 한 화면에서 확인할 수 있는 범위를 넓힌다. |
| 자동 전투 | 상단에는 생존·시간·진행 정보를, 중앙에는 전투를, 하단에는 현재 행동·배속·일시정지·설정 진입을 배치한다. | 중앙 전투 영역을 확보하고 상태 요약과 관리 버튼을 가장자리 또는 측면에 배치한다. | 가로 HUD를 확장한다. 보조 정보 패널이 영웅과 위험 예고를 가리지 않도록 실제 전투 표시 영역을 계산한다. |
| 훈련·A/B 비교 | 지표별로 A와 B를 위아래로 짝지어 보여 준다. 긴 변경 목록은 별도로 펼친다. | A/B 결과를 나란히 놓고 같은 지표 순서로 비교한다. | 비교 표와 변경 요약을 함께 읽을 수 있도록 확장한다. |
| 결과·분석 | 종료 사유·보상·핵심 원인을 먼저 보여 주고 상세 로그로 이동한다. | 결과 요약과 획득물·원인 분석을 좌우로 나눈다. | 같은 결과 자료를 사용하고 긴 목록·상세 기록의 동시 표시를 늘린다. |
| 설정·도움말·복귀·오류 | 분류를 고른 뒤 상세 내용을 읽는다. 확인·닫기·복구 버튼을 가리지 않는다. | 분류와 상세를 나누되 짧은 높이에서도 끝까지 읽을 수 있게 한다. | 가로 구조를 공유하고 본문이 지나치게 길게 펼쳐지지 않도록 폭을 제한한다. |

이 표는 표시 방식의 기준이다. 아직 구현되지 않은 비교·분석 기능을 추가 개발하라는 범위 확장은 아니며, 각 기능을 구현하거나 수정할 때 적용한다. 첫 플레이 안내, 확인창, 드롭다운, 툴팁과 오류 안내도 같은 대응 범위에 포함한다.

### 4.2. 전투 화면과 카메라

- HP·보호막·자원·남은 시간·처치 게이지·현재 행동·배속·일시정지 상태를 모든 환경에서 확인할 수 있어야 한다. 세부 판단 기록은 사용자가 열어 읽는다.
- UI가 차지한 공간을 제외한 전투 표시 영역을 기준으로 영웅과 주변의 주요 위험 예고를 배치한다. 모바일 가로의 짧은 높이와 세로의 좁은 폭을 각각 검토한다.
- 화면 비율에 따라 카메라 구도와 보이는 주변 공간은 조정할 수 있다. 그러나 감지 범위·탐색 여부·공격 사거리·적 생성·자동 행동 판단을 화면에 보이는 면적에 연동하지 않는다.
- 넓은 PC 화면도 아직 탐색하지 않은 지형이나 감지하지 않은 적의 정보를 공개하지 않는다. 기존 탐색·시야 규칙을 유지한다.
- 방향 전환은 카메라와 UI의 표현 변경이다. 맵을 새로 만들거나 영웅·적·투사체·장판의 게임 상태를 초기화하지 않는다.
- 장식 배경은 비율을 유지하며 필요한 만큼 잘라 표시할 수 있다. 버튼·텍스트·아이콘과 위험 판정 표시는 늘이거나 잘라서 맞추지 않는다.

## 5. 설정 기능

### 5.1. 모바일 화면 방향

설정의 `화면` 분류에 다음 항목을 제공하는 안으로 설계한다. 성소와 전투 중 모두 설정에 접근할 수 있도록 한다.

| 항목 | 표시와 동작 |
|---|---|
| 이름 | `화면 방향`으로 표시한다. |
| 선택지 | `가로`와 `세로`를 제공하고 현재 적용된 값을 명확히 표시한다. |
| 안내 | `선택한 방향에 맞춰 화면 구성이 바뀝니다.`라고 설명한다. |
| 적용 | 값을 선택한 뒤 `적용`을 누르면 방향과 배치를 변경한다. 바꾸지 않고 닫으면 기존 방향을 유지한다. |
| 적용 후 위치 | 전환된 방향의 동일한 설정 화면을 보여 주고, 닫으면 진입 전 화면으로 돌아간다. |
| 저장 | 실제 적용에 성공한 값을 기기에 저장하고 다음 실행에서 복원한다. |

화면 설정의 적용은 화면 방향만 저장한다. 사냥 칙령의 미저장 초안, 장비 선택, 반복 정책 등을 함께 저장하거나 적용하지 않는다. 기존 편집 화면에서 설정으로 이동하는 과정에 미저장 이탈 확인이 필요하다면 해당 화면의 규칙을 따른다. **방향 전환 자체는 편집 화면 이탈이나 저장 동작으로 취급하지 않는다.**

### 5.2. PC 표시 방식

PC는 모바일 가로 구성을 기본으로 사용한다. 설정의 같은 위치에는 `가로 구성 · 창 크기에 맞춤`을 안내하는 안으로 정리한다. 모바일용 가로·세로 선택으로 PC 창이나 모니터의 표시 방향을 강제 변경하지 않는다.

창 크기·최대화·기존 전체 화면 상태가 바뀌면 사용 가능한 영역에 맞춰 다시 배치한다. PC 전용 해상도 목록, 전체 화면 옵션의 신규 개발, 사용자가 직접 패널을 배치하는 기능은 이번 기획의 필수 범위에 포함하지 않는다.

### 5.3. 저장·복귀·실패 처리

- 방향 선호는 영웅별 빌드나 사냥 칙령 프리셋이 아닌 **기기별 표시 설정**으로 관리한다. 공유 코드와 계정 교차 저장으로 다른 기기의 화면 방향을 덮어쓰지 않는다.
- 저장값이 없는 모바일은 제안한 초기 세로 방향을 사용한다. PC는 모바일 저장값 유무와 무관하게 가로 공통 구성을 사용한다. 기존 저장에 새 필드가 없다고 오류로 처리하지 않는다.
- 앱을 다시 열거나 백그라운드에서 복귀하면 저장한 선호와 현재 실제 표시 영역을 확인해 안전 영역과 배치를 다시 계산한다.
- 운영체제나 창 환경의 제약으로 요청한 방향을 적용하지 못하면 실제 방향에 맞는 UI를 유지하고 적용 실패를 안내한다. 적용되지 않은 값을 현재 방향으로 표시하거나 성공한 설정으로 저장하지 않는다.
- 적용은 성공했지만 설정 저장에 실패하면 현재 방향과 저장 실패를 안내한다. 이전 저장값을 보존하고 재시도를 제공하며, 다음 실행에도 유지된다고 표시하지 않는다.

## 6. 방향 전환과 리사이징 중 상태 보존

| 상황 | 보존할 내용과 처리 |
|---|---|
| 일반 화면 | 현재 화면·탭·선택한 영웅·아이템·스킬·필터·정렬을 유지한다. 목록은 선택한 항목 또는 읽던 항목을 기준으로 위치를 복원한다. |
| 편집 중 | 미저장 입력·접힌 항목·현재 편집 대상을 유지한다. 화면을 다시 배치했다는 이유로 초안을 저장·되돌리기·초기화하지 않는다. |
| 대화창·확인창 | 열린 창과 확인 대상·예상 비용을 유지한다. 전환 시 발생한 터치 해제가 뒤쪽 버튼의 실행으로 이어지지 않게 한다. |
| 글자 입력 중 | 입력한 문자열을 보존한다. 키보드와 안전 영역을 다시 반영해 입력 위치와 완료·닫기 버튼에 접근할 수 있게 한다. |
| 전투·훈련 중 | 방향 전환만으로 HP·자원·쿨타임·효과·시드·보상·누적 결과를 바꾸지 않는다. 화면 설정을 연 동안은 일시정지하고 닫을 때 진입 전 실행·정지 상태를 복원하는 안을 적용한다. |
| 다른 이유로 일시정지 중 | 칙령 편집·도움말 등 기존 정지 사유를 유지한다. 화면 설정을 닫았다는 이유만으로 전투를 재개하지 않는다. |
| PC 창 크기 변경 | 표시 영역을 재배치한다. 크기 변경 자체는 사용자의 일시정지·재개 명령으로 취급하지 않는다. |
| 결과·자동 반복 대기 | 설정이나 결과 상세를 연 동안에는 다음 판 대기를 멈춘다. 닫으면 기존 반복 상태와 남은 대기시간을 복원하고 임의로 새 판을 시작하지 않는다. |
| 연속 전환·앱 복귀 | 마지막으로 성공한 적용 결과와 실제 표시 영역을 기준으로 정리한다. 중간 요청이 늦게 끝났다고 이전 방향으로 되돌아가지 않는다. 앱 복귀의 기존 전투·저장 규칙도 유지한다. |

방향 전환과 창 크기 변경에 따라 저장·구매·판매·분해·진입·보상 수령 등의 실행이 중복되지 않아야 한다. 레이아웃을 다시 만드는 처리는 실제 게임 명령과 분리한다.

## 7. 비율과 크기의 검토 기준

아래 값은 **UI 시안·검증용 대표 예시**이며 지원 기기 목록이나 고정 렌더링 해상도를 확정한 값이 아니다. 안전 영역을 제외한 실제 표시 공간, 글자 크기, 화면 밀도까지 함께 확인한다.

| 환경 | 대표 비율·표시 크기 예시 | 중점 확인 |
|---|---|---|
| 모바일 세로 | 9:16의 720×1280, 9:19.5의 1080×2340, 9:20의 1080×2400을 사용한다. | 좁은 폭의 조건문·장비 비교·하단 버튼과 긴 화면의 여백을 확인한다. |
| 모바일 가로 | 16:9의 1280×720, 19.5:9의 2340×1080, 20:9의 2400×1080을 사용한다. | 짧은 높이의 본문·팝업·키보드와 좌우 안전 영역을 확인한다. |
| PC 일반·확장 | 16:9의 1280×720·1920×1080, 16:10의 1920×1200, 3440×1440의 와이드 창을 사용한다. | 목록·상세의 확장, 긴 문장의 최대 폭, 카메라 구도와 여백을 확인한다. |
| 경계 사례 | 4:3·3:4·정사각형에 가까운 영역과 패널이 접히는 전후의 PC 창 크기를 사용한다. | 플랫폼 이름이나 비율 하나로 배치를 고정하지 않는지 확인한다. 이 검토만으로 태블릿·폴더블 지원 완료를 선언하지 않는다. |

글자·버튼·패널의 최소 크기와 PC 최소 창 크기는 개발 시 시안으로 정하고 실제 입력으로 검증한다. 최소 크기보다 공간이 작아지는 경우에는 핵심 동작에 접근할 수 있는 축약 구성을 우선하며, 지원 한계가 필요하면 그 기준과 안내를 명시한다. 레터박스를 기본 대응책으로 삼지 않는다.

## 8. 개발 인계 순서

1. 현재 UI의 고정 폭·높이, 스크롤, 팝업, 안전 영역, 카메라와 화면 상태 보존 경계를 확인한다. 현재 `GameUI`에는 720×1280 기준 확대·축소와 초기 안전 영역 적용이 있으므로, 이것만으로 가로·PC 대응이 끝났다고 판단하지 않는다.
2. 모바일 세로와 가로의 공통 배치 규칙을 먼저 정하고, PC는 가로 규칙의 확장으로 연결한다. 세 가지 환경에서 별도의 게임 데이터나 기능 구현을 복제하지 않는다.
3. 읽기 전용 화면으로 배치 변경을 확인한 뒤 화면 방향 설정·기기별 저장·전환 상태 보존을 연결한다.
4. 사냥 칙령·장비 비교처럼 복잡한 관리 화면, 전투 HUD와 결과·훈련 화면에 순서대로 적용한다. 진행 중인 다른 UI 작업에도 같은 기준을 전달한다.
5. 각 화면의 세 가지 환경 시안, 작은 화면의 처리, 상태 보존 결과를 함께 확인한다. 자동 검사와 실제 PC·모바일 실행 결과를 구분해 개발 기록에 남긴다.

현재 구조의 상세 구현은 개발 작업에서 다시 확인한다. 이 문서는 특정 UI 프레임워크로의 전면 교체, 전투 로직 변경, 별도 PC 전용 화면 시스템의 신설을 요구하지 않는다.

| SCR-07 | 실제 표시 환경 | 대표 비율과 패널 전환 경계를 확인하고, PC 실제 창 조절과 모바일 실기기 가로·세로·터치·키보드·복귀 결과를 남긴다. |
| SCR-08 | 실패와 중복 실행 | 방향 적용 실패·설정 저장 실패·연속 전환·구형 저장에서 사용 가능한 화면과 기존 값을 유지한다. 게임 명령과 보상이 중복 실행되지 않는다. |

완료 보고에는 환경별 화면 증거와 실제로 검사한 범위를 기록한다. 에디터의 화면 크기 미리보기만으로 모바일 방향 전환·물리 터치·운영체제 복귀까지 검증했다고 표시하지 않는다. 현재는 이 문서의 기획과 인계 기준만 마련한 상태다.
