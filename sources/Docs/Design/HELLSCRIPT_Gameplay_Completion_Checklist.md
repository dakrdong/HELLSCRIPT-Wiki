# HELLSCRIPT 플레이 완성도 상세 기획과 개발 완료 기준

갱신일: 2026-09-13

작성일: 2026-09-08 · 버전: v1.2 상세안 · 상태: 후속 개발을 위한 상세 시험안

**2026-09-09 추가 기획:** [사냥 칙령 상세안](HELLSCRIPT_Hunt_Edict_Detail.md)의 명시적 저장·공유 코드·프리셋 5칸·미장착 스킬 설정 보존·전투 중 스킬 교체 기준을 함께 적용합니다. 아래의 기존 3칸·전투 중 장착 잠금에 관한 기준은 이 추가 요구의 범위에서 대체됩니다. 실제 구현·검증 완료 기록은 아닙니다.

**2026-09-09 화면 대응 추가 기획:** 화면 검사는 모바일 가로·세로와 PC를 함께 대상으로 합니다. 설정의 방향 선택과 PC의 가로 구성 확장, 전환 중 상태 보존은 [화면 비율·방향 대응 상세안](HELLSCRIPT_Screen_Layout_Detail.md)의 SCR-01~SCR-08을 함께 적용합니다. 아래의 기존 세로 화면 검사 기록만으로 새 지원 범위를 완료한 것으로 보지 않습니다.

이 문서는 [상위 구현 기획서 v1.2](HELLSCRIPT_Unity_Implementation_Plan.md), [콘텐츠 카탈로그](HELLSCRIPT_Content_Catalog.md), [첫 플레이 빌드 현황](../Implementation/Playable_Build.md)과 현재 소스를 읽어 보완한 **읽기 전용 구현 점검 결과**다. 이번 점검에서는 게임을 실행하거나 테스트를 다시 돌리지 않았으며, 아래의 완료 기준은 앞으로 통과해야 할 기준이다. 기존 빌드의 검증 기록을 이 문서의 신규 항목까지 통과했다는 근거로 사용하지 않는다.

전체 개발 순서는 [후속 개발 기획](HELLSCRIPT_Development_Expansion_Plan.md)을 따른다. 장비의 직업·빌드별 구성, 접두사·접미사 추첨, 전설·세트의 상세 설계는 [장비 상세 명세](HELLSCRIPT_Itemization_Detail.md), 무작위 균열·보물 상자는 [균열·탐험 상세 명세](HELLSCRIPT_Rift_Exploration_Detail.md)를 따른다. 이 문서는 그 콘텐츠가 **이해하기 쉬운 자동 행동, 성장, 적의 대응 패턴, 결과 분석, 안정적인 반복 플레이**로 이어지기 위해 필요한 연결 규칙을 정리한다.

이후 동작 실행·투사체·덫·전투 중 편집 보호의 구현과 검증은 [전투 동작 개발 기록](../Implementation/Action_Expansion.md)에, 22조건·OR/AND 편집·규칙별 목표·판단 기록은 [행동 규칙 개발 기록](../Implementation/Rule_Expansion.md)에 정리했다. 아래 ‘기존 구현’ 열은 기획 착수 당시의 점검 결과이며 최신 구현 상태는 개발 기록과 소스를 따른다.

현재 이어서 만들 기능의 구체적인 흐름·예외·완료 기준은 [남은 개발 작업표](HELLSCRIPT_Remaining_Development_Backlog.md)에서 확인한다. D3의 실제 장비 구성과 생성 균열 비교, 경로·서리 장판 추천 규칙 보완은 [빌드 통합 개발 기록](../Implementation/Build_Integration_Expansion.md)에 이어서 기록한다.

## 1. 범위와 판정 방법

기존 확정 방향인 3직업, 액티브 6개 중 4개, 패시브 6개 중 3개, 레벨 30, 추천 빌드 6개, 저장 슬롯 3개, 조건 22종, 훈련장 3종, 최근 균열 10회 기록을 유지한다. 인터넷 연결 요구와 캐릭터별 초회 보상도 유지한다. 배속은 2026-09-09 변경에 따라 현재 1배속만 제공하고 1.5배속·2배속을 잠근다. 향후 월 구독의 1.5배속과 이벤트의 누적 시간 사용권은 [배속 잠금·사용권 정책](HELLSCRIPT_Speed_Access_Detail.md)을 따른다. 초기 가방·창고 판매와 향후 BM 도입을 구분하며, 세 배속의 내부 전투·성능 검사는 유지한다. PvP, 거래, 랭킹, 시즌, 길드, 펫·용병, 자동 장비 교체·강화와 캠페인은 추가하지 않는다.

| 표시 | 이 문서에서의 의미 |
|---|---|
| 기존 확정 | 상위 기획서에서 사용자 결정으로 기록한 범위다. |
| 기존 시험안 | 상위 기획서와 카탈로그에 이미 있는 해금 레벨·피해·시간·경제 값이다. 구현의 시작 기준이며 밸런스 통과를 뜻하지 않는다. |
| 신규 시험안 | 빈 처리 규칙이나 검증 조건을 이번에 구체화한 제안이다. 사용자 정책 확정으로 표시하지 않는다. |
| 부분 구현 | 관련 기능의 틀은 소스에 있지만 명세 전체가 구현됐다는 증거는 없다. |
| 후속 구현 | 해당 데이터·화면·서비스 계약을 추가해야 한다. |

우선순위는 기존 개발 단계와 별개로 다음 의미를 가진다. **A는 다음 플레이 확장에 앞서 정할 기반**, **B는 전체 콘텐츠를 플레이할 때 필요한 기능**, **C는 공개 전 필수 검증**이다. C는 선택 기능이나 공개 후로 미룰 기능이라는 뜻이 아니다. 일정이나 인원은 이 표만으로 약속하지 않는다.

이 문서의 `CHK-` 접두사는 개발 체크리스트 작업 ID다. 접두사 없는 W01·A01·M01·G01 등 콘텐츠 ID와 구분하며 아이템·스킬 정의 ID로 사용하지 않는다.

현재 구현 판단은 `Runtime/Core/GameCatalog.cs`, `CombatSimulation.cs`, `GameStore.cs`, `Runtime/Presentation/GameController.cs`, `GameUI.cs`와 `Tests/Editor/CoreTests.cs`를 좁게 읽은 결과다. 장비·맵의 내부 수치 검토는 별도 담당 범위다.

## 2. 첫 15분과 여섯 빌드의 성장

### 2.1 첫 15분의 경험 목표

단계별 안내·숨기기·재열람과 실제 진행 기록은 [첫 플레이 상세안](HELLSCRIPT_First_Play_Detail.md), 구현·검증은 [첫 플레이 개발 기록](../Implementation/First_Play_Expansion.md)을 따른다. 자동으로 수행한 흐름 검사는 아래의 신규 사용자 이해도 관찰과 구분한다.

다음은 **신규 사용성 시험안**이다. 플레이어에게 정해진 분 단위 대기나 강제 실패를 요구하지 않는다. 처음 시작한 계정으로 실제 소요 시간을 기록해 조정하며, 타이머를 맞추기 위해 경험치나 확정 장비를 몰래 지급하지 않는다.

| 대략적인 구간 | 플레이어가 하는 일 | 화면과 자동 행동이 알려 줄 내용 | 완료 판정 |
|---|---|---|---|
| 0–2분 | 직업을 고르고 성소에 들어간다. | 직업당 두 빌드의 목표를 한 문장으로 보여 준다. 완성 요구 레벨과 현재 사용 가능한 행동을 구분한다. 기본 무기와 잠긴 스킬을 확인할 수 있다. | 직접 이동·공격을 조작하지 않는 게임이라는 사실과 행동 설정의 위치를 설명할 수 있다. |
| 2–5분 | 1단계 균열에 진입해 첫 전투를 본다. | 현재 행동과 가장 중요한 판단 이유를 표시한다. 첫 스킬 사용 시 해당 규칙 카드로 이어지는 안내를 한 번 제공한다. | 영웅이 왜 공격·기본 공격·이동 중 하나를 했는지 한 사례를 설명할 수 있다. |
| 5–8분 | 보스 처치 또는 실패 결과를 확인한다. | 이미 주운 물건은 유지된다는 점, 실패 원인, 다음 해금까지의 진행을 보여 준다. 결과를 읽는 동안 자동 반복은 기본적으로 꺼져 있다. | 실패를 저장 손실로 오해하지 않고 장비 또는 행동을 한 가지 바꿀 수 있다. |
| 8–11분 | 장비를 비교하고 행동 조건 하나를 수정한다. | 공격력 수치 외에 사거리·생존·자원·세트 효과의 변화를 함께 표시한다. 수정 전후 조건을 자연어로 비교한다. | 바뀐 내용과 기대하는 행동을 플레이어가 설명할 수 있다. |
| 11–13분 | 훈련장에서 수정한 조건을 확인한다. | 실제 영웅 복사본으로 실행하고 자원·성장에 영향을 주지 않는다고 표시한다. 조건 충족·실행 불가 이유를 확인할 수 있다. | 조건을 바꾸기 전후에 행동이 달라지는 사례를 한 번 확인한다. 수치 향상을 보장하지 않는다. |
| 13–15분 | 다시 균열에 들어가거나 반복 정책을 저장한다. | 성공 시·실패 시 행동, 가방 부족 처리, 반복 중단 조건을 한 화면에서 요약한다. | 사용자가 다음 판에서 무엇이 자동으로 일어나는지 확인한 뒤 반복을 시작할 수 있다. |

안내는 단계별 완료 플래그를 영웅 또는 계정에 적절히 저장한다. 직업 선택·설정 안내는 계정 공통, 새 직업의 고유 스킬 안내는 영웅별로 관리하는 시험안이다. 안내를 건너뛰어도 서비스나 보상을 잠그지 않으며 도움말에서 다시 볼 수 있다. 첫 15분에 완성 빌드나 세트 획득을 보장하지 않는다.

### 2.2 빌드 성장표

현재 레벨 추천안과 레벨업의 처리 시점·HP 비율은 [성장 상세안](HELLSCRIPT_Growth_Detail.md), 구현·검증은 [성장 개발 기록](../Implementation/Growth_Expansion.md)을 따른다. 아래 성장 경험 목표와 모든 신규 사용자 검증을 완료했다는 의미는 아니다.

액티브 해금 레벨 1/3/6/10/15/20, 패시브 6개를 레벨 1부터 선택하고 슬롯 3개를 제공하는 규칙은 상위 기획서 16.1의 **기존 시험안**이다. 추천 빌드를 저레벨에 불러오면 잠긴 액티브 규칙은 비활성화하고, 기본 공격·탐색을 유지한다. 아래의 성장 설명은 그 규칙을 플레이어에게 보여 주기 위한 신규 시험안이다.

## 3. 완전 자동 행동 편집기

### 3.1 규칙 표현 계약

기존 **조건 22종**을 유지한다. 스킬의 사거리·CD·자원·장착·해금·행동 상태는 자동 실행 가능성 검사이며, 모든 규칙에서 같은 방식으로 적용한다. 이것을 조건 카드에 중복 입력하도록 요구하지 않는다. 반대로 ‘적 2명 이상’을 ‘보스가 있으면 항상 참’으로 몰래 바꾸지 않는다. 보스 대응이 필요하면 `SC07` 또는 `SC12`를 별도 OR 묶음으로 작성한다.

**규칙 수의 신규 해석 시험안:** 서로 다른 장착 액티브는 4개, 액티브별 규칙은 3개이므로 액티브 규칙은 최대 12개다. 상위 문서의 전체 활성 규칙 24개는 기본 공격·획득·상자·탐색 등 비스킬 주 행동 규칙을 포함한 상한으로 해석한다. 물약은 독립 회복 채널 1개로 두고 주 행동 상한에 넣지 않는다. 비스킬 행동을 추가해도 코드·노드 입력이나 임의 중첩은 제공하지 않는다. 이 해석은 상위 문서 v1.2의 4.2절에도 반영했으며 실제 구현과 검증은 후속 작업이다.

규칙 하나는 **OR 최대 2묶음, 묶음마다 AND 최대 3조건**이다. 빈 규칙은 저장 오류로 표시한다. 사용자가 명시적으로 선택한 ‘항상 검사’는 별도 표시 값으로 보존하되, 대상이 필요한 행동에 유효 대상이 없으면 실행하지 않는다. 잠금 스킬이나 소유하지 않은 장비 전용 선택지가 남은 프리셋은 삭제하지 않고 비활성 이유를 표시한다.

## 4. 전투 판정과 적 콘텐츠

### 4.1 효과의 공통 계약

패시브의 후속 발동·시간·저장 기준은 [패시브 상세 시험안](HELLSCRIPT_Passive_Combat_Detail.md), 실제 구현·검증 범위는 [패시브 개발 기록](../Implementation/Passive_Expansion.md)을 따른다. 아래 최초 완료 기준과 이후 단계별 통과 증거를 구분한다.

2026-09-09의 공통 피해 계산·원천별 보호막·중독 출처·보스 제압 구현은 [전투 효과 통합 기록](../Implementation/Effect_Expansion.md)에 정리했다. 아래 표는 최초 공백과 전체 완료 조건을 보존한다. 일부 공통 효과의 검사 통과를 CHK-C01~C06 전체 완료로 해석하지 않는다.

같은 날 추가한 세트 충전 예약, 절제의 수명, 절약된 집중의 보행·비용 감소, 출발 시 덫 생성과 저장 호환은 [충전·비용 효과 개발 기록](../Implementation/Charge_Expansion.md)에서 확인한다. 자동 검사 197개와 macOS의 실제 프로세스 재시작 검사를 통과한 범위이며, 아래 CHK-C04와 CHK-S02의 모든 효과·중단 구간이 완료됐다는 뜻은 아니다.

상위 기획서 6.2와 16.2의 피해 합산·독립 배율, 보호막 상한, 비용 감소 50%, 보스 제압 게이지, 전염의 비재귀 규칙을 유지한다. 모든 효과는 `효과 정의 ID / 발생 ID / 원 공격 ID / 시전자 ID / 대상 ID / 생성 전투 틱 / 남은 시간 / 다음 틱 / 능력치 스냅샷 / 재발동 금지·내부 CD` 중 자신에게 필요한 필드를 명시한다. 특정 전설의 규칙은 장비 명세가 소유하고, 전투 시스템은 그 규칙을 실행한다.

### 8.2 단계별 구현에 앞서 준비할 하위 검사

전체 순서와 최신 통과 기준은 [후속 개발 기획](HELLSCRIPT_Development_Expansion_Plan.md)의 D1–D6를 따른다. 아래는 각 단계에 연결할 플레이 완성도 검사다.

1. **D1 장비 검증부터 자료 계약을 맞춘다.** 한 빌드의 장비 획득·비교·효과·보상·저장 연결을 먼저 검증한다. 이때부터 규칙, 행동 상태, 효과 출처, 서버 권한과 보상 영수증의 ID·필드를 함께 정한다. 기획서와 카탈로그의 버전을 함께 기록한다.
2. **D2 무작위 균열과 상자를 연결한다.** 한 빌드로 지형·탐색·적·상자·보상·중단 복원의 연결을 검증한다. 이때 필요한 행동·로그 기반을 우선 보완하되 전체 조건 22종이나 3직업을 완료했다고 표시하지 않는다.
3. **D3 전체 전투 콘텐츠와 행동 편집기를 완성한다.** 18액티브·18패시브·22조건·6프리셋·12일반 적·6정예·3보스의 정의 참조와 개별 사례를 검사한다.
4. **D4 성장·마을·사용 흐름을 다듬는다.** 해금·비교·프리셋 보호·결과 분석·첫 15분·반복 중단을 완성하고 실제 사용자 관찰로 불명확한 지점을 수정한다.
5. **D5 온라인과 보석을 연결한다.** 서버·결제·교차 저장과 보석 자료 검증을 완료한다. 공개 후로 미룰 항목으로 취급하지 않는다.
6. **D6 기기·아트·공개 기준을 통과한다.** Android 성능·접근성·장애 복원, 시각·음향·출시 검증을 마친다. 위험 예고와 핵심 가독성은 D3부터 각 패턴과 함께 확인한다.

### 8.3 지금 소유자에게 다시 물어야 하는가

이 문서 범위에는 **기존 결정을 다시 확인해야 개발할 수 있는 정책 질문이 없다.** 위 신규 수치와 세부 동작은 시험안으로 두고 플레이 검증에서 조정한다. 아래 선택은 해당 작업에 들어가기 직전에 구체적인 후보와 근거를 준비해 확인한다.

| 선택 시점 | 확인할 내용 | 현재의 권고 |
|---|---|---|
| 온라인 서비스 연결 전 | 처음부터 사용할 로그인 방식과 공급자, 복구 방식, 예상 사용자 규모·운영 예산을 선택한다. | 공급자 비교와 실제 비용·지원 범위를 조사한 다음 하나의 구체적인 서비스 구성을 제시한다. 이미 승인한 온라인 요구 자체를 다시 묻지 않는다. |
| Android 실기기 검증 전 | 사용자가 우선 체험할 Android 기종과 최소 사양 목표를 정한다. | 실제 이용할 기기 한 대와 비교용 중간 사양 기기 한 대를 기준으로 측정한다. 기기가 확인되기 전 성능을 보장하지 않는다. |

장비·세트 수량이나 무작위 균열·상자 정책에서 기존 범위를 바꾸는 제품 선택이 생기면 각 담당 명세가 그 차이를 정리한다. 이 체크리스트에 같은 질문을 중복 추가하지 않는다.
