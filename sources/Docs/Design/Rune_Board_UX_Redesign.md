# 룬 보드 시안 재구성 — 공통 UI와 블럭 디자인

갱신일: 2026-10-01 · [English](Rune_Board_UX_Redesign.en.md) · [시안 열기](../../Prototypes/RuneBoard/HELLSCRIPT-RuneBoard.html) · [시안 README](../../Prototypes/RuneBoard/README.md)

## 요청과 범위

승인된 룬 보드 v13 HTML 시안([원본 패키지](RuneV13/reference-v13.zip))을 게임의 공통 UI로 다시 구성하고, 블럭이 한눈에 알아보이도록 상태별 디자인을 새로 만든다. 이미지는 직접 그리지 않고 Codex에 요청해 받았다. 게임 코드는 바꾸지 않았다. 바뀐 것은 HTML 시안의 화면 구성과 조작이다.

**규칙과 데이터는 v13 그대로다.** 규칙 엔진(`Prototypes/RuneBoard/vendor/engine.js`)과 튜토리얼 모델은 원본 패키지의 스크립트와 바이트가 같고, 보드·능력 데이터는 게임의 `Resources/Runes/V13/catalog.json`을 읽는다. 이 카탈로그가 패키지에 들어 있던 데이터와 같다는 것도 검사한다.

## 블럭과 칸의 상태

한 상태는 색 외에 면의 밝기·문양의 밝고 어두움·테두리 중 둘 이상으로 구분된다.

| 상태 | 모양 | 색 외 신호 |
| --- | --- | --- |
| 보관 중 | 보석 슬랩, 보관함 타일, ×개수 | 타일 안 칸 수, 색 문양(검·물방울·방패·발톱·별) |
| 선택됨 | 금색 테두리와 빛 | 선택 정보 카드, 초록 기준 점 |
| 배치 미리보기 | 점선 윤곽, 반투명, 칸별 켜짐/꺼짐 | “배치 가능 · N/M칸 켜짐” 문구 |
| 놓을 수 없음 | 붉은 점선, 어두운 면 | 사유 문구와 선택 정보의 붉은 태그 |
| 능력 켜짐 | 밝은 면, 빛나는 흰 문양. 노랑·금·엘리트·시작 돌처럼 밝은 면은 문양에 진한 외곽선 | 효과 칩의 숫자 증가 |
| 능력 꺼짐 · 통로 | 블럭 색이 어둡게 가라앉은 면(검게 덮지 않음), 칸마다 블럭 색 테두리, 음각 문양 | “꺼짐 N칸” 태그, 설명 문장 |
| 열린 빈 칸 | 청동 소켓, 요구 색 고리, 문양 | 문양 색 |
| 놓을 수 있는 자리 | 초록 점(+금색 테두리) | 점이 있는 칸만 허용 |
| 지금 열 수 있음 | 금색 점선 고리 | 슬롯 포인트가 있을 때만 |
| 미개방 | 회백색 석판, 희미한 문양 | 점선 고리 없음 |
| 영역 잠김 | 어두운 석판, 거의 보이지 않는 문양 | 영역 자물쇠 |

그리는 코드는 `Prototypes/RuneBoard/blocks.js` 한 곳에 있고 보드·보관함·선택 정보·끌고 있는 블럭·튜토리얼·상태 안내가 모두 이 함수를 쓴다.

## 사용 확인 후 고친 점 (2026-10-01)

1. **노란 블럭의 켜진 문양이 안 보임.** 흰 문양에 밝은 빛 번짐을 더했는데 노랑·금·엘리트(진주)·시작 돌은 면 자체가 밝아 문양이 묻혔다. 밝은 면에서는 빛 번짐을 빼고 문양에 진한 외곽선을 둘러 어떤 면 위에서도 읽히게 했다. 어두운 면(빨강·파랑·보라)은 그대로 흰 문양 + 빛 번짐이다.
2. **꺼진 칸이 빈 소켓처럼 보임.** 면 위에 검정을 50% 덮고 검은 빗금을 깔아 블럭 색이 사라졌다. 이제 검게 덮지 않고 면의 채도(55%)와 밝기(58%)만 낮추되 어두운 부분이 검정으로 뭉치지 않게 조금 들어 올리고, 칸마다 블럭 색 테두리를 두르고, 블럭 전체 윤곽에도 블럭 색 띠와 더 굵은 검은 외곽선(1.5 → 2)을 더했다. 빈 소켓(검은 바닥 + 청동 테두리)과 한눈에 구분된다.
3. **칸 정보 카드가 보드를 너무 많이 차지함.** 능력 값은 이름 아래 줄에, 요구 색·출처 태그와 “능력 켜짐” 문장은 그 아래에 따로 있었다. 값을 이름 줄로 올려 “공격력 +0.8”로 쓰고, 요구 색 태그(“공격 블럭 필요”), 출처 태그(“기존 룬 효과”), 정상 상태 문장(“능력 켜짐”·“열린 빈 칸”)을 없앴다. 요구 색은 위치 줄 앞의 작은 문양 아이콘으로 남기고, 꺼짐·미개방·영역 잠김·연결 오류만 위치 줄 끝에 한 줄로 적는다(예: “꺼짐 · 블럭 마법 ≠ 칸 치명타”). 세로 화면의 카드는 높이를 고정한 한 줄형(그림 | 이름·위치 | 버튼)이고 머리글 “03 칸 정보”는 숨겼다. 같은 화면 크기에서 카드 높이와 보드 높이(px):

| 화면 | 카드 전 → 후 | 보드 전 → 후 |
| --- | --- | --- |
| 416×881 | 152 → 92 | 232 → 291 (+25%) |
| 440×956 | 161 → 97 | 270 → 332 (+23%) |
| 360×780 | 132 → 79 | 217 → 268 (+24%) |

4. **빗금이 문양을 가림.** 꺼진 칸에 깐 빗금이 음각 문양 위에 겹쳐 문양이 오히려 잘 안 읽혔다. 빗금을 없애고 면을 어둡게만 했다. 꺼진 칸은 이제 어두운 면 + 칸마다 블럭 색 테두리 + 밝은 테두리선이 붙은 음각 문양이고, 문양 위에는 아무것도 겹치지 않는다. 블럭 색 테두리가 남아 있어 “채워진 칸”임은 계속 알 수 있다.

이 네 가지는 회귀 검사로 고정했다. 화면 픽셀을 재서 꺼진 칸이 빈 소켓처럼 검지 않은지(거의 검은 픽셀 비율 30% 이하, 채도 0.4 이상), 노랑·금 면의 켜진 문양에 흰 선과 어두운 외곽선이 모두 있는지 보고, 꺼진 칸 위에 빗금이 그려지지 않는지, 칸 카드에 태그 줄과 상태 문장이 없고 높이가 선택에 따라 변하지 않는지 본다. 각 검사는 해당 수정 전의 빌드로 돌리면 실패한다.

## 입력 규칙 (그대로 유지)

보드에 놓인 블럭은 0.1초 안에 끌면 보드가 움직이고 0.1초 이상 누른 뒤 끌면 블럭이 움직인다. 보관함은 터치에서 0.3초 눌러야 끌린다. 손 떨림 5픽셀은 끌기로 보지 않는다. 회전은 60° 6방향, 실행 취소는 50번이다. R·Delete·Ctrl+Z·Ctrl+S·Esc를 지원한다. 새로 더한 것은 마우스 올림 미리보기, 놓을 자리 점, 보관함 묶음 표시, 블럭 선택 시 자동 편집 전환이다. 보기 모드에서 보관함 블럭을 누르면 편집 모드로 바뀐다.

## 이미지 (Codex)

블럭 면과 바닥은 후처리에서 불투명 영역으로 잘라 정확한 육각형(가로 2R × 세로 √3R)에 맞추고 같은 육각형 마스크를 씌운다. 이웃한 칸의 가장자리가 직선으로 맞물리게 하기 위해서다. 배경 제거나 색 변경은 하지 않는다. 문양·아이콘은 흰색 한 가지 모양을 그대로 쓰고 색은 화면에서 입힌다. 탈락한 변형은 해시와 사유만 기록했다.

## 공통 UI 계약과의 관계

창 구조, 색, 글꼴 계층, 버튼·탭·머리글 규칙을 공통 계약에 맞췄다. 육각 보드는 계약이 인정한 특수 배치(“룬 육각 보드”)이므로 보드 영역만 전용 렌더러를 쓰고, 나머지는 공통 부품 규칙을 따른다. 글자 크기 배율은 제공하지 않으며 기본 크기에서만 검사했다. Unity에 옮길 때 기록할 어댑터 사유는 “육각 점유와 연결 규칙 때문에 전용 보드 렌더러가 필요하다”이다.
