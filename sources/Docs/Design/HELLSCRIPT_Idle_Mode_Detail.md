## 1. 목표와 설계 방향

**영웅은 같은 균열에서 실제로 탐색하고 싸운다. 사용자가 보지 않는 동안에는 화면을 만드는 작업을 쉬고, 확인하는 순간 현재 전투를 그대로 보여 준다.**

사용자가 원하는 경험은 ‘나 대신 계속 사냥하는 영웅을 필요할 때 바로 확인하는 것’이다. 방치 여부가 캐릭터의 판단·생존·보상에 영향을 주어서는 안 된다. 공격 중에 방치를 켰다가 다시 보면 이어지는 공격을 보고, 그동안 다른 방으로 이동했다면 그 방에서 실제로 진행 중인 행동을 본다.

‘항상 공격하는 모습으로 복귀’는 목표로 삼지 않는다. 균열 탐색에는 이동·상자 개봉·전리품 회수·다음 판 대기도 있다. 이때는 현재 행동과 이유를 보여 주어 연속성을 설명한다. 사냥 장면을 따로 만들어 붙이거나 복귀 직전에 적을 생성하는 방식은 사용하지 않는다.

### 1.1 기존 정책과의 관계

상위 기준은 [최종 기획서](HELLSCRIPT_Unity_Implementation_Plan.md)의 5장·8장·9.2~9.3·10장이다. 균열 동작은 [균열 상세 기획](HELLSCRIPT_Rift_Exploration_Detail.md), 반복·획득 정책은 [사냥 칙령 전역 옵션](HELLSCRIPT_Hunt_Edict_Global_Options.md), 화면 구성은 [화면 상세 기획](HELLSCRIPT_Screen_Layout_Detail.md)을 함께 따른다.

| 구분 | 이 문서에서 적용할 기준 |
|---|---|
| 기존 확정 | 앱을 켜 둔 방치는 실제 전투 시뮬레이션을 실행한다. 시간만 계산해서 장비를 지급하지 않는다. |
| 기존 계산 원칙 | 이동·공격·회피·획득을 자동으로 처리하고, 이용 권한이 있는 배속을 전투와 제한시간에 동일하게 적용한다. |
| 2026-09-09 사용자 확정 | 현재는 1배속만 제공하고 1.5배속·2배속을 잠근다. 향후 1.5배속은 월 구독, 2배속은 이벤트의 누적 시간 사용권으로 해금한다. |
| 기존 확정 | 실제 처치와 획득으로 보상을 정하며, 실패·가방 부족·포탈 정리 규칙을 유지한다. |
| 기존 확정 | 앱 미실행 보상은 계정 기준 골드·강화석이며, 채택된 누적 상한은 12시간이다. 실제 사냥과 중복 정산하지 않는다. |
| 이번 제안 | 절전 화면, 잠깐 보기, 일반 화면 복귀를 추가하고, 전투 진행과 화면 갱신을 분리한다. |
| 이번 범위 | 모바일의 앱 활성 상태에서 동작하는 절전 방치를 우선 구현한다. PC는 같은 표시 기능을 제공하되 최소화·절전 진입 정책을 별도로 검증한다. |

공개 버전의 온라인 전투·보상 확정 정책을 유지한다. 현재 로컬 저장 기반 개발 빌드에 서버 기능이 이미 구현된 것으로 해석하지 않는다.

배속의 최신 기준은 [배속 잠금·구독·시간 사용권 정책](HELLSCRIPT_Speed_Access_Detail.md)이다. 일반 화면·절전 화면·잠깐 보기에서 같은 권한을 적용한다. 내부 검증용 1.5배속·2배속 계산이 있다는 이유로 잠금을 해제하지 않는다.

## 2. 사용자 경험

### 2.1 진입

전투 화면에 **절전 방치** 버튼을 둔다. 처음에는 ‘현재 균열 사냥을 계속하며 화면 표시를 줄입니다. 화면을 잠그거나 앱을 나가면 사냥을 보존하고 미실행 보상으로 전환합니다.’라는 안내와 현재 반복 정책을 보여 준다. 다음부터는 한 번의 선택으로 진입한다.

반복 정책은 ‘성공 시 같은 단계 / 실패 시 한 단계 하향 / 연속 실패 3회 중단’처럼 저장된 실제 값으로 표시한다. 방치 진입만으로 자동 반복·단계 상승·배속·획득 정책을 바꾸지 않는다. 반복이 꺼져 있으면 ‘이번 균열까지만 진행합니다’를 표시한다.

일시정지·편집·확인창·훈련·가방 정리 중에는 신규 방치 진입을 제공하지 않는다. 정리가 필요한 상태를 먼저 해결하도록 기존 화면을 유지한다. 사용자가 전투를 중단해 둔 상태를 방치 버튼이 임의로 재개해서는 안 된다.

### 2.2 세 가지 표시 상태

다음 수치는 초도 시험값이다. 화면 갱신 빈도와 전투 계산 빈도는 서로 다르다.

| 표시 상태 | 사용자에게 보이는 것 | 진행과 전환 |
|---|---|---|
| 일반 화면 | 기존 전투 화면과 조작 가능한 메뉴를 표시한다. | 기존 화질·프레임 설정을 따른다. 절전 방치 버튼으로 전환한다. |
| 절전 화면 | 검은 바탕에 작은 상태 표시와 확인 안내만 표시한다. 살아 움직이는 배경·미니맵·캐릭터 장식은 사용하지 않는다. | 전투는 계속한다. 요약은 기본 1초마다 갱신하고, 중단 사유와 입력에는 즉시 반응한다. |
| 잠깐 보기 | 현재 균열의 실제 전투와 간단한 HUD를 30 FPS 목표로 보여 준다. | 절전 화면을 한 번 누르면 열린다. 마지막 입력 후 10초가 지나면 절전 화면으로 돌아간다. **계속 보기**를 누르면 일반 화면을 유지한다. |

절전 화면의 기본 정보는 현재 단계, 현재 행동, 방치 후 완료한 균열 수, 마지막 중요 획득 또는 중단 사유다. 상세 합계는 잠깐 보기에서 펼친다. 전체 화면을 매번 새로 배치하지 않고 바뀐 값만 갱신한다. 번인 방지를 위해 작은 표시 영역은 느린 주기로 위치를 바꾸되, 반짝임이나 상시 애니메이션을 넣지 않는다.

예시 문구는 **‘균열 12단계 · 다음 방으로 이동 중 · 7회 완료’**, **‘보스와 전투 중’**, **‘전리품을 회수하는 중’**이다. 실제로 멈췄다면 **‘가방 정리가 필요해 사냥이 멈췄습니다’**라고 표시한다. 숫자와 문구는 현재 전투 상태에서 읽으며 미리 정한 순서로 순환하지 않는다.

잠깐 보기에서 메뉴를 열거나 설정을 수정하면 자동 복귀 타이머를 취소하고 일반 화면으로 전환한다. 기존에 전투를 멈추는 편집·설정창은 그대로 멈춘다. 닫은 뒤에도 일반 화면을 유지한다. 단순히 전투를 바라보는 행위는 전투와 반복 대기를 멈추지 않는다.

### 2.3 버튼의 의미

| 버튼·입력 | 처리 |
|---|---|
| 절전 화면 한 번 누르기 | 입력을 소비한 뒤 잠깐 보기를 연다. 아래의 스킬·메뉴를 동시에 누르지 않는다. |
| 계속 보기 | 일반 화면으로 돌아간다. 사냥·배속·자동 반복은 유지한다. |
| 절전으로 돌아가기 | 다시 화면 표시만 줄인다. 전투를 저장 지점으로 되돌리지 않는다. |
| 다음 판부터 중단 | 이번 판과 획득 처리를 마친 뒤 자동 반복을 끝낸다. |
| 즉시 일시정지 | 일반 화면에서 기존 일시정지 기능을 사용한다. 포기·실패 처리와 구분한다. |

‘방치 해제’와 ‘사냥 중단’을 하나의 버튼 의미로 섞지 않는다. 처음 확인한 화면은 전투를 먼저 보여 주며, 획득 결과 팝업이 시야를 가리지 않게 한다. 요약은 작게 표시하고 사용자가 펼치게 한다.

## 3. 전투 상태와 표시 상태의 분리

절전 화면은 전투 위에 올라가는 별도 표시 상태다. 전투의 진행·정지를 결정하는 공통 팝업이나 `paused` 값으로 구현하지 않는다.

| 실제 전투 상태 | 절전 중 동작 | 확인했을 때 보이는 내용 |
|---|---|---|
| 탐색·이동 | 같은 경로·시야·이동 규칙으로 진행한다. | 실제 위치와 ‘다음 적 탐색 중’ 등 현재 행동을 보여 준다. |
| 일반 전투·보스전 | 기존 판단·충돌·피해·효과를 모두 적용한다. | 현재 공격 단계, 적 HP, 위험 예고와 투사체를 보여 준다. |
| 상자·성소·전리품 회수 | 기존 접근·개봉·획득 시간을 적용한다. | 진행 중인 상호작용과 남은 전리품을 보여 준다. |
| 결과·다음 판 대기 | 결과를 한 번 확정하고 기존 반복 정책을 적용한다. | 실제 성공·실패 결과와 다음 판까지 남은 시간을 보여 준다. |
| 가방 정리·진행 오류 | 해당 이유로 전투 또는 반복을 멈춘다. | 중단 이유와 해결 버튼을 보여 준다. |
| 수동 일시정지·설정·편집 | 기존 정지 조건을 따른다. | 사용자가 열어 둔 화면과 편집 내용을 유지한다. |

현재 5초인 결과 후 반복 대기는 절전 중에도 같은 속도로 진행한다. 일반 화면과 절전 화면의 보상 효율이 달라지지 않도록 방치 전용 즉시 재입장을 만들지 않는다. 잠깐 보기 전환으로 대기를 처음부터 다시 시작하거나 다음 판을 중복 생성하지 않는다.

반복 판단은 ‘결과 화면이 열렸는가’가 아니라 실제 판 종료·정산 완료·가방 처리 완료·반복 허용 상태로 결정한다. 절전 중 새 균열에서는 지도·적·보상 등 게임 진행에 필요한 데이터만 생성하고, 화면 객체는 확인할 때 준비한다.

## 4. 배터리 소모를 줄이는 순서

절전 효과는 GPU, CPU, 디스플레이, 통신, 저장을 함께 측정한다. 화면을 검게 만드는 것만으로 아래에서 계속 실행되는 작업이 사라지지는 않는다.

| 우선순위·대상 | 적용 방법 | 반드시 유지할 내용 |
|---|---|---|
| 1. 전투 화면 렌더링 | 절전 중 전투 카메라, 그림자, 후처리, 조명·반사 갱신, 화면 효과를 중단한다. 절전용 최소 UI만 그린다. | 현재 전투 상태와 확인 입력은 계속 처리한다. |
| 1. 화면 표현 계산 | 캐릭터 보간, 카메라 추적, 장식 애니메이션, 파티클, 피해 숫자, 트레일, 미니맵 갱신을 중단한다. | 피해·이동·충돌·위험 예고의 실제 판정은 전투 데이터에서 계속 처리한다. |
| 1. 효과 생성 | 보이지 않는 타격 효과·소리 객체를 처음부터 생성하지 않는다. 과거 효과를 대기열에 쌓지 않는다. | 실제 투사체·장판·지속 효과는 수명과 판정을 유지한다. |
| 1. 디스플레이·소리 | 앱 화면 밝기를 낮출 수 있는 플랫폼에서는 현재 창에 한정해 적용하고, 절전 중 전투 음원·진동·오디오 처리를 쉰다. | 기기 전체 밝기를 덮어쓰지 않는다. 복귀 시 사용자 설정을 복원한다. OS 설정과 패널에 따른 실제 절전 효과를 따로 측정한다. |
| 2. 반복 검색 | 주변 개체 검색에 공간별 목록을 사용하고, 길 찾기 결과와 변하지 않는 능력치 계산을 재사용한다. | 대상 이동·사망, 지형·위험·효과 변경 등 결과에 영향을 주는 변화가 생기면 즉시 무효화한다. |
| 2. 메모리·로그 | 목록과 표현 객체를 재사용하고, 표시용 문자열을 필요할 때 만든다. 분석은 수치와 구조화된 사건으로 기록한다. | 보상·실패 원인·행동 분석과 기존 최근 10회 상세 기록의 의미를 보존한다. |
| 2. 저장·통신 | 중복 저장과 변하지 않은 데이터 쓰기를 줄이고, 허용된 상태 전송과 부가 통계를 묶는다. | 보상 확정·세션 유효성·중복 지급 방지를 위한 필수 저장과 통신은 지연시키지 않는다. |
| 3. 실행 빈도 | 전투 갱신, 입력 확인, 화면 출력을 분리하고 실제 기기에서 깨우는 빈도를 조정한다. | 선택한 배속의 전투 시간이 실제 경과에 맞게 진행되어야 한다. |

검은 화면의 디스플레이 절전 효과를 모든 패널에서 동일하다고 가정하지 않는다. 밝기를 실제로 낮추지 못하는 환경에서는 렌더링·CPU 절감 결과와 패널 전력 결과를 분리해 보고한다. 화면 자동 꺼짐 방지는 절전 사냥 세션에 필요한 범위로 관리하고, 세션 종료 시 이전 정책을 복원한다. 사용자가 전원 버튼으로 잠그는 동작을 막지 않는다.

### 4.1 계산의 정확도를 유지하는 기준

초기 버전은 현재 전투 간격 0.05초와 행동 판단 간격 0.2초를 유지한다. 1배에서는 실제 1초에 전투 20틱, 2배에서는 40틱을 수행한다. 1.5배도 누적 시간을 보존하여 평균 30틱을 수행하며 모드 전환 때 나머지 시간을 버리지 않는다.

이는 세 배속의 내부 계산·성능 검증 기준이다. 현재 일반 사용자는 1배속만 사용할 수 있으며, 1.5배속·2배속은 향후 해당 권한 도입 전까지 잠금 상태를 유지한다.

절전 화면이 1초에 한 번 바뀌어도 전투 갱신과 입력 처리는 별도로 계속한다. 루프를 낮추기 위한 시험값은 실제 시간 기준 20회/초부터 시작하고, 한 번의 갱신에서 배속에 필요한 고정 틱을 순서대로 실행한다. Unity 전체를 1 FPS로 낮추는 설정과 혼동하지 않는다. 구체적인 렌더링 제어 API는 설치 버전과 모바일 출력 경로에서 확인한 뒤 선택한다.

고정 틱을 여러 개 한꺼번에 실행하는 것만으로 총 계산량이 줄지는 않는다. 반복 검색·화면 표현·메모리 할당의 제거가 우선이다. 별도 스레드는 측정으로 이점이 확인되고 데이터 소유권을 분리할 수 있을 때만 검토한다.

멀리 있는 적은 ‘화면 밖’이라는 이유만으로 계산을 멈추지 않는다. 어그로, 투사체, 오라, 소환, 지속 피해, 상자 이벤트와 연결된 적은 화면 밖에서도 결과에 영향을 줄 수 있다. 상호작용이 없음을 입증한 대상에 한해 다음 사건 시각까지 타이머를 계산하는 최적화를 검토한다. 같은 시각에 발생하는 사건의 순서와 난수 소비 순서를 보존한다.

전투 틱을 거칠게 바꾸거나 평균 DPS로 승패를 추정하는 별도 방치 전투는 이번 방식에 넣지 않는다. 이후 계산 생략을 도입하더라도 아래의 결과 동등성 검사를 통과한 구간에만 적용한다.

### 4.2 느린 기기와 시간 누적

활성 상태의 경과 시간은 단조 증가 시계를 기준으로 누적하고, 처리하지 못한 전투 시간을 조용히 잘라내지 않는다. 렌더링을 건너뛰거나 장식을 더 줄여도 전투 시간과 배속의 관계는 유지한다. 전투의 미래 결과를 미리 계산해 보여 주지도 않는다.

일시적인 지연은 제한된 작업량으로 나누어 따라잡는다. 지속적으로 따라잡지 못하면 ‘기기 상태로 사냥이 일시정지되었습니다’를 표시하고 마지막 처리 틱에서 보존한다. 초기 중단 판단 후보는 미처리 시간이 실제 0.5초를 넘는 상태가 3초 지속되는 경우이며 실기기에서 조정한다. 중단 이후 시간을 전투 시간으로 나중에 몰아서 계산하지 않는다. 앱 중단·수동 정지 구간도 전투 누적에 넣지 않는다.

## 5. 확인 순간의 연속성 계약

### 5.1 화면을 다시 만드는 순서

1. 확인 입력을 받은 틱 경계에서 현재 `runId`와 전투 시각을 포함한 일관된 표시용 상태를 읽는다. 메모리에 있는 실제 전투를 유지하며 이전 디스크 저장을 불러오지 않는다.
2. 현재 균열의 필요한 화면 객체를 준비하고, 영웅·적·카메라를 현재 좌표와 방향에 맞춘다. 예전 위치에서 현재 위치까지 화면 위로 미끄러져 이동시키지 않는다.
3. 진행 중인 공격·도약·채널링은 행동 시작 시각·경과 시간·단계에 맞춰 표시한다. 복귀했다고 동작을 처음부터 다시 재생하지 않는다.
4. 살아 있는 투사체·장판·위험 예고는 현재 위치와 남은 수명으로 표시한다. 끝난 타격 섬광·피해 숫자·사운드는 재생하지 않는다.
5. 화면 준비 중에도 전투는 계속한다. 첫 공개 프레임 직전에 최신 완료 틱으로 한 번 더 맞추고, 준비한 `runId`가 이미 끝났다면 최신 판이나 실제 대기 상태를 보여 준다.
6. 화면을 드러낸 뒤 일반 보간과 프레임 갱신을 시작한다. 준비가 지연되면 실제 상태를 확인 중이라고 짧게 표시한다.

짧은 전환 페이드는 시각적 완충 수단으로만 사용한다. 전투를 새로 시작하거나 계산 지연을 숨기는 수단으로 사용하지 않는다. 초기 목표는 입력 반응 100ms 이내, 실제 장면 표시 p95 300ms 이내다. 기준 기기에서 앱이 실행 중이고 필요한 공통 자산이 메모리에 남아 있는 상태를 대상으로 하며, 앱 재실행 시간과 구분한다.

다음 판의 화면을 한 번도 만들지 않은 상태도 같은 목표로 측정한다. 필요한 지형·캐릭터 공통 자산과 작은 재사용 풀은 유지하되, 모든 판의 화면을 메모리에 쌓지 않는다. 메모리를 과하게 비워 매번 큰 로딩이 생기는 최적화는 피한다.

### 5.2 반드시 보존할 상태

| 범위 | 필요한 정보 |
|---|---|
| 판·시간 | `runId`, 지도 시드·구성, 단계, 전투 시각, 남은 제한시간, 배속, 처리 틱과 남은 부분 시간, 결과 후 남은 대기시간을 보존한다. |
| 영웅 | 위치·방향·이동 경로, HP·보호막·자원, 목표, 행동 ID·단계·경과 시간, 재사용 대기시간·버프·지속 피해를 보존한다. |
| 적·전장 | 개체 ID, 위치·HP·어그로·행동, 투사체·장판·예고·소환과 해당 소유자·남은 수명을 보존한다. |
| 탐색·획득 | 탐색한 영역, 상자·성소 진행, 바닥 장비의 위치·발견·획득·무시 상태, 확정 보상 ID와 가방 상태를 보존한다. |
| 반복·재현 | 빌드·설정 버전, 성공·실패·연속 실패, 중단 사유, `rngState`와 지급 기록을 보존한다. |

표시 객체를 만들 때 전투용 난수를 소비하거나 피해·보상을 다시 발생시키지 않는다. 애니메이션 이벤트에 실제 피해가 매달려 있으면 먼저 분리해야 한다. 절전 전환을 반복해도 회복, 무적, 재사용 대기시간 초기화, 목표 변경, 난수 재추첨이 발생해서는 안 된다.

## 6. 보상·반복·중단 처리

실제 적 처치, 상자 개봉, 보스 처치와 가방 수납 규칙을 그대로 적용한다. 일반 화면과 같은 실클리어·초회 보상 자격을 인정한다. 절전 전용 추가 보상이나 보상 감소는 두지 않는다. 향후 고배속이 해금되면 사용자가 이용 가능한 배속을 선택할 수 있으며, 실제 시간당 사냥량이 달라짐을 표시한다. 절전 진입 자체로 배속을 바꾸지 않는다. 구독·사용 시간 만료에 따른 전환은 배속 정책을 따른다.

향후 **2배속 사용권 1h는 실제 사용 시간 60분을 추가하며, 잔여 30분에 사용하면 90분이 된다.** 차감은 2배속으로 실제 균열 진행이 이루어지는 구간에만 적용하는 안을 권고한다. 절전 화면에서도 사냥 중이면 차감하고, 1배속·1.5배속·일시정지·다음 판 대기·앱 중단에서는 잔액을 보존한다. 잠깐 보기와 일반 화면 복귀는 잔액을 초기화하거나 시간을 추가하지 않는다. 차감·만료·중복 사용 방지의 상세 기준은 [배속 잠금·사용권 정책](HELLSCRIPT_Speed_Access_Detail.md)을 따른다.

| 사건 | 기본 처리 |
|---|---|
| 균열 성공 | 보상을 한 번 확정하고 전리품을 처리한 뒤 저장된 반복 정책을 적용한다. 절전 화면을 유지한다. |
| 사망·시간 초과 | 기존 재시도·단계 하향·중단 정책을 적용한다. 이미 획득한 물건만 유지한다. |
| 가방 부족 | 기존 교체·무시·포탈 정리 정책을 적용한다. 수동 정리가 필요하면 사냥을 보존하고 대기한다. 임의 판매·분해·자동 장착을 추가하지 않는다. |
| 목표·횟수·시간 조건 도달 | 이미 제공되는 반복 중단 정책을 따른다. 판 종료 후 중단 조건과 즉시 정지 조건을 구분한다. 아직 구현되지 않은 사냥 칙령 옵션을 방치 기능에서 먼저 복제하지 않는다. |
| 희귀 획득 | 작은 상태 표시와 확인 후 요약에 반영한다. 사전 설정된 중단 조건이 없다면 계속 사냥한다. |
| 저장·진행·접속 오류 | 확인 가능한 상태와 중단 사유를 보존한다. 저장·보상 확정이 불가능하면 새 균열을 시작하지 않는다. 전경에서 통신이 끊기거나 세션 권한이 불명확하면 진행 중인 전투도 마지막 확정 틱에서 멈춘다. |

전경에서 연결을 기다리는 시간은 앱 미실행 보상에 넣지 않는다. 연결이 복구되면 기존 지급 요청 ID로 확정 결과와 세션 권한을 확인하고 사용자 입력으로 재개한다. 불명확한 보상 요청을 새 ID로 다시 실행하거나 연결 대기 시간을 전투에 몰아서 반영하지 않는다.

반복 종료·가방 정리·접속 문제 발생 시 절전 화면의 문구를 바로 바꾸되 화면 전체를 강제로 밝히지 않는다. 화면 알림을 기본으로 하고 소리·진동은 사용자 설정을 따른다. 중단 원인을 해결했다고 사냥을 자동 재개하지 않고 명시적인 재개 입력을 받는다.

배터리 부족으로 중단하는 선택 항목을 제안한다. 초기 후보는 **10% 이하에서 일시정지**이며, 사용자가 켠 경우에만 적용한다. 충전 여부·배터리 읽기 실패를 구분한다. 운영체제가 심각한 발열 상태를 알리거나 안정적으로 전투를 처리할 수 없으면 상태를 보존하고 중단한다. 이런 중단은 사망·실패·균열 포기로 집계하지 않는다.

## 7. 화면 잠금·앱 전환·종료

**이번 실시간 방치의 보장 범위는 앱이 실행 권한을 유지하며 활성 상태로 켜져 있는 동안이다.** 게임 안의 검은 절전 화면과 기기의 전원 버튼으로 화면을 잠그는 동작은 다르다.

상위 기획의 기존 경계를 유지한다. 앱을 나가거나 잠그면 진행 중 균열을 보존하고, 서버가 인정하는 미실행 구간은 기존 골드·강화석 정산으로 처리한다. 복귀 시 미실행 구간을 실제 균열에서 사냥한 것으로 만들거나 장비·실클리어로 변환하지 않는다.

Android는 화면 꺼짐·앱 전환에 따라 Activity 상태가 달라지고, 보이지 않는 앱의 프로세스를 시스템이 종료할 수 있다. 따라서 클라이언트가 계속 실행된다는 전제로 기능을 약속하지 않는다. 종료 직전 콜백에서만 저장을 시작하지 않고 활성 상태의 체크포인트와 확정 기록을 유지해야 한다. 이는 [Android 공식 활동 수명 주기 문서](https://developer.android.com/guide/components/activities/activity-lifecycle?hl=en)의 실행 상태·프로세스 제거·저장 지침을 바탕으로 한 설계 판단이다. iOS 지원 시에는 해당 플랫폼의 수명 주기와 저장 경로를 별도로 검증한다.

| 상황 | 진행·복귀 정책 |
|---|---|
| 게임 내부 절전 화면 | 실제 균열을 계속 진행한다. 확인하면 지금 진행 중인 상태를 보여 준다. |
| 알림창·포커스 변경 | 해당 OS의 실행 상태를 구분한다. 단순 포커스 변화와 실제 실행 중단을 같은 신호로 단정하지 않는다. |
| 앱 전환·화면 잠금 | 안전한 틱에서 진행을 보존하고 실제 사냥을 중단한다. 같은 구간의 미실행 보상 인정은 계정 정책을 따른다. |
| 다시 활성화 | 마지막 확정 상태를 복원하고 ‘중단된 균열을 이어갑니다’를 표시한다. 미실행 요약과 재개 입력을 제공하며, 이전 절전 화면을 즉시 강제 적용하지 않는다. |
| 강제 종료·배터리 소진 | 마지막 확정 체크포인트로 복구한다. 미확정 진행 손실 범위는 장애 검증 결과로 정하며 무손실을 사전 보장하지 않는다. |
| PC 최소화·기기 절전 | 현재 플랫폼의 계속 실행 허용·중단 이벤트를 검증한 뒤 지원 범위를 정한다. OS가 프로세스를 멈춘 시간은 실시간 사냥으로 세지 않는다. |

미실행 구간의 시작·끝과 지급 ID를 기록해 실제 사냥, 포탈·편집 대기, 다른 기기의 활성 사냥과 겹쳐 지급하지 않는다. 절전 진입·잠깐 보기·일반 화면 복귀는 앱 미실행의 시작이나 끝이 아니다.

화면을 잠그거나 앱을 종료한 뒤에도 같은 균열을 실제로 계속 진행해야 한다는 요구가 추가되면 서버가 전투를 계속 실행하는 별도 설계가 필요하다. 이 경우 서버 비용·세션 인계·기존 미실행 보상 정책까지 바뀌므로 이번 범위에 포함하지 않는다.

## 8. 저장과 장시간 실행

현재 개발 빌드의 3초 주기 저장을 1차 구현에서 유지한다. 배터리 절약을 이유로 저장 간격부터 늘리지 않는다. 저장 비용이 실제 병목으로 확인되면 변경된 데이터만 기록하는 방식과 중요한 사건 기록을 먼저 검토한다.

균열 진입·보상 확정·가방 처리·정상 중단·앱 이탈의 저장 경계를 명확히 한다. 시뮬레이션 체크포인트와 지급 기록을 연결하고, 같은 보상 ID는 다시 추첨·지급하지 않는다. 비동기 저장을 적용할 경우 오래된 저장 완료가 최신 상태를 덮어쓰지 않도록 순서를 보장한다.

장시간 방치의 메모리 사용량은 반복 횟수에 비례해 증가해서는 안 된다. 과거 균열의 표현 객체·타격 효과·임시 목록은 해제하고, 요약 누적값과 기존 보존 범위의 상세 기록만 남긴다. 확인할 때만 문자열과 상세 목록을 구성한다. 보고서에 필요한 원본 사건을 지워 분석 정확도를 낮추지는 않는다.

## 10. 검증 기준

### 10.1 전투 결과가 같은가

동일한 초기 상태·시드·빌드·설정·배속·입력 틱으로 일반 화면과 절전 화면을 실행한다. 같은 전투 틱의 상태와 최종 사건 순서를 비교한다. 화면 객체 ID나 장식용 난수는 비교에서 제외하되 전투 난수·보상 ID는 포함한다.

| 검사 | 통과 기준 |
|---|---|
| 전투·획득 동등성 | 처치·사망·피해·자원·타이머·클리어·가방·보상·전투 난수 상태가 같다. 같은 실행 환경의 결정적 필드는 정확히 일치해야 한다. |
| 세 배속 | 1배·1.5배·2배의 실제 경과 대비 전투 틱이 맞고, 전환 때 부분 시간이 초기화되지 않는다. |
| 배속 권한·사용 시간 | 현재 사용자 경로에서는 고배속이 잠겨 있다. 향후 내부 시험 권한으로 충전·차감·만료·모드 전환을 검증하며, 잔여 30분+1h=90분이 유지된다. |
| 판정 경계 | 같은 틱의 보스 사망·시간 초과, 투사체 명중·적 사망, 지속 효과 만료·피해 판정이 기존 순서를 따른다. |
| 무작위 전환 | 공격 준비·공격·회복·도약·채널링·보스 예고·장판·상자·포탈·결과 대기 등에서 전환을 반복해도 상태가 바뀌지 않는다. 초도 자동 검사 목표는 1,000회다. |
| 화면 첫 프레임 | 현재 위치·행동·적·투사체·위험 예고가 일치한다. 오래된 위치에서 이동하거나 끝난 효과가 몰아서 재생되지 않는다. |
| 반복·예외 | 다음 판 중복 입장, 중복 보상, 실패 횟수 초기화, 가방 정책 변경, 설정창의 정지 해제가 없다. |
| 복귀 조작 | 확인 터치가 아래 메뉴로 전달되지 않고, 편집 중 자동으로 절전 화면에 돌아가지 않는다. |
| 중단·저장 | 앱 전환·잠금·통신 단절·저장 실패·강제 종료 후 복구 범위와 정산 구간이 맞는다. 절전 전환 자체는 미실행 보상을 만들지 않는다. |

동등성 비교는 같은 기기·빌드에서 먼저 수행한다. 플랫폼 간 부동소수점 차이가 있는 경우 허용 오차와 판정의 동일성을 따로 정하고, 수치 오차를 이유로 승패·보상 차이를 허용하지 않는다.

### 10.2 실제 배터리가 줄어드는가

출시 대상에 맞춰 대표 저사양·중간급·고사양 Android 기기를 선정한다. iOS를 지원하면 별도 기기군을 추가한다. 개발 PC와 에뮬레이터의 수치를 휴대폰 배터리 결과로 대신하지 않는다.

동일 빌드·시드 묶음·캐릭터·단계·배속·네트워크·배터리 구간·주변 온도에서 비교하고, 순서를 바꿔 각 조건을 최소 3회 측정한다. 워밍업 후 30분 측정과 2시간 연속 실행을 초도 검증 시간으로 제안한다.

| 비교 조건 | 확인할 목적 |
|---|---|
| 일반 전투 화면 | 같은 배속·사냥량에서 기준 소비 전력과 발열을 측정한다. |
| 일반 화면과 같은 밝기의 절전 화면 | 렌더링·표현 계산을 제거한 효과를 분리한다. |
| 실제 사용 밝기의 절전 화면 | 밝기 정책까지 적용한 전체 절전 효과를 측정한다. |
| 1분마다 10초씩 잠깐 보기 | 사용자가 자주 확인하는 상황에서도 총소모가 줄어드는지 측정한다. |

전체 평균 전력·누적 에너지, 실제 1시간과 균열 1회당 소비량, CPU·GPU 작업 시간, 렌더링 횟수, 메모리·GC, 저장·통신 횟수, 기기 온도·열 제한, 복귀 지연을 기록한다. 배터리 퍼센트 감소만으로 작은 차이를 단정하지 않는다.

**초도 목표안:** 실제 사용 조건에서 절전 화면의 평균 소비 전력을 일반 화면보다 40% 이상 줄인다. 이는 아직 측정하지 않은 개발 목표이며 사용자에게 약속할 수치가 아니다. ‘70~90% 절약’처럼 검증되지 않은 수치를 안내에 쓰지 않는다. 기기별 결과와 자주 확인하는 조건의 결과를 함께 공개용 판단에 사용한다.

2시간 방치에서 메모리·이벤트 대기열이 계속 증가하지 않아야 한다. 복귀 지연은 평균뿐 아니라 p95와 최댓값을 기록한다. 새 균열 첫 표시·보스전·장시간 실행 후 복귀도 포함한다. 성능 목표를 달성하려고 사냥량이나 계산 정확도를 낮추면 실패다.

## 11. 개발 순서와 완료 조건

| 단계 | 작업 | 다음 단계로 넘어갈 근거 |
|---|---|---|
| 1. 표시·진행 분리 | 절전 상태를 추가하고 전투·반복·시계를 화면에서 분리한다. | 일반/절전 전투 동등성과 배속·반복 검사가 통과한다. |
| 2. 정확한 확인 | 잠깐 보기와 일반 복귀, 첫 프레임 동기화, 효과 중복 방지를 구현한다. | 임의 시점 복귀와 입력·설정창·다음 판 전환 검사가 통과한다. |
| 3. 화면 비용 제거 | 렌더링·표현 갱신·효과 생성·HUD·오디오·밝기 정책을 적용한다. | 실제 기기에서 사냥량 유지와 소비 전력 감소를 확인한다. |
| 4. 계산·저장 최적화 | 측정된 병목에 한해 검색·할당·저장·실행 빈도를 개선한다. | 각 변경의 전후 성능과 전투 동등성 근거가 있다. |
| 5. 장시간·중단 검증 | 발열·배터리·잠금·앱 전환·오류·강제 종료를 시험한다. | 복구 범위, 중복 정산 방지와 기기별 지원 범위를 확인한다. |

기능 완료는 ‘검은 화면이 나온다’가 아니라 **사냥량과 결과가 유지되고, 언제 확인해도 현재 행동이 이어지며, 실제 휴대폰에서 소비 전력이 감소함을 검증한 상태**다. 이번 문서 작성 단계에서는 게임 코드·씬·에셋을 변경하거나 방치 기능의 성능 검사를 수행하지 않았다.
