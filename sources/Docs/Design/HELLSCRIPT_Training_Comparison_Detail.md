# HELLSCRIPT 훈련 A/B 비교 상세안

작성일: 2026-09-09 · D4 / CHK-F02 개발 시험안 · 구현 및 검증 기준

같은 장비를 고정한 행동 A/B, 전체 누적 집계, 명시적 결과 저장의 구현과 검증 상태는 [훈련 비교 개발 기록](../Implementation/Training_Comparison_Expansion.md)을 따른다. 장비 교체 훈련과 사냥 칙령의 5개 슬롯·공유 코드는 별도 후속 범위다.

## 목적과 범위

같은 캐릭터와 훈련 환경에서 설정을 바꿨을 때 행동과 결과가 어떻게 달라지는지 보여 준다. [플레이어 훈련 상세안](HELLSCRIPT_Player_Training_Detail.md)의 실제 영웅 복사, 고정 배치 3종, 60전투초 종료와 보상 격리를 유지한다. 첫 플레이 안내에서 한 번의 수정·훈련을 경험한 뒤 더 자세히 비교할 수 있는 기능이다.

한 번의 비교는 A와 B 두 시도다. 한 조건씩 바꾸도록 권하되 여러 조건을 바꿨다면 모든 차이를 보여 준다. 총 피해가 높다는 이유만으로 B를 추천하거나 한 표본을 승률로 표시하지 않는다. 장비 교체 훈련, 최근 균열 10회의 원인 분석, 실제 시간당 파밍 효율은 [남은 개발 작업표](HELLSCRIPT_Remaining_Development_Backlog.md)의 별도 완료 기준을 유지한다.

## 진입과 진행

1. 성소의 훈련장에서 단일·다수·위험 패턴 중 하나와 A/B 비교를 선택한다. 실제 균열을 보존 중이면 진입하지 않는다.
2. A를 시작하기 전에 현재 영웅의 레벨·장비·강화·접사·스킬·패시브·행동 설정을 복사한다. 이 복사본이 한 쌍의 비교 기준이다. 훈련 시작 시드와 배치도 함께 보존한다.
3. A는 기준 설정으로 실행한다. 종료 결과에서 스킬별 피해와 사용 횟수, 피격·생존·이동·자원 부족을 확인한다.
4. ‘B 설정 만들기’에서 기존 행동 편집기를 사용한다. 현재 계정에 적용하는 버튼과 B에만 적용하는 버튼을 명확히 구별한다. 변경을 취소하면 A 결과로 돌아온다.
5. B는 A 시작 직전의 같은 기준에서 새로 실행한다. A 종료 시의 HP·자원·CD·적 피해·효과를 이어 받지 않는다. 바꾼 행동·스킬·패시브는 출발 전에 차이로 표시한다.
6. 두 결과를 나란히 보고 선택한 설정을 저장 슬롯에 남길 수 있다. 실제 현재 설정으로 적용하려면 마을에서 기존 적용 미리보기와 명시적 적용을 거친다. 결과 화면을 열거나 닫는 것만으로 실제 설정은 바뀌지 않는다.

비교 도중 영웅을 바꾸거나 다른 훈련을 선택하면 기존 비교를 계속하는 것으로 표시하지 않는다. A나 B 실행 도중 설정을 다시 바꾼 경우도 고정 설정 비교에 포함하지 않으며, 바뀐 설정으로 해당 시도를 처음부터 다시 실행하도록 안내한다. 일시정지는 가능하며 실제 경과 시간은 별도 표시한다. 배속은 [배속 잠금·사용권 정책](HELLSCRIPT_Speed_Access_Detail.md)을 따른다. 현재 사용자 훈련은 1배속만 제공하고 세 배속 계산은 내부 검증에서 확인한다.

## 같은 조건의 경계

| 고정할 항목 | 기록과 처리 |
|---|---|
| 캐릭터 | 영웅 ID·직업·레벨·XP와 기준 장비를 복사한다. 실행 사이에 실제 영웅이 성장해도 B의 기준을 몰래 갱신하지 않는다. |
| 장비 | 아이템 ID·베이스·요구 레벨·강화·접사 값·전설·세트·장착 부위를 보존한다. 첫 A/B 기능에서는 기준 장비를 고정한다. 이후 장비 교체 비교는 장비 차이를 표시하며 ‘행동 조건만 바꾼 비교’로 부르지 않는다. |
| 훈련 환경 | 훈련 종류·시드·맵 생성 버전·배치·표적 능력치·영웅 시작 위치를 보존한다. 결과의 표적 배치가 같다는 사실만으로 동일 시드를 추정하지 않는다. |
| 시작 전투 상태 | 각 시도는 새 훈련의 HP·자원·CD·효과·난수 상태로 시작한다. A의 공격·피해·버프·기록은 B에 누적하지 않는다. |
| 변경할 설정 | 규칙의 순서·사용 여부·조건·목표·위치·이동·물약과 장착 스킬·패시브의 차이를 모두 열거한다. 스킬과 패시브는 현재 해금 및 슬롯 제한을 지킨다. 이름·규칙 ID·버전 문자열만 다르면 전투 행동 변화로 세지 않는다. |
| 종료 | 60전투초·표적 전멸·영웅 사망 중 먼저 발생한 정상 종료를 기록한다. 수동 종료·진행 중·내비게이션 오류는 별도 상태로 표시하며 완료한 비교로 저장하지 않는다. |

한쪽이 먼저 사망했다면 각자의 실제 전투 시간과 생존 여부를 함께 보여 준다. 20초에 사망한 결과를 60초로 늘려 계산하지 않는다. 1배·1.5배·2배에서 고정 전투틱의 규칙을 유지하며 배속에 피해나 보상 배율을 추가하지 않는다.

## 결과와 집계 단위

최근 로그는 길이 제한이 있으므로 로그 목록을 세어 전체 결과를 만들지 않는다. `CombatSimulation`의 실제 사건 발생 지점에서 누적한 요약을 사용한다. 기존 행동·피해 판정의 결과를 관찰하며 집계를 위해 RNG를 소비하거나 새로운 공격을 실행하지 않는다.

| 표시 | 집계 기준 |
|---|---|
| 스킬 사용 | `ACTION_START`를 실제 사용 1회로 센다. 기본 공격과 각 스킬을 나누고, 발동·중단도 별도로 표시한다. 회오리의 피해 틱이나 다중 사격의 화살 개수를 사용 횟수에 더하지 않는다. |
| 스킬·효과별 피해 | 실제 나가는 피해 사건의 `definitionId`로 구분한다. 기본 공격·직접 스킬·지속 효과·전설 추가 피해를 각 출처에 한 번씩 합산한다. 추가 피해를 원 스킬과 전설 양쪽에 중복 합산하지 않는다. |
| 총 피해와 유효 HP 피해 | 방어 계산 후 피해와 실제로 깎인 HP를 구별한다. 전자는 현재 전투 총 피해와 대조하고, 후자는 과잉 피해를 제외한다. 피해 합계와 분모가 어떤 값인지 화면에 표시한다. |
| 피격 | 피해 판정 횟수·보호막 흡수·실제 HP 손실을 분리한다. 전부 흡수한 공격도 피격 판정에는 포함하지만 HP 손실로 세지 않는다. |
| 생존 | 종료 사유·실제 전투 시간·남은 HP를 표시한다. 무공격 표적 훈련에서는 피격 방어 성능을 평가할 수 없다고 설명한다. |
| 이동 | 실제 걸은 거리와 도약·후퇴·순간이동의 시작 및 완료 횟수를 나눈다. 준비 중 취소는 이동 성공으로 세지 않는다. |
| 자원 부족 | 규칙 평가에서 `RESOURCE`로 실행할 수 없었던 검사 횟수를 누적한다. 이는 ‘자원 부족 판정 횟수’이며 소요 시간이나 놓친 공격 횟수로 바꾸지 않는다. 여러 규칙의 같은 순간 판정을 독립적으로 센다는 설명을 제공한다. |
| 회피 | 이동기 사용과 위험 회피 성공은 구분한다. 위험 안에서 시작했는지, 같은 위험의 실제 판정 시점에 벗어났는지를 연결할 수 있어야 성공을 센다. 연결 근거가 없는 사건은 성공·실패를 추정하지 않고 평가 제외로 둔다. |

회피 집계의 시험 범위는 위험 훈련에서 실제 발생한 예고 공격부터 시작한다. 출처·발동 ID·피해 형상·판정 시점을 연결하고, 취소된 공격·이미 사라진 적·아직 발동하지 않은 위험·보호막 흡수를 회피 성공으로 오인하지 않는다. 모든 몬스터의 회피율까지 검증한 것으로 확대하지 않는다.

## 저장과 실패 처리

진행 중 A/B는 균열 이어하기 저장과 분리한다. 앱 종료로 끝나지 못한 시도는 완료 처리하지 않는다. 정상 종료한 한 쌍은 영웅별 최근 비교 1개를 저장하는 시험안으로 시작하며, 저장 전 기존 결과를 덮어쓸 범위를 알린다. 결과에는 기준 스냅샷·A/B 설정·변경 목록·집계 버전·종료 사유가 있어야 한다. 오래된 결과에 없는 지표는 0으로 꾸미지 않고 미기록으로 표시한다.

훈련으로 실제 XP·골드·재료·장비·강화·실클리어·초회·소탕·균열 기록은 바뀌지 않는다. 비교 결과 저장과 사용자가 명시한 슬롯 저장만 허용한다. 디스크 저장이 실패하면 이전 비교 결과와 실제 설정을 보존하고 실패를 알린다. 로컬 저장의 검증을 온라인 계정 동기화 완료로 취급하지 않는다.

## 구현 소유자와 검증

기존 씬의 `GameController → CombatSimulation → GameUI` 흐름을 확장한다. 비교 시작·A/B 전환은 실행 수명 소유자인 `GameController`, 깊은 복사·동일 조건 검사·변경 목록·결과 자료는 Core, 화면은 `GameUI`가 담당한다. 새로운 전투 시뮬레이터나 별도의 피해 계산기를 만들지 않는다. 누적 집계는 `ActionEvent`·`RecordDamage`·`RecordDecision`과 실제 이동·위험 판정 경계에서 갱신한다.

자동 검사에서는 같은 설정 A/B의 같은 결과, 바뀐 조건의 실제 행동 차이, 3직업·3훈련·3배속, 로그 상한을 넘는 집계, 장비·레벨 불일치, 미해금 스킬·중도 변경·수동 종료, 피해 출처와 합계, 복사본 격리, 저장 실패·구형 결과·재시작을 확인한다. ‘차이가 있다’는 이유만으로 더 좋은 빌드라고 판정하지 않는다.

실제 앱에서는 A 완료 → B 편집 취소 → B 편집 적용 → B 완료 → 두 결과 비교 → 명시적 저장 → 실제 프로세스 재시작 후 결과 복원을 연결한다. 세로 화면의 긴 스킬 목록과 변경 목록, 스크롤 끝의 저장·취소 버튼을 확인한다. 물리 터치와 신규 사용자의 이해도는 별도 관찰 기준이다.
