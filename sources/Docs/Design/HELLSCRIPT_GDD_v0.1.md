## 문서 상태
**사용자가 이미 확정한 요구사항은 유지한다. 이 문서에서 처음 제시하는 이름·스킬 효과·공식·수치·가격 단위·확률·UI 제한은 모두 테스트 초안이다.** 코드 구현, 실제 전투 시뮬레이션, 플레이테스트, 기기 성능 검증을 완료한 문서가 아니다.

동봉 Excel은 25개 시트로 구성되어 있다. `01_확정사항`은 대화에서 승인한 내용, 나머지 콘텐츠와 밸런스는 신규 설계다. `19_보석참조`와 `20_보석단계대조`에는 원작 검증 상태를 명시했다. 현재 자료만으로 디아블로4의 모든 보석 수치를 1:1 검증했다고 주장하지 않는다.

# 1. 플레이어가 하는 일
플레이어는 영웅을 직접 움직이거나 스킬을 누르지 않는다. 장비·스킬·특성·행동 규칙을 설계하고, 결과를 보고 수정한다.

**핵심 순환:** 마을 빌드 설정 → 균열 탐색·전투 → 보스 처치 또는 실패 → 결과 로그 → 수정 → 재도전.

**핵심 검증 질문:** 같은 장비와 같은 전투 조건에서 규칙만 바꿨을 때 생존·클리어 시간·회수 동선이 달라지고, 그 이유를 로그로 설명할 수 있는가?

실행 중 방치는 실제 전투다. 오프라인 방치는 골드·일반 강화 재료를 시간에 따라 지급할 뿐, 장비나 보스 보상을 생산하지 않는다. 소탕은 해당 영웅이 실제로 클리어한 최고 단계의 반복 클리어 보상 한 묶음을 즉시 정산한다.

# 3. 스테이지의 정확한 정의
## 3.1 상태 흐름
마을 → 입장 → 탐색/교전 → 처치점수100 도달 → 보스 등장 → 보스 처치 → 보상 확정 → 전리품 회수 → 다음 단계/같은 단계/귀환.

초기 제한 시간은 **300초**다. 탐색부터 보스 처치까지 같은 타이머를 쓴다. 보스 처치 후 회수 구간에서는 클리어 타이머가 끝나지만 현실 시간은 계속 기록한다.

일반몹은 점수1, 정예는 점수5를 준다. 지도에는 최소150점어치 적이 있어야 한다. 보스가 생성한 부하는 점수·골드·드롭을 주지 않는다.

보스가 등장하면 새 일반무리를 추가 생성하지 않는다. 남은 일반 적은 그대로 둔다. 보스는 미리 지정한 연결 가능한 큰 방에 나타나고 목적지를 표시한다. 플레이어가 보스에게 가는 방식 역시 자동이다.

보스 처치 시점의 보상과 별도의 완료 보상을 중복 지급하지 않는다. 데이터상 `BossClearReward` 한 묶음으로 통일한다. 이미 획득한 일반 전리품은 실패해도 유지한다. 보스 미처치 상태의 사망·시간초과에서는 이 묶음을 주지 않는다.

동일 틱에 보스HP0과 시간초과가 겹치면 **피해 처리 → 보스 사망·성공 판정 → 잔여 시간 실패 판정** 순서로 처리한다.

## 3.2 세 가지 시간
| 시간 | 측정 구간 | 쓰임 |
|---|---|---|
| 던전 시간 | 실제 전투·탐색이 진행되는 시간 | 300초 실패 판정 |
| 세션 현실 시간 | 입장·전투·일시정지·포탈정리·회수를 포함 | 현실 시간당 파밍 효율 |
| 오프라인 경과 시간 | 계정에 실행 중 전투 세션이 없는 보상 대상 구간 | 골드·일반재료 정산 |

편집 일시정지·포탈 자동정리에서는 던전 시계와 모든 전투 상태를 같이 동결한다. 편집창을 열어둔 시간을 오프라인 보상으로 세지 않는다. 배속을 쓰면 던전 시간도 같은 배속으로 흐른다. 300초 던전이 2배속에서 150초 현실 시간에 끝나는 것은 의도된 동작이다.

## 3.3 성공·실패 후 운영
성공 후: 다음 단계 도전 / 현재 단계 반복 / 마을 귀환 중 선택.
실패 후: 재도전 / N단 낮춰 반복 / 마을 귀환 중 선택.
별도로 연속 실패 N회 중단을 설정한다. 실패 때문에 원래 장비나 이전 완료 보상을 잃지는 않는다.

# 4. 능력치·피해 계산 초안
## 4.1 기본 능력치
| 항목 | 계산 |
|---|---|
| 최대HP | (직업 기초HP + 레벨당HP×(레벨-1) + 장비 고정HP) × (1+HP% 합계) |
| 주능력 | 전사=힘 / 궁수=민첩 / 마법사=지능 |
| 레벨 성장 | 주능력 레벨당+2, 나머지 기본능력 레벨당+1 |
| 힘 | 1당 방어도+2. 전사에게는 주능력 피해도 증가 |
| 민첩 | 1당 치명확률+0.03%p. 궁수에게는 주능력 피해도 증가 |
| 지능 | 1당 모든 비물리 저항+1. 마법사에게는 주능력 피해도 증가 |
| 의지 | 1당 받는 회복량·보호막 생성량 각각+0.1%p |
| 자원 | 최대100. 직업마다 초당회복·기본공격회복 다름 |
| 물약 | 최대HP35% 회복, 기본CD20초, 자동규칙 사용 |

힘·민첩·지능·의지를 모두 두는 이유는 보석·장비 옵션을 위한 연결 고리를 만들기 위해서다. 위의 능력치 환산 공식은 디아블로 원작 공식이 아니라 헬스크립트 테스트 초안이다.

## 4.2 공통 피해식
`공격 기준 D = 무기 기초피해 × [1+0.08×(아이템레벨-1)] × [1+0.05×강화단계] × [1+0.002×주능력]`

`직접 피해 = D × 스킬계수 × (1+해당 공격에 적용되는 가산 피해 합계) × 보석 등 별도 배율 × 치명 배율 × (1-방어 감소율) × (1-버프 피해감소율)`

물리: `방어 감소율=min(0.75, 방어도/(방어도+100+10×공격자레벨))`.
비물리: `방어 감소율=min(0.70, 해당저항/(해당저항+100+10×공격자레벨))`.
몬스터 공격자레벨은 초기안에서 `min(30, 균열단계)`로 둔다. 단계에 따른 기본공격 증가와는 별개다.

치명 확률은 기본5%에 민첩·장비·효과를 합산하고 75%에서 제한한다. 치명 피해 배율은 기본1.5다. 쿨감40%, 자원감소50%, 공격속도보너스50%, 이동속도보너스50%, 버프형 피해감소50%를 초기 상한으로 둔다.

지속피해는 기본적으로 치명타가 없다. 생성 시 공격 수치를 저장한다. 같은 시전자의 같은 눈보라가 겹치면 더 큰 틱만 적용하고, 무한 중복은 허용하지 않는다.

공격속도는 기본공격과 분쇄·관통·다중·화염구·연쇄 번개의 시전시간을 줄인다. 이동기·쿨타임·장판 틱·휠윈드 틱에는 적용하지 않는 초기안이다. 이 제한은 스킬 설명에 노출한다.

보호막은 체력보다 먼저 소모되며 기본 최대치는 최대HP100%다. 같은 효과는 더 큰 보호막으로 갱신하고 무한 합산하지 않는다. 둔화는 가장 강한 값만 적용한다. 일반·정예에는 기절·빙결이 적용된다. 보스는 위치제어와 직접 기절·빙결 대신 무력화 게이지를 받는다. 초기안: 제어 시도 지속1초당10점,100점에3초 무력화, 이후10초 게이지 누적 불가.

# 5. 직업·스킬 운용
액티브 해금 레벨은 1/3/6/10/15/20의 초안이다. 최대 액티브4개, 패시브3개는 바꾸지 않는다. 잠긴 스킬이 있는 추천 프리셋은 잠긴 항목을 표시하고 사용 가능한 항목만 적용한다. 30레벨까지의 경험치 요구는 테스트에서 조정한다.

전사는 **진입·선회·이탈**, 궁수는 **거리·사선·덫 경로**, 마법사는 **장판 위치·자원·속성 연계**를 설계한다.

각 스킬의 수치·범위·자원·쿨타임·선택지는 Excel `04_액티브18`에 있다. D계수0.5는 D50%다. 휠윈드의 범위는 반경, 다중사격의 범위60은 각도이며 해당 행 설명을 우선한다. 개발 시에는 범위의 단위를 별도 enum으로 분리해야 한다.

첫 전사 내부 프로토타입은 기본공격·휠윈드·도약으로 먼저 시작한다. 생존 순환 확인 뒤 철벽·함성을 연결한다. 이 구현 순서는 첫 공개 버전의 직업3종 범위를 줄인다는 뜻이 아니다.

# 6. 스크립트: 선택하는 전투 규칙
## 6.1 카드 구조
규칙1개는 `사용 여부 / 우선순위 / 조건그룹 / 행동 / 대상·지점 / 행동중 이동 / 중단 정책`을 가진다.

조건은 제공된 목록에서 선택한다. 초기 UI는 OR그룹 최대2개, 각 그룹의 AND조건 최대3개로 제한한다. 사용자가 직접 논리식이나 코드를 입력하지 않는다. 장착스킬당 최대3개 규칙, 전체24개 규칙을 초기 범위로 둔다.

한 스킬을 다른 역할로 여러 번 지정할 수 있다. 예를 들어 도약을 진입용·탈출용 두 규칙에 넣어도 실제 스킬 쿨타임은 공유한다.

## 6.2 실행 과정
1. 인지 범위·시야선에 따라 적·아이템·위험지역 상태를 갱신한다.
2. 조건을 판정한다.
3. 스킬 장착·자원·쿨·행동가능상태·유효 대상 또는 지점의 존재를 검사한다.
4. 실행 가능한 규칙을 사용자 우선순위로 정렬한다.
5. 주행동 하나를 선정하고 발동을 확정한다.
6. 비용·쿨을 확정하고 선정한 최선 후보를 향해 실행한다.
7. 결과와 필요시 중단 이유를 기록한다.

**조건 참 ≠ 발동 확정.** 도약 후보에 적이 모두 있어도 최소밀도 지점으로 도약한다. 그러나 착지 가능한 지점 자체가 하나도 없으면 발동 전 `NOT_READY_NO_DESTINATION`이다. 준비되지 않은 행동을 대기열에 무조건 쌓아 뒤늦게 실행하지 않는다.

발동 이후 적이 죽으면 가능한 동작은 마지막 유효 조준점으로 완료한다. 명중이나 피해를 보장하는 것은 아니며 비용을 환불하지 않는다. 순간이동 위치가 지형 변경으로 사라지는 예외는 검증 실패로 별도 기록한다.

주행동 채널은 하나다. 일반 이동·공격·이동스킬이 서로 위치를 덮어쓰지 않는다. 물약은 독립 채널로 허용한다.

## 6.3 후보 지점과 '최선'
적 인지 반경은12m이고 시야선을 적용한다. 모바일·PC에서 카메라 크기가 달라도 같아야 한다.

이동스킬은 16방향×3거리와 목적지 투영점 등 최대64개의 지형 유효 후보를 만든다. 전역 최적해를 찾는다고 보장하지 않는다. **평가한 유효 후보 중 사용자 기준상 최선**을 고른다.

'적 밀도 최소'이면 후보 반경3m의 인지 적 수를 먼저 최소화한다. 동률일 때만 임박 위험, 목표거리 오차, 이동거리, 후보ID 순으로 판정한다. '위험도 최소'는 다른 선택지다. 적 밀도 최소를 골랐는데 게임이 숨은 판단으로 공격형 이동을 수행하면 안 된다.

군집 중심이 벽·구덩이 안이면 가장 가까운 이동가능 지점으로 투영한다. 도보는 실제 연결 경로가 있어야 하고, 도약·순간이동은 착지와 허용 지형을 검사한다. 처음부터 보이지 않는 벽 뒤 적까지 알고 도약하지 않는다.

# 7. 던전 생성과 적
## 7.1 지도
스테이지당6~8개 방을 선택하고 기본 연결을 하나의 고리로 만든 뒤 보조 연결을 추가한다. 방 차수2 이상, 모든 방 연결, 실제 보행 경로 연결을 검사한다. '모든 방이 연결됨'만 검사하면 막다른 길이 남을 수 있으므로 별도 검증이 필요하다.

기본 고리 때문에 영웅이 같은 벽을 영원히 따라돌 수 있다. 방문 방·간선을 기록하고, 같은 순환만 반복하면 다음 미탐색 연결로 복구한다. 전술을 자동으로 고치는 것이 아니라 길찾기 오류·무진행 상태를 방지하는 처리다.

파괴해야만 지나가는 장애물·열쇠문·점프 전용 통로·퍼즐은 없다. 적은 고정 생성한 무리로 배치한다. 지도 생성과 루팅 난수 스트림을 분리한다.

## 7.2 단계 증가
일반 기준HP=`70×1.08^(R-1)`, 기준공격=`18×1.055^(R-1)`.
보스 기준HP는 일반 기준×45, 공격은×3에 보스별 추가 배수를 적용한다.
장비 주능력은 선형, 적의 체력·공격은 지수 성장하는 초안이다. 장기적으로 막히는 구간은 생긴다. 단계 상한이 없다는 것과 현재 장비로 끝없이 오를 수 있다는 것은 다르다.

정예 특성은 초기1개,20단 이상 최대2개 조합을 초안으로 둔다. 서로 회피 가능 공간을 없애는 조합은 금지목록으로 검사한다. 모든 보스의 큰 공격은 최소한 예고와 유효 대응 경로가 있어야 한다.

# 8. 장비·전설·세트
장비는 무기/머리/몸/손/발/허리/목걸이/반지8부위다. 일반0·마법1·레어3·전설4개의 랜덤옵션을 초기안으로 둔다. 같은 옵션ID는 한 아이템에 중복되지 않는다. 세트도 전설 등급이다.

베이스24개 중 일부는 성능이 같은 외형 변형이다. 24개의 서로 완전히 다른 무기 조작체계를 추가한다는 뜻이 아니다. 최초 외형 반영은 무기 우선이다.

개별전설15개는 자체 특수효과를 가진다. 세트장비12개는 개별 특수효과 대신 세트소속·랜덤옵션을 가진다. 두 종류를 합해27개의 전설 결과 정의가 생긴다. 세트2·4개와 개별전설 부위 사이의 선택이 생기게 한다.

## 8.1 등장 가중치
등급 추첨과 전설 구성원 추첨을 분리한다.
- 등급 추첨: 이 획득 기회가 전설인가?
- 구성원 추첨: 선택한 부위·직업·해금조건 후보 중 어느 전설인가?

구성원 확률=`아이템 가중치 / 해당 후보군 총가중치`.
가중치100/20/1은 예시 겸 초기값이며, 전체 게임에서100%/20%/1% 드롭한다는 의미가 아니다.

각 직업·각 부위에 가중치100인 후보를 최소1개 유지한다. 특히 목걸이에는 극희귀 직업전설뿐 아니라 공용 '절제의 서약'이 있어, 부위코어 제작으로 극희귀가 확정되지 않는다. 두 후보만 있을 때 극희귀의 전설-목걸이 내 조건부 확률은1/101이다. 전체 필드 획득확률은 등급·부위 확률까지 곱해야 한다.

보스·일반드롭·코어·상점·소탕은 같은 구성원 가중치 원칙을 사용한다. 균열 전투와 소탕에서는 10.1의 단계별 등급 확률을 먼저 적용하고, 전설로 결정된 뒤 기존 구성원 가중치를 사용한다. 코어·상점·기본 제작의 기존 등급·아이템 레벨 규칙에는 이번 보정을 적용하지 않는다. 전설 구성원의 기존 부위·직업·해금 조건과 개별 가중치, 세트 포함 여부는 유지하며 극희귀 전설만 따로 우대하지 않는다. 새 아이템 추가 시 분모가 바뀌므로 후보군 검사를 다시 해야 한다.

필수 기본 스킬 기능은 장비 없이도 작동한다. 극희귀 장비는 기본 생존수단을 처음 해금하기보다 운용을 강화하거나 변형한다.

# 10. 보상과 성장 경제 초안
1단계에서는 기존 경로별 등급 확률을 유지한다. 이후 실제 플레이하는 균열 단계가 높아질수록 전설 확률을 높이고 나머지 등급 확률을 비례해서 줄인다. 일반몹의 장비 드롭 자체 2%, 정예의 장비 1회 추첨, 보스의 장비 3회 추첨은 유지한다. 아래 곡선과 상한은 드롭 목표의 출발점이며 적정 플레이타임이 검증된 수치가 아니다.

## 10.1 균열 단계별 장비 등급 확률 / Equipment rarity by rift tier

목적은 더 높은 균열에 도전할 때 아이템 레벨뿐 아니라 상위 등급 장비를 얻을 기회도 높이는 것이다. 장비에 매직 찬스 옵션을 추가하지 않으며, 영웅의 최고 기록에 따라 영구 능력치를 쌓는 기능도 아니다. 디아블로4에서는 난이도에 따른 보상 기회라는 방향만 참고했다. 아래 수치와 공식은 HELLSCRIPT용 밸런스 초안이며 디아블로4의 실제 수치나 공식, 사용자 확정값, 플레이테스트 완료값으로 표시하지 않는다.

공통 상승구간 파라미터 `K=49`를 두고, 경로별 전설 기준 확률 `p0`와 상한 `cap`을 별도로 조절한다.

```text
t = max(0, R - 1)
g = t / (t + K)
pLegendary = p0 + (cap - p0) × g
pNonLegendary(rarity) = baseline(rarity) × (1 - pLegendary) / (1 - p0)
```

| 경로 / Source | 1단계 일반 / Common | 마법 / Magic | 레어 / Rare | 전설 p0 / Legendary | 전설 상한 / Cap | 장비 획득 기회 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| 일반 몬스터 / Normal | 55% | 25% | 19% | 1% | 10% | 기존 장비 드롭 2% 성공 후 1회 추첨 |
| 정예 / Elite | 0% | 60% | 35% | 5% | 25% | 기존 장비 1회 추첨 |
| 보스 / Boss | 0% | 0% | 85% | 15% | 45% | 기존 장비 3회 추첨 각각에 적용 |

50단계에서 `g=0.5`이므로 기준과 상한 차이의 절반을 얻는다. K 하나로 상승 속도를 조절하고, 고단계에서는 증가 폭이 완만해지는 단순한 곡선을 선택했다. 10%·25%·45% 상한은 경로의 보상 차이를 남기면서 전설 100%가 기본 상태가 되지 않도록 잡은 초안이다. 유한 단계에서는 상한 아래에 머물고 무한히 높아지면 상한에 접근한다.

전설 증가분은 비전설 전체에서 기존 비율에 따라 가져온다. 따라서 일반 경로의 일반:마법:레어는 55:25:19, 정예 경로의 마법:레어는 60:35를 유지한다. 정예의 일반, 보스의 일반·마법은 계속 0%다. 모든 확률의 합은 100%이며 전설, 레어 이상, 마법 이상 누적 확률은 단계가 높아져도 감소하지 않는다. 파라미터를 조절할 때 `K>0`, 기준 확률 합계 100%, `0≤p0≤cap<1`, 경로별 `일반≤정예≤보스` 순서의 p0와 cap을 유지한다. 공통 g를 사용하므로 이 조건은 모든 단계에서 보스 전설 확률≥정예≥일반을 보장한다.

실제 전투는 그 전투의 현재 균열 단계 R을 사용한다. 최고 실제 클리어가 50단계인 영웅이 10단계를 반복하면 10단계 확률을 적용한다. 소탕은 해당 영웅의 최고 실제 클리어 단계에 해당하는 보스 보상 1묶음을 지급하므로 그 단계의 보스 확률을 사용한다. 소탕에 별도 우대를 주거나 추첨 횟수·최초 클리어 처리·기록 갱신 규칙을 바꾸지 않는다.

오프라인은 기존 골드와 일반 강화 재료만 지급한다. 미확인 장비 상점·코어 제작·기본 제작은 이 보정에서 제외한다. 기존 드롭 아이템 레벨 `max(1,R-2)~R+2`, 옵션 개수와 수치 범위, 전설 구성원 가중치, 강화·분해 비용, 골드·재료 보상량, 스킬·특성·몬스터 능력치는 유지한다. 옵션 재설정은 C27·EC13의 최신 규칙, 즉 `L=max(1,아이템 레벨)`에서 `500×L+50×L×(L-1)` 골드를 횟수와 무관하게 매번 동일하게 사용한다. 계수 500·50은 테스트 초안이다.

보상은 해당 전투·소탕의 단계 정보로 확정하고 기존 저장·중복 방지 절차를 따른다. 수령·재접속 때 다시 추첨하지 않으며, 이후 최고 기록 갱신이나 다른 단계 입장이 이미 확정된 미수령 보상 결과를 바꾸지 않는다.

화면에서 일반 몬스터의 장비 드롭 자체 2%와 드롭된 장비의 전설 확률을 구분한다. 보스 확률은 3회 추첨 각각의 확률이다. 독립 추첨 3회에서 전설을 1개 이상 얻을 확률이 필요하면 `1-(1-pLegendary)^3`을 사용하며 `3×pLegendary`로 표시하지 않는다.

### English rules

Current encounter tier and reward source determine equipment rarity. Use `t=max(0,R-1)`, `g=t/(t+49)`, and `p=p0+(cap-p0)×g`. Scale each nonlegendary baseline probability by `(1-p)/(1-p0)`. The source baselines and caps are shown above. Tier 50 earns half the available increase. These are HELLSCRIPT balance drafts, not Diablo IV formulas, approved balance, or measured playtest results.

Use the active encounter tier for combat and the hero's highest actual clear for one sweep boss bundle. A hero with a tier-50 record farming tier 10 receives tier-10 rates. Keep the normal 2% equipment drop gate, one elite roll, and three boss rolls. Offline gold/material rewards, shops, crafting, item levels, affix ranges, legendary eligibility and member weights, set inclusion, and other economy/combat values are unchanged. No magic-find affix, permanent progression stat, or ultra-rare member bonus is added. Preserve fixed item-level reroll cost `500×L+50×L×(L-1)`, independent of attempt count, with `L=max(1,item level)`.

Finalize rewards using their encounter or sweep tier. Claims, reconnects, record changes, and entering another tier must not reroll finalized results. Each boss roll uses the listed rate; the probability of at least one legendary in three independent rolls is `1-(1-p)^3`.

## 10.2 소탕·오프라인과 기존 보상 경제

오프라인 상한12시간과 하루 소탕3회는 이번 문서의 신규 초깃값이다. 사용자가 이미 확정한 숫자로 취급하지 않는다.
오프라인: 시간당골드 `200+40×계정최고클리어R`, 일반재료 `5+floor(R/5)`.
소탕: 해당영웅 최고클리어 단계의 보스클리어 보상1묶음. 일반몹드롭·첫클리어보상·경험치·기록갱신은 제외하는 초안이다.

온라인은 같은 단계에서도 클리어속도·생존·회수에 따라 시간당 보상이 달라진다. 소탕은 같은 최고클리어 단계라면 현재 스크립트의 초당효율과 관계없이 같은 보상표를 쓴다. 이것은 사용자가 선택한 차이다.

오프라인 장비드롭은 없으므로 인벤토리 공간 때문에 기본재화 수령을 막지 않는다. 소탕 장비는 공간부족이면 확정 미수령 묶음으로 보관하고 추가소탕을 잠근다. 재접속으로 결과를 다시 추첨하지 않는다.

유료상품 범위는 영웅별 인벤토리 추가탭과 계정창고 추가탭이다. 실제 원화가격·유료재화가격·스토어상품ID는 이 문서에서 임의 확정하지 않는다. 랜덤상점은 사냥골드만 사용한다. 광고·유료추가소탕은 현재 초안에 없다.

# 11. 획득·가방·포탈
## 11.1 획득은 세 단계
(1) 획득 허용: 반경 안에서 주워도 되는가.
(2) 적극 회수: 그 아이템을 위해 이동할 것인가.
(3) 우선순위: 회수가 전투·생존보다 먼저인가.

골드 최소더미 조건은 골드끼리2m 내 병합한 다음 판단하는 초안이다. 병합 전후 총량이 같아야 한다. 무시한 골드도 나중에 병합으로 기준을 넘으면 획득 대상이 될 수 있다.

## 11.2 가득 찼을 때
| 정책 | 처리 |
|---|---|
| 포탈 정리 | 귀환→자동분해·정리→같은 던전 상태로 복귀 |
| 최저가치 폐기 | 신규 아이템까지 포함해 보호대상 제외 후보 중 최저값 제거 |
| 획득 무시 | 새 장비를 줍지 않고 전투 계속 |

가치비교는 등급→아이템레벨→판매가 순이다. 새 아이템이 최저가치라면 기존 장비를 버리지 않고 새 아이템을 무시한다. 버린 아이템은 그 스테이지에서 재획득하지 않도록 제외목록에 넣는다.

잠금·프리셋 사용 장비는 강제 보호다. 기본은 전설·세트도 보호하고 별도허용 옵션을 둔다. 후보가 모두 보호면 어떤 장비도 임의로 삭제하지 않고 이후획득무시로 전환한다.

## 11.3 포탈 세부
초안: 포탈 시전2초, 피격 시 중단, 재시도대기3초. 시전 중에는 던전시간이 정상 진행된다. 마을 자동정리에 들어가는 순간 전체 전투상태를 동결한다.

적 위치·HP·어그로·투사체·장판·영웅HP·자원·버프·쿨·잔여시간을 저장한다. 분해·보관으로 가방과 재료만 변한다. 무료회복·쿨리셋·몬스터리셋은 없다. 자동정리 왕복에서는 강화·장비교체·직업전환까지 몰래 수행하지 않는다.

# 12. 마을·훈련·세로 UI
NPC는 대장장이(강화·분해·기본제작), 비술사(옵션·코어·보석), 전술교관(훈련·추천프리셋), 균열관리인(입장·소탕·미확인상점)4명으로 역할을 묶는다. 마을을 걸어다닐 수 있지만 주요 기능은 메뉴로 바로 연다.

세로 전투화면: 상단에 단계·잔여시간·게이지, 중앙에 전투, 하단에HP·자원·현재실행규칙·읽기전용 스킬상태를 둔다. 스킬아이콘은 직접시전 버튼이 아니다. 스크립트 버튼을 누르면 일시정지하고 편집패널을 크게 연다. 적용·재개로 즉시 시험한다.

PC는 같은 설정내용을 옆 패널로 펼친다. PC에만 조건·인지범위·사냥이득을 추가하지 않는다. 월드 클릭으로 캐릭터를 직접 이동시키지 않는다.

훈련은 단일/군집/위험3상황이다. 맵·적배치·초기스탯·전투난수시드를 고정하고 이전/현재 결과를 비교한다. 실제 획득경제에는 영향을 주지 않는다. 완전한 재현은 구현 검증 대상이며 시드만 같으면 자동 보장된다고 주장하지 않는다.

# 13. 로그와 결과 보고
최소 이벤트:
`CONDITION_ENTER / RULE_READY / ACTION_START / ACTION_END / ACTION_INTERRUPTED / RULE_BLOCKED / TARGET_SELECTED / INVENTORY_POLICY / BOSS_CLEAR / RUN_END`.

조건을 매평가 참이라고 반복저장하지 않는다. 참으로 전환되는 사건과 실행이 발동한 사건은 각각 남긴다. 지속적으로 막힌 같은 원인은 집계하되 첫·마지막시간과 횟수를 보존한다.

한 로그에는 runId, simTime, realElapsed, ruleId, ruleVersion, actionId, targetId 또는 destination, 조건값, 자원·쿨 판정, 결과코드가 들어간다. 스테이지 중 스크립트를 바꾸면 새버전과 적용시각을 추가한다.

스테이지 보고서는 성공/실패, 던전시간, 현실시간, 스킬별 피해·사용횟수, 적별 받은피해, 자원부족횟수, 회수·마을정리시간, 획득보상을 보여준다. 사망 직전3~5초의 이벤트와 당시HP·쿨·이동대상을 표시한다.

최근10회 상세결과만 보존한다. 최고클리어기록·구매권한·보상영수증·경제요약은 삭제 대상이 아니다. 소탕·오프라인에서는 실제행동을 실행하지 않았으므로 가상의 전투로그를 생성하지 않는다.

예시 출력은 '도약 미발동: 쿨3.2초 남음' 또는 '후보12개 중 선택: 적2명·임박위험0'처럼 관측사실로 구성한다. 자동으로 그럴듯한 사망원인을 지어내지 않는다.

## 콘텐츠 공개·해금 순서 v0.1 (2026-09-12 변경)

이 절의 단계·레벨은 HELLSCRIPT 테스트 초안이며 외부 게임의 확정 수치가 아니다. 기존 본문 중 공개 순서와 패시브 슬롯 수가 다른 경우 이 변경 절을 적용한다. 상세 조건은 [변경 명세](HELLSCRIPT_Content_Unlock_Spec_v0.1.md), 구현·검증 상태는 [구현 기록](../Implementation/Content_Unlock_Expansion.md)을 따른다.

| 훈련장 | 첫 실제 균열 시도 종료 (실패 포함) |
| 장비 강화 | 최고 실제 클리어 ≥ 1단 |

계정 내 영웅의 최고 실제 클리어 A, 선택 영웅의 개인 최고 실제 클리어 H, 실행에 저장된 현재 단계 R, 영웅 레벨 P를 구분한다. 클리어 보상이 확정된 후 A ≥ N을 재평가한다. 입장만으로는 해금하지 않는다. 권한과 안내 완료는 별도 저장하며, 보석·코어 소비로 권한을 회수하지 않는다.

신규 영웅의 패시브 슬롯은 P=3/6/10에서 1/2/3개다. 기존 사용자는 기존 3개 슬롯과 적법한 장착을 보존한다. 액티브의 기존 1/3/6/10/15/20레벨 조건과 최대 4개 장착은 유지한다.

직업·상세 스크립트·프리셋·분해·판매·잠금·기존 창고·획득 필터·포탈·재도전은 초기 접근을 유지한다. 미구매 탭은 부여하지 않는다. 전설·세트 착용에는 추가 균열 단계 제한이 없다. NPC 내부에서 기능별로 권한을 검사한다. 포탈 자동 정리 중 강화·장비 교체 금지는 유지한다.

R=1~5는 첫 테마·기본 근접 적·첫 보스를 사용한다. R≥6에서 기존 원거리·장판·지원형 조합을 확대한다. R≥11은 두 번째 테마와 보스를 후보에 추가하고 R≥20은 정예 최대 2특성, R≥21은 세 번째 보스를 추가한다. 이전 후보·방과 보스의 호환 배치·회피 불가능 특성 조합 금지는 유지한다. 20단 이후 새 성장 메뉴는 추가하지 않는다.

소탕은 계정에서 메뉴가 열려도 H≥1인 영웅만 실행하며 보상과 단계별 등급 확률은 H 기준이다. 실제 전투 보상은 R을 사용한다. 옵션 재설정 비용은 500×L+50×L×(L−1), L=max(1,아이템 레벨)이며 반복 횟수와 무관하다. 기존 단계별 등급 확률표는 변경하지 않는다.

보석·소켓·합성은 현재 실행 구현이 없으므로 권한·예고·의존 안내만 제공한다. 무료 보상이나 레시피를 임의 추가하지 않는다. 서버 계정 동기화도 미연결이며 로컬 저장 및 검증된 권한의 합집합 병합 경계만 구현한다.
