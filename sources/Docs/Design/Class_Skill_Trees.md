# 직업별 스킬 트리와 성장 순서

수정일: 2026-09-23 · [English](Class_Skill_Trees.en.md)

전사·궁수·마법사는 각각 **일반 액티브 16개, 패시브 19개, 궁극기 2개로 총 37개**입니다. 이번 수정은 기존 108개 스킬의 직접 효과 관계를 다시 검사하고, 궁극기 강화 패시브를 각 궁극기에 하나씩 대응하도록 분리했습니다. 직업별 하나씩 추가되어 총 111개입니다.

[전사 HTML](../../Prototypes/SkillTree/Warrior.html) · [궁수 HTML](../../Prototypes/SkillTree/Ranger.html) · [마법사 HTML](../../Prototypes/SkillTree/Mage.html)


**게임 적용:** [사냥 칙령 통합](../Implementation/Hunt_Edict_Skill_Tree.md)에서는 일반 액티브 4칸과 별도 궁극기 1칸과 패시브 상시 적용을 사용한다. 아래 HTML의 초기 장착 칸 설명은 비교용 시안 기록이며 현재 게임 규칙보다 우선하지 않는다.

| --- | --- | --- | --- |

여섯 패시브는 HTML에서 **40레벨과 대응하는 궁극기의 기본 1등급 활성화**를 요구합니다. 반대편 궁극기만 활성화되어 있으면 열리지 않습니다. 각 패시브를 해당 궁극기 바로 아래에 배치했습니다. 수치를 늘리거나 두 효과를 중복 부여하지 않고 기존 효과를 나누었습니다.

## 성장 규칙과 연결 기준

1~9레벨은 기초, 10~19레벨은 생존과 자원 운용, 20~29레벨은 상태·설치물 연계, 30~39레벨은 빌드 완성, 40레벨은 궁극기와 전용 패시브를 배치합니다.

**독립 스킬 70개는 레벨만**, **직접 효과가 연결된 스킬 35개는 레벨과 실제 대상·발동 스킬**, **궁극기 6개는 공통 구간 조건**을 사용합니다. 일반적인 표식·보호막·저체력·기본 공격 조건만으로 특정 스킬을 강제하지 않습니다. 장비가 추가로 만드는 연계는 기본 스킬의 필수 관계로 바꾸지 않습니다.

직접 대상이 여러 개인 일반 패시브는 실제 대상 중 하나의 활성화를 요구합니다. 준비된 도주 AP12는 쿨타임 감소 대상인 후퇴 도약 A04와 발동에 쓸 덫 하나가 모두 필요합니다. 기본 화면에는 단일 필수 관계 26개만 그리고, 직접 대상 선택 관계 22개는 관련 스킬을 선택할 때 표시합니다. 상세 패널은 모든 실제 대상을 나열합니다. 단순 성장 순서나 같은 계열이라는 이유로 연결하지 않습니다.

궁극기는 기존 합의대로 **40레벨 이상 + 같은 직업의 직전 30~39레벨 구간 스킬 중 하나 활성화**입니다. 액티브·패시브·계열을 가리지 않으며 장착은 요구하지 않습니다. 이 공통 조건의 후보별 연결선은 그리지 않습니다.

조건을 충족한 기본 1등급은 무료입니다. 강화 포인트는 2레벨부터 레벨당 1개, 40레벨에서 39개이며 일반 스킬 최대 5등급·궁극기 1등급입니다. 선행 스킬의 추가 강화나 임의의 누적 투자량을 요구하지 않습니다. 장착은 액티브 4개·패시브 3개·궁극기 1개이며 패시브 칸은 3·6·10레벨에 열립니다.

## 소유 경계와 저장

스킬 이름·효과·실행 수치는 `Docs/Design/ClassSkills/catalog.json`과 `runtime_parameters.json`에서 `ClassSkills.json`으로 생성합니다. 이번 분리 효과는 실제 전투 코드에도 반영했습니다. HTML의 레벨·선행 관계는 `tree-design.cjs`가 소유하는 설계안이며 게임 해금 규칙에 일괄 적용하지 않았습니다. 기존 실행 데이터의 해금 레벨은 저장 호환성을 위해 보존하고, 새 P19는 40레벨에 등록했습니다. 일반 플레이 공개 상태는 계속 꺼져 있습니다.

기존 36개 등급을 가진 게임 저장·HED4 공유 문서는 새 37개 구성으로 읽습니다. 두 번째 궁극기를 선택했다면 기존 P18의 투자와 장착을 P19로 옮기며 총 포인트와 장착 칸을 늘리지 않습니다. HTML 저장도 같은 이전 규칙을 사용합니다. 원본 문서는 변경하지 않고 새 사본을 만듭니다.

브라우저 저장은 `HELLSCRIPT_SKILL_TREE_PLANNER_V1`이며 게임 계정과 별개입니다. 직업별 배분, 레벨 하향 환급, 되돌리기, JSON 내보내기·불러오기, 검색·종류 필터, 한영 전환과 세로·가로 화면을 제공합니다. 새 창·씬·프리팹·폰트 소유자를 추가하지 않습니다. 게임 UI 연결은 기존 `ClassSkillReadModel`, `ClassSkillLoadout`, `GameStore`와 공통 UI에서 처리해야 합니다.

화면의 설명·조건·후속 스킬은 현재 언어의 실제 스킬 이름으로 표시합니다. 예를 들어 얼음의 잔향 설명의 `M06·M09`는 ‘서리 폭발·빙하창’으로 표시하며, 기본 공격의 개발용 코드도 이름으로 바꿉니다. 스킬 노드와 상세 제목의 개발용 번호는 표시하지 않습니다. 한국어 조사는 치환한 이름의 받침에 맞춥니다. 원본 데이터와 저장·연결에 사용하는 ID는 유지하며, 표시 계층에서만 이름을 조회합니다.

## 검증과 다시 생성하기

`python3 tools/class_skills.py build`, `python3 tools/class_skill_runtime.py build`, `node Prototypes/SkillTree/build.cjs`로 문서·실행 데이터·HTML 데이터를 생성합니다. [그래프 결과](../../Prototypes/SkillTree/evidence/graph-validation.json)는 111개 모두 각 해금 레벨에 도달 가능함을 확인합니다. [모델 검사](../../Prototypes/SkillTree/evidence/engine-tests.txt)는 39건 통과했으며, 전용 궁극기와 반대쪽 궁극기 구분, 직접 대상 선택, 이전 저장 변환을 포함합니다.

[브라우저 검사](../../Prototypes/SkillTree/evidence/browser-validation.json)는 111개 아이콘, 실제 조작과 저장, 한영 10개 화면 크기 조합, 오프라인 HTML을 확인합니다. [궁극기 연결 화면](../../Prototypes/SkillTree/evidence/warrior-split-ultimates.png)과 [아이콘 비교](../Art/ClassSkillIcons/qa/ultimate-support-64-dark.png)를 보관합니다. Unity·macOS 검증의 실행 수와 범위는 [최종 검증 기록](../../Prototypes/SkillTree/evidence/validation-summary.json)에 기록합니다. 모바일 실기기는 검사하지 않았습니다. 공개 위키는 이 브랜치를 main에 병합할 때 게시합니다.
