# HELLSCRIPT 균열 생성·탐색·필드 보상 상세 기획

작성일: 2026-09-08  
버전: v1.2  
문서 상태: 후속 구현을 위한 검토안이다. 기존 확정 사항을 보존하며, 새로 제시한 수치와 정책은 구현·밸런스 검증 전의 제안이다.  
적용 대상: 첫 플레이 빌드 이후의 균열 생성, 자동 탐색, 상자, 필드 이벤트와 보상 정산이다. 이 문서를 작성하면서 게임 코드나 씬은 변경하지 않았다.

## 1. 목표와 문서의 기준

**2026-09-12 갱신:** 이 문서는 방을 어떻게 만들고 잇는지를 정한다. 그렇게 만든 방들이 한 판 안에서 어떤 역할을 맡는지와 목표 사슬·관문·전개 곡선은 [던전 구성 상세안](HELLSCRIPT_Dungeon_Composition_Detail.md)을 따른다. 그 문서가 이 문서의 규칙 네 가지를 바꾸며 바뀌는 목록은 거기 12장에 있다.

균열마다 길의 연결, 전투 공간, 적의 조합과 보상 위치가 달라져야 한다. 플레이어는 직접 캐릭터를 조작하는 대신, 자신의 빌드와 자동 행동 설정이 달라진 환경에서 어떻게 작동하는지 관찰하고 개선한다. 상자와 짧은 필드 이벤트는 제한시간 안에서 탐색에 투자할 이유를 제공한다.

기존 기준은 [최종 기획서](HELLSCRIPT_Unity_Implementation_Plan.md)의 4·5·8·9·10장과 [콘텐츠 명세](HELLSCRIPT_Content_Catalog.md)의 11–14장이다. 전체 개발 순서는 [확장 기획](HELLSCRIPT_Development_Expansion_Plan.md), 장비 생성은 [장비 상세 기획](HELLSCRIPT_Itemization_Detail.md), 전투와 나머지 완성 항목은 [게임 완성 체크리스트](HELLSCRIPT_Gameplay_Completion_Checklist.md)를 함께 따른다. 현재 구현 여부는 [첫 플레이 빌드 현황](../Implementation/Playable_Build.md)을 따른다. 이 문서의 신규 시험값을 기존 사용자 확정 사항으로 취급하지 않는다.

| 구분 | 유지할 기준 |
|---|---|
| 조작 | 던전 이동·전투·스킬·획득은 완전 자동으로 처리한다. 상자나 성소를 열기 위해 수동 연타를 요구하지 않는다. |
| 기본 콘텐츠 | 묘지·성채 2테마, 방 템플릿 12종, 일반 적 12종, 정예 특성 6종, 보스 3종을 유지한다. |
| 지도 | 막다른 길 없이 연결된 무작위 방 구성을 유지한다. 그래프 검사와 실제 보행 검사를 함께 통과해야 한다. |
| 목표 | 처치 게이지 100을 채운 뒤 보스를 처치한다. 탐색·일반 전투·보스전을 합쳐 전투 시간 300초를 사용한다. |
| 배속 | 1배·1.5배·2배가 이동, 개봉, 전투, 위험 예고와 제한시간에 똑같이 적용된다. 보상 배율은 추가하지 않는다. |
| 실패 | 이미 지급되거나 가방에 들어온 획득물은 유지한다. 미개봉 상자와 미획득 바닥 장비는 보상으로 바꾸지 않는다. |
| 포탈 | 같은 균열을 보존한다. 정리 상태에서 전체 전투 시간을 멈추며 HP·자원·재사용 대기시간을 초기화하지 않는다. |
| 보스 | 보스 반복 보상 묶음은 한 번만 확정한다. 보스 소환 부하는 게이지·골드·장비·경험치를 주지 않는다. |
| 초회·소탕 | 초회 보상은 캐릭터별·단계별 1회다. 소탕은 선택 영웅의 최고 실클리어 단계 보스 반복 보상만 주며 필드 상자를 포함하지 않는다. |
| 접속 | 공개 버전의 전투·보상 확정·기기 인계는 온라인을 전제로 한다. 현재 로컬 저장은 개발용 구현이다. |

현재 RiftMap.cs는 위치가 고정된 8개 방과 고리 통로를 사용한다. CombatSimulation.cs는 테마와 적의 위치·종류 일부를 무작위로 고르고, 정해진 방에 보스를 생성한다. 따라서 현재 빌드의 무작위 적 배치는 이 문서에서 요구하는 절차적 지도 생성의 완료 증거가 아니다.

## 2. 한 판의 구성과 변화 범위

### 2.1 생성 단위

**신규 시험안:** 한 판은 하나의 테마와 6–8개 방 인스턴스로 구성한다. 테마당 6개 템플릿을 모두 한 번씩 선택한 다음, 7–8번째 방은 보스 광장을 제외한 템플릿에서 추가한다. 같은 템플릿은 한 판에 최대 2회만 사용하고, 반복 인스턴스에는 서로 다른 회전과 장애물 구성을 적용한다. '12종'은 한 판의 방 수가 아니라 전체 제작할 템플릿 수다.

| 변화 축 | 판마다 달라질 내용 | 재접속 시 보존할 내용 |
|---|---|---|
| 테마 | 묘지 또는 성채를 선택한다. 초기 가중치는 1:1로 시작한다. | 선택한 테마와 장식 변형을 보존한다. |
| 연결 구조 | 6·7·8방, 고리 순서, 추가 연결 0–2개, 고리의 모양과 통로 길이를 바꾼다. | 방 그래프와 모든 연결구를 보존한다. |
| 방 배치 | 템플릿 순서, 0·90·180·270도 회전, 추가 방의 종류를 바꾼다. | 인스턴스 ID·위치·회전·템플릿 버전을 보존한다. |
| 내부 지형 | 검증된 장애물 배치 3종 이상 중 하나를 선택한다. | 충돌·시야·착지 차단 정보를 보존한다. |
| 일반 적 | 무리 위치, 규모, 근접·원거리·지원·돌진 조합을 바꾼다. | 개체 ID, 남은 HP, 행동과 처치 여부를 보존한다. |
| 정예 | 배치할 무리, 베이스 적, 특성과 허용 조합을 바꾼다. | 특성·연결 대상·내부 타이머를 보존한다. |
| 보상 지점 | 상자 위치, 상자 유형, 어느 낡은 상자가 장비 추첨권을 갖는지 바꾼다. | 상자 상태와 확정된 보상을 보존한다. |
| 성소·이벤트 | 없음 또는 허용된 선택 요소를 배치한다. | 사용 여부·진행도·효과 잔여시간을 보존한다. |
| 보스 | 보스 종류와 광장 내 유효 생성점을 선택한다. | 보스 ID·생성점·HP·패턴 상태를 보존한다. |

새 판의 시드가 다르다는 사실만으로 구성이 달라졌다고 판정하지 않는다. 방 템플릿의 순서·연결 간선·회전·장애물 배치에서 계산한 구조 식별값이 직전 판과 같으면 생성 후보를 다시 고른다. 같은 구조에서 적 좌표만 조금 바뀐 결과는 이 검사를 통과하지 못한다. 추가 연결 수와 방 수가 실제로 다양하게 발생하는지도 통계로 확인한다.

같은 테마가 연속으로 등장하는 것은 허용한다. **신규 제안:** 보스 3종은 각 테마에서 모두 사용할 수 있게 외형 장식만 맞추고, 같은 영웅의 직전 판 보스를 제외한 2종을 같은 가중치로 추첨한다. 직전 판 기록이 없으면 3종을 같은 가중치로 고른다. 패턴과 피격 영역은 테마에 따라 바꾸지 않는다. 이 규칙은 현재 단계에 따라 보스를 순환하는 개발용 방식의 대체안이다.

### 2.2 연결 구조와 도달성

**신규 시험안:** 기본 고리에 추가 연결을 붙인다. 각 방의 실제 사용 출입구는 2개 이상이며, 템플릿의 제공 출입구 수를 초과하지 않는다. 그래프 전체는 연결되고, 어느 연결 하나를 제거해도 두 구역으로 분리되지 않아야 한다. 장식용 출입구는 벽이나 철창으로 명확히 닫아 실제 길처럼 보이지 않게 한다.

통로가 교차해 같은 높이에서 길이 합쳐지면 그 교차점도 경로 그래프에 등록한다. 단순히 메시만 교차시키고 연결을 누락하지 않는다. 초도 범위에는 층 이동, 사다리, 점프 전용 길, 잠긴 필수 문, 일방통행을 넣지 않는다. 선택 상자도 두 출구 사이의 순환 동선에 배치하고 보상만 있는 긴 막다른 가지를 만들지 않는다.

다음 조건을 모두 통과해야 입장을 허용한다.

1. 모든 방·사용 출입구·상호작용 지점에 시작점에서 걸어갈 수 있어야 한다.
2. 방 내부에서도 사용 출입구끼리 연결되어야 한다. 장식물 때문에 길이 끊기거나 좁은 목이 생기면 실패다.
3. 접근 가능한 기본 적의 게이지 합이 최소 150이어야 한다. 상자 개봉, 선택 이벤트, 보스 소환 부하를 이 수량에 포함하지 않는다.
4. 보스 생성점과 회피 공간이 유효해야 한다. 캐릭터가 서 있는 지점에 보스를 겹쳐 생성하지 않는다.
5. 상자·성소는 실제 열기 위치까지 도달할 수 있어야 한다. 장식 메시의 중심점에 닿는 것으로 검사하지 않는다.
6. 통로, 시야와 투사체를 각각 검사한다. 보행 영역이 같다는 이유로 세 판정을 같은 함수로 처리하지 않는다.

## 3. 방 템플릿 12종의 제작 계약

### 3.1 공통 공간 규격

아래 좌표와 치수는 **신규 제작 시험값**이며 Unity 1단위를 1m로 해석한다. 방 로컬 원점은 보행면 중심, X는 동서, Z는 남북으로 둔다. 회전 전 좌표를 기준으로 출입구의 바깥 방향은 W·E·S·N으로 표시한다.

| 항목 | 초도 규격 |
|---|---|
| 영웅 탐색 프로필 | 반지름 0.45m, 높이 1.8m로 시작한다. 일반·정예의 충돌 크기는 별도 프로필로 검증한다. |
| 출입구·통로 | 유효 폭 3m 이상, 유효 높이 2.5m 이상으로 만든다. 문턱·장식으로 이 폭을 침범하지 않는다. |
| 방 안의 주요 우회로 | 충돌 경계를 제외하고 폭 4m 이상을 확보한다. 출입구 앞 3m 구간에는 충돌 장식물을 두지 않는다. |
| 시작 안전 구역 | 시작점 반경 6m에 적·상자·성소·위험 장판을 두지 않는다. 첫 무리의 가장 가까운 적까지 경로 거리는 10m 이상으로 시작한다. |
| 적과 출입구 | 무리 중심은 사용 출입구에서 4m 이상 떨어뜨린다. 원거리 적이 통로 전체를 즉시 덮는 방향을 피한다. |
| 상호작용 공간 | 상자 앞에 2×2m의 접근 공간과 최소 2개 열기 위치를 둔다. 진행 중 다른 개체가 한 위치를 막으면 다른 위치를 선택할 수 있다. |
| 보스 광장 | 중심 반경 8m를 고정 장애물 없이 확보한다. 외곽으로 이어지는 폭 4m 이상의 회피 경로 2개를 보장한다. |
| 이동기 | 통행·착지·시야·투사체 차단 태그를 분리한다. 벽 관통이 허용되지 않은 이동기가 방을 건너뛰지 못하게 한다. |
| 장식 | 비충돌 장식과 실제 충돌 장식을 구분한다. RM10 화로 장식에는 피해·위험 태그를 붙이지 않는다. |

### 3.2 템플릿별 계약

표의 출입구 좌표는 (X, Z)다. 장애물 변형은 예시 3종을 실제 자산으로 만들고 각각 도달성 검사를 통과시킨다. 숨은 임의 좌표에 장애물을 뿌리는 기능은 초도 범위에서 제외한다.

|---|---|---|---|
| RM01 둥근 납골실 | 16×16m. W(-8,0), E(8,0)다. | 기둥을 남북에 배치하거나, 대각선에 배치하거나, 외곽으로 이동한다. | 중앙 반경 4m를 비운다. 무리 앵커 4개와 상자 후보 2개를 제공한다. |

RM06·RM12는 해당 테마에서 한 번만 사용한다. 실제 보스 생성점은 중심 한 곳과 중심에서 6m 떨어진 사방의 대체점으로 구성한다. 보스 활성화 때 영웅과 최소 6m 떨어지고 보행 공간이 유효한 점을 고른다. 보스 몸체 반지름의 시작값은 1.2m이며 대체점에서도 중심 반경 8m의 안전 공간 안에 몸체가 들어가야 한다. 일시적으로 모든 후보가 다른 개체에 막혔으면 보스는 피해를 줄 수 없는 예고 상태로 최대 2전투 초 대기한 뒤, 영웅을 움직이거나 회복시키지 않고 유효한 후보를 다시 선택한다. 계속 실패하면 정상 전투로 진행하지 않고 생성 오류로 기록한다. 생성 시의 정적 검증과 활성화 시의 동적 검증을 분리한다.

**신규 장애 처리 시험안:** 2전투 초 뒤에도 보스를 생성하지 못하면 서버가 해당 판을 장애 중단 상태로 확정한다. 이미 진행된 시간은 되돌리지 않고, 그 시점의 제한시간·영웅·적·드롭·효과·상자·개봉 요청·보상 영수증을 함께 보존한 뒤 전투 시간을 멈춘다. 장애 대기를 앱 미실행 보상 시간으로 계산하지 않는다. 이 상태는 영웅의 패배나 시간 초과가 아니므로 연속 실패 횟수·실패 기록을 늘리지 않으며, 보스 보상·초회·실클리어를 자동 지급하지 않는다. 이미 확정된 획득물과 지급 기록은 유지한다.

복구 권한은 서버가 가진다. 클라이언트의 재시도는 같은 runId와 장애 ID의 복구 결과를 조회·요청하는 동작이며 새 시드·보상·HP·제한시간을 만드는 동작이 아니다. 서버는 같은 명세와 확정 상태에서 생성점 유효성을 다시 검사한 뒤 재개하거나, 복원이 불가능하면 장애로 판을 종료한다. 장애 종료에서도 이미 확정한 보상은 잃지 않고 미발생 보상은 지급하지 않으며, 연속 실패 횟수는 유지한다. 이 정산이 끝난 뒤에만 새 판을 시작할 수 있다. 재개·종료 요청도 한 번만 확정하며 재요청으로 다시 보상하거나 별도 재시도 판을 중복 생성하지 않는다.

각 자산은 템플릿 ID·버전, 경계, 사용 가능한 회전, 출입구 ID·좌표·방향·폭, 보행/시야/투사체/착지 태그, 장애물 변형 ID, 무리 앵커·허용 반경·최대 수용 개체, 상호작용 앵커·열기 위치, 시작/보스 가능 여부를 선언해야 한다. 표의 앵커 개수만 맞추고 실제 좌표·공간 검사를 생략할 수는 없다.

## 4. 생성 순서, 실패 복구와 기록

### 4.1 정상 생성 순서

1. 온라인 세션에서 영웅·단계·가방 정책을 검증하고 새 runId를 발급한다. 이전 판의 정리나 보상 확정이 끝나지 않았으면 새 판을 만들지 않는다.
2. 지도 생성 버전, 콘텐츠 버전, 공개 지도 시드와 서버 전용 보상 추첨 키를 고정한다. 하나의 난수 흐름을 장식·전투·보상에 함께 쓰지 않는다.
3. 테마·방 수·템플릿 인스턴스·회전·고리 순서를 선택한다. 시작방은 보스 광장이 아닌 방에서 고른다.
4. 실제 출입구를 배정하고 통로를 연결한다. 방이나 통로가 충돌하면 위치·회전을 다시 배치한다. 고리 완성 후 허용되는 추가 연결 0–2개를 시도한다.
5. 장애물 변형을 선택하고 보행 영역, 시야·투사체 경계와 이동기 착지 영역을 구성한다.
6. 보스 광장과 안전 구역을 예약한다. 시작방 안전 구역과 출입구 앞 공간을 예약한다.
7. 기본 적 150점 이상을 유효 무리 앵커에 배치한다. 선택 상자·이벤트의 존재와 관계없이 100점 달성이 가능해야 한다.
8. 상자 예산·위치·잠금 조건·경비 무리 ID를 결정한다. 성소·선택 이벤트는 남는 허용 앵커에 배치한다.
9. 도달성·폭·수용량·게이지·위험 조합·반복 구조 검사를 실행한다. 생성 결과와 판별값을 저장한 뒤 입장을 확정한다.
10. 화면 전환을 마치고 영웅이 행동을 시작하는 첫 틱부터 300초를 계산한다. 로딩과 생성 검사는 전투 시간에 넣지 않는다.

생성 결과는 단순 시드가 아니라 방 그래프, 인스턴스 배치, 장애물, 적·상자·성소 목록까지 가진 지도 명세로 저장한다. 게임 업데이트 후에도 같은 시드가 다른 지도나 보상을 만들지 않게 한다.

### 4.2 실패 시 대체 생성

**신규 시험안:** 동일 입장 요청 안에서 최대 24개 후보를 검증한다. 후보 인덱스는 별도 파생 시드를 사용하며 재접속 때 0부터 다시 추첨하지 않는다. 24개가 모두 실패하면 테마별로 미리 검증한 6방 대체 지도 3종 중 하나를 선택하고 동일한 기본 적·상자 예산을 적용한다.

대체 지도도 현재 콘텐츠 버전의 검증을 통과해야 한다. 대체 지도까지 실패하면 입장을 확정하지 않고 오류를 표시한다. 제한시간을 소모하거나 무효한 판을 실패 기록에 남기지 않는다. 완료하지 않은 판의 보스 보상·초회 보상을 보상 명목으로 자동 지급하지 않는다.

대체 지도에는 직전 판 구조 중복 회피보다 입장 가능성을 우선한다. 이 예외를 일반 생성 성공으로 숨기지 않고 생성 로그와 검증 보고서에 별도로 표시한다. **품질 목표:** 유효 시드 10,000개당 대체 지도 사용률 0.1% 미만을 목표로 검증하되, 아직 달성했다고 표시하지 않는다.

## 5. 적 무리, 정예와 보스의 배치

### 5.1 기본 전투 예산

**신규 시험안:** 첫 생성기의 기본 예산은 일반 적 110명과 정예 8명으로 고정한다. 정예는 일반 적 목록에서 승격한 별도 개체이며 110명에 중복 계산하지 않는다. 일반 적 1점, 정예 5점이므로 총 150점이다. 이후 밀도 조정은 별도 밸런스 버전으로 관리한다.

| 배치 항목 | 초도 기준 |
|---|---|
| 무리 크기 | 일반 적 3–6명과 정예 0–2명을 한 무리로 묶는다. 방 전체 적을 한 위치에 겹치지 않는다. |
| 시작방 | 일반 적 8–12명만 사용하고 정예를 두지 않는다. 안전 구역 밖의 첫 무리는 근접 중심으로 구성한다. |
| 보스 광장 | 기본 일반 적은 최대 10명, 정예는 0명으로 시작한다. 보스 공간을 예약한 외곽 앵커만 사용한다. |
| 나머지 방 | 남은 예산을 앵커 수·방 넓이에 비례해 분배한다. 정예는 한 방에 최대 2명으로 제한한다. |
| 무리 간 거리 | 중심 경로 거리 6m 이상을 시작값으로 한다. 지형상 여러 무리가 한 번에 붙는 경우도 허용하되 위험 합성 검증을 통과해야 한다. |
| 적의 다양성 | 한 판에 해당 테마의 6종 중 최소 4종을 사용한다. 지원형은 무리당 최대 1명, 돌진·장판·사망 폭발형 합계는 무리의 절반 이하로 시작한다. |
| 재생성 | 처치한 기본 적은 다시 생성하지 않는다. 화면 밖 비활성화는 개체 상태를 보존하는 처리다. |

추천 무리 원형은 '근접 4 + 원거리 1', '근접 3 + 지원 1', '근접 3 + 돌진 1', '근접 3 + 장판 1', '근접 3 + 사망 폭발 1'이다. 무리 원형에서 테마의 실제 N01–N12를 선택하고, 출입구·가림막·사선을 고려해 개별 위치를 바꾼다. 어느 판에서나 한 종류의 원형만 반복되지 않게 최소 3개 원형을 사용한다.

### 5.2 정예 특성의 조합 제한

**신규 시험안:** 단계 1–9에서는 정예당 특성 1개, 10단계부터는 1–2개를 사용한다. 초도 범위에서는 3개 이상을 겹치지 않는다. 특성 수가 늘어도 정예의 기본 게이지·장비 지급을 특성 수만큼 늘리지 않는다.

| 특성 | 배치 계약·금지 조건 |
|---|---|
| E01 추적 화염 | 지속 피해와 예고가 겹쳐도 통행 가능한 안전 지점이 남아야 한다. 초도 버전에서는 같은 개체의 E02와 조합하지 않는다. |
| E02 얼음 고리 | 안쪽과 바깥쪽 중 적어도 하나에 도달 가능한 회피 공간이 있어야 한다. 좁은 통로 중심에 고정 생성하지 않는다. |
| E03 생명 연결 | 서로 다른 정예 2명을 한 쌍으로 생성하며 고정 연결 ID를 저장한다. 둘을 분리할 동선이 없는 배치는 금지한다. 짝이 없는 개체에 적용하지 않는다. |
| E04 사격 방벽 | 정면 방향을 읽을 수 있는 적에만 적용한다. 자폭·사망 폭발형에 적용하지 않는다. 후방으로 접근할 보행 경로가 있어야 한다. |
| E05 시체 폭발 | 주변에 기본 일반 적 4명 이상이 있는 무리에서 사용한다. 이미 폭발한 사체를 다시 폭발시키지 않는다. 시체 소비 상태를 저장한다. |
| E06 분노 축적 | 장기 생존이 의미 있는 적에 적용한다. 자폭·사망 폭발형은 제외하고, 누적량을 화면 밖 이동이나 재접속으로 초기화하지 않는다. |

개별 피해량·반경·내부 대기시간은 전투 상세 명세가 결정한다. 이 문서의 배치 제한은 기존 콘텐츠 명세에 정의된 패턴의 수치나 작동 방식을 임의로 대체하지 않는다.

### 5.3 보스 활성화

게이지 100을 충족한 틱에 보스 등장 상태를 한 번만 확정한다. 보스 방은 입장 때 이미 선택되어 있으며, 해당 방을 발견했는지와 관계없이 방향 표식과 남은 경로를 표시한다. 보스 활성화로 제한시간을 초기화하거나 기존 일반 적을 지우지 않는다.

일반 적의 추가 생성과 아직 시작하지 않은 선택 이벤트는 이때 중단한다. 이미 있는 상자·성소와 기본 적은 유지한다. 기본 자동 우선순위는 보스 접근으로 바뀌며, 사용자가 '보스 등장 후에도 발견한 상자 회수'를 켠 경우에만 상자 우회 정책을 적용한다. 신규 기본값은 꺼짐이다.

보스 소환 부하는 기본 적 150점과 분리하고 모든 일반 보상을 0으로 고정한다. 소환 부하의 처치로 발동하는 영웅 효과를 허용할지는 각 전투 효과의 정의를 따르며, 보상 0을 이유로 전투 효과까지 일괄 제거하지 않는다. 보스 재생성, 부하의 정예 승격, 클리어 직전 입장 복원으로 인한 두 번째 보스 보상은 허용하지 않는다.

## 6. 시야, 미니맵과 자동 탐색

### 6.1 발견 규칙과 화면

**기존 시험값 유지:** 적·드롭·상호작용 지점은 기본 12m 감지 반경과 시야 검사를 사용한다. 발견한 방과 통로를 미니맵에 누적 표시하고, 벽 뒤의 미발견 적·상자 위치는 공개하지 않는다. 발견 후 시야를 벗어난 적은 마지막 발견 위치만 기억하며 현재 위치를 계속 알려 주지 않는다.

방에 진입하면 보행 형태와 사용 출입구를 지도에 표시하되, 방 안의 적·상자 발견은 개별 감지를 따른다. 미발견 출구 너머는 열린 길의 표시까지만 한다. 보스 활성화는 예외로 목적지와 연결 경로를 알려 준다.

미니맵은 영웅, 탐색 완료/미완료 출구, 발견한 정예, 잠김/열림/사용 완료 상자, 성소, 보스 방향을 구분한다. 작은 화면에서는 색만으로 구분하지 않고 아이콘 형태를 함께 사용한다. 미니맵 터치는 확대·정보 열기이며 수동 이동 명령으로 바꾸지 않는다.

### 6.2 탐색 정책

기존 '왼쪽 벽 따라가기 / 오른쪽 벽 따라가기 / 가장 가까운 미탐색 영역 / 감지한 적 추적'을 유지한다. 방 중심을 순서대로 도는 현재 구현을 방·출입구·관찰 지점을 가진 탐색 상태로 대체한다.

| 정책 | 선택 방법 | 공통 복구 |
|---|---|---|
| 왼쪽·오른쪽 벽 따라가기 | 사용한 출입구 방향을 기준으로 지정 쪽의 다음 유효 출구를 고른다. 이미 한 바퀴 돌았는지 방문 기록으로 판단한다. | 반복되는 출구 상태를 감지하면 가장 가까운 미탐색 분기로 전환한다. |
| 가장 가까운 미탐색 영역 | 알려진 그래프의 실제 경로 길이가 가장 짧은 미탐색 관찰 지점을 고른다. | 관찰 지점이 막히면 같은 구역의 다른 관찰 지점을 고른다. |
| 감지한 적 추적 | 시야 안의 유효 적을 목표 정책에 따라 고른다. | 유효 적이 없거나 마지막 발견 지점까지 확인했으면 가까운 미탐색 영역으로 전환한다. |

선정 점수가 같으면 위험도, 실제 경로 거리, 고정 ID 순으로 결정한다. 목표 유지 0.6초와 거리 판정 여유 ±0.75m라는 기존 시험값을 유지한다. 더 높은 생존 행동, 목표 사망, 경로 무효화는 유지 시간을 기다리지 않고 목표를 바꿀 수 있다.

**신규 복구 시험값:** 이동을 지시했는데 2전투 초 동안 0.5m 미만 이동하면 현재 경로를 다시 구한다. 같은 목표에 3회 연속 실패하면 그 목표를 5전투 초 보류하고 다른 출구나 열기 위치를 선택한다. 보류 시간이 끝나거나 경로의 장애물·문 상태·목표 위치가 실제로 바뀌면 다시 유효성을 검사한다. 시간이 끝났다는 이유만으로 불가능한 경로를 강제로 선택하지 않는다. 벽 따라가기에서 같은 출입구·진행 방향을 3회 방문하면서 새 발견이 없으면 미탐색 분기로 전환한다. 모든 접근이 실패하면 자동 반복을 멈추고 경로 오류를 보고한다. 영웅을 벽 너머로 순간이동하거나 HP·시간을 재설정해 문제를 숨기지 않는다.

시전·채널·상자 개봉·제자리 전투·일시정지·포탈 정리처럼 의도적으로 이동을 멈춘 시간에는 위의 막힘 누적을 진행하지 않는다. 전투 중 벽 뒤로 사라진 목표는 마지막 발견 위치와 유효 사거리 위치를 먼저 재계산한다. 생존을 위한 회피 후보가 하나도 없는 경우는 일반 목적지 막힘과 분리해 '유효 회피 지점 없음'으로 기록하고, 다음 방어·공격 규칙을 평가한다. 해당 상태를 임의 순간이동으로 해결하지 않는다.

게이지가 100 미만인데 모든 알려진 영역을 확인한 경우, 남은 기본 적의 서버 상태와 탐색 누락 여부를 검사한다. 적을 공짜로 처치 처리하거나 게이지를 강제로 채우지 않는다. 실제로 도달 가능한 미탐색 관찰 지점을 다시 제공하고, 생성 명세 자체가 깨졌다면 장애 사례로 기록한다.

## 7. 보물 상자의 자동 행동과 상태

### 7.1 상자의 역할과 수량

상자는 방 안의 장식이 아니라 획득 우선순위와 탐색 시간을 비교하게 만드는 자동 상호작용 대상이다. 새로운 열쇠 재화, 수동 자물쇠 퍼즐, 광고 개봉과 유료 재추첨은 초도 범위에 넣지 않는다.

**신규 시험안:** 상자 총수는 방 수 6/7/8개일 때 각각 4/5/6개다. 시작방에는 배치하지 않고, 시작점에서 그래프 거리 2방 이상이면서 보행 경로 45m 이상인 후보만 사용한다. 서로 다른 방에 먼저 하나씩 배치한 후 남은 상자를 분산한다. 한 방에는 최대 2개를 둔다.

| ID·유형 | 발생 수와 조건 | 개봉 조건·시간 | 보상 특성·구현 차수 |
|---|---|---|---|
| CH01 낡은 보물 상자 | 6/7/8방에서 기본 3/4/5개다. CH03이 등장하면 이 중 하나를 대체한다. | 게이지 30 이상에서 봉인이 풀린다. 유효 위치에서 1전투 초 동안 개봉한다. | 골드 배정분과 선택된 상자에만 장비 1개를 준다. 초도 구현에 포함한다. |
| CH02 수호자의 봉인 상자 | 판당 1개다. 정예가 배치된 방에 둔다. | 게이지 70 이상이고 연결된 경비 무리가 모두 죽어야 한다. 개봉에는 1.5전투 초가 걸린다. | 골드·일반 재료와 장비 1개를 준다. 경비는 기본 적 예산에 포함한다. 초도 구현에 포함한다. |
| CH03 저주받은 보물 상자 | 5단계 이상에서 판당 25% 확률로 CH01 하나를 대체하는 시험안이다. | 게이지 70 이상에서 접근하면 선택 이벤트를 시작한다. 완료 후 1.5전투 초 동안 개봉한다. | 별도 보상 예산을 추가하지 않고 두 번째 장비 추첨권과 골드 분배 비중을 받는다. 기본 상자 검증 뒤 2차로 구현한다. |

게이지 잠금은 외형과 미니맵에 표시하고 자동 행동은 잠긴 상자 앞에서 기다리지 않는다. 잠금 해제 이벤트가 발생하면 이미 발견한 상자를 추적 후보에 다시 넣는다. 상자의 정체와 종류는 발견하면 알 수 있지만 아이템 종류·등급·접사 결과는 개봉 전에 공개하지 않는다.

### 7.2 자동 개봉 정책

**신규 제안:** 행동 설정에 '상자 사용 여부', '안전할 때만 열기 / 전투 중에도 허용', '추적 가능한 상자 유형', '상자까지의 최대 우회 거리', '보스 등장 후 회수'를 추가한다. 기본값은 사용, 안전할 때만 열기, 초도 2유형 모두, 우회 거리 12m, 보스 등장 후 회수 안 함이다. 개봉 후 장비는 기존 획득 허용·추적 허용·우선순위를 그대로 적용한다.

상자에 장비가 들어 있을 수 있다는 사실과 실제 드롭 장비의 등급 조건을 혼동하지 않는다. 예를 들어 '전설만 추적'이라는 바닥 장비 설정만으로 미개봉 상자가 자동 제외되지는 않는다. 미개봉 상자 추적은 상자 정책이 담당한다.

기본 '안전할 때만' 조건은 인지한 교전 대상 없음, 개봉 위치 반경 3m에 현재 또는 예고된 적 위험 없음, 직전 1전투 초 동안 피격 없음으로 시작한다. 이는 화면 밖 적이 절대 공격하지 못한다는 보장이 아니며, 접근 중 적을 감지하면 전투 정책을 다시 평가한다.

**신규 중단 규칙:** 생존·회피와 필수 중단 조건을 먼저 평가한다. 피격, 강제 이동, 기절·빙결, 유효 위치 이탈, 네트워크 중단은 개봉을 취소한다. 중단하면 개봉 진행도는 0으로 돌아가지만 상자 보상 내용은 바뀌지 않는다. 다시 시도하려면 2전투 초가 지나야 한다. 독립 물약 사용은 이동이나 개봉을 취소하지 않으며, 물약의 기존 회복 규칙을 따른다.

공격과 개봉의 우선순위는 사용자가 정한 행동 순서를 따른다. '안전할 때만' 설정에서는 교전 대상을 인지하면 개봉을 시작하지 않거나 중단한다. '전투 중에도 허용' 설정에서는 일반 공격이 가능해졌다는 이유만으로 개봉을 자동 취소하지 않는다. 공격보다 개봉이 앞선 순서라면 개봉 동안 주 행동을 잠그고, 뒤에 있는 공격은 개봉이 끝난 뒤 평가한다. 개봉보다 앞선 공격 규칙이 유효해지면 그 공격이 개봉을 중단할 수 있다. 잠금은 생존·회피·필수 중단 조건과 독립 물약을 막지 않는다. 이미 시작한 공격은 그 공격에 정의된 중단 가능 구간에서만 개봉으로 전환한다.

사용자가 전투 중 개봉을 허용해도 사망·하드 제어·범위 이탈을 무시할 수는 없다. 이 선택은 획득을 공격보다 우선할 수 있게 하는 설정이지 무적 상태를 부여하는 설정이 아니다.

### 7.3 상태 전이와 중복 방지

| 상태 | 의미와 다음 처리 |
|---|---|
| Locked / Available | 생성된 상자는 잠금 조건에 따라 개봉 가능 여부를 가진다. 아직 발견하지 못한 경우도 서버 상태는 존재한다. |
| Approaching | 한 자동 행동이 상자 ID를 목표로 예약하고 유효 열기 위치로 이동한다. 같은 영웅의 다른 행동은 같은 상자를 중복 예약하지 않는다. |
| Opening | 유효 거리 1.5m 이내에서 개봉 시간을 진행한다. 중단되면 Available로 돌아간다. |
| OpeningCommitPending | 마지막 틱에서 개봉 요청을 보냈다면 응답 전까지 다시 요청 ID를 만들지 않는다. 연결 복구 후 같은 요청의 결과를 조회한다. |
| Opened | 상자 지급 영수증을 확정하고 골드·재료를 지급한다. 장비는 고유 드롭 ID를 가진 바닥 물건으로 생성한다. |
| Exhausted | 생성한 장비가 획득·무시·포기 상태로 모두 정리된 상태다. 다시 열 수 없다. |

상자 ID는 runId와 고정 생성 인덱스로 만든다. 개봉 요청 키는 runId + chestId + open이다. 하나의 확정 처리에 개봉 완료, 재화 지급 영수증, 장비 생성 목록을 묶고, 재요청에는 같은 결과를 돌려준다. 계정의 전투 세션 소유권은 한 기기에만 부여하므로 여러 기기가 같은 상자를 각자 여는 상황을 정상 동작으로 허용하지 않는다.

개봉 애니메이션 완료만으로 재화를 먼저 지급하지 않는다. 반대로 지급을 확정한 뒤 화면 전환에 실패하더라도 상자를 다시 닫힌 상태로 복원하지 않는다. 재화는 개봉 영수증, 장비는 드롭 수령 영수증으로 각각 중복을 막는다.

### 7.4 가방 부족, 종료와 미개봉 상자

상자는 가방이 가득 차도 열 수 있다. 골드·일반 재료는 가방을 차지하지 않고, 장비는 바닥에 남긴다. 이후 기존 '포탈 정리 / 낮은 가치 장비 교체 / 획득 무시'를 적용한다. 개봉 전에 임의로 희귀 장비를 버리거나, 가방이 부족하다는 이유로 장비를 골드로 자동 변환하지 않는다.

포탈 정리 시에는 상자, 개봉 진행, 경비 처치, 이벤트 진행, 드롭, 위험 효과를 함께 정지·저장한다. 포탈 정리로 해당 균열의 상자를 초기화하거나 회복 기회를 주지 않는다. 정리 상태에서는 장비 장착·강화·스킬 교체를 허용하지 않는 기존 제한을 유지한다.

**신규 제안:** 보스 처치로 전리품 정리 상태에 들어가면 미개봉 상자·미사용 성소·미완료 선택 이벤트를 종료한다. 정리 시간에는 이미 발생한 바닥 드롭만 회수한다. 제한시간과 위험이 사라진 뒤 모든 상자를 무료로 탐색하는 방식은 탐색 시간의 선택을 없애므로 초도 규칙으로 채택하지 않는다. 결과에는 '상자 개봉 3/5 · 미개봉 2'와 포기한 장비 수를 표시한다.

보스 처치와 개봉 완료가 같은 틱에 발생하면 한 틱의 유효 행동 결과를 모은 뒤 정리 상태를 확정한다. 그 틱에 개봉 완료 조건을 이미 충족한 상자만 지급하고 나머지는 종료한다. 영웅과 보스의 동시 사망은 기존 성공 판정을 유지하며, 이미 발생한 장비는 정리 화면에서 처리한다. 실패·시간 초과·중도 종료에서는 미개봉 상자와 미획득 드롭을 보상으로 전환하지 않는다.

## 8. 상자 보상 표와 파밍 방지

### 8.1 판당 예산

**2026-09-12 적용 범위:** 일반·정예·보스 장비는 [균열 단계별 등급 확률](HELLSCRIPT_Rift_Rarity_Detail.md)을 사용한다. 아래 상자 등급 확률과 판당 예산은 기존 값을 유지하며 단계별 등급 보정에서 제외한다. 소탕은 선택 영웅의 최고 실제 클리어 단계의 보스 확률로 장비 3회를 추첨한다. 실제 전투는 최고 기록과 관계없이 그 판의 `R`을 사용한다.

다음 표와 수치는 모두 **신규 경제 시험안**이다. 원래 적·보스 보상에 필드 상자 수입을 추가하므로 경제 검증이 필요하다. 상자 수가 많아졌다는 이유만으로 한 판의 총 장비·재화가 같은 비율로 증가하지 않게 한다.

| 예산 | 한 판에 미리 예약할 수량 |
|---|---|
| 상자 골드 G | floor(0.15 × (800 + 50R))로 한다. R은 균열 단계다. |
| 상자 일반 재료 M | max(1, floor(0.20 × (5 + floor(R/5))))로 한다. |
| 상자 장비 | 최대 2개다. CH02에 1개, 나머지 CH01 중 무작위 1개 또는 CH03에 1개의 추첨권을 배정한다. 모든 상자를 열면 2개를 얻는다. |
| 경험치·게이지 | 상자 자체에서는 지급하지 않는다. 경비로 배치된 기본 적만 기존 처치 보상을 준다. |
| 기타 재화 | 부위 코어·보석·신규 상자 전용 재화는 초도 상자 표에 넣지 않는다. 이후 해당 시스템의 검증된 획득 표에서 명시적으로 추가한다. |

CH02에 G의 절반을 내림해 배정하고 M 전체를 배정한다. 나머지 골드는 CH01에 가중치 1씩 분배한다. CH03이 있다면 그 상자의 가중치를 2로 처리한다. 나눗셈의 정수 잔여량은 상자 고정 ID 순서로 1씩 더해 총량을 보존한다. CH03이 없으면 CH01 중 하나를 동일 가중치로 골라 두 번째 장비 추첨권을 배정한다. CH03이 있으면 두 번째 추첨권을 그 상자에 배정한다.

이 수량은 생성 시 예약하는 예산이며, 개봉할 때마다 새 수량을 추가로 뽑는 독립 확률이 아니다. 어떤 상자를 먼저 열었다는 이유로 다른 상자의 이미 정해진 내용이 사라지지 않는다. 플레이어에게 '판당 제한 소진' 같은 임의 차단을 보여 주는 방식도 사용하지 않는다.

| 장비가 배정된 상자 | 마법 | 희귀 | 전설 계열 | 비고 |
|---|---:|---:|---:|---|
| CH01 | 80% | 19% | 1% | CH01마다 장비를 독립 추첨하지 않는다. 장비 추첨권이 배정된 하나만 이 표를 사용한다. |
| CH02 | 60% | 38% | 2% | 판당 1개의 장비를 이 표로 생성한다. |
| CH03 | 60% | 38% | 2% | CH01에 갈 두 번째 장비를 대체한다. 보상 1개를 추가하는 규칙이 아니다. |

장비의 아이템 레벨은 기존 max(1,R−2)부터 R+2까지 균등 정수 추첨을 사용한다. '전설 계열' 결과 이후의 직업·부위·세트/전설 후보, 접두사·접미사, 고유 효과 추첨은 장비 상세 명세의 단일 생성 절차를 호출한다. 여기서 전설과 세트를 각각 한 번씩 추첨하지 않는다. 상자는 장비 생성 규칙의 별도 우회 경로가 되어서는 안 된다.

예를 들어 1단계에서 모든 상자를 열면 골드 127, 일반 재료 1, 장비 2개를 얻는다. CH01+CH02의 전설 계열 기대 수량은 0.01+0.02=0.03개이며, 보스 장비 3개의 1단계 기대 수량 0.45개와 구분된다. 다른 단계에서는 보스 기대 수량을 `3×해당 단계 보스 전설 확률`로 계산한다. 이는 기대 개수이며 전설을 1개 이상 얻을 확률 `1−(1−p)^3`과 다르다. 첫 클리어 보상은 이 계산에서 제외한다. 이 예시는 설계상 기대값이며 측정된 실제 수입이 아니다.

### 8.2 반복 입장·재접속 악용과 정상 중도 종료

재접속은 같은 판을 복원하므로 상자·보스·드롭을 다시 추첨하지 않는다. 새 판은 새로운 지도를 만들지만, 시작방 상자 미배치·거리 제한·게이지 잠금·유한 예산 때문에 입장만 반복해서 상자 보상을 받을 수 없게 한다. 시작방의 기본 적은 기존 처치 보상을 정상 지급한다. CH02의 경비는 다시 생성되지 않으며, CH03의 이벤트 실패·재접속도 보상을 재충전하지 않는다.

기존 '실패해도 이미 획득한 물건 유지'를 보존하므로, 어느 정도 사냥한 뒤 일부 상자를 얻고 포기하는 행동 자체를 무효화하지는 않는다. 이를 막겠다고 실패 시 보상을 회수하거나, 숨은 입장세·일일 상자 제한을 추가하지 않는다. 목표는 **상자만 노리고 중도 종료하는 방식의 장기 시간당 가치가 정상 보스 클리어보다 높아지지 않게 만드는 것**이다.

**검증 목표:** 동일 단계·빌드·장비에서 '게이지 30 뒤 가까운 상자만 열고 종료', '70 뒤 봉인 상자까지 열고 종료', '보스 직행', '발견한 상자를 회수하며 클리어'를 비교한다. 기본 검사는 직접 지급한 골드, 일반 재료, 전설 계열 장비 개수의 시간당 수입을 서로 독립적으로 비교한다. 초회 보상은 제외하고 로딩·정리·개봉 시간을 실제 세션 시간에 포함한다. 1배·1.5배·2배를 모두 측정한다.

초기 합격 목표는 상자만 노리는 두 중도 종료 정책의 장기 골드 수입과 일반 재료 수입이 각각 정상 클리어 정책의 70% 이하인 것이다. 전설 계열 획득률은 정상 클리어 정책을 초과하지 않아야 한다. 어느 하나라도 기준을 넘으면 다른 수입이 낮다는 이유로 합격시키지 않는다. 기준을 넘으면 시험값인 잠금 게이지·위치·장비 가중치·상자 예산을 조정한다. 이를 검증하기 전에는 '상자 리셋 파밍 방지 완료'라고 표시하지 않는다.

장비의 판매·분해까지 반영한 환산 분석은 보조 지표로 구분한다. 분석이 필요하면 사용한 콘텐츠·경제 버전과 골드/재료 환산표를 실험 전에 고정하고 보고서에 공개한다. 동일 장비를 판매한 골드와 분해한 재료를 한 번의 수입에 동시에 더하지 않는다. 환산표가 정해지지 않은 단계에서는 임의 환율로 70% 기준을 판정하지 않고 위의 독립 지표만 사용한다.

## 9. 짧은 이벤트·성소와 보류할 확장

### 9.1 초도 선택 요소

상자 핵심 흐름이 안정된 뒤 성소 2종을 넣는 것을 제안한다. 성소는 판당 0–1개이며 등장 확률 50%, 시작방과 보스 광장을 제외한 유효 후보에 배치한다. 개봉 정책과 같은 접근·중단 규칙으로 0.5전투 초 동안 사용하고, 사용 후 다시 충전하지 않는다. HP 회복·자원 완충·재사용 대기시간 초기화 성소는 초도 범위에서 제외한다.

| ID·성소 | 신규 효과 시험값 | 행동 설계와의 관계 |
|---|---|---|
| SH01 길잡이의 성소 | 20전투 초 동안 비전투 이동속도 +15%를 준다. 비전투 여부는 장비 상세 기획의 LC01과 같은 판정을 사용하며, 성소 보너스는 비전투 탐색·회수 이동에 적용한다. | 탐색·획득 동선을 단축하지만 공격·회피 성능을 직접 대체하지 않는다. |
| SH02 결의의 성소 | 20전투 초 동안 버프 피해 감소 구간에 10%p를 더한다. 다른 버프 피해 감소와 합산한 뒤 해당 구간의 50% 상한을 적용한다. | 위험한 무리 진입을 돕는다. HP·보호막을 즉시 회복시키지 않는다. |

성소는 사용 여부와 종류별 추적 여부를 설정할 수 있고 기본값은 안전할 때 사용이다. 효과 시간은 배속을 적용하며 일시정지·포탈 정리·앱 중단 동안 멈춘다. 같은 성소 효과는 중첩하지 않고, 해당 판이 종료되면 제거한다. 성소 효과를 마을·훈련·새 판으로 이월하지 않는다. SH01의 이동 증가도 장비 상세 기획의 전체 이동 증가 합산·50% 상한을 따른다. SH02의 버프 피해 감소는 방어도·저항의 감소 구간과 분리하며 임의의 독립 배율을 추가하지 않는다.

### 9.2 2차 구현할 저주 상자 이벤트

**신규 제안:** CH03의 '잔향 진압'은 캐릭터가 자동 접근해 시작하는 짧은 전투다. 4마리의 잔향을 미리 검증한 앵커에 한 번만 생성하고, 12전투 초 안에 처치하면 상자를 개봉할 수 있다. 이 적은 게이지·경험치·골드·장비를 주지 않고 판당 기본 적 150점에도 포함하지 않는다. 기존 보스 소환 부하와 같은 보상 없음 태그를 사용하되 종류 ID는 구분한다.

이벤트는 전투 전체의 300초 안에서 진행한다. 별도 시간 정지·완료 후 전원 회복·시간 연장은 없다. 영웅이 현장을 벗어나도 시간은 흐르고, 실패하면 해당 상자는 그 판에서 다시 시도할 수 없다. 미완료 보상은 다른 상자로 옮기지 않는다. 보스가 등장하면 새 이벤트를 시작하지 않으며 이미 진행 중인 이벤트는 계속 진행한다. 보스 처치·판 종료 시 이벤트도 종료한다.

이벤트를 허용할 자동 정책과 남은 시간 기준을 별도로 제공한다. 기본값은 참여 안 함으로 두고, 참여를 켠 경우에도 남은 시간이 90초 이상일 때만 시작하는 시험안이다. 상자 2종과 보스 진행을 먼저 검증한 뒤 선택 기능으로 개발한다.

| 상인 출현·재화 베팅 | 필드에서 경제적 선택을 만든다. | 자동 구매 권한과 비용 정책이 없으므로 초도에서 제외한다. |

## 10. 시드·저장·재접속·재도전의 차이

| 상황 | 지도와 시간 | 보상과 영웅 상태 |
|---|---|---|
| 새 균열 진입 | 새 runId·지도 시드·보상 추첨 키·지도 명세를 만든다. 첫 행동부터 300초를 시작한다. | 기존 신규 진입 규칙대로 HP·자원·CD·버프를 초기화한다. 새 판의 유한 보상 예산을 갖는다. |

| 가방 포탈 정리 | 지도·전투·개봉·이벤트·효과 시간을 모두 보존한다. | 판매·분해·창고 이동을 허용한다. 무료 회복·장착 변경·강화·스킬 교체는 허용하지 않는다. |
| 앱 종료·백그라운드 중단 | 마지막으로 확정한 판 상태를 보존한다. 운영체제가 중단한 동안 실시간 사냥을 계속했다고 계산하지 않는다. | 온라인 복귀 후 같은 runId를 재개한다. 서버가 인정한 앱 미실행 구간만 기존 계정 규칙으로 별도 정산한다. |
| 전경 앱의 통신 단절·응답 대기 | 전경에서 연결만 끊긴 경우 마지막 확정 틱에서 전투를 멈추고 같은 runId의 연결 복구를 기다린다. | 통신 대기 시간을 앱 미실행 보상으로 계산하지 않는다. 미확정 개봉·보상 요청은 새 ID로 재발급하지 않고 기존 요청의 결과를 조회한다. 이후 앱이 실제로 중단되면 서버가 인정한 그 시점부터 미실행 구간으로 전환한다. |
| 기기 인계 | 새 기기가 같은 권위 상태를 받은 뒤 세션 소유권을 얻는다. | 이전 기기는 더 이상 그 판의 처치·개봉·지급을 확정할 수 없다. |
| 소탕 | 지도를 생성하지 않는다. | 영웅 최고 실클리어 단계의 보스 반복 보상만 지급한다. 상자·필드 이벤트·성소·일반 적·초회·경험치를 지급하지 않는다. |
| 개발용 시드 재생 | 생성 버전과 지도 명세를 지정해 같은 지형·배치를 재현한다. | 실제 계정 보상·실클리어·초회에는 반영하지 않는다. 플레이어의 재추첨 기능으로 공개하지 않는다. |

저장 자료에는 runId, 영웅·세션 소유권, 단계, 생성/콘텐츠/경제 버전, 지도 시드와 지도 명세, 난수 흐름별 상태, 전투 틱, 영웅·적·투사체·장판·상태이상, 처치 게이지, 탐색 방문/발견 상태, 상자/성소/이벤트 상태, 미획득 드롭, 보상 영수증과 미확정 요청을 포함한다. '생성 시드만 저장하고 개봉할 때 다시 추첨'하는 구현은 허용하지 않는다.

장식 난수, 적 배치 난수, 전투 난수, 보상 난수를 분리한다. 화면 렌더링·입자 효과·위험 예고의 흔들림·장식 애니메이션이 전투나 보상의 난수를 소모해서는 안 된다. 클라이언트에 공개한 지도 시드만으로 서버 전용 보상 결과를 계산할 수 있게 만들지 않는다. 개발용 재현 자료와 공개 서비스의 보상 권위는 다른 경로로 관리한다.

업데이트에서는 진행 중인 판이 참조하는 이전 콘텐츠를 재개·정리할 수 있게 보존하거나 검증된 이전 명세 변환을 제공해야 한다. 버전 불일치 때 다른 방·상자·보스를 새로 생성해 같은 판이라고 취급하지 않는다. 이전 판의 복원 정책이 없는 업데이트는 공개 배포 검증을 통과시키지 않는다.

## 11. 구현 전에 준비할 자료와 개발 순서

| 차수 | 작업 | 완료 산출물·선행 조건 |
|---|---|---|
| R0 규격 고정 | 방 12종의 연결구·앵커·차단 태그, 무리 표와 상자 예산을 데이터로 정리한다. | 모든 표의 ID와 수치 출처를 가진 자료를 만들고, 충돌하는 기존 문서의 시험값을 같은 버전으로 갱신한다. |

| R4 상자 핵심 | CH01·CH02, 자동 개봉·중단·미니맵·정산·가방 정책을 연결한다. | 전투 중단·동시 틱·재접속·포탈·가방 부족에서 보상 수량이 보존된다. |

시각 자료는 테마별 바닥·벽·장식 재질, 방 12종의 회전·변형, 상자 닫힘/봉인/개봉/소진 상태, 성소 2종, 미니맵 아이콘, 경로 표시·발견·봉인 해제·보스 등장 효과가 필요하다. 배경·아이콘·재질용 원화는 내장 이미지 생성기를 활용하되, 실제 충돌·통행·피격 판정은 별도 데이터로 만든다. 상자는 간단한 상자 몸체와 뚜껑 회전, 성소는 하나의 몸체와 빛 효과로 먼저 검증한다. 골격 애니메이션 제작을 선행 조건으로 삼지 않는다.

## 12. 합격 기준과 관찰 지표

### 12.1 자동 검증

- 테마별 방 수 6·7·8과 모든 템플릿·회전·장애물 변형을 포함한 시드 10,000개에서 시작점, 출입구, 상자 접근점, 보스 공간의 도달성을 검사한다. 실패한 시드는 숨기지 않고 재현 자료로 남긴다.
- 모든 지도에서 기본 적 150점 이상, 상자 4/5/6개, 정예 8명, 시작 안전 거리, 유효 통로 폭과 보상 예산 총량을 검사한다. 선택 요소가 없어도 게이지 100을 달성할 수 있어야 한다.
- 새로운 판의 구조 식별값이 직전 판과 달라야 한다. 대체 지도 예외를 분리하고 방 수·추가 연결·테마·무리 원형의 분포를 보고한다.
- 같은 생성 버전·시드·명세로 재현한 지도와 개체 ID가 일치해야 한다. 장식 추가가 전투·보상 추첨 결과를 바꾸지 않아야 한다.
- 개봉 시작·직전 완료·확정 응답 전후, 보스 사망, 가방 포탈, 이벤트 종료 시점에 연결을 끊어도 재화·장비가 중복되거나 유실되지 않아야 한다.
- 세 가지 가방 정책, 전설·세트 보호, 이미 무시한 드롭, 개봉과 보스 처치가 같은 틱인 경우를 검사한다. 미개봉 상자를 성공 후 무료로 열 수 없어야 한다.
- 시뮬레이션 틱과 입력이 같다면 배속에 관계없이 같은 전투 시간에서 같은 상태를 만들어야 한다. 실제 세션 시간과 성능 비용은 별도로 측정한다.

### 12.2 플레이 검증

6개 추천 빌드를 최소한 현재 실클리어 가능한 단계, 그보다 낮은 반복 사냥 단계, 다음 도전 단계에서 비교한다. 성소 없음/있음과 상자 우회 정책을 나누고, 시작 장비와 성장 장비를 구분한다. 하나의 강한 개발용 영웅이 클리어한 결과만으로 모든 빌드를 검증했다고 처리하지 않는다.

기록할 항목은 탐색·전투·개봉·포탈 시간, 첫 정예/상자/게이지 100/보스 조우 시점, 상자 발견·잠금 해제·개봉·포기 수, 경로 재계산·막힘·목표 전환, 처치·피해·사망 원인, 보상 경로별 수입, 실제 시간당 수입, 생성 재시도·대체 지도 사용률이다. 최근 10회의 상세 전투 로그와 연결할 runId를 공통으로 남긴다.

## 13. 기존 문서와 달라지는 제안의 목록

| 제안 | 기존 상태와 차이 | 처리 |
|---|---|---|
| 일반 110명+정예 8명 | 기존 문서는 최소 150점만 정했고, 개발 빌드는 고정 8방 배치를 사용한다. | 첫 생성기의 시험 예산이다. 확정된 콘텐츠 종수를 바꾸지 않는다. |
| 상자 4–6개·잠금 30/70·보상 예산 | 기존 문서에 구체적인 필드 상자 규칙이 없다. | 새 수입원·자동 행동·저장 규칙을 함께 검증할 신규 제안이다. |
| 성공 후 미개봉 상자 종료 | 기존 '전리품 정리'는 발생한 드롭만 다루며 미개봉 상자를 정의하지 않았다. | 탐색 비용을 유지하기 위한 신규 정책이다. 이미 발생한 드롭을 회수하는 기존 규칙은 유지한다. |
| 보스의 무작위 선택 | 개발 빌드는 단계에 따른 순환으로 보스를 선택한다. | 기존 3보스를 유지하면서 판마다 구성을 바꾸는 대체안이다. |
| 성소와 저주 상자 | 기존 필수 콘텐츠 목록에는 없다. | 성소는 상자 이후 검증하고 저주 상자는 2차 선택 기능으로 분리한다. 초도 핵심 작업의 선행 조건으로 삼지 않는다. |
| 목표 파밍·비밀방·새 재화 | 기존 미채택 또는 미정 영역이다. | 이 문서에서는 보류 후보로만 나열한다. 자동으로 확정 범위에 포함하지 않는다. |

이 상세안만으로 전체 콘텐츠의 피해 수치, 접두사·접미사 풀, 전설·세트 발동, 서버 정산 구조가 완료되었다고 간주하지 않는다. 해당 명세와 같은 콘텐츠·경제 버전을 사용하고, 승인된 규칙과 시험값을 구분한 뒤 개발에 들어간다.
