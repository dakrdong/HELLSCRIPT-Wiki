# 사냥 칙령 구현 계약

작성일: 2026-09-09 · 개발 시험안 · 저장·공유와 실행 연결의 구현 순서

최신 [공통 명세](HELLSCRIPT_Hunt_Edict_Detail.md), [전역 8분류](HELLSCRIPT_Hunt_Edict_Global_Options.md), [스킬 화면](HELLSCRIPT_Hunt_Edict_Skill_Options.md), [스킬별 핵심 옵션 v0.2](HELLSCRIPT_Hunt_Edict_Skill_Option_Catalog.md)를 구현 기준으로 삼는다. 사용자 후속 요구에 따라 스킬별 편집은 자동 사용 포함 4~5개, 총 89개로 줄이고 최대 8개를 지킨다. 이전 524개 항목 전체를 구현 대상으로 유지하지 않는다. 미해금 스킬을 빈칸으로 두고 가능한 내용을 가져오는 정책은 유지한다.


화면 배치와 방향 전환은 [화면 비율·방향 대응 상세안](HELLSCRIPT_Screen_Layout_Detail.md)을 함께 따른다. 모바일 가로·세로와 PC에 같은 기능을 제공하며, 크기 변경은 초안 저장이나 페이지 이탈로 처리하지 않는다. 부분 구현과 환경별 실행 증거는 [화면 배치 개발 기록](../Implementation/Screen_Layout_Expansion.md)에 구분한다.

## 최신 간소화 요구의 우선 적용

아래 HED1 자료 구조·세부 규칙·용량·검사 기록은 간소화 이전 개발 상태를 설명한다. 기존 기록을 보존하되, 새 화면에서 규칙 추가·임의 OR/AND·고급 조건 편집을 제공하는 근거로 사용하지 않는다. 후속 구현에서는 스킬별 핵심 선택값과 고정 판단 버전을 원본으로 삼고 실행용 규칙을 연결해야 한다. 이전 상세 규칙을 숨겨 붙여 실행하거나 기존 엔진의 조건 상한을 바꾼 것으로 해석하지 않는다.

새 핵심 옵션은 별도 스키마 버전으로 구분하며 같은 HED1 코드의 해석을 조용히 바꾸지 않는다. 구형 값이 정확히 대응하지 않으면 원본을 보존하고 변경·제외될 내용을 보여 준 뒤 ‘간소화하여 불러오기’로 편집본을 만든다. 실제 적용은 명시적 저장 이후다. 변환·화면·실행 검증이 끝나기 전에는 기존 코드 검사 결과를 핵심 옵션 v0.2의 완료 증거로 재사용하지 않는다.

## 데이터와 실행의 소유자

사냥 칙령 원본은 사용 스킬 네 칸, 기본 공격과 직업별 액티브 여섯 종의 자동 사용 상태, 모든 스킬의 보관 규칙, 전역 옵션과 전체 행동 순서를 소유한다. 실행용 `BuildConfig`는 이 원본에서 현재 실행할 규칙을 만든 결과로 연결한다. 편집 중인 원본을 실제 계정이나 진행 중 전투에 직접 연결하지 않는다.

스킬 칸은 안정적인 콘텐츠 ID 또는 빈 문자열을 저장한다. 규칙은 스킬 ID와 해당 스킬 안의 고정 번호로 식별하며, 전체 목록 순서가 실행 우선순위다. 칸 이동은 규칙 순서를 바꾸지 않는다. 스킬 해제는 칸을 비울 뿐 보관 규칙·자동 사용 상태·전용 옵션을 삭제하지 않는다.

전역과 스킬 전용 옵션은 정의 ID와 값으로 기록한다. 정의에는 화면 분류·허용 선택·숫자 범위·단위·기본값을 함께 둔다. 아직 실행 판정에 연결하지 않은 옵션을 설정 화면에서 작동하는 것으로 노출하지 않는다. 기존 옵션 이관과 새 판단의 구현·검증을 마친 항목부터 연결한다.

## 공유 코드의 개발 규칙

`HED1`은 버전·콘텐츠 기준·직업·배치·전역 옵션·스킬 보관 설정을 담는 자체 완결형 코드다. 정규화한 UTF-8 JSON을 Base64URL로 표현하고 SHA-256 오류 확인값을 붙인다. 외부 서버나 새 패키지를 사용하지 않는다. 이름·시각·계정 및 캐릭터 개인 ID·장비 인스턴스 ID·패시브 장착·현재 전투 상태는 포함하지 않는다.

공유 형식은 필드 순서와 기본값을 고정한다. 지원하지 않는 버전, 누락·추가·중복 필드, 알 수 없는 ID·선택값, 손상된 UTF-8, 비정상 숫자, 너무 크거나 깊은 입력을 거부한다. 파싱 후 정규화한 내용이 원문과 다른 코드도 적용하지 않는다. 정상적인 발급 코드에는 생략된 필드가 없으므로, 알 수 없는 값을 버리거나 수신자의 기본값으로 보충하지 않는다.

JSON은 최대 256KiB, 중첩은 16단계로 제한한다. 초기 128KiB 시험안은 당시 허용했던 114개 규칙의 직업별 최대 구성을 담지 못했다. 기존 시험 구성은 보존하고 용량을 늘렸다. 이후 추가된 기본 공격 3규칙 정책을 적용한 현재 최대 93규칙 구성은 약 121KB 이내이며, 용량을 통과시키려고 규칙 수를 줄인 것은 아니다. 구형 기본 공격이 3규칙을 초과하면 원본을 잘라내지 않고 이관 검토 대상으로 남긴다.

현재 개발 형식에는 압축을 사용하지 않는다. 최대 시험 구성은 코드가 약 16만 글자에 이르므로 실제 화면에 공개하기 전에 크기 개선과 긴 코드의 붙여넣기·복사를 검증해야 한다. PC와 모바일 입력 검사는 아직 남아 있다. 아직 공개하지 않은 이 형식을 배포용 규격으로 확정한 것은 아니다.

## 이관과 부분 가져오기

기존 슬롯 1~3의 이름·규칙·장비 보호 참조·패시브 구성은 보존하고 슬롯 4~5는 비워 둔다. 공유에서 제외하는 로컬 정보는 별도 메타데이터로 유지한다. 변환할 수 없는 기존 값은 삭제하거나 근사값으로 바꾸지 않고 원본을 보존한 채 이관 오류를 알린다.

공유 원본의 구조 검증과 현재 영웅의 사용 가능성은 구분한다. 알려진 같은 직업의 미해금 스킬은 해당 칸만 비우고 원래 ID·요구 레벨을 가져오기 안내에 남긴다. 보관 규칙과 다른 스킬의 참조는 그대로 유지한다. 참조할 수 없는 조건 묶음은 부정 조건을 포함해 실행 자격으로 사용하지 않으며, 다른 유효한 OR 묶음은 계속 판단한다. 빈칸에 새 스킬을 선택하면 그 스킬 자신의 옵션을 사용한다.

## 연결 순서와 검증

1. **원본·검증·코드:** 전역 8분류와 스킬별 옵션의 저장 정의, 네 칸과 숨긴 규칙의 보존, 안정적인 코드와 잘못된 입력 거부를 구현한다. 이 단계의 코드 검사만으로 게임 기능 완료를 표시하지 않는다.
2. **기존 데이터와 실행 변환:** 기존 설정을 손실 없이 옮기고, 현재 스킬만 실행하며 미해금 참조를 올바르게 보류한다. 저장·해제·재장착으로 HP·자원·쿨타임·이미 생성된 효과가 달라지지 않는지 검사한다.
3. **명시적 저장과 슬롯:** 저장 성공 후에만 실제 설정을 확정한다. 5개 슬롯·이름·코드와 훈련/A/B 저장 경로를 통일하고, 저장 실패·구형 슬롯·재시작을 확인한다.
4. **화면과 입력:** 현재 스킬 카드, 미보유 빈칸, 변경 요약·되돌리기·세 가지 이탈 선택, 코드 미리보기·복사를 연결한다. 실제 UI 경로와 긴 코드·이름 입력을 검증한다.
5. **확장 판단:** 전역 회피·긴급 대응·몰이·추적·회수·정리·탐색·반복과 스킬 전용 판단을 실제 사건에 연결한다. 기획의 모든 선택을 각각 실행·관찰하고 기존 전투·경제와 회귀 검사를 수행한다.

숫자가 정해지지 않은 새 옵션의 범위와 초기값은 구현 정의에 시험값으로 기록한다. 기존 캐릭터를 이관하면서 새로운 자동 판매·분해·회피·몰이 행동을 임의로 켜지 않는다. 소유자 확인이 필요한 서비스·경제 정책은 기존 남은 작업표의 경계를 유지한다.

## 현재 진행과 새 상세안의 반영 범위

저장 모델·검증·부분 가져오기 미리보기의 현재 검사 결과는 [사냥 칙령 개발 기록](../Implementation/Hunt_Edict_Expansion.md)을 따른다. 이전 524개 항목 목록은 과거 범위이며 최신 편집 대상은 핵심 옵션 v0.2의 89개다. 현재 저장 모델과 검사 결과가 새 선택값·고정 행동·구형 변환까지 지원한다고 보지 않는다. 후속 매핑은 새 편집 항목 수, 원본 보존, 선택별 실제 동작을 기준으로 다시 검증해야 한다.
