# HELLSCRIPT 무기·장비 상점 기획 검토안

작성일: 2026-09-20 · 수정일: 2026-09-21 · 개정: 자동 선택을 설정 열기·수동 모드 전환에서 분리한 8차 시안 · 상태: 기획 검토 · [English](HELLSCRIPT_Equipment_Shop_Proposal.en.md)

장비 상점은 사냥으로 얻은 장비 사이의 작은 빈틈을 메운다. 플레이어가 현재 장착한 장비보다 조금 나은 장비를 골라 사고 다시 균열에 도전하는 흐름을 만든다. 상점 구매만 반복해서 성장 단계를 건너뛰게 해서는 안 된다.

자동 선택 설정은 **등급 필터 → 장비 필터 → 필요한 장비만 사용하는 세부 설정**으로 나눈다. 등급과 장비 종류만 체크해도 판매 대상을 고를 수 있다. 남겨 둘 가치가 있는 장비 종류에만 세부 설정을 켜고 능력치 제외 조건을 적용한다. 설정을 저장한 뒤 `자동 선택`을 눌러 선택 목록을 만들며, 실제 판매는 별도로 실행한다.

8차에서는 `자동 선택`이 **저장된 조건에 맞는 아이템을 체크하는 역할만** 맡는다. 설정창은 `자동 선택 설정`으로 열고, 수동 체크 모드는 `다중 선택`으로 전환한다. 설정이 없으면 창을 열거나 모드를 바꾸지 않고 안내만 표시한다.

비교창은 사용자가 첨부한 디아블로 4의 정보 형식을 유지한다. **아이템을 누르면 선택 장비와 현재 장착 장비의 팝업이 나타난다. 각 능력치·옵션 끝에는 괄호로 증감값을 표시하고, 하단에는 장착 시 사라지는 속성을 모은다. 선택 전에는 비교 영역을 비워 둔다.** 구매에는 인벤토리를 표시하지 않는다. 판매에는 기존 8열 인벤토리와 다중 선택·일괄 판매를 제공한다. 되사기는 판매한 아이템 하나가 한 줄을 차지하며, 누르면 판매 당시의 모든 아이템 정보를 표시한다.

**강화는 아직 기획되지 않았으므로 강화 +1 예상치·강화 비용·강화 후 상승률은 제외한다. 비교 대상은 현재 장착 장비 하나로 통일하며, 보유 최고·창고 비교는 제공하지 않는다.** 업그레이드 정보는 아이템에 실제로 기록된 내용만 읽어서 표시한다. 기록이 없는 예시 장비에는 `기록 없음`을 표시하고 단계·확률·비용을 만들어 넣지 않는다. 현행 코드의 강화 기능을 승인된 기획으로 취급하지 않는다.

이 HTML 시안은 예시 계정으로 동작한다. 승인한 화면을 실제 게임의 장비 상인·소지품·저장·재화에 연결한 구현과 검증 범위는 [장비 상인 연결 기록](../Implementation/Equipment_Shop.md)을 따른다. 아래의 전투 평가 제안 전체가 구현되었다는 뜻은 아니며, 구현된 능력치 지표와 남은 전투 시뮬레이션 검증을 연결 문서에서 구분한다. 수치 범위와 가격 배율은 초기 튜닝값이다.

## 1. 확인한 상점 구조와 적용 범위

내장 브라우저로 확인한 [D4 무기 상점 캡처](https://guides4gamers.com/diablo-4/pois/weapons/)에서 상품 목록, 선택 상품 비교, 골드 거래와 되사기를 참고했다. 상점과 소지품을 동시에 보여 주던 배치는 사용자의 최신 지시에 따라 거래 탭별로 나눈다. 캡처 경로는 2023년 3월 자료이므로 최신 시즌과 완전히 같다고 주장하지 않는다. [무기 상인](https://diablo4.wiki.fextralife.com/Weapons+Vendor)과 [방어구 상인](https://diablo4.wiki.fextralife.com/Armor+Vendor)의 2026-05-02 갱신 커뮤니티 설명에서는 제한된 상품, 골드 거래, 60분 재입고를 확인했다. 블리자드의 내부 생성 공식은 확인하지 못했다.

이번 비교창의 직접 근거는 사용자가 첨부한 디아블로 4 비교 화면 두 장이다. 팝업 두 개, 옵션 끝의 증감값, 하단의 사라지는 속성 구성을 참고하되 표면·장비 그림·테두리는 HELLSCRIPT의 기존 자원을 유지한다.

8개 상품, 추천 생성 방식, 12개 되사기 보관과 재접속 보존은 HELLSCRIPT의 제안이다. 세로 화면에서 6.5개가 보이고 나머지는 스크롤되는 구성을 검토하려고 예시 재고를 6개에서 8개로 늘렸다. 기존 미확인 장비 상점은 별도 확률형 구매 역할을 유지한다. 강화·분해·접사 변경 기능의 기획을 이번 상점 시안에서 확정하거나 추가하지 않는다.

## 2. 첨부 인벤토리를 시각 기준으로 고정한다

이번 시안의 최우선 시각 근거는 [사용자가 첨부한 실제 창고·소지품 화면](EquipmentShop/inventory-reference.png)이다. 현재 작업 폴더와 원본 프로젝트의 `StorageWindow.cs`, `StorageWindow.Style.cs`, `EquipmentAtlas.png`가 동일한지도 확인했다.

| 요소 | 적용 기준 |
|---|---|
| 인벤토리 형태 | 8열 정사각 슬롯과 50칸, 빈칸 번호, 장비의 오른쪽 아래 아이템 레벨, 잠금 표시를 유지한다. |
| 장비 그림 | 기존 `EquipmentAtlas.png`의 6×4 매핑을 그대로 쓴다. 투명도를 유지한 축소 사본만 사용하며 원본은 변경하지 않는다. |
| 슬롯 테두리 | 일반 `#5b594c`, 마법 `#586b78`, 레어 `#978554`, 전설 `#a47643`, 세트 `#607557`을 유지한다. |
| 표면과 글자 | 창고의 차콜·올리브 표면, 얇은 황동 경계, 명조 계열 제목, 본문 `#d9d1be`, 제목 `#c0a777`을 따른다. |
| 도구와 분류 | 전체 등급, 위치·최근·등급·레벨 정렬, 프리셋, 전체·무기·방어구·장신구·재료·룬 블럭·보석 분류를 유지한다. |
| 공통 기호 | 창고·가방·교환·골드·보석은 `StorageGlyph.cs`와 같은 24단위 도형 좌표로 표시한다. 다른 아이콘 세트로 교체하지 않는다. |
| 상점 | 인벤토리와 같은 표면·슬롯·등급 테두리·도구·분류 탭을 쓰되, 상품명과 가격을 읽을 수 있는 세로 목록으로 구성한다. |
| 공통 창 | 상단 제목·닫기, 하단 골드·보석·기록·안내를 고정한다. 구매 버튼은 기존 창고의 암적색 버튼을 따른다. |

한 번에 선택한 거래 탭의 목록과 상세 영역만 표시한다. 판매 탭의 인벤토리에는 기존 8열 정사각 슬롯을 그대로 쓰며, 다중 선택 모드에서만 선택 표시를 겹친다. 가로 화면에서는 목록 폭을 줄여 상세 공간을 확보하고, 세로 화면에서는 위아래로 나눈다. 가운데의 넓은 장식 영역은 얇은 구분선으로 줄인다. 슬롯 그림·등급 테두리·상세·대화상자의 표면은 기존 창고 스타일을 유지한다.

## 3. PC와 아이폰 17 프로 맥스 배치

[Apple 공식 기술 사양](https://support.apple.com/ko-kr/125091)에서 아이폰 17 프로 맥스의 해상도 2868×1320과 Dynamic Island를 확인했다. 시안은 세로 1320×2868을 **3:1로 환산한 440×956 설계 좌표**, 가로는 956×440으로 검토한다. 이는 설계용 환산이며 실제 기기의 Unity 입력·안전 영역을 측정한 결과는 아니다.

| 규격 | 기본 배치 | 스크롤과 조작 |
|---|---|---|
| PC 1600×900, 1920×1080 | 왼쪽 거래 목록, 오른쪽 비교 팝업 두 개 | 구매·되사기는 한 줄 목록, 판매는 8열 인벤토리다. |
| iPhone 17 Pro Max 가로 956×440 | 왼쪽 거래 목록, 오른쪽 비교 팝업 두 개 | 판매의 8열 슬롯을 유지하고 거래 버튼은 비교 영역 아래에 고정한다. |
| iPhone 17 Pro Max 세로 440×956 | 위쪽 구매 목록 약 6.5개, 아래 나머지 공간은 비교 영역 | 선택 장비·현재 장착 팝업을 나란히 표시한다. 목록과 비교 본문은 각각 스크롤한다. |

상단 제목과 구매·판매·되사기 탭, 분류·정렬, 하단 재화와 거래 버튼은 내용과 함께 밀려나지 않는다. 비교 팝업은 예약된 영역 안에 나타나므로 상품 목록을 가리지 않는다. 최초 진입·거래 탭 전환 시 자동 선택하지 않는다. 같은 아이템을 다시 누르거나 닫기·Esc를 누르면 비교창과 거래 버튼을 모두 숨긴다. 필터에서 선택 장비가 사라질 때도 비교창을 비운다. 다중 선택의 선택 목록은 기존대로 아이템 ID를 기준으로 유지한다. 다중 선택 중 개별 `정보`를 누르면 같은 비교 내용을 안전 영역 안의 대화상자에서 확인할 수 있다.

Dynamic Island와 홈 표시줄을 고려한 **검토용 여백**은 세로 상단 62·하단 34, 가로 좌우 62·하단 21 설계 단위다. 이 숫자를 기기 공식 안전 영역으로 단정하지 않는다. Unity 연결 시 기존 `UiSafeArea.Current`에서 실제 값을 읽어야 한다. 시안에서 지정한 기기 규격의 슬롯 크기·조작 위치·스크롤을 확인하고, 실기기 터치와 글자 크기 확대는 별도로 검증한다.

### 정보 밀도와 비교 표시

4차에서 줄인 아이콘과 글자 크기를 유지한다. 모바일 상품 아이콘은 32×32, 행 높이는 40, 행 간격은 4, 제목은 16, 상품명·비교 본문은 11 설계 단위다. PC 상품 아이콘은 44이며 목록 폭은 최대 560이다.

세로 구매 목록은 제목·분류를 포함해 340 단위 높이로 고정한다. 초기 화면에서 상품 6개와 일곱 번째의 약 절반이 보인다. 아래 비교 영역은 430 단위이며 거래 버튼을 포함한다. 선택 전후에 경계가 움직이지 않는다. 가로에서도 목록 왼쪽·비교 오른쪽 배치를 유지한다. 긴 비교 내용은 비교 영역 안에서 스크롤하며 가격·거래 버튼은 고정한다.

- 선택 장비 팝업에는 해당 장비의 기본 능력치와 전체 옵션을 표시한다. 각 줄의 끝에는 `선택값 − 현재 장착값`을 괄호로 붙인다. 공격력 `44 (+1.6)`, 힘 `+15.9 (+1.9)`, 물리 피해 `+5.8% (−0.7%)`처럼 표시한다.
- 새 옵션은 현재 값을 0으로 보고 전체 값을 증가분으로 표시한다. 같은 값은 `(0)`으로 표시한다. 퍼센트 옵션의 차이는 상대 상승률이 아닌 퍼센트포인트 차이다. 기본 능력치와 접사는 각각 같은 항목·단위·효과 조건끼리 비교한다.
- 증가값은 초록색, 감소값은 붉은색, 변화가 없으면 기본 글자색을 쓴다. 부호를 함께 표시한다. 현재 예시는 모두 값이 높을수록 유리한 옵션이며, 향후 재사용 대기시간처럼 낮을수록 유리한 항목은 정식 능력치 정의의 유불리 기준을 따라야 한다.
- `장착 시 사라지는 속성`에는 현재 장착품에만 있고 선택 장비에는 없는 옵션을 붉은색으로 표시한다. 값이 줄어든 동일 옵션은 위쪽 음수 표시로 처리하고 이 목록에 중복해서 넣지 않는다. 없으면 `없음`을 표시한다.
- 이름·등급·부위·아이템 레벨·해당 기본 능력치·공격 속도·전체 옵션·업그레이드 기록·요구 레벨·판매가·거래 가격을 유지한다. 해당 장비가 갖지 않는 공격력·방어력 줄은 만들지 않는다. 현재 장착품 팝업도 자체 정보를 표시한다. 미정인 강화 예상치는 추가하지 않는다.

판매 인벤토리는 8열을 유지하며, 세로 예시에서는 약 43 단위의 정사각 슬롯으로 50칸을 한 화면에 표시한다. 가로 예시에서는 약 41 단위 슬롯으로 40칸을 표시하고 나머지를 내부 스크롤로 확인한다. 대화에 삽입한 모바일 시안은 기기 전체를 같은 비율로 축소하므로 검토 창의 폭이 달라져도 기기 내부 배치가 변하지 않는다. 터치 조작성은 실기기 확인 전이다.

## 4. 구매·판매·되사기

### 구매

1. 구매 탭에는 상품 목록과 선택 상품 정보만 표시한다. 인벤토리 슬롯은 표시하지 않는다.
2. 상품을 누르면 3절의 형식으로 선택 장비·현재 장착 장비 팝업을 표시한다. 전체 정보와 각 옵션의 증감, 장착 시 사라지는 속성을 확인한다. 비교 대상 전환과 강화 조작은 없다.
3. 가격이 표시된 구매 버튼으로 1회 거래한다. 실제 구현은 골드·가방 자리·상품 ID·재고 세대를 거래 직전에 재검증한다.
4. 구매한 정확한 인스턴스를 빈 소지품 칸에 넣고 해당 상품을 판매 완료로 바꾼다. 자동 장착하지 않으며 그 자리에 새 상품을 즉시 만들지 않는다.

### 판매

- 판매 탭에만 인벤토리를 표시한다. 기본 위치순은 가로 8칸, 총 50칸을 유지한다. 아이템을 누르면 상세 정보와 판매 버튼이 나타난다.
- `다중 선택`을 켜면 여러 아이템을 선택할 수 있다. 상세 영역에는 선택 목록과 판매 합계, `일괄 판매` 버튼이 나타난다. 각 항목의 `정보`로 전체 설명을 열 수 있다.
- `자동 선택`은 저장된 등급·장비 종류·사용 중인 세부 조건으로 **인벤토리 전체**를 평가하고 기존 선택을 결과로 교체한다. 인벤토리 화면의 분류·등급 필터와 무관하게 동작하며, 필터에 가려진 선택 수를 알린다. 이후 필터·정렬을 바꿔도 선택은 아이템 ID로 유지한다. `선택 해제`와 다중 선택 종료는 전체 선택을 비운다.
- 자동 선택은 수동 다중 선택 모드의 켜짐·꺼짐 상태를 유지한다. 일반 상태에서도 자동 선택된 아이템의 체크 표시, 선택 수, 합계, `선택 해제`와 `일괄 판매`를 표시한다. 이때 슬롯을 누르면 정보 팝업을 열고 체크 결과는 유지한다. 직접 체크를 조정하려면 `다중 선택`을 누르며, 진입 시 기존 자동 선택 결과를 이어받는다.
- 등급 또는 장비 종류가 미설정이면 기존 선택을 보존하고 도구 아래에 설정 안내만 표시한다. 설정은 있지만 일치하는 장비가 없으면 선택을 0개로 갱신하고 해당 안내를 표시한다. 두 안내는 모바일에서도 보인다.
- 장착·잠금·프리셋 참조·보석 장착 장비의 기존 판매 보호를 유지한다. 시안은 잠금과 프리셋 보호를 예시로 제공하며, 장착품은 가방 판매 대상에 넣지 않는다.
- 일괄 판매는 선택 ID, 소유 여부, 보호 상태, 판매가를 다시 확인한 뒤 전부 함께 처리한다. 검증이 실패하면 일부만 팔지 않는다. 판매 합계만큼 골드를 더하고 정확한 인스턴스를 되사기에 옮긴다.

### 자동 선택 설정

`자동 선택` 옆에 `자동 선택 설정` 버튼을 둔다. 최초 설정은 등급과 장비 종류 모두 미선택이며, 각 구역의 `전체 선택`으로 한 번에 체크하거나 해제할 수 있다. 일부만 체크했을 때는 전체 선택에 부분 선택 상태를 표시한다. 하단에는 현재 설정으로 선택될 장비 수와 `취소`·`설정 저장`을 고정한다. 저장만으로 장비가 선택되거나 팔리지는 않는다.

#### 1. 등급 필터

일반·마법·희귀·전설·고유·세트를 개별 체크한다. 체크한 등급만 판매 후보가 된다. 체크한 등급이 없으면 후보는 0개다. 기존 시안의 `레어` 표기는 `희귀`로 통일한다.

고유는 요청한 독립 필터로 제공하지만 이번 예시 소지품에는 0개다. 현행 게임은 `UniqueItemDefinition`을 전설 등급의 `special` 참조에 사용하며 세트도 별도 식별 정보로 구분한다. 따라서 이 화면의 여섯 분류를 새로운 게임 저장 등급 값으로 바로 추가해서는 안 된다. 실제 연결 전에 전설·고유·세트의 표시 분류와 원본 모델 간 대응을 확정해야 한다.

#### 2. 장비 필터

아래 장비 종류를 개별 체크한다. **등급과 장비 종류를 모두 만족해야** 판매 후보가 된다. 종류를 체크해도 세부 조건은 자동으로 펼치거나 켜지 않는다. 예를 들어 `일반·마법`과 `장비 전체`만 체크하고 세부 설정을 끄면 예시 인벤토리의 8개 장비를 바로 자동 선택할 수 있다. 필요 없는 장비는 이 두 필터만으로 처리한다.

| 분류 | 개별 체크 항목 | 기본적으로 노출하는 제외 조건의 예 |
|---|---|---|
| 무기 | 한손검, 양손검, 도끼, 활, 쇠뇌, 지팡이 | 공격력, 치명타 확률·피해, 공격 속도, 힘 |
| 방어구 | 헬멧·두건, 갑옷·상의, 장갑, 바지, 신발, 허리띠 | 방어도와 해당 부위의 생명력·저항·치명타·이동 속도·피해 감소 등 |
| 장신구 | 목걸이, 반지 | 생명력·저항·치명타·재사용 대기시간 감소 등 해당 부위의 옵션 |

#### 3. 장비별 세부 설정

장비 체크박스가 있는 각 행 옆에 `세부 설정` 버튼을 둔다. 체크한 장비의 버튼을 누르면 아래에 설정을 펼친다. 맨 위의 `세부 설정 사용`을 켠 경우에만 능력치 조건을 활성화하고 평가한다. 끄면 아래 옵션을 비활성화하며, 저장된 기준값은 남겨 두되 선택 계산에는 쓰지 않는다.

사용 중인 장비의 버튼은 황동색 배경·테두리와 `세부 설정 · 사용 중` 표기로 강조한다. 단순히 설정창을 펼친 상태나 장비를 체크한 상태만으로 사용 중 표시를 켜지 않는다. 장비 종류를 해제하면 버튼은 비활성화되지만 기존 설정은 보존한다.

모바일 가로에서는 세부 조건을 두 열로, 세로에서는 한 열로 표시한다. 입력 오류는 고정된 저장 버튼 바로 위에 표시한다. 아래 판정 규칙은 **세부 설정 사용이 켜진 장비에만** 적용한다.

- 각 조건은 체크박스와 `수치 이상 제외` 입력으로 구성한다. 체크한 조건만 계산에 넣으며, `제외 조건 추가`에는 해당 부위에 붙을 수 있는 나머지 옵션을 표시한다. 같은 옵션을 중복 등록하지 않는다.
- 능력치 이름·단위·부위 허용 범위는 현재 `StatCatalog`와 `ItemCatalog.Affixes`의 54개 접사 정의를 참고하고, 무기 기본 공격력을 더해 총 55개 항목에서 부위별로 추린다. 조건에 쓰는 수치는 장비 자체의 기본값과 같은 항목·단위의 접사 합계다. 캐릭터 전체 능력치, 현재 장착품과의 차이, 버프나 미정인 강화 예상치를 사용하지 않는다. 없는 옵션은 기준이 0이어도 충족한 것으로 세지 않는다.
- 종류마다 `제외 조건이 N개 이상 맞으면 제외`를 설정한다. N은 **0부터 체크한 조건 수까지의 정수**다. 능력치가 기준값과 같으면 충족으로 센다. N이 1 이상이면 충족한 조건 수가 N 이상인 장비를 선택에서 제외한다.
- **0은 능력치에 따른 제외를 사용하지 않는 값으로 제안한다.** 이 경우 체크한 종류의 판매 가능 장비를 선택하되 판매 보호는 유지한다. 화면에도 `0개: 능력치 조건으로 제외하지 않음`을 명시한다. 첫 조건을 체크하면 초기 충족 개수는 1로 바뀌며, 다시 0으로 지정할 수 있다. 조건을 삭제하면 N을 남은 조건 수 이내로 줄인다.
- 예를 들어 도끼에 `공격력 50 이상`, `치명타 확률 3% 이상`을 체크했을 때, 공격력 48.76·치명타 확률 3%인 도끼는 1개 조건을 충족한다. N=1이면 남겨 두고, N=2이면 판매 대상으로 선택한다. N=0이면 능력치 제외를 적용하지 않는다.
- 사용 중인 세부 조건에 음수·빈 기준값이나 범위를 벗어난 충족 개수가 있으면 오류를 표시하고 저장을 막는다. 세부 설정을 끈 장비의 미완성 기준값은 간단 필터의 저장을 막지 않는다. `취소`·닫기·Esc는 편집 중 변경을 버린다. 저장된 설정은 다시 열어 수정할 수 있고, 종류를 해제했다가 켜면 저장된 조건을 유지한다.
- 잠금·프리셋 보호는 자동 선택과 실제 판매 양쪽에서 적용한다. 현재 장착품은 판매용 가방에 들어 있지 않으며, 정식 구현에서도 장착·보석 장착 등 기존 판매 보호를 우선한다. 자동 선택을 반복해도 선택이 뒤집히거나 중복되지 않는다.

현재 장비 카탈로그의 24개 기본 장비를 13개 종류에 매핑한다. 요청한 **바지**는 체크 항목으로 추가했지만 현행 카탈로그에 부위·아이템이 없어 예시 소지품은 0개다. 바지의 옵션 목록은 상의 허용 범위를 임시로 사용한 기획안이며, 정식 바지 슬롯과 접사 규칙을 확정해야 한다. 한손검·양손검 표기는 현재 `sword`·`greatsword` 계열을 UI에서 구분한 것이다.

시안의 설정은 대화 내 미리보기 상태에만 보관하며 게임 계정이나 저장 파일에 쓰지 않는다. 독립 미리보기 페이지를 새로 열면 초기화된다. Unity 구현에서는 등급 분류·종류 ID·세부 설정 사용 여부·능력치 ID·단위·기준값·충족 개수·규칙 버전을 계정 설정에 저장하고, 실제 판매 직전에 인벤토리와 보호 상태를 다시 확인해야 한다.

### 되사기와 거래 보호

- 되사기는 **아이템 하나가 한 줄을 차지하는 목록**이다. 판매하지 않은 장비나 빈 인벤토리 칸을 표시하지 않는다. 각 줄에 그림·이름·등급·레벨·되사기 가격을 표시한다.
- 줄을 누르면 현재 장착품과 비교하면서 공격력·방어력·공격 속도·레벨·요구 레벨·등급·종류·부위·전체 옵션·업그레이드 기록·당시 판매가격·되사기 가격을 확인한다. 긴 정보는 생략하지 않고 상세 안에서 스크롤한다. 정식 모델의 소켓·보석 등 추가 정보도 원본 아이템 설명기를 재사용해 표시한다.
- 원래 아이템 ID·접사·소켓·업그레이드 기록·출처와 판매 당시 금액을 보존하며 다시 추첨하지 않는다. 업그레이드 기록 표시는 향후 강화 규칙이나 +1 예상치의 기획을 의미하지 않는다.
- 최근 12개를 보존한다. 일괄 판매로 한도를 넘으면 제외될 항목 수를 판매 전에 알리고 확인을 받은 뒤 진행한다. 취소하면 골드와 장비는 바뀌지 않는다. 판매 순서는 가방 위치순으로 고정하고 가장 최근 12개를 남긴다. 정상 재접속 후 보존은 정식 구현에서 검증한다.
- 재화 부족, 소지품 가득 참, 보호된 아이템, 이미 판매된 상품은 이유와 함께 거래를 막는다. 정식 구현에서는 중복 입력을 영수증으로 한 번만 처리한다.
- 프리셋 버튼은 예시 영웅의 현재 장착 구성을 보여 주며, 기록에는 시안에서 실행한 구매·판매·되사기를 남긴다. 실제 프리셋 편집과 계정 저장은 연결하지 않았다.

## 5. 레벨과 ‘약간 좋음’을 계산하는 기준

### 세 가지 진행 수치

현행 코드에서 영웅 레벨 `H`는 최대 30, 아이템 레벨 `I`는 최대 60이다. 착용 요구 레벨은 `min(30, (I+1)/2)`의 정수 계산이다. 최고 균열 클리어 `R`은 별도 값이다. 현행 일반 장비 상인은 `R`을 기준으로 생성하므로 소폭 개선을 보장하지 못한다.

```text
I_cap = min(60, 2 × H, max(1, R) + 2)
기존 생성기의 합법적인 1..I_cap 후보를 현재 장착품 주변부터 탐색한다.
```

H=12, R=16이면 I_cap=18, H=30, R=20이면 I_cap=22다. 영웅 레벨만 높다고 후반 아이템을 판매하지 않는다. 현재 장착품이 상한보다 좋더라도 그것을 이기기 위해 상한을 높이지 않는다. 빈 부위는 실제 무장 상태와 시작 장비를 기준으로 삼아 0으로 나눈 상승률을 만들지 않는다.

### 현재 장착 기준 B와 진행 기준 A

**비교 기준 B는 현재 장착 장비다.** 상품을 같은 부위에 교체한 결과를 비교한다. 보유 최고 장비를 찾아 비교 대상으로 바꾸거나 창고 장비를 꺼내 쓰도록 유도하지 않는다. 무기 계열이 달라지면 공격 속도·숙련·룬의 변화까지 포함한다.

**진행 기준 A는 실제 사냥 전리품과 균열 진행도로 만든 별도 기준이다.** 영웅·진행 구간·부위·무기 계열·평가 버전별로 보존한다. 장비를 벗거나 팔거나 옮겨도 이미 획득한 진행 기준을 낮추지 않는다. A는 화면에 추가 비교 항목으로 노출하지 않는다.

상점 구매품, 되사기와 출처를 이어받은 파생품은 A를 올리지 않는다. 균열·상자·보스·정상 소탕의 새 전리품과 실제 진행 변화만 A를 갱신한다. 제작품은 상점 재료를 우회 경로로 삼을 수 있으므로 A를 갱신하는 출처에서 제외한다. 기존 저장의 출처 불명 장비는 도입 시점에 한 번만 스냅샷하고 이후에는 거래 출처를 보존한다. 재입고는 선택지를 바꾸지만 구간의 절대 성능 상한은 높이지 않는다.

### 장비 교체 후 빌드 평가

영웅·사냥 칙령·스킬·룬·다른 장비를 복사하고 후보 부위만 바꾼다. 일시적 물약과 전투 버프는 제외한다. `HeroStats`와 기존 전투 계산을 재사용하되, 보유품만 허용하는 `TrainingEquipmentBaseline` 검사를 약하게 만들지 않는다. 상점 후보를 실제 소유 목록에 넣지 않는 별도의 불변 평가 진입점이 필요하다.

| 항목 | 초기 추천 조건 |
|---|---|
| 공격형 | 지속 공격 성능 D가 2~5% 높고 생존 성능 E가 1% 넘게 낮아지지 않아야 한다. |
| 생존형 | E가 2~5% 높고 D가 1% 넘게 낮아지지 않아야 한다. |
| 여러 상품 구매 | 같은 진행 기준에서 이전 구매품까지 포함한 합법 조합을 평가한다. D·E 각각 +8%를 초기 상한으로 검토한다. |
| 빌드 유지 | 세트·핵심 효과·무기 숙련·룬 손실을 개별 수치 상승으로 숨기지 않는다. |
| 단계 건너뛰기 | 다음 단계와 그 다음 단계의 기존 균열 완료 조건을 비교한다. 상점만으로 여러 단계가 새로 가능해지면 상한을 낮춘다. |

저렴한 능력치 계산으로 후보를 줄이고, 상위 후보만 고정 시드와 동일 조건의 일반 무리·정예·보스 전투로 평가한다. 물리·원소 패턴, 자원 부족·스킬 주기·공격 속도를 포함하고 중앙값과 불리한 결과를 함께 본다. 이동·회수·골드 획득은 편의 장점으로 따로 표시한다. 공격 상승과 생존 손실을 평균내어 통과시키지 않는다.

부위별 최대 128개 후보를 기존 생성기로 만든다는 것을 초기 탐색 예산으로 둔다. 처음에는 일반·마법·레어를 판매 후보로 삼고 전설·세트·상위 접사는 파밍에 남긴다. 실제 수치 범위를 벗어나 값을 깎거나 올려 2~5%를 강제로 만들지 않는다. 합법적인 추천이 없으면 기본 보충품·다른 역할 장비를 보여 주고 추천은 비운다. 최고 수준의 장비를 가진 플레이어에게 무조건 더 좋은 상품을 보장하지 않는다.

강화 방식이 확정된 뒤에는 상품 구매 후 추가 성장 가능성까지 평가 범위를 확장할 수 있다. **현재는 강화 단계·비용·확률·성능 상한을 정하지 않는다.** 이 문서의 구매 시점 상한만으로 미래의 강화까지 안전하다고 판단하지 않는다.

## 6. 재고와 가격

- 기본 재고는 무기 2, 방어구 4, 장신구 2의 8개이며 추천은 최대 2개로 제안한다. 세로 화면에는 약 6.5개가 보이고 나머지는 목록 안에서 스크롤한다.
- 60분 재입고와 실제 영웅 레벨·최고 균열 클리어 변화에서 재고 세대를 갱신한다. 창 열기·재접속·장비 교체·구매는 재추첨 사유가 아니다.
- 같은 영웅의 마을 상인들은 같은 재고를 공유한다. 구매 완료된 품목은 해당 세대에서 보충하지 않는다. 이전 구매품도 조합 상한 검사에 포함한다.
- 로컬 저장에서는 시계 조작을 서버 수준으로 막을 수 없다. 마지막 시각·재고 세대와 별도의 진행 상한을 보존해 반복 구매의 영향을 제한한다.
- 일반 보충 장비는 기존 `TownTrade.EquipmentPrice`, 마법·레어는 `8 × Item.Price`를 초기 가격으로 검토한다. 구매가는 판매가보다 높아야 하며 같은 상품을 지갑 크기에 따라 더 비싸게 팔지 않는다.
- 장비 구매 비용을 해당 진행 구간에서 약 2~4회 정상 사냥의 순수익과 비교해 조정한다. 강화 비용을 이 기준에 포함하지 않는다. 실제 경제 측정은 아직 하지 않았다.

## 7. 시안의 예시 데이터

예시 영웅은 Lv.12 전사, 최고 균열 16단계이며 실제 사용자 저장이 아니다. 소지품의 초기 14개 배치는 첨부 화면의 형태를 재현하되 예시 레벨과 등급을 사용한다. 이름·부위·장비 그림은 기존 카탈로그를 쓴다.

| 항목 | 현재 장착 | 판매 상품 |
|---|---:|---:|
| 베이스 | B02 강철 대검 | B02 강철 대검 |
| 아이템 레벨 | 15 | 16 |
| 무기 공격력 | 42.40 | 44.00 |
| 기본 공격력 변화 | — | +3.77% |
| 구매 가격 | — | 10,240 골드 |

상승률은 현행 `ItemCatalog.MainValue`로 계산한 무기 기본 능력치이며 최종 DPS나 균열 성공률이 아니다. 비교 팝업은 이 비율 대신 실제 차이인 `(+1.6)`을 표시한다. 현재 장착 대검에는 힘 14·물리 피해 6.5%·이동 속도 3%의 예시 옵션을 넣었다. 판매 대검과 비교하면 힘 +1.9, 물리 피해 −0.7%, 극대화 확률 +3%가 표시되고 이동 속도 3%가 사라지는 속성으로 나온다. 이 옵션 값들도 비교 표현을 확인하기 위한 예시다. 실제 추천은 빌드 평가를 통과해야 한다.

## 8. 구현 소유권과 승인 후 검증

1. 이 문서와 PC·모바일 가로·세로 시안을 검토한다.
2. 기존 장비·전투 계산을 재사용해 불변 후보 평가 계층을 만든다.
3. 제안 `EquipmentShopPolicy`, `EquipmentShopStock`, `GameStore.EquipmentShop`에서 생성·고정 재고·되사기·원자 거래를 담당한다. 이 이름의 파일이 이미 구현되었다는 뜻은 아니다.
4. `ShowTownMerchant`에서 창으로 연결하고 기존 창고의 스타일·슬롯·현지화·안전 영역을 재사용한다. 화면에서 재화를 직접 수정하지 않는다.
5. 저장 호환·거래 영수증·보호 조건·전투·경제를 검증하고 macOS와 모바일 실기기에서 입력을 확인한다.

저장 확장에는 재고 세대, 고정 상품 인스턴스, 구매 완료 상태, 되사기 인스턴스, 영웅별 진행 기준과 출처·정책 버전이 필요하다. 기존 `Item.origin`의 의미를 먼저 조사하고 새 용도로 덮어쓰지 않는다.

필수 검증은 약한 장비로 갈아입기, 상한보다 좋은 장착품, 빈 부위, 세트·룬·무기 계열 변화, 100회 재입고·재접속·영웅 간 전달, 이전 구매품을 포함한 조합, 재화·자리 부족, 중복 입력, 만료 재고, 판매 보호, 원본 되사기 복원이다. 다중 선택의 필터·정렬·탭 전환·해제, 보호품 제외, 일괄 판매의 전부 처리 또는 전체 취소, 12개 한도 경고, 되사기 전체 정보 보존도 검증한다. H=1/12/30과 R=0/16/60 이상을 포함한다. 전투 조건별 성장 폭, 구매율, 사용 시간, 순수익 대비 가격을 측정한다.

이번 자동 선택 실행·수동 모드 분리·미설정 안내 검증은 [8차 검증 기록](EquipmentShop/verification.json)과 [조건 판정·선택 실행·상태 보관 검사](EquipmentShop/auto-selection-policy-checks.json)에 남긴다. [7차 단계별 필터 검증 30항목](EquipmentShop/verification-v7.json), [6차 자동 선택 검증 44항목](EquipmentShop/verification-v6.json), [5차 비교 검증 36항목](EquipmentShop/verification-v5.json), [4차 정보 밀도 검증](EquipmentShop/verification-v4.json), [3차 기능 검증 43항목](EquipmentShop/verification-v3.json)은 별도로 보존한다. 과거 기록을 합쳐 이번 개정에서 모두 다시 검사했다고 해석하지 않는다. 실제 저장·Unity 구현·전체 회귀·실기기 터치·성능의 증거도 아니다.
