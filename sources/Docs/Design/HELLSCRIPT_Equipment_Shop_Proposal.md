# HELLSCRIPT 무기·장비 상점 기획 검토안

작성일: 2026-09-20 · 상태: 승인 전 기획·시안 · [English](HELLSCRIPT_Equipment_Shop_Proposal.en.md)

장비 상점은 사냥으로 얻은 장비 사이의 작은 빈틈을 메운다. 플레이어가 가진 것보다 조금 나은 장비를 골라 사고, 기존 강화 기능으로 조금 더 개선한 뒤 다시 균열에 도전하는 흐름을 만든다. 상점 구매를 반복하는 것만으로 다음 성장 단계를 건너뛰게 해서는 안 된다.

이 문서와 화면은 검토용이다. 게임 런타임·사용자 저장·실제 재화에는 연결하지 않았다. 수치 범위와 가격 배율은 **초기 튜닝 가설**이며, 실제 전투와 경제 검증을 통과한 확정 밸런스가 아니다.

## 1. 디아블로 4에서 가져오는 구조

2026-09-20에 내장 브라우저로 공개 자료를 확인했다. 화면 배치는 [무기 상점 원본 캡처와 설명](https://guides4gamers.com/diablo-4/pois/weapons/)을 기준으로 삼았다. 해당 캡처의 경로는 2023년 3월 자료이므로 최신 시즌과의 완전한 일치를 주장하지 않는다. [무기 상인](https://diablo4.wiki.fextralife.com/Weapons+Vendor)과 [방어구 상인](https://diablo4.wiki.fextralife.com/Armor+Vendor)의 2026-05-02 갱신 설명에서는 제한된 상품, 골드 거래, 60분 재입고와 남은 시간 표시를 확인했다. 이는 커뮤니티 문서이며 블리자드의 내부 상품 생성 공식을 확인한 것은 아니다.

| 관찰한 D4 구조 | HELLSCRIPT 적용 |
|---|---|
| 왼쪽 상인·세로 상품 목록 | 왼쪽 상품 목록을 유지한다. 새 상인 초상화 대신 기존 성소의 장비 상인과 연결한다. |
| 오른쪽 캐릭터 장비와 가방 | 현재 장착 장비·8열 가방을 오른쪽에 놓는다. |
| 선택 상품의 상세와 장착 비교 | 넓은 화면에서는 가운데 고정 비교창을 쓴다. 좁은 화면에서는 상품을 누르면 상세 화면으로 전환한다. |
| 아래쪽 되사기 목록 | 최근 판매품을 되산다. **보관 개수 12개와 재접속 보존은 본 기획의 제안**이다. |
| 재입고 시간 | 60분 단위로 상품을 바꾸되, 구매로 성능 상한이 올라가지는 않는다. |
| 골드로 구매·소지품 판매 | 구매 전에 상품의 모든 수치와 가격을 보여 준다. 판매는 소지품에서 선택한다. |

추천 생성 공식, 6개 상품 구성, 성장 상한은 HELLSCRIPT를 위한 신규 정책이다. D4의 확인되지 않은 내부 공식을 그대로 재현했다고 표현하지 않는다. 강화·분해·접사 재설정은 기존 대장장이 기능을 사용한다. 기존 미확인 장비 상점은 확률형 구매라는 별도 역할을 유지하며 이번 검토에서 제거하지 않는다.

## 3. 화면과 거래 흐름

### 가로 화면

상단에 상점 제목·닫기·언어를 둔다. 왼쪽에는 무기·방어구·장신구 분류와 상품 6개, 재입고 시간을 둔다. 가운데에는 선택 상품·기본 능력치·접사·현재 장착/보유 최고 비교·강화 1회 미리보기·구매 버튼을 둔다. 오른쪽에는 영웅 레벨, 현재 장착 장비, 8열 소지품과 판매 조작을 둔다. 왼쪽 아래에는 되사기 탭을 둔다.

### 세로 화면과 작은 가로 화면

상품 목록을 먼저 보여 준다. 상품을 누르면 같은 창 안의 상세 화면으로 전환하며 상단에 목록 복귀를 둔다. 구매·판매·되사기 탭, 제목, 재화, 구매 조작은 화면 안전 영역 안에 고정한다. 상품 목록과 상세 본문만 스크롤한다. 작은 화면에서 3열을 억지로 축소하지 않는다. 가방은 같은 8열 슬롯을 유지하되 세밀한 드래그 대신 탭 선택과 판매 버튼을 제공한다.

390×844·844×390·1600×900과 최소 320px 너비를 기준으로 설계한다. 실제 게임 구현 시 글자 125%/150%, 노치·홈 표시줄과 손가락 조작을 추가 확인한다. 대화 안의 시안은 내용 높이에 맞춰 펼쳐지는 검토 화면이며, Unity의 고정 안전 영역과 내부 스크롤 검증을 대신하지 않는다.

### 구매

1. 상품을 선택하면 생성된 실제 장비 인스턴스의 수치·등급·아이템 레벨·착용 요구 레벨·가격을 보여 준다.
2. 기본 비교는 현재 장착 장비다. 가방·창고에 더 좋은 호환 장비가 있으면 그 위치를 알리고 보유 최고 비교로 전환할 수 있다.
3. 강화 미리보기는 비용과 재료를 별도로 보여 준다. 미리보기를 켜도 구매품은 +0이며 비용을 자동으로 청구하지 않는다.
4. 구매를 누르면 가격이 표시된 버튼을 통해 1회 거래한다. 골드·가방 자리·상점 세대·상품 ID를 마지막으로 재검증한다.
5. 구매품은 가방으로 들어가고 상품은 판매 완료가 된다. 같은 자리에 새 상품을 즉시 만들지 않는다. 자동 장착하지 않는다.

### 판매·되사기

- 현재 장착·잠금·프리셋 참조·보석 장착 장비의 판매 보호는 `Economy.Protected`와 계정 전체 참조 검사를 유지한다.
- 단품 판매부터 제공한다. 일괄 판매는 이번 1차 범위에서 제외한다.
- 되사기는 최근 12개의 **원래 장비 인스턴스 전체**를 판매 당시 가격으로 복구한다. 강화·접사·소켓·획득 순서·출처를 다시 추첨하지 않는다.
- 재입고와 되사기 이력은 별도다. 상점 닫기와 정상 재접속으로 되사기 목록이 사라지지 않도록 저장한다. 13번째 판매로 밀려나는 품목은 판매 전에 알린다.
- 재화 부족·가방 가득 참·이미 구매됨·재입고로 만료됨은 버튼 주변에 이유를 표시하고 거래하지 않는다. 겹친 입력은 동일 영수증으로 1회만 반영한다.

## 4. 레벨을 세 종류로 구분한다

현행 코드에서 영웅 레벨 `H`는 최대 30, 아이템 레벨 `I`는 최대 60이다. 착용 요구 레벨은 `min(30, (I+1)/2)`의 정수 계산이다. 최고 균열 클리어 `R`은 별도 필드다. 현재 장비 상인은 `R` 기준 일반 장비만 생성하므로 플레이어가 원하는 ‘소폭 개선’은 보장하지 못한다.

신규 상품의 초기 아이템 레벨 상한은 다음으로 제안한다.

```text
I_cap = min(60, 2 × H, max(1, R) + 2)
후보는 1..I_cap의 합법적인 기존 장비 정의에서 생성한다.
현재 비교 대상의 아이템 레벨 주변부터 탐색하되 상한을 넘지 않는다.
```

예를 들어 H=12, R=16이면 I_cap=18이다. H=30, R=20이면 I_cap=22이므로 영웅 레벨만 높다고 I60 장비를 판매하지 않는다. 영웅이 이미 상한보다 좋은 장비를 갖고 있다면 그 장비를 이기려고 상한을 올리지 않는다. 빈 부위는 해당 직업의 시작 장비와 실제 무장 상태를 비교하며, 분모가 0인 상승률을 만들지 않는다.

## 5. ‘약간 좋음’을 계산하는 방법

### 5.1 비교 기준과 성장 기준을 분리한다

**구매 가치 비교 B:** 현재 장착 장비, 해당 영웅의 가방, 계정 공용 창고에서 지금 착용할 수 있는 같은 부위 장비를 모은다. 다른 직업·요구 레벨 미달 장비는 제외한다. 다른 영웅이 장착한 장비는 즉시 쓸 수 있는 보유품으로 간주하지 않는다. 도검·대검·도끼처럼 무기 숙련과 룬 보드가 달라지는 경우 같은 무기 계열을 먼저 비교한다.

모든 장비를 하나의 공격력 점수로 정렬하지 않는다. 현재 빌드에서 공격·생존의 양쪽을 비교해 서로 장단점이 있는 후보를 유지한다. 같은 역할에서 이미 보유한 장비가 상품의 모든 핵심 수치를 앞서면 추천하지 않는다. 현재 장착품보다 좋아도 창고의 같은 역할 장비보다 못하면 `창고에 더 좋은 장비가 있습니다`라고 표시한다.

**성장 기준 A:** 해당 영웅이 실제로 얻은 비상점 장비와 클리어 진행도로 만든 기준을 별도로 저장한다. 장비를 벗거나 팔거나 창고로 옮겨도 기준을 낮추지 않는다. 기준은 `(영웅, 진행 구간, 부위, 무기 계열, 평가 버전)`으로 구분한다. 단순히 현재 보유품을 매번 다시 읽는 방식으로 초기화하지 않는다.

상점 구매품과 그 품목을 강화·재설정·되산 결과는 A를 올리지 않는다. 균열·상자·보스·정상 소탕에서 얻은 새 전리품과 실제 진행 변화만 A를 갱신한다. 제작품은 B에 포함하지만 A를 올리지는 않는다. 상점 장비를 분해한 재료로 제작해 출처 제한을 우회하는 경로를 막기 위해서다. 기존 저장의 출처 불명 장비는 도입 시점에 1회 기준으로 스냅샷하고, 이후에는 거래 출처를 명시한다. 창고를 거치거나 다른 영웅에게 전달해도 출처를 보존한다. 따라서 재입고와 구매를 반복해도 상점 스스로 다음 목표를 올리는 연쇄 상승이 생기지 않는다.

### 5.2 아이템 단품 수치 대신 교체 후 빌드를 평가한다

현재 영웅·사냥 칙령·스킬·룬·다른 부위 장비를 복사하고 후보 부위만 교체한다. 일시적 물약과 전투 버프는 기준에서 제외한다. 기존 `HeroStats`, 장비·룬 기여, 전투 시뮬레이션을 재사용한다. 현재 훈련 장비 비교는 **보유품만** 허용하므로 상점 후보를 넣기 위해 그 검사를 약하게 만들지 않는다. 검토 전용 복사본을 평가하는 별도 진입점을 설계한다.

| 평가 항목 | 확인 내용 |
|---|---|
| 지속 공격 성능 D | 동일 시간의 일반 무리·정예·보스에서 자원 부족, 공격 속도, 스킬 주기까지 포함한 유효 피해를 비교한다. |
| 생존 성능 E | 같은 적 공격 패턴에서 생존 시간·누적 피해 허용량을 비교한다. 물리와 원소 피해를 별도로 확인한다. |
| 빌드 보존 | 세트 효과의 해제, 핵심 전설 효과 상실, 룬 보드·무기 숙련 전환, 자원 순환 악화를 확인한다. |
| 편의 성능 U | 이동·회수·골드 획득은 별도 장점으로 표시하며 공격력으로 합산하지 않는다. |

초기에는 `HeroStats`로 저렴하게 후보를 줄이고 상위 후보만 고정 시드·고정 전투 조건으로 정밀 평가한다. 정밀 평가는 최소 일반/정예/보스와 물리/원소 패턴을 포함한다. 반복 결과의 중앙값과 불리한 경우를 확인해 특정 시드에서만 좋은 후보를 추천하지 않는다. 전투 조건·횟수·평가 버전을 결과와 함께 저장한다.

### 5.3 초기 허용 범위

| 판단 | 초기 검토값 |
|---|---|
| 공격형 추천 | D가 비교 기준보다 2~5% 높고 E가 1% 넘게 하락하지 않아야 한다. |
| 생존형 추천 | E가 2~5% 높고 D가 1% 넘게 하락하지 않아야 한다. |
| 구매 후 강화 1회 | 같은 원래 비교 기준에서 핵심 성능이 10%를 넘게 뛰면 추천 후보에서 제외한다. |
| 여러 상품 동시 구매 | 같은 성장 기준에서 추천 상품의 합법적인 조합 전체를 평가한다. +0에서 D·E 각각 +8%, 추천 상품을 모두 +1로 만들었을 때 각각 +12%를 초기 상한으로 둔다. |
| 장기 강화 | +5와 현재 해금된 걸작까지 가능한 경로를 추가 검사한다. 해당 균열 구간의 기존 드롭·강화 장비 상한을 넘는 상품은 제외한다. |
| 성장 단계 | 다음 단계와 그 다음 단계의 기준 전투를 비교한다. 상점만으로 여러 단계의 성공 조건을 새로 충족하면 상한을 낮춘다. 실제 성공 조건은 기존 균열 완료 판정이다. |

서로 다른 척도를 평균내서 큰 공격 상승을 생존 하락으로 상쇄하지 않는다. 세트 해제와 핵심 룬 손실이 있으면 자동 추천을 중단하고 비교 정보만 보여 준다. `+2~5%`는 모든 상품에 붙이는 보증이 아니라 추천을 붙이기 위한 조건이다. 평가기가 충분히 확신하지 못하면 `성능 비교 필요`로 둔다.

강화 비용과 장기 성장 경로는 기존 규칙을 유지한다. 예산에 따라 지금 구매와 함께 가능한 강화 단계도 검사하므로, 재료가 많은 플레이어에게 +1만 검사하고 안전하다고 판정하지 않는다. +2 이상을 즉시 할 수 있으면 그 단계의 결과를 구간 상한과 비교해 상품을 제한한다. 이 상한은 실제 드롭 분포와 전투 검증으로 확정해야 하며, 검토 숫자만으로 성장 속도가 안전하다고 단정하지 않는다.

### 5.4 합법적인 후보를 고른다

기존 `ItemGenerator`에서 부위별 최대 128개 후보를 만든 후 선택한다. 기존에 없는 접사·등급·소켓·수치 범위를 만드는 후처리는 하지 않는다. 상점 장비는 +0, 일반/마법/레어, 비각성으로 제한한다. 전설·세트·상위 접사는 1차 판매 후보에서 제외하여 파밍의 역할을 유지한다. 후보량과 정밀 평가량은 프로파일링 후 조절한다.

```text
1. 레벨·직업·균열 상한으로 합법 후보 풀을 제한한다.
2. 소유품 B와 저장된 성장 기준 A를 불러온다.
3. 기존 생성기로 후보를 만들고, 장비 규칙을 검증한다.
4. +0 / +1 / 즉시 가능한 강화 / 장기 상한을 평가한다.
5. 이미 가진 동역할 장비보다 약한 후보와 빌드 손실 후보를 제외한다.
6. 개별·묶음 성능 상한을 모두 만족하는 소수 상품을 고른다.
7. 조건을 만족하는 후보가 없으면 추천을 만들지 않는다.
8. 장비 전체·가격·세대·평가 근거를 고정해서 저장하고 표시한다.
```

초반처럼 아이템 레벨 1 상승이 8%를 올리는 구간에는 2~5% 추천을 만들 수 없을 수 있다. 이때 수치를 임의로 깎거나 가짜 추천을 만들지 않는다. 합법적인 저가 기본 장비나 다른 역할 장비를 보여 주고 추천은 비운다. 최고 수준의 장비를 가진 플레이어에게도 억지로 더 강한 상품을 보장하지 않는다.

## 6. 재고·가격·반복 구매

기본 재고는 6개다. 무기 2, 방어구 3, 장신구 1을 초기 구성으로 삼되, 실제 장비 분포를 보고 약한 부위에 최대 2개의 추천을 배정한다. 적합한 추천이 없으면 같은 역할의 보충 장비로 대체하고 의미 없는 장비를 추천으로 포장하지 않는다.

- 60분 재입고와 실제 영웅 레벨/최고 클리어 변화에서 재고 세대를 갱신한다. 단순 재접속·창 열기·장비 교체·구매는 재고를 재추첨하지 않는다.
- 같은 영웅의 다른 마을 상인도 같은 재고 ID를 쓴다. 1상품 1개이며 구매가 완료된 슬롯을 즉시 보충하지 않는다.
- 시간이 바뀌어도 진행 구간의 A와 절대 상한은 유지한다. 새로 갱신된 추천들과 이미 산 상품의 조합도 상한 검사를 받는다.
- 현 프로젝트는 로컬 저장이므로 기기 시계 조작을 서버 수준으로 막을 수 없다. 마지막 확인 시각·재고 세대를 저장해 뒤로 돌리기와 재시작을 제한하되, 시계 신뢰와 무관하게 성장 상한으로 피해를 제한한다.
- 일반 보충 장비는 기존 `TownTrade.EquipmentPrice`를 출발점으로 삼는다. 마법·레어는 `8 × Item.Price`를 초기 가격으로 제안한다. 개인의 지갑 크기에 따라 같은 상품을 더 비싸게 팔지 않는다.
- 같은 상품의 구매가는 판매가보다 높아야 한다. 되사기는 판매 당시 가격이다. 일반 보충 장비도 생성 후 `구매가 > 판매가`를 검증한다.
- 구매+예정 강화의 총비용이 같은 진행 구간에서 약 2~4회 정상 사냥의 순수익에 해당하는지 측정한다. 이번 시안의 가격은 경제 실측 결과가 아니다.

## 7. 시안의 수치 예시

예시 영웅은 Lv.12 전사, 최고 균열 16단계다. 실제 사용자 저장을 읽은 값이 아니다. 이름·그림·부위는 현행 카탈로그를 사용하고, 무기 기본 수치는 현행 `ItemCatalog.MainValue` 공식으로 계산했다.

| 항목 | 현재 장착 | 판매 상품 | 판매 상품 +1 |
|---|---:|---:|---:|
| 베이스 | B02 강철 대검 | B02 강철 대검 | 같은 구매품 |
| 아이템 레벨 | 15 | 16 | 16 |
| 무기 공격력 | 42.40 | 44.00 | 46.20 |
| 장착품 대비 기본 공격력 변화 | — | +3.77% | +8.96% |
| 장비 가격 | 판매가 1,200 | 구매가 10,240 | 별도 강화비 3,200 + 재료 20 |

이 예시의 접사는 합법 범위의 설명용 수치다. 표의 상승률은 **무기 기본 공격력**이며 최종 DPS·균열 성공률이 아니다. 정식 추천 배지는 위의 빌드 평가를 통과해야 한다. 시안에서는 `소폭 개선` 표시가 상품 선택과 비교 표현을 검토하기 위한 예시임을 구분한다.

## 8. 구현 소유권과 순서

| 단계 | 작업과 책임 |
|---|---|
| 1. 기획 확정 | 이 문서의 재고 구성·성능 범위·가격 가설과 가로·세로 시안을 검토한다. |
| 2. 평가 기반 | 기존 장비 계산·훈련 복사본을 재사용하는 후보 평가 계층을 만든다. 후보가 실제 보유 목록에 들어가지 않게 한다. |
| 3. 거래·저장 | 제안 `EquipmentShopPolicy`, `EquipmentShopStock`, `GameStore.EquipmentShop`이 생성·고정 재고·되사기·원자 거래를 담당한다. 이름은 제안이며 현재 구현된 파일이 아니다. |
| 4. 화면 연결 | `ShowTownMerchant`에서 신규 창으로 연결하고 `StorageWindow.Style`·장비 그림·현지화를 재사용한다. 화면에서 재화를 직접 수정하지 않는다. |
| 5. 실제 검증 | 저장 호환·영수증·보호 조건·전투 조합·경제를 검증한 뒤 macOS와 모바일에서 입력을 확인한다. |

저장 확장에는 재고 세대, 고정 상품 인스턴스, 구매 완료 상태, 최근 판매 인스턴스, 영웅별 성장 기준, 출처와 정책 버전이 필요하다. `Item.origin`의 기존 용도를 먼저 조사하고 새 의미를 덮어쓰지 않는다. 새 출처 필드는 이전 저장을 읽을 때 안전하게 기본값을 채운다.

## 9. 승인 후 필요한 검증

| 상황 | 합격 기준 |
|---|---|
| 약한 장비로 갈아입고 방문 | 성장 기준과 판매 상한이 낮아지거나 재추첨되지 않는다. |
| 창고에 더 좋은 장비가 있음 | 현재 장착보다 높다는 이유만으로 추천하지 않는다. |
| 강화를 많이 한 기존 장비 | 같은 강화 단계로 거짓 비교하지 않고 현재 실성능과 총비용을 비교한다. |
| 세트·룬·무기 계열 변경 | 수치 일부 상승으로 핵심 효과 손실을 숨기지 않는다. |
| 재입고·재접속·부캐 전달 100회 | 비상점 진행이 없을 때 A와 구간 성능 상한이 증가하지 않는다. |
| 골드 부족·가방 가득 참·중복 클릭·세대 변경 | 무차감 또는 정확히 1회 반영하며 구매품을 다시 추첨하지 않는다. |
| 되사기·정상 재접속 | 원래 아이템 ID·접사·강화·출처·판매가가 보존된다. |
| H=1/12/30, R=0/16/60 이상 | 요구 레벨·아이템 60 상한·균열 상한을 모두 지킨다. |
| 강화 가능한 재료가 많음 | +1만 검사하지 않고 즉시 가능한 강화 후의 구간 상한도 지킨다. |
| 추천 상품 여러 개와 이전 구매품 조합 | 개별 적합성뿐 아니라 합산 성능 상한을 지킨다. |
| 전투·경제 | 실제 전투 조건별 성장 폭, 구매율, 구매 후 사용 시간, 순수익 대비 가격을 기록한다. |

시안 검증 범위는 별도의 `EquipmentShop/verification.json`에 기록한다. 그것은 브라우저 시안의 동작과 화면 확인이며 Unity 구현·전체 회귀·모바일 실기기 증거가 아니다.
