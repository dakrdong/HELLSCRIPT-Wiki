# HELLSCRIPT 사냥 칙령: 저장·공유·프리셋·스킬 설정

작성일: 2026-09-09 · 상태: 사용자 추가 요구를 반영한 설계안 · 게임 기능 구현 완료 기록이 아닙니다.

사냥 칙령(Hunt Edict)은 캐릭터의 자동 사냥 행동을 정하는 기능입니다. **사용할 스킬의 선택·배치, 전역 설정, 개별 스킬 설정을 하나의 저장 대상으로 묶습니다.** 프리셋을 불러오면 연결된 스킬이 사용 스킬 칸에 함께 배치되고 그 스킬의 옵션도 복원됩니다. 저장한 구성은 다른 플레이어에게 코드로 전달할 수 있습니다. 화면의 보조 명칭은 ‘자동 사냥 행동 설정’입니다.

## 1. 결정 사항과 설계 범위

| 구분 | 내용 |
|---|---|
| 사용자 요구 | 설정은 명시적으로 저장할 때만 저장합니다. 변경이 있으면 저장하기·되돌리기를 제공하고, 미저장 페이지 이탈 시 저장 여부를 묻습니다. |
| 사용자 요구 | 저장한 속성으로 코드를 생성합니다. 이름을 붙여 보관하는 프리셋 슬롯 5개, 불러오기, 코드를 클립보드에 복사하는 공유하기를 제공합니다. |
| 사용자 요구 | 다른 플레이어도 같은 코드를 입력하면 같은 프리셋 내용을 가져올 수 있어야 합니다. |
| 사용자 요구 | 모든 스킬의 사냥 칙령 옵션을 정의하되, 일반 편집 화면에는 현재 장착한 스킬만 표시합니다. 스킬을 언제든 바꿀 수 있는 방향을 적용합니다. |
| 사용자 추가 확인 | 사용할 스킬 선택과 사냥 칙령을 연결합니다. 프리셋 하나에 사용 스킬 배치와 해당 스킬의 옵션을 함께 저장하고, 불러올 때 두 내용을 함께 복원합니다. |
| 사용자 추가 확인 | 다른 사람의 프리셋에 미보유·미해금 스킬이 있으면 보유한 스킬만 원래 칸에 배치하고 나머지는 빈칸으로 둡니다. 사용할 수 있는 내용은 가져오고, 빈칸의 이유를 알려 사용자가 다른 보유 스킬로 직접 채울 수 있게 합니다. |
| 사용자 추가 확인 | 스킬당 직접 편집하는 옵션은 최대 8개이며 4~6개를 권장합니다. 핵심 옵션 v0.2는 자동 사용을 포함해 4~5개로 구성하고, 스킬 카드의 임의 조건식·규칙 추가·고급 옵션 편집을 제거합니다. |
| 담당 설계안 | 기존 캐릭터별 저장 구조를 이어서 캐릭터마다 5개 슬롯을 제공합니다. 코드 형식·이름 길이·미저장 경고의 취소 버튼·호환성 처리는 아래의 구현 기준 제안입니다. |
| 이번 문서의 범위 | 공통 저장 흐름, 코드 재현 범위, 프리셋, 스킬 표시·교체와 검증 기준을 정합니다. 실제 구현과 기기 검증 여부는 별도로 기록해야 합니다. |

이 요구는 기존 기획의 ‘사용자 저장 슬롯 3개’와 ‘균열에서 스킬 장착 변경 금지’를 해당 범위에서 대체합니다. 액티브 6개 중 최대 4개, 패시브 6개 중 최대 3개의 장착 상한과 실제 스킬 해금 조건은 유지합니다. ‘언제든 교체’는 잠긴 스킬을 지급하거나 재사용 대기시간을 초기화한다는 뜻이 아닙니다.

관련 원본은 [전역 8개 분류](HELLSCRIPT_Hunt_Edict_Global_Options.md), [스킬 옵션·화면 요약](HELLSCRIPT_Hunt_Edict_Skill_Options.md), [스킬별 핵심 옵션 v0.2](HELLSCRIPT_Hunt_Edict_Skill_Option_Catalog.md), [기존 상위 기획](HELLSCRIPT_Unity_Implementation_Plan.md), [콘텐츠 카탈로그](HELLSCRIPT_Content_Catalog.md)입니다. 저장·배치 정책은 이 문서, 개별 스킬의 편집 범위는 핵심 옵션 v0.2의 최신 변경을 우선합니다.

## 2. 화면 구조

```text
사냥 칙령 · Hunt Edict
├─ 전역 설정
│  ├─ 회피 규칙
│  ├─ 긴급 생존·회복
│  ├─ 전투 위치·몰이
│  ├─ 공격 대상·추적
│  ├─ 전리품 회수
│  ├─ 가방·자동 정리
│  ├─ 탐색·상호작용
│  └─ 반복 사냥·중단
├─ 사용 스킬·개별 설정
│  ├─ 사용할 액티브 선택·배치 [사용 스킬 칸 1~4]
│  │  ├─ 각 칸: 스킬 선택 / 교체 / 해제
│  │  ├─ 미보유 스킬 자리: 빈칸 + 원본 스킬·이유 + 보유 스킬 선택
│  │  └─ 배치 변경 → 연결된 스킬 카드와 옵션을 함께 갱신
│  ├─ 현재 직업의 기본 공격
│  ├─ 위 배치에서 선택한 액티브 목록 [최대 4개]
│  │  └─ 자동 사용 + 고유한 사용 방식 [총 4~6개 권장, 최대 8개]
│  └─ 장착 패시브의 효과·발동 조건 [읽기 전용]
├─ 프리셋
│  ├─ 슬롯 1~5: 이름·직업·스킬 구성·코드
│  │  ├─ 불러오기
│  │  ├─ 저장된 현재 설정으로 덮어쓰기
│  │  ├─ 이름 수정 후 저장
│  │  └─ 공유하기 [해당 슬롯의 코드 복사]
│  └─ 공유 코드 입력 → 내용·호환성 확인 → 불러오기 또는 보관
└─ 공통 저장 영역
   ├─ 상태: 저장됨 / 저장하지 않은 변경 있음 / 저장 실패
   ├─ 저장하기
   ├─ 되돌리기
   ├─ 마지막 저장본의 코드
   ├─ 프리셋으로 저장
   └─ 공유하기 [현재 저장본의 코드 복사]
```

큰 설정 분류는 접고 펼치는 카드로 표시하고, 접힌 상태에서 현재 값을 요약합니다. 세부 수치는 해당 기능을 켜거나 조건 방식을 선택했을 때만 표시합니다. 같은 페이지의 카드 펼침·스크롤은 이탈이 아닙니다. 전역·스킬·프리셋을 별도 페이지로 구현한다면, 그 페이지를 떠나는 이동도 미저장 이탈 검사 대상입니다. 하위 선택 창에서 돌아오는 동작은 같은 편집 작업으로 유지합니다.

**‘사용 스킬 칸 4개’와 ‘프리셋 보관 슬롯 5개’는 다른 공간입니다.** 사용 스킬 칸은 현재 사용할 액티브를 배치하고, 프리셋 슬롯은 그 배치와 사냥 칙령 전체의 복사본을 보관합니다. 사용 스킬의 선택·교체·배치 순서를 바꾸면 해당 스킬 카드도 같은 편집본을 기준으로 갱신합니다. 별도의 스킬 장착 화면에서 진입하더라도 같은 장착 구성과 저장 흐름을 사용하며, 사냥 칙령 안에 다른 사용 스킬 목록을 따로 만들지 않습니다.

## 3. 저장·편집·되돌리기

### 3.1 서로 다른 세 가지 내용

| 이름 | 역할 | 변경되는 시점 |
|---|---|---|
| 임시 편집본 | 현재 화면에서 수정하는 사용 스킬 배치와 전역·스킬 설정입니다. | 스킬 선택·배치·옵션 변경 또는 프리셋·공유 코드 불러오기 때 바뀝니다. 저장 전에는 실제 사냥과 영구 저장에 반영하지 않습니다. |
| 현재 저장본 | 마지막으로 저장에 성공한 사냥 칙령입니다. | ‘저장하기’가 성공했을 때만 바뀝니다. 실제 사냥과 공유 코드의 기준입니다. |
| 슬롯의 프리셋 | 특정 저장 내용을 이름과 함께 보관한 독립 복사본입니다. | 슬롯 저장·덮어쓰기·이름 저장을 명시적으로 실행했을 때만 바뀝니다. 현재 설정을 바꿔도 기존 슬롯은 바뀌지 않습니다. |

사용 스킬 배치와 전역 설정, 모든 스킬 설정은 한 사냥 칙령의 구성요소입니다. ‘저장하기’는 현재 편집본 전체를 검증하고 함께 저장합니다. 미보유 스킬을 빈칸으로 둔 구성을 저장하는 것은 허용하지만, 저장 처리 도중 스킬만 교체되고 옵션은 이전 상태로 남는 불일치는 허용하지 않습니다. ‘되돌리기’도 배치와 옵션을 함께 마지막 저장 성공본으로 복원합니다. 변경 요약에는 교체·추가·해제한 스킬과 배치 칸의 변경을 옵션 변경과 함께 보여 줍니다.

진행 상황·획득 재화의 기존 자동 저장은 유지할 수 있지만, 그 저장에는 마지막으로 확정한 설정만 들어갑니다. 임시 편집본을 계정·전투 저장 객체에 연결하지 않습니다. 앱이 강제 종료되면 미저장 편집 내용은 없어지고 마지막 저장 성공본으로 복귀합니다.

### 3.2 버튼과 상태

| 상태 | 저장하기 | 되돌리기 | 현재 설정의 공유·프리셋 저장 |
|---|---|---|---|
| 저장본과 동일 | 비활성화합니다. | 비활성화합니다. | 저장된 코드가 있으면 사용할 수 있습니다. |
| 변경 있음 | 활성화합니다. | 활성화합니다. | ‘먼저 변경 내용을 저장하세요’와 함께 비활성화합니다. 기존 슬롯 자체의 공유는 그 슬롯 내용으로 가능합니다. |
| 잘못된 값 있음 | 오류 위치를 안내하고 저장을 완료하지 않습니다. | 사용할 수 있습니다. | 미저장 내용을 코드로 내보내지 않습니다. |
| 저장 실패 | 편집본을 유지하고 재시도를 허용합니다. | 마지막 저장 성공본으로 돌아갈 수 있습니다. | 이전 저장본과 코드를 유지하며 새 저장 완료 표시를 하지 않습니다. |

‘되돌리기’는 기본값 초기화가 아니라 마지막 저장 성공본으로의 복귀입니다. 프리셋을 불러온 뒤 되돌리면 불러오기 전의 현재 저장본으로 돌아갑니다. 값을 수동으로 원래대로 되돌린 경우에도 실제 설정 비교 결과가 같으면 변경 표시를 해제합니다. 스크롤·선택 카드·슬롯 이름 입력·저장 시각은 사냥 설정의 변경 판정에 섞지 않습니다.

슬롯 이름에는 사냥 설정과 별도의 변경 상태를 둡니다. 이름만 수정해도 해당 슬롯의 저장·되돌리기와 페이지 이탈 확인은 활성화되지만, 사냥 설정 코드가 달라졌다고 표시하지 않습니다. 이탈 팝업은 ‘사냥 설정’, ‘슬롯 2 이름’처럼 저장·폐기할 범위를 함께 표시합니다. 한 페이지에 두 종류의 변경이 함께 남아 있다면 ‘저장하고 나가기’는 표시한 범위를 모두 검증해 함께 저장한 뒤 이동하고, 실패하면 해당 작업 전체를 유지합니다.

저장 처리는 ‘전체 검증 → 영구 저장 성공 → 현재 저장본·실행 설정 확정 → 새 코드 표시’ 순서를 보장합니다. 실패하면 실제 사냥 설정과 저장본을 이전 상태로 유지하고 임시 편집본은 남깁니다. 저장 후 실제 전투 반영에 실패하는 상태가 생기지 않도록 적용 가능성도 저장 전에 검증합니다.

### 3.3 미저장 이탈 팝업

제목: **변경한 사냥 칙령을 저장할까요?**

본문: **저장하지 않은 변경 내용이 있습니다.**

| 버튼 | 결과 |
|---|---|
| 저장하고 나가기 | 저장 성공 후 요청한 페이지로 이동합니다. 실패하면 편집 화면과 변경 내용을 유지합니다. |
| 저장하지 않고 나가기 | 임시 편집본을 버리고 이전 저장본을 유지한 채 이동합니다. |
| 계속 편집하기 | 이탈을 취소합니다. 팝업의 닫기·뒤로 가기도 같은 의미입니다. |

뒤로 가기, 다른 메뉴·캐릭터로 이동, 실제 설정 페이지 간 이동, 일반 종료 요청에 같은 처리를 사용합니다. 운영체제가 강제로 앱을 종료하는 경우에는 팝업을 보장할 수 없으며 미저장 값을 자동으로 확정하지 않습니다. 변경 사항이 없으면 팝업을 띄우지 않습니다.

## 4. 코드 생성·공유·가져오기

### 4.1 같은 코드가 담는 내용

공유 코드는 서버의 임의 레코드 번호가 아니라 설정 내용을 담는 자체 완결형 문자열로 설계합니다. 커뮤니티의 오래된 글에서 복사하더라도 원래 작성자의 계정·슬롯에 의존하지 않고 내용을 읽을 수 있어야 합니다.

| 코드에 포함 | 코드에서 제외 |
|---|---|
| 코드 형식 버전, 설정 스키마·콘텐츠 기준 버전 | 계정 ID·캐릭터 개인 ID·작성자 개인정보 |
| 직업 ID, 사용 스킬 칸 1~4 각각의 액티브 ID 또는 빈칸 | 현재 HP·자원·위치·남은 재사용 대기시간 |
| 전역 8개 분류의 모든 설정과 행동 우선순위 | 경험치·골드·보상·진행 중 균열·난수 상태 |
| 기본 공격과 해당 직업 6개 액티브의 설정, 미장착 보관 설정 | 개인 장비 인스턴스 ID·장비 소유권·로컬 프리셋의 장비 보호 참조 |
| 조건·목표·이동·스킬 간 참조의 안정적인 콘텐츠 ID | 프리셋 이름·슬롯 번호·저장 시각·임의 생성 규칙 ID |

장착한 액티브 구성을 포함해 어떤 스킬 설정을 사용할지도 재현합니다. 패시브의 고유 효과·피해 수치·장비 능력치는 사냥 칙령의 편집 대상이 아닙니다. 해당 효과를 전제로 하는 조건은 원래 ID로 보존하고, 다른 플레이어가 그 효과를 보유했는지는 별도로 표시합니다. 코드는 장비나 미해금 스킬을 지급하지 않습니다.

사용 스킬은 칸 번호와 안정적인 스킬 ID를 연결해 저장하며 빈칸도 명시합니다. 세 스킬만 배치한 프리셋을 불러오면 나머지 칸은 원본대로 비워 두고, 수신자가 이전에 사용하던 네 번째 스킬을 남기거나 빈칸을 자동으로 당겨 채우지 않습니다. 옵션은 칸 번호가 아니라 스킬 ID에 연결하므로 같은 스킬을 다른 칸으로 옮겨도 그 스킬의 옵션이 따라갑니다. **배치 칸 순서는 화면의 구성이고, 실제 스킬 실행 순서는 별도로 저장한 행동 우선순위입니다.**

**같은 버전에서 같은 코드를 해석한 원본 내용은 동일해야 합니다.** 요구 스킬을 모두 보유하면 전역 설정·스킬 설정·장착 액티브 구성·순서를 그대로 복원합니다. 미보유 스킬이 있으면 사용자 요청에 따라 해당 배치 칸을 비운 편집본을 만들고 ‘일부 스킬 적용’으로 표시합니다. 이 경우에도 원본의 스킬 ID와 옵션을 삭제하거나 다른 스킬로 자동 대체하지 않습니다. 장비·패시브·레벨·적·지도 차이에 따른 전투 결과까지 같게 만든다는 뜻은 아닙니다.

### 4.2 코드 형식 제안

형식은 `HED1.<설정 데이터>.<오류 확인값>`을 제안합니다. 이 문구는 형식 설명이며 실제 사용할 수 있는 프리셋 코드는 아닙니다.

설정 데이터는 정규화한 데이터의 UTF-8 바이트를 URL 안전 문자로 표현합니다. 압축을 도입한다면 압축 방식·버전도 고정하고 동일 입력의 결과가 변하지 않는지 검사합니다. 필드 순서·생략 가능한 값의 기본값·숫자 정밀도를 통일하고, 선택의 순서가 의미 있는 행동·장착 목록은 순서를 보존합니다. 스킬은 배열 위치 대신 W01·A01·M01 같은 콘텐츠 ID를 사용합니다. 내부 규칙 참조에는 같은 내용에서 재현되는 식별 방식을 사용합니다.

동일한 설정과 버전에서 다시 저장하면 동일한 코드가 나와야 합니다. 이름만 바꾸거나 다른 슬롯에 저장해도 코드는 바뀌지 않습니다. 저장 시각·무작위 ID·언어별 표시 이름을 넣지 않습니다. 오류 확인값은 복사 손상 검사용이며 작성자의 신뢰성이나 공식 추천을 인증하지 않습니다. 코드는 실행하는 프로그램이 아니라 검증한 설정 데이터로만 해석합니다.

문자열·압축 해제 크기, 목록 개수, 중첩 깊이, 수치 범위, 허용 ID와 선택값에 상한을 두고 전체 검증을 마친 후에만 편집본을 만듭니다. 정확한 용량 상한은 전역 8분류와 모든 스킬의 핵심 옵션을 실제 인코딩한 결과로 확정합니다. 서버에서 조회하는 짧은 링크나 커뮤니티 게시 기능은 이번 요구의 범위에 추가하지 않습니다.

### 4.3 공유하기

현재 설정 영역의 ‘공유하기’는 마지막 저장 성공본의 코드를 복사합니다. 슬롯의 ‘공유하기’는 그 슬롯에 보관된 코드만 복사합니다. 클립보드 복사 성공 후 ‘사냥 칙령 코드를 복사했습니다’라고 표시합니다. 복사에 실패하면 코드를 직접 선택·복사할 수 있게 하고 성공했다고 표시하지 않습니다. 코드를 복사하는 동작 자체는 설정을 저장하거나 외부 커뮤니티에 게시하지 않습니다.

### 4.4 코드 입력·프리셋 불러오기

1. 사용자가 코드 입력 또는 붙여넣기를 실행합니다. 클립보드를 상시 읽지 않습니다.
2. 형식·오류 확인값·버전·값·ID를 검증하고 직업, 스킬 구성, 전역 설정 요약과 현재 설정의 차이를 보여 줍니다. 미보유 스킬은 오류로 전체 가져오기를 막지 않고 원래 칸에 빈칸으로 표시합니다.
3. ‘불러오기’를 누르면 사용할 수 있는 스킬은 원래 칸에 배치하고, 미보유 스킬 자리는 비운 채 전역 설정과 스킬별 옵션을 하나의 임시 편집본으로 가져옵니다. 화면에 ‘사용 스킬 3/4개 적용’처럼 결과와 빈칸의 이유를 표시합니다. 이미 미저장 변경이 있으면 먼저 저장·버리기·계속 편집 선택으로 그 변경을 처리합니다.
4. 불러온 내용이 현재 저장본과 다르면 저장하기·되돌리기를 활성화합니다. 이때까지 실제 사냥과 기존 슬롯은 바뀌지 않습니다.
5. 사용자가 ‘저장하기’를 누르면 장착 스킬 배치와 칙령 옵션이 함께 현재 사냥에 반영됩니다. 이름과 슬롯을 선택해 따로 ‘프리셋으로 저장’할 수도 있습니다.

같은 코드를 같은 보유 상태에서 다시 불러왔을 때 생성되는 편집본이 현재 저장본과 같으면 불필요한 변경 표시를 하지 않습니다. 가져오기는 전체 내용 교체를 기준으로 하며, 미보유 스킬의 빈칸을 수신자의 기존 사용 스킬로 조용히 채우지 않습니다. 구버전의 빠진 설정값은 버전 명세에 정의된 기본값 또는 명시적 변환으로 처리합니다.

| 문제 | 처리 |
|---|---|
| 손상·잘린 코드·잘못된 값·알 수 없는 필수 ID | 원인과 위치를 안내하고 불러오기를 중단합니다. 현재 설정·편집본·슬롯을 보존합니다. |
| 지원하지 않는 새 버전 | 필요한 버전을 표시하고 적용하지 않습니다. 알 수 없는 필드를 버리고 저장하지 않습니다. |
| 구버전 | 무손실 변환을 지원할 때만 변경 내용을 보여 주고 편집본으로 가져옵니다. 원본 코드를 보존하고 새 저장 시 변환된 버전의 코드를 생성합니다. |
| 다른 직업 | 해당 직업의 코드임을 표시하고 현재 캐릭터에 적용하지 않습니다. 해당 직업으로 이동할 때도 미저장 이탈 규칙을 지킵니다. |
| 알려진 같은 직업의 미보유·미해금 액티브 | 해당 칸만 비우고 보유 스킬과 전역 설정을 가져옵니다. 원본 스킬 이름·미보유 또는 해금 조건을 표시합니다. 빈칸을 남긴 상태로 저장할 수 있으며 원본 전체와 동일 적용했다고 표시하지 않습니다. |
| 미장착·미해금 스킬이 보관 설정에만 있음 | 정의가 유효하면 그대로 보존합니다. 보관 자체는 오류가 아니며 실제 실행 목록에 넣지 않습니다. |
| 현재 없는 장비·패시브 효과를 참조 | 조건을 삭제·대체하지 않고 필요한 효과와 실행할 수 없는 이유를 표시합니다. 일반 편집 화면의 효과 선택은 현재 가능한 것에 맞춥니다. |

현재 사용할 수 없는 구성도 보관하려는 경우에는 가져오기 미리보기에서 이름·슬롯을 선택하고 ‘프리셋 보관’을 명시적으로 실행합니다. 이 동작은 현재 사냥 설정을 바꾸지 않는 슬롯 저장이며 자동 저장이 아닙니다.

### 4.5 미보유 스킬이 있는 프리셋의 부분 적용

부분 적용은 정상적으로 해석할 수 있는 같은 직업의 프리셋에 적용합니다. 게임에 존재하지만 현재 캐릭터가 보유·해금하지 않은 스킬과, 코드가 손상돼 알 수 없는 스킬 ID는 구분합니다. 재사용 대기시간·현재 자원 부족처럼 전투 중 일시적으로 사용할 수 없는 상태는 미보유가 아니므로 스킬 칸을 비우지 않습니다.

| 원본의 배치 | 현재 캐릭터 상태 | 불러온 사용 스킬 칸 |
|---|---|---|
| 1칸 화염구 | 보유 | 화염구와 해당 칙령을 배치합니다. |
| 2칸 눈보라 | 보유 | 눈보라와 해당 칙령을 배치합니다. |
| 3칸 순간이동 | 보유 | 순간이동과 해당 칙령을 배치합니다. |
| 4칸 원소 보호막 | 미해금 | 빈칸에 ‘원본: 원소 보호막 · Lv.15 해금 필요’와 ‘보유 스킬 선택’을 표시합니다. |

이 상태에서 사용자는 네 번째 칸을 비운 채 저장하거나, 보유한 연쇄 번개 같은 스킬을 직접 선택할 수 있습니다. 뒤의 스킬을 앞 칸으로 당기거나 다른 보유 스킬을 자동 추천·장착해 원본 칸을 채우지 않습니다. 원본에서 처음부터 비어 있던 칸과 미보유 때문에 비워진 칸은 안내 문구로 구분합니다. 필요한 액티브를 하나도 보유하지 않아도 네 칸을 비운 채 전역 설정·기본 공격 설정을 가져와 저장할 수 있습니다.

미보유 스킬의 개별 옵션은 보관 영역에 유지하지만, 해당 액티브는 실행 목록에서 제외합니다. 다른 스킬의 핵심 선택이 이를 필요로 하면 ‘참조 스킬 미보유’로 표시하고, 해당 선택에 명시된 일반 대체 행동을 사용하거나 그 전용 행동을 보류합니다. 다른 스킬은 계속 판단하며 원래 선택값을 몰래 바꾸지 않습니다. 구형 OR/AND 자료를 해석할 때는 참조 불가 묶음을 실행 자격으로 사용하지 않고 다른 유효 묶음만 판단합니다. 미보유를 부정 조건의 참으로 처리하거나 다른 스킬로 참조를 자동 치환하지 않습니다.

전역 긴급 생존에서 미보유 회피기를 지정한 경우에도 해당 참조만 실행 불가로 표시하고 다른 가능한 전역 설정을 유지합니다. 원본에 보행 후퇴가 켜져 있으면 그 방침을 따르며, 없던 후퇴나 다른 회피기를 새로 켜지 않습니다. 미보유 회피기 때문에 공격 자원을 예약하는 등의 실행 제한은 실제 사용할 수 있는 수단에만 적용합니다. 이러한 참조 보류는 전체 저장을 막는 자료 오류와 구분합니다.

사용자가 빈칸에 다른 스킬을 선택하면 그 스킬 ID에 해당하는 현재 편집본의 보관 옵션을 사용하고, 없다면 그 스킬의 기본 옵션으로 시작합니다. 원래 빈칸을 요구했던 스킬의 옵션을 복사해 붙이지 않습니다. 원본 공유 코드·슬롯의 내용은 그대로 유지하며, 부분 적용한 구성을 저장하면 실제 배치와 옵션에 맞는 새 코드를 생성합니다. 이미 모든 조건을 충족해 내용이 동일하다면 기존과 같은 코드가 나옵니다.

빈칸이 생긴 이유와 원본 스킬 정보는 불러오기 결과의 안내 정보입니다. 이를 슬롯에 보존하려면 원본 프리셋을 명시적으로 보관합니다. 부분 적용 후 저장한 코드의 활성 배치는 실제 빈칸 또는 수동 대체 스킬이며, 숨겨진 원본 스킬을 장착 명령으로 남기지 않습니다. 나중에 원래 스킬을 해금해도 빈칸이나 수동 대체한 칸을 자동으로 바꾸지 않습니다. 사용자가 원본 프리셋을 다시 불러오거나 직접 스킬을 선택하고 저장했을 때만 반영합니다.

## 5. 프리셋 슬롯 5개

각 캐릭터의 프리셋 화면에 번호가 고정된 슬롯 1~5를 제공합니다. 기존 캐릭터별 슬롯 구조를 유지하는 설계안이며, 사용자 요구 수량은 5개입니다. 추천 빌드는 별도 영역에 두어 사용자 슬롯을 차지하지 않게 합니다.

| 항목 | 처리 기준 |
|---|---|
| 새 슬롯 저장 | 현재 사냥 설정의 저장 성공 후 ‘프리셋으로 저장’에서 이름·슬롯을 선택하고 저장합니다. 이름·코드·읽을 수 있는 요약을 함께 보관합니다. |
| 이름 | 공백뿐인 이름은 허용하지 않습니다. 표시 길이는 1~24자로 제안하되 한글 조합·이모지 등 실제 표시 문자 기준으로 검사합니다. 이름은 코드의 의미에 포함하지 않습니다. |
| 불러오기 | 슬롯에 저장한 스킬 중 보유한 스킬을 원래 칸에 배치하고, 미보유 스킬의 칸은 이유가 표시된 빈칸으로 둡니다. 옵션·전역 설정도 함께 복원하며 실제 장착·사냥 반영은 ‘저장하기’를 눌렀을 때 함께 이뤄집니다. |
| 덮어쓰기 | 기존 이름과 변경 요약을 보여 준 뒤 명시적으로 덮어씁니다. 저장 실패 시 기존 슬롯 전체를 유지합니다. |
| 이름 수정 | 이름 수정 후 해당 슬롯의 ‘저장’을 눌러 확정합니다. 코드와 현재 사냥 설정은 바뀌지 않습니다. 미저장 이름을 가진 채 페이지를 이탈해도 공통 팝업을 사용합니다. |
| 공유 | 선택한 슬롯에 실제로 저장된 코드만 복사합니다. |
| 기존 3개 슬롯 이관 | 슬롯 1~3의 이름·내용을 보존하고 4~5를 빈 슬롯으로 추가합니다. 훈련 결과의 프리셋 저장 등 모든 진입 경로도 5개로 통일합니다. |
| 기존 장비 보호 참조 | 로컬 장비 참조를 공유 코드에 넣지 않되, 이전 프리셋이 보호하던 장비를 이관 과정에서 자동으로 보호 해제하지 않습니다. 로컬 메타데이터로 분리 보존합니다. |
| 기존 패시브 구성 | 기존 슬롯에 있던 패시브 장착 구성도 로컬 이관 정보에 보존합니다. 사냥 칙령 공유 코드에 넣지 않는다는 이유로 기존 빌드 정보를 삭제하지 않으며, 사냥 칙령 불러오기가 현재 패시브 장착을 조용히 바꾸지 않습니다. |
| 훈련 결과에서 저장 | 시험한 설정을 실제 캐릭터에 먼저 적용하지 않고, 훈련 결과 화면에서 이름·슬롯을 선택해 시험본을 직접 명시적으로 저장합니다. 검증·슬롯 저장 성공 후 코드를 확정하며 현재 사냥 설정은 그대로 유지합니다. |

슬롯 2를 불러온 뒤 설정을 바꿔 저장해도 슬롯 2는 원래 내용 그대로입니다. 슬롯 2까지 바꾸려면 별도의 덮어쓰기를 실행해야 합니다.

예를 들어 프리셋 ‘서리 사냥’에 1칸 화염구, 2칸 눈보라, 3칸 순간이동, 4칸 원소 보호막과 각 스킬의 칙령을 저장합니다. 다른 조합을 사용하다가 이 프리셋을 불러오면 편집 화면의 네 칸이 위 구성으로 바뀌고, 각 스킬의 사용 여부·조건·목표·이동 설정도 함께 돌아옵니다. 저장하면 실제 사용 스킬과 사냥 규칙이 한 번에 바뀌고, 되돌리면 이전 저장본의 배치와 규칙을 함께 복구합니다. 이 조합은 흐름 설명용이며 추천 빌드로 확정한 것은 아닙니다.

## 6. 스킬 표시·보존·교체

### 6.1 모든 스킬을 정의하고 현재 장착 목록만 표시

액티브 18종과 기본 공격 3종의 옵션은 [스킬별 핵심 옵션](HELLSCRIPT_Hunt_Edict_Skill_Option_Catalog.md)에 모두 정의합니다. 실제 일반 편집 화면은 현재 직업의 기본 공격과 장착한 액티브 최대 4개만 보여 줍니다. 각 카드는 자동 사용을 포함해 4~6개를 권장하며 최대 8개입니다. 패시브 18종은 본래 발동 조건·효과를 읽기 전용으로 안내하며 임의 발동 명령을 추가하지 않습니다.

전체 스킬 설정 보관 영역과 현재 실행 규칙 목록을 분리합니다. 미장착 스킬의 설정은 숨기지만 삭제하지 않습니다. 다시 장착하면 마지막으로 저장한 해당 스킬의 옵션이 복원됩니다. 최초 장착 스킬은 명시적인 기본 설정을 사용하며, 해금·재장착으로 기존 사용자 설정을 덮어쓰지 않습니다. 다른 스킬이 참조하던 스킬이 빠졌다면 그 참조를 보존하고 ‘참조 스킬 미장착’으로 실행 제한을 표시합니다.

단, 같은 편집 세션에서 옵션을 수정한 뒤 스킬을 빼고 다시 장착한 경우에는 임시 편집본에 보관한 수정값을 복원합니다. 장착 해제는 미저장 수정을 버리는 동작이 아닙니다. 마지막 저장본을 기준으로 다시 시작하는 것은 새 편집 세션에 진입하거나 사용자가 되돌리기·저장하지 않고 나가기를 선택한 경우입니다.

스킬 카드의 규칙 추가·OR/AND·고급 조건 편집은 핵심 옵션 v0.2로 대체합니다. 새 원본에는 핵심 선택값과 판단 버전을 보관하며 이전 세부 규칙을 숨겨 실행하지 않습니다. 스킬당 3규칙·OR 2묶음·AND 3조건·활성 24규칙은 기존 실행 표현의 한도이며 사용자 옵션 개수와 구분합니다. 미장착 보관 값은 실행 목록과 분리하고 ID·자료 형태·수치 검증을 받습니다. 구형 규칙이 핵심 선택으로 정확히 변환되지 않으면 원본을 보존하고 변환될 내용을 먼저 보여 줍니다.

### 6.2 언제든 스킬 교체

이번 요구를 전투 중에도 장착 스킬을 바꿀 수 있는 방향으로 해석합니다. 편집 동안 전투를 일시정지하고, 장착 목록과 그에 따른 칙령 변경을 임시 편집본에서 확인한 뒤 저장해야 확정합니다. 장착 목록을 편집했다면 스킬 카드도 그 임시 목록을 기준으로 바뀌지만 실제 전투의 장착 상태는 저장 전까지 유지됩니다.

편집 진입 전의 일시정지 상태를 기억합니다. 저장 후 나가기·변경을 버리고 나가기·변경 없이 닫기를 완료하면 그 상태를 복구합니다. 원래 진행 중이던 전투만 재개하며, 사용자가 먼저 멈춘 전투는 그대로 멈춰 둡니다. 저장 실패나 계속 편집을 선택한 동안에는 편집을 위한 정지를 유지합니다.

이미 시작한 공격을 정상적으로 끝낼 수 있는 경우에는 그 행동의 원래 설정을 보존해 마무리하고 다음 판단부터 새 장착 구성을 사용합니다. 채널링처럼 계속되는 행동은 기존 중단 가능 구간을 지켜 종료합니다. 중단 불가 구간을 무시하거나 저장을 반복해 같은 공격을 다시 발동하지 않습니다.

HP·자원·효과 타이머·스킬별 재사용 대기시간은 설정 코드에 넣지 않고 현재 전투 상태로 유지합니다. 스킬을 빼도 남은 재사용 대기시간을 해당 스킬 ID에 보존하여 재장착으로 초기화되지 않게 합니다. 이미 생성된 투사체·장판·덫은 원래 발생 당시의 정의와 수명을 유지하고, 장착 해제가 이미 발생한 피해나 효과를 소급해서 바꾸지 않게 합니다.

공정한 A/B 비교처럼 시작 시 구성을 고정한 검사 모드에서 구성을 바꾸면 같은 비교 결과로 계속 집계하지 않습니다. 편집·재시작 흐름으로 연결하고, 일반 사냥의 교체 가능 정책과 구분합니다.

## 8. 구현 완료 시 확인할 기준

1. 옵션을 바꾸고 저장하지 않은 상태에서 진행 자동 저장·일시중지·정상 종료·강제 종료가 발생해도 마지막 설정 저장본을 침범하지 않습니다.
2. 변경 후 원래 값으로 되돌리면 변경 표시가 해제됩니다. ‘되돌리기’는 기본값이나 방금 불러온 프리셋이 아니라 마지막 저장 성공본을 복원합니다.
3. 모든 실제 페이지 이탈에서 팝업의 세 경로를 확인합니다. 저장 실패 시 나가지 않고 편집본·이전 저장본·이전 코드를 각각 유지합니다.
4. 같은 설정은 같은 코드를 만들며, 이름·시각·슬롯이 달라져도 코드가 바뀌지 않습니다. 다른 계정에서도 해석한 원본 내용은 동일하고, 필요한 스킬을 모두 보유했을 때는 전체 설정·장착 목록·규칙 순서가 원본과 일치합니다.
5. 손상 코드·다른 직업·미래 버전·알 수 없는 스킬·범위를 벗어난 수치와 과도한 크기를 거부해도 기존 설정과 슬롯이 바뀌지 않습니다.
6. 5개 슬롯의 저장·덮어쓰기·이름 변경·공유·불러오기와 실제 앱 재시작 후 복원을 확인합니다. 저장 실패와 기존 3개 슬롯 이관도 검사합니다.
7. 미장착 스킬 옵션이 일반 화면에 나타나거나 실행되지 않습니다. 해제·다른 스킬 장착·다시 장착·앱 재시작 후에도 저장된 원래 설정을 복원합니다.
8. 프리셋 불러오기만으로 현재 사냥이나 슬롯이 바뀌지 않습니다. 코드에 없는 값을 수신자의 기존 값으로 섞어 채우지 않습니다.
9. 스킬 교체·프리셋 적용·재장착으로 HP·자원·재사용 대기시간·투사체·장판·덫 상태가 초기화되거나 중복 발동하지 않습니다.
10. 액티브 18종·기본 공격 3종의 조건과 전용 옵션이 해당 실제 스킬의 조준·범위·동작에 맞습니다. 패시브에는 임의 수동 발동 옵션이 없습니다.
11. 모바일·PC에서 긴 코드 붙여넣기·클립보드 복사·이탈 팝업·키보드 입력·스크롤과 가독성을 실제 입력으로 확인합니다. 코드 검사만으로 실제 화면 검증을 대체하지 않습니다.
12. 서로 다른 스킬 배치의 프리셋을 불러오면 네 칸의 스킬 ID·위치·빈칸과 옵션이 함께 바뀝니다. 미저장 상태에서는 실제 장착이 유지되고, 저장 성공·되돌리기·저장 실패에서 배치와 옵션의 상태가 분리되지 않습니다.
13. 같은 스킬을 다른 칸으로 옮겨도 옵션은 스킬 ID를 따라갑니다. 기존 칸의 옵션이 새 스킬에 붙거나, 빈칸에 이전 스킬이 남거나, 화면 배치 순서가 행동 우선순위를 덮어쓰지 않습니다.
14. 미보유 스킬이 1개·여러 개·전부인 프리셋에서도 가능한 설정을 불러와 저장합니다. 원래 칸 유지·미보유 이유·보류된 참조·수동 대체 옵션을 확인하고, 나중에 해금해도 자동 장착하지 않습니다. 부분 적용 저장은 원본 코드·슬롯을 변경하지 않고 실제 구성의 코드를 생성합니다.
15. 자동 사용·장비 전용 선택까지 포함한 스킬별 편집 항목이 최대 8개인지 확인합니다. 핵심 옵션 v0.2는 4~5개이며, 하위 입력·추가 규칙·고급 탭을 열어 실제 개수가 늘어나지 않습니다.
