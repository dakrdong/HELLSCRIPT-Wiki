# 필드별 몬스터 로스터와 훈위안 모델 생성 계획

작성일: 2026-10-11 (갱신 2026-10-28) · [English](HELLSCRIPT_Monster_Roster_20261011.en.md)

균열 필드 6종마다 일반 몬스터 20종 이상과 보스 3종 이상을 갖추기 위한 구성안이다. 일반 몬스터 120종(기존 20 + 신규 100), 보스 18종(기존 5 + 신규 13), 모두 138종이다. 모델은 Tencent HY 3D(훈위안)의 하루 무료 생성 20회로 만들고, 아래 우선순위대로 하루 20종씩 생성한다. 기존 필드 규칙은 [균열 필드 6종](HELLSCRIPT_Rift_Fields.md), 기존 적·보스 수치는 [일반 적·정예 상세](HELLSCRIPT_Enemy_Combat_Detail.md)와 [보스 5종 전투 상세](HELLSCRIPT_Boss_Combat_Detail.md)를 따른다.

## 1. 설계 원칙

- **룩앤필**: 디아블로 4처럼 몬스터를 계통(가족) 단위로 묶고, 같은 필드 안에서는 재질과 색이 통일된다. 사실적이고 음울한 고딕 판타지, 낡은 재질, 높은 탑다운 카메라에서도 읽히는 굵은 실루엣. 기존 초상화(`Resources/Art/TrainingGround/Portraits`)의 어두운 회화풍을 기준으로 한다. 상처·노출된 살 같은 잔혹 묘사는 쓰지 않는다.
- **몬스터 하나에 질문 하나**: 모든 몬스터는 플레이어(=사냥 칙령)가 답해야 할 질문을 하나씩 던진다. 누구를 먼저 칠지, 어디로 피할지, 언제 기술을 쓸지, 이동기를 아껴 둘지, 광역과 단일 화력 중 무엇을 고를지. 각 표의 `칙령 시험` 열이 그 질문이다.
- **피할 수 있어야 한다**: 모든 피해는 기존 예고 게이지(원·고리·부채꼴·직선)로 먼저 보여 준다. 피할 수 없는 피해, 1.5초를 넘는 행동 불가, 60%를 넘는 둔화는 쓰지 않는다. 투사체는 기존처럼 한 발동에서 한 발만 맞는다.
- **필드 안 역할 배분**: 필드마다 근접 5–6, 돌진·도약 2–3, 원거리 3, 장판·제어 3, 지원·소환 3, 사망 효과 2, 특수(매복·고정 구조물·보물) 1–2종을 둔다. 같은 필드 안에서 같은 기믹을 반복하지 않는다.
- **수치**: 기존 20종의 능력치와 패턴은 바꾸지 않는다. 신규 몬스터의 수치는 기획 시안이며, 구현 때 기존 `EnemyCombat` 형상과 같은 초당 피해 예산(근접 슬롯은 N01의 ±15%)으로 맞춘다.
- **현재 등장 표**: 기존 등장 표(묘지 외 필드가 N02–N05를 함께 쓰는 구성)는 그대로 두고, 레지스트리에 출시된 신규 몬스터가 해제 단계부터 자기 필드의 같은 역할 칸에 함께 들어간다(11장).

## 11. 몬스터 레지스트리와 데이터 전투 (2026-10-11 구현)

신규 몬스터와 보스를 코드 수정 없이 데이터로 추가하는 기반이다. 매일 루틴이 `tools/monster_registry.py add`로 20종씩 게임에 넣으면 같은 날 균열에 등장한다.

### 11.1 레지스트리

- 게임 데이터는 `Assets/HELLSCRIPT/Resources/Monsters/MonsterRegistry.json`, 런타임은 `Runtime/Core/MonsterRegistry.cs`다. 몬스터 도감이 쓰는 계약: `MonsterRegistry.All`(도감 순서: 필드 번호 → 일반 → 보스 → 번호), `ById`, `ForKind`, `ForBoss`, `IdOf(EnemyState)`(보스는 패턴의 B 번호, 그 외는 종류의 N 번호, 정예는 기본 종류, 황금 고블린은 null).
- 항목 필드: `id`(N01–N120, B01–B18), `boss`, `kind`(N 번호−1, 보스 −1), `pattern`(B 번호−1, 일반 −1), `name`·`role`·`family`(한국어 문구 키, 영어는 `en.txt`), `field`(GameCatalog 필드 번호, 보스는 본거지 필드: B01 묘지, B02 성채, B03 동굴, B04 사막, B05 고원), `slot`(무리 역할 0 근접·1 돌진·2 원거리·3 장판·4 지원·5 폭발), `unlockTier`, `portrait`(`Art/TrainingGround/Portraits/<ID>`), `art`(HunyuanReady 키), `artPending`, `skills`(이름·설명 키, 원소 태그 physical/fire/cold/lightning/poison/shadow 하나 이상, 1회 피해 배율 또는 0, 선택 `icon`), `hp`·`attack`·`speed`, 보스용 `keepDistance`·`approach`·`body`, `attacks`, `traits`, `legacy`.
- 기존 25종은 `legacy: true`로 현재 종류·패턴·수치·스킬만 설명하고 전투는 기존 코드 그대로다. 기존 보스 스킬 아이콘은 `Art/Boss/skill-<정의>`다. 21번째 종류와 6번째 보스부터 이름·능력치(`CombatSimulation.EnemyStats`, `BossCombat.ProfileOf`)·전투를 레지스트리에서 읽는다.
- 아트가 준비되지 않은 몬스터는 `artPending: true`로 출시한다. 이때 `portrait`와 `art`는 빈 문자열이고, 월드에서는 기존 기본 도형 몸체를, 훈련장에서는 빈 초상화 틀을 보여 준다. 임시로 다른 몬스터의 초상화를 쓰지 않는다.
- 설계 원본은 `Docs/Design/MonsterRoster/roster.json`이다. 138종 모두 레지스트리 형식에 한·영 문구(`nameEn`, `roleEn`, `familyEn`, 스킬 `nameEn`·`descriptionEn`), `shipped`, `day`, `deferred`(아직 구현하지 않은 기믹)를 더한다.

### 11.3 등장 표와 보스

- 무리 칸 후보는 그 필드·칸의 원래 종류와, 3D 모델이 있고 같은 필드·같은 `slot`이며 `unlockTier`가 현재 단계 이하인 출시 몬스터다(종류 순). 고르는 값은 레이아웃 `encounterSeed`와 스폰 번호의 해시(`RiftGenerator.SpawnPick`)라 실행·조우 난수를 쓰지 않는다. 후보가 하나뿐인 칸은 이전과 똑같고, 위치·역할·정예·보상은 바뀌지 않는다. 5단계 이하에서 0번 칸만 쓰는 규칙도 그대로다.
- 모델 보유 여부는 레지스트리의 `art` 키가 비어 있지 않은지로 판정한다. 아트 대기·모델 제거 항목은 균열의 추가 후보에서만 빠지고 레지스트리·도감에는 남는다. 도감 카드와 상세에서는 공통 문구 "준비 중입니다."로 표시하고 처치 수와 발견 진척 집계에서 제외한다.
- 신규 일반 몬스터의 해제 단계는 1단계 필드(묘지·동굴·초원) 6, 11단계 필드(성채·사막·고원) 11이다. 그래서 1–5단계 자연 진행과 기존 고정 결과(FieldTests 기준값, 1단계 전투)는 바뀌지 않는다.
- 떼 몬스터는 배치된 하나가 우두머리가 되고 `pack`−1마리 추종자가 붙는다. 추종자는 부하로 취급해 보상·처치 게이지·사체가 없어서 균열 보상은 기존과 같다.
- 보스: 9장의 "실제 추첨 규칙"을 따른다. 기존 단계 규칙이 고른 보스(1·11·21·31·41단계 해제, 그대로)에, 3D 모델이 있고 그 필드가 본거지이며 해제 단계에 이른 출시 데이터 보스를 더해 레이아웃 해시(`RiftGenerator.FieldBoss`)로 고른다. 추가 후보가 없는 필드·단계는 이전과 같다.
- 훈련장 적 선택과 스킬 미리보기 시나리오 검증은 등록된 모든 종류를 받는다.

### 11.4 도구

- `python3 tools/monster_registry.py next 20`: 출시하지 않은 다음 ID를 하루 순서대로(있으면 `tools/monster_pipeline/day_order.json`, 없으면 로스터 `day`) 보여 준다.
- `python3 tools/monster_registry.py add <ID...> [--art-pending] [--allow-deferred]`: 로스터 항목을 레지스트리로 옮기고, 없는 한국어 키의 영어 줄을 `en.txt`에 쓰고, 로스터를 `shipped: true`로 바꾼 뒤 검사한다. 검사에 실패하면 아무것도 쓰지 않는다. `deferred`가 있는 항목은 `--allow-deferred` 없이는 거절한다.
- `python3 tools/monster_registry.py refresh <ID...>`: 출시 뒤 로스터 항목이 바뀌면 레지스트리 항목을 다시 복사한다(아트 대기 상태 유지).
- `python3 tools/monster_registry.py art-ready <ID...>`: `artPending`으로 출시한 항목에 초상화와 모델이 들어오면 로스터의 `portrait`·`art`를 넣고 검사한다.
- `python3 tools/monster_registry.py validate`: 형식, ID 중복, kind/pattern 일치, 문구 완결성(영어 누락, 구조물 이름 포함), 원소 태그, 둔화 강도 60%·봉인 1.5초·저주·시야·독 상한, 구조물 형식과 차단 시간(영웅 주위 2초, 벽 5초), 반격 설정, 초당 피해 예산(N01 기준 근접 칸 ±15%, 다른 칸은 N01 + 15% 이하, 보스 1회 배율 2.0 이하), 예고 0.4초 이상, 행동 불가 1.5초 이하, 둔화 3초 이하, 소환·분열 대상 등록 여부, `artPending`이 아닌 항목의 초상화·모델 존재를 확인한다.
- 회귀 검사: `python3 tools/test_monster_registry.py`, Edit Mode `MonsterRegistryTests`·`MonsterPrimitiveTests`·`MonsterMechanicTests`·`MonsterSpawnTableTests`(같은 규칙을 C#으로 다시 확인).

### 11.5.1 아트 대기 일괄 출시 (2026-10-20)

로스터 미출시 90종 중 88종(일반 N30·N32·N34·N36–N38·N41·N46·N47·N50–N57·N59–N120 79종, 보스 B09·B11–B18 9종)을 `add --art-pending`으로 한꺼번에 출시했다. 모델과 초상화는 아직 없어서 월드는 기본 도형 몸체, 도감은 빈 초상화 틀을 쓴다. 아트가 들어오면 `art-ready`로 해제한다.

- 해제 단계는 로스터 값 그대로다(일반 몬스터 묘지·동굴·초원 6단계, 성채·사막·고원 11단계, 보스 26–66단계). 해제 단계가 1인 B08·B10은 1–5단계 보스 선택을 바꾸므로 제외했다. 그래서 1–5단계 시드와 기존 고정 결과는 그대로다.
- 6단계 이상에서는 칸 후보가 늘어 같은 시드의 몬스터 종류가 달라지고, 기존 몬스터의 비중이 줄어든다(예: 사막 근접 칸은 기존 1종이 7종 중 하나가 된다). 배치·역할·정예·보상 구조는 `MonsterSpawnTableTests`로 확인한 대로 바뀌지 않는다.
- 도감은 총 136종(일반 120 + 보스 16)이고 처치 기록은 ID별이라 기존 세이브가 그대로 이어진다.

### 11.6 보류와 한계

로스터에 보류(`deferred`) 항목은 없다. 매일 루틴은 `--allow-deferred` 없이 출시한다. 구현상 한계는 다음과 같다.

- 벽·감옥은 영웅의 걷기만 막는다. 적은 통과하고, 영웅의 길찾기는 벽을 모르기 때문에 벽 앞에서 멈춘 채 벽을 공격하거나 시간이 끝나기를 기다린다.
- 시야 감소는 인지 거리 7m 제한과 HUD 상태로만 나타나며 화면 안개 연출은 없다.
- 사냥 칙령은 안전 지점(밀물의 바위)을 따로 찾아가지 않는다. 기존 침묵의 찬가 피난 지점과 같다.
- 비행은 이동과 표시 높이만 바꾼다. 영웅의 지면 효과는 비행 몬스터도 맞힌다.
- 분신은 주인의 1페이즈 공격 중 투사체가 아닌 것만 흉내 낸다.
