# 신규 직업 세트 아이콘 제작 기록

작성일: 2026-09-22

[English](Class_Set_Icons.en.md)

신규 24세트의 **장비 아이콘 105개와 세트 문양 24개, 총 129개**를 제작했습니다. 모든 항목에 개별 PNG, 한영 이름과 효과, 실제 프롬프트, 생성 원본, 해시와 검수 기록이 있습니다. 기존 6세트는 제작 대상에서 제외했습니다.

내장 이미지 생성 도구가 실제 모델명을 반환하지 않아 모든 이미지는 **`generated_candidate`**, 모델은 **`unknown`**입니다. 기본 지정 모델인 `gpt-image-2`의 사용을 입증할 수 없으므로 게임용 확정 자산으로 승인하지 않았습니다. 이미지 제작과 파일 검수가 끝난 상태이며, 모델 근거와 게임 내 채택 승인은 별도로 남아 있습니다.

ID, 이름, 부위와 효과의 기준은 읽기 전용 인계본에서 복사한 [sets.json](brief/sets.json)과 [인계 지침](brief/README.md)입니다. 원본 인계 작업 공간은 변경하지 않았습니다. JSON의 SHA-256은 `242ef72d0a64a5615d2b69c549be0962c53d1081a348f2e9290f3f0596d1da51`, 지침의 SHA-256은 `d611a706e89edfd17561ac967ec346f7ca948b851e2ffa760ac23bfb614146ab`입니다.

제작 도중 원본 지침에 **1254px 네이티브 원본도 허용하며 크기만 맞추는 편집은 요구하지 않는다**는 설명이 추가됐습니다. [추가 지침 사본](brief/Class_Set_Icons_Handoff_Clarification.md)의 해시는 `8ae3399779419e2c67bd0fb19c9b5bee3dc8367ba939cdec7692f704aaafd4e4`입니다. 최초 사본을 덮어쓰지 않고 두 시점을 구분했습니다. `sets.json`은 변경되지 않았으며, 네이티브 원본 129개를 모두 함께 전달하므로 이후 통합에서 원본을 직접 선택할 수 있습니다.

세트 효과 60단계는 `manifest.json`의 `bonusMappings`에서 해당 세트 문양 24개에 연결합니다. 예를 들어 `REF_SW01_B2`와 `REF_SW01_B3`은 모두 `REF_SW01.png`를 사용합니다. 단계별 숫자나 별도 문양을 이미지에 넣지 않았습니다.

## 시각 기준과 파일 계약

`EquipmentAtlas.png`와 `Art/GlobalHUD`의 검·캐릭터·패시브 아이콘 원본을 직접 확인했습니다. 낡은 철과 가죽, 억제된 금속 하이라이트, 큰 명암 덩어리를 참고하고 다크 고딕 회화풍으로 제작했습니다. 세트마다 재질과 문양을 함께 반복하고, 다른 세트는 외곽 형태와 구조로 구별했습니다. 같은 그림의 색만 바꾸는 방식은 사용하지 않았습니다.

각 부위와 문양은 독립된 생성 요청으로 만들었습니다. 이미지 안에는 글자, 숫자, UI 테두리, 바닥이나 배경을 넣지 않았습니다. 생성 원본은 네이티브 알파를 가진 PNG이며 크로마키, 사후 배경 제거와 알파 재구성은 사용하지 않았습니다.

| 항목 | 저장 방식 |
| --- | --- |
| 규격본 | `Assets/HELLSCRIPT/Resources/Art/ClassSetIcons/<ID>.png`에 1024×1024 RGBA PNG로 저장했습니다. |
| 식별자 | 장비는 원본 장비 ID, 문양은 원본 세트 ID를 파일명으로 사용했습니다. |
| Resources 키 | `Art/ClassSetIcons/<ID>`를 manifest에 기록했습니다. 이번 작업에서 로드 코드에 연결하지는 않았습니다. |
| 생성 원본 | 직업별 `originals/<ID>.png`에 도구 반환 파일을 바이트 그대로 보존했습니다. |
| 생성 근거 | 직업별 `evidence/<ID>.json`에 도구 경로, 원본·규격본 해시, 알파와 크기 검사값을 저장했습니다. |
| 재제작 이력 | 교체된 시안과 이유는 직업별 `rejected/` 및 manifest에 보존했습니다. |
| Unity 메타데이터 | 새로운 PNG에 고유 GUID를 부여하고 단일 Sprite 설정을 기록했습니다. 기존 다른 에셋의 메타데이터는 변경하지 않았습니다. |

도구는 1024px 요청에 **1254×1254 PNG**를 반환했습니다. 원본과 납품 규격본을 구분하여 기록했습니다. 규격본은 기존 알파의 전체 영역을 기준으로 비율을 유지해 축소한 뒤 투명 여백을 추가했습니다. 알파를 곱한 색상으로 재샘플링해 가장자리 번짐을 줄였으며, 비투명 픽셀은 중앙 76% 영역 안에 있습니다. 이 과정에서 해상도와 픽셀값은 달라지지만 그림의 의미나 형태를 다시 그리지는 않았습니다.

## 검증 범위와 재현

파일 검사는 129개 ID의 누락·중복, 105개 장비와 24개 문양의 수량, 60단계의 연결, 인계 이름·부위, PNG·알파·크기·여백, 원본 해시, 규격 변환 재현과 GUID 중복을 확인합니다. 직업별 manifest와 통합 manifest의 파일 경로·상태·해시도 비교합니다.

제작 담당자는 모든 이미지를 실제 64px 크기의 밝은 배경과 어두운 배경에서 확인했습니다. 검수 시트에는 더 큰 보조 이미지도 함께 실었습니다. 부위와 문양의 식별, 잘린 형태, 사각 배경판, 눈에 띄는 가장자리 오염을 확인했습니다. 시각 판정은 사람이 수행한 제작 검수이며 자동 스크립트의 독립적인 미술 평가를 뜻하지 않습니다. 전사 목걸이의 열린 끈, 궁수 목걸이의 잘린 끈과 궁수 활의 낮은 대비는 별도 생성·수정 요청으로 보완했습니다.

재검증할 때는 저장소 루트에서 다음 명령을 실행합니다. Python과 Pillow가 필요합니다.

```text
python3 Docs/Art/ClassSetIcons/build_catalog.py
python3 Docs/Art/ClassSetIcons/validate_assets.py --require-complete
```

검증 스크립트는 PNG를 변경하지 않습니다. `--write-missing-meta`는 누락된 새 메타데이터만 만들며 기존 GUID를 덮어쓰지 않습니다. [검증 결과](validation.json)의 `scope`와 항목별 판정이 실제 확인 범위입니다.

## 통합과 게시 상태

전투 데이터, UI 배치, 프리팹, 씬과 아이콘 연결 코드는 이번 범위에 포함하지 않았습니다. Unity 임포트, Edit Mode 테스트, macOS 게임 실행 및 모바일 실기기 검증은 수행하지 않았습니다. 파일 검사와 오프라인 시각 검수가 게임 적용을 증명하지는 않습니다.

이 묶음은 `codex/class-set-icons` 작업 브랜치에서 전달합니다. 문서를 위한 로컬 위키 생성·검사를 수행하며, 사용자 지정 범위에 따라 main 병합과 공개 위키 배포는 수행하지 않습니다. 공개 반영은 이후 병합 담당자의 절차로 남습니다.

첫 위키 생성은 새 작업 공간에 기존 문서의 검증 첨부가 없어 중단됐습니다. 기존 위키 데이터에 기록된 해시와 일치하는 과거 첨부 272개를 읽기 전용 원본에서 로컬의 Git 제외 경로로 복사한 뒤 다시 검사했습니다. [복구 근거](wiki-input-recovery.json)에 파일별 해시를 기록했습니다. 이 자료는 기존 문서의 링크 복구용이며 이번 작업에서 게임 검사를 새로 실행했다는 근거로 사용하지 않습니다.
