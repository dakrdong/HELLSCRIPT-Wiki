# 위키와 DB 갱신 규칙

## 원본과 조회본

기획의 원본은 `Docs/Design`, 개발 기록은 `Docs/Implementation`에 있습니다. 이 위키는 원문을 보존하면서 카테고리·검색·관련 자료를 연결하는 로컬 조회 화면입니다. 정리용 안내 문서는 `Wiki/content`에서 관리합니다.

콘텐츠 DB는 가능한 항목을 현재 C# 정의와 `GameCatalog.asset`에서 추출합니다. 일반 적·정예·보스의 설계 의도 등 문서에서 가져오는 값은 ‘기획·구현 기록’으로 표시합니다. 검증되지 않은 수치를 임의로 보충하지 않습니다.

`tools/wiki.py build`는 원문과 콘텐츠를 읽어 위키 데이터를 생성합니다. `tools/wiki.py check`는 레코드 ID, 참조, 원문 링크, 이미지 파일과 현재 원본 해시를 검사합니다. `tools/wiki.py serve --port 4175`는 현재 생성된 위키를 로컬에서 엽니다.

## 버전 보존

문서의 본문이 바뀌면 다음 버전을 새로 저장합니다. 같은 본문으로 다시 생성하면 버전을 추가하지 않습니다. 기존 문서의 과거 기록을 꾸며내지 않으며, 위키 등록 이전의 실제 편집 이력은 별도로 확인해야 합니다.

화면에 표시하는 문서 날짜와 위키에 저장한 시각은 별개입니다. 원문 날짜는 원문에서 읽고, 보존 시각은 최초 등록 또는 변경된 본문을 수집한 시각을 사용합니다.

DB는 원본을 재현한 현재 조회본이며 게임 값을 직접 수정하는 편집기가 아닙니다. 수치를 바꾸려면 담당 기획·코드·에셋의 권한과 검증 절차를 따른 뒤 DB를 갱신합니다.

## 현재 상태 표시

| 표시 | 의미 |
| --- | --- |
| 현재 정의 | 현재 코드 또는 에셋에서 직접 읽은 콘텐츠 값입니다. |
| 기획·구현 기록 | 기획 표나 개발 기록에서 요약한 내용입니다. 실제 판정 전체를 자동 추출한 것은 아닙니다. |
| 임시 사용 | 현재 게임에 연결되었으나 정식 출시 제작·승인을 마치지 않은 리소스입니다. |
| 제작 대기 | 기존 기획에 필요하지만 정식 리소스 제작 또는 등록이 남아 있습니다. |
| 당시 기록 | 최초 빌드·과거 검사 시점의 결과입니다. 최신 구현 상태를 덮어쓰지 않습니다. |

## 검증 기록 해석

검증 DB는 저장된 XML 보고서의 결과를 읽습니다. 검사 수를 서로 합산해 전체 검증 범위로 표시하지 않습니다. 실패를 수정하기 전의 기록도 삭제하지 않으며, 통과 여부·검사 시각·원본 파일을 함께 표시합니다.

위키의 자료 검사와 Unity 자동 검사, 실제 앱 실행, Android 실기기 검증은 서로 다른 작업입니다. 위키를 생성했다고 게임 검증을 새로 수행한 것으로 보고하지 않습니다.

참고한 PackBound 위키의 문서 트리·DB 탐색 방식은 유지하되, HELLSCRIPT의 콘텐츠와 로컬 주소를 별도로 관리합니다.

## 문서·리소스·검증 기록을 추가할 때

`Docs/Design`, `Docs/Implementation`, `Wiki/content`에 새 Markdown 문서를 두면 `build`가 페이지를 자동으로 만듭니다. 다만 트리의 분류, 짧은 제목, 요약은 `tools/wiki.py`의 `PAGE_META`(기획·안내 문서) 또는 `DEV_SUMMARY`(개발 기록)에 등록해야 합니다. 등록하지 않은 문서는 ‘후속 개발 기록’ 분류와 일반 요약으로 표시됩니다.

새 화면이나 코드 생성 표현은 `build_resources`의 ‘코드 생성 표현’ 목록에 구현 파일과 연결 기록을 함께 추가합니다. 새 이미지 파일은 `Assets/HELLSCRIPT/Resources/Art`에 두고 사용처·출처를 [임시 리소스 출처](../../Docs/Implementation/Asset_Provenance.md)에 남긴 뒤 같은 함수의 사용처 표에 등록합니다.

검증 DB는 `Artifacts/Validation`의 `*editmode*.xml` 보고서 전체를 읽습니다. 실패를 수정하기 전의 보고서도 삭제하지 않고 함께 표시하며, 각 보고서의 단계와 구분은 파일 이름에서 읽습니다. `Artifacts/`는 저장소에 포함하지 않으므로 보고서가 없는 환경에서는 검증 DB가 비어 있을 수 있습니다.

## 시간·태그·이력 탐색

전체 위키 트리에서 카테고리·최신순·오래된순을 선택합니다. 최초 등록과 마지막 변경을 구분하고 날짜 범위를 함께 적용할 수 있습니다. 태그를 누르면 해당 태그가 정확히 붙은 문서만 표시하며, 검색어와 날짜 조건을 함께 사용할 수 있습니다. 문서의 ‘이력 비교’에서는 보존된 두 본문의 추가·삭제 줄을 확인합니다. 연결 문서와 역참조도 문서 하단에서 제공합니다.

태그를 추가하려면 `Wiki/page-metadata.json`에 문서 ID와 `tags` 배열을 등록한 뒤 위키를 갱신합니다.

## 공개용 위키 관리

공개용 위키는 전체 문서·이력·DB·이미지·원본 근거를 개발 위키와 동일하게 제공하는 읽기 전용 사본입니다. 별도의 소개 문서 목록으로 제한하지 않습니다. 검색·필터·정렬·상세 조회·다운로드·이력 비교를 제공하며 등록일과 변경일은 시간 없이 날짜만 표시합니다.

`build`는 `Wiki/site/public/`에 정적 파일을 생성하고 `check`는 개발 위키와 데이터·첨부 자료가 일치하는지 검사합니다. 편집 기능이나 저장 API는 포함하지 않습니다. 개발 위키의 ‘공개용 위키’에서 로컬 사본을 열 수 있으며, 외부에 게시하려면 이 폴더를 배포합니다.
